This navigation sub-module, loaded by =sp-navi=, configures =consult-snapfile=, a Consult front-end that queries a local file-search server over a websocket.

- The package is loaded from a local checkout in =~/cloned-utilities/consult-snapfile/emacs=, not from a package archive.
- It needs the =consult= and =websocket= packages, plus the snapfile server running on the configured host and port.

** Package

Loads =consult-snapfile= from the local checkout after Consult and websocket are available, and binds =C-c s f= to =consult-snapfile=.

- If the directory does not exist, the package will not be found.
- The checkout path goes through the constant =sp-consult-snapfile-dir=. =use-package= reads a list given to =:load-path= as a list of paths, and would evaluate =sp-path= as a variable.
- =:ensure nil= keeps Elpaca from looking for the package in an archive.
- The settings are in =:custom=: the client talks to the snapfile server on =127.0.0.1= port 9876 (=consult-snapfile-server-host=, =consult-snapfile-server-port=), and each query returns at most 100 results (=consult-snapfile-max-results=). Because of =:after=, they are applied once Consult and websocket have loaded.

#+begin_src emacs-lisp -i
;; `:load-path' reads a list as a list of paths and evaluates each symbol in it as a
;; variable, so a call to `sp-path' has to go through a variable.
(defconst sp-consult-snapfile-dir
  (sp-path sp-clones-dir "cloned-utilities/consult-snapfile/emacs")
  "Local checkout of the consult-snapfile client.")

(use-package consult-snapfile
  :ensure nil
  :load-path sp-consult-snapfile-dir
  :after (consult websocket)
  ;; Optional: bind to your preferred key
  :bind ("C-c s f" . consult-snapfile)

  :custom
  ;; Server settings
  (consult-snapfile-server-port 9876)
  (consult-snapfile-server-host "127.0.0.1")
  ;; Max results to return
  (consult-snapfile-max-results 100))
#+end_src
