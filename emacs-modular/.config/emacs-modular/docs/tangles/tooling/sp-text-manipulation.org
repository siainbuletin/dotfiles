The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module collects editing behaviour that applies to text in general. It:

- sets up copy, cut, paste and undo (Command keys on the Mac, Ctrl keys elsewhere, no CUA),
- cleans whitespace on every save,
- adds commands for fixing blank lines around Org headings, filling and unfilling paragraphs, and copying an Org region as rich text,
- makes yanking smarter about surrounding spaces,
- configures the built-in =abbrev= package,
- rebinds the case commands to their DWIM variants.

Dependencies and loading:

- Everything here is built in to Emacs, apart from the external macOS tools =textutil= and =pbcopy= used by =formatted-copy=.
- It refers to =sp-var-dir= from =early-init.el= for the abbrev file location.
- The module is loaded with the utility modules in both the default and minimal module lists in =init.el=, so its global key bindings and its save hook are always active.

** Copy, cut, paste and undo

- On the Mac (=system-type= is =darwin=):
   + =sp-macos= makes Command =super=, so the keys are =s-c= (=kill-ring-save=), =s-x= (=kill-region=), =s-v= (=yank=), =s-z= (=undo=) and =s-Z= (=undo-redo=, Command+Shift+Z).
   + =S-s-z= is bound to =undo-redo= too, because that is the event Emacs receives for Command+Shift+Z on the Mac.
   + CUA mode is off, so =C-c= and =C-x= are only prefixes, and =C-v= is =scroll-up-command=.
   + The Emacs defaults are unbound on every system:
      - =C-y= (=yank=), =C-w= (=kill-region=) and =M-w= (=kill-ring-save=).
      - =C-_=, =C-/=, =C-?=, =C-M-_= and =C-x u= (undo and redo).
   + =C-z= is unbound so it cannot suspend Emacs.
   + Org already binds =s-v= to =org-yank= (=sp-org-base=), which wins in Org buffers.
- On Linux and Windows (Ctrl takes the place of Command, Super takes the prefixes):
   + CUA mode is off here too, so there is one layer of keys.
   + The prefixes move to Super: =s-c= is translated to =C-c= and =s-x= to =C-x=, in =key-translation-map=.
   + The typed =C-c= and =C-x= are translated to the private events =<sp-copy>= and =<sp-cut>= when they start a key sequence, and those are bound to =kill-ring-save= and =kill-region=.
   + Inside a sequence, a typed =C-c= or =C-x= stays itself, so =s-c C-c= is =C-c C-c= and =s-x C-c= is =C-x C-c=.
   + =C-v= is =yank=, =C-z= is =undo= and =C-S-z= is =undo-redo=.
   + On Windows =w32-lwindow-modifier= and =w32-rwindow-modifier= are =super=.
   + =i3= and =sway= use Caps Lock as Mod5 (=lv3:caps_switch=), so no window manager binding takes Super.
- Caveats of the prefix swap:
   + Every =C-c ...= and =C-x ...= in manuals, docs and which-key hints is typed as =s-c ...= and =s-x ...= here; the second key can stay Ctrl, as in =s-x C-f=.
   + Windows itself takes =Win+C= and =Win+X=, so the prefixes need a remap there (PowerToys Keyboard Manager, or =w32-register-hot-key=); no Windows window manager is configured in this repository.
   + The check that a key starts a sequence uses =this-command-keys-vector=; this is from memory and was not run, so a real Emacs is needed (try =C-h k s-c C-c= and =C-h k C-c=).
   + Terminal Emacs gets no Super key, so this is GUI-only, as the keymaps already are.
- On all systems the Emacs defaults are unbound (see above).
- Caveats of unbinding =C-w=, =M-w= and =C-y=:
   + Only the global bindings go. Maps that bind the key themselves keep it, for example =C-w= in =isearch-mode-map= (=isearch-yank-word-or-char=) and the =C-x C-w= (=write-file=) and =C-M-w= (=append-next-kill=) chords.
   + Documentation, tutorials, the Emacs manual and other people's advice say =C-w=, =M-w= and =C-y=; those keys now say "undefined" here, so translate them to the new keys.
   + Muscle memory: a stray =C-w= or =M-w= does nothing instead of killing text, which is safer than cutting by accident but silent apart from the echo-area message.
   + The kill ring itself is unchanged: the new keys use the same =kill-region=, =kill-ring-save= and =yank=, so =M-y= (=yank-pop=) and =consult-yank-pop= still work after a paste. =M-y= only works right after a yank, so it follows the new paste key.
   + Terminals inside Emacs (=vterm=, =eat=) pass =C-w= to the shell, where it deletes the previous word; this change does not affect them.
   + Any mode or package whose docs or hydras tell you to press =C-w= or =M-w= (the global ones) needs the new key; this was not audited across the config, and a real Emacs session is needed to find them.
   + Not run in Emacs here (none in the container).
- The same choices on all three systems: [[file:../../architecture/global-keymap-namespaces.org]["Same keys on macOS, Linux and Windows"]].
- Why the prefixes move: one key cannot be both copy and a prefix, and CUA was the only way to do both. Design: [[file:../../architecture/global-keymap-namespaces.org][global-keymap-namespaces]], "Replacing CUA".

#+begin_src emacs-lisp -i
;;;; Copy, cut, paste and undo, as in every other app.
(cond
 ((eq system-type 'darwin)
  ;; Command is Super (`sp-macos'): plain keys, no CUA, so C-c and C-x are
  ;; only prefixes.
  (keymap-global-set "s-c" #'kill-ring-save)
  (keymap-global-set "s-x" #'kill-region)
  (keymap-global-set "s-v" #'yank)
  (keymap-global-set "s-z" #'undo)
  (keymap-global-set "s-Z" #'undo-redo)
  (keymap-global-set "S-s-z" #'undo-redo))
 (t
  ;; Linux and Windows: Super is the C-c and C-x prefix, Ctrl the clipboard.
  ;; Without CUA, C-c and C-x cannot be both a prefix and copy and cut, so the
  ;; prefixes move to Super (s-c is C-c, s-x is C-x) and the typed C-c and C-x
  ;; become copy and cut. i3 and sway leave Super alone (their layer key is
  ;; Mod5).
  (defun sp-text-manipulation-first-key-p ()
    "Return non-nil when no key of the current sequence was typed yet."
    (zerop (length (this-command-keys-vector))))
  (defun sp-text-manipulation-translate (typed event)
    "Return EVENT for a TYPED key that starts a sequence, else TYPED itself."
    (if (sp-text-manipulation-first-key-p) event typed))
  ;; A translation is applied once, so the swap does not loop.
  (keymap-set key-translation-map "s-c" "C-c")
  (keymap-set key-translation-map "s-x" "C-x")
  (keymap-set key-translation-map "C-c"
              (lambda (_prompt) (sp-text-manipulation-translate (kbd "C-c") [sp-copy])))
  (keymap-set key-translation-map "C-x"
              (lambda (_prompt) (sp-text-manipulation-translate (kbd "C-x") [sp-cut])))
  (keymap-global-set "<sp-copy>" #'kill-ring-save)
  (keymap-global-set "<sp-cut>" #'kill-region)
  (when (eq system-type 'windows-nt)
    (setq w32-lwindow-modifier 'super
          w32-rwindow-modifier 'super))
  (keymap-global-set "C-v" #'yank)
  (keymap-global-set "C-z" #'undo)
  (keymap-global-set "C-S-z" #'undo-redo)))

;; The Emacs defaults for the same jobs are unbound, so there is one layer of
;; keys: no C-y, no C-w, no M-w, no C-_ / C-/ / C-? / C-x u.
(dolist (key '("C-y" "C-w" "M-w" "C-_" "C-/" "C-?" "C-M-_" "C-x u"))
  (keymap-global-unset key))
;; On the Mac C-z would suspend Emacs; stop me from freezing it.
(when (eq system-type 'darwin)
  (global-unset-key (kbd "C-z")))

#+end_src

* Whitespace cleanup

** Clean whitespace command

=sp-clean-whitespace= removes trailing spaces and tabs from every line, collapses three or more consecutive newlines to a single blank line, and deletes trailing spaces at the very end. It works on optional explicit bounds, else the active region, else the whole accessible buffer, and reports when it is done.

#+begin_src emacs-lisp -i
;; Cleaning up unnecessary whitespace
(defun sp-clean-whitespace (&optional Begin End)
  "Delete trailing whitespace, and replace repeated blank lines to just 1.
Only space and tab is considered whitespace here.
Works on whole buffer or selection, respects `narrow-to-region'."
  (interactive)
  (let (xbeg xend)
    (seq-setq (xbeg xend)
              (if (and Begin End)
                  (list Begin End)
                (if (region-active-p)
                    (list (region-beginning) (region-end))
                  (list (point-min) (point-max)))))
    (save-excursion
      (save-restriction
        (narrow-to-region xbeg xend)
        (progn
          (goto-char (point-min))
          (while (re-search-forward "[ \t]+\n" nil t) (replace-match "\n")))
        (progn
          (goto-char (point-min))
          (while (re-search-forward "\n\n\n+" nil t) (replace-match "\n\n")))
        (progn
          (goto-char (point-max))
          (while (eq (char-before) 32) (delete-char -1))))))
  (message "done sp-clean-whitespace"))
#+end_src

** Run on every save

Adds the cleanup to the global =before-save-hook=, so every file is cleaned on save in every mode. Two consequences follow from the code:

- If a region is active when you save, only that region is cleaned.
- The blank line collapsing also applies inside code and source blocks.

Each save also prints the done message.

The hook also runs for the idle saves of =auto-save-visited-mode= and =lem-full-auto-save= (every 5 seconds of idle time, see =sp-backups=). Mid-sentence that stripped the space just typed at the end of a line and collapsed blank lines around point, which in an Org buffer moved text and broke the word being written. So the hook now calls =sp-clean-whitespace-before-save=, which skips the cleanup in the modes of =sp-clean-whitespace-autosave-skip-modes= (default =org-mode=, derived modes included) unless the save was asked for: =this-command= is =save-buffer=, =save-some-buffers= or =write-file=. Set the option to =nil= to clean on every save again. Calling =M-x sp-clean-whitespace= is unchanged. Not run in Emacs (none in the cloud container).

#+begin_src emacs-lisp -i
(defcustom sp-clean-whitespace-autosave-skip-modes '(org-mode)
  "Major modes in which saves not asked for by the user skip the cleanup.
The cleanup runs from `before-save-hook'.  The idle auto-saves of
`auto-save-visited-mode' and `lem-full-auto-save' also run that hook, so in
these modes (or modes derived from them) it would strip the space you have
just typed at the end of a line and collapse blank lines around point while
you are still writing.  An explicit save (`save-buffer', `save-some-buffers'
or `write-file') is always cleaned.  The command `sp-clean-whitespace' is
not affected."
  :type '(repeat symbol)
  :group 'spcustom)

(defun sp-clean-whitespace-before-save ()
  "Run `sp-clean-whitespace' before a save, unless an auto-save is under way.
See `sp-clean-whitespace-autosave-skip-modes'."
  (unless (and (apply #'derived-mode-p sp-clean-whitespace-autosave-skip-modes)
               (not (memq this-command
                          '(save-buffer save-some-buffers write-file))))
    (sp-clean-whitespace)))

(add-hook 'before-save-hook #'sp-clean-whitespace-before-save)
#+end_src

* Blank lines around Org headings

** Fix blank lines

=sp-org-fix-blank-lines=, from alphapapa's unpackaged.el, makes sure there is a blank line before every heading and between a heading (after its planning lines and drawers) and its body text.

- It acts on the current subtree, or on the whole buffer with a prefix argument.
- The widened buffer section is needed because =org-map-entries= narrows to each entry.
- Drawers are skipped with a regexp search because =org-at-drawer-p= misbehaves on hidden text.

#+begin_src emacs-lisp -i
;;;; Add whitespace before and after heading
;;
;; Ensure that blank lines exist between headings and between headings and their contents. 
;; With prefix, operate on whole buffer. Ensures that blank lines exist after each headings’s
;; drawers. Works on a subtree or a whole buffer. It also adds blank lines after drawers. 
;; Works well with *~org-return-dwim~.
;;
;; source: https://github.com/alphapapa/unpackaged.el#agenda-for-subtree-or-region

;;;###autoload
(defun sp-org-fix-blank-lines (&optional prefix)
  "Ensure that blank lines exist between headings and between headings and their contents.
With prefix, operate on whole buffer. Ensures that blank lines
exist after each headings's drawers."
  (interactive "P")
  (org-map-entries (lambda ()
                     (org-with-wide-buffer
                      ;; `org-map-entries' narrows the buffer, which prevents us from seeing
                      ;; newlines before the current heading, so we do this part widened.
                      (while (not (looking-back "\n\n" nil))
                        ;; Insert blank lines before heading.
                        (insert "\n")))
                     (let ((end (org-entry-end-position)))
                       ;; Insert blank lines before entry content
                       (forward-line)
                       (while (and (org-at-planning-p)
                                   (< (point) (point-max)))
                         ;; Skip planning lines
                         (forward-line))
                       (while (re-search-forward org-drawer-regexp end t)
                         ;; Skip drawers. You might think that `org-at-drawer-p' would suffice, but
                         ;; for some reason it doesn't work correctly when operating on hidden text.
                         ;; This works, taken from `org-agenda-get-some-entry-text'.
                         (re-search-forward "^[ \t]*:END:.*\n?" end t)
                         (goto-char (match-end 0)))
                       (unless (or (= (point) (point-max))
                                   (org-at-heading-p)
                                   (looking-at-p "\n"))
                         (insert "\n"))))
                   t (if prefix
                         nil
                       'tree)))
#+end_src

** Unfill a paragraph

=sp-unfill-paragraph=, from Stefan Monnier, joins a multi line paragraph into one line.

- It fills with a =fill-column= as large as the buffer.
- Binding =emacs-lisp-docstring-fill-column= to t stops Emacs Lisp docstrings from using their own fill column.
- Bound globally to =M-Q=, the shifted counterpart of =M-q=.

#+begin_src emacs-lisp -i
;;;;; Unfill Paragraph
;; Stefan Monnier <foo at acm.org>. It is the opposite of fill-paragraph
(defun sp-unfill-paragraph (&optional region)
  "Takes a multi-line paragraph and makes it into a single line of text."
  (interactive (progn (barf-if-buffer-read-only) '(t)))
  (let ((fill-column (point-max))
        ;; This would override `fill-column' if it's an integer.
        (emacs-lisp-docstring-fill-column t))
    (fill-paragraph nil region)))
(keymap-global-set "M-Q" #'sp-unfill-paragraph)
#+end_src

* Rich text copy

** Formatted copy

=formatted-copy= exports the active region, or the whole buffer, from Org to HTML in a temporary buffer (body only, visible text only).

- Pipes that HTML through macOS =textutil= to make RTF.
- Puts the result on the clipboard with =pbcopy=.
- This lets Org text be pasted with formatting into apps like Mail or Word.
- It only works on macOS.
- The local =html= variable is computed but not used.

#+begin_src emacs-lisp -i
;;;;; Formatted Copy
(defun formatted-copy ()
  "Export region to HTML, and copy it to the clipboard."
  (interactive)
  (save-window-excursion
    (let* ((buf (org-export-to-buffer 'html "*Formatted Copy*" nil nil t t))
           (html (with-current-buffer buf (buffer-string))))
      (with-current-buffer buf
        (shell-command-on-region
         (point-min)
         (point-max)
         "textutil -stdin -format html -convert rtf -stdout | pbcopy"))
      (kill-buffer buf))))
#+end_src

* Abbreviations

** Abbrev mode

Configures the built-in =abbrev= package, deferred two seconds after startup.

- Abbrevs are stored in =abbrev/.abbrev_defs= under =sp-var-dir=.
- They are not saved automatically, and are read in silently if the file exists.
- Enabling =abbrev-mode= in text buffers is left commented out, so abbrevs only expand where the mode is turned on some other way.

#+begin_src emacs-lisp -i
;; Abbreviation

(use-package abbrev
  :ensure nil
  :defer 2
  :config
  ;; (add-hook 'text-mode-hook #'abbrev-mode)
  (setq abbrev-file-name (concat sp-var-dir "abbrev/.abbrev_defs")
        save-abbrevs 'nil)
  (if (file-exists-p abbrev-file-name)
      (quietly-read-abbrev-file)))

* Smart yanking

Marcin Borkowski's smart yanking moves point before a yank so that you do not end up with doubled spaces.

** Whitespace at the edges of a string

=has-space-at-boundary-p= reports whether a string starts with whitespace, ends with it, both or neither.

#+begin_src emacs-lisp -i
;;;;; Smart Yanking
;;Courtesy of Marcin Borkowski http://mbork.pl/2018-07-02_Smart_yanking

(defun has-space-at-boundary-p (string)
  "Check whether STRING has any whitespace on the boundary.
      Return 'left, 'right, 'both or nil."
  (let ((result nil))
    (when (string-match-p "^[[:space:]]+" string)
      (setq result 'left))
    (when (string-match-p "[[:space:]]+$" string)
      (if (eq result 'left)
          (setq result 'both)
        (setq result 'right)))
    result))
#+end_src

** Whitespace around point

=is-there-space-around-point-p= reports the same for the text immediately before and after point.

#+begin_src emacs-lisp -i
(defun is-there-space-around-point-p ()
  "Check whether there is whitespace around point.
      Return 'left, 'right, 'both or nil."
  (let ((result nil))
    (when (< (save-excursion
               (skip-chars-backward "[:space:]"))
             0)
      (setq result 'left))
    (when (> (save-excursion
               (skip-chars-forward "[:space:]"))
             0)
      (if (eq result 'left)
          (setq result 'both)
        (setq result 'right)))
    result))
#+end_src

** Adjust point

=set-point-before-yanking= compares the yanked text with the text before point:

- If both have leading space, it moves back over that space.
- If both have trailing space, it moves forward over it.
- So the yanked spaces replace the existing ones rather than adding to them.
- It only moves point. The existing space is not deleted, so the effect is on where the text lands.

#+begin_src emacs-lisp -i
(defun set-point-before-yanking (string)
  "Put point in the appropriate place before yanking STRING."
  (let ((space-in-yanked-string (has-space-at-boundary-p string))
        (space-at-point (is-there-space-around-point-p)))
    (cond ((and (eq space-in-yanked-string 'left)
                (eq space-at-point 'left))
           (skip-chars-backward "[:space:]"))
          ((and (eq space-in-yanked-string 'right)
                (eq space-at-point 'right))
           (skip-chars-forward "[:space:]")))))
#+end_src

** Text modes only

=set-point-before-yanking-if-in-text-mode= limits the adjustment to buffers derived from =text-mode=, which includes Org and Markdown but not programming modes.

#+begin_src emacs-lisp -i
(defun set-point-before-yanking-if-in-text-mode (string)
  "Invoke `set-point-before-yanking' in text modes."
  (when (derived-mode-p 'text-mode)
    (set-point-before-yanking string)))
#+end_src
