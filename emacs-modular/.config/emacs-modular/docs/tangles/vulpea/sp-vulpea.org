Literate source for the Vulpea modules in =libraries/modules/vulpea/=.

- One file tangles thirteen =.el= files, one per module, each with its own =provide=.
- No module loads them as a group; =sp-org-ext= requires them.
- Each part sets its =:tangle= path in the =:header-args:emacs-lisp+:= property of its top-level heading.
- The =#+PROPERTY= line above is =:tangle no=, so a block outside a part is not written.
- To tangle, see [[file:../../tangling-instructions.org][Tangling instructions]].

The sub-modules are not new.

- Old homes in =libraries/modules/text/=: =sp-vulpea-base=, =sp-vulpea-ui=, =sp-vulpea-para=, =sp-vulpea-schemas=, =sp-vulpea-ext=, =sp-vulpea-ext-back= and =sp-vulpea-split=.
- Old homes in =libraries/modules/funct/=: =sp-vulpea-convert-properties=, =sp-vulpea-grouped-backlinks= and =sp-vulpea-org-ql=.
- Each keeps its own doc.
- The code is unchanged.
- Most files have no newline after their last line. Org always ends a tangled file with one, so tangling adds that newline and changes nothing else.

The table modules (=sp-collection-query=, a custom module of mine) are deliberately not part of this group; they have their own doc, =docs/tangles/funct/sp-collection-query.org=, and are loaded by =sp-org-ext= right after these.

* sp-vulpea-base.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-base.el
:END:

This module sets up =vulpea=, a library and database layer for Org-based notes (an alternative to org-roam), together with =vui=, the UI component library used by other Vulpea modules such as =sp-collection-query-vui=. It is required from =sp-org-ext=, and the further Vulpea extensions live in =sp-vulpea-ext=.

It configures which directories are indexed, how notes are displayed in the minibuffer, which property stores aliases, and how new note files are named. Several settings are given twice (once in =use-package= and once with a plain =setq=), and the plain =setq= forms run at load time, so they win.

*** vulpea

Installs =vulpea= and waits for it to finish, so later code can call its functions immediately.

- The empty =:init= only carries a comment copied from Doom-oriented documentation about =org-directory=.
- =vulpea-db-sync-directories= is set further down.

Keybindings:
- ~M-o n a~ in Org buffers runs =vulpea-buffer-alias-add= to add an alias to the current note.
- ~M-o n n~ in Org buffers runs =org-id-get-create= to give the entry at point (or the file, before the first heading) an ID.
  + It is the successor of the =M-o n n= of the removed =org-node= module (=org-node-nodeify-entry=), so the key is not new to the hand.
- ~M-o f~ is =sp-find-note= (module =sp-org-tag-groups=), not =vulpea-find=, so notes show their tag emoji and colours.

#+begin_src emacs-lisp -i
(use-package vulpea
  :ensure (:wait t)

  :init
  ;; Vulpea derives its defaults from `org-directory'. Doom's :lang org
  ;; module sets it to ~/org/ - override here if your notes live elsewhere,
  ;; or set `vulpea-db-sync-directories' explicitly.

  :bind
  (:map org-mode-map
   ("M-o n a" . vulpea-buffer-alias-add)
   ("M-o n n" . org-id-get-create))
)
#+end_src

** Database settings

*** Synced directories

Sets =vulpea-db-sync-directories= to the folders Vulpea indexes.

- =sp-notes-dir=: the notes (=~/notes/=).
- =user-emacs-directory=: the Emacs config, so its Org docs are indexed too.
- =sp-writing-projects=: the writing projects (=~/Documents/writing/= by default, see =sp-globals=).
  - To use another folder, customize =sp-writing-projects= instead of editing this list.
  - Its =:ID:= entries are indexed, so they can be linked from the notes.
  - A file there gets the agenda tag on save once it holds an open TODO heading (any =org-todo-keywords= keyword), so those headings reach the agenda through =vulpea-para=.
  - For files that already have open TODOs, run =M-x vulpea-para-agenda-backfill= once.
- A folder that does not exist is left out, so a missing =~/Documents/writing/= does not break the scan. Restart, or re-evaluate the form, after creating it.
- After adding a folder, run =M-x vulpea-db-sync-full-scan= (or restart) to index it.

#+begin_src emacs-lisp -i
(setq vulpea-db-sync-directories
      (seq-filter #'file-directory-p
                  (list sp-notes-dir user-emacs-directory sp-writing-projects)))

;; The database is rebuilt from the notes, so it lives in `var/' (Git ignores
;; it) and not in the config folder, where Vulpea puts it by default.
(setq vulpea-db-location (expand-file-name "vulpea.db" sp-var-dir))
#+end_src

*** Database location

=vulpea-db-location= is =vulpea.db= under =sp-var-dir=. Vulpea's own default is a file in the config folder (=user-emacs-directory=), where it was one of the binary files Git had to be told to ignore. The database is rebuilt from the notes, so it can be deleted; the next scan indexes the vault again. It is set in the block above, together with the synced directories. Anything that reads the location (for example the file watcher of =sp-graphs=) reads =vulpea-db-location=, so nothing else had to change.

*** Parse method

=single-temp-buffer= makes Vulpea parse files by reusing one temporary buffer, which is faster than visiting each file normally.

#+begin_src emacs-lisp -i
(setq vulpea-db-parse-method 'single-temp-buffer)
#+end_src

*** Automatic database sync

Turns on =vulpea-db-autosync-mode=, which keeps the database updated as note files change, =sp-vulpea-autosync-delay= idle seconds (10 by default) after start-up (=sp-vulpea-start-autosync=) instead of while =init.el= loads. Emacs starts with the database as the last session left it, which queries and the agenda files can already use.

- =sp-vulpea-start-autosync= enables the mode only once: it cancels the pending timer and does nothing if the mode is already on.
- =sp-vulpea-schedule-autosync= sets the idle timer; it runs from =emacs-startup-hook=, or at once if init is already over (for example when the module is reloaded).
- =sp-find-note= (=M-o f=) calls =sp-vulpea-start-autosync= too, so the picker never runs with autosync off, even before the timer fires.
- Enabling the mode returns fast: the first scan is the background one below, so there is no long freeze from the enable itself. The echo area shows the time it took.

- =vulpea-db-sync-scan-on-enable= is =background=: the files are listed by a subprocess and queued, and the queue parses only the files whose content changed since the last scan, in batches while Emacs is idle. Changes made outside Emacs (a git pull, a sync) are picked up that way.
- Nothing depends on which file is opened first. Before, the scan started two idle seconds after the first vault file was visited, which the dashboard did by reading the agenda files, and it ran =vulpea-db-sync-full-scan= in the foreground (listing, cleanup and dir-locals check in the main Emacs), which froze it.
- =vulpea-select-cache-prewarm= is set to nil: with it on, vulpea reads every row of the database into a candidate cache for =vulpea-find= and =vulpea-insert= as soon as autosync starts, in 500-note chunks on the main thread (about 56% of the CPU in a batch profile of the real vault). Now the cache is built at the first =vulpea-find= or =vulpea-insert=, which pauses once. Not run in Emacs here.
- The echo area shows =[vulpea] starting autosync...= and how long it took, then vulpea's own progress messages.
- =M-x vulpea-db-sync-full-scan= is still there for a scan by hand, and =C-u= forces a re-index. Not run in Emacs here (none in the container).

#+begin_src emacs-lisp -i
;; Enable autosync a few idle seconds after start-up, not during init, and let
;; vulpea scan in the background: it lists the files in a subprocess and queues
;; them, and the queue parses only the files whose content changed.  Opening a
;; note, the dashboard included, starts nothing.
(setq vulpea-db-sync-scan-on-enable 'background)

(defcustom sp-vulpea-autosync-delay 10
  "Idle seconds after start-up before `vulpea-db-autosync-mode' is turned on.
The scan runs in the background (see `vulpea-db-sync-scan-on-enable'), so a
short wait is enough: it only lets start-up finish and Emacs become usable."
  :type 'number
  :group 'spcustom)

;; Vulpea builds a candidate cache of every note for `vulpea-find' and
;; `vulpea-insert' as soon as autosync is on, reading all rows of the database
;; in 500-note chunks on the main thread (`vulpea-select-cache-prewarm').  With
;; about 9,800 files that kept Emacs busy for minutes.  Without the prewarm the
;; cache is built at the first `vulpea-find' or `vulpea-insert', which pauses once.
(setq vulpea-select-cache-prewarm nil)

(defvar sp-vulpea--autosync-timer nil
  "Idle timer that will call `sp-vulpea-start-autosync', or nil.")

(defun sp-vulpea-start-autosync ()
  "Turn on `vulpea-db-autosync-mode' once, if it is not on yet.
The vault is scanned in the background.  Safe to call any number of times."
  (when (timerp sp-vulpea--autosync-timer)
    (cancel-timer sp-vulpea--autosync-timer))
  (setq sp-vulpea--autosync-timer nil)
  (unless (bound-and-true-p vulpea-db-autosync-mode)
    (let ((started (float-time)))
      (message "[vulpea] starting autosync; changed files are indexed in the background...")
      (vulpea-db-autosync-mode +1)
      (message "[vulpea] autosync started in %.2fs" (- (float-time) started)))))

(defun sp-vulpea-schedule-autosync ()
  "Start `sp-vulpea-start-autosync' after `sp-vulpea-autosync-delay' idle seconds."
  (unless (or (bound-and-true-p vulpea-db-autosync-mode)
              (timerp sp-vulpea--autosync-timer))
    (setq sp-vulpea--autosync-timer
          (run-with-idle-timer sp-vulpea-autosync-delay nil
                               #'sp-vulpea-start-autosync))))

;; Init is over when `after-init-time' is set; then the hook has already run.
(if after-init-time
    (sp-vulpea-schedule-autosync)
  (add-hook 'emacs-startup-hook #'sp-vulpea-schedule-autosync))
#+end_src

** Templating for new notes

*** Default note creation

=vulpea-create-default-function= decides the file name and tags for a new note.

- Files are named with a timestamp followed by a slug of the title.
- If the title contains the string TODO, the note gets the tag task. Otherwise it gets note.

#+begin_src emacs-lisp -i
;; Templating for Vulpea

(setq vulpea-create-default-function
      (lambda (title)
        (list :file-name (format "%s_%s.org"
                                 (format-time-string "%Y%m%d%H%M%S")
                                 (vulpea-title-to-slug title))
              :tags (if (string-match-p "TODO" title)
                        '("task")
                      '("note")))))
#+end_src

* sp-vulpea-ui.el

** Sidebar

*** Installing vulpea-ui

Installs =vulpea-ui=, waiting for the install to finish so the settings below apply to a loaded package. The =:config= block is empty. All =vulpea-ui-= options are set in =:custom= (they used to be top-level =setq= forms after the =use-package=), and the sections below describe them. There is no =:after vulpea=: Vulpea itself loads lazily (from its own =:bind=), so waiting for it left =vulpea-ui= unloaded and =C-x t s= undefined. =vulpea-ui= requires Vulpea when it loads.

  :custom

  ;; Size as fraction of frame (0.0-1.0)
  (vulpea-ui-sidebar-size 0.33)
  ;; Maximum heading depth (nil = unlimited)
  (vulpea-ui-outline-max-depth 3)
  ;; Utility functions for vulpea-ui
  (vulpea-ui-auto-refresh t)  ;; So you don't have to constantly do a manual refresh.
  ;; Respect narrowing in the sidebar

** Links in collection views

=vulpea-ui= draws the cells of a collection view as plain strings in a =tabulated-list=, so a meta value such as =[[ID:806b...][Thesis]]= showed raw, and a bare ID showed as a string of digits. =sp-vulpea-ui-collection-link-ids= is =:around= advice on =vulpea-ui-collection--column-raw-value=: for =meta=, =property= and =fn= columns it runs the value through =sp-org-link-link-ids= (a bare ID that is a note becomes its title as a link; =[[ID:..]]= becomes =[[id:..]]=) and =sp-org-link-linkify= (both in =sp-org-id-link=). The cell then shows the description in =org-link= face, and RET or a click on it follows the link, while RET elsewhere in the row still visits the note. Column widths and sorting use the shown text. The column's own tooltip (the full text) replaces the link's.

#+begin_src emacs-lisp -i
;; IDs in the collection views as links
(defun sp-vulpea-ui-collection-link-ids (orig note col ctx)
  "Show IDs in meta, property and computed cells as Org links.
Around `vulpea-ui-collection--column-raw-value' (ORIG, NOTE, COL, CTX): a
bare note ID becomes the title of its note, and links are shown by their
description, in `org-link' face, followed with RET or a click."
  (let ((value (funcall orig note col ctx)))
    (if (and (memq (plist-get col :id) '(meta property fn))
             (stringp value) (not (string-empty-p value)))
        (sp-org-link-linkify (sp-org-link-link-ids value))
      value)))

(advice-add 'vulpea-ui-collection--column-raw-value :around

*** Agenda mode

Turns on =vulpea-para-agenda-mode=.

- Vault buffers maintain their =agenda= tag when saved.
- =org-agenda-files= is refreshed from the database before =org-agenda= and =org-todo-list=.
- Views that restrict the files themselves bind =vulpea-para-agenda-inhibit-files-update= (see =sp-agenda-views=).
- Entry points that bypass both (the splash, =sp-trails=) read the variable as last set, so it is also refreshed once, shortly after start-up, when the database is ready. (defvar sp-dashboard-agenda-ready)
(declare-function sp-dashboard-refresh-agendas "sp-dashboard")

;; The dashboard waits for the agenda files instead of reading the wrong ones.
(setq sp-dashboard-agenda-ready nil)

(defun sp-vulpea-para-refresh-agenda-files ()
  "Set `org-agenda-files' from the database, ignoring errors.
Then tell the dashboard, which waits for them, and redraw it."
  (let ((started (float-time)))
    (message "[vulpea-para] setting the agenda files from the database...")
    (condition-case err
        (progn
          (vulpea-para-agenda-files-update)
          (message "[vulpea-para] %d agenda files set in %.2fs"
                   (length org-agenda-files) (- (float-time) started)))
      (error (message "[vulpea-para] agenda files not set yet: %s"
                      (error-message-string err))))
    (setq sp-dashboard-agenda-ready t)
    (when (fboundp 'sp-dashboard-refresh-agendas)
      (sp-dashboard-refresh-agendas))))

(add-hook 'emacs-startup-hook
          (lambda ()
            (run-with-idle-timer 3 nil #'sp-vulpea-para-refresh-agenda-files)))

* sp-vulpea-schemas.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-schemas.el

Declares the note types (schemas) used in the Vulpea knowledge base, with =vulpea-schema-define=.

- Each schema says which notes it applies to, through a predicate that checks for a particular Org tag.
- Each schema lists the meta fields such notes should have. A field has:
  - a key,
  - a type (=string=, =number= or =note= for a link to another note),
  - whether it is required,
  - whether it may hold several values,
  - for links, which tags the target note should carry.
- A schema can inherit fields from another with =:include=.

The schemas cover:

- music (albums, musicians, groups),
- questions and research inquiries,
- people and organisations,
- software,
- literature notes.

The table and sidebar code in =sp-vulpea-ui= and the =sp-collection-query= modules builds on these definitions.

- =sp-org-ext= requires this module after =sp-vulpea-base=.
- It assumes Vulpea is already loaded, since it calls =vulpea-schema-define= at top level.

** Converting a single node

These functions operate on the "node at point": the heading at or above point, or the file-level node when point is before the first heading.

*** Finding the insertion point

=sia-vulpea--after-property-drawer-pos= returns the position right after the node's property drawer.

- For a heading: after its drawer, or after the heading line when there is none.
- For the file-level node: it also skips any leading =#+KEYWORD:= lines, in any order relative to the drawer.
- So meta lines never end up above =#+title:= or =#+date:= when the drawer comes first in the file.

#+begin_src emacs-lisp -i
;;;; Low-level: one node at a time ---------------------------------------

(defun sia-vulpea--after-property-drawer-pos ()
  "Return the position right after the property drawer of the node at point.
\"Node at point\" is the heading at or above point, or the
file-level node if point is before the first heading.

For a heading, this is simply right after its own drawer (or
right after the heading line, if it has none).

For the file-level node, this additionally skips past any
leading #+KEYWORD: lines (#+title:, #+date:, #+filetags:, etc.)
in whatever order they appear relative to the property drawer.
Without this, meta lines inserted \"right after the drawer\"
would land *above* #+title:/#+date: whenever the drawer happens
to come first in the file -- which is exactly the bug this
guards against."
  (save-excursion
    (if (org-before-first-heading-p)
        (progn
          (goto-char (point-min))
          (let (moved)
            (setq moved t)
            (while moved
              (setq moved nil)
              (cond
               ((looking-at "^[ \t]*:PROPERTIES:[ \t]*$")
                (re-search-forward "^[ \t]*:END:[ \t]*$" nil t)
                (forward-line 1)
                (setq moved t))
               ((looking-at "^[ \t]*#\\+[a-zA-Z_-]+:.*$")
                (forward-line 1)
                (setq moved t)))))
          (point))
      (org-back-to-heading t)
      (forward-line 1)
      (if (looking-at "^[ \t]*:PROPERTIES:[ \t]*$")
          (progn (re-search-forward "^[ \t]*:END:[ \t]*$" nil t)
                 (forward-line 1)
                 (point))
        (point)))))
#+end_src

*** Inserting or updating a meta line

=sia-vulpea--insert-or-update-meta-line= writes =- KEY :: VALUE= right after the drawer. If a line for the same key already exists between the drawer and the next heading, its value is replaced instead, so re-running a conversion does not create duplicates.

#+begin_src emacs-lisp -i
(defun sia-vulpea--insert-or-update-meta-line (key value)
  "Insert or update a \"- KEY :: VALUE\" meta line for the node at point.
Placed right after that node's property drawer. If a meta line
for KEY already exists between the drawer and the next heading
(or end of file, for the file-level node), its value is replaced
instead of adding a duplicate -- so re-running a conversion is
safe and idempotent."
  (let* ((start (sia-vulpea--after-property-drawer-pos))
         (end (save-excursion
                (goto-char start)
                (if (re-search-forward "^\\*" nil t) (line-beginning-position) (point-max))))
         (re (format "^\\(-[ \t]+%s[ \t]+::[ \t]*\\).*$" (regexp-quote key))))
    (save-excursion
      (goto-char start)
      (if (re-search-forward re end t)
          (replace-match (concat "\\1" value) t)
        (goto-char start)
        (insert (format "- %s :: %s\n" key value))))))
#+end_src

*** Separating blank line

=sia-vulpea--ensure-blank-line-before-meta= inserts a newline before the meta block only if the preceding line is not already blank, which again keeps repeated runs idempotent.

#+begin_src emacs-lisp -i
(defun sia-vulpea--ensure-blank-line-before-meta ()
  "Ensure a blank line separates the node at point's property
drawer (and, for the file-level node, its #+KEYWORD: lines) from
the meta block that begins right after them -- see
`sia-vulpea--after-property-drawer-pos'. Only inserts a newline
if the line immediately before that position isn't already
blank, so re-running a conversion never piles up extra blank
lines."
  (save-excursion
    (goto-char (sia-vulpea--after-property-drawer-pos))
    (unless (or (bobp)
                (save-excursion (forward-line -1) (looking-at "^[ \t]*$")))
      (insert "\n"))))
#+end_src

*** Converting a node's properties

=sia-vulpea--convert-node-properties= walks the node's standard properties.

- Skips blocklisted names and empty values.
- Writes each remaining one as a meta line with a downcased key.
- Deletes it from the drawer unless =keep-original= is non-nil.
- Adds the separating blank line once if anything was converted.
- Returns the list of converted property names.

#+begin_src emacs-lisp -i
(defun sia-vulpea--convert-node-properties (&optional keep-original)
  "Convert the node at point's own drawer properties to meta lines.
\"Node at point\" is the heading at or above point, or the
file-level node if point is before the first heading. Only
properties not in `sia-vulpea-convert-property-blocklist', and
with a non-empty value, are converted; the property name is
downcased for the meta key. Unless KEEP-ORIGINAL is non-nil, each
converted property is then deleted from the drawer. If anything
was converted, a blank line is inserted before the meta block
(once, however many properties were converted) to separate it
from the drawer/front matter above -- see
`sia-vulpea--ensure-blank-line-before-meta'. Returns the list of
property names converted (empty if none)."
  (save-excursion
    (unless (org-before-first-heading-p) (org-back-to-heading t))
    (let ((converted nil))
      (dolist (prop (org-entry-properties (point) 'standard))
        (let ((name (car prop)) (value (cdr prop)))
          (unless (or (member (upcase name) sia-vulpea-convert-property-blocklist)
                      (null value)
                      (string-empty-p value))
            (sia-vulpea--insert-or-update-meta-line (downcase name) value)
            (push name converted)
            (unless keep-original (org-entry-delete (point) name)))))
      (when converted
        (sia-vulpea--ensure-blank-line-before-meta))
      (nreverse converted))))
#+end_src

*** Fast pre-scan of a file

=sia-vulpea--file-has-convertible-properties-p= reads a file as plain text in a temporary buffer.

- Looks for any =:NAME: value= line whose name is not =PROPERTIES=, =END= or blocklisted, and whose value is non-empty.
- Does not start =org-mode=, so it is cheap.
- May give false positives (a matching line outside a drawer). These only cost an unneeded file visit later.
- Is meant never to miss a convertible file.

#+begin_src emacs-lisp -i
(defun sia-vulpea--file-has-convertible-properties-p (file)
  "Non-nil if FILE's raw text contains at least one property-drawer
line whose name isn't in `sia-vulpea-convert-property-blocklist'
and whose value is non-empty.

This is a fast, structure-agnostic text scan -- no `org-mode', no
Vulpea db -- meant only as a pre-filter before the real,
buffer-based conversion. It doesn't require FILE to actually be
visited or parsed as Org, just read as text, which is what makes
it cheap. A false positive here (matching something that isn't
really inside a drawer) just means a file gets opened for
nothing during the real pass, which is harmless -- so the regex
doesn't need to be a perfect drawer parser, only a conservative
one that never produces a false *negative*."
  (with-temp-buffer
    (insert-file-contents file)
    (goto-char (point-min))
    (catch 'found
      (while (re-search-forward
              "^[ \t]*:\\([A-Za-z_][A-Za-z0-9_-]*\\):[ \t]+\\(.+\\)$" nil t)
        (let ((name (match-string 1)) (value (match-string 2)))
          (unless (or (member (upcase name) '("PROPERTIES" "END"))
                      (member (upcase name) sia-vulpea-convert-property-blocklist)
                      (string-empty-p (string-trim value)))
            (throw 'found t))))
      nil)))
#+end_src

*** Cooperative file loop

=sia-vulpea--process-files-async= processes a list of files one at a time.

- Visits each with =find-file-noselect= and calls a per-file function in that buffer.
- After each file, schedules the next with a zero-second timer. That returns control to the command loop, so redisplay happens and =C-g= works between files.
- The docstring is explicit that this is cooperative yielding, not true background work.
- A progress reporter shows N/TOTAL and an ETA from the average time per file.
- =on-done= receives all results in order at the end.
- Visited buffers are left open.

#+begin_src emacs-lisp -i
(defun sia-vulpea--process-files-async (files per-file-fn label on-done)
  "Call PER-FILE-FN once per file in FILES, one at a time, without
freezing Emacs for the whole run.

Each file is handled, then the *next* one is scheduled via a
fresh zero-second timer instead of just continuing a tight
`dolist' loop -- that gap is what hands control back to Emacs's
command loop between files, so redisplay happens, `C-g' still
works, and the UI doesn't lock up. To be fully transparent about
what this is and isn't: stock Emacs has no threads that run
Elisp concurrently, so nothing here runs \"in the background\"
while you keep typing in another buffer -- it's cooperative
yielding, not true parallelism. (Emacs 26+ built with
`--with-threads' does have `make-thread', but Elisp execution
under it is still serialized by a global lock, so it wouldn't
actually speed this up or free the UI thread the way OS threads
would -- it's not used here.) What you do get is a UI that stays
responsive and interruptible for the whole duration of a large
batch, which a plain loop over hundreds of files would not give
you.

PER-FILE-FN is called with one file path, current-buffer already
that file's buffer (via `find-file-noselect'); its return value
is collected. LABEL is shown alongside a live N/TOTAL count and
an ETA, estimated from the average time per file so far. ON-DONE
is called with the list of all per-file return values, in the
same order as FILES, once every file has been processed."
  (let* ((total (length files))
         (reporter (make-progress-reporter (format "%s " label) 0 total))
         (start-time (current-time))
         (i 0)
         (results nil))
    (cl-labels
        ((step ()
           (if (null files)
               (progn
                 (progress-reporter-done reporter)
                 (funcall on-done (nreverse results)))
             (let ((file (pop files)))
               (push (with-current-buffer (find-file-noselect file)
                       (funcall per-file-fn file))
                     results)
               (setq i (1+ i))
               (progress-reporter-update
                reporter i
                (format " (%d/%d, ETA %s)" i total
                        (sia-vulpea--format-duration
                         (if (zerop i)
                             0
                           (* (/ (float-time (time-subtract (current-time) start-time)) i)
                              (- total i))))))
               (run-with-timer 0 nil #'step)))))
      (step))))
#+end_src

*** Preview across all notes

* sp-vulpea-convert-keywords.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-convert-keywords.el
:END:

This module moves note metadata out of the file header and into Vulpea meta lines.

- A file-header keyword is a line like =#+bib-project: thesis= in the first section of a note.
- The result is the meta line =- bib-project :: thesis=, placed after the header, where Vulpea indexes it.
- It is the sibling of =sp-vulpea-convert-properties=, which does the same for property drawer entries.

How it works:

- It lists every header keyword it finds, with how many notes use it and an example value, and you pick the ones to convert with =completing-read-multiple=.
- =#+title:= and =#+date:= are never offered by default; the list is the option =sp-vulpea-convert-keywords-ignore=.
- The default scope is the current note. With =C-u= (or =sp-vulpea-convert-keywords-all-notes=) it scans every note Vulpea knows about, and the list shows keys across all of them.
- Before anything is written, a preview buffer shows each note and the meta lines it would get, and you confirm.
- The original keyword line is removed after conversion, unless =sp-vulpea-convert-keywords-remove-original= is nil.
- A keyword that appears several times (for example two =#+bib-project:= lines) becomes several meta lines with the same key, which Vulpea reads as a list.
- Running it again does nothing: a meta line that already exists with the same key and value is not added twice.
- Only the first section is scanned, using the Org parser, so a =#+key:= line inside a source block or below a heading is left alone.
- The current note is edited but not saved, so =C-/= undoes it. In the all-notes run each file is saved, and a file with unsaved changes in Emacs is skipped and reported.

Dependencies:

- Requires =org=, =org-element=, =seq=, =subr-x= and =sp-vulpea-convert-properties=, whose helpers find where meta lines go.
- Uses =vulpea-db-query= only for the all-notes scope.
- Loaded from =sp-vulpea-ext=. It binds no key; use =M-x sp-vulpea-convert-keywords=.

** Reading the header

*** Finding the keywords

=sp-vulpea-convert-keywords--scan-buffer= returns the top-level keywords of the first section of the current buffer as plists with =:key= (lower case), =:value=, =:beg= and =:end= (the whole line, including its newline). It narrows to the text before the first heading and uses the Org parser, so blocks are skipped. It takes no ignore list; callers filter.

#+begin_src emacs-lisp -i
(defun sp-vulpea-convert-keywords--ignored-p (key)
  "Non-nil if KEY is in `sp-vulpea-convert-keywords-ignore'."
  (member (downcase key) (mapcar #'downcase sp-vulpea-convert-keywords-ignore)))

(defun sp-vulpea-convert-keywords--scan-buffer ()
  "Return the header keywords of the current buffer, in order.
Each is a plist (:key KEY :value VALUE :beg BEG :end END), KEY in
lower case, BEG..END the whole line with its newline. Only
top-level keywords before the first heading count."
  (save-excursion
    (save-restriction
      (widen)
      (goto-char (point-min))
      (narrow-to-region
       (point-min)
       (if (re-search-forward org-outline-regexp-bol nil t)
           (match-beginning 0)
         (point-max)))
      (let* ((tree (org-element-parse-buffer))
             (section (car (org-element-contents tree)))
             found)
        (when (and section (eq (org-element-type section) 'section))
          (dolist (el (org-element-contents section))
            (when (eq (org-element-type el) 'keyword)
              (let ((beg (org-element-property :begin el)))
                (push (list :key (downcase (org-element-property :key el))
                            :value (string-trim (or (org-element-property :value el) ""))
                            :beg beg
                            :end (save-excursion
                                   (goto-char beg)
                                   (forward-line 1)
                                   (point)))
                      found)))))
        (nreverse found)))))

(defun sp-vulpea-convert-keywords--convertible (&optional keys)
  "Header keywords of the current buffer that could be converted.
Drops ignored keys and empty values. With KEYS, keeps only those."
  (seq-filter
   (lambda (e)
     (and (not (string-empty-p (plist-get e :value)))
          (not (sp-vulpea-convert-keywords--ignored-p (plist-get e :key)))
          (or (null keys) (member (plist-get e :key) keys))))
   (sp-vulpea-convert-keywords--scan-buffer)))
#+end_src

*** Collecting the choices

=sp-vulpea-convert-keywords--collect= takes a list of sources, each a file name or a buffer, and returns an alist of =(KEY . (:count N :example VALUE))=, where N is the number of sources that have the key. A file is read in a temporary Org buffer without hooks; one with no =#+key:= line other than ignored ones is not parsed at all.

#+begin_src emacs-lisp -i
(defun sp-vulpea-convert-keywords--file-may-have-keys-p ()
  "Non-nil if the current buffer has a `#+key:' line that is not ignored.
A cheap text check, used to skip parsing files that cannot match."
  (save-excursion
    (goto-char (point-min))
    (catch 'found
      (while (re-search-forward "^#\\+\\([A-Za-z0-9_-]+\\):" nil t)
        (unless (sp-vulpea-convert-keywords--ignored-p (match-string 1))
          (throw 'found t)))
      nil)))

(defun sp-vulpea-convert-keywords--call-on-source (source fn)
  "Call FN in SOURCE, a buffer or a file name, and return its value.
A file is read into a temporary Org buffer; SOURCE is not visited."
  (if (bufferp source)
      (with-current-buffer source (funcall fn))
    (with-temp-buffer
      (insert-file-contents source)
      (when (sp-vulpea-convert-keywords--file-may-have-keys-p)
        (delay-mode-hooks (org-mode))
        (funcall fn)))))

(defun sp-vulpea-convert-keywords--collect (sources)
  "Return (KEY . (:count N :example VALUE)) for the keywords in SOURCES.
SOURCES are buffers or file names. N counts the sources having
KEY; the list is sorted by KEY."
  (let ((table (make-hash-table :test #'equal))
        (reporter (and (> (length sources) 20)
                       (make-progress-reporter "Scanning header keywords " 0 (length sources))))
        (i 0))
    (dolist (source sources)
      (let ((seen nil))
        (dolist (e (sp-vulpea-convert-keywords--call-on-source
                    source #'sp-vulpea-convert-keywords--convertible))
          (let ((key (plist-get e :key)))
            (unless (member key seen)
              (push key seen)
              (let ((old (gethash key table)))
                (puthash key (list :count (1+ (if old (plist-get old :count) 0))
                                   :example (if old (plist-get old :example) (plist-get e :value)))
                         table))))))
      (when reporter (progress-reporter-update reporter (cl-incf i))))
    (when reporter (progress-reporter-done reporter))
    (let (alist)
      (maphash (lambda (k v) (push (cons k v) alist)) table)
      (sort alist (lambda (a b) (string< (car a) (car b)))))))
#+end_src

** Writing meta lines

*** Placing the lines

=sp-vulpea-convert-keywords--insert-meta= puts the pairs after the header, where =sia-vulpea--after-property-drawer-pos= says the meta block starts.

- If a meta block already follows (after at most blank lines), the new lines go at its top, so the list stays in one piece.
- Otherwise they are inserted there and separated from the header, and from any text after, by a blank line.
- A pair already present with the same key and value is skipped.

#+begin_src emacs-lisp -i
(defun sp-vulpea-convert-keywords--meta-present-p (key value start end)
  "Non-nil if \"- KEY :: VALUE\" is a line between START and END."
  (save-excursion
    (goto-char start)
    (re-search-forward
     (format "^-[ \t]+%s[ \t]+::[ \t]+%s[ \t]*$"
             (regexp-quote key) (regexp-quote value))
     end t)))

(defun sp-vulpea-convert-keywords--insert-meta (pairs)
  "Insert meta lines for PAIRS, a list of (KEY . VALUE), in the first section.
Returns the pairs that were added (those not already present)."
  (save-excursion
    (goto-char (point-max))
    (unless (or (bobp) (bolp)) (insert "\n"))
    (goto-char (point-min))
    (let* ((start (sia-vulpea--after-property-drawer-pos))
           (end (save-excursion
                  (goto-char start)
                  (if (re-search-forward org-outline-regexp-bol nil t)
                      (match-beginning 0)
                    (point-max))))
           (new (seq-remove
                 (lambda (p)
                   (sp-vulpea-convert-keywords--meta-present-p
                    (car p) (cdr p) start end))
                 pairs)))
      (when new
        (let ((text (mapconcat (lambda (p) (format "- %s :: %s\n" (car p) (cdr p)))
                               new ""))
              (meta-below (save-excursion
                            (goto-char start)
                            (skip-chars-forward " \t\n")
                            (beginning-of-line)
                            (and (looking-at "-[ \t]+[^ \t\n]+[ \t]+::")
                                 (point)))))
          (if meta-below
              (progn (goto-char meta-below) (insert text))
            (goto-char start)
            (insert text)
            (unless (or (eobp) (looking-at "[ \t]*$")) (insert "\n"))
            (sia-vulpea--ensure-blank-line-before-meta))))
      new)))
#+end_src

*** Converting one buffer

=sp-vulpea-convert-keywords--plan= returns the =(KEY . VALUE)= pairs the chosen keys would give in the current buffer. =sp-vulpea-convert-keywords--apply= writes them: the keyword lines are deleted first (last one first, so positions stay valid) when removal is on, then the meta lines are inserted. It returns the pairs it converted.

#+begin_src emacs-lisp -i
(defun sp-vulpea-convert-keywords--plan (keys)
  "Return (KEY . VALUE) for the header keywords named in KEYS."
  (mapcar (lambda (e) (cons (plist-get e :key) (plist-get e :value)))
          (sp-vulpea-convert-keywords--convertible keys)))

(defun sp-vulpea-convert-keywords--apply (keys)
  "Convert the header keywords named in KEYS in the current buffer.
Honours `sp-vulpea-convert-keywords-remove-original'. Does not
save. Returns the list of (KEY . VALUE) converted."
  (let ((entries (sp-vulpea-convert-keywords--convertible keys)))
    (when entries
      (when sp-vulpea-convert-keywords-remove-original
        (dolist (e (reverse entries))
          (delete-region (plist-get e :beg) (plist-get e :end))))
      (sp-vulpea-convert-keywords--insert-meta
       (mapcar (lambda (e) (cons (plist-get e :key) (plist-get e :value)))
               entries))
      (mapcar (lambda (e) (cons (plist-get e :key) (plist-get e :value)))
              entries))))
#+end_src

(defun sp-vulpea-convert-keywords (&optional all-notes)
  "Convert file-header keywords such as `#+bib-project:' to Vulpea meta lines.
Lists the header keywords found in the current note (in every
Vulpea note with prefix argument ALL-NOTES), minus
`sp-vulpea-convert-keywords-ignore', lets you pick which to
convert, shows a preview and asks before writing. See
`sp-vulpea-convert-keywords-remove-original'.

The current note is changed but not saved. With ALL-NOTES each
note is saved, except one with unsaved changes, which is skipped."
  (interactive "P")
  (unless (or all-notes (derived-mode-p 'org-mode))
    (user-error "Not an Org buffer; use C-u to run over all notes"))
  (let* ((sources (if all-notes
                      (sp-vulpea-convert-keywords--note-files)
                    (list (current-buffer))))
         (choices (sp-vulpea-convert-keywords--collect sources)))
    (unless choices
      (user-error "No header keywords to convert (ignoring %s)"
                  (string-join sp-vulpea-convert-keywords-ignore ", ")))
    (let* ((keys (sp-vulpea-convert-keywords--read-keys choices))
           (plan (and keys
                      (seq-filter
                       #'cdr
                       (mapcar (lambda (s)
                                 (cons s (sp-vulpea-convert-keywords--call-on-source
                                          s (lambda () (sp-vulpea-convert-keywords--plan keys)))))
                               sources)))))
      (unless keys (user-error "Nothing picked"))
      (unless plan (user-error "None of those keywords has a value to convert"))
      (sp-vulpea-convert-keywords--show-preview plan)
      (unwind-protect
          (unless (y-or-n-p (format "Convert %d note%s? "
                                    (length plan) (if (= 1 (length plan)) "" "s")))
            (user-error "Aborted"))
        (when-let* ((win (get-buffer-window "*keywords to meta preview*")))
          (quit-window nil win)))
      (if (not all-notes)
          (let ((done (with-current-buffer (car sources)
                        (sp-vulpea-convert-keywords--apply keys))))
            (message "Converted %d header keyword%s to meta lines (not saved; C-/ undoes)"
                     (length done) (if (= 1 (length done)) "" "s")))
        (let ((converted 0) skipped)
          (let ((run (sp-batch-report-run-batches
                      plan
                      (lambda (item _decision)
                        (let* ((file (car item))
                               (open (get-file-buffer file)))
                          (if (and open (buffer-modified-p open))
                              (push file skipped)
                            (with-current-buffer (find-file-noselect file)
                              (cl-incf converted (length (sp-vulpea-convert-keywords--apply keys)))
                              (save-buffer)
                              (unless open (kill-buffer))))))
                      :label "Keywords to meta"
                      :describe (lambda (item)
                                  (format "Convert %s?" (file-name-nondirectory (car item)))))))
            (message "Converted %d header keyword%s in %d note%s%s%s"
                     converted (if (= 1 converted) "" "s")
                     (- (plist-get run :done) (length skipped))
                     (if (= 1 (- (plist-get run :done) (length skipped))) "" "s")
                     (if skipped
                         (format "; skipped %d with unsaved changes: %s" (length skipped)
                                 (string-join (mapcar #'file-name-nondirectory skipped) ", "))
                       "")
                     (sp-batch-report-batches-note run))))))))

* sp-vulpea-grouped-backlinks.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-grouped-backlinks.el
:END:

This module shows the backlinks of a Vulpea note, split into groups, in an Org buffer (=-org-detached=) or in a sidebar that follows the main note (=-sidebar=).

- A link in ordinary prose goes into the Mentions section, which has one subsection per kind of source note:
  - Notes: regular notes (tagged =concept= or =zettel=; any note that is not one of the other two kinds also lands here).
  - Litnotes: notes tagged =litnote=.
  - Writing projects: files below =sp-writing-projects=, which wins over the tags.
- A link on a Vulpea meta line of the form =- KEY :: [[id:...]]= goes into a group named after that key.
- The blocks (sections and Mentions subsections) are separated by =sp-vulpea-grouped-backlinks-block-padding= blank lines (default 2) in every view.
- Example: notes listing someone under =pub-author= appear in their own group, not mixed in with notes that merely mention the person.

Dependencies and open points:

- Depends on =vulpea=, =org= and the sibling module =sp-collection-query-core= (for =sp-collec-query-select-note=).
- Loaded from =sp-vulpea-ext=.
- The =vulpea-ui= widget is a separate file, =sp-vulpea-grouped-backlinks-widget.el=, so this file does not need =vulpea-ui= or =vui= at load time.
- The author flags that the shape of the link data from =vulpea-db-query-links-to= was not confirmed against a running Emacs, so the classification code may need adjusting.

The commentary at the top of the module says:

#+begin_quote
What this does: for a given note, finds every other note linking
to it, and sorts each link into either "Mentions" (a plain inline
or body-text [[id:...]] link, split by the kind of note it sits in:
regular notes, litnotes, writing projects) or a group named after the meta
property it was found in -- e.g. a note with
  - pub-author :: [[id:...][Christopher Arthur]]
contributes to a "pub-author" group when you look at Christopher
Arthur's backlinks, distinct from any note that just mentions him
in passing prose.

The vulpea-ui widget is in sp-vulpea-grouped-backlinks-widget.el.
`sp-vulpea-grouped-backlinks-classify' holds the one point of Vulpea
API I couldn't fully confirm.
#+end_quote

*** Meta key at a position

=sp-vulpea-grouped-backlinks--meta-key-at= opens the source file (visiting it if needed), goes to the link's position and checks whether that line is a description-list item with a =KEY ::= tag. It returns the key, or nil when the link is in plain prose.

#+begin_src emacs-lisp -i
(defun sp-vulpea-grouped-backlinks--meta-key-at (file pos)
  "If POS in FILE sits on a \"- KEY :: ...\" meta line, return KEY.
Otherwise return nil, meaning this link sits in plain prose (a
heading, a paragraph, anywhere that isn't a meta description-list
entry) rather than a structured meta property."
  (with-current-buffer (find-file-noselect file)
    (save-excursion
      (goto-char pos)
      (beginning-of-line)
      (if (looking-at "^[ \t]*-[ \t]+\\([A-Za-z0-9_-]+\\)[ \t]+::[ \t]")
          (match-string 1)
        nil))))
#+end_src

*** Kind of a mention

=sp-vulpea-grouped-backlinks--mention-kind= decides which Mentions subsection a source note belongs to.

- =sp-vulpea-grouped-backlinks--writing-p= is true when the source file is below =sp-writing-projects= (the same test the origin groups of =sp-find-note= use for the writing projects).
- Writing projects: the file is in a writing project; this wins over the tags.
- Litnotes: the note is tagged =litnote=.
- Notes: everything else, which is the regular notes tagged =concept= or =zettel=; untagged notes are shown there too, so no mention is dropped.

The two functions are in the block of the next section.

*** Grouping the links

=sp-vulpea-grouped-backlinks-classify= groups the backlinks of an ID.

- Asks the Vulpea database for every link pointing at the ID.
- For each link, looks up the source note and the meta key at the link's position.
- Collects notes in a hash table under the key, or under =Mentions / KIND= for a plain link.
- Returns an alist of group name and deduplicated notes.
- The long docstring (which contains a blank line, hence two units) records the assumption that each link is a plist with =:source= and =:pos=.
- If the real shape differs, those two =plist-get= calls are what to change.

#+begin_src emacs-lisp -i
(defun sp-vulpea-grouped-backlinks--writing-p (path)
  "Non-nil when the file PATH is below `sp-writing-projects'."
  (and path
       (bound-and-true-p sp-writing-projects)
       (string-prefix-p (file-name-as-directory
                         (expand-file-name sp-writing-projects))
                        (expand-file-name path))))

(defun sp-vulpea-grouped-backlinks--mention-kind (note)
  "Return the kind of source NOTE is, one of `sp-vulpea-grouped-backlinks-mention-kinds'.
- \"Writing projects\": its file is below `sp-writing-projects'.
- \"Litnotes\": it is tagged `litnote'.
- \"Notes\": anything else, i.e. the regular notes (tagged `concept' or
  `zettel', or not tagged at all)."
  (cond ((sp-vulpea-grouped-backlinks--writing-p (vulpea-note-path note))
         "Writing projects")
        ((member "litnote" (vulpea-note-tags note)) "Litnotes")
        (t "Notes")))

(defun sp-vulpea-grouped-backlinks-classify (id)
  "Return an alist of (GROUP . NOTES) for every note linking to ID.
GROUP is \"Mentions / KIND\" for a plain inline/body link (KIND from
`sp-vulpea-grouped-backlinks--mention-kind'), or the
meta-property key name (e.g. \"pub-author\") for a link found on
a \"- KEY :: [[id:...]]\" line -- see `sp-vulpea-grouped-backlinks--meta-key-at'.
NOTES is a deduplicated list of `vulpea-note' structs: the source
of each such link.

This relies on `vulpea-db-query-links-to' returning link plists
with at least :source (a note ID) and :pos (a buffer position in
the source file). I've seen this shape referenced in Vulpea's own
db/changelog material, but haven't been able to confirm it
against a live Emacs session -- if this errors for you, `C-h f
vulpea-db-query-links-to' will show the real return shape, and
the two `plist-get' calls below are the only things that would
need adjusting."
  (let ((groups (make-hash-table :test #'equal)))
    (dolist (link (vulpea-db-query-links-to id))
      (let* ((source-id (plist-get link :source))
             (pos (plist-get link :pos))
             (source-note (and source-id (vulpea-db-get-by-id source-id))))
        (when (and source-note pos)
          (let* ((key (sp-vulpea-grouped-backlinks--meta-key-at (vulpea-note-path source-note) pos))
                 (group (or key
                            (concat sp-vulpea-grouped-backlinks--mentions-prefix
                                    (sp-vulpea-grouped-backlinks--mention-kind
                                     source-note)))))
            (puthash group (cons source-note (gethash group groups)) groups)))))
    (let (result)
      (maphash
       (lambda (group notes)
         (push (cons group
                     (seq-uniq notes (lambda (a b)
                                       (equal (vulpea-note-id a) (vulpea-note-id b)))))
               result))
       groups)
      result)))
#+end_src

*** Sorted groups

=sp-vulpea-grouped-backlinks-sorted= returns the groups of an ID in the order every view shows them.

- Calls =sp-vulpea-grouped-backlinks-classify=.
- Puts the mention groups first, in the order of =sp-vulpea-grouped-backlinks-mention-kinds=, then the meta-key groups by name.
- =sp-vulpea-grouped-backlinks-sections= folds the groups into sections, the shape the views draw:
  - A section is =(TITLE . SUBGROUPS)=, with SUBGROUPS an alist of =(LABEL . NOTES)=.
  - Mentions is one section with a subgroup per kind.
  - A meta key is a section with one subgroup whose label is nil (a flat list of notes).
- =sp-vulpea-grouped-backlinks-section-count= is the number of notes in a section.
- =sp-vulpea-grouped-backlinks--padding= is the blank lines between two blocks.
- Used by the Org buffer, the sidebar and the widget, so they cannot disagree.

#+begin_src emacs-lisp -i
(defun sp-vulpea-grouped-backlinks--rank (group)
  "Return the sort rank of the group name GROUP.
Mention groups come first, in `sp-vulpea-grouped-backlinks-mention-kinds'
order; the meta-key groups follow."
  (if (string-prefix-p sp-vulpea-grouped-backlinks--mentions-prefix group)
      (or (seq-position sp-vulpea-grouped-backlinks-mention-kinds
                        (string-remove-prefix
                         sp-vulpea-grouped-backlinks--mentions-prefix group))
          0)
    (length sp-vulpea-grouped-backlinks-mention-kinds)))

(defun sp-vulpea-grouped-backlinks-sorted (id)
  "Return the groups of notes linking to ID, in display order.
Mention groups come first (see `sp-vulpea-grouped-backlinks--rank'), the
meta-key groups after them sorted by name.  See
`sp-vulpea-grouped-backlinks-classify' for the shape."
  (sort (sp-vulpea-grouped-backlinks-classify id)
        (lambda (a b)
          (let ((ra (sp-vulpea-grouped-backlinks--rank (car a)))
                (rb (sp-vulpea-grouped-backlinks--rank (car b))))
            (if (= ra rb)
                (string< (car a) (car b))
              (< ra rb))))))

(defun sp-vulpea-grouped-backlinks--fold-sections (groups)
  "Fold the sorted GROUPS into sections, a list of (TITLE . SUBGROUPS).
SUBGROUPS is an alist of (LABEL . NOTES).  The mention groups become one
\"Mentions\" section with a subgroup per kind of source note; each
meta-key group is a section with one subgroup whose LABEL is nil."
  (let (mentions sections)
    (dolist (group groups)
      (if (string-prefix-p sp-vulpea-grouped-backlinks--mentions-prefix
                           (car group))
          (push (cons (string-remove-prefix
                       sp-vulpea-grouped-backlinks--mentions-prefix (car group))
                      (cdr group))
                mentions)
        (push (list (car group) (cons nil (cdr group))) sections)))
    (append (when mentions (list (cons "Mentions" (nreverse mentions))))
            (nreverse sections))))

(defun sp-vulpea-grouped-backlinks-sections (id)
  "Return the backlinks of ID as sections, the shape every view draws.
See `sp-vulpea-grouped-backlinks--fold-sections'."
  (sp-vulpea-grouped-backlinks--fold-sections
   (sp-vulpea-grouped-backlinks-sorted id)))

(defun sp-vulpea-grouped-backlinks-section-count (section)
  "Return the number of notes in SECTION, over all its subgroups."
  (apply #'+ (mapcar (lambda (sub) (length (cdr sub))) (cdr section))))

(defun sp-vulpea-grouped-backlinks--flat-p (section)
  "Non-nil when SECTION has no subsections, only a list of notes."
  (null (car (cadr section))))

(defun sp-vulpea-grouped-backlinks--padding ()
  "Return the blank lines that separate two blocks, as a string."
  (make-string (max 0 sp-vulpea-grouped-backlinks-block-padding) ?\n))
#+end_src

** Displaying the result

*** Grouped backlinks buffer

=sp-vulpea-grouped-backlinks-org-detached= is the interactive command that shows the groups in an Org buffer.

- "Detached" because the buffer does not follow the note you are in: it shows the note you picked, until you run the command again.
- It was called =sia-vulpea-show-grouped-backlinks=. The old name is removed, with no alias (see [[file:../../../../../../adr/0025-dryrun-and-convert-command-names.org][ADR 0025]]).
- Follow-up commands (a sidebar that follows the note, a =vulpea-ui= widget) are planned as separate commands.

- Prompts for a note with =sp-collec-query-select-note= when none is given.
- Fills a buffer named after the note, in =org-mode=, with a top heading, one subheading per section (Mentions first, then the meta keys, each with its count), a third-level heading per kind of source under Mentions, blank lines between blocks, and an =id:= link to each source note so =org-open-at-point= works on them.
- Shows the buffer with =display-buffer=.
- No key is bound to it in this file.

#+begin_src emacs-lisp -i
(defun sp-vulpea-grouped-backlinks--insert-org-notes (notes)
  "Insert one Org list item with an `id:' link for each of NOTES."
  (dolist (n notes)
    (insert (format "- %s\n"
                    (org-link-make-string (concat "id:" (vulpea-note-id n))
                                           (vulpea-note-title n))))))

(defun sp-vulpea-grouped-backlinks-org-detached (&optional note)
  "Show backlinks to NOTE, grouped into \"Mentions\" (a subsection per kind
of source note) plus one section per meta-property key they were found
under (see `sp-vulpea-grouped-backlinks-sections'). Prompts for NOTE, via
`sp-collec-query-select-note' (tag-annotated completion), if not given.

Each entry is a real, clickable [[id:...][Title]] link back to
the note that made the reference -- opened in `org-mode' so
`org-open-at-point' works on them, same pattern as the property-
conversion report."
  (interactive)
  (let* ((note (or note (sp-collec-query-select-note "Show backlinks for: ")))
         (sections (sp-vulpea-grouped-backlinks-sections (vulpea-note-id note))))
    (with-current-buffer (get-buffer-create
                           (format "*vulpea backlinks: %s*" (vulpea-note-title note)))
      (erase-buffer)
      (org-mode)
      (insert (format "* Backlinks to %s\n\n" (vulpea-note-title note)))
      (if (null sections)
          (insert "No backlinks found.\n")
        (let ((padding (sp-vulpea-grouped-backlinks--padding))
              (first-section t))
          (dolist (section sections)
            (unless first-section (insert padding))
            (setq first-section nil)
            (insert (format "** %s (%d)\n" (car section)
                            (sp-vulpea-grouped-backlinks-section-count section)))
            (if (sp-vulpea-grouped-backlinks--flat-p section)
                (sp-vulpea-grouped-backlinks--insert-org-notes
                 (cdr (cadr section)))
              (let ((first-sub t))
                (dolist (sub (cdr section))
                  (unless first-sub (insert padding))
                  (setq first-sub nil)
                  (insert (format "*** %s (%d)\n" (car sub) (length (cdr sub))))
                  (sp-vulpea-grouped-backlinks--insert-org-notes
                   (cdr sub))))))))
      (goto-char (point-min))
      (display-buffer (current-buffer)))))
#+end_src

** Sidebar

=sp-vulpea-grouped-backlinks-sidebar= shows the groups in a pop-up side window that follows the note in the main window.

- It sits beside the =vulpea-ui= sidebar (same side, the next slot), not instead of it.
- Moving to another note, for example through a mention, redraws it.
- Following can be switched off, and the switch only affects this sidebar; the widget always follows.

*** Settings

The user options of the sidebar.

- =sp-vulpea-grouped-backlinks-sidebar-follow=: non-nil (default) redraws the sidebar for the note in the main window; nil keeps the note it shows (pinned).
- =sp-vulpea-grouped-backlinks-sidebar-side=: =left=, =right= (default), =top= or =bottom=.
- =sp-vulpea-grouped-backlinks-sidebar-slot=: slot on that side; 1 (default) puts it next to the =vulpea-ui= sidebar, which has slot 0.
- =sp-vulpea-grouped-backlinks-sidebar-size=: fraction of the frame (default 0.33).

*** Main note

=sp-vulpea-grouped-backlinks-sidebar--main-note= returns the note of the main window, or nil.

- Asks =vulpea-ui= for its main window and for the note of that window's buffer, so both sidebars agree.
- The main window is never a side window, so the sidebar here is not mistaken for it.
- A narrowed buffer or a non-note buffer gives nil (or the file-level note); the sidebar then keeps what it shows.

*** Drawing

=sp-vulpea-grouped-backlinks-sidebar--render= draws the groups of NOTE in the current buffer.

- Two header lines: the title, and whether the sidebar follows or is pinned.
- One line per section with its count, then one button per note; under Mentions, one indented line per kind of source, with the buttons one level deeper.
- Blocks are separated by =sp-vulpea-grouped-backlinks-block-padding= blank lines.
- A button opens the note in the main window with =vulpea-ui-visit-note=.
- Point goes to the top, as in the =vulpea-ui= sidebar.

  "Insert the line \"TITLE (COUNT)\", indented by INDENT columns."
  (insert (make-string indent ?\s)
          (propertize (format "%s (%d)" title count)
                      'face 'font-lock-keyword-face)

  (dolist (n notes)
    (insert (make-string indent ?\s))

(defun sp-vulpea-grouped-backlinks-sidebar--render (note)
  "Draw the grouped backlinks of NOTE in the current buffer."
  (let ((inhibit-read-only t)
        (sections (sp-vulpea-grouped-backlinks-sections (vulpea-note-id note))))
    (erase-buffer)
    (setq sp-vulpea-grouped-backlinks-sidebar--note note)
    (insert (propertize (format "Backlinks to %s" (vulpea-note-title note))
                        'face 'bold)
            "\n"
            (propertize (if sp-vulpea-grouped-backlinks-sidebar-follow
                            "following the main note (f: pin)"
                          "pinned (f: follow)")
                        'face 'shadow)
            "\n\n")
    (if (null sections)
        (insert "No backlinks found.\n")
      (let ((padding (sp-vulpea-grouped-backlinks--padding))
            (first-section t))
        (dolist (section sections)
          (unless first-section (insert padding))
          (setq first-section nil)
          (sp-vulpea-grouped-backlinks-sidebar--insert-heading
           (car section)
           (sp-vulpea-grouped-backlinks-section-count section)
           0)
          (if (sp-vulpea-grouped-backlinks--flat-p section)
              (sp-vulpea-grouped-backlinks-sidebar--insert-notes
               (cdr (cadr section)) 2)
            (let ((first-sub t))
              (dolist (sub (cdr section))
                (unless first-sub (insert padding))
                (setq first-sub nil)
                (sp-vulpea-grouped-backlinks-sidebar--insert-heading
                 (car sub) (length (cdr sub)) 2)
                (sp-vulpea-grouped-backlinks-sidebar--insert-notes
                 (cdr sub) 4)))))))
    (goto-char (point-min))))

*** Following

The sidebar redraws when the main window shows another note.

- =sp-vulpea-grouped-backlinks-sidebar--sync= compares the main note with the drawn one and redraws only if the ID differs.
- It does nothing when following is off, when the sidebar is not visible or when there is no main note (for example a non-note buffer).
- =sp-vulpea-grouped-backlinks-sidebar--on-window-change= is added to =window-buffer-change-functions= and =window-selection-change-functions=, the hooks =vulpea-ui= tracks its note with.
- It only arms a zero-second timer; the work runs from the timer.
- This is the reason =vulpea-ui= gives for doing the same: work done inside the window change functions can see a stale window layout.
- One timer at a time, so two hooks firing for one redisplay cause one sync.

#+begin_src emacs-lisp -i
(defun sp-vulpea-grouped-backlinks-sidebar--sync ()
  "Redraw the sidebar if the main window shows another note."
  (setq sp-vulpea-grouped-backlinks-sidebar--timer nil)
  (when-let* ((buf (get-buffer sp-vulpea-grouped-backlinks-sidebar-buffer-name))
              ((and sp-vulpea-grouped-backlinks-sidebar-follow
                    (get-buffer-window buf t)))
              (note (sp-vulpea-grouped-backlinks-sidebar--main-note))
              (shown (buffer-local-value
                      'sp-vulpea-grouped-backlinks-sidebar--note buf))
              ((not (equal (vulpea-note-id note) (vulpea-note-id shown)))))
    (with-current-buffer buf
      (sp-vulpea-grouped-backlinks-sidebar--render note))))

(defun sp-vulpea-grouped-backlinks-sidebar--on-window-change (&optional _frame)
  "Arm a sync after a window or buffer change."
  (unless (or (minibufferp) sp-vulpea-grouped-backlinks-sidebar--timer)
    (setq sp-vulpea-grouped-backlinks-sidebar--timer
          (run-with-timer 0 nil #'sp-vulpea-grouped-backlinks-sidebar--sync))))

(defun sp-vulpea-grouped-backlinks-sidebar--add-hooks ()
  "Track the main window while the sidebar exists."
  (add-hook 'window-buffer-change-functions
            #'sp-vulpea-grouped-backlinks-sidebar--on-window-change)
  (add-hook 'window-selection-change-functions
            #'sp-vulpea-grouped-backlinks-sidebar--on-window-change))

(defun sp-vulpea-grouped-backlinks-sidebar--remove-hooks ()
  "Stop tracking and cancel a pending sync."
  (remove-hook 'window-buffer-change-functions
               #'sp-vulpea-grouped-backlinks-sidebar--on-window-change)
  (remove-hook 'window-selection-change-functions
               #'sp-vulpea-grouped-backlinks-sidebar--on-window-change)
  (when (timerp sp-vulpea-grouped-backlinks-sidebar--timer)
    (cancel-timer sp-vulpea-grouped-backlinks-sidebar--timer))
  (setq sp-vulpea-grouped-backlinks-sidebar--timer nil))
#+end_src

- Keys: =f= toggles following, =g= redraws the shown note (the backlinks changed), =q= closes the sidebar, =RET= opens the note under point.

*** Commands

Three commands.

- =sp-vulpea-grouped-backlinks-sidebar=: opens the sidebar for the main note, or closes it when it is open (a toggle, like =vulpea-ui-sidebar-toggle=). With no note in the main window it asks for one.
- =sp-vulpea-grouped-backlinks-sidebar-close=: closes the window and kills the buffer.
- =sp-vulpea-grouped-backlinks-sidebar-toggle-follow=: flips =sp-vulpea-grouped-backlinks-sidebar-follow= and redraws; when it turns following on, it catches up with the main note at once.

*** Component

=sp-vulpea-grouped-backlinks-widget= renders the groups of the current note.

- Does nothing when no note is shown.
- Computes the groups in =vui-use-memo=, keyed on the note: an idle refresh reuses them, and a refresh with cache invalidation (=vulpea-ui-sidebar-refresh=) computes them again.

(defun sp-vulpea-grouped-backlinks-widget--pad (blocks)
  "Return BLOCKS with blank lines between them (`sp-vulpea-grouped-backlinks--padding')."
  (let (out)
    (dolist (block blocks)
      (when out
        (dotimes (_ (max 0 sp-vulpea-grouped-backlinks-block-padding))
          (push (vui-text "") out)))
      (push block out))
    (nreverse out)))

(defun sp-vulpea-grouped-backlinks-widget--block (title notes)
  "Return a heading TITLE with its count, and a link to each of NOTES under it."
  (vui-vstack
   (vui-text (format "%s (%d)" title (length notes))
             :face 'font-lock-keyword-face)
   (apply #'vui-vstack
          :indent 2
          (mapcar (lambda (n)
                    (vui-component 'vulpea-ui-note-link :note n))
                  notes))))

(defun sp-vulpea-grouped-backlinks-widget--section (section)
  "Return the block of SECTION: a flat group, or a heading over its subsections."
  (if (sp-vulpea-grouped-backlinks--flat-p section)
      (sp-vulpea-grouped-backlinks-widget--block
       (car section) (cdr (cadr section)))
    (vui-vstack
     (vui-text (format "%s (%d)" (car section)
                       (sp-vulpea-grouped-backlinks-section-count section))
               :face 'font-lock-keyword-face)
     (apply #'vui-vstack
            :indent 2
            (sp-vulpea-grouped-backlinks-widget--pad
             (mapcar (lambda (sub)
                       (sp-vulpea-grouped-backlinks-widget--block
                        (car sub) (cdr sub)))
                     (cdr section)))))))

(vui-defcomponent sp-vulpea-grouped-backlinks-widget ()
  "Backlinks of the current note, grouped by meta property."
  :render
  (let ((note (use-vulpea-ui-note)))
    (when note
      (let ((sections (vui-use-memo (note)
                        (sp-vulpea-grouped-backlinks-sections
                         (vulpea-note-id note)))))

          :title "Grouped backlinks"
          :count (apply #'+ (mapcar #'sp-vulpea-grouped-backlinks-section-count
                                    sections))
          :children
          (lambda ()
            (if (null sections)
                (vui-text "No backlinks")
              (apply #'vui-vstack
                     (sp-vulpea-grouped-backlinks-widget--pad
                      (mapcar #'sp-vulpea-grouped-backlinks-widget--section
                              sections))))))))))

* sp-vulpea-backlink-check.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-backlink-check.el
:END:

This module answers one question about a heading: is it linked to from anywhere in the vault?

- =M-x sp-vulpea-backlink-check= (or =(sp-vulpea-backlink-check)= evaluated) works on the heading at point.
- The heading needs an =ID= property; without one the command says so and stops.
- The answer appears in the echo area, for example =3 backlinks from 2 notes=, or =not backlinked=.
- The answer is a propertized string, so it is an Embark target of type =sp-vulpea-backlinks=.
- =embark-act= (=C-.=) on it opens the =*vulpea backlinks: TITLE*= buffer with every location.

The check is one database query:

- It calls =vulpea-db-query-links-to= with the heading ID, the same query as =sp-vulpea-grouped-backlinks=.
- Headings with an =ID= are notes of their own in Vulpea, so a link to a heading is found, not only a link to a file.
- It reads no file, so it stays fast on a big vault.
- A link from the heading to itself is not counted.

The locations buffer reads files, but only when you ask for it:

- One group per source note, with its file name.
- One entry per link: the heading it sits under, the line number and the text of the line.
- =RET= or a click jumps to the link; =n= and =p= move between entries; =g= refreshes; =q= quits.
- A file that is open in a buffer is read from that buffer, so unsaved edits count.
- The position comes from the database, so it can be a little off until the file is synced again.

How Embark finds the result, since the echo area is not a buffer:

- =sp-vulpea-backlink-check-target= is added to =embark-target-finders= at the front.
- It returns the result when the echo area still shows it (=current-message=).
- It also returns it for =sp-vulpea-backlink-check-timeout= seconds after the command ran, in case the message was already replaced.
- It also works on the line of the result in the =*Messages*= buffer, from the text property (if =*Messages*= keeps it).
- If the message is already gone, run =M-x sp-copy-last-message= and then =embark-act=:
  - =sp-copy-last-message= runs =sp-copy-last-message-functions= on the copied text.
  - =sp-vulpea-backlink-check-restore= is on that hook; it finds the text among the last =sp-vulpea-backlink-check-history-size= results (20).
  - The =Copied: ...= message is then the propertized result again, so =embark-act= works on it.
  - If two headings gave the same text, the newest one wins.
- Embark is configured with =with-eval-after-load=, as the other modules do, so this file does not load it.

Customisation:

- =sp-vulpea-backlink-check-timeout=: seconds the last result stays an Embark target after the echo area changes (default 10).
- =sp-vulpea-backlink-check-history-size=: results remembered for =sp-copy-last-message= (default 20).
- =sp-vulpea-backlink-check-context-width=: columns of the line of context in the buffer (default 100).

(defun sp-vulpea-backlink-check--links (id)
  "Return the links to the note ID, without the ones from ID itself."
  (seq-remove (lambda (link) (equal (plist-get link :source) id))
              (vulpea-db-query-links-to id)))

(defvar sp-vulpea-backlink-check--history nil
  "Alist of (TEXT . ID) of the latest results, newest first.")

(defcustom sp-vulpea-backlink-check-history-size 20
  "Number of results kept to make them Embark targets again.
See `sp-vulpea-backlink-check-restore'."
  :type 'natnum
  :group 'sp-vulpea-backlink-check)

(defun sp-vulpea-backlink-check--propertize (text id)
  "Return TEXT as a result string for the heading ID."
  (propertize text
              'sp-vulpea-backlink-check id
              'face (if (equal text "not backlinked") 'shadow 'success)
              'help-echo "embark-act: list the backlinks"))

(defun sp-vulpea-backlink-check-restore (text)
  "Return TEXT as a result string again, if it is a recent result, else nil.
For `sp-copy-last-message-functions': the text copied out of *Messages*
has lost its properties.  This also makes the heading the target for
`sp-vulpea-backlink-check-timeout' seconds."
  (when-let* ((cell (assoc (string-remove-prefix "Copied: " text)
                           sp-vulpea-backlink-check--history)))
    (setq sp-vulpea-backlink-check--last (cons (cdr cell) (float-time)))
    (sp-vulpea-backlink-check--propertize (car cell) (cdr cell))))

(defun sp-vulpea-backlink-check--format (id links)
  "Return the echo-area result for ID with LINKS, a propertized string."
  (let* ((n (length links))
         (sources (length (seq-uniq (mapcar (lambda (l) (plist-get l :source))
                                            links))))
         (text (if (zerop n)
                   "not backlinked"
                 (format "%d backlink%s from %d note%s"
                         n (if (= n 1) "" "s")
                         sources (if (= sources 1) "" "s")))))
    (sp-vulpea-backlink-check--propertize text id)))

(defun sp-vulpea-backlink-check--id-at-point ()
  "Return the ID of the heading at point, or signal a `user-error'."
  (unless (derived-mode-p 'org-mode)
    (user-error "Not in an Org buffer"))
  (or (org-entry-get nil "ID")
      (user-error "This heading has no ID")))

(defun sp-vulpea-backlink-check (&optional id)
  "Say in the echo area whether the heading at point is backlinked.
ID defaults to the ID property of the heading at point.  The result,
for example \"3 backlinks from 2 notes\", is an Embark target: `embark-act'
on it lists the backlinks.  Return the result string."
  (interactive)
  (let* ((id (or id (sp-vulpea-backlink-check--id-at-point)))
         (result (sp-vulpea-backlink-check--format
                  id (sp-vulpea-backlink-check--links id))))

    (setq sp-vulpea-backlink-check--history
          (seq-take (cons (cons (substring-no-properties result) id)
                          (assoc-delete-all (substring-no-properties result)
                                            sp-vulpea-backlink-check--history))
                    sp-vulpea-backlink-check-history-size))
    (message "%s" result)
    result))

** Locations

- Each location is a plist: =:note=, =:path=, =:pos=, =:line=, =:heading= and =:context=.
- A buffer visiting the file is used when there is one, otherwise the file is read into a temporary buffer.

#+begin_src emacs-lisp -i

(defun sp-vulpea-backlink-check--location (link)
  "Return the location plist of the LINK plist, or nil without a source file."
  (when-let* ((note (vulpea-db-get-by-id (plist-get link :source)))
              (path (vulpea-note-path note))
              (pos (plist-get link :pos)))
    (let ((buf (find-buffer-visiting path)))
      (with-temp-buffer
        (if buf
            (insert (with-current-buffer buf
                      (save-restriction (widen) (buffer-string))))
          (insert-file-contents path))
        (goto-char (min pos (point-max)))
        (list :note note :path path :pos pos
              :line (line-number-at-pos)
              :heading (save-excursion
                         (and (re-search-backward "^\\*+[ \t]+\\(.*\\)$" nil t)
                              (string-trim (match-string 1))))
              :context (truncate-string-to-width
                        (string-trim (buffer-substring
                                      (line-beginning-position)
                                      (line-end-position)))
                        sp-vulpea-backlink-check-context-width nil nil "…"))))))

(defun sp-vulpea-backlink-check--locations (id)
  "Return the locations of the links to ID, grouped by source note.
The value is an alist of (NOTE . LOCATIONS), in file order."
  (let (groups)
    (dolist (link (sp-vulpea-backlink-check--links id))
      (when-let* ((loc (sp-vulpea-backlink-check--location link)))
        (let* ((key (plist-get loc :path))
               (cell (assoc key groups)))
          (if cell
              (setcdr cell (cons loc (cdr cell)))
            (push (list key loc) groups)))))
    (mapcar (lambda (g)
              (cons (plist-get (cadr g) :note)
                    (sort (cdr g) (lambda (a b)
                                    (< (plist-get a :pos) (plist-get b :pos))))))
            (nreverse groups))))
#+end_src

** Locations buffer

- The buffer is a =special-mode= buffer, named after the heading title.
- Every entry line has the text property =sp-vulpea-backlink-check-loc= with its location.

#+begin_src emacs-lisp -i

(defvar-local sp-vulpea-backlink-check--buffer-id nil
  "The heading ID the locations buffer lists.")

(defun sp-vulpea-backlink-check-visit ()
  "Jump to the backlink at point."
  (interactive)
  (let ((loc (get-text-property (point) 'sp-vulpea-backlink-check-loc)))
    (unless loc (user-error "No backlink on this line"))
    (find-file-other-window (plist-get loc :path))
    (goto-char (plist-get loc :pos))
    (when (derived-mode-p 'org-mode)
      (org-fold-show-context 'link-search))))

(defun sp-vulpea-backlink-check--next (n)
  "Move N backlink entries forward; backward when N is negative.
An entry spans two lines with the same location, so a step skips the
lines of the entry point is on.  Point stays put when there is none."
  (let ((step (if (> n 0) 1 -1)))
    (dotimes (_ (abs n))
      (let* ((start (point))
             (here (get-text-property start 'sp-vulpea-backlink-check-loc)))
        (while (and (not (if (> step 0) (eobp) (bobp)))
                    (progn (forward-line step)
                           (let ((loc (get-text-property
                                       (point) 'sp-vulpea-backlink-check-loc)))
                             (or (null loc) (eq loc here))))))
        (let ((loc (get-text-property (point) 'sp-vulpea-backlink-check-loc)))
          (when (or (null loc) (eq loc here))
            (goto-char start)))
        (when (< step 0)
          ;; Backward lands on the second line of the entry: go to its first.
          (let ((loc (get-text-property (point) 'sp-vulpea-backlink-check-loc)))
            (while (and loc (not (bobp))
                        (eq loc (get-text-property
                                 (1- (line-beginning-position))
                                 'sp-vulpea-backlink-check-loc)))
              (forward-line -1))))))))

(defun sp-vulpea-backlink-check-next-entry (&optional n)
  "Move to the next backlink entry, N times."
  (interactive "p")
  (sp-vulpea-backlink-check--next (or n 1)))

(defun sp-vulpea-backlink-check-previous-entry (&optional n)
  "Move to the previous backlink entry, N times."
  (interactive "p")
  (sp-vulpea-backlink-check--next (- (or n 1))))

(defvar-keymap sp-vulpea-backlink-check-mode-map
  :doc "Keys of the backlink locations buffer."
  :parent special-mode-map
  "RET" #'sp-vulpea-backlink-check-visit
  "<mouse-2>" #'sp-vulpea-backlink-check-visit
  "n" #'sp-vulpea-backlink-check-next-entry
  "p" #'sp-vulpea-backlink-check-previous-entry)

(define-derived-mode sp-vulpea-backlink-check-mode special-mode "Backlinks"
  "Major mode of the buffer that lists the backlinks of a heading."
  (setq-local revert-buffer-function
              (lambda (&rest _)
                (when sp-vulpea-backlink-check--buffer-id
                  (sp-vulpea-backlink-check--render
                   sp-vulpea-backlink-check--buffer-id)))))

(defun sp-vulpea-backlink-check--render (id)
  "Draw the locations of the links to ID in the current buffer."
  (let ((inhibit-read-only t)
        (groups (sp-vulpea-backlink-check--locations id)))
    (erase-buffer)
    (setq sp-vulpea-backlink-check--buffer-id id)
    (insert (propertize (format "Backlinks to %s"
                                (or (when-let* ((note (vulpea-db-get-by-id id)))
                                      (vulpea-note-title note))
                                    id))
                        'face 'bold)
            "\n"
            (propertize "RET: visit  n/p: move  g: refresh  q: quit" 'face 'shadow)
            "\n\n")
    (if (null groups)
        (insert "Not backlinked.\n")
      (dolist (group groups)
        (insert (propertize (vulpea-note-title (car group))
                            'face 'font-lock-keyword-face)
                (propertize (format "  %s"
                                    (abbreviate-file-name
                                     (vulpea-note-path (car group))))
                            'face 'shadow)
                "\n")
        (dolist (loc (cdr group))
          (insert (propertize
                   (format "  %s (line %d)\n    %s\n"
                           (or (plist-get loc :heading) "(before the first heading)")
                           (plist-get loc :line)
                           (plist-get loc :context))
                   'sp-vulpea-backlink-check-loc loc
                   'mouse-face 'highlight
                   'follow-link t)))
        (insert "\n")))
    (goto-char (point-min))
    (sp-vulpea-backlink-check--next 1)))

(defun sp-vulpea-backlink-check--pending-id ()
  "Return the ID of the result in the echo area or just reported, or nil."
  (or (when-let* ((msg (current-message)))
        (get-text-property 0 'sp-vulpea-backlink-check msg))
      (when-let* ((last sp-vulpea-backlink-check--last)
                  ((< (- (float-time) (cdr last))
                      sp-vulpea-backlink-check-timeout)))
        (car last))))
