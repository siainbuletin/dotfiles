Literate source for =libraries/modules/academic/sp-fetch-academic.el=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../tangling-instructions.org][Tangling instructions]].

The module brings references and papers in from the web.

- Search: =biblio= (CrossRef, arXiv and the other backends) and =biblio-gscholar= for Google Scholar. Both moved here from =sp-academic=, together with the lookup commands that were in =sp-bibprocess=.
- DOI: =org-ref= resolves a DOI to a BibTeX entry and can fetch the PDF.
- Download: a command that saves a PDF from a URL into the literature folder and writes it into the =file= field of the entry.
- Keys: every entry, however it arrives, gets the key from the scheme in [[file:sp-academic.org::*Citation keys][Citation keys]].
- consult-omni: =sp-fetch-academic-omni= searches OpenAlex, PubMed and Scopus from the minibuffer (=consult-omni= is set up in [[file:../custom/sp-search-browsing-trails.org][sp-browsing]]) and hands the chosen result to the DOI or download command. Why it is not Google Scholar: [[file:../custom/sp-search-browsing-trails.org::*Google Scholar: biblio-gscholar or consult-omni][the comparison]].

It is required by =sp-academic= after =sp-bibprocess=, so a profile only lists =sp-academic=.

Settings worth knowing:

- =sp-fetch-academic-download-dir= is where downloaded PDFs go (=sp-literature-dir=, =~/Documents/literature/=).
- =biblio-bibtex-use-autokey= is =t=, so a =biblio= result is cleaned and keyed as soon as it is inserted.
- =org-ref-pdf-directory= is also =sp-literature-dir= (set in =sp-academic=), so PDFs fetched by DOI end up beside the downloaded ones.

Keys, under the bibliography group of the leader (=C-; B=, bound in =sp-keys=):

| Key         | Command                           | What it does                                   |
|-------------+-----------------------------------+------------------------------------------------|
| =C-; B b= | =sp-fetch-academic-biblio-lookup= | search a backend or enter a DOI, insert the entry |
| =C-; B i= | =sp-fetch-academic-doi=           | add an entry from a DOI with =org-ref=, optionally fetch the PDF |
| =C-; B u= | =sp-fetch-academic-download=      | download a PDF from a URL and attach it        |
| =C-; B f= | =sp-fetch-academic-attach-pdf=   | attach a PDF on disk to an entry and add it to DEVONthink |
| =C-; B s= | =sp-fetch-academic-omni=          | search scholarly sources with consult-omni, add the chosen paper by DOI (or PDF address) |

* Searching with biblio

** biblio and Google Scholar

Installs =biblio=, which queries services such as CrossRef and arXiv for BibTeX entries, and =biblio-gscholar=, a Google Scholar backend for it.

- =biblio-bibtex-use-autokey= makes every inserted entry go through =bibtex-clean-entry=, so it gets a key from the scheme instead of whatever the service returned.
- =C-; B b= runs =sp-fetch-academic-biblio-lookup=, bound under [[*Keys]]. It used to run =sp-bibtex-biblio-lookup= from =sp-bibprocess=; the old name is gone, with no alias.
- Google Scholar has no public API. =biblio-gscholar= scrapes the results page, so it may be blocked or ask for a CAPTCHA; use CrossRef or arXiv when it fails.

#+begin_src emacs-lisp -i
;;;; Searching with biblio

(use-package biblio
  :ensure t

  :custom
  (biblio-bibtex-use-autokey t))

(use-package biblio-gscholar
  :ensure (biblio-gscholar :host github :repo "seanfarley/biblio-gscholar.el"))
#+end_src

** Choosing the target file

=sp--fetch-academic-bibfile= picks the =.bib= file an entry goes into:

- the only registered one, if there is a single file,
- the current buffer's file, if already in =bibtex-mode=,
- a completion prompt otherwise.

It signals a =user-error= when no file is registered.

#+begin_src emacs-lisp -i
(defun sp--fetch-academic-bibfile ()
  "Return the BibTeX file a new entry should go into."
  (cond ((null sp-bibtex-files)
         (user-error "No BibTeX file(s) defined"))
        ((null (cdr sp-bibtex-files)) (car sp-bibtex-files))
        ((derived-mode-p 'bibtex-mode) (buffer-file-name))
        (t (completing-read "Select BibTeX file: " sp-bibtex-files nil t))))
#+end_src

** Combined lookup

=sp--fetch-academic-combined-lookup= offers the backends known to =biblio= plus an extra "DOI" entry in one completion prompt.

- Choosing DOI asks for a DOI and inserts its BibTeX directly.
- Any other backend starts an interactive =biblio-lookup= search, whose results are inserted into the file that is current.
- It relies on the internal =biblio--named-backends=.

#+begin_src emacs-lisp -i
(defun sp--fetch-academic-combined-lookup ()
  "Combines `biblio-lookup' and `biblio-doi-insert-bibtex'."
  (require 'biblio)
  (let* ((dbs (biblio--named-backends))
         (db-list (append dbs '(("DOI" . biblio-doi-backend))))
         (db-selected (biblio-completing-read-alist
                       "Backend:"
                       db-list)))
    (if (eq db-selected 'biblio-doi-backend)
        (let ((doi (read-string "DOI: ")))
          (biblio-doi-insert-bibtex doi))
      (biblio-lookup db-selected))))
#+end_src

** Insert a lookup into a bibliography

=sp-fetch-academic-biblio-lookup= opens the target file, moves to the end, runs the combined lookup and saves. It is the old =sp-bibtex-biblio-lookup= with the file choice moved into the helper above.

#+begin_src emacs-lisp -i

(defun sp-fetch-academic-biblio-lookup ()

* DOI look-up with org-ref

** Add an entry from a DOI

=sp-fetch-academic-doi= resolves a DOI to a BibTeX entry with =doi-utils= from =org-ref=, which asks CrossRef and appends the entry to the chosen file.

- The prompt is prefilled with a URL at point, if any, and a leading =https://doi.org/= or =doi:= is removed, so a pasted DOI link works.
- =org-ref= cleans the new entry with =bibtex-clean-entry=, which should apply the key scheme and the entry format from =sp-bibprocess=. This has not been run, so check the first key you get.
- Afterwards it offers to fetch the PDF with =doi-utils-get-bibtex-entry-pdf=. That only works for open-access papers and publishers =org-ref= knows; the PDF is saved in =org-ref-pdf-directory= as =KEY.pdf=.
- When that file exists, =sp-fetch-academic-file= runs, so the =file= field is written and DEVONthink gets the PDF (before, the field stayed empty).

#+begin_src emacs-lisp -i
;;;; DOI look-up

(defun sp--fetch-academic-clean-doi (doi)
  "Return DOI without whitespace or a resolver prefix."
  (replace-regexp-in-string "\\`\\(?:https?://\\(?:dx\\.\\)?doi\\.org/\\|doi:\\)" ""
                            (string-trim doi)))

(defun sp--fetch-academic-follow-doi (key bibfile)
  "Run the follow-up for the PDF `org-ref' saved for KEY, if there is one."
  (let ((pdf (expand-file-name (concat key ".pdf")
                               (if (boundp 'org-ref-pdf-directory)
                                   org-ref-pdf-directory sp-literature-dir))))
    (when (file-exists-p pdf)
      (sp-fetch-academic-file key pdf bibfile))))

;;;###autoload
(defun sp-fetch-academic-doi (doi)
  "Add the BibTeX entry for DOI to a bibliography and offer to fetch the PDF."
  (interactive
   (list (read-string "DOI: " (thing-at-point 'url t))))
  (require 'doi-utils)
  (let ((bibfile (sp--fetch-academic-bibfile)))
    (doi-utils-add-bibtex-entry-from-doi (sp--fetch-academic-clean-doi doi) bibfile)
    (when (y-or-n-p "Try to fetch the PDF too? ")
      (with-current-buffer (find-file-noselect bibfile)
        (goto-char (point-max))
        (bibtex-beginning-of-entry)
        (let ((key (bibtex-key-in-head)))
          (doi-utils-get-bibtex-entry-pdf)
          (sp--fetch-academic-follow-doi key bibfile))))))
#+end_src

* Downloading files

** Attach a file to an entry

=sp-fetch-academic-file-field-value= is the one place that decides how a path is written in a =file= field.

- Inside =sp-literature-dir= it is relative to that folder (=KEY.pdf=, =inbox/mac-bibdesk/x.pdf=), because =citar-library-paths= is that folder and the attachment lint (=sp-bibtex-lint-fix-files=) writes the same form.
- Outside it, the path is relative to the =.bib= file (or =sp-bibliography-dir=), so it still resolves from the bibliography.
- Before, the path was always relative to =sp-bibliography-dir=, which gave =../literature/KEY.pdf= and did not match the lint.

=sp--fetch-academic-attach= writes FILE into the =file= field of the entry at point.

- A second file is appended after a semicolon, the separator the attachment audit in =sp-bibprocess= splits on.
- A file that is already listed is not added twice; the function returns nil then, non-nil when it wrote.
- A new field goes after the last one, adding the comma that was missing if need be.
- =bibtex-set-field= does not exist in Emacs's =bibtex=, so the field is edited with the =bibtex-search-forward-field= helpers.

#+begin_src emacs-lisp -i
;;;; Downloading files

(defun sp-fetch-academic-file-field-value (file &optional bibfile)
  "The text for FILE in a `file' field of an entry of BIBFILE.
Relative to `sp-literature-dir' when FILE is inside it, else to the folder of
BIBFILE (default `sp-bibliography-dir')."
  (let ((file (expand-file-name file))
        (library (file-name-as-directory (expand-file-name sp-literature-dir))))
    (if (string-prefix-p library file)
        (file-relative-name file library)
      (file-relative-name file (if bibfile
                                   (file-name-directory (expand-file-name bibfile))
                                 sp-bibliography-dir)))))

(defun sp--fetch-academic-attach (file &optional bibfile)
  "Add FILE to the `file' field of the BibTeX entry at point; non-nil when written.
BIBFILE is the .bib file of the entry, for a path outside `sp-literature-dir'."
  (let ((relative (sp-fetch-academic-file-field-value file bibfile)))
    (save-excursion
      (bibtex-beginning-of-entry)
      (let* ((bounds (bibtex-search-forward-field "file" t))
             (old (and bounds (bibtex-text-in-field-bounds bounds t))))
        (cond
         ((and old (member relative (mapcar #'string-trim (split-string old ";" t))))
          nil)
         (bounds
          (let ((start (bibtex-start-of-text-in-field bounds)))
            (delete-region start (bibtex-end-of-text-in-field bounds))
            (goto-char start)
            (insert "{" (if (string-empty-p (string-trim old)) "" (concat old "; ")) relative "}")
            t))
         (t
          (bibtex-end-of-entry)
          (backward-char)
          (skip-chars-backward " \t\n")
          (unless (eq (char-before) ?,) (insert ","))
          (insert "\n  file = {" relative "}")
          (when bibtex-comma-after-last-field (insert ","))
          t))))))
#+end_src

** Check for a PDF

=sp--fetch-academic-pdf-p= reads the first four bytes of a file. A real PDF starts with =%PDF=; a paywall or landing page saved by mistake is HTML, and the download command deletes it.

#+begin_src emacs-lisp -i
(defun sp--fetch-academic-pdf-p (file)
  "Return non-nil when FILE starts with the PDF magic number."
  (with-temp-buffer
    (set-buffer-multibyte nil)
    (insert-file-contents-literally file nil 0 4)
    (equal (buffer-string) "%PDF")))
#+end_src

** One follow-up for every PDF

=sp-fetch-academic-file= is the follow-up that every way of getting a PDF ends in: the download command, the DOI command, a PDF that is already on disk, and the inbox. It is the part of =sp-fetch-academic= that makes sure the PDF, not only the BibTeX key, ends up filed.

- Input: the citekey KEY and the PDF file; optionally the =.bib= file and, for a work with no entry yet, the entry text. Output: a plist =(:file :bibfile :attached :dt :sync)=.
- Step 1, the file: a PDF outside the literature folder is moved there as =KEY.pdf=. A different =KEY.pdf= that already exists stops the command, nothing is overwritten.
- Step 2, the entry: with an entry text (the inbox) it is appended to the =.bib= first; without one the key must already be in a =.bib= (found by =sp-fetch-academic-key-bibfile=).
- Step 3, the =file= field: =sp--fetch-academic-attach=, relative to =sp-literature-dir=; a path already listed is not added again. The =.bib= is saved.
- Step 4, DEVONthink (macOS, =sp-fetch-academic-devonthink=): =sp-reading-ensure-file= checks for an existing record first, by citekey, then by file path, and indexes the PDF as =KEY.pdf= only when there is none.
- Step 5 (=sp-fetch-academic-sync-metadata=): =sp-devonthink-sync-key= copies author, title and keywords to the record and writes the litnote link when the key has a litnote.
- A failure in step 4 or 5 is reported, not signalled: the =file= field is already written.
- Who calls it: the download and DOI commands and =C-; B f= (entry exists); =sp-fetch-inbox-confirm= (entry text given; the inbox renames and moves the record itself first, so step 4 finds it).

=sp-fetch-academic-key-bibfile= answers "which registered =.bib= has this key" once; =sp-fetch-inbox= and the keyword sync use it too.

=sp-fetch-academic-attach-pdf= is the command for a PDF that is already on disk: in a BibTeX entry it takes the key from the entry, and asks for the file. It is bound to =C-; B f=.

#+begin_src emacs-lisp -i
;;;; One follow-up for every PDF

(declare-function sp-reading-ensure-file "sp-reading")
(declare-function sp-devonthink-sync-key "sp-devonthink-sync")

(defun sp-fetch-academic-key-bibfile (key)
  "The file of `sp-bibtex-files' that has an entry KEY, or nil."
  (let ((re (format "^[ \t]*@[[:alpha:]]+[ \t]*[{(][ \t]*%s[ \t]*," (regexp-quote key))))
    (seq-find (lambda (f)
                (and (file-readable-p f)
                     (with-temp-buffer
                       (let ((coding-system-for-read 'utf-8)) (insert-file-contents f))
                       (re-search-forward re nil t))))
              (bound-and-true-p sp-bibtex-files))))

(defun sp--fetch-academic-append (bibfile text)
  "Append the entry TEXT to BIBFILE and save it."
  (with-current-buffer (find-file-noselect bibfile)
    (save-excursion
      (goto-char (point-max))
      (unless (bolp) (insert "\n"))
      (insert "\n" (string-trim text) "\n")
      (save-buffer))))

(defun sp--fetch-academic-dt-p ()
  "Non-nil when the DEVONthink step can run."
  (and sp-fetch-academic-devonthink (eq system-type 'darwin) (executable-find "osascript")))

(defun sp--fetch-academic-place (key pdf)
  "Move PDF to KEY.pdf in `sp-literature-dir' unless it is there; return the new path."
  (let ((dest (expand-file-name (concat key ".pdf") sp-literature-dir)))
    (cond ((and (file-exists-p dest) (file-exists-p pdf)
                (equal (file-truename dest) (file-truename pdf)))
           dest)
          ((file-exists-p dest) (user-error "%s already exists" dest))
          ((string-prefix-p (file-name-as-directory (expand-file-name sp-literature-dir))
                            (expand-file-name pdf))
           (expand-file-name pdf))
          (t (make-directory sp-literature-dir t)
             (rename-file pdf dest)
             dest))))

(defun sp--fetch-academic-devonthink (key file)
  "Add FILE to DEVONthink as KEY.pdf unless it has a record, then sync KEY.
Return a plist (:record STATUS :sync RESULT), or nil when nothing ran.  STATUS
is that of `sp-reading-ensure-file'.  A failure is a message, not an error."
  (when (sp--fetch-academic-dt-p)
    (condition-case err
        (progn
          (require 'sp-reading)
          (let ((status (cdr (sp-reading-ensure-file key file))))
            (list :record status
                  :sync (when (and sp-fetch-academic-sync-metadata
                                   (require 'sp-devonthink-sync nil t))
                          (sp-devonthink-sync-key key)))))
      (error (message "Filed, but DEVONthink was not updated: %s" (error-message-string err))
             nil))))

;;;###autoload
(defun sp-fetch-academic-file (key pdf &optional bibfile entry)
  "Put PDF with the entry KEY: file name, `file' field, DEVONthink record, sync.
The entry is in BIBFILE, default the one of `sp-bibtex-files' that has KEY.
With the string ENTRY (a work with no entry yet) it is first appended to BIBFILE,
which is then required.  Return a plist (:file :bibfile :attached :dt)."
  (let* ((bibfile (cond (entry (or bibfile (user-error "No .bib file to add the entry to")))
                        (bibfile)
                        ((sp-fetch-academic-key-bibfile key))
                        (t (user-error "No entry %s in the registered .bib files" key))))
         (file (sp--fetch-academic-place key pdf)))
    (when entry (sp--fetch-academic-append bibfile entry))
    (let ((attached
           (with-current-buffer (find-file-noselect bibfile)
             (save-excursion
               (goto-char (point-min))
               (unless (bibtex-find-entry key) (user-error "No entry %s in %s" key bibfile))
               (prog1 (sp--fetch-academic-attach file bibfile)
                 (save-buffer))))))
      (list :file file :bibfile bibfile :attached attached
            :dt (sp--fetch-academic-devonthink key file)))))

;;;###autoload
(defun sp-fetch-academic-attach-pdf (pdf &optional key)
  "Attach the PDF on disk to an entry and add it to DEVONthink.
In a BibTeX entry KEY is its key; otherwise it is asked."
  (interactive
   (list (read-file-name "PDF: " sp-literature-dir nil t)))
  (let* ((key (or key
                  (and (derived-mode-p 'bibtex-mode)
                       (ignore-errors (save-excursion (bibtex-beginning-of-entry)
                                                      (bibtex-key-in-head))))
                  (read-string "Citation key: ")))
         (result (sp-fetch-academic-file key pdf)))
    (message "%s: %s%s" key (abbreviate-file-name (plist-get result :file))
             (if-let* ((dt (plist-get result :dt))) (format " (DEVONthink: %s)" (plist-get dt :record)) ""))
    result))
#+end_src

** Download and import

=sp-fetch-academic-download= saves a PDF and, when point is in a BibTeX entry, attaches it.

- The URL is prefilled from the one at point.
- The file name is the entry's citation key, so the PDF is found by Citar (=citar-library-paths= is the same folder). Outside an entry it asks for a key and falls back to the name in the URL.
- It refuses to overwrite a file (before downloading) and deletes a download that is not a PDF.
- Inside an entry it then runs =sp-fetch-academic-file=: the =file= field and DEVONthink, as in [[*One follow-up for every PDF][the follow-up]].
- Fetching goes through =url-copy-file=, so it uses Emacs's own proxy and cookie settings. Sites that need a login or a browser session will return a web page and be rejected.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-fetch-academic-download (url)
  "Download the PDF at URL into `sp-fetch-academic-download-dir'.
Inside a BibTeX entry, name the file after its key and attach it."
  (interactive
   (list (read-string "PDF URL: " (thing-at-point 'url t))))
  (let* ((in-entry (and (derived-mode-p 'bibtex-mode)
                        (ignore-errors
                          (save-excursion (bibtex-beginning-of-entry)
                                          (bibtex-key-in-head)))))
         (key (or in-entry
                  (read-string "Citation key (empty: name from the URL): ")))
         (base (if (string-empty-p key)
                   (file-name-base (url-filename (url-generic-parse-url url)))
                 key))
         (file (expand-file-name (concat base ".pdf")
                                 sp-fetch-academic-download-dir)))
    (when (file-exists-p file)
      (user-error "%s already exists" file))
    (make-directory sp-fetch-academic-download-dir t)
    (url-copy-file url file)
    (unless (sp--fetch-academic-pdf-p file)
      (delete-file file)
      (user-error "%s is not a PDF" url))
    (when in-entry
      (sp-fetch-academic-file in-entry file (buffer-file-name)))
    (message "Saved %s" file)
    file))
#+end_src

* Searching with consult-omni

=sp-fetch-academic-omni= runs =consult-omni-scholar= (defined in =sp-browsing=; sources in =consult-omni-scholar-sources=: OpenAlex, PubMed, Scopus, doi.org, notes) with the callback switched off, so the command gets the selected candidate back instead of opening its page.

- A result with a =:doi= property (OpenAlex, Scopus and PubMed set it) goes to =sp-fetch-academic-doi=, which adds the entry and offers the PDF.
- A result with only a =:pdf-url= (OpenAlex, for open access works) goes to =sp-fetch-academic-download=.
- Anything else is refused with a message.

Not run against the real sources: the property names were read from the source modules.

#+begin_src emacs-lisp -i
;;;; Searching with consult-omni

;;;###autoload
(defun sp-fetch-academic-omni ()
  "Search scholarly sources with consult-omni and add the chosen paper.
A result with a DOI goes to `sp-fetch-academic-doi'; one with only the URL of
a PDF goes to `sp-fetch-academic-download'."
  (interactive)
  (unless (require 'sp-browsing nil t)
    (user-error "The sp-browsing module (consult-omni) did not load"))
  (let* ((cand (consult-omni-scholar nil nil nil t))
         (doi (and (stringp cand) (get-text-property 0 :doi cand)))
         (pdf (and (stringp cand) (get-text-property 0 :pdf-url cand))))
    (cond ((and (stringp doi) (not (string-empty-p doi)))
           (sp-fetch-academic-doi doi))
          ((and (stringp pdf) (not (string-empty-p pdf)))
           (sp-fetch-academic-download pdf))
          (t (user-error "That result has neither a DOI nor a PDF address")))))
#+end_src

** Linking litdb to Emacs

[cite:@arthur-1979-dialec-value-form]

#+begin_src emacs-lisp -i
(use-package request :ensure t)
(use-package counsel :ensure t)

(use-package litdb
  :ensure (litdb :type git :host github :repo "jkitchin/litdb" :branch "main" :files ("litdb.el"))
  :after (hydra request counsel org-ref))
#+end_src

The =litdb.el= header has no =Package-Requires=, so Elpaca installs none of what it =require='s (=hydra=, =request=, =counsel=; =openalex= comes with =org-ref=). Without them the load failed with =Cannot load litdb=; they are installed here, and =litdb= waits for them with =:after=.

- The recipe's =:files= must be a /list/, =("litdb.el")=; a bare string ="litdb.el"= matches nothing, so the build dir is empty and Elpaca fails with =No elisp files in .../builds/litdb=.
- Upstream (=jkitchin/litdb=, branch =main=) still keeps =litdb.el= at the repository root, so no subdirectory path is needed.
