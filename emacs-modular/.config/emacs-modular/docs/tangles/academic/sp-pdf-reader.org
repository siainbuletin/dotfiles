* What it is for

- =emureader= is the PDF reader of the configuration; it replaces the old =emacs-reader= checkout (an older version of the same package).
  - It is installed by Elpaca with =use-package= and an explicit recipe (see "Install and build").
  - It renders with MuPDF through a dynamic module.
- =sp-pdf-open= opens a PDF in it, optionally at a page.
  - The page counts from 1 and is the physical page of the PDF.
  - Without =emureader= (or without the built module) it falls back to =find-file= and says so.
- DEVONthink actions use it: Embark =p= on a record (=sp-devonthink-record-pdf=) opens the PDF in Emacs through =sp-pdf-open=.

* What emureader cannot do

- It only views: page jumps, zoom, outline, bookmarks and saveplace. It has no highlights and no annotations.
- Annotation commands stay in DEVONthink for now (=sp-devonthink-highlight=, the highlight links, the =o= action that opens the record there).

* Install and build

- The =use-package= form only runs under Elpaca, so batch tests never try to install it.
- The recipe is explicit: =:ensure (:repo "https://codeberg.org/MonadicSheep/emureader.git" ...)=.
  - Why: Elpaca keeps a cached copy of the GNU ELPA menu (=var/elpaca/cache/gnu-elpa.eld=) and does not refresh it by itself.
  - emureader (renamed from emacs-reader on 2026-11-04, version 0.4.0) is not in an older cached menu.
  - A package missing from the menu gets a recipe with no repository, and =elpaca-update-all= fails with =(wrong-type-argument stringp nil)= in =elpaca-git--fetch=.
  - The upstream repository is the one GNU ELPA mirrors, so the code is the same.
- Packages that depend on emureader (for example =lsp-mode=) fail with it until it installs.
- The dynamic module needs MuPDF 1.26.0, gcc and GNU Make; on macOS: =brew install mupdf gcc make=.

** Where the module is built

- Elpaca keeps two directories per package:
  - =var/elpaca/sources/emureader/=: the git checkout, with the =Makefile=, =render/*.c= and the module.
  - =var/elpaca/builds/emureader/=: only symlinks to the files selected by =:files=; Elpaca deletes and recreates it on every build.
- Elpaca's default =:files= leaves out the =Makefile= and =render/=, so the builds dir had no =Makefile=.
  - =M-x emureader-build= runs =gmake module= in the directory of =emureader.el=, which is the builds dir.
  - Result: =gmake: *** No rule to make target 'module'=.
- =emureader= also looks for =emureader-dyn.dylib= (=.so= on Linux) in that same builds dir, so the module must end up there.
- The recipe therefore does two things:
  - =:build (:before elpaca-build-link sp-pdf-reader--elpaca-build-module)= runs =gmake module= (or =make=) in the source dir before Elpaca links the build dir.
    - The module is kept in the source dir, so it survives the build dir being recreated.
    - make is incremental, so later builds are fast.
    - A failure (for example MuPDF missing) is printed in the Elpaca log but does not fail the install, so =lsp-mode= and the other dependants still build.
  - =:files (:defaults "Makefile" "render" "emureader-dyn.*")= links the module, the =Makefile= and =render/= into the builds dir.
    - The module is found by =emureader=.
    - =M-x emureader-build= works as a manual fallback; its objects land in the source dir through the =render/= symlink.
- =elpaca-defscript= is a macro that only exists under Elpaca, so the step is defined through =eval=.
- To build after changing the recipe or updating the package: =M-x elpaca-rebuild RET emureader=, then restart Emacs.
- =sp-pdf-reader-ready-p= tells whether the module is built; until then =sp-pdf-open= uses =find-file=.

* Options

- =sp-pdf-reader-function-open=, =sp-pdf-reader-function-goto-page= and =sp-pdf-reader-function-build= name the three =emureader= functions used.
  - They are variables so a wrong or renamed name is a one-line change.

#+begin_src emacs-lisp
;;; sp-pdf-reader.el --- Read PDFs in Emacs with emureader -*- lexical-binding: t; -*-

;;; Commentary:

;; Installs emureader and gives one function, `sp-pdf-open', that
;; opens a PDF in it at a page.  Annotations stay in DEVONthink.
;; Literate source: docs/tangles/academic/sp-pdf-reader.org.

;;; Code:

(require 'subr-x)

(defgroup sp-pdf-reader nil
  "Reading PDFs in Emacs with emureader."
  :group 'applications
  :prefix "sp-pdf-reader-")

(defcustom sp-pdf-reader-function-open 'emureader-open-doc
  "Function that opens a document file in emureader (one argument: the file)."
  :type 'symbol)

(defcustom sp-pdf-reader-function-goto-page 'emureader-goto-page
  "Function that goes to a page of the current document (counted from 1)."
  :type 'symbol)

(defcustom sp-pdf-reader-function-build 'emureader-build
  "Command that builds the dynamic module of emureader."
  :type 'symbol)

;; Only under Elpaca: a plain batch Emacs (the tests) must not try to install.
;; The recipe is explicit: Elpaca's cached GNU ELPA menu can predate the
;; rename to emureader, and a package missing from the menu gets a recipe
;; with no repository (error in `elpaca-git--fetch').
;;
;; The module is built in the source dir, before Elpaca links the build dir.
;; Elpaca deletes and recreates the build dir on every (re)build, and its
;; default :files leave out the Makefile and render/, so `emureader-build'
;; (which runs make in the build dir) has nothing to run there.  The module,
;; the Makefile and render/ are linked into the build dir, where emureader
;; looks for the module.
(when (fboundp 'elpaca)
  ;; `eval' because `elpaca-defscript' is a macro that only exists under Elpaca.
  (eval
   '(elpaca-defscript sp-pdf-reader--elpaca-build-module (:type system :dir source)
      "Build the emureader dynamic module in E's source directory.
A failure is only reported, so a missing MuPDF does not block the install."
      ("sh" "-c"
       "m=$(command -v gmake || echo make); \"$m\" module || echo 'emureader: module build failed (brew install mupdf gcc make), then M-x emureader-build'"))
   t)
  (use-package emureader
    :ensure (:repo "https://codeberg.org/MonadicSheep/emureader.git"
             :files (:defaults "Makefile" "render" "emureader-dyn.*")
             :build (:before elpaca-build-link sp-pdf-reader--elpaca-build-module))
    :defer t))

;;;; Opening

(defun sp-pdf-reader-ready-p ()
  "Non-nil when emureader is installed and can open a document."
  (and (require 'emureader nil t)
       (fboundp sp-pdf-reader-function-open)
       (fboundp sp-pdf-reader-function-goto-page)))

;;;###autoload
(defun sp-pdf-open (file &optional page)
  "Open the PDF FILE in emureader, at PAGE (counted from 1) if given.
Falls back to `find-file' when emureader is not ready."
  (interactive (list (read-file-name "PDF: " nil nil t nil
                                     (lambda (f) (or (file-directory-p f)
                                                     (string-suffix-p ".pdf" f t))))
                     (when current-prefix-arg (read-number "Page: " 1))))
  (let ((file (expand-file-name file)))
    (unless (file-exists-p file) (user-error "No such file: %s" file))
    (cond
     ((sp-pdf-reader-ready-p)
      (funcall sp-pdf-reader-function-open file)
      (when page (funcall sp-pdf-reader-function-goto-page page)))
     (t
      (message "emureader is not ready (install it, then M-x %s); using find-file"
               sp-pdf-reader-function-build)
      (find-file file)))))

;;; Provide

(provide 'sp-pdf-reader)
;;; sp-pdf-reader.el ends here
#+end_src
