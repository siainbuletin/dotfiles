* What it does

=M-x sp-refile= (=C-c C-w= in Org buffers, =C-x s t=) is the one command for moving things around. It replaces three separate ones:

| Before                              | Now                                                              |
|-------------------------------------+------------------------------------------------------------------|
| =org-refile= (heading, same file)   | pick a heading of the current note in the prompt                 |
| =sp-split-leave-parents=            | pick =[New note: own file]= in the prompt                        |
| =sp-move-region-to-heading= (M-a)   | pick =[Another note...]=, then a heading of it (or its top)      |
| merging a whole note into another   | run it before the first heading (or with =C-u C-u=)              |

** The prompt

On a heading, =sp-refile= asks "Refile to" with one completion list:

- every heading of the current note, by outline path (the heading itself and its children are left out, so a subtree is never moved into itself);
- =[New note: own file]=: the heading becomes a note of its own, by =sp-split-leave-parents= (parents line, link left behind, file filed by tag, footnotes and the =- seealso ::= line of the id links in the heading from #240). A prefix argument leaves no link there;
- =[Another note...]=: asks for a note (the Vulpea prompt of =sp-select-note=), then for one of its headings or =[Top of note]=.

The subtree keeps its =:ID:=, so links to it keep working wherever it goes. It is inserted as the last child of the target; the source subtree is removed only after the copy is in place and the target file is saved.

** Merging a note

Before the first heading of a note (or with =C-u C-u= anywhere) the whole note is the thing to move: you are asked for a target note and heading, and the note becomes a subtree there: the =#+title:= is the heading, =#+filetags:= its tags, the note's =:ID:= stays on the heading (links to the note still resolve), its text comes first and its headings follow, one level deeper. After you confirm, the old file is deleted (moved to the trash when =delete-by-moving-to-trash= is set).

Choosing =[Top of note]= as the target calls Vulpea's =vulpea-merge= (both notes file-level): the source body goes under a heading with its title, tags are unioned, meta merged, its title and aliases become aliases of the target, links to the source are re-pointed and the file is deleted. Choosing a heading of the target is not something =vulpea-merge= does, so then the note becomes a subtree there, built from Org functions (the =:ID: stays, so links still resolve).

** Compatibility

The split code of the old =sp-split-leave-parents= module now lives in this file (the section "Splitting a heading into a note", moved unchanged from =sp-org-lint.org=), and =sp-split-leave-parents= still works by name; =sp-refile= calls it. The feature =sp-split-leave-parents= is still provided. =sp-move-region-to-heading= is for loose text, not for headings, and is not part of this command.

** Splitting a heading into a note

This module provides =sp-split-leave-parents=, a wrapper around Vulpea's =vulpea-split-heading=.

- It turns the heading at point into its own note file while keeping the link structure of the notes intact.
- Compared with the plain split, it:
  - records where the note came from in a =parents= meta line,
  - leaves a link to the new note in the source file,
  - asks for tags when the new note has none and files it into the folder of its tags,
  - makes sure footnotes still resolve on both sides of the split.

Dependencies and caveats:

- Depends on =vulpea= and =org-id=.
- Uses =sp-notes-filing-folder= and =sp-notes-filing-root= from =sp-notes= to find the folder of a tag, when =sp-notes= is loaded.
- Hooks into =vulpea-split--write-file=, a private Vulpea function. A Vulpea update that renames or reshapes it can break this module; the module warns at load time if the function is missing.
- Required from =sp-vulpea-ext=.
- Bound to ~C-x s t~ in =org-mode-map= by =sp-org-base=.
- That makes ~C-x s~ a prefix key in Org buffers, which shadows =save-some-buffers= there.

The commentary at the top of the module says:

#+begin_quote
`sp-split-leave-parents' wraps `vulpea-split-heading'.  On top of the
normal split it:

1. Adds a `- parents :: [[id:...][Title]]' meta line to the new note,
   pointing at the note the heading came from.  The source is the
   nearest ancestor heading with an ID, else the file-level note (its
   ID is created when missing).  When the subtree already has a
   `parents' line, the new link is put in front of the old value,
   separated by a comma.

2. Leaves a plain link to the new note in the source file, as a line
   of body text exactly where the heading started (not a heading).
   With a prefix argument no link is left.

3. Asks for tags when the new note has none (`sp-split-ask-tags') and
   files it into the folder of its tags (`sp-notes-filing-folder'),
   keeping the file name.  The note keeps its org ID, so links are
   unaffected.  Disable with `sp-split-file-by-tags'.

4. Keeps footnotes working across the split (see
   `sp-split-check-footnotes').  Org labels are unique per file and
   this setup uses no footnote section, so a heading that moves away
   from its definitions would lose its sources.  Every heading that
   cites a footnote gets its own copy of the definition, at the end
   of its own text, in the new note, and in the source note for
   definitions that left with the subtree.  Copies after the first
   get a suffixed label (`[fn:smith]', `[fn:smith-2]', ...).

5. Moves id links out of the heading text (`sp-split-links-to-seealso').
   The title of the new note is the heading without its
   `[[id:...][...]]' links, and they go into a `- seealso ::' meta line
   in its body.

Steps 1, 2, 4 and 5 hook `vulpea-split--write-file', a private function of
vulpea, and only act while `sp-split-leave-parents' is running.  A
plain `vulpea-split-heading' is unchanged.
#+end_quote

*** Parents and source links

**** Building an id link

=sp-split--link-to= returns an Org id link to ID, described with the note's title from the Vulpea database, or FALLBACK-TITLE when the database does not know the ID yet.

#+begin_src emacs-lisp -i
(defun sp-split--link-to (id fallback-title)
  "Return an id link to ID, titled from the database or FALLBACK-TITLE."
  (org-link-make-string
   (concat "id:" id)
   (if-let* ((note (vulpea-db-get-by-id id)))
       (vulpea-note-title note)
     fallback-title)))
#+end_src

**** Finding the parent note

=sp-split--parent-link= finds where the heading with ID lives.

- Visits the file and walks up the ancestor headings.
- Takes the first one with an ID property, using its heading text as title.
- If no ancestor has an ID, falls back to the file-level note. It creates a file-level ID with =org-id-get-create= when there is none, so the source file can be modified as a side effect. The title is the buffer title or the file name.
- Returns the parent ID together with a ready-made link.

#+begin_src emacs-lisp -i
(defun sp-split--parent-link (id)
  "Return (PARENT-ID . LINK) for the note the heading with ID lives in.
Walks up the ancestors of the heading and takes the first one with an
ID.  If none has one, falls back to the file-level note, creating its
ID when it is missing."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (when-let* ((pos (org-find-entry-with-id id)))
         (goto-char pos)
         (let (pid title)
           (while (and (not pid) (org-up-heading-safe))
             (when-let* ((x (org-entry-get (point) "ID")))
               (setq pid x
                     title (org-link-display-format
                            (org-get-heading t t t t)))))
           (unless pid
             (goto-char (point-min))
             (setq pid (or (org-entry-get (point-min) "ID")
                           (org-id-get-create))
                   title (or (and (fboundp 'vulpea-buffer-title-get)
                                  (vulpea-buffer-title-get))
                             (file-name-base path))))
           (cons pid (sp-split--link-to pid title))))))))
#+end_src

**** Adding the parent to the new note's body

=sp-split--body-with-parent= edits the text that will become the new note.

- Only looks at the part before the first child heading, so children keep their own parents lines.
- If a parents line already exists, the new link goes in front of the old value with a comma, unless that parent is already listed.
- Otherwise a new parents line is added at the top. It is joined directly to an existing meta list, or separated from ordinary text by a blank line.
- The comment about reading match data early guards against later calls clobbering it.

#+begin_src emacs-lisp -i
(defun sp-split--body-with-parent (body parent-id link)
  "Return BODY with LINK recorded in its `parents' meta line.
PARENT-ID is the id LINK points to."
  (let* ((case-fold-search nil)
         ;; Only the section before the first child heading: children
         ;; may carry `parents' lines of their own, which stay untouched.
         (top-end (or (string-match "^\\*+ " body) (length body)))
         (top (substring body 0 top-end))
         (rest (substring body top-end)))
    (cond
     ;; A parents line already exists: prepend the new link to its value.
     ((string-match
       "^\\([ \t]*[-+][ \t]+parents[ \t]+::[ \t]*\\)\\(.*\\)$" top)
      ;; Read everything out of the match data before calling anything
      ;; that may clobber it.
      (let* ((mb (match-beginning 0))
             (me (match-end 0))
             (prefix (match-string 1 top))
             (existing (string-trim (match-string 2 top))))
        (if (string-search (concat "id:" parent-id) existing)
            body
          (concat (substring top 0 mb)
                  prefix link
                  (if (string-empty-p existing)
                      ""
                    (concat ", " existing))
                  (substring top me)
                  rest))))
     (t
      (let ((line (concat "- parents :: " link)))
        (cond
         ((string-empty-p body) line)
         ;; Body opens with meta already: join that list.
         ((string-match-p "\\`[ \t]*[-+][ \t]+[^ \t\n]+[ \t]+::" body)
          (concat line "\n" body))
         (t (concat line "\n\n" body))))))))
#+end_src

**** Id links in the heading

A heading can carry id links (=[[id:...][Name]]=). They do not belong in the title of the new note, so they are moved to a =seealso= meta line.

=sp-split--extract-id-links= returns the heading text without its id links, and the links themselves.

- Each link is replaced in the title by its description text, so only the ID is stripped; a link without a description leaves nothing.
- Duplicate links are listed once, and extra spaces left by the removal are tidied.
- If nothing is left of the title (only description-less links), the title is the displayed link text and no link is moved, so the note keeps a title.

=sp-split--body-with-seealso= records the links in the body.

- An existing =seealso= line gets the new links after its value, skipping IDs already on it.
- Otherwise a =- seealso ::= line is added, joined to an existing meta list or separated from ordinary text by a blank line, as for =parents=.
- It runs before the parents line is added, so =parents= ends up first.

#+begin_src emacs-lisp -i
(defconst sp-split--id-link-regexp
  "\\[\\[id:\\([^]\n]+\\)\\]\\(?:\\[\\([^]\n]*\\)\\]\\)?\\]"
  "Match an id link; group 1 is the ID, group 2 the description, if any.")

(defun sp-split--extract-id-links (title)
  "Return (CLEAN-TITLE . LINKS) for the heading text TITLE.
LINKS are the id links found in TITLE, as strings, in order and without
duplicates; CLEAN-TITLE is TITLE with each link replaced by its description
(nothing, for a link without one), whitespace tidied.  When
nothing would be left of TITLE, it is returned as the text of its links'
descriptions and LINKS is nil, so the new note still has a title."
  (let ((links nil)
        (start 0))
    (while (string-match sp-split--id-link-regexp title start)
      (setq start (match-end 0))
      (cl-pushnew (match-string 0 title) links :test #'equal))
    (if (null links)
        (cons title nil)
      (let ((clean (string-trim
                    (replace-regexp-in-string
                     "[ \t]+" " "
                     (replace-regexp-in-string
                      sp-split--id-link-regexp
                      (lambda (m)
                        (save-match-data
                          (string-match sp-split--id-link-regexp m)
                          (or (match-string 2 m) "")))
                      title t t)
                     t t))))
        (if (string-empty-p clean)
            (cons (org-link-display-format title) nil)
          (cons clean (nreverse links)))))))

(defun sp-split--body-with-seealso (body links)
  "Return BODY with the id LINKS recorded in its `seealso' meta line.
A link whose ID is already on the line is not added again.  Like
`sp-split--body-with-parent', only the text before the first child
heading is looked at."
  (let* ((case-fold-search nil)
         (top-end (or (string-match "^\\*+ " body) (length body)))
         (top (substring body 0 top-end))
         (rest (substring body top-end)))
    (cond
     ((null links) body)
     ((string-match
       "^\\([ \t]*[-+][ \t]+seealso[ \t]+::[ \t]*\\)\\(.*\\)$" top)
      (let* ((mb (match-beginning 0))
             (me (match-end 0))
             (prefix (match-string 1 top))
             (existing (string-trim (match-string 2 top)))
             (new (seq-remove
                   (lambda (l)
                     (string-match sp-split--id-link-regexp l)
                     (string-search (concat "id:" (match-string 1 l)) existing))
                   links)))
        (if (null new)
            body
          (concat (substring top 0 mb)
                  prefix existing
                  (if (string-empty-p existing) "" ", ")
                  (string-join new ", ")
                  (substring top me)
                  rest))))
     (t
      (let ((line (concat "- seealso :: " (string-join links ", "))))
        (cond
         ((string-empty-p body) line)
         ((string-match-p "\\`[ \t]*[-+][ \t]+[^ \t\n]+[ \t]+::" body)
          (concat line "\n" body))
         (t (concat line "\n\n" body))))))))
#+end_src

**** Leaving a link in the source

=sp-split--insert-source-link= inserts a link to the split heading on its own line just before the heading in the source file.

- Because it goes in front of the heading, it survives when Vulpea cuts the subtree.
- It returns markers around the inserted text, so the insertion can be undone if writing the new file fails.

#+begin_src emacs-lisp -i
(defun sp-split--insert-source-link (id title)
  "Insert a plain link to ID on the line where its heading starts.
TITLE is the fallback description.  The link goes in front of the
heading, so it is still there once vulpea cuts the subtree.  Return a
cons of markers around the inserted text, or nil."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (when-let* ((pos (org-find-entry-with-id id)))
         (goto-char pos)
         (let ((beg (copy-marker pos)))
           (insert (sp-split--link-to id (org-link-display-format title))
                   "\n")
           (cons beg (copy-marker (point)))))))))
#+end_src

*** Footnotes

Footnotes and splitting:

- Org footnote labels are unique per file.
- This setup keeps each definition at the end of the text of the heading that uses it, rather than in a footnote section.
- Splitting a subtree off can therefore leave references without definitions on either side.
- In these functions a section means a heading's own text, up to the next heading of any level.

**** Background

The comment block introducing the footnote helpers, explaining the problem described above.

#+begin_src emacs-lisp -i
;;;; Footnotes
;;
;; Org footnote labels are unique per file.  Without a footnote section,
;; definitions sit at the end of the text of the heading that uses them,
;; so a split can strand references (definition left in the source) or
;; strand the source (definition left with the subtree).  Sections here
;; are a heading's own text: from the heading to the next heading of
;; any level, children excluded.
#+end_src

**** Scanning footnotes

=sp-split--fn-scan= parses the buffer with =org-element-parse-buffer= and returns three lists:

- the start positions of all headings,
- every standard reference, with its label and position,
- every definition, with its label, position and full text.

A labelled inline footnote counts as a definition. It is rewritten into the standard definition form so it can be copied elsewhere.

#+begin_src emacs-lisp -i
(defun sp-split--fn-scan ()
  "Scan the accessible part of the current Org buffer for footnotes.
Return (HEADS REFS DEFS).  HEADS is the sorted list of heading start
positions.  REFS lists (LABEL BEGIN) for each standard reference
`[fn:LABEL]'.  DEFS lists (LABEL BEGIN TEXT) for each definition, TEXT
being the whole definition as `[fn:LABEL] ...'; a labelled inline
footnote `[fn:LABEL:...]' counts as a definition too."
  (let ((tree (org-element-parse-buffer))
        heads refs defs)
    (org-element-map tree 'headline
      (lambda (h) (push (org-element-property :begin h) heads)))
    (org-element-map tree '(footnote-reference footnote-definition)
      (lambda (el)
        (let ((label (org-element-property :label el))
              (begin (org-element-property :begin el)))
          (when label
            (if (eq (org-element-type el) 'footnote-definition)
                (push (list label begin
                            (string-trim-right
                             (buffer-substring-no-properties
                              begin (org-element-property :end el))))
                      defs)
              (let ((cb (org-element-property :contents-begin el))
                    (ce (org-element-property :contents-end el)))
                (if (eq (org-element-property :type el) 'inline)
                    (when (and cb ce)
                      (push (list label begin
                                  (format "[fn:%s] %s" label
                                          (string-trim
                                           (buffer-substring-no-properties
                                            cb ce))))
                            defs))
                  (push (list label begin) refs))))))))
    (list (sort heads #'<) (nreverse refs) (nreverse defs))))
#+end_src

**** Which section a position is in

=sp-split--fn-section= returns the start of the heading section containing a position, or 0 for text before the first heading.

#+begin_src emacs-lisp -i
(defun sp-split--fn-section (pos heads)
  "Return the start of the section containing POS, given sorted HEADS.
Text before the first heading is section 0."
  (let ((sec 0))
    (dolist (h heads sec)
      (when (<= h pos) (setq sec h)))))
#+end_src

**** End of a section

=sp-split--fn-section-end= returns the position of the next heading after a section start, or the end of the buffer.

#+begin_src emacs-lisp -i
(defun sp-split--fn-section-end (sec heads)
  "Return the end of section SEC: the next heading, or the end of buffer."
  (or (seq-find (lambda (h) (> h sec)) heads) (point-max)))
#+end_src

**** Fresh labels

=sp-split--fn-fresh= returns the label itself if unused, otherwise the first free label with a numeric suffix starting at 2.

#+begin_src emacs-lisp -i
(defun sp-split--fn-fresh (label used)
  "Return LABEL if it is not in USED, else LABEL-2, LABEL-3, ... likewise."
  (if (not (member label used))
      label
    (let ((n 2))
      (while (member (format "%s-%d" label n) used)
        (setq n (1+ n)))
      (format "%s-%d" label n))))
#+end_src

**** Relabelling a definition

=sp-split--fn-def-with-label= swaps the label at the start of a definition's text for a new one.

#+begin_src emacs-lisp -i
(defun sp-split--fn-def-with-label (text label)
  "Return the definition TEXT with its label replaced by LABEL."
  (replace-regexp-in-string "\\`\\[fn:[^]\n]*\\]" (format "[fn:%s]" label)
                            text t t))
#+end_src

**** Applying footnote edits

=sp-split--fn-apply= turns the planned additions (definitions to append at the end of given sections) into insertions with sensible blank-line spacing, merges them with the label replacements, and applies everything from the end of the buffer backwards so earlier positions remain valid.

#+begin_src emacs-lisp -i
(defun sp-split--fn-apply (heads adds edits)
  "Apply footnote changes to the current buffer.
ADDS maps a section to the definition texts to put at the end of it
\(newest first).  EDITS is a list of (POS LENGTH STRING) replacements.
Everything is positioned against the buffer as it is now, and applied
from the end so earlier positions stay valid."
  (dolist (a adds)
    (let* ((pos (sp-split--fn-section-end (car a) heads))
           (prefix (cond ((= pos (point-min)) "")
                         ((and (>= (- pos (point-min)) 2)
                               (string= (buffer-substring-no-properties
                                         (- pos 2) pos)
                                        "\n\n"))
                          "")
                         ((save-excursion (goto-char pos) (bolp)) "\n")
                         (t "\n\n")))
           (suffix (if (= pos (point-max)) "\n" "\n\n")))
      (push (list pos 0 (concat prefix
                                (mapconcat #'identity (reverse (cdr a)) "\n\n")
                                suffix))
            edits)))
  (dolist (e (sort edits (lambda (x y) (> (car x) (car y)))))
    (goto-char (car e))
    (delete-region (car e) (+ (car e) (cadr e)))
    (insert (nth 2 e))))
#+end_src

**** Definitions in the source file

=sp-split--fn-source-defs= scans the whole file containing ID and returns its footnote definitions as an alist from label to text.

#+begin_src emacs-lisp -i
(defun sp-split--fn-source-defs (id)
  "Return an alist (LABEL . TEXT) of the footnote definitions in ID's file."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))

#+end_src

**** Fixing footnotes in the new note

=sp-split--fn-fix-body= works on the new note's body in a temporary Org buffer (with mode hooks delayed for speed).

For each cited label it decides which heading sections need their own copy of the definition:

- If the definition is nowhere (not in the body, not in the source), the label is recorded as dangling.
- If it is only in the source, every citing section gets a copy.
- If it is in the body but cited from several sections, the sections without a definition get a copy.

Each copy after the first gets a fresh suffixed label, and the references in that section are renamed to match (skipping the four characters of the opening bracket and fn colon to reach the label). It returns the new body, the number of copies and the dangling labels.

#+begin_src emacs-lisp -i
(defun sp-split--fn-fix-body (body source-defs)
  "Make the footnotes in BODY self-contained.
SOURCE-DEFS is an alist (LABEL . TEXT) of the source file's definitions.
A heading in BODY that cites a footnote gets its own copy of the
definition when the definition is not in BODY at all, or when the
footnote is cited from several headings and the heading has none of its
own.  Return (NEW-BODY COPIED DANGLING), DANGLING being the labels
cited but defined nowhere."
  (with-temp-buffer
    (delay-mode-hooks (org-mode))
    (insert body)
    (pcase-let* ((`(,heads ,refs ,defs) (sp-split--fn-scan))
                 (used (mapcar #'car defs))
                 (edits nil)
                 (adds nil)
                 (copied 0)
                 (dangling nil))
      (dolist (label (seq-uniq (mapcar #'car refs)))
        (let* ((mine (lambda (e) (equal (car e) label)))
               (rsecs (seq-uniq
                       (mapcar (lambda (r) (sp-split--fn-section (cadr r) heads))
                               (seq-filter mine refs))))
               (dsecs (mapcar (lambda (d) (sp-split--fn-section (cadr d) heads))
                              (seq-filter mine defs)))
               (text (or (nth 2 (assoc label defs))
                         (cdr (assoc label source-defs))))
               (needy (cond ((null text)
                             (push label dangling)
                             nil)
                            ;; Defined only in the source: every citing
                            ;; heading gets a copy.
                            ((null dsecs) rsecs)
                            ;; Defined here, cited from several headings:
                            ;; those without a definition get a copy.
                            ((cdr rsecs)
                             (seq-remove (lambda (s) (memql s dsecs)) rsecs))
                            (t nil))))
          (dolist (sec needy)
            (let ((new (sp-split--fn-fresh label used)))
              (push new used)
              (unless (equal new label)
                (dolist (r (seq-filter
                            (lambda (r)
                              (and (equal (car r) label)
                                   (eql (sp-split--fn-section (cadr r) heads)
                                        sec)))
                            refs))
                  ;; Skip `[fn:' to reach the label itself.
                  (push (list (+ (cadr r) 4) (length label) new) edits)))
              (push (sp-split--fn-def-with-label text new)
                    (alist-get sec adds nil nil #'eql))
              (setq copied (1+ copied))))))
      (sp-split--fn-apply heads adds edits)
      (list (string-trim-right (buffer-string)) copied (nreverse dangling)))))
#+end_src

**** Keeping footnotes in the source

=sp-split--fn-keep-in-source= handles the opposite direction.

- While the subtree is still in place, finds definitions inside the subtree that are cited from headings outside it.
- Copies them to each of those headings.
- The first citing heading can keep the original label, because the original definition is about to leave with the subtree.
- Returns the number of definitions copied.

#+begin_src emacs-lisp -i
(defun sp-split--fn-keep-in-source (id)
  "Keep footnotes usable in the source once the subtree of ID is cut.
Definitions inside the subtree that headings outside it still cite are
copied to those headings.  Must run while the subtree is still in
place.  Return the number of definitions copied."
  (let ((copied 0))
    (when-let* ((note (vulpea-db-get-by-id id))
                (path (vulpea-note-path note)))
      (with-current-buffer (find-file-noselect path)
        (org-with-wide-buffer
         (when-let* ((pos (org-find-entry-with-id id)))
           (goto-char pos)
           (org-back-to-heading t)
           (let ((beg (point))
                 (end (save-excursion (org-end-of-subtree t t) (point))))
             (pcase-let* ((`(,heads ,refs ,defs) (sp-split--fn-scan))
                          (inside (lambda (p) (and (>= p beg) (< p end))))
                          (used (mapcar #'car
                                        (seq-remove
                                         (lambda (d) (funcall inside (cadr d)))
                                         defs)))
                          (edits nil)
                          (adds nil))
               (dolist (d (seq-filter (lambda (d) (funcall inside (cadr d)))
                                      defs))
                 (let* ((label (car d))
                        (outside (seq-filter
                                  (lambda (r)
                                    (and (equal (car r) label)
                                         (not (funcall inside (cadr r)))))
                                  refs))
                        (secs (seq-uniq
                               (mapcar (lambda (r)
                                         (sp-split--fn-section (cadr r) heads))
                                       outside))))
                   ;; The original goes away with the subtree, so the
                   ;; first citing heading may keep the label.
                   (dolist (sec secs)
                     (let ((new (sp-split--fn-fresh label used)))
                       (push new used)
                       (unless (equal new label)
                         (dolist (r (seq-filter
                                     (lambda (r)
                                       (eql (sp-split--fn-section (cadr r) heads)
                                            sec))
                                     outside))
                           (push (list (+ (cadr r) 4) (length label) new)
                                 edits)))
                       (push (sp-split--fn-def-with-label (nth 2 d) new)
                             (alist-get sec adds nil nil #'eql))
                       (setq copied (1+ copied))))))
               (sp-split--fn-apply heads adds edits)))))))
    copied))
#+end_src

**** Safe wrapper for the new note

=sp-split--fn-check-body= runs the body fix when footnote checking is on, records the result in the report, and on any error logs a message and returns the body unchanged, so a footnote problem never aborts the split.

#+begin_src emacs-lisp -i
(defun sp-split--fn-check-body (body id)
  "Return BODY, the body of the note split from ID, with footnotes fixed.
Never aborts the split: on an error BODY is returned unchanged."
  (if (not sp-split-check-footnotes)
      body
    (condition-case err
        (pcase-let ((`(,new ,copied ,dangling)
                     (sp-split--fn-fix-body body (sp-split--fn-source-defs id))))
          (setq sp-split--fn-report
                (list :into-new copied :dangling dangling))
          new)
      (error
       (message "sp-split: footnote check skipped: %s"
                (error-message-string err))
       body))))
#+end_src

*** Hooking into Vulpea

**** Advice around the file writer

=sp-split--write-file-advice= wraps =vulpea-split--write-file=.

- Passes straight through unless =sp-split-leave-parents= is running.
- When active, it receives the path, ID, title, heading, tags, properties and body of the note about to be written.
- At this point Vulpea has already validated the split and the subtree is still in the source.

It then:

- finds the parent link,
- moves id links out of the title (see above) and fixes footnotes in the body,
- adds the seealso and parents lines,
- inserts the link in the source if wanted,
- calls the original writer, then copies footnotes back into the source.

If writing the new file fails, the inserted source link is removed again and the error is re-signalled, so the source is left as it was.

#+begin_src emacs-lisp -i
(defun sp-split--write-file-advice (fn &rest args)
  "Around advice for `vulpea-split--write-file'.
FN is the original function and ARGS its arguments: PATH ID TITLE HEAD
TAGS PROPERTIES BODY.  Does nothing unless `sp-split-leave-parents' is
running."
  (if (not sp-split--active)
      (apply fn args)
    (pcase-let ((`(,path ,id ,title ,head ,tags ,props ,body) args))
      ;; The subtree is still in the source file at this point, and
      ;; vulpea has already run its checks, so a refused split never gets
      ;; this far.
      (let* ((parent (sp-split--parent-link id))
             ;; Id links in the heading go to a `seealso' line, not the title.
             (extracted (if sp-split-links-to-seealso
                            (sp-split--extract-id-links title)
                          (cons title nil)))
             (title (car extracted))
             (body (sp-split--fn-check-body body id))
             (body (sp-split--body-with-seealso body (cdr extracted)))
             (body (if parent
                       (sp-split--body-with-parent
                        body (car parent) (cdr parent))
                     body))
             (stub (when sp-split--want-link
                     (sp-split--insert-source-link id title))))
        (condition-case err
            ;; The subtree is still in the source once the file is
            ;; written, which is when its footnotes can be copied back.
            (prog1 (funcall fn path id title head tags props body)
              (sp-split--fn-after-write id))
          (error
           ;; Writing the new file failed: take the link back out.
           (when (and stub (marker-buffer (car stub)))
             (with-current-buffer (marker-buffer (car stub))
               (delete-region (car stub) (cdr stub))))
           (signal (car err) (cdr err))))))))
#+end_src

*** Tags and filing

**** Asking for tags

A split-out note often has no tags, so before it is filed =sp-split--file-by-tags= asks for them (=sp-split-ask-tags=, on by default) with =sp-org-tag-read-note-tags=. That is the same menu as in note creation: the tags headed by their group in =sp-org-tag-groups-alist= when =sp-org-tag-groups= is loaded, a plain completion otherwise. The tags go into the =#+filetags= line of the new file (=sp-split--set-filetags=) and decide the folder of the file.

#+begin_src emacs-lisp -i
(declare-function sp-org-tag-read-note-tags "sp-org-tag-lint")

(defcustom sp-split-ask-tags t
  "When non-nil, ask for the tags of a split-out note that has none.
The menu is `sp-org-tag-read-note-tags' (grouped by tag group); the tags
go into `#+filetags' and decide the folder of the file."
  :type 'boolean
  :group 'sp-split)

(defun sp-split--set-filetags (path tags)
  "Write TAGS as the `#+filetags' line of the note at PATH."
  (with-current-buffer (find-file-noselect path)
    (org-with-wide-buffer
     (goto-char (point-min))
     (let ((case-fold-search t)
           (line (format "#+filetags: :%s:" (mapconcat #'identity tags ":"))))
       (cond ((re-search-forward "^#\\+filetags:.*$" nil t)
              (replace-match line t t))
             ((re-search-forward "^#\\+title:.*$" nil t)
              (insert "\n" line)))))
    (save-buffer)))
#+end_src

**** Filing by tags

=sp-split--file-by-tags= moves the new note's file into the folder of its tags.

- Tags: the note's own, or asked for when it has none (and then written to =#+filetags=).
- Folder: =sp-notes-filing-folder= under =sp-notes-filing-root=; the file name stays as vulpea wrote it.
- It does nothing when the note has no tags, is already in its folder, or the target file exists (it says so).
- A buffer visiting the file is saved and killed first.
- After the move it:
  - tells Vulpea to forget the old path (using the private =vulpea-db--forget-file=),
  - registers the new location with =org-id=,
  - re-indexes the file,
  - returns the updated note.

#+begin_src emacs-lisp -i
(defun sp-split--file-by-tags (note)
  "Ask for the tags of NOTE if it has none, then file it into its tag folder.
Return the note as vulpea knows it afterwards.  The org ID stays the same,
so id links keep working.  A note without tags, or one already in its
folder, stays where it is, and so does one whose target file exists."
  (require 'sp-notes nil t)
  (let* ((old (vulpea-note-path note))
         (id (vulpea-note-id note))
         (tags (or (vulpea-note-tags note)
                   (when (and sp-split-ask-tags (require 'sp-org-tag-lint nil t))
                     (let ((chosen (sp-org-tag-read-note-tags
                                    (format "Tags for \"%s\": " (vulpea-note-title note)))))
                       (when chosen (sp-split--set-filetags old chosen))
                       chosen))))
         (root (and (boundp 'sp-notes-filing-root) sp-notes-filing-root
                    (file-name-as-directory (expand-file-name sp-notes-filing-root))))
         (dir (and tags root (fboundp 'sp-notes-filing-folder)
                   (file-name-as-directory
                    (expand-file-name (sp-notes-filing-folder tags) root))))
         (new (and dir (expand-file-name (file-name-nondirectory old) dir))))
    (if (or (not new) (file-equal-p old new) (file-exists-p new))
        (progn (when (and new (not (file-equal-p old new)))
                 (message "Not filed: %s exists" new))
               (if tags (or (vulpea-db-get-by-id id) note) note))
      (when-let* ((buffer (find-buffer-visiting old)))
        (with-current-buffer buffer (save-buffer))
        (kill-buffer buffer))
      (make-directory dir t)
      (rename-file old new)
      (vulpea-db--forget-file old)
      (org-id-add-location id new)
      (vulpea-db-update-file new)
      (message "Filed in %s" (abbreviate-file-name dir))
      (or (vulpea-db-get-by-id id) note))))
#+end_src

**** sp-split-leave-parents

The interactive entry point, autoloaded.

** Moving a subtree

TEXT is the subtree as a string. It goes in as the last child of the heading at TARGET, a marker; a nil TARGET puts it at the end of the file as a top-level heading. The target buffer is saved.

#+begin_src emacs-lisp -i
(defun sp-refile--insert (text target buffer)
  "Insert the subtree TEXT as the last child of TARGET in BUFFER.
TARGET is a marker, or nil for the end of BUFFER as a top-level heading.
BUFFER is saved when it visits a file."
  (with-current-buffer buffer
    (org-with-wide-buffer
     (let ((level 1))
       (if target
           (progn (goto-char target)
                  (setq level (1+ (org-current-level)))
                  (org-end-of-subtree t t))
         (goto-char (point-max)))
       (unless (bolp) (insert "\n"))
       (let ((start (point)))
         (insert text)
         (unless (bolp) (insert "\n"))
         ;; Re-level the inserted tree to LEVEL.
         (save-excursion
           (goto-char start)
           (let ((delta (- level (org-current-level))))
             (unless (zerop delta)
               (org-map-region
                (lambda ()
                  (if (> delta 0)
                      (dotimes (_ delta) (org-do-demote))
                    (dotimes (_ (- delta)) (org-do-promote))))
                start (point-max))))))))
    (when buffer-file-name (save-buffer))))

(defun sp-refile--move-heading (target buffer)
  "Move the subtree at point under TARGET in BUFFER (see `sp-refile--insert').
The copy is made and saved first, the original is removed after."
  (let* ((src (current-buffer))
         (beg (save-excursion (org-back-to-heading t) (copy-marker (point))))
         (end (save-excursion (org-back-to-heading t)
                              (org-end-of-subtree t t) (copy-marker (point))))
         (text (buffer-substring-no-properties beg end)))
    (when (and (eq buffer src) target
               (>= target beg) (< target end))
      (user-error "Cannot refile a heading into itself"))
    (sp-refile--insert text target buffer)
    (with-current-buffer src
      (org-with-wide-buffer
       (delete-region beg end))
      (when buffer-file-name (save-buffer)))))

** Merging a whole note

=sp-refile--note-as-subtree= turns the current note into one subtree string.

#+begin_src emacs-lisp -i
(defun sp-refile--note-as-subtree ()
  "Return the whole current note as a level 1 subtree string.
The title becomes the heading, `#+filetags' its tags, the note's ID
stays in a property drawer, the text before the first heading comes
first and the headings follow, one level deeper."
  (let* ((text (org-with-wide-buffer (buffer-substring-no-properties
                                      (point-min) (point-max))))
         title tags id)
    (with-temp-buffer
      (insert text)
      (delay-mode-hooks (org-mode))
      (goto-char (point-min))
      (let ((kw (org-collect-keywords '("TITLE" "FILETAGS"))))
        (setq title (car (cdr (assoc "TITLE" kw)))
              tags (split-string (or (car (cdr (assoc "FILETAGS" kw))) "")
                                 ":" t "[ \t]+")))
      (setq id (org-entry-get (point-min) "ID"))
      (goto-char (point-min))
      ;; Drop the front matter: the top property drawer and #+keywords.
      (when (looking-at-p "[ \t]*:PROPERTIES:")
        (when (re-search-forward "^[ \t]*:END:[ \t]*\n?" nil t)
          (delete-region (point-min) (point))))
      (goto-char (point-min))
      (while (looking-at "[ \t]*#\\+[A-Za-z_]+:.*\n?")
        (replace-match ""))
      ;; Demote every existing heading by one.
      (goto-char (point-min))
      (while (re-search-forward "^\\(\\*+\\) " nil t)
        (replace-match "\\1* "))
      (concat "* " (or title "Untitled")
              (if tags (format " :%s:" (string-join tags ":")) "")
              "\n"
              (if id (format ":PROPERTIES:\n:ID:       %s\n:END:\n" id) "")
              (string-trim-left (buffer-string) "\n+")))))

(defun sp-refile--merge-note (target buffer note)
  "Merge the current note under TARGET in BUFFER, the buffer of NOTE.
With the top of the note as TARGET this is `vulpea-merge' (tags, aliases and
meta are folded in and links to the source re-pointed).  With a heading
as TARGET the note becomes a subtree there; Org functions only.  Asks
before the file of the current note is deleted."
  (if (and (null target) (fboundp 'vulpea-merge))
      (let* ((id (org-with-wide-buffer (org-entry-get (point-min) "ID")))
             (source (and id (vulpea-db-get-by-id id))))
        (unless source (user-error "This note is not in the Vulpea database"))
        (unless (y-or-n-p (format "Merge %s into %s and delete it? "
                                  (vulpea-note-title source)
                                  (vulpea-note-title note)))
          (user-error "Merge cancelled"))
        (vulpea-merge source note))
    (sp-refile--merge-subtree target buffer)))

(defun sp-refile--merge-subtree (target buffer)
  "Merge the current note as a subtree under TARGET in BUFFER.
Asks before the file of the current note is deleted afterwards."
  (let ((file buffer-file-name)
        (src (current-buffer)))
    (unless file (user-error "This buffer is not a note file"))
    (when (eq buffer src) (user-error "Cannot merge a note into itself"))
    (unless (y-or-n-p (format "Merge %s into %s and delete it? "
                              (file-name-nondirectory file)
                              (buffer-name buffer)))
      (user-error "Merge cancelled"))
    (let ((text (sp-refile--note-as-subtree)))
      (sp-refile--insert text target buffer)
      (set-buffer-modified-p nil)
      (kill-buffer src)
      (delete-file file delete-by-moving-to-trash)
      (when (fboundp 'vulpea-db-update-file)
        (ignore-errors (vulpea-db-update-file file))))
    (message "Merged %s" (file-name-nondirectory file))))

;;;###autoload
(defun sp-refile (&optional arg)
  "Move the heading at point, or merge the note when before its first heading.
On a heading, choose from the headings of this note, `[New note: own
file]' (split, see `sp-split-leave-parents'; a plain prefix argument
leaves no link) or `[Another note...]'.  Before the first heading, or
with `C-u C-u', the whole note is merged under a heading of another note."
  (interactive "P")
  (unless (derived-mode-p 'org-mode) (user-error "Not an Org buffer"))
  (let ((merge (or (equal arg '(16))
                   (org-with-wide-buffer
                    (and (not (ignore-errors (org-back-to-heading t) t)))))))
    (if merge
        (pcase-let ((`(,target ,buf ,note) (sp-refile--read-other-note)))
          (sp-refile--merge-note target buf note))
      (let* ((cands (sp-refile--local-candidates))
             (choice (completing-read
                      "Refile to: "
                      (append (list sp-refile--new-note sp-refile--other-note)
                              (mapcar #'car cands))
                      nil t)))
        (cond
         ((string= choice sp-refile--new-note)
          (let ((current-prefix-arg arg))
            (sp-split-leave-parents (and arg t))))
         ((string= choice sp-refile--other-note)
          (pcase-let ((`(,target ,buf ,_note) (sp-refile--read-other-note)))
            (sp-refile--move-heading target buf)))
         (t
          (sp-refile--move-heading (cdr (assoc choice cands))
                                   (current-buffer))))))))
