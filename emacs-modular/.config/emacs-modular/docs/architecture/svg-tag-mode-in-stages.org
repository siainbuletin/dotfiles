#+title: Bringing svg-tag-mode back, in stages
#+date: 2026-11-03
#+status: proposed

This is a plan, not an implementation: no code changes come with it. Written from a Linux container with no Emacs, so *nothing here has been run on the Mac*. What I could do was read the history of the earlier attempts (#254, #259, #260, #264, #266) and the source of =svg-tag-mode= 0.3.3 and =svg-lib= as they are on =master= of the two upstream repositories today. Claims about Emacs internals that I did not check in source are marked /(memory)/; read them as things to test, not as facts.

* Goal

Get Nicolas Rougier's [[https://github.com/rougier/svg-tag-mode][svg-tag-mode]] back in two steps, each its own pull request and each testable on its own:

1. *Stage 1: the raw package.* Install it unmodified, off by default, with no hook, so that =M-x svg-tag-mode= is the only way to turn it on. Nothing of mine sits on top of it.
2. *Stage 2: the extra tag rendering* first proposed in #254 / #260 / #264: tags of Org headings drawn as chips, coloured by tag group, with the tag's emoji in front, following the theme palette.

Stage 2 does not start until the checklist of stage 1 has been run on the Mac and its results are written down.

The #254 code is recoverable with =git show 8c27fdb= (module, doc and tests); #260's with =git show d7306b3=. Both predate the Stow reorganisation, so their paths start with =.config/emacs-modular/=.

What #254 did that is worth keeping:
- Three =svg-tag-tags= entries, because =svg-tag-mode= puts one display on one match: =\(:\)NAME= (the colon before a tag shows its emoji), =\(NAME\):= (the name becomes a chip) and =:[ \t]*$= (the final colon shows nothing).
- A predicate that checks that the match lies inside group 5 of =org-complex-heading-regexp=, so =foo:= in a title, a time such as =12:30= or a =#+filetags:= line is left alone.
- Chip colours from =sp-org-tag-groups--chip-face= (the theme-derived palette), emoji from =sp-org-tag-groups--decorate= in the =select= context.
- A =sp-after-load-theme-hook= function that calls =font-lock-flush= in buffers with the mode.
- Four ERT tests of the regexps, the predicate and the nil-without-graphics behaviour (these ran in no Emacs either).

What #254 did that I would not repeat:
- It switched the global mode on /when the module loads/ (=(when sp-org-svg-tags-enable (sp-org-svg-tags-global-mode 1))=), with =(require 'svg-tag-mode nil t)= inside the mode function. At load time the package may not be built yet by Elpaca; that fails silently and is order-dependent.
- It was global: every buffer that enters =org-mode=, including buffers an indexer opens, ran =svg-tag-mode-on=.
- It was never run in a graphic frame.

* Does SVG rendering make Emacs hang?

*Short answer: I found no evidence that it did, and some evidence that it did not; but the package has a few costs that scale with the number of tags on screen and that nobody has measured.*

** Evidence that svg-tag-mode was not the cause

- Sia has since found that the hang came from other start-up work and is fixed.
- The CHANGELOG entry for the hang records a native =sample= of the hung Emacs pointing at =vulpea-db-autosync-mode= re-indexing about 9,800 files on the main thread. #270 records that the =vulpea-select-cache-prewarm= alone was 56 % of the CPU in a batch profile of a copy of the real vault. None of that involves images.
- =svg-tag-mode= had been in use, hooked on =prog-mode=, before #254 (see the table), with no hang reported against it.
- #264 removed =svg-tag-mode= together with vterm (#261), the fastfetch greeting (#263) and others; it was one of many removals made at once, so its removal says nothing about it.

** What the code does (read from source)

From =svg-tag-mode.el= 0.3.3 and =svg-lib.el=:

1. *Rendering is lazy.* =svg-tag-mode-on= adds one =font-lock= keyword per entry of =svg-tag-tags=, and a keyword function is called when =jit-lock= fontifies a region. So only text that is fontified gets an image: the visible window plus =jit-lock-chunk-size= padding, and the rest of the buffer only if something forces it (=font-lock-ensure=, =font-lock-fontify-buffer=, or stealth fontification when =jit-lock-stealth-time= is set; this configuration does not set it).
2. *There is no tag cache in the package.* =svg-lib-tag= builds a new SVG (=svg-create=, two =svg-rectangle=, one =svg-text=) and calls =svg-image= on it for every match, every time the line is refontified. Identical tags produce identical SVG text, and Emacs's own image cache is keyed on the image spec /(memory)/, so the rasterised bitmap should be shared; the Lisp-side building is not.
3. *=svg-lib-tag= calls =font-info= on every call* (=(font-info (format "%s-%d" font-family font-size))=), and =window-font-width= / =window-font-height=. =font-info= goes to the font backend /(memory)/ and is the first thing I would profile. If the font cannot be found it returns nil and =(aref font-info 2)= signals an error inside fontification, which =jit-lock= reports and then keeps retrying.
4. *=svg-tag-mode-on= has global side effects.* It =advice-add='s =org-fontify-meta-lines-and-blocks= (an =:around= advice that itself advises =remove-text-properties= for the duration of each call), enables =cursor-sensor-mode= (a function runs at every point movement across a =display= boundary), and adds a lambda to =read-only-mode-hook= that does =(font-lock-flush (point-min) (point-max))= in whatever buffer toggles read-only. Magit, Forge and =view-mode= toggle read-only often; with the mode on in a big buffer, each toggle refontifies all of it (lazily, via =jit-lock=, but all of it).
5. *The default pattern is unanchored.* =\(:\)NAME= matches in titles, body text, times and URLs. #254 compensated with the predicate; the predicate runs =looking-at org-complex-heading-regexp= per match on heading lines, which is cheap on one line and not free on a file with thousands of colons.
6. *Emoji and SVG.* If an emoji were put /inside/ the SVG text, rendering would depend on librsvg / Pango font fallback and would differ between machines. #254 avoided this by putting the emoji in a =display= /string/ (text with a face), which Emacs shows with its normal fontset fallback. Stage 2 keeps that rule.
7. *Image lifetime.* Emacs frees an image from its cache when it has not been displayed for =image-cache-eviction-delay= seconds (default 300) /(memory)/. A buffer with a few thousand distinct tags that is scrolled through can hold a few thousand small bitmaps for five minutes; with the same few tag names repeated, far fewer.

* Stage 1: the raw package

** Scope

- Install =svg-tag-mode= (and its dependency =svg-lib=, which Elpaca resolves from =Package-Requires=) with =use-package= and Elpaca =:ensure=, as the other modules do (no clone onto =load-path=).
- *Off by default.* No hook, no global mode, no =setq= of =svg-tag-tags=, no advice of mine. The upstream default is a single entry for =:TODO:=; that is what "raw" means. =M-x svg-tag-mode= turns it on in the current buffer; =M-x global-svg-tag-mode= is upstream's, and not to be bound.
- Guard on a graphic frame at /call time/ only if upstream's own error is not good enough; otherwise leave it, because a guard is not raw.
- Where: =sp-faces= is where it lived before, so the doc =docs/tangles/ui/sp-faces.org= gets a section "SVG tags" and the tangled =.el= gets the form below, in the same pull request, with the =Changes by pull request= entry and a CHANGELOG line (feature set "Org heading tags as SVG chips").

** Form

#+begin_src emacs-lisp :tangle no
(use-package svg-tag-mode
  :ensure t          ; MELPA (memory); use (:host github :repo "rougier/svg-tag-mode") to follow master
  :defer t
  :commands (svg-tag-mode))
#+end_src

=:defer t= with =:commands= means nothing is loaded and nothing is built into the start-up path beyond what Elpaca does for any package. =:ensure t= vs. a git recipe: MELPA builds from =master= of the same repository, so both give 0.3.3; the git recipe is the choice if you want to pin a =:ref=. The decision is Sia's; I recommend =:ensure t=, as the old =sp-faces= block had it.

** Test in a throwaway tag

Upstream's default entry draws =:TODO:=. To see something without writing configuration, in a scratch buffer:

#+begin_src emacs-lisp :tangle no
(setq-local svg-tag-tags '((":TODO:" . ((lambda (_) (svg-tag-make "TODO"))))))
(svg-tag-mode 1)
#+end_src

then type =:TODO:=. That is =setq-local= in a scratch buffer and leaves nothing in the configuration.

All the "Stage 1" items of the checklist below pass, and start-up time with the package installed but the mode off is within noise of start-up without it.

| 2d        | Refresh on theme change (=sp-after-load-theme-hook=) and the =org-modern-tag= guard                            | #254's refresh function             | refresh only buffers that are displayed in a window; flush the others lazily on =window-configuration-change= |
| 2e (maybe) | A user-level switch that enables the mode in Org buffers that visit a file and are shown in a window         | /new/                               | replaces #254's =define-globalized-minor-mode= at load time; avoids H1                  |

Rules that apply to all of 2a-2e, because they are the lessons of #254:
- Never enable anything at module load. The mode is off until =M-x= or until a documented hook is added in a later, separate pull request.
- Never =require= the package inside the mode function without =:defer t= / =:commands= in the =use-package= form that owns it; the function should =autoload=.
- Stay inside =org-complex-heading-regexp= group 5, and test the predicate on lines with times, URLs and =#+filetags:=.
- Keep a memo, with the theme epoch in its key, so that a theme change invalidates it.
- Document in the literate doc what has and has not been run, as the other docs do.

** 3. Profiling

The goal is a number for each hypothesis, so the decision to continue is not a guess.

- [ ] *CPU while scrolling.* In a big Org file with many tagged headings (use a real vault file, then the biggest one), with the Stage 2 mode on:
  =M-x profiler-start RET cpu+mem=, scroll the whole file with =C-v= held for 10 seconds, =M-x profiler-report=. Expand the tree: look for =svg-lib-tag=, =font-info=, =svg-image=, =svg-print=, =svg-tag--cursor-function=, =org-fontify-meta-lines-and-blocks=. Save the report text in the PR.
- [ ] *Micro-benchmark of one tag* (H2): =M-: (benchmark-run 1000 (svg-tag-make "project" :face 'org-tag :inverse t))= in a graphic frame. Write down the seconds per 1000; anything over a second means stage 2 needs the memo before it ships.
- [ ] *Memory* (H4): =M-: (image-cache-size)= (bytes, or use =M-x memory-report= and read the Image Cache line), scroll the big file, ask again, then wait =image-cache-eviction-delay= (300 s) or run =M-: (clear-image-cache)= and ask a third time. Compare with the process size in Activity Monitor (column "Memory") or =vmmap -summary (pgrep -x Emacs)=. Growth that does not come back after =clear-image-cache= is not the image cache.
- [ ] *GC pressure*: =M-: (memory-use-counts)= before and after the scroll; =M-: gcs-done= and =gc-elapsed= before and after.
- [ ] *Count the buffers* (H1): =M-: (cl-count-if (lambda (b) (buffer-local-value 'svg-tag-mode b)) (buffer-list))= while vulpea autosync runs. Expected: only the buffers you opened. A number in the thousands means the mode is global; stop and fix 2e.
- [ ] *Emoji* (H5): with stage 2c on, time the first redisplay of a heading with an emoji tag, and a heading without one.
- [ ] *Start-up profile.* =M-x profiler-start= cannot start before init. Use =emacs --eval '(profiler-start (quote cpu))'= via the =emacs-pr= profile, or compare =M-x emacs-init-time= and =M-x elpaca-log= with and without the new form.

** 4. If Emacs freezes

In this order, because each step is more drastic:

1. Press =C-g= once, and wait three seconds. =C-g= only helps if the code is in Lisp.
2. If =debug-on-quit= was set first (=M-: (setq debug-on-quit t)= before the test, or =M-x toggle-debug-on-quit=), =C-g= opens a backtrace buffer where the freeze is. Copy the backtrace into the PR. Turn it off afterwards.
3. From another terminal: =kill -USR2 (pgrep -x Emacs)=. By default Emacs enters the debugger on =SIGUSR2= /(memory)/ (=debug-on-event=); this works even when =C-g= does not, as long as it is in Lisp.
4. If neither answers, the stall is in C (librsvg, a font lookup): =sample (pgrep -x Emacs) 10 -file ~/emacs-sample.txt=, as you did for the autosync hang. Look for =rsvg_= / =svg_load= / =CTFont= / =image_load= in the hot stack.
5. Last resort: =pkill -x Emacs=; the next start shows the autosave files.

Useful switches before testing:
- [ ] =emacs --debug-init= for errors at start.
- [ ] =M-x toggle-debug-on-error= while testing a mode toggle: a keyword function that signals will show a backtrace instead of a silent skip.
- [ ] To see which fontification errors are swallowed, watch =*Messages*= for =Fontification functions= / =jit-lock= lines while scrolling.

** 5. Bisecting

If something is slow and it is not clear whether SVG is the cause:
- [ ] =M-x svg-tag-mode= off: does it go away? If yes, SVG (or its font-lock keywords) is involved.
- [ ] =M-x cursor-sensor-mode= off while the mode is on: if the slowness goes, it is the cursor function.
- [ ] Run the same steps in =emacs -Q= with only the stage-1 form; if it is fine there, the cause is an interaction with the rest of the configuration (=org-modern=, =vulpea=, =sp-fonts=), not the package.
- [ ] =org-modern= is already on in Org buffers (=sp-org-appearance=, =org-modern-tag= is =nil=, so it does not draw tags): confirm that the two do not remove each other's =display= properties by turning =org-modern-mode= off and on with the SVG mode on.
