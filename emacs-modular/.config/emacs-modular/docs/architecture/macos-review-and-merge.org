#+title: Reviewing and merging AI-made changes on macOS
#+startup: overview

How I review, try and merge the pull requests Claude writes for this repository. The top-level [[file:../../../../README.org][README.org]] only links here; the reasons for each choice are in the decision records in [[file:../../../../adr/README.org][adr/]].

- Most changes arrive as pull requests from cloud sessions, often several at once and sometimes stacked.
- This applies to my Mac only, not to the Arch machines in the README.
- The repository is a normal clone in =~/dotfiles=, linked into =~= with GNU Stow ([[file:../../../../adr/0023-stow-instead-of-yadm.org][0023]]). There is no yadm and no second clone any more.

* Current choices

| Job                                    | Tool                                  | Decision |
|----------------------------------------+---------------------------------------+----------|
| Dotfiles repository, live config in =~= | GNU Stow (=~/dotfiles=, a normal clone) and =fish=    | [[file:../../../../adr/0001-plain-clone-for-gui-git-tools.org][0001]] |

| Brainstorming with Claude in Emacs     | =sp-vc-ai-workbench= (not loaded yet) | [[file:../../../../adr/0008-workbench-for-brainstorming-only.org][0008]] |

- Magit (styled by =sp-magit-style=) stays for staging, small commits and messages.
- Magit finds the repository through the Stow links because =vc-follow-symlinks= is set ([[file:../../../../adr/0023-stow-instead-of-yadm.org][0023]]).
- The alternatives I considered and did not adopt are in the table in [[file:../../../../adr/0002-sourcegit-for-visual-git.org][0002]]:
  - Graphite, git-branchless, jj, lazygit
  - GitKraken, Sublime Merge, Fork, Meld
  - VS Code, GitHub Desktop
  - Magit ediff, =smerge-mode=, =consult-gh=, =magit-stack=
