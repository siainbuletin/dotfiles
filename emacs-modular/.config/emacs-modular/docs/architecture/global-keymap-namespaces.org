#+title: Global keybindings in one keymap per feature
#+startup: overview
#+date: 2026-11-03

Design for moving every global keybinding into a keymap of its own per feature, mounted under one leader key, so that no two features can bind the same key by accident. Modelled on Lambda Emacs (=lambda-library/lambda-setup/lem-setup-keybindings.el= in the =lambda-emacs-modified= copy). *Design only: nothing in the configuration changes with this note.*

*What has and has not been run.* Written from a Linux container with no Emacs in it. Everything about this configuration comes from reading the sources (=sp-keys.el= and a search of every module under =libraries/modules/=, without =cloned/= and =themes/=). Statements about Emacs and about packages are from memory and marked /(memory)/; they need one check in a real Emacs before a step is built on them. Packages' own default keymaps (Magit, Dired, gptel and so on) were not audited.

*Decisions taken on 2026-11-03 (after the first version).*
- *GUI Emacs only*: I do not use terminal Emacs, so terminal support is a future task and no longer a constraint; the terminal material is kept as a short "later" note.
- The leader must not overlap *Alfred (Cmd+Space)* or the *input-source switch (Ctrl+Space)* on macOS, Linux and Windows; that rules out every =SPC= root (see [[*The leader key][The leader key]]).
- *Python is removed* from the configuration (=sp-python= and =ein=), so its keys and shadows are gone from this note.
- *Evil is removed*; the last commit that had it is linked in [[*Open decisions][Open decisions]].
- *Shims live until I decide to remove them*, not until a date.

* Summary

- Today there are three keybinding systems side by side:
   + the Lambda-style leader tree in =sp-keys= (=C-x C-SPC= plus 17 group maps)
   + about 80 raw =keymap-global-set= / =global-set-key= calls,
   + 60-odd =:bind= forms spread over the modules, and mode-local bindings that reuse the same =C-c <letter>= keys.
- Nothing checks them against each other, and the last one loaded silently wins.
- Collisions (details in [[*What the audit found][What the audit found]].)
   + The audit found *four global collisions* (=C-c s l=, =C-c s r=, =C-c m=, =<f6>=),
   + *one three-way collision* (=C-c f=),
   + *six mode-local shadows* of global keys (mostly Org),
   + *one leader key that hides a built-in* (=C-x C-SPC= is =pop-global-mark=, and =Ctrl+Space= belongs to the input-source switch, so it probably cannot be typed at all),
   + and *eleven commands in the leader tree that I found no definition for*.
- Recommendation: keep Lambda's idea (one leader, one map per feature) but build it differently:
   + each feature module owns a =defvar-keymap= and exports it;
   + =sp-keys= only /mounts/ those maps under letters from a single registry table; a test compares that table with the live keymaps.
   + Hot keys that should not take a leader (=C-c c=, =C-.=, =M-.=) are listed in the same table as exceptions.
   + Mode-local keys move to =C-c C-<x>= or a local leader.
   + The leader root becomes =C-;= (not =C-z=: =cua-mode= is on).
- Roll it out in five small pull requests, the first of which changes no key (audit command and test), and keep the old keys as shims that tell me where the key went, until I decide to remove them.

* What Lambda Emacs does

The file is about 400 lines of =bind-keys= forms, one per group. The parts that matter:

- *One personal prefix*, =lem-prefix= = =C-c C-SPC=, bound to =lem+leader-map= with =bind-keys :prefix-map ... :prefix=.
- *One prefix map per feature*, each under a letter of the prefix:
   + =b= buffers,
   + =c= comments, =C= config,
   + [ ] =M= compile,
   + [ ] =e= eval,
   + [ ] =f= files,
   + [ ] =F= flymake,
   + [ ] =m= mail, =n= notes (with =n b= for bibliography), =q= quit, =s= search, =S= spelling, =t= toggles, =g= version control,
   + [ ] =w= windows, =W= workspaces, and an empty =u= map for the user's own keys.
   + Each map has a name (=lem+buffer-keys=) so it can be extended or inspected by name.
- *Hydras* for the long-running modes (transpose on =.=), which-key configured to show after 0.75 s or on =C-h= (=which-key-show-early-on-C-h=).
- *No bindings in the feature modules.*
   + The file says so itself: it separates keys from packages, but it is "the place to go to deal with all keybindings".

What I take: the leader and the map per feature, the empty user map, the mnemonic letters, which-key as the discovery tool. What I do not take:

- *Prefixes built from strings.* Every group re-derives its place with =(concat lem-prefix " b")=.
   + A child prefix (=n b=) only works if its parent was bound earlier, and binding a child below a key that is still a command signals "starts with non-prefix key" at load time.
   + Mounting map objects removes the order dependence ([[*The design][The design]]).
- *All keys in one file.*
   + It makes the audit easy and the feature module harder to read.
   + The compromise below keeps the /map/ in the feature module (the module says what it offers) and the /letter/ in =sp-keys= (one place says where it lives).
- *The prefix itself.*
   + =C-c C-SPC= is a =C-c= + control character, which the Emacs conventions reserve for major modes /(memory)/.
   + See [[*The leader key][The leader key]].
- *No labels.* Lambda's groups show up in which-key as "+prefix". See [[*which-key labels][which-key labels]].

- Below the Lambda part it also holds a miscellany of raw bindings:

   + =ironkey= protects =M-.= and =C-x p= from minor-mode overrides.

** Outside =sp-keys=

88 top-level binding forms (79 of them =keymap-global-set= or =global-set-key=), 5 =bind-keys= forms, about 60 =:bind= forms, and mode-local =define-key= calls (Python's 28 are gone with =sp-python=).
- There is no Evil (removed), no General and no Meow in use.
- The tools in play are =bind-key= / =use-package :bind=, raw =keymap-global-set=, =ironkey=, =which-key=, =embark= and =transient=.

** How the single-letter =C-c= space is used today

Emacs reserves =C-c <letter>= for the user /(memory)/; there are only 52 of them, and this configuration already spends at least these as global prefixes or commands: =a b c d e f h i j k l m n o p r s t w z=. Some are package defaults used against the convention (=C-c p= projectile, =C-c C-p= projectile, =C-c C-d= helpful), some are my own, and the same letter is often used by two features. A single leader costs one slot and gives 52 child slots per level.

* What the audit found

"Global" means bound in =global-map= (or by =bind-key*= in =override-global-map=); "local" means bound in a mode map and so active only there. When two global bindings meet, the one evaluated last wins and nothing warns.

** Two global commands on one key

| Key      | First                                         | Second                                 | Result |
|----------+-----------------------------------------------+----------------------------------------+--------|
| =C-c s l= | =easysession-switch-to= (=sp-keys=)            | =consult-line= (=sp-search=)            | =sp-search= loads after =sp-keys= (=sp-navi= follows it), so easysession /load/ is lost |
| =C-c s r= | =easysession-rename= (=sp-keys=)               | =consult-ripgrep= (=sp-search=)         | easysession /rename/ is lost |
| =C-c m=   | =sp-goto-minibuffer-window= (=sp-windows=)      | =supersonic= (=sp-multimedia= =:bind=)   | whichever is evaluated last; the UI module loads before the media module, but see load order below |
| =<f6>=    | =redraw-display= (=sp-windows=)                 | =projectile-run-project= (=sp-workspaces= =:bind=) | same |
| =C-c f=   | =org-focus-hud= (=sp-org-time=)                 | =dirvish= (=sp-dired=), and in Org buffers the prefix =C-c f n/q= (footnotes) | three users of one key |
| =C-c a= / =C-c o a= | =org-agenda= twice                      | (=sp-agenda-views=)                      | harmless duplicate |

** A local binding hides a global one

Most of these are fine as long as I know about them. The ones that cost something:

| Key | Global | Local | Effect |
|-----+--------+-------+--------|
| =C-x s= | =save-some-buffers= | =org-mode-map=: =C-x s t= (=sp-refile=) | a prefix in the local map hides a /command/ in the global map, so =C-x s= (and =C-x s !=) stops working in Org buffers /(memory)/ |
| =C-c f= | see above | =org-mode-map=: =C-c f n=, =C-c f q= | same mechanism: the two global =C-c f= commands vanish in Org |
| =C-c C-d= | =helpful-at-point= | =org-mode= binds =org-deadline= there; Lisp buffers bind =C-c C-d h= (sly) | =helpful-at-point= is dead in Org and Lisp |
| =C-:=, =C-.= | =avy-goto-char=, =embark-act= | =flyspell-mode-map= binds both (=sp-spelling=; Emacs' flyspell binds =C-.= by default /(memory)/) | both lost while flyspell is on |
| =C-<return>= | =pulse-line= (=sp-faces=) | Org: =org-insert-heading-respect-content= /(memory)/ | lost in Org |
| =M-a= | =sp-move-region-to-heading= | built in: =backward-sentence= | the global rebind takes a high-use motion key |

A rule that explains the table: *a prefix and a command on the same key shadow each other; two prefixes merge.* =C-x t i/h/d= in =org-mode-map= and the global =C-x t= tab prefix merge (the tab commands still work in Org), but =C-x s t= against the global command =C-x s= does not /(memory)/. Any design has to treat "this key is a command somewhere" as a conflict with "this key is a prefix elsewhere".

** Reserved and built-in keys that are taken

- =C-x= is Emacs' own namespace and grows between versions.
   + This configuration also binds =C-x C-f=, =C-x C-b=, =C-x C-r= (=recentf-open-files=, hides =find-file-read-only=),
   + =C-x t b= (=transpose-buffers=, hides =switch-to-buffer-other-tab= in the tab prefix /(memory)/),
   + =C-x w t/r/f/f= (the =EMACS-31= comment says they exist upstream in Emacs 31; confirm and drop them if so),
   + =C-x n n=, =C-x r D=, =C-x s t=, =C-x t i/h/d/s=.
- =C--= and =M--= (negative argument) are taken by =text-scale-decrease= and =font-size-decrease=;
   + =M-== (=count-words-region=) and =M-+= by =font-size-increase=;
   + =M-u/l/c= are rebound to the same =-dwim= commands Emacs already has.
- =C-c <control char>= is for major modes:
   + =C-c C-d= and =C-c C-p= (Projectile), =C-c C-w= (=sp-refile= over =org-refile=, deliberate).
- =<f1>= is unbound globally by =sp-prog-misc= ("avoid help-for-help"). =C-h= is untouched. =C-z= is unbound twice (it is =undo= under CUA).

* Caveats
** Load order and timing

- =keymap-global-set= at the top level of a module runs while init reads that module. The module order is =lem--default-modules= in =init.el= and is documented for another purpose in [[file:load-order.org][load-order.org]];
   + today it decides which of two conflicting keys wins, and nobody chose that.
- =use-package :bind= for a package installed with =:ensure t= is, as far as I know, wrapped in an =elpaca= form and runs when Elpaca processes that package's queue entry, after init /(memory)/.
   + If so, a =:bind= and a top-level =keymap-global-set= are ordered by something other than module order, and the order of two =:bind= forms depends on Elpaca's queue.
   + *Do not infer the winner from the file order; read it from the live keymap.*
      * This is the first thing to check in a real Emacs, and the reason the test below inspects the result and not the sources.
- A map that does not exist yet cannot be extended: =org-mode-map=, =projectile-command-map=, =tabspaces-command-map= belong to packages.
   + Use =:bind (:map ...)= or =with-eval-after-load=. Feature maps created with =defvar-keymap= in this configuration always exist and can be mounted at any time, which is the main argument for them.
- =tabspaces-command-map= is defined in =sp-tabs= and also re-built in the leader tree (=W= in =sp-keys=):
   + the same twelve-odd commands in two maps with different letters (=n= rename vs none, =C= vs =c= for clear).
- Mounting a map object (=(keymap-set sp-leader-map "t" sp-toggle-map)=) shares it: later =keymap-set= calls into the child are visible through the parent. Copying it (=copy-keymap=) loses that. Never copy.
- =bind-keys :prefix-map X :prefix "C-x C-SPC b"= defines =X= /and/ binds the string path.
   + If the parent is not yet a prefix, the binding fails.
   + Mounting by object has no such order.

** Keys that do not reach Emacs

*GUI only.* I do not use terminal Emacs, so keys such as =C-.=, =C-:=, =C-<return>= or =C-M-S-<arrow>= are fine. What still matters in the GUI /(memory)/:

- macOS: =mac-command-modifier= is =meta=, =mac-option-modifier= is =none=, =ns-right-command-modifier= is =super= (=sp-macos=).
   + =s-= keys are on the /right/ Command only;
   + Hyper (=H-=) is not mapped at all, so =H-w= and =H-b= cannot be typed;
   + =M-= is Command, so Cmd+Space is =M-SPC= and Alfred takes it before Emacs sees it; some Command shortcuts (=M-`=, =M-h=, =M-m=) are intercepted by macOS too.
- The input-source switch is Ctrl+Space on all three systems, which the OS handles before Emacs: =C-SPC= (and so =C-x C-SPC= and =C-c C-SPC=) cannot be relied on.
- Left for later, if terminal Emacs comes back:
   + =C-:=, =C-;=, =C-.=, =C-,=, =C->=, =C-<=, =C-+=, =C-<return>=, =<C-tab>=, =C-M-S-<arrow>= and =S-<f11>= need a keyboard protocol (kitty/CSI u, the =kkp= package) in a terminal;
   + =C--= arrives as =C-_= (undo);
   + a multiplexer (this repository has a =zellij= config) can swallow keys.
   + The registry can carry a =gui-only= flag so a terminal pass can start from a list.

** The leader key

*Constraints.*
- GUI only.
- Not Cmd+Space (Alfred; in this configuration Cmd is Meta, so it is =M-SPC=).
- Not Ctrl+Space (input-source switch), so not =C-SPC= and not any sequence that ends in it, including today's =C-x C-SPC=.
- Not =C-z=, =C-x=, =C-c= or =C-v=: =cua-mode= is on (=sp-text-manipulation=), so they undo, cut, copy and paste while a region is active.
- Nothing with =SPC= as its last key survives. That also rules out Lambda's =C-c C-SPC= and any =s-SPC= / =H-SPC= (=s-= is the right Command only).

| Option | For | Against |
|--------+-----+---------|
| =C-x C-SPC= (today) | no change | cannot be typed if the OS keeps Ctrl+Space; hides =pop-global-mark= |
| =C-c C-SPC= (Lambda) | same as Lambda | same problem; =C-c= + control character is for major modes /(memory)/ |
| =C-c <letter>= | user-reserved | spends one of the 52 slots; all are used now |
| =<f5>= to =<f9>= | user-reserved | =<f5>=, =<f6>=, =<f8>=, =<f9>= are bound; laptop function keys need Fn |
| =C-z= | free: no mode here binds it | =cua-mode= makes it undo, so it is out |
| =C-c <letter>= / =C-x ...= as a root | familiar | =cua-mode= copies or cuts with a region active; the key only acts as a prefix when no region is selected |
| =C-;= | one chord; free in the global map; not used by CUA, Org, Alfred or the input-source switch | =flyspell-mode-map= binds it (=flyspell-auto-correct-previous-word=) /(memory)/; =sp-spelling= unbinds it and moves its correction to =C-; z p= |
| =C-,= | one chord | Org binds it (=org-cycle-agenda-files=) /(memory)/ |

*Recommendation: =C-;= as the root*, as one variable (=sp-prefix= becomes =sp-leader-key=).
- Nothing in =libraries/modules/= binds =C-;= except =sp-spelling= (in =flyspell-mode-map=, now removed); neither Alfred, the input-source switch nor CUA touches it.
- It works with or without a selected region, which =C-c= and =C-x= do not under CUA.
- =pop-global-mark= cannot stay on =C-x C-SPC= (it ends in =SPC=), so it goes to =C-; b P= (previous position), because =b m= is =consult-mark= already.
- Fallback if it is awkward to type: mount the same map under a second key (an unused function key), since two keys on one map object cost nothing.

** CUA and the =C-c= keys

- With =cua-mode= and an active region, =C-c= copies and =C-x= cuts; they act as prefixes only when no region is selected, or when the next key follows quickly (the delay is =cua-prefix-override-inhibit-delay= /(memory)/; its default was not checked).
- Consequence: every global =C-c <letter>= key is unreliable while text is selected. That includes the hot keys =C-c c= (capture) and =C-c a= (agenda).
- Adaptation:
   + the leader gives a path that ignores the region: =C-; a c= (capture) and =C-; a a= (agenda);
   + =C-c c= and =C-c a= stay as hot keys for when no region is selected;
   + new global keys go into the leader, not into =C-c <letter>=, so the =C-c= space only shrinks;
   + the =C-c= keys that remain in modes (for example Org's) keep working under CUA only without a region, as before.
- Not changed: =C-x= keys such as =C-x C-f= (no region needed) and =C-x s t= in Org.

** Keys freed by CUA

- CUA gives copy, cut, paste and undo to =C-c=, =C-x=, =C-v= and =C-z=. The Emacs keys for the same jobs are now duplicates:
   + =C-y= (=yank=), duplicated by =C-v=;
   + =C-w= (=kill-region=), duplicated by =C-x= with a region;
   + =M-w= (=kill-ring-save=), duplicated by =C-c= with a region;
   + =C-/=, =C-_= and =C-x u= (=undo=), duplicated by =C-z=. Keep one of them as a spare undo.
- To check in Emacs:
   + whether =M-y= (=yank-pop=) still works after =C-v=; if it does, keep it paired with =C-v=; if not, it is free too.
- They can be rebound with a plain =keymap-global-set=. No advice is needed: advice changes what a function does, not which key runs it.
- Caveats:
   + =isearch= and the minibuffer have their own =C-y= and =C-w=; a global rebind does not touch them.
   + Org remaps the command =yank=, not the key =C-y=, so rebinding the key does not break Org.
   + Old habits: the first days, =C-y=, =C-w= and =M-w= would run the new commands.
   + Other people's docs, and Emacs' own help, assume the old meanings.
- Candidates, not applied: single keys for the hottest commands (capture, agenda, avy), which also takes pressure off =C-c <letter>=.
- Nothing is rebound yet. I will see which ones I want as I keep using this setup.

** Replacing CUA

- What CUA does:
   + =C-v= and =C-z= are bound in an overlay keymap (=cua-global-keymap=, via =emulation-mode-map-alists=). It beats =global-map=, so they cannot be rebound with =keymap-global-set=.
   + =C-x= and =C-c= are cut and copy only while a region is active (/(memory)/). Otherwise they are the prefixes.
   + =cua-prefix-override-inhibit-delay= decides how long CUA waits for a second key before it cuts or copies; a key typed within the delay makes =C-x= or =C-c= a prefix again. Check its value with =C-h v=.
- Why the =C-c= and =C-x= case cannot be made "native":
   + One key cannot be both copy and prefix while a region is active.
   + A plain binding in =global-map= has to choose one: copy, or the prefix. CUA's delay is the way to have both.
   + Doing it without CUA means rewriting that delay: read the next key within a timeout, and push it back as the prefix's second key.
   + A =menu-item= binding with =:filter= can pick between the two commands by the region, but not by timing.
- Options:
   + *A. Keep CUA and tune it.* Set =cua-prefix-override-inhibit-delay= so a quickly typed =C-c C-c= with a region works. No new code. Remaining cost: a held =C-c= copies after the delay.
   + *B. CUA for cut and copy only, native for the rest.* Set =cua-remap-control-v= and =cua-remap-control-z= to nil (/(memory)/), bind =C-v= to =yank= and =C-z= to =undo= (and =C-S-z= to =undo-redo=) in =global-map=. Then those two keys are ordinary bindings. =C-x= and =C-c= stay with CUA.
   + *C. No CUA: use the platform keys.* On the Mac, Command is the copy key everywhere else. Make Command =super= and Option =meta=: =s-c=, =s-x=, =s-v=, =s-z= and =s-S-z= are plain, unambiguous bindings, and =C-c= and =C-x= are only prefixes again. Costs:
      * Meta moves from Command to Option (=sp-macos= sets it the other way today), so =M-x= becomes Option+X.
      * Option no longer types special characters. The Romanian input source (switched with Ctrl+Space) does that.
      * Linux and Windows have no such key; they keep CUA (option A or B) there.
   + *D. Remap outside Emacs.* Hammerspoon or Karabiner turns Command+C/X/V/Z, in Emacs only, into keys such as =<f13>= that Emacs binds natively. Same result as C without moving Meta, at the price of another tool in the chain.
- Recommendation:
   + Mac: C, if Meta on Option is acceptable; otherwise A.
   + Linux and Windows: B.
   + In all cases the =C-c= hot keys keep a leader twin (=C-; a c=, =C-; a a=), so nothing depends on =C-c= with a region.
- Not applied, and not run: this needs a real Emacs on the Mac to confirm the three =/(memory)/ points (the =cua-remap-control-*= options, the delay default, and how Command and Option behave with =mac-command-modifier= changed).

** Same keys on macOS, Linux and Windows

Decided on 2026-11-03: option C on the Mac, and the other two systems brought as close to it as the OS allows.

- Three jobs, one key each, on every system:
   + *Meta* is Alt (Option on the Mac). Nothing else grabs it: AeroSpace, i3 and sway no longer bind Alt.
   + *Clipboard and undo* is the system's own key: Command on the Mac (=s-c=, =s-x=, =s-v=, =s-z=, =s-Z=), Ctrl on Linux and Windows (CUA, with =C-v= and =C-z= plain bindings). Both are set in =sp-text-manipulation=.
   + *Window manager layer* is Caps Lock held, on the Mac and on Linux.
- The window manager layer:
   + Mac: Hammerspoon turns Caps Lock into =F18= (=hidutil=) and runs the =aerospace= commands (=hammerspoon/.config/hammerspoon/aerospace-keys.lua=); =aerospace.toml= no longer binds =alt-*= in main mode.
   + Linux: =caps:super= in X (=setxkbmap=, i3) and in sway (=xkb_options=); both use =$mod= = Mod4, so Caps Lock is Super and the Windows key still works.
   + Windows: no window manager is configured in this repository. If one is added, remap Caps Lock to a spare key with PowerToys Keyboard Manager and use that.
- What stays different, because the hardware differs:
   + Command sits where Alt sits on a PC keyboard, so the thumb position of the clipboard keys is not the same.
   + =s-= keys in Emacs (=s-b=, =s-i=, =s-=, =s--=, =s-0=) are Command on the Mac and Caps Lock (or the Windows key) on Linux. i3 and sway only take the combinations they bind, so the rest reach Emacs; check =s-b= and =s-i= after the first run.
   + On Linux and Windows =C-c= and =C-x= are still CUA's region trick (the C-c leader twins =C-; a c= and =C-; a a= avoid it).
- Not run: none of this was tried on a real keyboard (no Emacs, i3, sway, AeroSpace or Hammerspoon in the container).

Which of the two works with the built-in which-key of Emacs 30 and 31 needs one test.
- Individual commands show by symbol name.

** Mode-specific overrides

The leader is global, so a mode that binds the same root key as a command would hide the whole tree (Org's =C-c SPC= is the example for a root of that shape /(memory)/; =C-;= is not bound by Org, but the registry test still checks the root against the maps listed in the audit). Rules for the feature modules:

1. Global feature keys go in the feature's map, never in =C-c <letter>= (and not in =C-c C-<x>=).
2. Mode-local keys use =C-c C-<x>= (the major-mode namespace, and it merges with the major mode's own) or a /local leader/ =<leader> m= that each major mode fills through a variable (=sp-leader-local-map=, buffer-local, set by the mode hook). With Python gone this is mostly for Org (the =C-c f n/q=, =C-c s i/a=, =C-c l d/c= keys in =org-mode-map=), so that =C-c f= and =C-c s= are no longer partly local.
3. A mode that really needs a key that is global elsewhere (for example =C-c C-w= for =sp-refile= in Org) says so in the registry as a deliberate local override; the test accepts a listed override and fails on an unlisted one.
4. Do not use =bind-key*= (override map) except for keys that must work in every mode, and say which in the registry. Today it is used for =s-== =s--= =s-0= (fonts) and the =C-x n n= case above.

** Migration and muscle memory

- *Count of keys that would move:* the scattered =C-c <letter>= bindings (about 45 global) and the =sp-keys= extras.
   + The 17 leader groups that already exist keep their letters, so the keys I use most keep them under the new root (=C-; b b=, =C-; g s=, =C-; f f=); the root itself changes, and =C-x C-SPC= stays as a shim.

   + A table =sp-keys-moved= (old key, new key, since) generates them, so removing a shim is deleting a row;
   + the audit lists the shims still alive.
- Keep the hot keys.
   + Candidates for the exceptions list: =C-c c= (capture), =C-c a= (agenda), =C-.= (embark-act), =M-.=, =C-x C-f=, =C-x C-b=.
   + Each exception must have a reason in the table; any other global binding outside the leader is a test failure.
- *Denote is being phased out* (ADR 0010): do not design a place for =C-c w d ...=, =C-c z= and =M-n ...=; remove them with the Denote removal, and give them no shim.
- Muscle memory also lives in other tools: =gh dash=, Hammerspoon and the shell aliases in this repository do not send Emacs keys, but the fish =emacs-pr= helper and the sandbox profiles load =sp-keys= too, so the same table must work in the =writing= and =sandbox= profiles.

** Testing for conflicts

Three layers, from cheapest:

1. *Registry test (batch, no packages).* The registry is an Org table in this design's follow-up doc (the =sp-keys= literate doc), tangled to a =defconst=. The test checks the table itself: no two rows with the same key, no row whose key is a strict prefix of another row's key unless it is a prefix row, every command is a symbol, every leader letter is used once. This runs in CI next to the tangle check, with the existing =ert= tests in =tests/=.
2. *Live audit (needs the real Emacs).*
    - =M-x sp-keys-audit= walks =global-map=, the leader map, and the maps listed in a variable (=org-mode-map=, =dired-mode-map=, =magit-mode-map=, =org-agenda-mode-map=, the minor-mode maps in =minor-mode-map-alist=) with =map-keymap= and reports to a buffer:
       + keys whose final binding differs from the registry;
       + prefix-vs-command mismatches;
       + local bindings that hide a global one;
       + bound symbols that are not =commandp=;
       + the same command on several keys.
    - =describe-personal-keybindings= already reports =[was ...]= for anything bound through =bind-key= / =:bind=, so route as many bindings as possible through it. The raw =keymap-global-set= calls bypass it, which is the argument for one entry point.
3. *OS-level check (GUI).* A short manual list: press =C-h k= then each leader and hot key in the GUI on the Mac (and later on Linux and Windows) and see which arrive.
    - Alfred and the input-source switch are the keys to try first.
    - Keep it as a table in the doc with a date for the last run. A terminal pass is left for later.

The audit also doubles as the CI guard: a pull request that adds a global binding outside the registry fails layer 1.

* The design

** Shape

#+begin_example
sp-leader-map              (mounted at the leader key; one variable)
 ├── b  sp-buffer-map      (owned by sp-buffers)
 ├── g  sp-vc-map          (owned by sp-vcontrol)
 ├── s  sp-search-map      (owned by sp-search)
 ├── n  sp-notes-map       (owned by sp-notes)  ── b  sp-bib-map
 ├── m  sp-local-map       (buffer-local: major-mode keys, the "local leader")
 └── ...
#+end_example

- *Each feature module defines and exports one map* with =defvar-keymap= and fills it itself, so the module that owns a command is the one that says which key it has /inside its own map/.
- *=sp-keys= owns the letters*: one table =(LETTER MAP LABEL)= and one loop that mounts each map under the leader and labels it. Changing a letter is a one-line change in one file; nobody else needs to know it.
- *Leader, hot keys and exceptions* are in the same registry so the audit can read them.
- Sketch (not code to tangle; style as in the project instructions):

#+begin_src emacs-lisp :tangle no
;; In the feature module (sp-search.el):
(defvar-keymap sp-search-map
  :doc "Search commands."
  :name "Search"
  "l" #'consult-line
  "r" #'consult-ripgrep
  "m" #'sp-search
  "f" #'consult-snapfile)

;; In sp-keys.el, the only place that knows the letters:
(defconst sp-keys-groups
  '(("s" sp-search-map "search")
    ("S" sp-session-map "session")
    ("g" sp-vc-map "git"))
  "Leader letter, keymap variable and label of each feature group.")

(defun sp-keys-mount-groups ()
  "Mount every group of `sp-keys-groups' on `sp-leader-map'."
  (dolist (group sp-keys-groups)
    (when-let* ((map (and (boundp (nth 1 group)) (symbol-value (nth 1 group)))))
      (keymap-set sp-leader-map (nth 0 group) (cons (nth 2 group) map)))))
#+end_src

A map that is not defined yet (a late module) is mounted when its module provides the feature: =(with-eval-after-load 'sp-search (sp-keys-mount-groups))=. Mounting twice is harmless.
