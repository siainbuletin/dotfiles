#+title: Dotfiles changelog
#+startup: overview

Changes to the dotfiles that are not the Emacs configuration: the repository layout, the other tools' settings and the scripts around them. Changes to the Emacs configuration are in [[file:emacs-modular/.config/emacs-modular/CHANGELOG.org][the Emacs changelog]]. Changes are grouped by the feature they build or fix. Within a set the pull requests follow the order they depend on each other, the base first. Each line starts with its pull request number, then the author, then what happened: ✨ Added, 🔧 Changed, 🐛 Fixed, 🔥 Removed, 💡 Proposed; the category headings are not repeated.

* Moving from yadm to Stow
/2026-11-02 to 2026-11-04./ The repository is a normal Git repository in =~/dotfiles= with one Stow package per tool, not a yadm repository on =$HOME=. The Emacs side of the move (=emacs-pr=, Magit, =sp-dotfiles-dir=) is in the Emacs changelog under "Reviewing and merging in Magit".

- [[https://github.com/siainbuletin/dotfiles/pull/271][#271]] (Claude) ✨ Added =stow-migration/=: a package map (=packages.tsv=), =migrate.sh= with preflight, backup, restructure, dry run, cutover, verify, retire and rollback (files Stow replaces go to a backup folder, never deleted), a guide, and ADR 0023. Nothing is moved by merging it. Rehearsed in a scratch home folder on Linux with Stow 2.3.1.
- [[https://github.com/siainbuletin/dotfiles/pull/274][#274]] (Sia) 🔧 Changed the repository layout: every tracked file moved into a Stow package, one per tool, with =git mv= so history follows; the yadm alternates became the =alacritty-darwin=, =alacritty-linux= and =alacritty-windows= packages; =.Xauthority=, the yadm config and the old blacklist =.gitignore= are dropped; the CI workflow paths follow. The Emacs configuration is now in =emacs-modular/.config/emacs-modular/=.
- [[https://github.com/siainbuletin/dotfiles/pull/287][#287]] (Claude) 🔧 Changed ADR 0001 to "superseded by 0023", with a short dated note and its text untouched, and ADR 0023 to "accepted", with a new section "Why I chose Stow after all": easier versioning, docs and Magit, sync problems, and untracked files slowing branches in VSCode and SourceGit.

* One layer key for window managers
/2026-11-04./ Option is Meta in Emacs on the Mac, so AeroSpace, i3 and sway stop binding Alt/Option and share one layer key, Caps Lock held. Design: "Same keys on macOS, Linux and Windows" in [[file:emacs-modular/.config/emacs-modular/docs/architecture/global-keymap-namespaces.org][the keymap design]]. The Emacs side of the same pull request is in the Emacs changelog under "Global keybindings in one keymap per feature".

- [[https://github.com/siainbuletin/dotfiles/pull/284][#284]] (Claude) 🔧 Changed =aerospace.toml=: the main-mode =alt-*= bindings are gone (hold Caps Lock plus =h/j/k/l=, =1=-=9=, =a b d e m t w=, =Tab=, =/=, =,= instead; Caps Lock plus =Shift+;= enters service mode, whose joins are =shift-hjkl=). ✨ Added =hammerspoon/.config/hammerspoon/aerospace-keys.lua=: Caps Lock becomes F18 (=hidutil=) and F18 held plus the old key runs the same =aerospace= command. 🔧 Changed i3 (=setxkbmap -option caps:super=, dmenu on =$mod+d= instead of Alt+Space) and sway (=$mod= is Mod4, =xkb_options caps:super=). Windows has no window manager here. Not run on any system (none in the container); the =aerospace= path in =aerospace-keys.lua= needs checking.
