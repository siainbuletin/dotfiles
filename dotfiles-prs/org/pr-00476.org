**** Problem
:PROPERTIES:
:CUSTOM_ID: problem
:END:
- After =d= (drop) in a report, the message of the command was shown for a moment and then replaced by the hints ("the echo area blinks").

**** Causes
:PROPERTIES:
:CUSTOM_ID: causes
:END:
- *Duplicate forced call:* =sp-batch-report-open= had two extra =sp-echo-help-set= calls (one left over from #468 beside the one from #470). Each one forces the hints into the echo area, so every redraw (=d=, =u=, =g=) overwrote the message.
- *Idle re-show too eager (my change in #470):* it replaced any message after the idle delay (1.5 s), so a message could not be read.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- Removed the duplicate =sp-echo-help-set= call in =sp-batch-report-open=.
- =sp-echo-help-set= has a new =QUIET= argument: the hints do not replace a message that is showing. A redraw (the point is put back) and the mode body set them quietly; opening a fresh report still shows them at once.
- New =sp-echo-help-message-hold= (default 5 s): the idle re-show replaces a message only after Emacs has been idle that long. =C-c ?= still shows the hints at once.
- Docs updated as bullets (=sp-interaction.org=, =sp-batch-report.org=); no CHANGELOG edit.

**** Tests (Emacs 29.3, batch)
:PROPERTIES:
:CUSTOM_ID: tests-emacs-293-batch
:END:
- =sp-batch-report-test= 22, =sp-echo-help-test= 7, =sp-async-work-test= 10 pass.
- New =sp-batch-report-redraw-keeps-the-command-message=: redraw does not print the hints while a message is showing (this failed with the duplicate call); idle at 2 s leaves it, idle at 6 s shows the hints.
- =sp-echo-help-idle-show-replaces-a-message= now checks the hold time.
