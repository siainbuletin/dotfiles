Stacked on #17 (which is stacked on #16). Merge in order and GitHub retargets each one.

*Before:* the browser graph put boxes in columns by depth, with parents on the left, and the other relations were drawn as lines between boxes the tree had already placed. There was no way to say where a relation should go.

*After:* each relation in =vulpea-hierarchy-relations= takes a =:direction=: =up=, =down=, =left=, =right=, or an angle in degrees (0 is right, 90 is up, so 45 is up and to the right). It says where the object of the relation is drawn, seen from its subject. Parents now go above their children, siblings sit on one row, and a note with several parents is drawn once and joined to all of them. Defaults: =supports= right, =opposes= left, =informs= 45, =answers= up. The Graphviz default =vulpea-hierarchy-rankdir= is now ="TB"= to match; the SVG export ignores the other directions.

*Backend change (needed for this):* the page's own tidy-tree code could not place a note relative to a note in another branch, so positions now come from the fCoSE force-directed layout, which takes "above/below/left of/right of" rules. The page still does its own drawing. Pros: directions, diagonals and cross-branch rules; multi-parent notes drawn once; deterministic. Cons: about 560 KB of vendored MIT-licensed scripts (=libraries/modules/custom/vendor/vulpea-hierarchy/=, with a README and licences) pasted into each page; heuristic layout that breaks some rules in crowded graphs and is less tidy than a tree; about 0.5 s for 120 boxes; the scripts need manual updates; SVG export has no directions. The full table, and the alternatives I considered (Cytoscape renderer, ELK, d3-force, Graphviz), are in the doc section "Layout backend of the browser page".

*How:* =constraints= turns the tree and each link's direction into relative-placement rules, dropping any rule that would contradict earlier ones; =place= runs fCoSE in a window-less Cytoscape graph; =separate= pushes apart boxes that still overlap. Tested on mock notes in headless Chromium (directions, recentre, depth, back, fold), on a 121-box tree with 25 random links (about 0.5 s, readable but crowded), and =dot= accepts the Graphviz output. Not run against your real vault. The literate doc is regenerated and tangles back byte for byte.
