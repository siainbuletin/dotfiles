**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
=sp-author-notes= (preview, apply, refresh), =sp-author-notes-bibtex=, =sp-litnotes-refs-report=/=-convert= and =sp-litnotes-titles-report=/=-apply= no longer read and write the whole vault in one go. A new module, =sp-async-work=, runs them as jobs in slices of 50 ms from timers, between your keystrokes (it stops a slice early when a key is waiting).

- Progress is in the mode line, e.g. =[Litnote titles writing 12/340]=. =M-x sp-async-work-cancel= stops a job; files already written keep their backups.
- A job waits while you type in the minibuffer, so its questions never replace yours.
- Reports open when the reading is done; the commands return at once.
- A big =.bib= file is read 200 entries per slice.

**** Why not a second Emacs
:PROPERTIES:
:CUSTOM_ID: why-not-a-second-emacs
:END:
The footnote lint uses =emacs -Q --batch=, which fits a pure file-to-result job. These commands ask questions in the middle (disambiguating names, missing years, confirmations), query the Vulpea database, create notes through the interactive machinery, and update open buffers and the database after writing. A headless Emacs has none of that, so each command would be split into two copies of its logic. Slices keep every question and database call where it was; nothing runs in parallel, so there is no race with your editing.

**** Safety
:PROPERTIES:
:CUSTOM_ID: safety
:END:
- Report first, backup before write: unchanged.
- =sp-litnotes-refs-convert= now asks its (up to three) questions right after the report opens, before any writing, so nothing asks you something while you work elsewhere.
- =sp-litnotes-refs-convert= and =sp-litnotes-titles-apply= re-check each note right before writing: skipped if its buffer has unsaved changes or it changed since the report (named in the summary). Open buffers without changes are reverted/killed as before.
- =sp-author-notes= keeps its earlier rule: an unsaved buffer is saved first when you apply.

**** Decisions for you
:PROPERTIES:
:CUSTOM_ID: decisions-for-you
:END:
- =sp-litnotes-titles-apply= and =sp-author-notes-preview= used to return their results; they now do so only when =sp-async-work-synchronous= is set (the tests use it).
- A single huge item (one very large note) still takes its time; slices end at item boundaries.
