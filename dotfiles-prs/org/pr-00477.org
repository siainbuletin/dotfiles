**** What and why

- =M-x sp-org-lint-footnotes= failed with =Cannot open load file: sp-interaction=.
- Cause:
  - The worker is a bare =emacs -Q --batch= with only =funct/= on its =-L= path.
  - Since the echo-area hints work, =sp-batch-report= requires =sp-interaction=, which is in =base/=.
- Fix, in =sp-org-lint.org= (tangled to =sp-org-lint-footnotes.el=):
  - =sp-org-lint-fn--worker-load-dirs=: the library folder, its parent and the parent's sub-folders, like the recursive load path of =init.el=.
  - =sp-org-lint-fn--worker-command=: builds the command line (testable); =sp-org-lint-fn--start= uses it.
- Two more breakages sat behind the first one, now fixed:
  - With =base/= on the path the worker would have loaded =sp-globals=, which needs =early-init.el= (=sp-cache-dir= void). The worker sets =sp-org-lint-fn--worker= and skips it.
  - =sp-org-lint-fn-backup-directory= used =sp-var-dir= at load time, void in a bare Emacs. It now falls back to =user-emacs-directory=.
- Other workers: it is the only place that spawns =emacs= (=invocation-name=); the other batch commands run in-process via =sp-async-work=.
