** Description
/Requested by *Sia*/

*Cause of the long grey box:* =sp-mini-frame= set =mini-frame-resize= to =not-set= and gave the frame no height, so it kept the default frame height while Vertico showed only its candidates.

*Changes in =sp-mini-frame=:*

- No count of its own: the frame uses Vertico's normal =vertico-count= (from =sp-completion=). Nothing is set locally for the mini-frame.
- The frame starts at one line and is *fitted to its content* (=mini-frame-resize= is now =t=), with a maximum of prompt + =vertico-count= candidates (+ the dotted divider line for =M-x=).
- *Centred* horizontally (as before) and vertically for its largest size: =top= is computed in pixels as (parent height - largest frame height) / 2; the frame grows downward from there.
- *Padding of 4 pixels* (=sp-mini-frame-padding=) in the frame's own background colour; =sp-mini-frame-border-color= gives it a colour for an outline. The border faces are now set on every showing (mini-frame sets them only when it makes the frame). =M-x= loses its one-pixel foreground border because the border is now the padding.

*Not tested* (no Emacs in the container; =.el= paren-checked only): the height fitting with Vertico's candidate overlay (=vertico-resize=), the vertical centring on a real display, and the padding colour after a theme change. If the frame is one line too tall or short, adjust =sp-mini-frame--lines=.

*Note:* =CHANGELOG.org= on =main= already has an entry numbered #119 (=sp-fetch-academic=) while that change merged as #118; this PR's entry uses its own number.
