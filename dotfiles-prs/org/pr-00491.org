**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- New module =sp-bibtex-abstract= (literate doc: =docs/tangles/academic/sp-bibtex-abstract.org=).
- Moves the =abstract= field of a BibTeX entry into its litnote under =* Abstract=.
- Keys under =C-; L b f=:
  - =B= dry-run report (Org table sections, =d=/=u=/=A=/=g= as in the other lints)
  - =b= move the abstracts of a whole file, after one question, in batches
  - =e= move the abstract of the entry at point (prefix: dry run)
  - =R= restore a run from its backup
- Safety:
  - Note first: saved, then read back from disk; only if it holds the abstract does the field leave the =.bib=.
  - The =.bib= is written once, at the end, with verified entries only; every other field of an entry must be unchanged or the entry is left alone.
  - Note writes only add (=sp-litnotes-meta--verify-kept=).
- Matching and edge cases:
  - Entry-to-note matching uses =sp-author-notes-bibtex--covered= (ROAM_REFS / =#+reference:=).
  - =* Abstract= missing: created as the first heading. Empty: filled. Same text: only the field goes.
  - Different text: conflict, reported with both texts, nothing overwritten.
  - No litnote: skipped and listed. Macro, concatenation or empty abstract: listed as a problem.
- Conversion: abstract is converted to Org (accents to Unicode, =\emph= to =/x/=, =\&= etc., braces removed, =$math$= kept verbatim, unknown commands kept and named in the report).
- Backup: =sp-bibtex-abstract-backup-directory/<stamp>/= holds the =.bib=, changed notes and a manifest; also visible to =sp-backup-lookup=.
- Tests: =tests/sp-bibtex-abstract-test.el= (23, Emacs 29 batch, temp files) plus a keys test; the lint, meta and keys suites still pass. Not run on the real vault.
- Not changed: no CHANGELOG edit; the main =sp-bibtex-lint-dryrun= report has no abstract button yet.
