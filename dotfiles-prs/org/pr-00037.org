/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW26cs7ZQYxbbiqDNfMZAWuBV][project thread]]/

*Before:* =relationship-annotator-graph= wrote a static HTML file and opened it from disk, so the graph was a snapshot and needed a new run after every edit.

*After:*

- =M-x rel-anno-graph= now opens a live view: a new module =sp-relationship-annotator-live= serves the same page from Emacs on =http://127.0.0.1:8765/=, rendered from the vulpea database on each load. The old static command is =rel-anno-graph-static= (unchanged otherwise, and the SVG export is untouched). Also =rel-anno-live-open=, =-start=, =-stop=, =-refresh=; options =relationship-annotator-live-port= and =-debounce=. =/graph.json= returns the nodes and edges.
- *Shorter command prefix.* All interactive commands use =rel-anno-= (=rel-anno-svg=, =rel-anno-review=, =rel-anno-outline-native=, =rel-anno-outline-vui=, the three outline-buffer commands and the live ones). *The obsolete aliases are removed*, including the old =vulpea-hierarchy-*= ones, so the old command names no longer work; nothing else in the repo used them. Variables and internal functions keep the long prefix.
- *No polling.* An open page holds a Server-Sent Events stream. Emacs watches the folder of =vulpea-db-location= with =file-notify=, waits until it is idle (debounced), cuts the tree for each open page and compares a SHA-1 of the data with the one the page was rendered from. Only a different hash sends a message, so editing a note that is not in the graph reloads nothing. A page that reconnects after a drop is compared the same way, so changes made meanwhile are not lost.
- On a reload the page restores the note it was recentred on, pan, zoom and folded branches (kept in =sessionStorage=).

*How:* a small server on =make-network-process=, bound to 127.0.0.1 (not configurable), GET only, rejecting any =Host= header that is not localhost with this port. I did not use =simple-httpd= (one global server rooted at =/var/www=, all interfaces by default). On =vulpea-graph=: the analysis found no rendering code to reuse (metrics and lists only), so only its neighbour-walk idea applies, already done by =relationship-annotator--scope=; I did not read =vulpea-graph-ui=. Literate doc in =docs/tangles/custom/sp-relationship-annotator-live.org=; the annotator doc and =docs/main.org= are updated; =init.el= loads the module after =sp-relationship-annotator=; =CHANGELOG.org= entries added.

*Tested* (Emacs 29.3, in a container, real annotator code with stubbed vulpea/vui and three fake notes): the modules tangle from their docs and byte-compile. A batch Emacs served =/=, =/graph.json=, =/favicon.ico=, 404, 403 (wrong Host or port), 405 (POST). With an event stream open: a db file touch without a data change sent nothing; a title change plus a touch sent =changed=; a stale =since= hash on connect and =-refresh= sent it; a closed stream was dropped; stop closed everything. Headless Chromium on a live server: the page drew, a recentre plus pan and zoom survived a data-triggered reload, no JS errors.

*Not tested:* real vulpea (whether =vulpea-db-autosync-mode= writes =vulpea-db-location= or its =-wal= soon after a save, and that name being right on your version), your vault and its size (a check builds the tree in Emacs while idle), macOS file notification (fsevents/kqueue), the idle timer in an interactive Emacs (batch has none; the test used a plain timer), the outline buffer keys and the vui outline (not run), =browse-url= with your browser. If the watch cannot start, a message says so and =rel-anno-live-refresh= remains.
