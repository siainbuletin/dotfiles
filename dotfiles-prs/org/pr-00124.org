/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW28jYkTEHaVRbSbZqCYEwELz][project thread]]/

*Reported:* since the vulpea scan was deferred, Emacs hangs for 10+ seconds after init while vulpea reindexes and the dashboard agenda entries fill in, with silent gaps in the echo area.

*Likely cause (read from the code, not measured):* =sp-vulpea-scan-once= ran =vulpea-db-sync-full-scan=, which lists, cleans up and checks dir-locals in the foreground of Emacs; the dashboard's reading of the agenda files visited a vault file and so started that scan; and each of the four dashboard boxes re-read every agenda file.

*Changes*

- =sp-vulpea-base=: removed =sp-vulpea-scan-once= and its =find-file-hook=. =vulpea-db-autosync-mode= starts from a 5s idle timer after start-up (=sp-vulpea-start-autosync=) with =vulpea-db-sync-scan-on-enable= set to ='background=: files are listed in a subprocess and the queue parses only changed files. Opening a note no longer starts a scan.
- =sp-dashboard=: the entries of a list of agenda files are read once per draw (=sp-dashboard--read-entries=, cached only during =sp-dashboard--insert-boxes=), and the boxes filter/sort a copy. Until =org-agenda-files= is set (=sp-dashboard-agenda-ready=) the boxes show "loading agenda files..."; =sp-dashboard-refresh-agendas= redraws the Dashboard when the files are set, if it is the selected buffer.
- =sp-vulpea-para=: the agenda-files refresh sets the ready flag and prints messages with the count and time. Autosync start and dashboard reads print their time too.
- Docs (=sp-vulpea.org=, =sp-dashboard.org=) and CHANGELOG updated; =.el= files edited in step with the docs.

*Not tested:* nothing was run; there is no Emacs in the container and vulpea is not installed. Parens checked only. Profiling steps are in =profiling/vulpea-startup-profiling.md= in the project files. If it still hangs, the profiler will show where.
