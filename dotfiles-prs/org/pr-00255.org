**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- =.config/beets/beets.org=: starter literate config. It tangles two files into =.config/beets/synology/=:
  - =config.yaml=: beets config (library =/config/musiclibrary.blb=, music =/music=, plugins web, chroma, fetchart, embedart, lastgenre, scrub, info, missing, duplicates). It pulls in =secrets.yaml= with =include:=.
  - =compose.yaml=: Container Manager project for =lscr.io/linuxserver/beets:latest=, with volumes =/volume1/docker/beets:/config=, =/volume1/music:/music= and =/volume1/music/_import:/downloads=, on port 8337.
- =.config/beets/deploy-to-synology.sh=: tangles with =emacs -Q --batch= when a tangled file is missing or older than =beets.org= (or when given =-f=), then copies with =scp -O=. Settings come from =-H/-u/-p/-d= or =SYNOLOGY_HOST/USER/PORT/DEST=, with defaults =192.168.88.10=, =$USER=, =22= and =/volume1/docker/beets=. =-n= is a dry run. It copies a local =secrets.yaml= if there is one, and otherwise creates an empty one on the NAS.
- =.config/beets/.gitignore= keeps =secrets.yaml= and local beets state out of the repo.
- =README.org=: new *Homelab configuration* section that links to =beets.org= and the script.

**** Choices to check
:PROPERTIES:
:CUSTOM_ID: choices-to-check
:END:
- The files go into =synology/= and not into =~/.config/beets/config.yaml=. That is where a beets on the laptop would look for its config, and the container paths (=/music=, =/config=) would break it.
- The =web= plugin has to stay enabled, because the image runs =beet web= as its main process and its health check waits for port 8337.
- ~PUID=1026~, ~PGID=100~, ~TZ=Etc/UTC~ and the =/downloads= folder are guesses, marked as such in =beets.org=.
- I didn't add a CHANGELOG entry, because =CHANGELOG.org= covers only the Emacs config.

**** Tested (in a Linux container, not against a real NAS)
:PROPERTIES:
:CUSTOM_ID: tested-in-a-linux-container-not-against-a-real-nas
:END:
- Tangling with Emacs =-Q --batch= writes 6 blocks, and both YAML files parse.
- The tangled =config.yaml= (with local paths) loads in beets 2.14.1 and =beet ls= works. With =secrets.yaml= missing, beets prints a warning and carries on.
- The script passes =shellcheck=. I ran it end to end against stub =ssh=/=scp= that write to a local folder: first run tangles, second run skips the tangle, a newer =beets.org= makes it tangle again, =secrets.yaml= gets copied when it exists, and bad port, relative destination, extra arguments and a missing Emacs each fail with a clear message.
- Not run: real =scp= to DSM, or the container itself.
