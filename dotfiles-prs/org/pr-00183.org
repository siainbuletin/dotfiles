/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2KgDpD79Y9VMv49HyVJm1LH][project thread]]/

*Before:* search commands were spread over many packages and keys (=consult-*=, =rg=, =deadgrep=, =org-semantic=, =p-search=, Recoll, notes grep), with no single place to start.

*After:* =C-c s m= opens =sp-search-menu=, a transient popup that gathers them.

**** Changes (=sp-search= module and doc, CHANGELOG)
:PROPERTIES:
:CUSTOM_ID: changes-sp-search-module-and-doc-changelog
:END:
- *Reading of "decorated buffer like Magit":* a transient popup with a dashboard-style header (search directory and project, which completion frameworks are active, warning if =rg= is missing). I did not build a Magit-style status buffer.
- Groups: buffer and directory (consult-line, imenu, ripgrep, snapfile, consult-todo), grep buffers (rg, deadgrep, ag, Recoll), notes grep (=sp-search-in-notes=, =org-node-grep=, =vulpea-grep=, consult-notes), semantic (=org-semantic-*=, =p-search=, reindex), omni.
- Every package command is guarded with =fboundp=, so nothing dead is offered. =vulpea-grep= is not defined anywhere in the config, so it shows only if a package provides it.
- *Tab-inbox slot:* key =t= points to =sp-tab-inbox-p-search=, hidden until that command exists. No p-search PR was open or merged when I checked, so add the real name in the menu once it lands.
- Doc =sp-search.org=: new "The search menu" section with a table of what each command does, and how the menu links to Vertico, vertico-posframe, Orderless, Marginalia, Embark (export to grep/occur buffers), Ivy/Counsel (Recoll only), Prescient; Corfu/Cape have no link.
- The module already existed (=base/navi/sp-search=) so I extended it; =docs/main.org= already lists it.
- *Key clash:* =sp-keys= rebinds =C-c s l= and =C-c s r= to easysession later, shadowing the Consult keys in =sp-search=. The menu has =l=/=r=. I used =C-c s m= because =C-c s s= is easysession save.
