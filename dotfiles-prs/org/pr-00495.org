**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- Relaunched Emacs often opens a small frame that AeroSpace leaves floating.
- Likely cause: =sp-frame.el= sets =(undecorated . t)= in =default-frame-alist=, and AeroSpace may not treat undecorated windows as standard.
- Adds an =[[on-window-detected]]= rule for =org.gnu.Emacs= with =layout tiling=.
- Only the first matching rule runs, so a rule before it keeps the =quick-capture= popup floating.
- No Emacs frame settings changed.
- Documented in =aerospace.org=, section "Emacs frames tile".
- No CHANGELOG edit (the nightly tidy owns it; this belongs in the global one).

**** Not verified
:PROPERTIES:
:CUSTOM_ID: not-verified
:END:
- The Mac was not reachable from the cloud session, so the app id =org.gnu.Emacs= and the floating layout were not checked on the device.
- First check: =aerospace list-windows --all --format '%{app-bundle-id} %{window-layout} %{window-title}'=.
- If the id differs, change it in both rules.
