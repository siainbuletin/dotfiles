**** The attempt and why it failed
:PROPERTIES:
:CUSTOM_ID: the-attempt-and-why-it-failed
:END:
- *Goal:* a greyer PDF page in DEVONthink's dark mode; DEVONthink has no setting for it.
- *Tried (#520):* =dt-pdf-grey= wrote the =PDFBackground= key of =com.devon-technologies.think= (it already held a mid grey, 0.4246723651885986) with =defaults write=, with DEVONthink closed. It saved the originals and had =--reset=, =--quit=, =--relaunch=, =--dry-run=, and an optional =--disable-pdf-dark-mode=.
- *Findings on Sia's Mac:*
  - Setting =PDFBackground= (0.2 and other levels) changed nothing visible.
  - Only ~DisablePDFDarkMode = 1~ had an effect: the PDF switches to the light appearance, not to a grey.
  - The stored value had the same types DEVONthink uses (=real= alpha, =string= components), so the write was well formed.
  - =strings= on the DEVONthink binary shows only =PDFBackground=, =PDFBackgroundColor=, =setPDFBackgroundColor:= and =DisablePDFDarkMode= for PDF colour: no dark-specific or tint key.
  - =sdef= of DEVONthink has no PDF background property (the =background= matches are text formatting and the imprint command).
- *Why it failed:*
  - DEVONthink probably inverts the page itself in dark mode, and nothing exposes the tint.
  - =PDFBackground= is unused or colours only something small like the page margin (not confirmed).
  - No preference or AppleScript route sets the colour.
- *Not built:* a Hammerspoon =hs.canvas= overlay (tints the whole window, shifts highlight colours); Sia declined it.
- *What still works:* =defaults write com.devon-technologies.think DisablePDFDarkMode -bool true= with DEVONthink closed, for the light appearance.
- The ADR records all of this as bullets.
