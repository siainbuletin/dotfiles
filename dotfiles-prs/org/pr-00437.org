**** Change
:PROPERTIES:
:CUSTOM_ID: change
:END:
- One shared resolver in the core module: =sp-devonthink-record KEY= returns =(:uuid U :supplier KEY-OR-PARENT :via PARENT-OR-NIL)=: own record first, then =crossref=, then =xref=. =sp-devonthink-resolve= (page logic from #436) builds on it.
- =sp-devonthink-note-record-uuid [ACTION]= is the same decision for the current litnote: the =#+devonthink:= keyword, else the entry's record, else the parent's. When it uses the parent's record it says so in the echo area; with an =ACTION= it asks first (the action would reach the whole book).
- =crossref= and =pages= are read with =citar-get-value=, then from =citar-get-entry= (case-insensitive) when that gives nothing.
- Commands that now follow =crossref=:
  - In this PR: =sp-devonthink-insert-link= (page prompt starts with the chapter's page plus offset), =sp-devonthink-open-from-note=, =sp-devonthink-set-keyword= (asks first), =sp-devonthink-citar-open=, and =sp-reading-open= (reading module, via =sp-devonthink-resolve= when loaded).
  - In the stack (see Merge order): =sp-devonthink-tag-note= (#415, asks first), =sp-devonthink-similar-to-note= (#418, read-only, says which record), =sp-devonthink-highlights-import= (#420, asks first), and the sync report, backfill and field probe (#421; the backfill asks once before writing the parent's UUID into chapter notes, the probe asks first, the report lists "Covered by the record of the crossref parent").
- Doc: "Which record a citekey means" in =sp-devonthink.org=. Tests: 31 in =sp-devonthink-test.el= (including the real interactive =insert-link= with an entry that has only a crossref parent) and 13 in =sp-reading-test.el=; the stack PRs add tests for their commands.
