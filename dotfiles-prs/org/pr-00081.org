*Before:* many module docs describe a function or a change in one long paragraph of four or five sentences, which is slow to scan.

*After:* the prose in =docs/tangles/**= and =docs/architecture/= and =docs/main.org= is broken into a one-line lead plus short bullets, grouped by what each bullet says (what it does, dependencies, caveats, known bugs, status).

- About 140 docs changed, roughly 700 paragraphs. Every paragraph over 200 characters with two or more sentences was rewritten.
- The repeated "Literate source for ..." intro is now three bullets (what is in the blocks, where =:tangle= is set, link to the README).
- Wording is kept; no facts were added or removed. Known bugs and "not tested" notes are still there, now as lists.
- Left as written on purpose: text quoted from other manuals or posts (=org-config=, =denote=, =dashboard=, =search=, =file-management=, =sp-typesetting=, =sp-helper-functions=), and a few personal notes (=reading=, =dms=, =task=, =sp-appearance-overview=, part of =zettelkasten=). Say if you want those done as well.

*Checked:* for all 179 =.org= docs, the contents of every source block, every =#+begin=/=#+end= line, =#+PROPERTY= lines and =:tangle=/=:header-args= property lines are byte-identical to =main= (script compared before and after), so the tangled =.el= files do not change. Rebased on current =main=. *Not checked:* I did not run =org-babel-tangle= (no Emacs in the container), and did not render the docs in Org, so list spacing is only checked by reading the diff.
