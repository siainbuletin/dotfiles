**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
With the plain posframe of #156 the =M-x= glitch is gone. This puts the minibuffer text size back, in a way that follows =text-scale-adjust=:

- =sp-minibuffer= maps the fontaine face =sp-minibuffer-face= (1.36 of =default= in =regular=, the same as =sp-text-face= in Org) onto =default=, as before.
- It then calls =text-scale-set= with the =text-scale-mode-amount= of the window that was selected when the minibuffer opened. So ~s-=~ / =s--= / =s-0= in a buffer scale the text of the next =M-x=, file picker or note picker in step with the buffer's text. A minibuffer that is already open does not change size.
- It is on =minibuffer-setup-hook= (the selected window is only known there), not =minibuffer-mode-hook=.
- It does not reset =face-remapping-alist=, which is what dropped the text scale in #146.

Docs (=sp-fonts.org=) and CHANGELOG updated.

**** Reading of the request
:PROPERTIES:
:CUSTOM_ID: reading-of-the-request
:END:
I read "the size of the text equals the fontaine face" as: the base size is the fontaine face (=sp-minibuffer-face=), not a size of its own. Org text still uses =sp-text-face= as before. If you wanted the minibuffer at the plain =default= size, change the first line of =sp-minibuffer=.
