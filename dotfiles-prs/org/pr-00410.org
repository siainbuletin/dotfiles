**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Part of =sp-bibtex-lint=:* a new fix kind =keys=. =sp-bibtex-lint-fix-keys= (=C-c w b k=, the =keys= button of the dry-run report, or =sp-bibtex-lint-convert=) works in batches of =sp-bibtex-lint-batch-size= like the other fixes. The dry run (=C-c w b l=) lists long keys in a section of their own.
- *Prompt:* for each key over =sp-bibtex-key-max-length= (45) it shows the title and suggests a key from =bibtex-generate-autokey= (else the old key cut to the limit, a letter added if taken). The answer is checked (at most 45 characters, no forbidden characters, not another entry's key in any registered file, or one chosen in the run). An empty answer keeps the key.
- *Updating what uses the key* (shown as a plan in =*BibTeX key renames*=, then =y= = everything, =b= = only the .bib file, =s= = skip), controlled by =sp-bibtex-key-update-targets= (=notes files bibrefs=):
  - *Notes* (=sp-bibtex-key-notes-directory=, default =sp-notes-dir=, every =.org= file): the key on =#+reference:= and =:ROAM_REFS:= lines, and citations =@key= (=[cite:@key]=, =[cite/t:@a; @b]=, in text) and =cite:key=. Whole keys only (=@key-2= and =@keyx= are left alone). Each changed note is copied to =key-renames-STAMP/= in =sp-bibtex-lint-backup-directory= first; a note open with unsaved changes is left alone and listed; vulpea is told with =vulpea-db-update-file=.
  - *Cross references:* =crossref=, =xref=, =xdata=, =related= in the file and the other registered files.
  - *PDFs:* files in =sp-literature-dir= named =KEY.ext= or =KEY-anything.ext= (citar's additional files), and the =file= field of the entry. They move through the existing =sp-bibtex-files--move=, so with =sp-bibtex-files-devonthink-tool= set DEVONthink does the rename.
- *DEVONthink tool:* =tools/devonthink-move.py= can now rename: a new name in the same folder is a =rename= in the plan, done with ~rec.name = …~ (tried without, then with the extension; the old name is restored if the file is not where asked), and the record is filed back in the group it was in. Previously such a move would have stopped the run, because DEVONthink's =move= keeps the file name. Changed in =docs/tangles/academic/devonthink-move.org= and tangled.
- Order of changes, so a failure leaves things as they were: PDFs first, then notes and other .bib files, then the entries (written by the lint with its backup), then =citar-refresh=.
- PDFs named after an old BibDesk key (not the citekey) are not touched.
- Docs in =docs/tangles/academic/sp-academic.org= and =devonthink-move.org= (bullet lists). No CHANGELOG edit.
