** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2ApjJf3fNB4nmVud6MqNpBi][project thread]]/

*Before:* =M-x vulpea-hierarchy-graph= drew every parent/child link in the vault as one Graphviz SVG, which is too large for a big vault. =M-x vulpea-hierarchy-outline= showed the whole tree as Org headings.

*After:* Both commands first ask for a starting note and a depth. =vulpea-hierarchy-graph= opens an interactive graph in the browser: pan, zoom, and click a box to fold it. =vulpea-hierarchy-outline= shows native buttons: TAB or =[+]=/=[-]= expands a note on demand, RET visits it, and =c= picks a new start. The SVG export is kept as =vulpea-hierarchy-svg=. Notes at the last depth show how many children they hide.

*How:* One scope function walks the parent tree from the chosen note to the chosen depth. The browser page is generated HTML with the data embedded as JSON and no external assets. Titles are written with =textContent=, and the JSON escapes =<=, =>= and =&=. The button view reads the full tree from vulpea and expands only the branches you open. Tested on Emacs 29.3 with mock notes (scope, toggling, HTML output, and JavaScript syntax). Not yet run against the real vault database.
