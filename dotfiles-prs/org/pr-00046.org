/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2DjHKVMQmvVnXWZYx2E2crb][project thread]]/

*Before:* =org-ql= was installed in =sp-org-base=, and =org-super-agenda=, which =org-ql= requires, a few modules later in =sp-org-agenda=. Elpaca queued it as a dependency first and warned =org-super-agenda previously queued as dependency of: (org-ql)=. =emr= (in =sp-prog-misc=) had the same problem with =paredit=, installed by =sp-lisp= further down the list. Every module loaded during startup.

*After:*

- =org-ql= moves to =sp-org-agenda=, right after =org-super-agenda= (=.el= and the literate doc).
- =sp-lisp= loads before =sp-prog-misc=.
- Twelve leaf modules (=sp-academic=, =sp-dgraphs=, =sp-relationship-annotator=, =sp-notes=, =sp-semantic=, =sp-dyn-graph=, =sp-sandbox=, =sp-vcontrol=, =sp-magit-style=, =sp-terminal=, =sp-eshell=, =sp-ai=) are in =lem--late-modules= and load 0.5 s after Emacs first goes idle once Elpaca has finished its queues. =sp-defer-late-modules= = =nil= loads them with the rest. No other module requires them.
- =docs/load-order.org= (linked from =docs/main.org=) has two Graphviz graphs (rendered SVGs beside it), the table of requirements behind each arrow, and a checklist for placing a new module. CHANGELOG entry added under a "Startup and module load order" set.

*Checked:* Emacs 29.3 reads =init.el= and the changed modules; the module list is the same set as before; the late-module functions ran against stubs (twelve modules required in order, queues processed). The requirements come from the =Package-Requires= headers of =org-ql=, =org-super-agenda=, =emr=, =org-ref=, =org-gtd=, =org-node=, =code-review=, =vulpea-ui=, =treemacs=, =claude-code=, =gptel-agent= and others, read from GitHub.

*Not checked:* a real startup. Elpaca cannot reach MELPA from the container, so I have not seen the warning disappear, nor that the late modules install and configure their packages after init (I read =elpaca.el=, which suggests they do once =elpaca-process-queues= is called). Keys defined only in late modules (for example =C-M-g= for magit) work from about a second after startup. Duplicate explicit declarations (=hl-todo=, =org-autolist=, =elisp-demos=, =company=) are left alone.
