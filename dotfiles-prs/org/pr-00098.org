*Before:* the mode line showed no buffer name, no major or minor mode, nothing. =sp-lambda-line= (the module =init.el= loads; there is no =sp-modeline.el= on =main=) calls =(lambda-line-mode)=, which with =lambda-line-position= =bottom= puts the status line in =mode-line-format=. The next form then set =mode-line-format= to a bare ="%_"= when the position is =bottom=, overwriting it. That divider trick is only for =top=, where the status line lives in the header line (it was ='top= in =sp-choose-modeline=). Separately, lambda-line's default format never shows minor modes (symbol, buffer name, major mode + branch, position, time).

*After:*

- =sp-lambda-line=: the divider is set only for =top=, so the status line shows (buffer name, major mode, branch, position).
- New =sp-modeline= (tooling), adapted from =prot-modeline.el= and =prot-emacs-modeline.el=: no =prot-common=/=prot-icons= and no package, faces inherit from the theme (no hard-coded hex colours), plus minor modes (=sp-modeline-minor-modes-style=: lighters, count or nil), and =global-mode-string= so =sp-tag-emoji= shows. Not loaded by =init.el=; a commented ='sp-modeline= sits beside ='sp-lambda-line= in both lists (load one of the two).
- Doc =docs/tangles/tooling/sp-modeline.org= tangles to the =.el=; =sp-lambda-line.org=, =main.org= and CHANGELOG updated.

*Not tested:* nothing was run (no Emacs in the container; the =.el= was only paren-balanced by script). Check in your Emacs 31 that the lambda-line fix shows the line, and try =sp-modeline= with =M-x sp-modeline-mode= after =(require 'sp-modeline)=.
