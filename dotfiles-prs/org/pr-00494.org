**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Problem (comment on #487):* =d= (drop) in the author works report gets slow and the buffer hangs. =u= restore and =g= refresh took the same path.
- *Cause:* =d=, =u= and =g= draw the whole report again through =sp-batch-report-open=, which called the mode function every time. That re-runs =org-mode= over the whole old buffer: all of =org-mode-hook= (=org-indent-mode=, =org-num-mode=, =org-table-widget-mode=, cite hover, ...), reset of buffer state, then the buffer is erased and filled. Before #492 the table widget also laid out every table again on each of those.
- *Fix:* =sp-batch-report-open= starts the mode only when the buffer is not in it yet. Same for every other report that uses it (litnote titles, tag lint, footnote lint, normalise, notes filing ...). The buffer-local state is set afterwards as before.
- Also: a table cell is only escaped when it holds =|= or a newline (the common case did two regexp passes per cell).
- *Not done, on purpose:* editing only the affected row and table in place. After this change the redraw is a plain text rebuild; a local edit would be a larger change and a new UI that renders reports as a =vulpea-ui-schema-dashboard= style special-mode buffer is being worked on in another thread, which may replace this Org renderer and supersede this PR.
- Docs are bullet lists (=sp-batch-report.org=); =.el= matches. =when-let*= only; no CHANGELOG edit.
