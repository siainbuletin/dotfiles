** Description
Adds =gh-pr-pdf=, a command that turns the pull requests of a GitHub repository (and optionally its Discussions) into searchable org files and one paginated PDF, so a codebase's history can be studied as plain text.

#+begin_example
gh-pr-pdf siainbuletin/dotfiles
#+end_example

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- New Stow package =gh-pr-pdf/=: the script at =gh-pr-pdf/.local/bin/gh-pr-pdf= (links to =~/.local/bin/gh-pr-pdf=) and =gh-pr-pdf/README.org= (usage, needs, safety, "Not run"; Stow's default ignore list skips the README).
- The script wraps =github-backup= for the raw JSON (description, conversation, reviews, inline review comments, commits), writes =org/pr-NNNNN.org= per pull request in number order plus =org/all.org=, then =pandoc -t typst= and =typst compile= make the PDF.
  - Each org file has a property drawer (=:PR_NUMBER:=, =:STATE:=, =:AUTHOR:=, =:URL:=) for org-ql, and every commit is a link to =github.com/OWNER/REPO/commit/<sha>=.
  - Options: =--discussions=, =--skip-fetch=, =--no-pdf=, =--per-pdf N=, =--reverse=, =--private=, =-o DIR=.
  - Pull request text comes from strangers, so raw HTML is dropped, =pandoc= runs with =--sandbox=, and lines starting with an org directive (=#+INCLUDE:= and so on) become literal text. Checked with an injected =#+INCLUDE: "/etc/passwd"=.
- =stow-migration/packages.tsv=: one row (=gh-pr-pdf    all .local/bin/gh-pr-pdf=) so the package is in the list =migrate.sh= derives for each machine. It matches no file in =$HOME=, so it should not change what the migration moves.

**** Not run

Written in a container without Typst or network access to GitHub's API. Run on made-up JSON: the org and Typst-source output, including headings inside bodies, empty bodies, numeric ordering, =--per-pdf= and the Discussions renderer. Not run:

- =typst compile=: the PDF itself has not been seen. Try =gh-pr-pdf siainbuletin/dotfiles= and open the PDF; without =typst= it stops after writing the =.typ= file and says so.
- =github-backup= on a real repository. The JSON key names the script reads (=comment_regular_data=, =comment_data=, =review_data=, =commit_data=) are from memory. If a pull request reports commits but no commit list is found, the script warns and prints the keys it saw; the fix is the key names in =render_pr=.
- The Discussions fetch (=gh api graphql=), which reads up to 100 comments and 50 replies per discussion and warns on more.
- =stow gh-pr-pdf= (no Stow in the container): expect =~/.local/bin/gh-pr-pdf= as a symlink into =~/dotfiles/gh-pr-pdf/.local/bin/=.
