** Description
Stacked on #18 (merge #16, #17, #18 first).

Before: The module was called =sp-vulpea-hierarchy= and only read relations between notes. Node types, the type patterns of a relation, anomaly checks and computed attributes lived in the external =discourse-graphs= package.

After: The module is =sp-relationship-annotator= (=relationship-annotator-*=). Notes can have a type (=DG_TYPE= property, =type= metadata or a file tag), a relation can list the types it should connect, and the browser graph flags other edges with a warning sign. Boxes without a coloured tag take the colour of their type, and an attribute such as =[2]= is shown after the title. =relationship-annotator-review= lists anomalies, claims with gaps and the strength of each answer. The old variable and command names stay as obsolete aliases, so =sp-dg-positions= (#12) keeps reading the rankdir.

The port covers the node types, relation patterns, the anomaly check, the formula language for attributes, argument gaps and answer strength. The formula parser has no global state, takes relation names from the configuration and stops on self-references. The SQLite cache, the websocket UI and node/link creation were not ported; =docs/relationship-annotator-vs-discourse-graphs.org= compares the two and lists what was left out.

How: the discourse layer works on the tree that =--build= returns, with an index of edges standing in for the SQL queries. The literate doc was regenerated and tangles to the .el and .html byte for byte. Tested on mock notes in Emacs 29.3 and headless Chromium, not on a real vault.
