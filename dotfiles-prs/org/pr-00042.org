** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2FVFDA4BhYwYUqzWKVLmVVB][project thread]]/

*Before:* an agent had no way to run or check the Emacs config in a cloud container. Booting =init.el= stalls there, because Elpaca needs MELPA and GNU ELPA, which that environment blocks.

*After:* =.config/emacs-modular/.claude/skills/run-emacs-modular/= holds a skill, a driver and a harness:

- =driver.sh report= loads every default module and prints ok/FAILED per module (59 ok, 13 failed here, the failures being modules whose packages are absent).
- =driver.sh eval FORM MOD…= evaluates a form after requiring modules.
- =driver.sh test FILE= runs an ERT file against the loaded modules.

*How:* the harness sources =early-init.el= but not =init.el=, turns =use-package= =:ensure= into a no-op and requires modules one by one. It works on a throwaway copy of the config, with an empty notes folder.

*Not verified:* a full boot with packages, the GUI, keybindings, Magit and TRAMP. Those need MELPA/ELPA access or the Mac (=emacs-pr=). The =report=, =eval= and =test= commands were run in this container with Emacs 29.3.
