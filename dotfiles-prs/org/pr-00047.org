/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2GXf2KrJqndPq66pawUCkK2][project thread]]/

*Before:* the =Projects= item of the splash menu is being removed (#45 follow-up) because it is to become a sidebar with writing projects and the =sp-org-issues= tracker. There was no design for it.

*After:* =docs/projects-sidebar-layout.org= compares five ways to host the sidebar (a side window with a dedicated buffer, a =vulpea-ui= widget, treemacs-style nodes, a child frame, a plain split), recommends a left side window drawn with =vui= in a new =sp-projects-sidebar= module, says how writing projects (a =vulpea-para= =Writing= area) and issues (the file from =sp-org-issues=) would be read and refreshed, how it fits =sp-workspaces=, and lists a five-step plan and open questions. It is linked from a new "Design notes" section in =docs/main.org=, and has a CHANGELOG entry.

*Checked:* the claims about existing modules (=sp-vulpea-ui=, =sp-tab-inbox=, =sp-treemacs=, =sp-buffers=, =sp-workspaces=, =vulpea-para=, =sp-org-issues=) against the source. No code, so nothing was run.

*Not checked:* side-window behaviour in a real Emacs (slot sharing with treemacs, =ace-window=, =popper=), and whether the vulpea database exposes todo keywords for headings; the doc says so where it matters.
