**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Problem:* =sp-see-also= (outgoing: what this litnote mentions) and =sp-see-also-show-concept= (incoming: who mentions a concept) were two separate views, and for a litnote you could not see all the ways it is referenced.
- *One interface:* =sp-see-also-show &optional TARGET=, one buffer =*see-also*=.
  - no argument: the litnote of the current buffer; =C-u=: pick any note by title; from Lisp, TARGET is nil, a file or a note ID.
  - =sp-see-also-show-concept= and =-by-name= stay as thin wrappers, nothing breaks.
- *Two parts in the view:*
  - "This note mentions": concepts and open questions, as before (left out for a note with no file of its own).
  - "Referenced by": every litnote that refers to the note, with a count per way, e.g. =×4 · footnote 1 · link 1 · parent 1 · cite 1=.
- *Ways a note is referenced* (=sp-see-also-reference-kinds=, default all): =footnote=, =section=, =link= (any other =id:= link), =parent= (=parent ::= line), =cite= (citation of the note's =#+reference:= citekey).
- New =sp-see-also-references ID CITEKEY EXCLUDE-FILE=; links, parent lines and citations are read from files each time, not cached (no cache version change). Source blocks and comments are ignored; the note's own file is left out.
- Docs: =docs/tangles/academic/sp-see-also.org= ("The two views" rewritten as bullet lists, "Using it", Limits). Tangled =.el= and tests regenerated.
- Tests: 41 ERT tests pass (6 new/changed) on Emacs 29.3; tangle check passes. =when-let*= style only. No CHANGELOG edit.
- Not run in the real GUI, vault or =vulpea-db=.
