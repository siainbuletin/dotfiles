New "Dynamic block templates" section in =sp-org-base= (doc and tangled =.el=).

- =sp-org-dblock-templates=: customizable alist =(LABEL . PLIST)=; the plist is what =org-create-dblock= takes (=:name= plus block parameters).
- =M-x sp-org-dblock-insert-template= (also =C-c C-x t= in Org buffers): pick a template with =completing-read=, insert it at point, update it (=sp-org-dblock-update-after-insert=, default on), leave point on the =#+BEGIN= line.
- Default template "Children of this note": =collection-query-table= with =:parent-of self :columns (:title) :sort-by :title=.
- =:parent-of self= is resolved by =sp-collec-query-resolve-parent-of= on every update to the ID of the note the block is in (=org-id-get-create=, so a note without an ID gets one). It accepts the symbol =self= and the string ="self"=, so the template needs no change in the table code.
- CHANGELOG entry under Open pull requests (to move into a feature set when merged).

Tested in Emacs 29.3 batch: 4 new ERT tests in =tests/sp-org-base-dblock-test.el= pass (they use a stub dblock, not Vulpea). =tools/check-tangle.sh= is clean for =sp-org-base.el=; the only drift it reports is =sp-search.el=, already on =main=. Not tried in the live Emacs with Vulpea, so inserting the real table in a note needs a check on the Mac. =C-c C-x t= was unbound in =org-mode-map= in stock Org; check it does not clash with your own bindings.
