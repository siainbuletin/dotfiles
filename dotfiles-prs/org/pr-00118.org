*Why this PR exists:* #90 was merged before its last commits, and #92 (stacked on the #90 branch) was merged into that closed branch, so neither =sp-fetch-academic= nor the =sp-bibliography-dir= change reached =main=. This brings both in on top of current =main= (which also moved =sp-paths= into =sp-globals=).

- *=sp-fetch-academic=* (new sub-module, required by =sp-academic=; doc =docs/tangles/academic/sp-fetch-academic.org=): =biblio= and =biblio-gscholar= and the lookup commands move here (=C-c w b b= is now =sp-fetch-academic-biblio-lookup=, no alias); =sp-fetch-academic-doi= (=C-c w b i=) adds an entry through =org-ref='s =doi-utils=; =sp-fetch-academic-download= (=C-c w b u=) saves a PDF into the literature folder, rejects non-PDFs and writes it into the entry's =file= field. =consult-omni= is only a marked placeholder in the doc, linked with =sp-browsing.org=; =sp-browsing= itself is not changed (its working recipe is a switched-off block in =sp-browsing-old.org= that caused startup errors). Added to the =docs/main.org= module tree and =docs/architecture/load-order.org=.
- *One folder option:* =sp-bibliography-dir= (in =sp-globals=) now defaults to =~/Documents/bibliography=; =sp-bibtex-dir= and =sp-bibliography= are removed, no aliases. =sp-cite-to-org= / =sp-cite-to-markdown= pass one =--bibliography= flag per registered =.bib= file instead of reading =sp-bibliography=. Move existing =.bib= files to the new folder, or set =SP_BIBLIOGRAPHY_DIR=.
- *Key pattern fix:* =main= had a block of six =bibtex-autokey-*= options at the end of the =bibtex= =:custom= list (names 1, no separators, 0 title words) that came back with the =setq= clean-up and overrode the pattern, giving =smith2017=. Removed; loading =sp-bibprocess= in batch Emacs now gives names 2, title words 2, separator =-=.

*Checked* (Emacs 29.3, batch, =use-package= stubbed): download copies a =file://= PDF, names it after the key, writes ~file = {...}~, rejects an HTML file; the attach helper with no/existing =file= field; DOI clean-up; =sp-bibtex-register= and the pandoc flag helper on a temp directory; the effective autokey values after loading =sp-bibprocess=; docs tangle to the =.el= files byte for byte (own tangler). *Not run:* CrossRef, Google Scholar, =org-ref= DOI/PDF fetch, pandoc, Elpaca installs, the whole configuration. I expect =org-ref= to clean a new DOI entry with =bibtex-clean-entry= (so it gets the key pattern) but did not confirm it.
