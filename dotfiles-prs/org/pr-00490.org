**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Request:* a function in the BibTeX lint that takes the Zotero paths in =file= fields, matches each PDF to the copy already in =literature/inbox/zotero-backup=, moves it to the top of =literature/=, rewrites the field, and moves the record in DEVONthink too. Modelled on the earlier =bdsk= fix.
- *New module =sp-bibtex-zotero=* (own doc =docs/tangles/academic/sp-bibtex-zotero.org=, bullet lists; the module is separate because =sp-bibprocess.el= is already about 2,600 lines). Required from =sp-academic=.
- *Keys* (=C-; L b z=, same verbs as every lint group): =l= dry run, =a= apply (=C-u= also the weak matches), =r= restore a run.
- *What the real data looks like* (read-only look at =~/Documents/bibliography= and =~/Documents/literature=):
  - The "6-digit encoding" is an *8-character Zotero key* (=A-Z0-9=, for example =Z6HVLKNU=). All 3,926 Zotero paths in the 80 =.bib= files use it (=sp-bibtex-zotero-key-regexp= if that ever changes).
  - 3,879 of those paths have a folder in =zotero-backup=; the folder normally holds the PDF and Zotero cache files (=.zotero-ft-cache= and so on).
  - Path forms handled: bare =/Users/…/Zotero/storage/KEY/name.pdf=, Zotero's =label:path:mime=, several parts joined with =;=, BibTeX escapes (=\;=), wrapped lines, another user's home (=/Users/clb3/…=).
- *Matching* (names only, no guessing): =exact=, =normalised= (case, spacing, accents, TeX accents like ={\"i}=, curly quotes and dashes), then two *weak* levels shown for review only (=by-dir=: the only file of that type in the folder; =by-name=: no folder, but exactly one file of that name in the whole backup). Otherwise reported as =no-dir=, =no-file= (Zotero caches only), =ambiguous=, =collision= or =unsafe-name=.
- *Dry-run numbers from a Python mirror of these rules on the real files* (nothing was written; the Elisp itself has not run on the real library):
  - 1,824 sure matches, which are 1,426 distinct PDFs (several entries share one file);
  - 11 weak matches for review; 34 paths with no folder and no file of that name; 50 whose folder has no PDF;
  - 19 destination names clash between different backup folders (6 identical files, 13 different), so the 13 would be reported as =collision= and not moved; no clash with a file already at the top of =literature/=;
  - 1,408 =.html= snapshots and 75 =.epub= and other files are left alone (=sp-bibtex-zotero-extensions=, default =("pdf")=).
- *Safety*:
  - dry run changes nothing; the plan is an Org table report built with =sp-batch-report-table-section= (rows link to the entry; =d= drops a row from the plan, =u= brings it back, =g= refreshes, =A= or =C-c C-c= applies);
  - only adds or modifies: no file or record is deleted; a file is never moved over another; a clash is reported, or, for an identical file already at the top, only the field is rewritten (the backup copy stays);
  - apply copies the =.bib= file first (same backup folder as the other lint fixes) and writes a manifest (=zotero-manifest.eld=) *before* moving, so a cut-short run can still be restored; if the move fails half way, the files that did move are still rewritten and the error is shown;
  - =restore= moves the files back and puts the earlier =.bib= text back; it refuses if the =.bib= file changed after the run, and keeps the current text as =before-restore.bib=;
  - *DEVONthink*: moves go through =tools/devonthink-move.py= (PR #410) with =--plain-rename=, so records keep UUID, tags and highlights. The dry run asks the tool for its own dry run (records to move, files not in DEVONthink, blocked). Apply and restore *refuse before touching anything* when =sp-bibtex-files-devonthink-tool= is unset or DEVONthink is not running (checked with =pgrep=, so DEVONthink is never launched by accident); =sp-bibtex-zotero-require-devonthink= turns that off.
- No =CHANGELOG.org= edit (nightly tidy), =when-let*=/=if-let*= only, no =.el= edited by hand (tangled from the docs; =tools/tangle-all.el= gives no drift for the three docs touched).
