/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW29vhgKfRxAMNLbYh7KprHvb][project thread]]/

Before: there was no file tree in the config, so keeping the modules and the docs in =docs/tangles= in view meant switching to dired.

After: pressing =<f9>= opens a treemacs side window rooted at =~/.config/emacs-modular= (=user-emacs-directory=), and pressing it again closes it. Nothing opens at startup.

The tree is rooted at a fixed folder, =sp-treemacs-root=, instead of treemacs' "current project", because the yadm repository's root is =$HOME= and following the project would show the whole home folder.

How: a new module, =libraries/modules/ui/sp-treemacs.el=, installs treemacs through Elpaca (=:ensure t=), binds =<f9>= to =sp-treemacs-toggle=, keeps treemacs' saved workspace in =sp-cache-dir=, and turns on =treemacs-follow-mode=. The toggle is defined in =:config= because it uses the =treemacs-is-path= macro. The module is added to the window management group in =init.el=, after =sp-mini-frame=. Its literate doc, =docs/tangles/sp-treemacs.org=, tangles back to the =.el= byte for byte (checked with =org-babel-tangle-file=), and has a =:tangle no= Sandbox block.

Tested in =emacs -nw -Q= with treemacs from source: =<f9>= is an autoload before first use, the first press adds the root and shows the tree, the second hides it, the third shows it again without adding the root twice.
