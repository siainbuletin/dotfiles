**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- Problem: =M-x emureader-build= fails with =gmake: *** No rule to make target 'module'= in =var/elpaca/builds/emureader/=.
- Cause (checked on the checkout on Sia's Mac):
  - =emureader-build= runs =gmake module= in =emureader-directory=, the directory of the loaded =emureader.el=, which is the Elpaca builds dir.
  - Elpaca's default =:files= links only =*.el= and a few docs there, so there is no =Makefile= and no =render/*.c=.
  - The =Makefile= and sources are in =var/elpaca/sources/emureader/=; running =gmake module= there works on macOS (it is not a macOS problem).
  - Elpaca also deletes and recreates the builds dir on every build, so a module built there would be lost.
- Fix, in the =use-package= recipe:
  - =:build (:before elpaca-build-link sp-pdf-reader--elpaca-build-module)=: runs =gmake module= in the source dir before linking.
    - A failure (e.g. MuPDF missing) is only printed in the Elpaca log, so =lsp-mode= and other dependants still build.
  - =:files (:defaults "Makefile" "render" "emureader-dyn.*")=: links the module, =Makefile= and =render/= into the builds dir, where =emureader= looks for the module.
    - =M-x emureader-build= also works as a manual fallback.
- Literate doc updated as bullet lists.
