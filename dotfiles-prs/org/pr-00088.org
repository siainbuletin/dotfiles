​#85 started =cursor-intangible-mode= from an idle timer, but the echo-area error still appeared constantly. This removes the mode.

*Why the error cannot be suppressed*

- The mode puts =cursor-sensor--move-to-tangible= on =pre-redisplay-functions=. It calls =cursor-sensor-tangible-pos=, which returns nil when it finds no tangible position, then does arithmetic on nil: =(wrong-type-argument number-or-marker-p nil)= (Sia's backtrace).
- Redisplay runs the hook inside =with-demoted-errors=, so the error is caught and printed in C-level redisplay before any handler of ours runs. =condition-case=, =debug-on-error= and =warning-suppress-types= cannot reach it. Advising the function would mean patching Emacs's own code.
- It repeats because redisplay runs the hook every time, for as long as the condition holds.
- Edge cases where the mode would work: a buffer that is never erased, never redrawn and always has a button. The dashboard redraws on every window-state change (=sp-dashboard-refresh=), and the buttons come and go with the privacy mode and agenda boxes, so it cannot meet that. A guard that makes it safe would have to run before redisplay, which is the same hook.

*Changes* (=sp-dashboard.el=, =sp-dashboard.org=, =CHANGELOG.org=)

- =sp-dashboard--isolate-menu= no longer marks text =cursor-intangible= or starts the mode; =sp-dashboard--enable-intangible= is removed. The keymap overlay stays: =TAB= / =S-TAB= already step through the buttons (wrapping), and the commands that move point are bound to =ignore=, so point only rests on a button.
- =sp-dashboard-focus-face= has =:extend nil=.
- =global-hl-line-mode= is turned off in the dashboard buffer: =(setq-local hl-line-mode -1)= does not disable it, and =prog/sp-prog-misc.el= turns the global mode on. This is the likely cause of the whole-line highlight, since the focus overlay covers only the button text; not verified.

*Not tested:* no Emacs in this environment, so none of it was run.
