*Before:* startup reports =[FAILED] sp-env (void-function exec-path-from-shell-copy-env)=. =sp-env.el= had a second, top-level =dolist= (added in ee21b24 for =GIT_CEILING_DIRECTORIES=) calling =exec-path-from-shell-copy-env= outside the =use-package= form. That form only loads the package in a GUI window system (=:when=), and under Elpaca its =:config= runs after activation, so the top-level call hit an unloaded package (always in a terminal Emacs). The list also contained a literal =...= left from an abbreviated edit, which would have been passed as a symbol.

*After:*

- =GIT_CEILING_DIRECTORIES= joins the single variable list inside =:config=; the stray top-level =dolist= is removed.
- The daemon case (=(when (daemonp) ...)=, which also called the package outside =use-package=) becomes part of the =:if= condition, so the package loads and initialises there too.

*Not tested:* nothing was run (no Emacs in the container). On fish, =exec-path-from-shell= is unchanged; if a startup warning about the shell appears, it is separate from this error.
