**** What changes
:PROPERTIES:
:CUSTOM_ID: what-changes
:END:
- =Cmd+X= in DEVONthink toggles between the selection tool and the highlight tool.
- It acts only when a PDF is shown. The test is that Tools > Annotate > Highlight Text exists and is enabled. Otherwise Cut is passed through unchanged.
- It reads the real mode, so it is not blind: highlighting is on when the Highlight Text menu item has a check mark.
  - On: it chooses the selection tool, an item in Tools > Annotate starting with Select, Pointer or Text Selection. If there is none, it chooses Highlight Text again to switch it off.
  - Off: it chooses Highlight Text.
  - If the menu shows no check marks at all, it falls back to the last state the key set. That is only a record of the last press and can be wrong if you switch tools with the mouse.
- An alert shows "Highlight" or "Select" after each press.
- =Caps+x= now uses the same toggle (before it only started highlighting). Keeping it as well makes sense: it is the key that works in every DEVONthink context and is the only one that shows an alert when no PDF is shown.
- The colour keys still start highlighting, as before.

**** What is lost
:PROPERTIES:
:CUSTOM_ID: what-is-lost
:END:
- Cut with =Cmd+X= stops working while a PDF is shown in DEVONthink, even in a text field of that window, such as an annotation note.
- Text editors, the item list, rename fields and other apps still get Cut, because no PDF is shown there or the key is only active in DEVONthink.
- The =Cmd+X= check reads the Annotate menu on each press, like =Cmd+Z=, so there may be a small delay.
