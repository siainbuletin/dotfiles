**** What
:PROPERTIES:

=org-clock-in= signalled =Wrong number of arguments= because =sp-modeline-parts-clock-switch-state= took no arguments, but Org calls =org-clock-in-switch-to-state= with one: the entry's current todo keyword (or nil). The function now takes =&optional state=, uses it instead of reading point, and returns the clock keyword only when the entry has an open keyword and the configured keyword is in =org-todo-keywords-1=. Behaviour is otherwise unchanged. The other clock hooks (=-flag=, =-unflag=) are called with no arguments by Org, so they are fine. Doc and CHANGELOG updated.
