** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2D4kQX5Tmjr48sWCkaDNynw][project thread]]/

*Before:* no way to turn loose thesis ideas into tasks from Emacs.

*After:* =M-x sp-thesis-dump= opens a buffer for a brain dump. =C-c C-c= sends it to Claude, which returns annotated Org =TODO= tasks (summary, tags, effort, citekeys), a checklist of citekeys to look up (checked by Emacs against the =.bib= files, so "missing" does not depend on what Claude says) and open questions. The answer opens in a review buffer; =C-c C-c= files it under a heading of the task file (created if missing).

*Portable:* =sp-thesis-dump.el= needs only Emacs 28.1, Org 9.5 and the =claude= command. Project variables (task file, heading, bib files, TODO keywords, tags, citation style, citekey style, outline file, language) are prompted for when missing and can be saved in the project's =.dir-locals.el=; =C-u M-x sp-thesis-dump= asks for all again. Machine settings (the =claude= command, =--mcp-config=, =--allowedTools=) are global and never read from =.dir-locals.el=. Copy the one file into the thesis repo's Emacs setup.

*How "org-mcp" is used:* MCP puts the model in the client role, so Emacs cannot send to Claude through an MCP server. Emacs runs =claude -p= in the project directory, and if =sp-thesis-dump-claude-allowed-tools= lists the org-mcp tools, Claude can read the Org files for context. Emacs does the filing. Without MCP the prompt carries the existing headlines, known citekeys and an optional outline file.

*Also:* literate doc =docs/tangles/custom/sp-thesis-dump.org= (tangles the module and a companion Claude Code skill =docs/skills/thesis-brain-dump/SKILL.md= for the same job outside Emacs), =init.el= loads it after =sp-sandbox=, entries in =docs/main.org= and =CHANGELOG.org=.

*Tested:* byte-compiles without warnings on Emacs 29.3; settings, prompting and saving to =.dir-locals.el=, prompt, parsing (including a code fence), rendering, filing under a nested heading and the failure path were run in batch Emacs against a stand-in =claude= script.

*Not tested:* the real =claude -p --output-format json= envelope, reading the prompt from stdin, =--mcp-config=/=--allowedTools=, the org-mcp tool names, the GUI on macOS, and the skill.
