/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW212AZe9AuXK5zGyitrMyoeN][project thread]]/

Based on =main=. It does not depend on #17 to #20 or #22, which touch other files; the day stamp file simply uses =sp-cache-dir= when it exists.

*Before:* =sp-org-issues= could show the issue board, but nothing told me each morning what to do first across issues and pull requests.

*After:* =M-x sp-org-issues-morning= opens a read-only =*Morning*= Org buffer with one ranked list of the open issues and the open pull requests of the repositories in =sp-org-issues-repos= (plus =sp-org-issues-morning-extra-repos=). It also appears once, on the first Emacs start of each day. Ranking, highest first: failing checks (100), merge conflict (90), changes requested (85), approved and green (80), an issue whose PR is gone (75), waiting for my review (70), then issues by PROG 60, NEXT 50, WAIT 20, TODO 10. Deadlines add up to 30, a waiting PR gains a point a day up to 10, and a PR stacked on another open one loses 15 per level and says "only after #N". An issue and its PR (the =PR= property) are one line. All scores are in =sp-org-issues-morning-scores=. The full rule, the TDD workflow and how to brief Claude for it are in the guide =tdd/tdd-with-claude.md= in the project files.

*How:* pull requests are read with =gh pr list --json= (needs =gh auth login=), one repository after the other without blocking Emacs; without =gh= the list shows the issues and says so, and a repository that fails is named at the top. The code is written test first: 25 ERT tests in the =* Tests= section of the literate doc tangle to =tests/sp-org-issues-test.el=.

Run them with =emacs -Q --batch -l tests/sp-org-issues-test.el -f ert-run-tests-batch-and-exit= from the folder of =init.el=.

*Tested:* the 25 tests pass in headless Emacs 29.3, including the fetch against a fake =gh= script. I saw them fail before the code existed and broke the stack rule on purpose to check that the right test fails. The doc tangles to the module and to the test file.

*Not tested:* the real =gh= (this session cannot use GitHub's GraphQL API), the real vulpea area lookup, the =*Morning*= window and the startup greeting in the full configuration. Please run =M-x sp-org-issues-morning= on your Mac.
