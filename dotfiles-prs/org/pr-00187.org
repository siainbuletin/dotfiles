**** Findings
:PROPERTIES:
:CUSTOM_ID: findings
:END:
- *amx*: =amx-items= held only amx's initial command list and an empty history. Nothing in the config installs or loads amx; the file is a leftover. If a package pulls amx in, its save file is now in =var/cache/=.
- *=.eld= files* (tracked at the root, all package defaults, none edited by hand): =projectile-bookmarks.eld= (known projects, kept), =projectile-frecency.eld= (visit counts, cache), =projects.eld= and =places.eld= (stale: =nil= and an old =elpa/lambda-themes= path), =agent-shell/markdown-links.eld= (opened links, cache). Already elsewhere: =tabspaces-session.eld=, =fontaine-latest-state.eld=, saved query-table views. User data among them: only the known-projects list and the saved views. No =tangle-hashes.eld= or reload-hash file exists in the repo.
- *=org_dataview.db=*: an SQLite table of Org properties from the =org-dataview= experiment, which is commented out in =sp-org-ext=. I did not guess its location variable, so it is only untracked and ignored.
- =forge-database.sqlite= and =url/cookies= are also tracked at the root; left alone.

**** Before you pull (Git deletes the tracked copies)
:PROPERTIES:
:CUSTOM_ID: before-you-pull-git-deletes-the-tracked-copies
:END:
#+begin_src sh
cd ~/.config/emacs-modular && mkdir -p var/etc var/cache
cp discourse-graphs.db var/discourse-graphs.db
cp org_dataview.db var/org-dataview.db
cp savehist var/savehist
cp projectile-bookmarks.eld var/etc/
cp projectile-frecency.eld var/cache/
[ -f vulpea.db ] && mv vulpea.db var/vulpea.db   # untracked, Git does not touch it
#+end_src

=bookmarks= is moved by Git. If =vulpea.db= is not moved, Vulpea just rebuilds it (slower first start). Nothing is deleted on your machine by me.
