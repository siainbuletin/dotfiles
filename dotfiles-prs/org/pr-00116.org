** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2GZfKdKaJ3ZDytUsAiWfF6L][project thread]]/

*Cause:* =olivetti-mode= centres and narrows text by setting window margins. =sp-set-window-margins= in =sp-frame= runs on the global =window-configuration-change-hook= (and at startup and for new frames) and sets a 2/2 margin on every window. The global hook runs after Olivetti's buffer-local one, so it overwrote Olivetti's margins and the text ran to the window edge instead of the 80-column body.

*Fix:* =sp-set-window-margins= now skips windows whose buffer has =olivetti-mode= on (checked with =bound-and-true-p=, so it is safe before Olivetti loads). Doc (=docs/tangles/ui/sp-frame.org=) and CHANGELOG updated.

*Not changed, worth knowing:* =sp-writedesk= sets =olivetti-minimum-body=, which is not an Olivetti variable (it is =olivetti-minimum-body-width=), so that line does nothing. If you fix its name, 100 > 80 would widen the body to 100 columns, so I left it for you to decide.

*Not tested:* no Emacs in the container; please check an Org buffer after =M-x eval-buffer= of =sp-frame.el= or a restart.
