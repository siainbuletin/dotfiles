- The command is =sp-bibtex-lint-fix-merge= (the only merge lint; also step 4 of =sp-bibtex-lint-fix-authors=).
- It already reverted the visiting buffer through =sp-bibtex-lint--save=, shared by every write-capable lint fix (date, duplicates, authors, organisations, files, keys, crossref).
- Gaps in that shared helper:
  - a buffer with unsaved changes was skipped silently, so it stayed stale;
  - citar's cache was refreshed only by the long-keys fix;
  - the merge checks for unsaved changes only when it starts, but its questions can take a while.
- The abstract mover has its own =sp-bibtex-abstract--refresh-buffer= (revert plus vulpea update); left alone to keep the diff small.
- The merge had no way to drop groups; the other fixes drop entries with =d= and restore with =u=.

**** What changed
:PROPERTIES:
:CUSTOM_ID: what-changed
:END:
- Reload (shared by all lint writers):
  - New =sp-bibtex-lint--refresh=, called by =sp-bibtex-lint--save=: reverts the unmodified buffer without a question (point stays), never discards unsaved edits (warns instead), refreshes citar.
  - New =sp-bibtex-lint--unsaved-resolve=, used by =sp-bibtex-merge--apply= just before writing: with unsaved changes asks =d= diff, =r= recheck after saving, =s= skip (nothing written).
- Drop and restore (merge only):
  - In the group question: =d= drops the group for later, =u= brings a dropped group back.
  - Dropped groups are skipped going forward, also in later runs of the Emacs session; =p= can step back to one to restore it.
  - Stored in =sp-bibtex-lint--excluded= with key =FILE::TARGET#merge=, so =M-x sp-bibtex-lint-restore-dropped= lists and restores them with the dropped entries.
  - When every group is dropped, the command says so and asks nothing.
- Docs updated as bullets in =sp-academic.org=, re-tangled to =sp-bibprocess.el=.
- =CHANGELOG.org= not edited.
