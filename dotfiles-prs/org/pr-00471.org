**** Answer

- *Yes*, the =.bib= files can be read after startup, in idle time, so the first =citar= call finds them parsed.
- *Yes*, a cache on disk avoids re-reading unchanged files across Emacs sessions.
- *No git needed*: =citar= already compares size, modification time and a hash of the contents, and only parses a file whose content changed. Asking git would only repeat that (and spawn a process).

**** How citar caches (read from =citar-cache.el=)
:PROPERTIES:
:CUSTOM_ID: how-citar-caches-read-from-citar-cacheel
:END:
- Parsed files live in =citar-cache--bibliographies= (memory only, hence the slow first call of every session).
- Every call checks each file: same size and mtime, nothing is read; changed mtime, the file is hashed and parsed only if the hash differs.
- A bibliography tied to no buffer is dropped the next time citar releases unused ones, so the preload ties each file to =global=.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- Idle preload in =sp-citations= (loaded through =sp-late-modules=): an idle timer loads =citar= (retries if Elpaca has not installed it yet) and reads one file per idle slice (0.3 s idle between files).
- =C-g= while a file is parsed stops the preload; citar reads the rest when called.
- Refresh: saving a =.bib= buffer schedules a new pass (covers =sp-fetch-inbox=, which saves the buffer); =sp-bibtex-register= does the same. A pass only checks files that did not change.
- Disk cache =citar-bibliography.eld= in =sp-cache-dir=: entries plus the size/hash/fields plist, written only after a pass that parsed something. On the next start citar still validates it, so a changed file or changed template fields is parsed again; candidates are formatted again from the entries. A damaged or missing file is ignored.
- Options: =sp-citations-preload= (t), =sp-citations-preload-delay= (3 s), =sp-citations-preload-refresh-on-save= (t), =sp-citations-preload-persist= (t), =sp-citations-preload-cache-file=.
- I did not use =sp-async-work= (#468): its slices are timer based, not idle based, and a "wait until the user is idle" step would spin. Plain idle timers fit better; the cost is no mode-line progress.
- Docs: new section in =sp-academic.org= as bullets; no CHANGELOG edit; no =when-let=.
