Fixes the errors seen when starting Emacs from =main=, and audits the other =use-package= forms.

*Root causes*

- =Cannot load goto-last-change / rainbow-mode / treemacs-nerd-icons / org-contrib / openwith=, and =ns-auto-titlebar/:init=: these forms had no =:ensure=. Elpaca's =use-package= support installs nothing by default; =elpaca-use-package-by-default= in =init.el= does not exist in current Elpaca (checked in its source). The =locate-library= guards removed in #61 used to hide this.
- =Failed to parse package consult-snapfile ... sp-path=: =use-package= reads a list given to =:load-path= as a list of paths and evaluates each symbol as a variable. The path now goes through the constant =sp-consult-snapfile-dir=.
- =which-key loaded before Elpaca activation=: the raw =(which-key-mode 1)= in =sp-keys= autoloaded the built-in package early. Removed; the existing =use-package which-key= enables the mode. The stray =(which-key-mode +1)= =:custom= entry is removed too.

*Audit (second commit)*

- All other third-party =use-package= forms without =:ensure= now have =:ensure t= (about 70). =inheritenv= used =:straight=, which this config does not use; =org-focus-hud= gets =(:host github :repo "SSD2019/org-focus-hud")=.
- Left alone: =tramp=, =pulse=, =org= (built-in), =exwm= (module not loaded), =excali= (local checkout), =citar-org-node= (=:vc=).
- Reordered so Elpaca does not queue a dependency first: =company= before =company-quickhelp=, =go-mode= before the Go helpers, =auctex= before =auctex-latexmk= and =company-auctex=.

Module docs in =docs/tangles/= are updated and their code blocks match the =.el= files. CHANGELOG: one entry in "Startup and module load order" (after #61), and a duplicated =Fixed= entry removed.

*Not tested* (no Emacs here): nothing was loaded or byte-compiled. =use-package= and Elpaca behaviour was read from their sources. I could not reach MELPA or GNU ELPA from the container, so I assumed the package names (for example =go-complete=, =dot-mode=, =pcomplete-extension=) exist there; an unknown name will show up as an Elpaca error on first start. Please start Emacs and check =*Messages*= and =M-x elpaca-log=.
