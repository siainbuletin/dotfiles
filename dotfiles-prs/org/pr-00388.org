**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- A heading titled =See also= (any case), with its subtree, is now a see-also section.
- Every =id:= link in it is a mention of that concept, in list items or plain text.
- Mentions have =:where= = =section= (weight 1.5, in =sp-see-also-where-weights=).

**** Scope
:PROPERTIES:
:CUSTOM_ID: scope
:END:
- The scope is the parent of the section: the nearest ancestor with an =:ID:=.
- At the bottom of the file (no ID'd ancestor) it belongs to the file.
- An =:ID:= on the =See also= heading itself is ignored.
- The open question above it counts, as for footnotes.

**** How
:PROPERTIES:
:CUSTOM_ID: how
:END:
- Reuses the footnote scanner: =sp-see-also-parse-buffer= gains an optional =SECTIONS= argument.
- =sp-see-also-mentions-in-buffer= (cache and index) passes it, so =sp-see-also-show=, =sp-see-also-show-concept=, and the widgets and =concept-usage= block show them.
- The sidenote renderer is unchanged: it calls the parser without =SECTIONS=.
- Links already read as footnotes inside a section, and links in source/comment blocks, are not counted twice or at all.
- Cache version 3, so files are re-read; editing a section re-reads only that file.
- Literate source =sp-see-also.org= updated and re-tangled (new section "See also" sections, weights, tests).

**** Tests
:PROPERTIES:
:CUSTOM_ID: tests
:END:
- 5 new ERT tests on fixtures; 25/25 pass in batch on Emacs 29.3.
- *Not run on the real vault* or in a GUI/vulpea-ui.
- Known limit: a heading in all capitals (=SEE ALSO=) is not matched (the existing title parser reads the first capital word as a keyword).
- Branch is not number-prefixed: the number was unknown before creating the PR and the rename API is blocked.
