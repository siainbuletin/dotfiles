**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Problem:* a PDF opened through the DT Open PDF applet gets its own DEVONthink window (#394), and AeroSpace did not tile it.
- *Cause (reasoned, not observed):*
  - The window belongs to DEVONthink, not to the applet (it is =LSUIElement=, no windows).
  - AeroSpace tiles only windows it detects as standard; DEVONthink's per-record windows can be detected as floating.
  - =aerospace.toml= had no =on-window-detected= rules.
- *Fix:* two rules run =layout tiling= for app ids =com.devon-technologies.think3= (DEVONthink 3) and =com.devon-technologies.think= (DEVONthink 4). The id that is not installed never matches.
- Edited the literate =aerospace.org= (new section "DEVONthink windows") and the tangled =aerospace.toml= together.
- *Limit:* if AeroSpace does not register the window at all, a rule cannot help; the checklist below tells how to see that.
- All DEVONthink windows tile, the main one too. No CHANGELOG edit (nightly tidy).
- Not run on the Mac: container has no AeroSpace.
