**** Causes
:PROPERTIES:
:CUSTOM_ID: causes
:END:
- *=(setf citar-cache--bibliography-buffers)= is void:* =sp-citations.el= loads before =citar= does. When Emacs loads a file it expands =setf= and =cl-pushnew= at once; the accessor was unknown, so the expansion became a call to a function named =(setf citar-cache--bibliography-buffers)=, which does not exist. Reproduced in batch with the same message; this hit every file.
- *No =citar-bibliography.eld=:* the file was written only at the end of a pass that finished. The pass died on the first file, and nothing wrote it at exit either.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- The slots =entries=, =props= and =buffers= are read with =cl-struct-slot-value= and set with =aset= at =cl-struct-slot-offset=, never with =setf= on the accessors (=sp-citations-preload--slot=, =--set-slot=).
- =sp-citations-preload--compatible-p= checks the variable, the three functions and the three slots before the first file. If they differ, the preload says so once in the echo area and stays off.
- The disk cache is written when the pass ends, when it stops on an error or =C-g=, and on =kill-emacs-hook=. Each time only if citar's entry tables differ from the last write, or the file does not exist, so a parse done by a =citar= call is saved at exit too.
- Docs updated as bullets; no CHANGELOG edit; no =when-let=.
