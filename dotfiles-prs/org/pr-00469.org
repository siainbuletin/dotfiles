**** Problem
:PROPERTIES:
:CUSTOM_ID: problem
:END:
- In the =vulpea-ui-view= frame the view window is dedicated, so =C-x b= stops with =Cannot switch buffers in a dedicated window= (Emacs =switch-to-buffer=, =switch-to-buffer-in-dedicated-window= is nil).
- Message taken from Emacs source; not reproduced in a GUI.

**** Reading implemented
:PROPERTIES:
:CUSTOM_ID: reading-implemented
:END:
- Sia wants to switch buffers from that frame (e.g. jump to another note) and have it work sensibly.
- New option =sp-vulpea-ui-view-switch-buffer-action=:
  - =other-window= (default): the chosen buffer opens in the notes window (=sp-vulpea-ui-view--editing-window=) and that frame gets the input focus. The view window stays dedicated and keeps following the current note.
  - =prompt=: Emacs asks whether to undedicate the view window, then switches in place (the view disappears from that window).
  - nil: Emacs's own error.
- An =:around= advice on =switch-to-buffer= acts only when the selected window is the dedicated view window; every other window is untouched. consult, tabspaces and =sp-tabs-switch-to-buffer= all end in =switch-to-buffer=, so they are covered, with the shared buffer list from #466.
- If the switch fails or is quit, the view window is selected again.
- With no notes window available, the original runs (so the Emacs error).
