*Before:* =docs/architecture/load-order-*.svg= were committed and re-rendered on every edit, so open PRs conflicted on them.

*After:*

- =docs/Makefile=: =make -C .config/emacs-modular/docs docs= extracts every =#+begin_src dot ... :file NAME.svg= block from the Org docs and runs =dot -Tsvg=, writing the SVG next to the =.org= file (so =[[file:...svg]]= links work locally). Needs Graphviz.
- The two SVGs are removed from git; =docs/**/*.svg= and =docs/.build/= are in =.gitignore=.
- =.github/workflows/docs-svg.yml=: on PRs it only checks every block renders; on push to =main= it force-pushes the SVGs to an orphan =docs-assets= branch (same relative paths). That is how the files "show up in the repo".
- ADR 0011 compares the options (artifact only, GitHub Pages, committing from CI, status quo) and picks the branch; CHANGELOG entry and a note in =load-order.org=.

*Open PRs (#54, #58, #72/#73):* once this merges, merging =main= into them will conflict only if they edit the SVG files. Resolve with =git rm= of both SVGs (keep the =dot= change in the =.org=); the SVG is then rebuilt by make.
