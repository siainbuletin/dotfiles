** Description
/Requested by *Sia*/

Caps Lock + number worked, but Caps Lock + Shift + key (move window / move to workspace) did not, and typed capital letters in a text field.

Cause: the layer key (Caps Lock remapped to F18) was an =hs.hotkey= bound with no modifiers. Hammerspoon matches those exactly, so with Shift already down F18 did not match, passed through to the app, and the Shift+key then typed a capital letter.

Fix (=hammerspoon/.config/hammerspoon/aerospace-keys.lua=): the layer is now an =hs.eventtap= that tracks F18 down/up whatever modifiers are held, swallows it, and looks the next key up with or without Shift (Cmd/Alt/Ctrl pass through). The same bindings are kept.

Only checked with =luac -p=; Hammerspoon is on your machine. To test after merging: =git -C ~/dotfiles pull=, Hammerspoon → Reload Config, then try Caps + Shift + h/l and Caps + Shift + 1, pressing Shift first and Caps first. If Shift-then-Caps still types capitals, the F18 remap itself is not applying: =hidutil property --get UserKeyMapping= should list it.
