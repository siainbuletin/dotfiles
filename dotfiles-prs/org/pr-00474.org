**** What and why
:PROPERTIES:
:CUSTOM_ID: what-and-why
:END:
Sia asked that =sp-litnotes-meta-fill= (single and =-fill-all-convert= batch) never deletes fields, only adds or modifies.

- Audited every path in =sp-litnotes-meta.el= that removes, empties or rewrites meta (fill, =--set=, =--put=, the unquote step, the type tag, the key sort, the bib-parent/pub-title lints, the =(none)= choice from #473).
- Found and fixed:
  - *Real loss:* with =sp-litnotes-meta-update-changed= (default t) a =pub-author=/=pub-editor= with more names than BibTeX (a co-author added by hand) was replaced by the BibTeX list, dropping the extra name. =--differs-p= now says "no difference" when the note has more names.
  - =--put= with nil/empty replaced a value by nothing. =--set= and =--put= now ignore blank values; only =sp-litnotes-meta--allow-clear=, bound by the /remove/ choice of =sp-litnotes-meta-parent-lint-convert= (a per-note choice with backup), empties a line.
  - =--set= added a new line right after the last item's first line, splitting a continuation line from its item; it now goes after the continuation lines.
- Checked, no change needed: empty and =(none)= answers (=bib-project=, =relevance-factor=, =read-priority=, =read-status=) give nil and leave the note alone; the key sort and the type tag only move or extend; =--tidy-new-note= (drops =#+print_bibliography=) runs only for newly created notes, not in a fill.
- *Safeguard:* before saving, =sp-litnotes-meta-fill= compares the note with its text from before (=sp-litnotes-meta--lost=). A fewer lines of a key, a value now empty, a non-blank line gone, or a filetag gone refuses the write, restores the buffer and signals =sp-litnotes-meta-lost-data=. In the batch that is one failed note in the results; the rest are still filled.
- The existing dry run (=sp-litnotes-meta-fill-all-dryrun=) already writes nothing; I did not add another one.
- Doc: bullets under "Design choices" in =docs/tangles/academic/sp-litnotes-meta.org=.
- No CHANGELOG edit (nightly tidy).
