**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- New option =sp-batch-report-save-and-kill= (default =t=) in =sp-batch-report=; set it to =nil= to get each command's old rule back.
- Three helpers, with no prompts and no messages (=inhibit-message=, =save-silently=, short answers, no kill query, no "changed on disk" question):
  - =sp-batch-report-flush-file FILE [BACKUP]=: saves an open buffer with unsaved changes (after =BACKUP= copied the disk text), reverts a stale unchanged one.
  - =sp-batch-report-close-file FILE=: saves, then kills the buffer.
  - =sp-batch-report-with-file FILE FN [BACKUP]=: flush, run in the buffer, close.
- Edge cases:
  - Unsaved changes are saved; the backup keeps the disk text first (the titles and meta backups now keep the first copy of a run instead of failing on a second one).
  - File changed on disk and edited in the buffer: the buffer wins.
  - The buffer you are in (current, or in the selected window, or bound in =sp-batch-report-keep-buffers=) is saved but not killed. The Works command of an author note binds it, since it runs from the note.
  - A buffer that cannot be saved is not killed; a failed kill is only written to =*Messages*=.
  - Files locked by another Emacs are still skipped by the titles command.
- Used by: author notes passes (=sp-author-notes--process-file=, =--populate=), =sp-litnotes-refs=, =sp-litnotes-titles=, and =sp-litnotes-meta= (status, parent lint, title lint, chapter tables).
- Not changed: =sp-bibprocess= (BibTeX files), =sp-see-also=, =sp-notes=, and the interactive single-note commands of =sp-litnotes-meta=.
- Note: =sp-batch-process= does not exist; the helpers live in =sp-batch-report=.
- Docs: =docs/tangles/funct/sp-batch-report.org= has a bullet section and a changes entry; the tangle check passes.
