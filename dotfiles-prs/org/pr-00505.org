**** What changed
:PROPERTIES:
:CUSTOM_ID: what-changed
:END:
New command =sp-bibtex-lint-fix-duplicates= (=C-; L b f u=): an entry with the same field twice is flagged first, and nothing is written until you apply.

- Duplicate = same field name in one entry (case-insensitive); values compared without outer braces/quotes and with white space collapsed.
- Identical copies: the report says so; the first copy is kept (safe).
- Differing values: the report lists them numbered; you pick the value to keep for each field, or choose "leave as it is" to keep every copy. A differing value is never dropped without your pick.
- Flow, like the other fixes: the command opens the report (=d=/=u=/=g=/=A=); =A= starts batches of =sp-bibtex-lint-batch-size=; each batch asks =a= apply (choose for each differing field), =i= identical copies only, =s= skip, =q= quit.
- The file is copied to =sp-bibtex-lint-backup-directory= before the first write (restore by copying it back); an entry changed since the lint is left alone and counted.
- Only the removed field lines change (the field with its comma, and its own line); the rest of the entry and its layout stay.
- =sp-bibtex-lint-dryrun= has a "Duplicate fields" section and a button; =sp-bibtex-lint-convert= lists "duplicate fields".
- Docs: section "Duplicate fields" in =sp-academic.org= (bullets); =L b f u= in =sp-keys.org=. No shims, =CHANGELOG.org= not edited.
