/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW22ykMMYap3WBMUhHviqhAoA][project thread]]/

Stacked on #20 (which is stacked on #19, #18 and #17). Merge in order and GitHub retargets each one.

*Before:* about thirty modules spelled out =~/notes=, =~/bibliography=, =~/Documents/literature=, =~/src= and the like, so the configuration only worked with one machine's layout and a test run could not be kept away from the real notes. =init.el= ended in a Custom block with a list of =/Users/siainbuletin/notes/...= agenda files, which made =org-agenda= open every one of them. The system modules sat in their own =env/= directory.

*After:*

- A new first module, =sp-paths=, names each location once (=sp-notes-dir=, =sp-documents-dir=, =sp-literature-dir=, =sp-bibliography-dir=, =sp-org-dir=, =sp-src-dir=, =sp-git-dir=, =sp-clones-dir=, =sp-data-home=, =sp-yadm-repo=, =sp-chrome-history-file=) and offers =sp-path= to build a path below one. The modules use these instead of literals. Each location can be overridden from the environment (=SP_NOTES_DIR=, =SP_BIBLIOGRAPHY_DIR=, =SP_DOCUMENTS_DIR=, =SP_ORG_DIR=, =SP_SRC_DIR=, =SP_GIT_DIR=, =SP_CLONES_DIR=, =XDG_DATA_HOME=). Defaults come from =~=, and the Chrome history path has a macOS, Windows and Linux default. This prepares for =sp-syswin= and the Linux module, which are not part of this PR.
- =env/= moves to =base/= (=sp-env=, =sp-exwm=, =sp-macos=, =sp-syslinux=, =sp-syswin=), in =libraries/modules/= and in =docs/tangles/=. The tangle paths, =docs/main.org= and =conditional-loading.org= follow. =sp-env= requires =sp-paths= and explains in its commentary that the =SP_*= overrides are read before the shell environment is imported.
- The whole Custom block at the end of =init.el= (=custom-set-variables= and =custom-set-faces=) is removed, so =sp-vulpea-para= decides which agenda files load. A copy of the removed block is kept outside the repo in case anything in it should come back.

*Behaviour notes:*

- On your Mac every path default resolves to what it was before.
- Removing the Custom block also drops what it set besides the agenda files: =sp-ui-default-font= (PT Mono 120), =sp-ui-variable-width-font= (Aporetic Serif Mono 120), =sia/modeline= (doom-modeline), =custom-safe-themes=, =package-selected-packages=, =package-vc-selected-packages= (lambda-themes), =helm-minibuffer-history-key=, =transient-show-menu=, =bibtex-aux-opt-alist= and the four =org-extra-emphasis= faces. Fonts, the modeline and the emphasis colours will fall back to defaults until they are set in a module. Without a =custom-file=, Customize writes a new block into =init.el= again.
- Left alone on purpose: =~/.config/...=, the legacy =~/.emacs.d= entries, =~/bin/mark.sh=, =~/opt/plantuml=, =~/.worktrees/= and plain =~/= starting directories.

*How:* the literate sources in =docs/tangles/= are edited together with the modules. In Emacs 29.3 batch, =sp-paths.org= tangles to =sp-paths.el= identically, and the moved docs tangle to their modules unchanged. =sp-paths= is added at the top of the Core section of both module lists in =init.el= and of the profiles in =sp-config-profiles.el=. I loaded =sp-paths= with and without =SP_NOTES_DIR= and checked that every changed file reads. I did not start the full configuration, so please try a launch on your Mac.
