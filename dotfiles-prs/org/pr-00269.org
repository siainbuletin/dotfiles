** Description
/Requested by *Sia*/

**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- =sp-ai= is no longer in the default module list in =init.el=, so none of the AI packages (gptel, claude-code, eca, agent-shell, efrit, monet, vulpea-mcp, org-mcp) load or install at startup.
- New command =M-x sp-ai-load= requires =sp-ai=, then calls =elpaca-wait= so Elpaca installs and activates what is missing before it returns. Calling it twice is harmless.
- =docs/tangles/media/sp-ai.org= now says the MCP servers start with =sp-ai-load=, including for the headless daemon.

**** Why
:PROPERTIES:
:CUSTOM_ID: why
:END:
In batch runs of the config, =sp-ai= was by far the slowest module (11--16 s of a 26 s init, 38 s in one run), mostly Elpaca work for its git-sourced packages.

**** Effect to be aware of
:PROPERTIES:
:CUSTOM_ID: effect-to-be-aware-of
:END:
The =vulpea-mcp= and =org-mcp= servers used for Claude's MCP access are no longer up at startup. They start after =sp-ai-load= (for a daemon: =emacsclient -s mcp -e '(sp-ai-load)'=).

**** Not tested
:PROPERTIES:
:CUSTOM_ID: not-tested
:END:
=init.el= was only checked for balanced parentheses (=check-parens= in batch). I have not run a GUI Emacs, so =sp-ai-load= has not been tried interactively.
