Design note =docs/architecture/global-keymap-namespaces.org=, modelled on Lambda Emacs' =lem-setup-keybindings.el=. No code or key changes.

- Audit of =sp-keys= and every other binding in =libraries/modules/=: four global collisions (=C-c s l=, =C-c s r=, =C-c m=, =<f6>=), a three-way one on =C-c f=, ten local shadows of global keys (Python and Org mostly), =C-x C-SPC= hiding =pop-global-mark=, and eleven commands in the leader tree with no definition in the repo.
- Caveats: leader key options, load order and Elpaca timing of =:bind=, terminal and macOS key limits, which-key labels, mode-local overrides, migration shims, and a three-layer test.
- Design: one =defvar-keymap= per feature module, mounted by =sp-keys= from one registry table; five steps, the first changing no key.
- README row and CHANGELOG line added.

Not run in Emacs (none in the container). Statements about Emacs defaults are marked "(memory)" in the doc and need one check in a real Emacs.
