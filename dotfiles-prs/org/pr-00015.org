** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2ApjJf3fNB4nmVud6MqNpBi][project thread]]/

*Before:* in the browser graph and the SVG export of =sp-vulpea-hierarchy=, a box showed only the title, cut off with an ellipsis when it was long, and the file tags of the note were not shown.

*After:* each box ends its title with the note's file tags, written =:tag1:tag2:= (muted in the browser), and the text wraps so all of it is visible. In the browser, boxes grow to fit their lines; in the SVG, labels wrap at =vulpea-hierarchy-wrap-width= characters (28 by default).

*How:* the page measures text on a canvas and wraps it into =tspan= lines, and the layout now uses per-box heights. The Emacs side sends =tags= with each node and builds wrapped, escaped Graphviz labels (=vulpea-hierarchy--wrap=, =--label=, =--dot-label=). The literate doc is regenerated and tangles back byte for byte to the =.el= and =.html=. Tested with mock notes: JSON data, a JavaScript syntax check, a headless Chromium screenshot with a long title and four tags, and =dot= accepting a label with quotes. Not run against the real vault database.

This is the first of four stacked PRs; the next ones branch from it.
