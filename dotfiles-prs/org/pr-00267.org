** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2NidJm7Tzd128tJp4sbpQtK][project thread]]/

=sp-ai= is out of the startup list in =init.el=. Its git-sourced packages (claude-code, efrit, vulpea-mcp, monet) made Elpaca block in =elpaca-wait=, and it was the slowest module at start (about 12 to 15 s).

New command =M-x sp-ai-load= (defined in =init.el=): loads =sp-terminal= (the =eat= backend that claude-code waits for), then =sp-ai=, then runs =elpaca-process-queues= so missing packages install. It logs to =*Messages*= through =sp-require-module=.

*Consequence:* the MCP servers (mcp-server-lib, vulpea-mcp, org-mcp) are down until =sp-ai-load= runs, so Claude's MCP calls through =emacs-mcp-stdio.sh= get no answer. A headless daemon that must serve them needs to run =sp-ai-load= after start.

Docs: =sp-ai.org= and =load-order.org= say so; CHANGELOG entry added. Not run in Emacs (none in the container); parentheses of =init.el= checked by script.
