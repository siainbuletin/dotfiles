**** Summary

- Sia's ask, read as: replace a PDF "if needed" (better or corrected copy of an article already filed) and refile it in DEVONthink.
- New flow in =sp-fetch-inbox=:
  - open the new copy from the inbox; press =C-c C-p= (=sp-fetch-inbox-replace=) and pick an existing key, or type that key
  - =C-c C-c=: when the key is in a =.bib= and =KEY.pdf= exists, filing becomes a replacement (before: error "already exists")
  - confirmation names the file, the backup folder and the key; nothing changes before yes
- Replacement:
  - old file copied to =sp-fetch-inbox-backup-dir= (default =~/Documents/literature/replaced/=) as =KEY-YYYYMMDD-HHMMSS.pdf=
  - new PDF overwrites =KEY.pdf=
  - existing =.bib= entry is kept: nothing appended, so citekey and litnote links stay
- DEVONthink:
  - record whose file is =KEY.pdf= (looked up by path) is kept, so UUID, tags, metadata and links stay and no duplicate appears
  - record of the new copy (inbox) is moved to the DEVONthink trash (restorable)
  - no record for =KEY.pdf=: new file is indexed, as usual
- Assumptions:
  - "refile" means keep the existing record and swap the file under it, not create a second record
  - undo = the backup copy plus the DEVONthink trash
  - highlights DEVONthink stored inside the old file are in the backup, not the new file
  - metadata sync is skipped (the entry is unchanged)
- Docs: =docs/tangles/academic/sp-fetch-inbox.org= ("Replacing a PDF", bullet lists); =tools/check-tangle.sh= shows only the expected tangle of this doc. =CHANGELOG.org= not edited.
