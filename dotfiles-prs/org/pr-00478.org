**** Cause of the slowdown
:PROPERTIES:
:CUSTOM_ID: cause-of-the-slowdown
:END:
- The DEVONthink listing script (#472) called =r.name()=, =r.path()=, =r.kind()=, =r.type()=, =r.additionDate()=, =r.creationDate()=, =r.uuid()= on every record: about 8 Apple Events per record, versus 4 before.
- Apple Events cost milliseconds each, so a big inbox with sub-groups adds up to seconds.
- Cause inferred from reading the code; not measured, because DEVONthink and Emacs cannot run in the cloud container.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- Listing script reads each field once per group for all children (=c.name()=, =c.additionDate()=, ...); still a single =osascript= call.
- =sp-fetch-inbox--merge= uses a hash table instead of =member= over a list.
- =sp-fetch-inbox-devonthink-depth= (default 8; 0 skips the sub-group walk).
- =sp-fetch-inbox-profile=: when non-nil, messages the time of each step (DEVONthink script, parse, folder scan, merge, arrange) in =*Messages*=.
- Sorting, =C-c s=, grouping and =C-c d= are unchanged; the items are still built once per command.
