Follows #89 (vendored themes).

*Before:* only third-party themes; the Modus mechanisms a palette cannot hold (headings, mixed fonts, variable-pitch UI) existed only for Ef/Modus; theme names and light/dark were known from a hand-kept list; the macOS appearance code lived in =sp-macos=.

*After:*

- New module =sp-theme-engine= (+ doc) and two themes in =libraries/themes/sp/=, =sp-dark= and =sp-light=, three lines each.
  - *Flavors* (=sp-theme-flavors=): 12 base colours per flavor, =catppuccin-set-color=-style (=sp-theme-set-color=, reloads). Dark is a simplified =ef-dream=; light uses the matching =ef-day= colours (my choice, with a teal cyan). These are the only hex codes.
  - The 26 Doric palette keys are *derived by blending*, and the faces come from =doric-themes-define-theme=, so Doric's bundles define about 1,300 faces.
  - *Semantic mappings* (=sp-theme-mappings=): Modus-style roles (=bg-region=, =fg-heading-1=, =err=, ...) -> palette keys, overridable per flavor (=sp-theme-set-mapping=); =sp-theme-mapped-faces= are written against roles.
  - *Semantic face names* (=sp-urgent=, =sp-crucial=, =sp-focus=, =sp-strong=, =sp-meek=, ...), per-flavor overridable.
  - *Ported Modus mechanisms:* =sp-theme-headings=, =sp-theme-mixed-fonts=, =sp-theme-variable-pitch-ui=. Bold and italic are Doric's bundles, so they have no option.
- =sp-themes=: *registry* reading every theme file the same way (name, background, description, package, family); the prompt is grouped by family and annotated from it. *=sp-theme-auto-mode=* is the one switch for light/dark (macOS setting, falling back to time of day via =sp-theme-day-hours=; also syncs new frames for daemons). =sp-macos= now only turns it on (its own detection and daemon hook are removed).
- Removed the colour-blind themes (4 Modus, 2 Ef) from the library.
- 19 ERT tests (=tests/sp-theme-engine-test.el=, =tests/sp-themes-test.el=).

*Checked* (Emacs 29.3; GUI-like checks in a 256-colour terminal): all 19 tests pass; all 75 themes load and the registry background matches the real background of every one; =sp-dark= and =sp-light= give the mapped colours, heading heights and merged attributes (e.g. =org-code= keeps its Doric colour and gains =fixed-pitch=); =set-color= and =set-mapping= reload; auto-mode with the time source switches and cleans up. *Not checked:* macOS (appearance hook, =defaults read=), a GUI, a full startup of the configuration.

*Notes for review:* the defaults still load =ef-dream= / =lambda-light-faded= for dark/light; set =sp-theme-appearance-themes= to =sp-dark= / =sp-light= to switch. =sp-dark= and =sp-light= are last in their families. Emacs keeps every =custom-theme-set-faces= call of a theme as its own record and enables the oldest, so the engine merges into and drops the older record (explained in the doc). The Modus engine file still contains the colour-blind palettes (vendored unchanged).
