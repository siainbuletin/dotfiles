**** What changed (stage 1)
:PROPERTIES:
:CUSTOM_ID: what-changed-stage-1
:END:
- New =sp-batch-report-view= (literate doc =docs/tangles/funct/sp-batch-report-view.org=): the default view, a =special-mode= buffer in the style of =vulpea-ui-schema-dashboard=.
  - Folding sections (=TAB=, =S-TAB=) with the count at the window edge (a =display= =:align-to=, so it stays aligned on resize).
  - One row per entry; file and Org links become labels; table sections have aligned columns; header line shows sections, entries, dropped.
  - Items can carry an =:action= (RET runs it).
  - No new package: =vui.el= re-renders a tree on every change, which is what made drop slow.
- =d= / =u= only restyle the rows with that key (text properties and one fixed-width count); the report is not made again, the buffer size does not change, =g= and =A= still get the dropped keys.
- =sp-batch-report-display= (=special= default, =org=): the Org buffer stays as =sp-batch-report-org-mode=.
  - Reports still built as Org text (BibTeX lint report, litnote titles/refs/meta, notes filing, property preview) open in it, with the keys of their own mode merged in.
  - =sp-batch-report-buffer-p= says whether a buffer is a report in either view.
- Every =sp-bibtex-lint-fix-*= command (=order=, =indent=, =prefixes=, =authors=, =files=, =crossref=, =keys=) now opens the shared report first: drop (=d=), restore (=u=), refresh (=g=), apply (=A=) and stop (=k=) work in all of them.
  - Dropped entries are kept per fix (=FILE::KEY#order=, ...); the author fixes keep their old shared key, so existing dropped lists still work.
  - =A= runs the previous flow (confirmation or batches, backup, one write) on what is left.
- Keys unchanged (=RET=, =n=/=p=, =d=, =u=, =A=, =g=, =b=, =D=, =k=, =q=, echo-area hints), plus =TAB=/=S-TAB=; =n=/=p= now move between entries.
