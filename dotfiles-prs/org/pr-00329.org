**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- New module =sp-collection-query-tables-book= (the =sp-collection-query-tables= family already exists, so this is a new part of it, not a new family): a table of the sections of a note tagged =book= or =collection=, sorted by page.
  - Sections are notes whose =bib-parent= links to the book. It is an ordinary query spec (=:parent-of= + =:parent-prop "bib-parent"= + =:sort-by :page=), so every renderer, saved views and dynamic blocks work with it.
  - =C-c w b= / =M-x sp-collec-query-book-open= opens it for the note at point (the book, or one of its sections); elsewhere it asks for a book.
- Two new columns in the core: =:pages= (text of =pub-pages=) and =:page= (its first number, used for sorting). Sections with no number (e.g. roman numerals) sort last.
- New =vulpea-ui= widget "Book position" (=sp-collection-query-tables-book-widget=, order 345): the book as a button, "Section N of M", previous/next buttons, and all sections in page order with the current one marked. It uses the same data function as the table (=sp-collec-query-book-position=). Registered like the Link inbox widgets, and loaded after =vulpea-ui=.
- Literate doc =sp-collection-query-tables.org= updated in bullets; the =.el= files tangled from it.

**** Page property: =pub-pages=
:PROPERTIES:
:CUSTOM_ID: page-property-pub-pages
:END:
I used the existing =pub-pages= meta key. The schemas in =sp-vulpea-schemas= already define it for =booksection=, =incollection= and =journalarticle=, so no new key is needed. Its value is text (=12-34=, =pp. 12-34=) and the table sorts on the first number in it. Say so if you would rather have a separate numeric key.
