**** Problem
:PROPERTIES:
:CUSTOM_ID: problem
:END:
- =sp-devonthink-insert-link= failed with =No DEVONthink record named arthur-2004-value-negat.pdf=.
- Cause: the single-record lookup searched =name:KEY.pdf= and required the record name to equal =KEY.pdf= exactly.
- DEVONthink often keeps the name without =.pdf=, so the lookup found nothing (the bulk refresh already handled this, the single lookup did not).
- The lookup was also AppleScript (=search ... in root of database=), the style that failed with -1728 elsewhere.

**** Change
:PROPERTIES:
:CUSTOM_ID: change
:END:
- =sp-reading--lookup-script= is now JXA: searches =name:KEY=, accepts a record whose name (without =.pdf=, any case) or file name on disk equals KEY.
- =sp-reading-uuid= falls back, on a miss, to one full =sp-reading-refresh= (path-based, as in #426) and looks again.
- Still returns nil for a key that is truly absent, so the error message stays.
- Doc: =sp-reading.org= (tangled to =sp-reading.el=); 3 new ERT tests, 3 existing ones updated.
