** Description
Follows #340. =typst compile= on the PDF from =gh-pr-pdf= failed on a pull request whose title contains =@key=:

#+begin_example
error: label `<key>` does not exist in the document
= PR \#190: ✨ Show the reference of @key links on hover
#+end_example

Typst reads =@name= in text as a reference, and the same happened on the matching commit line. The first version relied on =pandoc= escaping it, which it does in 3.1.3 (the version in the container, where I could not reproduce the error) but evidently not in the version used for the failing run.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- =gh-pr-pdf/.local/bin/gh-pr-pdf=: =@=, =$= and =<= in pull request text are swapped for placeholder characters before =pandoc= sees them and turned into =\u{40}=, =\u{24}= and =\u{3c}= in the Typst source afterwards. That form is valid in running text and inside string arguments such as link targets, so it does not depend on how a given =pandoc= version escapes. Fenced code blocks and inline code keep the real characters.
  - =$...$= is the same kind of clash (Typst math), and =<key>= in text is a label.
- Same file: the Markdown stage no longer reads =$...$= as math (=tex_math_dollars= off). Before, a plain =$HOME/$PATH= in a pull request body was rewritten to a math fragment, which was wrong in the org files too.
- Same file: the script warns with line numbers if an unescaped =@name= is still in the Typst source.
- =gh-pr-pdf/README.org=: the "Safety" section describes the escaping, and "Not run" now says what the failed first run was.

**** Not run
:PROPERTIES:
:CUSTOM_ID: not-run
:END:
=typst compile= (not installed in the container). Checked on made-up JSON modelled on the report: the =@key= title and commit line, =$HOME and $PATH=, =<key>=, an email address, =[cite:@key]=, a table, fenced code (including a nested four-backtick fence), inline code, link targets and a private-use character. The output has no leftover placeholders, the leak scanner finds no unescaped =@name=, and code stays literal. Six unit checks on the escaping function pass. To verify: run =gh-pr-pdf siainbuletin/dotfiles --skip-fetch= again and compile.

Unchanged and worth knowing: Markdown text like =<key>= (outside code) is still dropped, because GitHub's own renderer treats it as an HTML tag and the script removes raw HTML for safety. Put it in backticks and it is kept.
