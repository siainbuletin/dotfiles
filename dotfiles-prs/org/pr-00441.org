**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
- *Problem:* a chapter or section (=incollection=/=inbook= with =crossref=) has no DEVONthink record, so its keywords (what it is about) had no place in DEVONthink.
- *My reading of the request* (say if wrong):
  - The chapter's keywords are *not inherited from the parent and not merged into the parent's tags*.
  - They are stored *on the parent's record, scoped to the chapter*, in a block of the record's =comment=:
    #+begin_example
    -- sp-chapter: child-2001-x --
    keywords: value form, Money
    -- end sp-chapter --
    #+end_example

  - Text outside the block is left as it was; writing again replaces only that chapter's block; an empty list removes it.
  - The chapter's litnote shows them *at the bottom*, under =* Keywords in the book "Title" (parent-key)= (=collection= for a collection or proceedings, =book= for a book, =work= otherwise), with =:SP_CHAPTER_OF:= on the heading so re-running rewrites only its body.
- *Scoping is by text convention only:* only the Emacs code knows a block belongs to one chapter; DEVONthink does not. They do not appear in the tag browser or =tags:= searches (intended).
- *Open question (decided with Sia: comment only for now):* is a comment enough to find chapter keywords in DEVONthink? The "Discoverability" checklist below is there to answer that. Fallback if not: prefixed tags such as =ch:KEY/keyword= (noisier, and the book then carries every chapter's tags).
- *Source of the keywords:* the =keywords= field of the chapter's BibTeX entry (comma or semicolon separated, duplicates dropped). =C-u= lets you edit them first.
- *Commands* (=C-c k d=):
  - =C= =sp-devonthink-chapter-keywords-store=: writes the block to the parent's record. *Asks first*, naming the parent and saying its tags stay as they are.
  - =c= =sp-devonthink-chapter-keywords-show=: reads the block and puts the section at the bottom of the note. Never writes to DEVONthink; leaves the buffer unsaved.
  - An entry with a record of its own is refused (its keywords belong on that record).
- Why =comment=: it is a free text field that exists on every record, is visible in the inspector, and is not used by tags, the =litnote= field or the =#+devonthink:= keyword. A custom metadata field holds one value, so it could not be scoped per chapter without inventing a format inside it anyway.
- Docs: new "Chapter keywords" section in =docs/tangles/academic/sp-devonthink.org= (bullet lists), keys table, testing notes and the open question; =.el= re-tangled. Page-label logic and the offset code untouched.
- Tests: 40 ERT tests pass on Emacs 29.3 (10 new: block round trip keeping other text, key-prefix safety, asking first, refusing an entry with its own record, show is idempotent and writes nothing). Tangle check passes. =when-let*= style only. No CHANGELOG edit.
- *Not tested against DEVONthink.* The AppleScript (=comment of (get record with uuid …)= read and set) was not run; the Org/Emacs logic was tested with the record comment faked.
