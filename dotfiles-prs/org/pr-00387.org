- *Rename:* =sp-collection-query-tables*= becomes =sp-collection-query*= (files, features, doc, tests, requires). The =sp-collec-query-= symbols are unchanged. A views file saved under the old names is still read (the tracked file in =views/= is renamed too).
- *One insert command:* =sp-org-dblock-insert-template= (=C-c C-x t=) now lists every dynamic block, grouped like =sp-find-note= groups notes:
  - Group = the template's =:category= (stripped before insertion); =sp-org-dblock-category-order= puts Academic, then Collections, first.
  - Modules add templates via =sp-org-dblock-template-functions=; hand-written ones stay in =sp-org-dblock-templates=.
- *Views are templates:* new =sp-collection-query-templates= offers every view (including =reference-entries= and =encyclopedia-articles= from #386) as =collection-query-table :view NAME=. Built-in literature views are in /Academic/; any other view (e.g. one saved for albums) is in /Collections/. =sp-collec-query-view-categories= overrides by name. =sp-collec-query-insert-view-dblock= is now an obsolete alias.
- *=vulpea-collection= (from vulpea-ui):* =sp-org-dblock-disabled-names= (default =("vulpea-collection")=) removes it from =org-dynamic-blocks= (vulpea-ui registers it with =org-dynamic-block-define=), re-applied whenever a block is defined and after vulpea-ui loads. =vulpea-ui-collection-insert-dblock= refuses with a pointer to the one command. Blocks already in notes still update; collection buffers and the sidebar widget are untouched.
