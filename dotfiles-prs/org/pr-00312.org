**** Symptom
:PROPERTIES:
:CUSTOM_ID: symptom
:END:
Caps+Shift+; enters AeroSpace's service mode, but there is no way back out.

**** Likely cause
:PROPERTIES:
:CUSTOM_ID: likely-cause
:END:
The service-mode =esc= binding was =['reload-config', 'mode main']=. AeroSpace runs the commands of a binding in order and stops at the first one that fails, so if =reload-config= fails (or reports an error), =mode main= never runs and the mode is stuck. This is a diagnosis from the config, not a reproduced bug (no Mac here).

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- =aerospace.toml=: ~esc = ['mode main', 'reload-config']~ (leave first, then reload).
- =aerospace-keys.lua=: Caps Lock + Esc runs =aerospace mode main=, so there is a way out even when AeroSpace does not receive Esc. It uses the existing =bind= helper, so it works with the current hotkey layer and with the event-tap version in #310.
- =aerospace.org=: kept in sync (the TOML block, the =esc= note, the key list).
