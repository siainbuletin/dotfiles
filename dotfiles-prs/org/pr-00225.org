** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01BZHwSgnGAC4LTh4wgvYJsE?thread=cmsg_01BZHwSgnGAC4LTh4wgvYJsESgfFwDt41Q2LvPimo5EdKU][project thread]]/

Before: plugging the iPod into the Mac let Finder sync it straight away, which read and deleted =iPod_Control/iTunes/Play Counts=, so Legacy Scrobbler had nothing left to scrobble.

After: =~/.config/listening/ipod-no-autosync= turns that off and can undo it.

- =on= (default, safe to rerun) sets ~dontAutomaticallySyncIPods = true~ in =com.apple.AMPDevicesAgent= (Finder's device sync helper, 10.15+) and =com.apple.iTunes= (10.14 and earlier), then restarts =AMPDevicesAgent=. Earlier values are saved for =off=.
- =status= shows both settings, the agent, mounted iPods and whether =Play Counts= is still on them.
- =off= restores the values from before =on=.
- =backup= copies =Play Counts= + =iTunesDB= from every mounted iPod to =$XDG_DATA_HOME/listening/ipod-backups/=, skipping unchanged copies.
- =agent install|remove= adds a launchd agent (=StartOnMount=) that runs =backup= whenever a volume mounts.

The per-device Finder checkbox "Automatically sync when this iPod is connected" is not changed by the script; the docs and =on= output say to untick it once.

How: bash 3.2--compatible script in =.config/listening/=, a new section in =PLAN.org=, and a CHANGELOG entry. Stacked on #171 because =PLAN.org= only exists there.

Testing: run in a Linux container against stand-ins for =uname=, =defaults=, =pgrep=, =killall= and =/Volumes= (=IPOD_VOLUMES= override): on → on again (no-op) → backup ×2 (second skipped) → off restored the original =false= and removed the unset key. *Not run on a Mac*: whether current macOS still honours the =AMPDevicesAgent= key, whether Finder reads Play Counts on connect even without syncing (the backup agent is the fallback and may lose that race), and the launchd agent.
