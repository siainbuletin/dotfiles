**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
The query tables (=#+BEGIN: collection-query-table=, read from Vulpea's database) only changed when you ran =C-c C-x C-u=. New =sp-collec-query-dblock-auto-mode= does that step for you. It is *off by default*: turn it on with =(sp-collec-query-dblock-auto-mode 1)=.

- =open=: a moment after visiting an Org file that has a block (idle timer, so opening is not slowed).
- =save=: =sp-collec-query-dblock-delay= (2 s) after any Org note is saved, every open buffer with a block is updated (gives Vulpea's autosync time to read the file).
- Only the =collection-query-table= blocks (and the old =vulpea-table= name) are touched, never clock tables; buffers without a block are skipped by a text search.
- No loops: an unchanged result leaves the buffer unmodified (compared by buffer hash); nothing is saved unless =sp-collec-query-dblock-save= is set, and then only a buffer with no unsaved edits, and that save starts no new round.
- Also =M-x sp-collec-query-dblock-update-all= for a one-off.

Docs: new section "Keeping dynamic blocks up to date" in =docs/tangles/funct/sp-collection-query-tables.org=; the =.el= is tangled from it. CHANGELOG entry under Open pull requests.
