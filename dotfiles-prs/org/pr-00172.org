/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2SnxWxFd1BzigKY2tZa4GJe][project thread]]/

A query table can now be sorted by several columns, applied in the order they are set.

*How I read the request:* "sort a column based on multiple parameters, set in order" as a primary sort key plus tie-breakers (like a spreadsheet's multi-level sort), each with its own direction.

- =:sort-by= may be a list of columns: the first is the primary key, each next one breaks ties of those before it. An element may be =(COLUMN . asc)= or =(COLUMN . desc)=; plain columns use =:sort-desc=. A single column still works.
- The sort is stable, so ties keep the query order (before, descending reversed them too).
- Menu: =o= reads the columns in order (=rating,title:desc=); =O= is the default direction for columns without their own.
- vui: clicking a column makes it primary and keeps the earlier clicks as tie-breakers (the number after the arrow is the rank); a Reset button returns to the spec's sort.
- exc and Org renderers, the dynamic block and saved views take the list through the spec; the summary line says "sorted by ...". exc's own in-grid sorting is not touched.
- New =tests/sp-collection-query-tables-test.el= (core sort with stubbed Vulpea, passes on Emacs 29.3). Menu and vui were not run in Emacs.
- Literate doc and CHANGELOG updated. Based on main after #169.
