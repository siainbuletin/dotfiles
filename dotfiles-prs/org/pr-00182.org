** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2VaozMqv8TaGKJqSqW7rjFE][project thread]]/

*Before:* searching the tab inbox meant =sp-tab-inbox='s title mentions in the sidebar; no free-form or semantic query, and no way to file the results into a new note.

*After:* =C-c k t= (=sp-tab-psearch=) asks for a query and opens a p-search session over the inbox only, ranked by =org-semantic=. In the result buffer, =embark-act= collects the result at point (=c=) or the top N (=C=) into a note you pick or create.

**** Changes (new =sp-tab-psearch= module and doc, =init.el=, docs, CHANGELOG)
:PROPERTIES:
:CUSTOM_ID: changes-new-sp-tab-psearch-module-and-doc-initel-docs-changelog
:END:
- Candidate generator: each line of =sp-tab-inbox-dir= is a candidate (headings, keywords and drawers skipped), opened on its line.
- Semantic prior: query goes to =org-semantic= with a =dir:= predicate for the inbox, so nothing else in the notes appears. Hit order sets the score (0.9 down to 0.55), lines no hit contains get 0.3. =C-u= also adds p-search's word query.
- =sp-tab-psearch-engine= (=C-c k T=): same search as a p-search engine search box.
- Collect reuses =sp-tab-inbox-collect-all= (background move, link left behind, new note from a title).
- Loaded late, after =sp-semantic=. p-search is already installed by =sp-search= (use-package with Elpaca); this module installs nothing.

**** Choices to check
:PROPERTIES:
:CUSTOM_ID: choices-to-check
:END:
- *"Embark collect"* is read as an embark action on the result set (targets =sp-tab-idea= and =sp-tab-idea-results=), not an =embark-collect= buffer: p-search results are not completion candidates.
- org-semantic's grouping by note/section is not used (the unit is a line); only its ranking is.
- The semantic search blocks while the prior is calculated, and runs twice on start (p-search recalculates).
- Branch number 182 was the next free number when I pushed; check nobody else took it.
