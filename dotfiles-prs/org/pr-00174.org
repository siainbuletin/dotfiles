**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
Removes =sp-minibuffer= and its =minibuffer-setup-hook= line from =sp-fonts= (#161), which remapped =default= and set =text-scale= in the minibuffer buffer on every prompt and mirrored the minibuffer / glitched =M-x= in =vertico-posframe=.

The larger text now comes from one setting: =sp-posframe-update-font= turns =sp-minibuffer-face= (fontaine, 1.36 of =default= in =regular=) into =vertico-posframe-font=, a font spec with the =default= family at that size. It runs once at load and on =fontaine-set-preset-hook=; nothing runs per prompt. This is step 2 of the rebuild plan in the =sp-posframe= doc.

**** Trade-offs
:PROPERTIES:
:CUSTOM_ID: trade-offs
:END:
- The size no longer follows =text-scale-adjust= of the calling buffer.
- Prompts shown at the bottom of the frame (plain =read-string=, =y-or-n-p=) and the terminal fallback keep the =default= size.
- If the glitch returns, set =vertico-posframe-font= to nil first (one line to bisect).

Docs (=sp-fonts.org=, =sp-posframe.org=) and CHANGELOG updated. Not run in Emacs (none in the container); please check the posframe size with =M-x=.
