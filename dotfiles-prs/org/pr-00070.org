Follow-up to #67. Reasons are in ADRs 0011, 0012 and 0013.

- *Dashboard* (0011): =lem-dashboard= is no longer loaded. The agenda entries of =sp-splash= (the =Dashboard= buffer; there is no =sp-dashboard.el= on main, the rename PR #64 was closed unmerged) run views of =sp-agenda-views= through =sp-splash-agenda-commands=: PARA view, issue board, and a new =l= view of the coming deadlines. The per-agenda file variables are removed (thesis keeps its own). =sp-open-agenda-in-workspace= takes an optional view key.
- *org-ql* (0011): new =q= view with =org-ql-block= blocks (next actions without a date, waiting, done in the last 7 days).
- *org-super-agenda* (0012): no conflict with vulpea-para in mechanism, but global groups would split the PARA blocks. The mode is now on, groups are set per view, only on the Daily Agenda (=D=).
- *org-gtd* (0013): =org-gtd-keyword-mapping= removed (org-gtd's default equals the task sequence, which holds all keywords in one sequence as org-gtd requires). Processing the inbox with org-gtd is a proposal in the ADR, not implemented.

*Not verified*: nothing was run with the real packages; org-ql and org-super-agenda could not be installed in the container, and the org-gtd facts come from its GitHub source, not the installed version. After merging, check =M-x describe-variable org-gtd-keyword-mapping=, the =q= view and the =D= view.
