**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- New module =sp-batch-report= (doc =docs/tangles/funct/sp-batch-report.org=, tests =tests/sp-batch-report-test.el=):
  - =sp-batch-report-file-link=, =-file-links=, =-note-link= make Org links (=[[file:/abs/path][name]]=).
  - =sp-batch-report-mode=: a read-only Org buffer. =RET= visits the link, =n=/=p= move between links, =g= runs the command again, =q= closes.
  - =sp-batch-report-show= fills the buffer (optional refresh function and derived mode).
- Every file in these reports is now a link and the buffer is that mode:
  - =sp-litnotes-titles-dryrun= and the first half of =-convert=
  - =sp-litnotes-refs-dryrun= and the first half of =-convert=
  - =sp-litnotes-meta-fill-all-dryrun= and =-convert=
  - =sp-notes-filing-dryrun= (keeps =C-c C-c=)
  - the property and keyword conversion previews (=sp-vulpea-convert-*=)

**** How far =vulpea-doctor= was reused
:PROPERTIES:
:CUSTOM_ID: how-far-vulpea-doctor-was-reused
:END:
- It builds one string (title, sections, aligned lines, an Issues list) and shows it in a =special-mode= buffer. It has no links, no keys, no refresh and no per-item actions, and it is a function, not a library.
- So only its look was kept (title, sections, read-only buffer, =q=). Its =special-mode= buffer could not hold followable links, so the shared buffer is a read-only Org buffer.
- Left as they were, because they already have =RET= to visit a line: author notes report, footnote lint, tag lint, Org normalise, BibTeX lint, the litnote status table. =sp-author-notes-works-dryrun= is a one-line message.
