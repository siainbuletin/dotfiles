**** What I found
:PROPERTIES:
:CUSTOM_ID: what-i-found
:END:
- The inline view (=C-c o x=, filter =C-c o X=) already had =sp-agenda-views-inline-extra-dirs=, but the default was only =sp-writing-projects=, so litnotes were not scanned.
- The old hidden-folder check looked at the full path, so a folder under a hidden directory would have been skipped entirely.
- Org's search view opens every file it scans, so adding hundreds of litnotes unfiltered would be slow.
- The search view skips text before a file's first heading (confirmed in Emacs 29.3's =org-search-view=) and files with no heading. Litnotes can have text there.

**** What changed
:PROPERTIES:
:CUSTOM_ID: what-changed
:END:
- Default =sp-agenda-views-inline-extra-dirs= is now =sp-writing-projects= plus =litnotes/= in =sp-notes-dir= (folders or single files). The whole notes folder is not a default: it is large and mostly PARA files the agenda already lists.
- New =sp-agenda-views-inline-exclude-regexp=: skips hidden files and folders, lock and backup files, =archive/= and =backup/= folders, =.org_archive= files, matched against the path relative to each folder.
- Ripgrep prefilter: of the extra files, only those that hold a keyword (case-insensitive, whole words, same filter as the view) are searched; 400 files per call. Agenda files are always searched. Without ripgrep, or if it fails, every extra file is searched.
- The file list is built each time the view opens, so a new litnote shows without a restart.
- New =sp-agenda-views-inline-grep= (=g= in the =C-c o X= menu): lists every keyword line in a grep buffer, including text before a file's first heading; =RET= jumps to the line. Needs ripgrep.
- Filtered and unfiltered views both use the same file list.
- Docs as bullets in =sp-org-agenda.org=, re-tangled. =CHANGELOG.org= not edited.
