**** The load error
:PROPERTIES:
:CUSTOM_ID: the-load-error
:END:
=Cannot open load file ... sp-collection-query-tables-book= is not a code bug: =sp-collection-query-tables-book.el= (and the =-book-widget= file) are in =main=, but =~/.config/emacs-modular= is a tree of Stow links, and a file added by a pull has no link until you re-stow. Fix on your side, once after pulling:

#+begin_example
cd ~/dotfiles && stow -R emacs-modular
#+end_example

(this is in =stow-migration/README.org=). No code change is needed for it; the doc now says so.

**** What this PR changes: where saved views live
:PROPERTIES:
:CUSTOM_ID: what-this-pr-changes-where-saved-views-live
:END:
- =sp-collec-query-views-file= now defaults to =views/sp-collection-query-tables-views.el= *inside the configuration*, and that file is tracked in the repo (empty at first). After =stow -R emacs-modular= it is a link into =~/dotfiles=, so a view saved from the menu (=S=) or with =sp-collec-query-view-save-from-dblock= shows up in =git status= there, ready to commit. Nothing has to be copied or moved by hand.
- The older locations (below =sp-etc-dir=, and directly in the config) are still read until the new file holds a view; the next save writes the new file, carrying those views over.
- Built-in views stay in the code (=sp-collec-query-views-defaults=).
