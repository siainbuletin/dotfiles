**** Cause (reproduced on the Mac with the real citar 1.4.0, parsebib 6.7, Emacs 31.1, your 80 =.bib= files)
:PROPERTIES:
:CUSTOM_ID: cause-reproduced-on-the-mac-with-the-real-citar-140-parsebib-67-emacs-311-your-80-bib-files
:END:
- It is not a bad entry. The nil is the =format-string= slot of a bibliography that the preload took from =citar-bibliography.eld=.
- =sp-citations-preload--prime= fills =entries=, =props= and =buffers=; =format-string= and the pre-formatted candidates stay nil until =citar-cache--get-bibliography= runs for that file.
- =sp-citations-preload--read= calls =sp-citations--apply-layout= first. In a new session its state is empty, the layout counts as changed, and =sp-citations--repreformat= pre-formatted every bibliography in the cache, including the primed ones. =citar-format--parse= fails on a nil format string.
- The file in the message is only the first in hash order; any primed file would fail. The preload took it for "saved entries did not work", dropped that file and read it again, so the cost was one wasted parse and a misleading message.
- With an empty cache (first pass) or a second pass in the same session nothing is primed or the state is set, which is why the tests did not see it.

**** Changes

- From the first commit of this PR, kept for other errors: the backtrace of a preload error (=M-x sp-citations-preload-show-error=), a retry from the =.bib= when saved entries fail, and an error in one file no longer stops the other files.
