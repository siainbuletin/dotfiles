**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
An old Zotero export wrote names with a prefix as =biblatex= key=value text, e.g. ~family=Hayek given=Friedrich given=Friedrich ..., given=Friedrich A., prefix=von useprefix=false~. This adds a separate operation to =sp-bibtex-lint= that fixes them.

- New command =sp-bibtex-lint-fix-prefixes=, also in =sp-bibtex-lint-convert= (as "name prefixes") and as a button in the dry-run report. =sp-bibtex-lint-dryrun= now lists these entries (with links to the file lines) and counts them.
- Key=value names (~family=~, ~given=~, ~prefix=~, ~suffix=~, ~useprefix=~), also wrapped in braces and in any order:
  - become the lint's own form, =von Hayek, Friedrich A.= (the module standard is =Last, First=; the existing author fix would turn =Friedrich A. von Hayek= into that anyway)
  - repeated ~given=~ parts are merged; a part that fits a longer one (=Friedrich=, =F.= for =Friedrich A.=) is dropped and the fullest stays
  - =useprefix= is ignored, =suffix= goes in the middle (=Smith, Jr., John=)
  - names it cannot read (no ~family=~, two different families, given names that do not fit) are reported and left as they are
- Misplaced prefixes in names that already have a comma move in front of the last name: =Hayek, Friedrich A. von=, =Hayek von, Friedrich=, =Hayek, Friedrich A., von= give =von Hayek, Friedrich A.=; =de la= moves together. Only lower-case particles of =sp-bibtex-name-particles= move and one given name always stays (=Li, Bin= is untouched).
- Same pattern as the other fixes: backup before the first write, batches of =sp-bibtex-lint-batch-size= (50) with apply / skip / drop some / bring back / quit, and now =g= (apply this and all later batches, as in #368). =g= also works in step 1 of the author-name fix. Dropped entries stay out of a global run.
- Literate doc updated in =docs/tangles/academic/sp-academic.org= (bullet lists) and the =.el= tangled from it.
