**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- *Views as dblock templates:* a =collection-query-table= block takes =:view "name"=. Other keys in the block override the view's (e.g. =:parent-of=).
  - =sp-collec-query-insert-view-dblock= asks for a view and inserts such a block.
  - =sp-collec-query-view-save-from-dblock= registers a new view from the block at point, with no file editing. The menu's =S= already did the same for a spec. Both write the existing views file (=sp-collec-query-views-file=).
- *Built-in views* (=sp-collec-query-views-defaults=, in the repo; a saved view with the same name wins):
  - =book-sections=: notes linking to this note by =bib-parent=, by page, with a =Check= column.
  - =collection-articles=: same, plus =pub-year=, for a =collection=.
  - =bib-parent-mismatches=: every note in the vault that has a warning.
- *Flagging:* new =:check= column (=sp-collec-query-check=) and =:flagged t= spec key. Rules in =sp-collec-query-check-rules=: a =booksection= needs a =book= parent, an =incollection= a =collection= parent, and a note whose parent is a =book= (or =collection=) must be tagged =booksection= (or =incollection=).

**** Notes
:PROPERTIES:
:CUSTOM_ID: notes
:END:
- The views file lives under =sp-etc-dir= (not in the repo) as before. To commit your own templates, copy them into =sp-collec-query-views-defaults= or point =sp-collec-query-views-file= into the repo.
- =book-sections= and =collection-articles= differ only in their columns, because the parent's tag decides the check.
- The menu does not expose =:flagged= yet.
