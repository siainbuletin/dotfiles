**** What and why
:PROPERTIES:
:CUSTOM_ID: what-and-why
:END:
- A child BibTeX entry with ~crossref = {parent}~ now gets the fields it lacks from the parent, so =sp-litnotes-meta-fill= and the litnote autofill (pub-author / pub-editor / pub-title / pub-year) find =year=, =booktitle=, =publisher=, =editor=... in the child itself.
- It is a new =crossref= kind of =sp-bibtex-lint=, built on the same machinery as the other fixes.

**** Commands
:PROPERTIES:
:CUSTOM_ID: commands
:END:
- =M-x sp-bibtex-lint-crossref-entry=: the entry at point; lists what it would add and asks first; =C-u= is a dry run; one undo step.
- =M-x sp-bibtex-lint-crossref-dryrun=: report for the whole file; writes nothing.
- =M-x sp-bibtex-lint-fix-crossref=: whole file after one question and a backup, like =sp-bibtex-lint-fix-files=.
- The full =sp-bibtex-lint-dryrun= report has a section and a button; =sp-bibtex-lint-convert= has an entry.
- The buffer-wide commands are =sp-async-work= jobs: parents are indexed first in slices, and =M-x sp-batch-cancel= (#468) stops them; the report uses the echo-area hints of #470.
- No key binding was added (the leader keys are being redesigned); say if you want one.

**** Rules
:PROPERTIES:
:CUSTOM_ID: rules
:END:
- A field is added only when the child lacks it and the parent has it (non-empty); nothing is overwritten.
- =sp-bibtex-crossref-fields=: groups of equivalent names (=year=/=date=/=month=, =location=/=address=), plus =publisher series volume number edition isbn editor organization eventtitle venue=. A child with its own =year= or =date= gets no =month=.
- =sp-bibtex-crossref-renames=: type-aware renames, first rule wins:
  - mv* parent: =title= → =maintitle=, =subtitle= → =mainsubtitle=, =titleaddon= → =maintitleaddon=
  - =inbook= / =incollection= / =inproceedings= / =conference= / ...: =title= → =booktitle=, =subtitle= → =booksubtitle=, =titleaddon= → =booktitleaddon=
  - =inbook= / =bookinbook= / =suppbook=: =author= → =bookauthor=
  - =@periodical= parent, =@article= child: =title= → =journaltitle=, =subtitle= → =journalsubtitle=
- =pages=, =doi=, =url=, =file=, =keywords=, =abstract=, =note=, =author= and =title= are never copied under their own name.
- New fields are appended after the last field; =sp-bibtex-lint-fix-order= puts them in place. An entry laid out like =bibtex-mode= stays so.
- Documented, bullet-pointed, in =docs/tangles/academic/sp-academic.org= ("Fields from the crossref parent"); =sp-bibprocess.el= is tangled from it (=tools/check-tangle.sh= passes).

**** Not done / limits
:PROPERTIES:
:CUSTOM_ID: not-done--limits
:END:
- A parent's own parent is not followed (reported); a run does not see its own changes, so in a chain the second run passes the fields on.
- =xref= is not used (biblatex does not inherit from it).
- The default field list and renames follow my recollection of the biblatex manual's default inheritance setup; I could not open the manual from the cloud container, so please compare them with section 3.15.3 of the manual.
