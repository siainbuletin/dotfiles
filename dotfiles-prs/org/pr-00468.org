**** How the batch commands run
:PROPERTIES:
:CUSTOM_ID: how-the-batch-commands-run
:END:
- There is no =sp-batch-process=. The engine is =sp-async-work= (in-process timers); =sp-batch-report= is only the report buffer.
- =sp-author-notes= and the other litnote linters run as *timer slices inside the same Emacs* (50 ms per slice), not as a subprocess. That is why nothing shows in =proced=.
- Only the footnote lint starts a second Emacs (=make-process=).

**** Why C-g did not work
:PROPERTIES:
:CUSTOM_ID: why-c-g-did-not-work
:END:
- Emacs runs timer functions with =inhibit-quit= = =t= (checked on Emacs 29.3).
- A =C-g= during a slice only set a flag, acted on after the slice. Between slices it is a plain keypress.
- A quit also skipped the rescheduling, so the job stayed "running" with no timer (a zombie that blocked a rerun).

**** What changed
:PROPERTIES:
:CUSTOM_ID: what-changed
:END:
- A slice runs with =inhibit-quit= nil; a =C-g= in a slice stops the job cleanly.
- Two =C-g= in a row (outside the minibuffer) stop all jobs (=sp-async-work-quit-cancels=).
- =M-x sp-batch-cancel= (alias of =sp-async-work-cancel=) and =k= in the report buffer (header line and echo-area hints).
- Running jobs write =var/batch-jobs/ID.job= (key=value lines, at most once a second, removed at the end); stale files of dead Emacs processes are cleaned on listing.
- =M-x sp-batch-list-jobs=: jobs of all Emacs instances, =k= stops one (a cancel file for another Emacs, direct for this one).
- =tools/sp-batch-jobs [list | cancel ID|--all]=: plain =sh=, works from fish.
- Options considered (cancel file, =emacsclient=, =kill -USR2=, =kill=) are bullets in =docs/tangles/funct/sp-async-work.org=.
