Follow-up to #335 (backfill all children).

**** Problem
:PROPERTIES:
:CUSTOM_ID: problem
:END:
Notes made by =sp-litnotes-meta-backfill-all-children= came out with =#+title: Notes on <author>, <title>= and a =#+print_bibliography:= line. Both come from citar's own file-note template (=sp-citar-note=, "Notes on ..."), not from =citar-vulpea=, which only makes a title from =citar-vulpea-note-title-template=. So the backfill was using citar's file source.

=#+print_bibliography:= is the Org-cite marker that prints the bibliography of the works cited in that note. A litnote cites nothing, so it is not needed.

**** What changes
:PROPERTIES:
:CUSTOM_ID: what-changes
:END:
- The backfill makes each note with the =citar-vulpea= notes source when it is registered, whatever =citar-notes-source= is.
- Each new note is tidied afterwards: a =Notes on ...= title is replaced and =#+print_bibliography:= lines are removed. A title that does not start with "Notes on" is left alone.
- New option =sp-litnotes-meta-new-title=: =title= (default, the BibTeX title alone, as asked) or =standard= ("Last (Year) Title", what =sp-litnotes-titles-convert= writes).
- Literate doc updated; one new ERT test.

**** Testing
:PROPERTIES:
:CUSTOM_ID: testing
:END:
- =sp-litnotes-meta= ERT tests pass (14/14, Emacs 29.3, stubbed citar and Vulpea); =tools/check-tangle.sh= passes.
- Not run with the real citar-vulpea on the real vault. The cause (citar's file source being used) is inferred from the "Notes on" title and the citar-vulpea source code; the tidy step fixes the result either way.
