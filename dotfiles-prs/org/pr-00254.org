Replaces the plain rendering of heading tags in Org buffers with SVG chips from [[https://github.com/rougier/svg-tag-mode][svg-tag-mode]], driven by the existing tag groups.

- *Install*: =use-package= with Elpaca, =svg-lib= from MELPA and =svg-tag-mode= from =rougier/svg-tag-mode=.
- *Colour*: each chip uses =sp-org-tag-groups--chip-face=, so it takes the group colour from the theme-derived palette (#249); =unsorted= tags are neutral (#248). A theme change redraws the chips.
- *Emoji*: the tag's emoji is shown in front of the chip in =sp-org-tag-groups-select-emoji-face= (#247), the same as =sp-select-note=. =sp-org-svg-tags-show-emoji= turns it off.
- *How*: =svg-tag-mode= puts one display on one match, so there are three keywords: the tag name (chip), the colon before it (emoji) and the final colon (hidden). Matches outside the tags of a heading are ignored.
- *Toggle / fallback*: =M-x sp-org-svg-tags-global-mode=, default from =sp-org-svg-tags-enable=. In a terminal frame, or without SVG support, it stays off and the tags are plain text.
- *Interactions*: stays off if =org-modern-tag= is on (it is nil in =sp-org-appearance=); =org-indent= only sets a line prefix and =org-tags-column= is 0, so no alignment is needed.
- Edited the doc (=sp-org-tag-groups.org=) and re-tangled =sp-org-tag-groups.el=. That also brings in =sp-org-tag-groups--explicit-groups=, which the committed =.el= lacked (same fix as #252, so the two will merge cleanly).

Tests: 4 new ERT tests, 9/9 pass in Emacs 29.3 batch (=-L libraries/modules/funct -L libraries/modules/ui=); I also ran the real =svg-tag-mode= font-lock over a sample buffer with a stub for the image. *Not run in a graphic frame*, so how the chips look and whether the emoji sit well with the chip height has to be checked on the Mac.
