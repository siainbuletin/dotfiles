**** Likely cause (from reading the code; not confirmed on your Emacs)
:PROPERTIES:
:CUSTOM_ID: likely-cause-from-reading-the-code-not-confirmed-on-your-emacs
:END:
- =citar= keeps, with each file, the list of fields it parsed (=citar--fields-to-parse=) and reads the file again when the list differs.
- The list comes from the templates, and =sp-citations--layout-templates= only adds =${tags keywords:N}= when the room is 110 columns or more. So the list depended on the width of the frame.
- The preload ran at one width and the first call at another (the posframe takes a fraction of the frame), so the cache was thrown away.
- Other possible causes (preload not finished yet, not in the cache) are not excluded: see =sp-citations-preload-explain= below.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- =sp-citations--stable-fields=, a filter on =citar--fields-to-parse=: sorts the list and always has =tags= and =keywords= in it, so it is the same at any width.
- =M-x sp-citations-preload-explain=: for each file, says whether it is in the cache, tied to =global=, has the same fields and size, and whether the preload is still waiting. If it still reads a file again, run it before =citar-open= and send me the text.
- The end of a pass says =citar preload: N bibliography file(s) ready= in =*Messages*=.
- The disk cache from before this change has the old fields, so each file is parsed once more after updating.
- Docs as bullets; no CHANGELOG edit; no =when-let=.
