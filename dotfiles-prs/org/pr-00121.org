** Description
/Requested by *Sia*/

*Reported:* the text in the =M-x= mini-frame blends into the background and shows only where highlighted; and =ESC= / =C-g= in it blocks everything.

*Likely cause of the invisible text (not confirmed):* since #115 =M-x= takes the colours =mini-frame= computes from the /frame parameters/ of the parent frame. After a theme is loaded later (=sp-load-theme=) those parameters still hold the first frame's colours, while the text is drawn with the theme's =default= face. Result: a background computed from the old colours with the new text colour on it.

*Change:* =sp-mini-frame--colors= reads the text colour and the background from the =default= face of the selected frame; the background is the text colour mixed in by =sp-mini-frame-contrast= (0.08, as before #115). Both are passed as frame parameters. The =M-x= prompt block uses =:inverse-video= and no colour lookup. The prompt styling hook now reports an error in the echo area instead of aborting the prompt.

*Not fixed, not understood yet:* =ESC= / =C-g= blocking everything. I could not find a cause in the code; it might be input focus not returning to the main frame after the child frame is hidden, or =mini-frame-resize t= (from #119) during the exit. I have asked for details in the thread.

*Not tested:* nothing was run in Emacs.
