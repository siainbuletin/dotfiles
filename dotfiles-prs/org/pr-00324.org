**** Why
:PROPERTIES:
:CUSTOM_ID: why
:END:
The =literature= database (about 65 GB) is too big for the iPad and for the NAS's WebDAV sync store, which has about 20 GB on the SSD. So =literature= stays on the Mac, searchable from DEVONthink and Emacs, and a small =reading= database syncs instead. A rule fills it, so you don't sort anything by hand.

**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
=tools/devonthink-reading.py= has two actions. Both are dry runs unless you pass =--apply=.

- =create= makes =~/Databases/reading.dtBase2= with one group per selected =.bib= file. If the file exists but is closed, it opens it instead.
- =send= moves a PDF into =reading= when its litnote's =read-status= is one of the chosen values (default =to-be-read=) and its citekey is in one of the chosen =.bib= files (default: all of them). It refuses to go over the budget (default 20 GB). With =--return=, it moves records that no longer match back to their old group, which it remembers in =~/.local/state/devonthink-reading/origins.json=.
- You can change the rule as you go: =--status= and =--bib= (both repeatable), or =~/.config/devonthink-reading/config.json=. =--json= prints the plan as JSON for a later Emacs command.
- The rule matches on the citekey: =ROAM_REFS= or =#+reference:= in the litnote, the =.bib= entry key, and the PDF file name =KEY.pdf=.
- The script and its tests are literate: they tangle from =docs/tangles/academic/devonthink-reading.org=, which also has the usage, the settings, how the rule decides, and what is untested. Edit the =.org= and tangle it (=C-c C-v t=); =tools/tangle-all.el= and the =tangle= CI check only cover =sp-*.org= module docs, so they don't check this one.
- Also summarised in =docs/architecture/devonthink-emacs-integration.org=, section "The =reading= database".

**** Tested
:PROPERTIES:
:CUSTOM_ID: tested
:END:
- =python3 -m unittest tests/test_devonthink_reading.py=: 11 tests pass. They cover parsing, the rule, the budget, =--return=, dry run against =--apply=, and remembering where each record came from, with DEVONthink faked.
- *Not run on the Mac.* The DEVONthink calls are untested, and so is the question of whether moving an indexed record between databases leaves its PDF in =~/Documents/literature/=. Try =create=, then =send --apply --limit 1=, and check the record and the file.
