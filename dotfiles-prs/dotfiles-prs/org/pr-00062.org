/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2HrSnCzQDTcWT2ugso36vjb][project thread]]/

Stacked on #59 (it rewrites the header of =sp-org-lint=); retarget to =main= after #59 merges.

*Before:* notes written with Org's default behaviour end in a =Footnotes= heading, but this setup keeps each definition at the end of the text of the heading that cites it (=org-footnote-section= is nil; =sp-vulpea-split= copies definitions per heading).

*After:* =M-x sp-org-lint-footnotes= in =sp-org-lint= (docs: =docs/tangles/funct/sp-org-lint.org=, "Sectional footnotes").

- *Async:* the files of the vulpea database are read by a second headless Emacs (=make-process=), one at a time; a report buffer fills in as results arrive. Emacs stays usable.
- *Preview first:* the scan changes nothing. =a= in the report applies, after a yes/no question.
- *What moves:* each definition in a =Footnotes= heading goes to the end of the own text of the heading that contains its reference (same section meaning as =sp-split--fn-section=). Cited from several sections: every section gets a copy, later ones with a suffixed label (=smith-2=), as in =sp-vulpea-split=. An emptied =Footnotes= heading is removed; one with other content stays.
- *Reported, never deleted:* orphan definitions, dangling references, and conflicts (label defined twice, cited from the footnotes heading itself, cited only from another footnote).
- *Safety:* every file is copied to =sp-org-lint-fn-backup-directory= (per-run folder) before being written; a file that changed since the preview, is open with unsaved edits, has CRLFs, or fails the post-check (reference count, dangling set and definition count) is skipped. Written via temp file and rename. Open unmodified buffers are reverted and vulpea is asked to re-read the files when idle.
- =C-u= asks for a folder instead of using the vulpea database. No external packages.

*Checked* (headless Emacs 29.3, container only, fake vault in a temp directory): 11 ERT tests in =tests/sp-org-lint-test.el= (tangled from the doc), including a real run of the worker process: scan, apply, backup content, and a file changed after the preview. A 300-file fake vault scans in about 2 s in the worker. The =.el= byte-compiles without warnings.

*Not checked:* a real Emacs session with the report buffer on screen, the vulpea database query (=vulpea-db-query=; not loaded here, the folder fallback was used), macOS, TRAMP, and the real vault. Run the preview on the vault and read it before pressing =a=.
