**** Summary

:CUSTOM_ID: summary

Fixes =Error running timer 'vulpea-ui--run-scheduled-sync': (wrong-type-argument vulpea-note nil)=.

The sidebar sync renders the backlinks widget, which calls =vulpea-ui-backlinks-note-filter= with the note of each linking file. That note is nil when the file is not in the vulpea database yet (new, unsynced or untracked file, as happens around the =sp-org-tag-= commands that open or create files). Our filter called =vulpea-note-tags= on it. It now keeps such files.

Changed in the org source (=docs/tangles/vulpea/sp-vulpea.org=) and the tangled =sp-vulpea-ui.el= identically, plus a CHANGELOG entry.

**** Testing
:PROPERTIES:
:CUSTOM_ID: testing
:END:
Not run: no Emacs in the container, and the filter is an inline =use-package= option, so no ERT test. The cause was read from the installed vulpea-ui source (=vulpea-ui--backlinks= calls the filter with =file-note=, which can be nil).
