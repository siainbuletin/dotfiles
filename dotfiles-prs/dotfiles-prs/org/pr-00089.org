Follows the design note merged in #80.

*Before:* themes came from Elpaca packages (modus, ef, doric, lambda, catppuccin); =sp-load-theme= disabled every theme and reset the mode line /before/ asking, so quitting the prompt left the bright default theme; several modules loaded themes on their own.

*After:*

- =libraries/themes/=: =lib/= (engines on =load-path=), =active/= (the 7 themes in use: =ef-dream=, =ef-day=, =ef-melissa-light=, =lambda-light=, =lambda-light-faded=, =lambda-dark-faded=, =doric-fire=), =library/= (the other 72, one folder per package, for trying out), =sp/= (own themes, empty). README with upstream commits. No Elpaca for themes; =easy-theme-preview= stays. No LICENSE added.
- =sp-themes=: four families in =sp-theme-families= (hard light, faded light, faded dark, hard dark). =sp-load-theme= is the single entry: grouped prompt (families first, then =library=), no confirmation (=custom-safe-themes= set in code plus =load-theme= advice, nothing for =custom.el=), applies optional =sp-theme-palette-overrides= (Ef/Modus only), then disables the previous themes only /after/ the new one loaded (=sp-theme-disable-others=, nil = stack). =T= loads a family. =sp-theme-appearance-themes= / =sp-theme-load-appearance= replace the hard-coded themes in =sp-macos= and the toggle; =sp-theme-dark-p= replaces the =lambda-dark= check in =sp-dashboard=.
- Removed: =lem-dashboard.el= and its doc, =libraries/sp-archived-configs.el= (last commit linked in =sp-helper-funct.org=), =sp-disable-all-themes=, dead Modus options (=-prompts=, =-completions=, =-org-blocks=, =-disable-other-themes=) and duplicates.
- New =docs/architecture/modus-faces-outside-global-system.org=: Modus mechanisms and the 1,237 faces a Doric-style global face system would not cover.

*Checked* (Emacs 29.3 in a 256-colour terminal): all 7 themes and all 72 library themes load, exactly one enabled after each =sp-load-theme=; family lookup and =sp-theme-dark-p= right for all 7; override applied (=ef-day= cursor); toggle switches light/dark. The three edited modules were tangled from their docs. *Not checked:* macOS appearance hook, GUI, a full startup of the whole configuration.

*Decisions for review:* =ef-dream= is the only =hard-dark= theme and =doric-fire= sits in =faded-dark= (near-identical backgrounds, edit =sp-theme-families=). I read "remove the disabling step" as "never disable before loading"; set =sp-theme-disable-others= to nil to stack as literally asked, but faces then mix. The old =ADR 0011= still says =lem-dashboard='s module stays; left as history. =sp-kill-and-archive-region= still writes to its own file in =sp-setup-dir=.
