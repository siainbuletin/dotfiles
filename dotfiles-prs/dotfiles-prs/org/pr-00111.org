** Description
/Requested by *Sia*/

*Problem:* in Sia's Emacs the box titles and entries could not be walked: =keycast-log-mode= showed =TAB= and =<right>= running =sp-dashboard-next-button= and =sp-dashboard-enter-box=, but nothing moved.

*Likely cause (not reproduced):* =sp-dashboard-refresh= was on =window-state-change-hook= and =window-configuration-change-hook=, and it kills and redraws the Dashboard every time they run. Those hooks also run for reasons other than a resize (a key logger, the mode line, a message). A redraw puts point back on the first title and out of any box, so each key press is undone at once.

*Change:*

- The hooks now call =sp-dashboard--refresh-on-resize=, which redraws only when the pixel size of the window or the font differs from the last draw (=sp-dashboard--drawn-geometry=, set when the mode starts). =sp-dashboard-refresh= itself is unchanged for the other callers (=g=, art moves, privacy changes).
- The width of the larger box titles is read with =window-font-width= instead of =string-pixel-width=, so nothing is measured in a temporary buffer on each draw.
- Doc and CHANGELOG updated.

*Checked:* Emacs 29.3 headless: running both window hooks after TAB and =<right>= keeps point and the box; a real resize still redraws. Graphical Emacs 29.3 on a virtual display with a window manager and real Tab, S-Tab, Right and Left key presses (xdotool), through the real startup hooks and =sp-set-window-margins=: everything works, titles stay aligned. *Not checked:* Sia's Emacs (31, Mac), real nerd-icons, keycast. I could not reproduce the failure here, so this may not be the whole cause.
