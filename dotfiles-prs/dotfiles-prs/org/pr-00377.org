**** Cause
:PROPERTIES:
:CUSTOM_ID: cause
:END:
- The message =None of the files for 'KEY' exist; check 'citar-library-paths'...= comes from =citar-file--parse-file-field= (it is a =message=, not a raised error). The =file= field points to =~/Documents/literature/KEY.pdf=, but the PDF is somewhere else below the library (e.g. =inbox/mac-bibdesk/=), so citar finds nothing and the table's PDF column and =citar-open= come up empty.

**** Changes
:PROPERTIES:
:CUSTOM_ID: changes
:END:
- New parser =sp-citations-parser-library=, added to =citar-file-parser-functions= (in the =citar= =:config=):
  - for each name in the =file= field that does not exist (absolute, or relative to =sp-literature-dir=), it looks for a file of the same name below =sp-literature-dir= (case and accent insensitive);
  - names that exist are left to citar's own parsers.
- Index of =sp-literature-dir= is built on first use and rebuilt (at most every =sp-citations-library-index-ttl= = 60 s) when a name is not found. Hidden folders and the backup folder are skipped.
- This replaces my first attempt (a try/catch fallback in the query tables), which is reverted. =citar-open=, =citar-get-files= and the =:pdf= column now all find the same files.
- Doc: =sp-academic.org= (sp-citations section).

**** Not verified
:PROPERTIES:
:CUSTOM_ID: not-verified
:END:
- Tried the parser alone in Emacs 29 with citar's default parser stubbed (finds =inbox/mac/Foo-2001.pdf= for =~/Documents/literature/foo-2001.pdf=; ignores existing and truly missing names); the tangle check passes. Not run with real citar or on the vault.
- Does not fix the paths in the =.bib= files; =sp-bibtex-lint-fix-files= (#372) does.
