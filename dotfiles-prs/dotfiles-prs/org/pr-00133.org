**** Problem
:PROPERTIES:
:CUSTOM_ID: problem
:END:
At launch a =*scratch*= window opens beside the Dashboard instead of the Dashboard alone.

**** Likely cause
:PROPERTIES:
:CUSTOM_ID: likely-cause
:END:
Since 8e1917b (Oct 23) =tabspaces-mode= starts after init with =tabspaces-session-auto-restore=. On startup it restores the window layout saved at the last exit (=window-state-put=). =sp-dashboard--setup-splash-hooks= runs later, on =window-setup-hook=, and only replaces the buffer of the selected window, so any restored second window (here =*scratch*=) stays. The layout is saved again at every exit, so it keeps coming back. Nothing in the PRs #114-#131 touches this (quick-capture #131 is not merged).

**** Fix
:PROPERTIES:
:CUSTOM_ID: fix
:END:
=sp-dashboard--setup-splash-hooks= calls =delete-other-windows= before drawing the Dashboard. It runs once at start-up only, not on refresh. Doc and CHANGELOG updated.

**** Not verified
:PROPERTIES:
:CUSTOM_ID: not-verified
:END:
Not run in Emacs (none in the sandbox); the cause is from reading the config and the upstream =tabspaces= source. Please check in a fresh Emacs. If =*scratch*= still appears, =M-: (window-list)= right after launch and the contents of =var/tabspaces-session.eld= would show who creates it. Under =emacs --daemon= tabspaces defers the restore to the first client frame, which runs after this hook, so a daemon setup could still show the split.
