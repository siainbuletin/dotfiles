Sia reports that the svg-tag-mode integration of #254 blocks Emacs init and overflows memory. This removes it so startup is unblocked first:

- Removes the "SVG tags in the org buffer" section from =sp-org-tag-groups.org=, re-tangles =sp-org-tag-groups.el= (nothing left of =sp-org-svg-tags-*=), drops the 4 tests and moves the CHANGELOG line to a removal entry.
- =sp-org-tag-groups= returns to the pre-#254 version, so the tag colours, emoji and the =--explicit-groups= fix stay. =sp-faces.el= is untouched.

*Cause is not confirmed* (no graphic Emacs here). Likely suspect: =sp-faces.el= already declares =svg-tag-mode= with =use-package= (=:hook prog-mode=, a global =svg-tag-tags=), and #254 declared and enabled it a second time from a late module, with a global mode and a buffer-local =svg-tag-tags=. The next attempt will be stock =svg-tag-mode= only, reusing the =sp-faces= declaration, off by default, with no coupling to the tag groups or emoji and no decoration of file-header tags or TODO keywords.

Tests: the 5 remaining ERT tests of the module pass in Emacs 29.3 batch.
