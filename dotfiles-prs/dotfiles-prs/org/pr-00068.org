/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2XXKDQ5Dp5crxRdWfcttAXb][project thread]]/

New module =sp-merge-pick= (=libraries/modules/prog/=, doc in =docs/tangles/prog/sp-merge-pick.org=, which tangles to the module byte for byte).

*Flow*

1. =C-x C-SPC g m= opens a graph log of all branches (unicode lane glyphs, Magit's colours). In the yadm repo start from =M-x yadm=.
2. =C-c v i= marks the commit at point as INTO, =C-c v f= another as FROM. Both lines are highlighted and labelled.
3. =C-c v p= previews the merge in memory with =git merge-tree --write-tree= and lists conflicting files; =RET= on one opens a three-way Ediff (INTO, FROM, merge base). =C-c v d= shows what FROM adds, =C-c v e= picks any file for the same Ediff.
4. =C-c v n= starts a =--no-commit= merge (after asking, and after offering to check out INTO's branch if the worktree is clean). Then resolve with Magit =e=, Smerge or =M=, commit with =c c=, or abort with =m a=.

Only step 4 changes the worktree. Nothing commits.

*Wiring*: module added to the late list in =init.el=; =sp-keys= autoloads =sp-merge-pick-log= on =m= in =lem+vc-keys= (code and doc); =load-order.org= lists the module; CHANGELOG set "Reviewing merges in Magit".

*Tested* in headless Emacs 29.3 with Magit from Oct 2026 on a small repo with a conflict: log buffer, marks and overlays, glyph display properties, the preview and conflict list, the file buffers handed to Ediff (Ediff call stubbed), the no-commit merge including checking out INTO's branch, and the byte-compile (clean).

*Not tested*: the Ediff session itself, colours and glyph widths in a real GUI or TTY, =C-c v= on the yadm repo, git older than 2.38 (the preview needs it). =docs/load-order-modules.svg= is not redrawn.
