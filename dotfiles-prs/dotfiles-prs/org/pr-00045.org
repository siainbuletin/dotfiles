Before: one lambda layer with offsets =sp-splash-art-x-offset= (-12) and =sp-splash-art-y-offset=, centred on the menu; the buffer was =*splash*=.

After:

- The lambda is centred vertically in the window (y 0) with x -50, measured from the window centre.
- A second layer draws the EMACS block-letter banner (banner 3 of the =dashboard= package), 30 columns right of centre and 8 lines above it, so it doesn't cross the lambda in a wide window.
- Both art files are local plain files in =libraries/images/= (=lambda-splash.txt=, =dashboard-banner-3.txt=, a copy of the package's banner so it can be edited); nothing is read from the =dashboard= package. =sp-splash-art-directory= sets the folder, and the terminal splash reads the lambda from there too.
- The title, version line and the menu are centred under the banner and start two lines below it (=sp-splash-content-layer=), so they follow the banner when it is moved.
- Layers live in =sp-splash-art-layers=, =(NAME :file F :x X :y Y :face FACE)=, topmost first. Remove one to hide it. =S-<arrow>= moves the current layer, =TAB= picks the next, =0= resets, =s= copies the =setq= form. This replaces the two offset options from #31/#44.
- The buffer is now =Dashboard=; =sp-workspaces.el= (Home tab) follows the new name.
- Docs: =sp-splash.org= "Art layers" section rewritten and =sp-workspaces.org= updated; both tangle to the same text as the =.el=. CHANGELOG entry added.

Merged with current =main=: Sia's direct edit there (x -50, y 10 on the old two-offset options) is superseded by the layers, so the lambda layer keeps y 0 as asked.

Checked in headless Emacs 29.3 (200x50 frame, =nerd-icons-faicon= stubbed): both layers drew behind the text from =libraries/images/=, the menu sat under the banner, =TAB=/=S-<right>= moved a layer, the setq form printed correctly.
