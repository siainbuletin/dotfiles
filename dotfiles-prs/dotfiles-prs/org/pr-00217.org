**** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
First piece of integrating =sp-search= / =consult-omni= with =sp-trails=: a new module =sp-trails-search= (with literate doc).

- =sp-trails-search= (=o= in =sp-trails-map=, =j= in the =C-c s m= menu) asks which consult-omni search to run (web and notes, web, scholarly, my notes), starts/resumes a trail if none is current, and runs it.
- =RET= on a result still opens it in the external browser, and also adds it to the trail as a =TOREAD= page (query, source, DOI, authors kept as properties). Nothing is recorded while only browsing results.
- The page hangs under the trail page at point, else under the trail. The browser extension later reports the same URL, which =sp-trails-add-page= dedupes, and links followed from it become its children.
- Embark action =t= records a result without opening it.
- Done by advising =consult-omni--get-source-prop= for =:on-callback= only while a trail search runs, so no vendored code is patched.

Not in this PR (listed in the doc): ripgrep results as trail nodes, linking saved views to trail nodes, recording note results.
