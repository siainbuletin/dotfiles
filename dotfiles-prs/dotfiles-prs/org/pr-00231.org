**** Summary

:CUSTOM_ID: summary
:END:
New "Linting the .bib files" section in =sp-bibprocess= (doc =sp-academic.org=, tangled to =sp-bibprocess.el=). Independent of #230.

- =M-x sp-bibtex-lint-report= (=C-c w b l=): dry run over =sp-bibtex-files=. Reports =author=/=editor= names not in the canonical =Last, First= form, fields out of the order of =sp-bibtex-field-order=, duplicate keys, entries it cannot read, and names one typo (≤2 edits) away from an existing author note.
- =M-x sp-bibtex-lint-apply= (=C-c w b L=): asks once, copies each file to =sp-bibtex-lint-backup-directory=, rewrites names and field order. Duplicates and typo hints are not changed. An entry with a =%= comment inside is never rewritten (it is reported).
- =sp-bibtex-author-capf= in =bibtex-mode=: completes names in =author=/=editor= from the author notes, in =Last, First=.
- *No author note is ever created*; the vault is only read. A name with no note is not reported.
- Runs in slices through =sp-async-work= (100 entries per slice).

**** Decisions for you

:CUSTOM_ID: decisions-for-you

- Default =sp-bibtex-field-order= is my guess (author, editor, title ... year, doi, url, file, keywords, abstract, note); please adjust.
- A rewritten entry is regenerated as =@type{key,= with fields aligned at ~=~; values keep their text and delimiters.
