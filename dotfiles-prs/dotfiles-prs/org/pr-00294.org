**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
CUA is gone on every system, and the Emacs defaults for the same jobs are unbound, so there is one layer of keys.

- *Mac (Command = Super):* =s-c= copy, =s-x= cut, =s-v= paste, =s-z= undo, =s-Z= and =S-s-z= redo (the latter is the event Emacs usually gets for Command+Shift+Z).
- *Linux and Windows (Ctrl):* =C-S-c= copy, =C-S-x= cut, =C-v= paste, =C-z= undo, =C-S-z= redo.
- *Unbound everywhere:* =C-y=, =C-w=, =M-w=, =C-_=, =C-/=, =C-?=, =C-M-_=, =C-x u=.
- =sp-text-manipulation.org= documents it, including a caveats list for unbinding =C-w=/=M-w=/=C-y=. =sp-keys.org= no longer says CUA is on. The =.el= is the tangled copy.

**** Readings I chose
:PROPERTIES:
:CUSTOM_ID: readings-i-chose
:END:
- Without CUA, plain =C-c= and =C-x= must stay prefixes, so copy and cut on Linux/Windows use the Shift variants. Say if you would rather have something else.
- Redo is the built-in =undo-redo=, not undo-tree.
- No CHANGELOG edit (nightly routine owns it).

Not run in Emacs (none in the container); please try on the Mac and on Linux/Windows.
