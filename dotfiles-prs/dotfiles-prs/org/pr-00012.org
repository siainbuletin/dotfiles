** Description
/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW2PGHTAG7Ju4Mw8ZC3zoPzju][project thread]]/

Before: discourse-graphs could tell me a claim was contested only through its own dashboards, its status logic was fixed, and the research-question states I had sketched had one catch-all =CONTESTED= state.

After: a new =sp-dg-positions= module draws the positions in a discourse graph the way =sp-vulpea-hierarchy= draws the note hierarchy, with the same kind of interface (=dg-positions-outline=, =dg-positions-graph=, =dg-positions-rankdir=, =dg-positions-graph-file=). It adds one view per status (=dg-positions-status=), a gaps view and a check view. Questions, claims, evidence and sources, the relations between them, the statuses and the gaps are all declared in one readable list, =dg-positions-rules=, so a new relation such as =contests= or =reframes= is one line. A new doc, =docs/tangles/research-question-states.org=, says exactly which state each object should be in; how contested an answer is now lives on the answer, not on the question.

How: the module reads =dg-all-nodes= and =dg-all-relations= from the discourse-graphs database and never writes to a note. =dg-positions-install= copies the declared node types and relations into discourse-graphs' own variables so it parses the new =DG_<RELATION>= properties; run =dg-rebuild-cache= afterwards. The literate doc =docs/tangles/custom/sp-dg-positions.org= is the source and tangles to =libraries/modules/custom/sp-dg-positions.el=; it is loaded from =init.el= after =sp-vulpea-hierarchy=. The doc's nine ERT tests pass in Emacs batch mode, the file byte-compiles without warnings, and the graph was rendered with Graphviz. It has not been run against a real discourse-graphs database.
