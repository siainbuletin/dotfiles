Follows #204. In =sp-author-notes=, an unquoted =pub-author= piece with more than one comma (=Francisco López-Muñoz, Gabriel Rubio, Juan D. Molina, Cecilio Alam=) was read as one name. It is now its own case:

- The report has a section "Lists of names with commas, to disambiguate" with the split it proposes: each piece a name when the first piece has two words or more, =Last, First= pairs (flipped) when it is one word and the count is even, no proposal otherwise.
- When the changes are written you are asked whether to split it (=sp-author-notes-disambiguate-function=, default =y-or-n-p=). Yes makes one author and one =:person:= note per name; no leaves the text as it is.
- One comma (=Smith, John=) is still one name; =;=, =and= and quotes work as before.

Tested: 15 ERT tests in Emacs 29.3 batch with a temporary vault. Not run on the real =~/notes=.
