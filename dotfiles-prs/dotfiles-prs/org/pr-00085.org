/Requested by *Sia* · [[https://claude.ai/code/project/chan_01KaQfLZaF43QUMN3kcT7pW2?thread=cmsg_01KaQfLZaF43QUMN3kcT7pW23eddj9am1nebvkG14YLgqW][project thread]]/

*Problem:* at startup, while vulpea indexed the vault, the echo area intermittently showed =redisplay--pre-redisplay-functions: (wrong-type-argument number-or-marker-p nil)=. Sia's backtrace: =cursor-sensor-tangible-pos= returned nil inside =cursor-sensor--move-to-tangible= on the Dashboard window. =cursor-intangible-mode= was on while the dashboard was erased or half-built, so no button existed to move point to.

*Changes*

- =sp-dashboard=: =sp-dashboard--isolate-menu= no longer calls =cursor-intangible-mode=. A new =sp-dashboard--enable-intangible= turns it on from an idle timer (0.1 s) after the draw, and only if the buffer is live and has a button. The property marking and the keymap overlay are unchanged.
- =sp-vulpea-base=: =vulpea-db-sync-scan-on-enable= is nil, so enabling =vulpea-db-autosync-mode= no longer scans the vault at startup (the database, save hook and watchers still work; an empty database is still scanned). =sp-vulpea-scan-once= runs =vulpea-db-sync-full-scan= two idle seconds after the first tracked note is opened, then removes itself. =M-x vulpea-db-sync-full-scan= still works by hand.
- The literate docs (=sp-dashboard.org=, =sp-vulpea.org=) are updated with the code.

*Not tested:* no Emacs in this environment, so none of this was run. =vulpea-db-sync-scan-on-enable= and =vulpea-db-sync-tracked-file-p= come from reading vulpea's source on GitHub; check they exist in the installed version.
