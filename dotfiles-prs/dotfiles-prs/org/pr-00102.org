** Description
*Before:* after =sp-load-theme= to a theme with another background, white borders stayed around the buffers. =sp-windows= painted the window dividers, the fringe and (indirectly) the frame border with the default background *once, when the module loaded*, so they kept the colour of the theme loaded at startup. Most themes (Doric included) also give =internal-border= no background, and Emacs does not repaint a frame's border when a face changes.

*After:* =sp-windows-blend-borders= paints the three divider faces, =fringe=, =internal-border= and =child-frame-border= with the current default background and redraws the graphic frames. It runs at load, from =sp-after-load-theme-hook=, and for each new graphic frame (a daemon that started without a frame has no background to read yet). Values like =unspecified-bg= (terminal frames) are skipped.

*Checked* (Emacs 29.3, no GUI available): with the default background stubbed to two colours in turn, all five faces follow it. *Not checked:* a real graphic frame, so please confirm on your Mac that the borders now follow =sp-load-theme=. If a border is still white, it is probably the =spacious-padding= faces, and I would look there next.
