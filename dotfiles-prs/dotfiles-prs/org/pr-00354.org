**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
- The lint report (=sp-bibtex-lint-dryrun=) has one button per fix, each with the number of entries it would change. A button is a =sp-bibtex-lint:KIND:FILE= Org link, so =RET= runs it.
- Three commands, one per fix (one =.bib= file, batches of =sp-bibtex-lint-batch-size= = 50, apply/skip/quit per batch, backup before the first write, nothing written without an answer):
  - =sp-bibtex-lint-fix-order=: fields in the order of =sp-bibtex-field-order=; values untouched.
  - =sp-bibtex-lint-fix-indent=: every entry laid out by =bibtex-fill-entry=, the =bibtex-mode= standard.
  - =sp-bibtex-lint-fix-authors=, three steps:
    1. names that are not =Last, First= are rewritten
    2. names one typo away from an author note
    3. names with the surname of an author note (below)
  - For steps 2 and 3, per batch: =n= normalises the name in the BibTeX field to the note's name, =l= adds the name as a vulpea alias of the note (the =.bib= is not changed), =e= asks for each name, =s= skips, =q= quits.
- Surname matches (step 3), a kind of match of its own:
  - the report lists them in their own section with their own count, so they do not bury the typos
  - same surname, and given names that fit the note's name by name: =TW Adorno=, =T. W. Adorno= and =Theodor Adorno= fit =Theodor W. Adorno=; =Michael Smith= is not =John Smith=, and =W Adorno= or =Theodor L. Adorno= are not =Theodor W. Adorno=
  - several notes with the surname: those with as many given names as the BibTeX name are preferred (=TW Adorno= is =Theodor W. Adorno=, not =Tamara Adorno=); if more than one is left (=T Adorno=) the name is ambiguous, listed in its own section with the candidates, and never changed or aliased
  - a name that is a typo of a note stays a typo match; a name that is a note's name or alias is not flagged
- Aliases of a note count as known names. =sp-bibtex-lint-convert= (=C-c w b L=) asks which fix to run.
- Any entry a fix touches is laid out like =bibtex-fill-entry=.
- Literate doc updated as bullet lists; it tangles to the committed =sp-bibprocess.el=.
