**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
Replaces the Denote commands I liked, in =sp-notes=:

- =sp-notes-create= (=SPC n c=, like =denote-create-note=): asks for a title and registered tags, writes the note with =:ID:= and =:CREATED:=, visits it. With tags it is written straight into its filing folder (same rules as the tag filing); without tags it stays at the top of the root, as the filing mode leaves it.
- =sp-notes-open= (=SPC n o=, like =denote-open=): =completing-read= over every org file in all subfolders of the notes root. Each candidate is the file name with creation date, tags and title beside it, newest first. Dot folders, =ltximg/=, =attach/= and =data/= are not listed (=sp-notes-open-exclude-regexp=); inbox, area, log and workbook are.
- =:CREATED:= on new notes: added in =sp-org--write-note= (new optional DIR arg and =sp-org-created-stamp=), so person and literature notes made through it get it too.

**** Ambiguity: where =:CREATED:= goes
:PROPERTIES:
:CUSTOM_ID: ambiguity-where-created-goes
:END:
- Read as: the file-level property drawer beside =:ID:=, format =[2026-11-07 20:15]= (inactive timestamp, no weekday). It is what =sp-quick-capture=, =vulpea-para= and =sp-org-issues= already write.
- Date shown by =sp-notes-open=: =:CREATED:=, else the id in the file name, else the modification time, so old notes without it still sort.
- Not changed: notes made by =vulpea-create= (=vulpea-find=, inbox tab). Say if you want =vulpea-create-default-function= to add it too.
- ADR 0025 (=-dryrun=/=-convert=) does not apply: these commands do not preview or convert anything.
