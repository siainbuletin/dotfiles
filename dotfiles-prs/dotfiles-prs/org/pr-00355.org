**** What
:PROPERTIES:
:CUSTOM_ID: what
:END:
Improves #280: when the =crossref='ed entry has no literature note, =bib-parent= is no longer left out. The note is made and linked.

- The parent is matched by its citation key (the =ROAM_REFS= key), never by title.
- A missing parent is made without asking, by =sp-litnotes-meta-create-function=, the same path =sp-litnotes-meta-backfill-children= and =-all-children= use:
  - =vulpea-create= with an ID, =:CREATED:=, =ROAM_REFS=, the =litnote= tag and the BibTeX type tag (=sp-bibtex-types=)
  - filled from its own BibTeX entry, given a plain title, and put in the Vulpea database
- =sp-litnotes-meta-fill= (single) and =sp-litnotes-meta-fill-all-convert= (batch from #348) both do this.
- Batch: each missing parent is made once, however many notes cross-reference it (=sp-litnotes-meta--made-parents=). It is counted in the one-time questions and in the final message.
- Dry run: new "Parent notes to make" section (each parent once, with the notes that link it), a count line, and "(new note)" on the =bib-parent= lines.
- Deep chains are flagged and avoided:
  - A normal crossref is =child -> parent= and the parent has no crossref. =child -> parent -> grandparent= (loops and self-references included) is flagged.
  - For such a note the fill and the batch convert nothing: no =bib-parent=, no parent note, even if the parent already has a note.
  - The dry run has a count line and a section "Crossref chains deeper than two levels" listing each chain; the single command prints a message.
  - New =M-x sp-litnotes-meta-fill-deep-chain= converts one flagged note on purpose: it shows the chain, asks once, fills the note and links or makes its direct parent. The parent is filled by the normal rules, so a loop is cut there. There is no batch version.
- A parent key with no BibTeX entry is left out with a message.
- =sp-litnotes-meta-offer-parent= became =sp-litnotes-meta-create-parent= (default t, old name kept as an obsolete alias). Set it to nil to get the old "leave it out" behaviour. The =y-or-n-p= question and the =citar-create-note= route are gone.
