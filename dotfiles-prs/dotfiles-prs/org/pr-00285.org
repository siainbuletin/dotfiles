Fixes =browse-url-url-at-point: Wrong type argument: buffer-or-string-p, (link ...)= when opening a URL in an Org file.

- =browse-url-url-at-point= calls =(thing-at-point 'url t)=, which strips text properties from whatever the provider returns. A list (a parsed =link= element) there gives exactly this =buffer-or-string-p= error.
- Org buffers now use =sp-org-url-at-point= as the =url= provider. It always returns a string or nil.
- A Markdown link pasted inside a plain link (~https://[www.youtube.com/watch?v=x](https://www.youtube.com/watch?v=x)~) opens the inner address.
- Doc section, CHANGELOG line and =tests/sp-org-url-test.el= added.

*Caveat:* I did not find in this repository the code that returns the link object, so the cause is inferred from the error and the =thingatpt= source. The fix guards the answer for Org buffers. If it still fails, =M-x toggle-debug-on-error= and send the backtrace.
