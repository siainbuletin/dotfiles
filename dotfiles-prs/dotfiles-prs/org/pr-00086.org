*Before:* in many modules the options of a package sat in top-level =setq= forms just before or after its =use-package=.

*After:* in 14 modules those options are =:custom= entries of the package's =use-package=, in the =.org= docs (canonical) and in the tangled =.el=. Attached comments and trailing comments moved with their setting. The doc text says where each option now lives (bullets, no leftover sections for removed code blocks).

*Behaviour that changes (check these):*

- =:custom= uses =customize-set-variable=, so a variable with a =:set= function now runs it; =setq= did not. I did not read the installed packages' source to see which have one.
- =:custom= runs before =:init= and =:config=. For =discourse-graphs= the =dg-*= options used to be set after =discourse-graphs-mode= was turned on; =citar-denote= and =org-node= likewise enable their mode after the options now.
- =sp-org-refile=, =sp-consult-snapfile= and =sp-vulpea-ui= have =:after=, so their options now apply once that package has loaded, not at module load.
- =sp-org-agenda= sets =org-agenda-tags-column= twice (0, then =org-tags-column=), as before; the last one wins.
- =sp-citations=: the existing =:custom= already holds a =(when …)= and a =(setq citar-notes-paths …)= form, which =use-package= reads as variables named =when= and =setq= (the doc already says so). The new entry was added after them and is a normal one.

*Not tested:* no Emacs here, so nothing was loaded or byte-compiled. What I did run: a Python check that every changed =.el= has the same bracket balance as before, and a Python tangler that shows each doc tangles to its =.el= (the same 15 pre-existing mismatches, such as =sp-icons= and =sp-themes=, before and after). =python3 tools/set-defcustom-group.py --check= fails on =main= too, for =sp-collection-query-tables{,-org,-views}.el=; I did not touch those.
