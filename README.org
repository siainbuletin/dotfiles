** General notes

Most of my operating system needs revolve around Emacs. Although there's a regular =.emacs.d/= directory at the top level, my actual individual configurations live in =.config=. This is because I'm using different configuration profiles for Emacs, through the use of Chemacs2. See my literate configuration for Emacs for more details: [[file:emacs-modular/.config/emacs-modular/README.org][emacs-modular/.config/emacs-modular/README.org]] describes the modular configuration and how to tangle its literate sources, and the architecture notes are in [[file:emacs-modular/.config/emacs-modular/docs/architecture/][docs/architecture/]].

All of the existing configurations and their names (so you can start with Emacs with the proper flair in the terminal, as ~emacs --with-profile=<name>~ can be found declared in ~.emacs.profiles.el~ in the top directory.

** Keys are bound differently from stock Emacs

Most of the keys in my Emacs are bound differently, so stock advice (=C-w=, =M-w=, =C-y=, =C-x u=, and =C-c=/=C-x= as prefixes) does not match what I type. CUA mode is off; copy, cut, paste, undo and redo use Command on the Mac and Ctrl on Linux and Windows, where the =C-c= and =C-x= prefixes move to Super. The table of replaced prefixes and chords is in [[file:emacs-modular/.config/emacs-modular/docs/tangles/base/sp-keys.org][sp-keys.org]], section "Replaced prefixes and chords". To see what a key really does, use =C-h k= and press it, or =C-h w= for a command.

** Commit and PR messages start with an emoji

Every commit message and every pull request title starts with an emoji for the kind of change, then a short summary in the imperative.

- ✨ new feature or new behaviour (=✨ Add sp-refile: one command to refile notes=)
- 🐛 bug fix (=🐛 Fix void-variable when loading sp-org-tag-lint=)
- 🔧 tooling, refactoring, renames, moves, scripts, CI, build and settings
- 📝 documentation: READMEs, literate docs, ADRs, design notes, CHANGELOG tidy
- ⚡ performance (already in use, e.g. caches and deferred loading)
- 🔥 removing a feature, module or dead code (already in use)
- A type word after the emoji is optional (=✨ feat:=, =🐛 fix:=, =📝 docs:=, =🔧 refactor:=); the emoji is not.
- Pick the emoji by what the change does, not by the files it touches. A fix to a doc is 📝; a fix to code is 🐛.
- If a change is several kinds at once, use the emoji of the main one.
- The PR title and the merge commit keep the PR title's emoji; the commits inside the PR carry their own.
- Messages that follow the pattern are left as they are; history on =main= is not rewritten to add emojis.
- The reasons are in [[file:adr/0026-emoji-prefix-for-commits-and-prs.org][ADR 0026]]; the same rule is in =CLAUDE.md= for Claude.

** Homelab configuration

Configuration for the services that run on my Synology NAS lives here too, as literate Org files that tangle to the files the NAS needs. Each folder has a script that tangles its Org file and copies the result to the NAS with =scp=; it runs from a shell, or from Emacs with =M-x compile= or =M-x async-shell-command=.

- *beets* (music library manager, in Container Manager): [[file:.config/beets/beets.org][.config/beets/beets.org]] tangles the beets =config.yaml= and the Container Manager =compose.yaml= into =.config/beets/synology/=, and [[file:.config/beets/deploy-to-synology.sh][.config/beets/deploy-to-synology.sh]] copies them to =/volume1/docker/beets=. API keys go in a =secrets.yaml= that is kept out of the repository.

** Installation instructions

*** ARCHVED: Installing via GNU Stow

Clone the directory of dotfiles into the $HOME directory with git. (I usually prefer to use GitHub through the CLI for authentication when setting the remote origin). Then, authenticate using HTTPS:

#+BEGIN_SRC
git clone https://github.com/siainbuletin/dotfiles.git
cd dotfiles
#+END_SRC

Then, in order to create symlinks, you need to use GNU Stow.

#BEGIN_SRC
stow .
#END_SRC

If you happen to be creating a symlink for a directory that already exists, you can choose to overwrite the existing repository by using the =--adopt= flag. This will tell Stow to move any of the conflicting files into the dotfiles directory.

#BEGIN_SRC shell
stow --adopt .
#END_SRC
