* What exactly are you trying to replace

I want to bring in an _annotated bibliography_ format that would allow me to have integrated notes all over the Emacs system. This means a tight integration with the zettelkasten system. Currently, my system is based around =denote=, so I'll be using =citar-denote= for configuring the literature notes.

There's multiple bibliography files that I have on my computer. This can be seen all at once from =helm-bibtex= already, which has a nice interface to my BibTeX files.

This list of descriptors tells how I've settled on particular solutions for the various moving parts of my configuration. One version of replacing Zotero completely can be done with this:

- managing the database :: through =ebib=. it can handle a much larger BibTeX file.

- handling citations :: both =org-ref= and =org-cite= can handle this in =org= documents. set up both of them to use the =ebib= database as the default bibliography.

- literature notes :: can be done with =org-roam-bibtex=, which plugs into =org-roam=. That means that when I click a citation, a hydra asks me what I want, I press 'n', and it takes me to an existing note or opens an =org-roam-capture= buffer, pre-filled with title, keywords, author etc.

The problem with =org-roam-bibtex= is that it hasn't been updated much lately.

- fetch PDFs from DOI :: org-ref

- look up paper on databases :: =biblio= (dependency of =org-ref=) can be used to look up a paper on e.g. ArXiv and retrieve the BibTeX entry.

Biblio can also download the PDF for you , either direct from ArXiv or it can look for open access versions of the paper. You need to provide a folder path for your bibliography.

- getting up to speed with reading :: Having this folder path correctly set up, the hydra mentioned before will also offer to open the PDF. It must be named the same as the cite key. If this is correctly set up, it is a breeze to download PDFs and open them for a quick look in =pdf-tools= or even =org-noter=, read and annotate and save your note in the org-roam system, and close it again.

- inserting from the bibtex database :: =Citar= can search your BibTeX database and insert org-cite formatted citations, BibTeX entries, or formatted references. It can also be used to find and insert multiple cite keys (I don't think it can be made to insert org-ref formatted citations, but once the keys are there, that is easy).

With Citar + Embark, I can search for a reference , narrow it down with consult/vertico, and with the =embark-citar= menu I can either open the PDF or the org-roam notes for the entry that way.

It took me a bit to find the right setup, and there are still a few rough edges, but I still think it is way nicer than any reference manager I have used before.

The functionality that I actually need for my system

It's actually quite hard to settle on a combination of settings for what I need in my own usage. While =org-ref= is one of the most advanced packages for bibliography management that has been made for Emacs, it doesn't actually provide all of the functions that I may want.

- a way to attach my PDF files :: I want to have integration with the file system that can go as deep as I need it to.

It also needs to not be bound to specific directories. The problem with =org-attach= is that it creates specific directories

- easy way to find the PDF files again :: This would also mean that I can search the PDF files by name, or query them through the command line through something like grep. I want to avoid being locked into the Emacs ecosystem as much as possible. Also, the PDF files should be able to live in a single flat directory from which I can select things.

- functionality between markdown and org-mode :: This is especially important if I want to have =completion-at-point= for my citation keys. Currently, the package that supports this is =citar=.

** TODO General biliography bootstrapping

This is where we're calling the default BibTex functions. =bibtex=, here, refers to the Emacs BibTeX mode. BibTeX mode has support for adding entries according to certain field configurations (it would be a lot more visual, like working in BibDesk for the same purpose).

The new optional fields that are defined under =bibtex-user-optional-fields= define keywords for tagging the literature and =file= to allow reading attachments from Emacs.

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (use-package bibtex
    :ensure nil
    :custom
    (bibtex-dialect 'biblatex)
    (bibtex-user-optional-fields
     '(("keywords" "Keywords to describe the entry" "")
       ("file"     "Relative or absolute path to attachments" "" )))
    (bibtex-align-at-equal-sign t)
    :config
    (sia-bibtex-register)
    :bind
    (("C-c w b r" . sia-bibtex-register))
  )
#+end_src

The =sia-register-bibtex= function  assigns all files with the =.bib= extension in the directory stored in the ~sia-bibliography-directory~ variable to the list of global BibTeX files. You need to set this variable to the location where you store your bibliography. Section #sec-bib in _Emacs Writing Studio_ explains creating and managing a bibliography. We use a special variable to ensure other variables have the same value.

** Adding the most recently downloaded PDF to the current entry

#+begin_src emacs-lisp :tangle "init.el" :eval never
(defun do.refs/ebib-add-newest-from-downloads (&optional file-extension)
    "Add the most recent file from `do.refs/pdf-download-dir' to the ebib entry at point."
    (interactive)
    ;; pull out the most recent file from ~/Downloads with the .pdf extension.
    (let ((newest-file (let ((dir-files (directory-files-and-attributes do.refs/pdf-download-dir)))
                         (caar (sort
                                (if (not file-extension)
                                    ;; the newest file from the download directory
                                    (mapcan (lambda (x)
                                              (let ((file-name (concat (file-name-as-directory do.refs/pdf-download-dir) (car x))))
                                                (when (file-regular-p file-name) (cons x nil))))
                                            dir-files)
                                  ;; all files with a certain extension
                                  (mapcan (lambda (x) (when (string-equal (file-name-extension (nth 0 x)) file-extension) (cons x nil)))
                                          dir-files))
                                ;; sort by date
                                (lambda (x y) (not (time-less-p (nth 6 x) (nth 6 y)))))))))
      (if newest-file
          ;; https://nullprogram.com/blog/2017/10/27/
          ;; need to override `read-file-name' because ebib normally prompts us for the file to import
          (let ((fpath (concat (file-name-as-directory do.refs/pdf-download-dir) newest-file))
                (bibkey (ebib--get-key-at-point)))
            (cl-letf (((symbol-function 'read-file-name) (lambda (&rest _) fpath)))
              (let ((current-prefix-arg '(4))) ;; C-u (to keep from removing original file)
                (call-interactively #'ebib-import-file)))
            (message "[Ebib] [Dennis] Imported %s for %s" fpath bibkey))
        (message "[Ebib] [Dennis] No files from %s imported." do.refs/pdf-download-dir))))
#+end_src

** Searching contents of PDFs

Taken from the citar wiki: https://github.com/emacs-citar/citar/wiki/Example-functions

If you run this and select candidates, this will pass the list of any associated PDF files to pdf-tools to search across all of them. If you run embark-act-all on a filtered candidate list, it will pass the files associated with all of those candidates.

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (defun sia-search-pdf-contents (keys-entries &optional str)
    "Search pdfs."
    (interactive (list (citar-select-refs)))
    (let ((files (citar-file--files-for-multiple-entries
                  (citar--ensure-entries keys-entries)
                  citar-library-paths
                  '("pdf")))
          (search-str (or str (read-string "Search string: "))))
      (pdf-occur-search files search-str t)))
#+end_src

  ;; with this, you can exploit embark's multitarget actions, so that you can run `embark-act-all`
  (add-to-list 'embark-multitarget-actions #'sia-search-pdf-contents)
#+end_src

** Add metadata to PDF files

This function will use the metadata from the entry and update the PDF file metadata. Note that it will make use of the 'editor' field when the 'author' field is empty while also keeping your library free of the backup files that =exiftool= creates by default (backups will be stored in the ex/citar-library-backup-path).

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (defvar sia-citar-library-backup-path "~/Documents/literature/backup")

  (defun sia-citar-update-pdf-metadata (citekey)
    (interactive (list (citar-select-ref)))
    (citar--check-configuration 'citar-library-paths)
    (unless citar-library-paths
      (user-error "Make sure `citar-library-paths' is non-nil"))
    (let* ((files (gethash cite-key (citar-get-files cite-key))))
      (unless files
        (user-error (format "There are no PDF files associated with %s" citekey)))
      (let ((file (or (unless (cdr files) (car files)) (completing-read "Please select a PDF file: " files)))
            (title (citar-get-value 'title citekey))
            (author (cond ((citar-get-value 'author citekey)
                           (citar-get-value 'author citekey))
                          ((citar-get-value 'editor citekey)
                           (concat (citar-get-value 'editor citekey) " (ed.)")))))
        (progn
          (copy-file file sia-citar-library-backup-path 1)
          (call-process-shell-command
           (concat "exiftool -overwrite_original_in_place -Title='" title "' -Author='" author "' " file))))))
#+end_src
