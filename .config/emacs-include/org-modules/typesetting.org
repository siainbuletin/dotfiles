** Appearance of the environment - plugging =olivetti-mode=

I currently don't know if I actually like this environment, but I have to enable it if I want to make use of the =sia-olivetti= function.

#+begin_src emacs-lisp :tangle "init.el" :eval never
      (use-package olivetti
        :ensure t
        :demand t
        :after org
        :custom
        (olivetti-minimum-body 100)
        (olivetti-body-width 80)
        :bind
        (("C-c w o" . sia-olivetti))
        :hook
        (org-mode . olivetti-mode))
#+end_src

The hook will turn on =olivetti-mode= by default in an org-mode buffer.

If you define ~olivetti-body-width~ as a number (in this case ~80~), then you won't actually have adaptive reflow for the text when you change from a wider frame to a more narrow one. If you set ~olivetti-body-width~ as a fraction (what I had before, ~0.8~), then it will resize, but when using a wider frame, it will make the text a little bit to spread out to have it be easily readable.

** Defining my own plain LaTeX class

#+begin_quote
This will give us a class that won’t include all the default packages in the generated LaTeX file. Put this in your init file. You can then use it with #+LATEX_CLASS: org-plain-latex.[fn:2]
#+end_quote

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (with-eval-after-load 'ox-latex
  (add-to-list 'org-latex-classes
  	     '("article"
                 "\\documentclass{article}"
                 ("\\section{%s}" . "\\section*{%s}")
                 ("\\subsection{%s}" . "\\subsection*{%s}")
                 ("\\subsubsection{%s}" . "\\subsubsection*{%s}")
                 ("\\paragraph{%s}" . "\\paragraph*{%s}")
                 ("\\subparagraph{%s}" . "\\subparagraph*{%s}"))

               '("org-plain-latex"
                 "\\documentclass{article}
             [NO-DEFAULT-PACKAGES]
             [PACKAGES]
             [EXTRA]"
                 ("\\section{%s}" . "\\section*{%s}")
                 ("\\subsection{%s}" . "\\subsection*{%s}")
                 ("\\subsubsection{%s}" . "\\subsubsection*{%s}")
                 ("\\paragraph{%s}" . "\\paragraph*{%s}")
                 ("\\subparagraph{%s}" . "\\subparagraph*{%s}"))))
#+end_src

** Creating the necessary ~SETUPFILE~

A SETUPFILE is simply a file that contains some sort of org mode configuration. For example, the #+LATEX_CLASS: we saw earlier. Or, maybe #+LATEX_HEADER:. It could even be as simple as #+TITLE:. In this SETUPFILE we can place all of our lines of LaTeX code we want included in the final generated document. This is a very powerful and easy method of perfectly customizing our export.

Linking to a SETUPFILE is done like this

~#+SETUPFILE: ~/Dropbox/Mackup/emacs-stuff/org/jake-standard-latex-export.org~

*** Structuring the ~SETUPFILE~

Now, in that SETUPFILE, we place the LaTeX lines we normally would put in a .tex file. For example, \usepackage{amsmath}. Hopefully you have your own favorite .tex file setup, but if not I suggest learning LaTeX and/or finding a template online.

I suggest using a macro to add #+LATEX_CLASS: to each line, rather than typing it manually of course! Notice the LaTeX_CLASS: - the custom one we just created.

#+begin_src org
,#+LaTeX_CLASS: org-plain-latex
,#+LaTeX_CLASS_OPTIONS: [letter]
,#+LATEX_HEADER: \usepackage{lmodern} % Ensures we have the right font

,#+LATEX_HEADER: \usepackage[AUTO]{inputenc}
,#+LATEX_HEADER: \usepackage{graphicx}
,#+LATEX_HEADER: \usepackage{amsmath, amsthm, amssymb}
,#+LATEX_HEADER: \usepackage[table, xcdraw]{xcolor}

% and so on...
#+end_src

** Enabling code highlighting in a LaTeX export[fn:2]

#+begin_src emacs-lisp :tangle "init.el" :eval never
(setq org-latex-listings 't)
#+end_src

This means that you need to add this to the ~SETUPFILE~:

#+begin_src org
,#+LATEX_HEADER: \usepackage{listings}
#+end_src

If you enable org-latex-listings but don’t include the listings package in your TeX file, it will likely not compile (if you are exporting an org file with code blocks).

Is there any way to preserve the formatting?

I might need to use =ox-pandoc= for this to work well. This version is good if you want to use the same formatting for the export all the time. There's also the option to pass options for pandoc compilation via the org header: https://github.com/emacsorphanage/ox-pandoc#passing-options-to-pandoc It could be easy to set up with YASnippet.[fn:5]

You need to also set =pandoc= up to generate good looking DOCX files. For this, you need a template document. =pandoc= has to be set up properly with =pacman= in order to behave well. The best way to do a DOCX export with pandoc is to play by its rules. This means that you need to start from its own templates.

To get a document formatted as this reference, you need to run this command in the shell:

#+begin_src shell :eval never
pandoc -o custom-reference.docx --print-default-data-file reference.docx
#+end_src

After this, you should open the ~.docx~ document in the word processor and edit the styles as needed.[fn:5]
