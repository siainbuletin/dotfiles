#+TITLE: Utility functions for editing in Emacs
#+startup: overview

This includes any kind of utility function that enhances the functionality of base Emacs. This doesn't make use of any kind of package (as much as possible). It's mostly composed of quick patches that I added on the go. Each function is explained as needed.

* Reloading the configuration on the fly

This will make reloading the configuration a lot easier.

Unfortunately, the reloading won't function like a silverbullet for anything. You may need to actually quit Emacs sometimes to really test out whether the reloading worked. I also noticed that the reloading works worse with =elpaca=, that's where you'll need to restart Emacs more often.

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (defun reload-init-file ()
    (interactive)
    (load-file user-init-file))

  ;; set shortcut for the reloading
  (keymap-global-set "<f5>" 'reload-init-file)
#+end_src

* Getting rid of customization via =M-x= menu

This will eliminate the =custom-file= which is created if you try to configure Emacs through the interactive menu.

In the event that I mistakenly call =M-x customize= to change something in my Emacs, this function makes sure that the file never actually appends to the =init.el=. (Afterall, it will get overwritten anyway once I run =org-babel-tangle= again.)

By using the =make-temp-file= function, the file will be placed in the =/tmp= directory[fn:1]

The function is taken from Protesilaos' configuration

#+begin_src emacs-lisp :tangle no :eval never
  (setq custom-file (make-temp-file "emacs-custom-"))
#+end_src

* Undo tree

By default, the Emacs undo tree doesn't support redo, which is absolutely despicable.

** Through =undo-tree=

The =undo-tree= has been merged into master, so all you have to do to get it to work now is declare it as such:

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (use-package undo-tree
    :config
    (add-to-list 'undo-tree-incompatible-major-modes #'nxml-mode)
    (global-undo-tree-mode)

    :custom
    (undo-tree-history-directory-alist '(("." . "~/.emacs.d/undo"))))
#+end_src

And for saving the history of those undos.

#+begin_src emacs-lisp :tangle no :eval never
  (setq undo-tree-auto-save-history nil))
#+end_src

** Through =vundo=
There's also the option to use =vundo=, which I prefer in this case.

#+begin_src emacs-lisp :tangle "init.el" :eval never
  (use-package vundo
    :ensure t)
#+end_src

If you want to use prettier Unicode characters to draw the tree:

* TODO Make reloading the modular Emacs literate configuration from just one function

I basically need to handle three commands with just one.
1. =org-export-to-org=
2. switch over to =temp.org= as the buffer that's being evaluated (maybe the temp file could actually be loaded into memory or loaded to =/tmp= just for the purpose of getting this configuration working)
3. =org-babel-execute-block= for executing all of the block in the =temp.org= (I have already fixed the part about going through all of the checking for each execution of each code block within the buffer)
4. =org-babel-tangle= for the actual tangling process

Since it's not a good idea to use a lambda (anonymous function) to call the multiple different functions within a single keybinding, it is a better idea to define my own function.

The lambda would look like this:

#+begin_example emacs-lisp
(global-set-key (kbd "C-c a b c") (lambda () (interactive) (some-command) (some-other-command)))
#+end_example

Will you please explain why not quote lambdas?
- This works great. Thanks! I have the same question about quote though --- I usually also quote the lambdas, and would like to know why not to.
-  Because '(...) is a list, not a function. See https://stackoverflow.com/questions/16801396/when-should-emacs-function-syntax-be-used/16802304#16802304
- Also, quoting lambdas hurts byte compilation.

I recommend never binding lambda expressions to keys, for the simple reason that when you ask Emacs what that key does, it will end up telling you something like this (to use the accepted code, when byte-compiled, as an example):

=C-c a b c= runs the command =#[nil "\300 \210\301 \207" [some-command
some-other-command] 1 nil nil]=, which is an interactive compiled Lisp
function.

It is bound to C-c a b c.

=(anonymous)=

Not documented.
If you never byte-compile your code, it's less cryptic, but still unformatted:

#+begin_quote
=C-c a b c= runs the command =(lambda nil (interactive) (some-command)
(some-other-command))=, which is an interactive Lisp function.
#+end_quote

Which, while still readable in the case of a small function like this, gets rapidly incomprehensible for larger functions.

* Configuring integration with shell tools

See notes on [[denote:20251119T222358][dwim-shell-command]] and the more general [[denote:20251119T222058][Interfacing with Emacs from outside of it]].

#+begin_quote
Alternatively, can also install via use-package, define your own commands and remap to shell-command’s existing binding.
#+end_quote

#+begin_src emacs-lisp :tangle "init.el" :eval never
(use-package dwim-shell-command
  :ensure t
  :bind (([remap shell-command] . dwim-shell-command)
         :map dired-mode-map
         ([remap dired-do-async-shell-command] . dwim-shell-command)
         ([remap dired-do-shell-command] . dwim-shell-command)
         ([remap dired-smart-shell-command] . dwim-shell-command)))
#+end_src

* Templating

Yasnippet makes boiler plate and other code snippets much faster to write with snippets that activates with small keywords. Just type the keyword and TAB, and yasnippet will fill in the snippet :) (you may have to fill in some names like class name or parameter names after TAB off course…).[fn:2]

#+begin_src emacs-lisp :tangle "init.el" :eval never
(use-package yasnippet
  :demand t

  :config
  (yas-reload-all)

  :hook
  (sh-mode . yas-minor-mode))

;; install useful snippets
(use-package yasnippet-snippets
  :after yasnippet)
#+end_src
