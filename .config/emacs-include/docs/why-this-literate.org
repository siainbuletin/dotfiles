#+TITLE: Explaining the methodology for choosing this type of configuration

* Different methodologies for doing an Emacs literate configuration
*** Loading the org configuration from =init.el= through =org-babel-load-file=

This would be done by calling this block in your =init.el=, and then leaving the rest of the configuration to do its thing:

#+begin_example emacs-lisp :tangle no
(require 'org)
(org-babel-load-file
 (expand-file-name
  "/path/to/config.org"))
#+end_example

The problem with this approach is that it introduces performance issues.[fn:1] Since =org-mode= is loaded *before* actually starting Emacs, the startup time will be impacted significantly. Emacs doesn't need most of the bloat the =org-mode= loads, and it would be much smarter to leave that for the after-=init.el= process.

*** Tangling the org configuration with =org-babel-tangle=

The more *optimal* solution, in this case, is to call =org-babel-tangle=, with the org configuration file open (meaning: the _current_ file, =literate-config.org=), which is *evaluated* through =C-c C-v C-t=. This command updates all of the files that are declared as *targets* through the =:tangle= flag. On the next startup --- or through using the =<F5>= [[*Make reloading the config easier][helper function]] that I designed for reloading the =init.el= file on the fly --- Emacs will have the updated configuration that was detailed in the literate config.

** How exactly does a literate configuration manage to be created?

You have a few options for the way that you're going to create your =init.el= file. You can create it as an entire file (so it takes the entirety of =dotemacs.org=, for the case of this document), or it can tangle based on each heading in the org document structure. It can even go as granular as each source block that is declared.

** How can =org-babel= support actual Emacs Lisp configuration?

*This explanation here is for =org-babel-load-file= function, which is _not_ ideal for creating the configuration.*

This works through the =org-babel-load-file= function. To enable the tangling for the files, you need to add this snipped to your =init.el=

#+begin_src emacs-lisp :tangle no
;; Load up Org Mode and (now included) Org Babel for elisp embedded in Org Mode files
(setq dotfiles-dir (file-name-directory (or (buffer-file-name) load-file-name)))

;; load up Org and Org-babel
(require 'org)
(require 'ob-tangle)

;; load up all literate org-mode files in this directory
(mapc #'org-babel-load-file (directory-files dotfiles-dir t "\\.org$"))
#+end_src

What this does is that it compiles each =config.org= file into a =config.el[c]= file. (Remember that the =[c]= in this case denotes that the termination of the file is actually =*.elc=, which denotes compiled Emacs Lisp code.

See also the =load-file= function that is supported by default in Emacs Lisp.

*How can you create a context in which you're alerted that you haven't closed your parentheses?*

Some longer configurations would benefit just from being converted into separate Emacs packages. That would make the file for the compilation a lot easier to parse, as well as allowing individual literate programming in that case as well.

You lose some of the helpers like company-mode, paredit-mode when you write code snippet, so naturally you wouldn't write long code.

One of the most common errors that you can have if you're writing your =init.el= through org-mode is that you forget to close parentheses when you're writing between source code blocks. If you've forgotten some parentheses, this will produce the =End of file during parsing= error. This can be easily checked in the =init.el= file that was tangled using =M-x check-parens RET=.[fn:3]
