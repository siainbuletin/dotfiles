**What this changes**

- **No `config.el`.** The module lists live in `sp-module-sets`. For per-machine tweaks, `setq` or modify that variable in `early-config.el`, which loads first, instead of keeping a separate config file.
- **New profiles are one entry.** Because the switch check is derived from the alist, adding `(writing sp-libraries sp-settings sp-writing)` makes `emacs -writing` work with no dispatcher changes.
- **Modules are symbols.** `'sp-base-code` just works, provided `sp-base-code.el` ends with `(provide 'sp-base-code)` and the directory is on `load-path` (the recursive setup from earlier). Your `'sp-base code` with the space would be read as two symbols, so make sure it's hyphenated.
- **`require` instead of `load`.** Your `sp-load` re-executes a file on every call and doesn't use features. `require` loads each module once and skips it afterwards. The `condition-case` keeps the same "report and continue" behavior as your function.
- **`cl-dolist` became `dolist`.** `cl-dolist` is only needed for `cl-return`, which this loop doesn't use.

- The `-default` switch isn't needed anymore, since `default` is the fallback. It still works, because `default` is in the alist.

* Creating a module loader file, instead

I've replaced the `config.el` cascade with a single `sp-config-profiles.el`. I haven't run it, and it relies on helpers from your Lambda setup (`sp--emacs-switches`, `sp-gui-only-modules`, `measure-time`, `sys-mac`).

It uses a recursive lookup
**How it works**

- **Recursive lookup like `require`.** Every subfolder of `sp-library-dir` is added to `load-path` once, using the same `normal-top-level-add-subdirs-to-load-path` approach as earlier. After that, `'sp-base-code` resolves wherever the file lives, with no paths.

- **Profiles replace `config.el`.** The `sp-module-profiles` alist holds one list of symbols per bundle (`default`, `minimal`, `test`). `sp--active-profile` still picks one from the `-minimal` and `-test` switches, and the default is the fallback. To change what loads, edit that list.

- **Error reporting is kept.** `sp-require-module` wraps `require` in `condition-case` and prints `Failed to load sub-library ...` with the error, so one broken module doesn't stop the rest. It also catches a file that loads but fails to provide its feature.
- **Your existing `sp-load` has a drop-in replacement.** `siapip/require` accepts a symbol or a list, so `(siapip/require '(sp-base-code sp-ui))` replaces the path-based calls.

**Removed**

All `sp-config-file` and `sp-default-config-file` logic is gone, including the branch that copied a default config into place.

You can delete those variables from your early-init. The macOS deferred load is now one `when` at the end of `sp-load-profile`, limited to the default profile and non-headless hosts, matching your original behaviour. The headless GUI-frame warning hook is unchanged.

**What to check**

- **Every module must `(provide 'its-file-name)`.** `require` needs the feature name to match the file name, which `load` didn't care about. A mismatch shows up as one of the failure messages.
- **File names must be unique across subfolders**, since two `utils.el` files collide on `load-path`.
- **Possible typos in your original lists.** `sp-keys` in the default profile vs `sp-keybindings` in minimal (I kept `sp-keys` and left a FIXME), and `sp-dired` listed twice, which I deduplicated. Your message also wrote `'sp-base code` with a space, which I assume means `sp-base-code`.
- **`require` loads each feature only once.** If you re-evaluate a file in a running session, `(require 'x)` won't reload it. Use `(load-library "x")` or `M-x load-file` for that.

(defun sp-load-profile (&optional profile)
  "Load every module of PROFILE (default: the one chosen by switches).
Skips modules in `(sp-gui-only-modules)' when `sp-headless-host' is non-nil."
  (let* ((profile (or profile (sp--active-profile)))
         (modules (alist-get profile sp-module-profiles)))
    (unless modules
      (user-error "No modules defined for profile `%S'" profile))
    (message "\n;; ======================================================
;; *Loading Lambda-Emacs profile: %S*
;; ======================================================" profile)
    (measure-time
     (dolist (mod modules)
       (unless (and sp-headless-host
                    (memq mod (sp-gui-only-modules)))
         (sp-require-module mod))))
    ;; MacOS settings: deferred until idle, default profile only, never headless.
    (when (and sys-mac (not sp-headless-host) (eq profile 'default))
      (run-with-idle-timer 1 nil #'require 'sp-macos nil t))))
