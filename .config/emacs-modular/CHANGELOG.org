#+title: Changelog
#+startup: overview

Changes to the Emacs configuration, one entry per pull request. Entries are
grouped by merge date, newest first, using the Keep a Changelog categories
(Added, Changed, Fixed, Removed). Paths are relative to this folder. Long
lists of files sit in a sub-list under their entry: press =TAB= on the entry
to fold or unfold it.

* Open pull requests
** Added
- Notes can have a type (=question=, =claim=, =evidence= or =source=) from a =DG_TYPE= property, a =type= metadata field or a file tag. A relation can list the types it connects, and the browser graph flags other edges with a warning sign. Boxes take the colour of their type when no tag has one, and an attribute computed from a formula, such as =[2]=, follows the title. =relationship-annotator-review= lists the anomalies, the claims with gaps and the strength of each answer. This ports the logic of =discourse-graphs=; =docs/relationship-annotator-vs-discourse-graphs.org= compares the two. ([[https://github.com/siainbuletin/dotfiles/pull/19][#19]], Claude)
- Each relation in =vulpea-hierarchy-relations= takes a =:direction= (up, down, left, right or an angle), so the browser graph can put =supports=, =opposes= and the like on a chosen side of a note. ([[https://github.com/siainbuletin/dotfiles/pull/18][#18]], Claude)
- =vulpea-hierarchy-tag-colors= tints each box in the browser graph and the SVG export by the first of its file tags that has a colour, and the legend lists the tags in view. ([[https://github.com/siainbuletin/dotfiles/pull/17][#17]], Claude)
- =vulpea-hierarchy-relations= declares relations between notes, each read from one or more sources: a metadata key, the inverse of a key (such as =children ::=), or a file property such as =DG_SUPPORTS=. Relations other than =parent= are drawn as labelled links in the browser graph and the SVG export. ([[https://github.com/siainbuletin/dotfiles/pull/16][#16]], Claude)
** Changed
- =sp-vulpea-hierarchy= is renamed =sp-relationship-annotator=, and every =vulpea-hierarchy-*= variable and command is now =relationship-annotator-*=. The old names still work as obsolete aliases. ([[https://github.com/siainbuletin/dotfiles/pull/19][#19]], Claude)
- The browser graph places boxes with the fCoSE layout, vendored in =libraries/modules/custom/vendor/vulpea-hierarchy/=. Parents go above their children, and the Graphviz default =vulpea-hierarchy-rankdir= is now ="TB"=. ([[https://github.com/siainbuletin/dotfiles/pull/18][#18]], Claude)
- A click on a box in the browser graph recentres the graph on it, with buttons for the depth and for going back, and a marker to fold a branch. The page holds =vulpea-hierarchy-embed-depth= levels (4) below the starting note, cut in Emacs, so a large vault doesn't make it large; to go further, run the command again from another note. ([[https://github.com/siainbuletin/dotfiles/pull/17][#17]], Claude)
- =vulpea-hierarchy-relations= replaces the option =vulpea-hierarchy-parent-key=; its value is now the =parent= relation. ([[https://github.com/siainbuletin/dotfiles/pull/16][#16]], Claude)
