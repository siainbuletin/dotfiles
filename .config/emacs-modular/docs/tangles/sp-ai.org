Literate source for =libraries/modules/media/sp-ai.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. Tangling this file (=C-c C-v t=) rewrites that =.el= file from these blocks; nothing is tangled unless you run it.

This module installs a handful of packages for working with large language models from inside Emacs. It only installs them; none of the packages get keybindings, backends or API keys here, so their defaults (or settings made elsewhere) apply.

The packages are =gptel= (a general chat client for many LLM providers), =eca= (Editor Code Assistant), =agent-shell= (a shell-like interface to coding agents) and =vulpea-mcp=, which exposes the Vulpea note database to LLMs over the Model Context Protocol. The last one ties this module to the Vulpea setup in =sp-vulpea-base=.

* LLM clients

** gptel

Installs =gptel=. The =(:wait t)= recipe tells Elpaca to finish installing it before continuing, presumably so later packages that build on gptel find it available.

#+begin_src emacs-lisp -i
(use-package gptel
  :ensure (:wait t))
#+end_src

** eca

Installs =eca=, the Editor Code Assistant client, with default settings.

#+begin_src emacs-lisp -i

  :ensure t)
#+end_src

** agent-shell

Installs =agent-shell=, which runs coding agents in a comint-style buffer. No agents are configured here.

#+end_src

* Notes for LLMs

** vulpea-mcp

The comment explains the goal: letting an LLM see the Vulpea notes. =vulpea-mcp= is installed straight from its Codeberg git repository and serves the Vulpea database to MCP-capable agents.

#+begin_src emacs-lisp -i
;; Making an LLM recognise my vulpea notes

(use-package vulpea-mcp
  :ensure (:type git :repo "https://codeberg.org/nicolas-graves/vulpea-mcp.git"))
#+end_src
