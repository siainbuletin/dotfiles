The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module sets up the =elfeed= feed reader, =elfeed-org= for keeping the feed list in an Org file, and a command for capturing feed entries into Org through =org-protocol=. It is not in any module list in =init.el=, and the notes in =conditional-loading.org= describe it as unconfigured, so it is a work in progress that does not currently load.

As written it would not load cleanly. The file has no =provide= form, so =(require 'sp-rss)= would fail. The =elfeed-org= block has a malformed =:custom= entry. The capture command uses =flet=, which belongs to the old =cl= library and is not available in a modern Emacs without loading it. A closing comment wonders how feeds could tie into bibliography management, as in Emacs Writing Studio.

** Elfeed

Configures =elfeed= with its database in an =elfeed= folder in =user-emacs-directory=, shows entries with =display-buffer= so they open alongside the search list, and binds =C-c w e= to open it. There is no =:ensure= here, so it relies on the package being installed some other way.

#+begin_src emacs-lisp -i
(use-package elfeed
  :custom
  (elfeed-db-directory
   (expand-file-name "elfeed" user-emacs-directory))
  (elfeed-show-entry-switch 'display-buffer)
  :bind
  ("C-c w e" . elfeed))
#+end_src

** elfeed-org

Installs =elfeed-org= and runs =(elfeed-org)= to read the feed list from Org files. The =:custom= section wraps a =setq= in a list, which =use-package= reads as setting a variable called =setq= to the value of =sia-elfeed-org-files=, so it would signal an error rather than set the file list. The intent appears to be using =~/Documents/elfeed.org= as the feed file; the variable =elfeed-org= actually reads is =rmh-elfeed-org-files=.

#+begin_src emacs-lisp -i
(use-package elfeed-org
  :ensure t
  :config
  (elfeed-org)
  :custom
  (setq sia-elfeed-org-files (list "~/Documents/elfeed.org")))
#+end_src

* Capturing entries

** Capture selected entries

=yant/elfeed-capture-entry=, judging by its prefix adapted from another user's config, tags the selected search entries as opened, marks them read and, for each one with a link, calls =org-protocol-capture= with template =B=, the link, a title combining feed and entry names, and the entry itself. =raise-frame= is temporarily stubbed out so capturing does not pop frames. It then refreshes the entries and moves to the next line. Template =B= must exist in the capture templates, and =flet= needs replacing with =cl-letf= for this to run on current Emacs.

#+begin_src emacs-lisp -i
(defun yant/elfeed-capture-entry ()
  "Capture selected entries into inbox."
  (interactive)
  (elfeed-search-tag-all 'opened)
  (previous-logical-line)
  (let ((entries (elfeed-search-selected)))
    (cl-loop for entry in entries
             do (elfeed-untag entry 'unread)
             when (elfeed-entry-link entry)
             do (flet ((raise-frame nil nil))
                  (org-protocol-capture (list :template "B"
                                              :url it
                                              :title (format "%s: %s"
                                                             (elfeed-feed-title (elfeed-entry-feed entry))
                                                             (elfeed-entry-title entry))
                                              :elfeed-data entry))))
    (mapc #'elfeed-search-update-entry entries)
    (unless (use-region-p) (forward-line))))
#+end_src
