Literate source for the Vulpea modules in =libraries/modules/vulpea/=. This one file tangles ten =.el= files, one per module, each with its own =provide=; there is no module that loads them as a group, =sp-org-ext= requires them. The =:tangle= path of each part is set in the =:header-args:emacs-lisp+:= property of its top-level heading (the =#+PROPERTY= line above is =:tangle no=, so a block outside a part is not written); see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The sub-modules are not new: they were =sp-vulpea-base=, =sp-vulpea-ui=, =sp-vulpea-para=, =sp-vulpea-schemas=, =sp-vulpea-ext=, =sp-vulpea-ext-back= and =sp-vulpea-split= in =libraries/modules/text/=, and =sp-vulpea-convert-properties=, =sp-vulpea-grouped-backlinks= and =sp-vulpea-org-ql= in =libraries/modules/funct/=, each with its own doc. The code is unchanged. Most of the files have no newline after their last line, and Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

The table modules (=sp-vulpea-table=, a custom module of mine) are deliberately not part of this group; they have their own doc, =docs/tangles/funct/sp-vulpea-table.org=, and are loaded by =sp-org-ext= right after these.

* sp-vulpea-base.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-base.el
:END:

This module sets up =vulpea=, a library and database layer for Org-based notes (an alternative to org-roam), together with =vui=, the UI component library used by other Vulpea modules such as =sp-vulpea-table-vui=. It is required from =sp-org-ext=, and the further Vulpea extensions live in =sp-vulpea-ext=.

It configures which directories are indexed, how notes are displayed in the minibuffer, which property stores aliases, and how new note files are named. Several settings are given twice (once in =use-package= and once with a plain =setq=), and the plain =setq= forms run at load time, so they win.

*** vulpea

Installs =vulpea= and waits for it to finish so later code can call its functions immediately. The empty =:init= only carries a comment copied from Doom-oriented documentation about =org-directory=. =vulpea-db-sync-directories= is set further down.

Keybindings: ~M-o f~ runs =vulpea-find= globally, and ~M-o n a~ in Org buffers runs =vulpea-buffer-alias-add= to add an alias to the current note.

#+begin_src emacs-lisp -i
(use-package vulpea
  :ensure (:wait t)

  :init
  ;; Vulpea derives its defaults from `org-directory'. Doom's :lang org
  ;; module sets it to ~/org/ - override here if your notes live elsewhere,
  ;; or set `vulpea-db-sync-directories' explicitly.

  :bind
  (("M-o f" . vulpea-find)
   :map org-mode-map
   ("M-o n a" . vulpea-buffer-alias-add))
)
#+end_src

** Database settings

*** Synced directories

Sets =vulpea-db-sync-directories= to =~/notes/= only, so the Emacs config directory is not indexed. The =use-package= form above used to set it too, to =~/notes/= plus =user-emacs-directory=, but this =setq= ran afterwards and replaced it, so the duplicate was removed and the effective value is unchanged. Add =user-emacs-directory= here if the config directory should be indexed as well.

#+begin_src emacs-lisp -i
(setq vulpea-db-sync-directories (list sp-notes-dir))
#+end_src

*** Parse method

=single-temp-buffer= makes Vulpea parse files by reusing one temporary buffer, which is faster than visiting each file normally.

#+begin_src emacs-lisp -i
(setq vulpea-db-parse-method 'single-temp-buffer)
#+end_src

*** Automatic database sync

Turns on =vulpea-db-autosync-mode=, which keeps the database updated as note files change.

#+begin_src emacs-lisp -i
(vulpea-db-autosync-mode +1)
#+end_src

*** Alias property

Stores aliases in the =ROAM_ALIASES= property instead of Vulpea's default =ALIASES=, which keeps notes compatible with org-roam.

#+end_src

Runs =vulpea-db-query-by-tags-every= for notes tagged both project and active. The result is discarded, so this line has no effect beyond executing the query at load time. It looks like an example left in from the documentation.

** Templating for new notes

*** Default note creation

=vulpea-create-default-function= decides the file name and tags for a new note. Files are named with a timestamp followed by a slug of the title. If the title contains the string TODO the note gets the tag task, otherwise note.

#+begin_src emacs-lisp -i
;; Templating for Vulpea

(setq vulpea-create-default-function
      (lambda (title)
        (list :file-name (format "%s_%s.org"
                                 (format-time-string "%Y%m%d%H%M%S")
                                 (vulpea-title-to-slug title))
              :tags (if (string-match-p "TODO" title)
                        '("task")
                      '("note")))))
#+end_src

* sp-vulpea-ui.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-ui.el
:END:

This module configures =vulpea-ui=, the user interface layer for the Vulpea note database: a sidebar showing the current note's outline and backlinks, and collection views that render filtered tables of notes. Later modules such as =sp-vulpea-table-views= build on the rendering and settings established here, together with the schemas in =sp-vulpea-schemas=.

It depends on =vulpea= and on Org being loaded, since it binds a key in =org-mode-map= at load time. The module is not in the main =init.el= list; it is pulled in by =(require 'sp-vulpea-ui)= from =sp-org-ext=.

*** Sidebar layout and refresh

The sidebar opens on the right, takes a third of the frame, shows headings in its outline down to level 3, and refreshes automatically so it follows the current note without manual refreshes.

#+begin_src emacs-lisp -i
;; Position: 'right (default), 'left, 'top, 'bottom
(setq vulpea-ui-sidebar-position 'right)

;; Size as fraction of frame (0.0-1.0)
(setq vulpea-ui-sidebar-size 0.33)

;; Maximum heading depth (nil = unlimited)
(setq vulpea-ui-outline-max-depth 3)

;; Utility functions for vulpea-ui
(setq vulpea-ui-auto-refresh t) ;; So you don't have to constantly do a manual refresh.
#+end_src

*** Respecting narrowing

With =vulpea-ui-respect-narrowing= on, the sidebar only reflects the visible, narrowed part of a buffer. As the comment explains, Emacs has no hook for narrowing changes, so the sidebar would only notice on its next idle refresh.

(setq vulpea-ui-respect-narrowing t)

;; Emacs has no narrowing hook, so the sidebar notices a narrow or widen on the next idle

#+end_src

*** Narrow and refresh in one step

=sp-org-toggle-narrow-and-sidebar= toggles narrowing to the current subtree and refreshes the sidebar immediately, avoiding the delay. It is bound to =M-<insert>= in Org buffers. Because =define-key= runs at load time, =org-mode-map= must already exist when this module loads.

#+begin_src emacs-lisp -i
(defun sp-org-toggle-narrow-and-sidebar ()
  "Toggle subtree narrowing and refresh the sidebar immediately."
  (interactive)
  (org-toggle-narrow-to-subtree)
  (vulpea-ui-sidebar-refresh))

(define-key org-mode-map (kbd "M-<insert>") #'sp-org-toggle-narrow-and-sidebar)
#+end_src

** Backlinks widget

*** Previews

Backlinks show a preview of their context, with 30 characters before and 50 after the link for links that occur in prose.

#+begin_src emacs-lisp -i
;; the backlinks widget

;; Show/hide content previews
(setq vulpea-ui-backlinks-show-preview t)

#+end_src

*** Filtering and sorting

Notes tagged =archive= are excluded from backlinks. Links from every kind of context (metadata, headers, tables, lists, quotes, code, footnotes and prose) are included, and backlinks are sorted by title, A to Z.

#+begin_src emacs-lisp -i
;; Filter which notes appear in backlinks
;; (function receiving vulpea-note, return non-nil to include)
(setq vulpea-ui-backlinks-note-filter
      (lambda (note)
        (not (member "archive" (vulpea-note-tags note)))))

;; Filter by context type
;; t = all types, or a list of: meta, header, table, list, quote, code, footnote, prose
(setq vulpea-ui-backlinks-context-types t)

;; Sorting: nil (no sorting), 'title-asc, 'title-desc, or custom function
(setq vulpea-ui-backlinks-sort 'title-asc)
#+end_src

** Collection views

*** Named collection views

=vulpea-ui-collection-views= defines four named tables, each with a filter, a list of columns and a sort order.

- =thesis-reading-list=: file-level notes tagged =book= whose =bib-project= metadata links to a specific thesis note, showing title, publication title, author, read status, links, tags and modification time, newest first. A commented-out filter on =read-status= is noted as not working yet.
- =open-questions=: first-level headings tagged =question=, showing their =q-status=, links, tags and modification time. Two closing quotes used to be missing (after =question= and after =q-status=), so the reader swallowed the =:level= and =:columns= text into one long tag string and the view matched nothing useful.
- =music=: file-level notes tagged =music=, showing year and genre, sorted by title.
- =albums=: notes tagged =album= with creator, year, genre, influences, rating and review columns. The =(meta "rating")= column used to be missing its closing parenthesis, which nested the remaining columns and the =:sort= clause inside it.

#+begin_src emacs-lisp -i
;; Collection views
(setq vulpea-ui-collection-views
      '(
        ("thesis-reading-list" . (:filter (:tags-all ("book")
					                          :level 0 ;; this is what will bring file-level notes
					                          ;; :meta ("read-status" . t) ;; this one doesn't work yet for some reason
                                    :meta ("bib-project" . "[[ID:806b08ac-3ed1-4338-a26e-3af9e0e9328c][Devalorizarea artei în capitalismul de platformă]]")
                                    )
			                :columns (title (meta "pub-title") (meta "pub-author") (meta "read-status") links tags modified)
			                :sort ("Modified" . t)))
        
        ("open-questions" . (:filter (:tags-all ("question")
                                      :level 1 ;; this will only bring up headings at first
                                      )
                             :columns (title (meta "q-status") links tags modified)
                             :sort ("Modified" . t)
        ))
        
        ("music" . (:filter (:tags-all ("music")
                            :level 0)
                    :columns (title (meta "year") (meta "genre") tags modified)
                    :sort ("title" . t)))
        
        ("albums" . (:filter (:tags-all ("album"))
                     :columns (title
                                (meta "creator" :width 60)
                                (meta "year")
                                (meta "genre")
                                (meta "genre-influences")
                                (meta "rating")
                                (meta "review")
                                context tags modified)
                     :sort ("title" . t)))))
#+end_src

* sp-vulpea-para.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-para.el
:END:

This module wires the =vulpea-para= library into Org's agenda. vulpea-para organises notes along the PARA method (projects, areas, resources, archives) on top of the =vulpea= note database; a copy of it is kept under =libraries/modules/cloned/vulpea-para/=. Here it decides which files are agenda files: =vulpea-para-agenda-mode= keeps an =agenda= tag on every vault file that holds open work, and sets =org-agenda-files= from the database before each agenda, so Emacs does not visit every file to find out. Notes tagged =cemetery= are kept out. This is the only place that controls the agenda files; see [[file:../../../../../adr/0009-one-agenda-owner-per-setting.org][ADR 0009]].

It is required by =sp-org-ext=. The agenda line prefix is set in =sp-org-agenda=, the capture templates in =sp-org-capture= and the views in =sp-agenda-views=, so none of them is touched here.

The commentary at the top of the module says:

** Agenda files

*** Cemetery filter

=sp-vulpea-para-agenda-note-p= is the predicate =vulpea-para-agenda-files-filter= calls with each note tagged =agenda=: it returns nil for a note tagged =cemetery=, so retired projects and archived to-dos never become agenda files, even though they still hold the =agenda= tag. vulpea-para's checks for missing files know about the filter and leave those files out on purpose. A named function makes it testable (=tests/sp-vulpea-para-test.el=).

#+begin_src emacs-lisp -i
(defun sp-vulpea-para-agenda-note-p (note)
  "Return non-nil when NOTE may be an agenda file.
Notes tagged \"cemetery\" are kept out."
  (not (vulpea-note-tagged-any-p note "cemetery")))

;; keep a cemetery (or anything) out of the agenda file list
(setq vulpea-para-agenda-files-filter #'sp-vulpea-para-agenda-note-p)
#+end_src

*** Done keywords and the inbox

The database-side checks of vulpea-para need to know which keywords mean finished; they come from =sp-org-keywords=, so there is one list. =inbox.org= always counts as holding open work, so the inbox stays on the agenda to be emptied.

#+begin_src emacs-lisp -i
(setq vulpea-para-done-keywords (sp-org-keywords-done))
(setq vulpea-para-open-work-files '("inbox.org"))
#+end_src

*** Agenda mode

Turns on =vulpea-para-agenda-mode=: vault buffers maintain their =agenda= tag when saved, and =org-agenda-files= is refreshed from the database before =org-agenda= and =org-todo-list=. Views that restrict the files themselves bind =vulpea-para-agenda-inhibit-files-update= (see =sp-agenda-views=). Entry points that bypass both (the splash, =sp-trails=) read the variable as it was last set, so it is also refreshed once, shortly after start-up, when the database is ready. Files saved before the mode was on get the tag from vulpea-para's backfill commands (run them once).

#+begin_src emacs-lisp -i
(vulpea-para-agenda-mode 1)

(defun sp-vulpea-para-refresh-agenda-files ()
  "Set `org-agenda-files' from the database, ignoring errors."
  (condition-case err
      (vulpea-para-agenda-files-update)
    (error (message "[vulpea-para] agenda files not set yet: %s"
                    (error-message-string err)))))

(add-hook 'emacs-startup-hook
          (lambda ()
            (run-with-idle-timer 3 nil #'sp-vulpea-para-refresh-agenda-files)))
#+end_src

*** Cemetery filter

A fake note is a plist of tags; headless, =vulpea-para=, =vulpea= and the keyword module are provided as stand-ins, so only the filter and the configuration around it are exercised. A note tagged =cemetery= must not be an agenda file, whatever else it is tagged, and the filter must be what =vulpea-para-agenda-files-filter= holds.

#+begin_src emacs-lisp -i
;;; sp-vulpea-para-test.el --- Tests for sp-vulpea-para  -*- lexical-binding: t; -*-

;;; Code:

(require 'ert)

(when noninteractive
  (provide 'vulpea-para)
  (defvar vulpea-para-agenda-files-filter nil)
  (defvar vulpea-para-done-keywords nil)
  (defvar vulpea-para-open-work-files nil)
  (defun vulpea-para-agenda-mode (&rest _) nil)
  (defun vulpea-note-tagged-any-p (note &rest tags)
    (seq-intersection (plist-get note :tags) tags))
  (load (expand-file-name
         "../libraries/modules/text/sp-org-keywords.el"
         (file-name-directory (or load-file-name buffer-file-name)))
        nil t))

(load (expand-file-name
       "../libraries/modules/vulpea/sp-vulpea-para.el"
       (file-name-directory (or load-file-name buffer-file-name)))
      nil t)

(ert-deftest sp-vulpea-para-test-cemetery-is-kept-out ()

** Converting a single node

These functions operate on the "node at point": the heading at or above point, or the file-level node when point is before the first heading.

*** Finding the insertion point

=sia-vulpea--after-property-drawer-pos= returns the position right after the node's property drawer. For a heading that is after its drawer, or after the heading line when there is none. For the file-level node it also skips any leading =#+KEYWORD:= lines in any order relative to the drawer, so that meta lines never end up above =#+title:= or =#+date:= when the drawer comes first in the file.

#+begin_src emacs-lisp -i
;;;; Low-level: one node at a time ---------------------------------------

(defun sia-vulpea--after-property-drawer-pos ()
  "Return the position right after the property drawer of the node at point.
\"Node at point\" is the heading at or above point, or the
file-level node if point is before the first heading.

For a heading, this is simply right after its own drawer (or
right after the heading line, if it has none).

For the file-level node, this additionally skips past any
leading #+KEYWORD: lines (#+title:, #+date:, #+filetags:, etc.)
in whatever order they appear relative to the property drawer.
Without this, meta lines inserted \"right after the drawer\"
would land *above* #+title:/#+date: whenever the drawer happens
to come first in the file -- which is exactly the bug this
guards against."
  (save-excursion
    (if (org-before-first-heading-p)
        (progn
          (goto-char (point-min))
          (let (moved)
            (setq moved t)
            (while moved
              (setq moved nil)
              (cond
               ((looking-at "^[ \t]*:PROPERTIES:[ \t]*$")
                (re-search-forward "^[ \t]*:END:[ \t]*$" nil t)
                (forward-line 1)
                (setq moved t))
               ((looking-at "^[ \t]*#\\+[a-zA-Z_-]+:.*$")
                (forward-line 1)
                (setq moved t)))))
          (point))
      (org-back-to-heading t)
      (forward-line 1)
      (if (looking-at "^[ \t]*:PROPERTIES:[ \t]*$")
          (progn (re-search-forward "^[ \t]*:END:[ \t]*$" nil t)
                 (forward-line 1)
                 (point))
        (point)))))
#+end_src

*** Inserting or updating a meta line

=sia-vulpea--insert-or-update-meta-line= writes =- KEY :: VALUE= right after the drawer. If a line for the same key already exists between the drawer and the next heading, its value is replaced instead, so re-running a conversion does not create duplicates.

#+begin_src emacs-lisp -i
(defun sia-vulpea--insert-or-update-meta-line (key value)
  "Insert or update a \"- KEY :: VALUE\" meta line for the node at point.
Placed right after that node's property drawer. If a meta line
for KEY already exists between the drawer and the next heading
(or end of file, for the file-level node), its value is replaced
instead of adding a duplicate -- so re-running a conversion is
safe and idempotent."
  (let* ((start (sia-vulpea--after-property-drawer-pos))
         (end (save-excursion
                (goto-char start)
                (if (re-search-forward "^\\*" nil t) (line-beginning-position) (point-max))))
         (re (format "^\\(-[ \t]+%s[ \t]+::[ \t]*\\).*$" (regexp-quote key))))
    (save-excursion
      (goto-char start)
      (if (re-search-forward re end t)
          (replace-match (concat "\\1" value) t)
        (goto-char start)
        (insert (format "- %s :: %s\n" key value))))))
#+end_src

*** Separating blank line

=sia-vulpea--ensure-blank-line-before-meta= inserts a newline before the meta block only if the preceding line is not already blank, which again keeps repeated runs idempotent.

#+begin_src emacs-lisp -i
(defun sia-vulpea--ensure-blank-line-before-meta ()
  "Ensure a blank line separates the node at point's property
drawer (and, for the file-level node, its #+KEYWORD: lines) from
the meta block that begins right after them -- see
`sia-vulpea--after-property-drawer-pos'. Only inserts a newline
if the line immediately before that position isn't already
blank, so re-running a conversion never piles up extra blank
lines."
  (save-excursion
    (goto-char (sia-vulpea--after-property-drawer-pos))
    (unless (or (bobp)
                (save-excursion (forward-line -1) (looking-at "^[ \t]*$")))
      (insert "\n"))))
#+end_src

*** Converting a node's properties

=sia-vulpea--convert-node-properties= walks the node's standard properties, skips blocklisted names and empty values, writes each remaining one as a meta line with a downcased key, and deletes it from the drawer unless =keep-original= is non-nil. It adds the separating blank line once if anything was converted and returns the list of converted property names.

#+begin_src emacs-lisp -i
(defun sia-vulpea--convert-node-properties (&optional keep-original)
  "Convert the node at point's own drawer properties to meta lines.
\"Node at point\" is the heading at or above point, or the
file-level node if point is before the first heading. Only
properties not in `sia-vulpea-convert-property-blocklist', and
with a non-empty value, are converted; the property name is
downcased for the meta key. Unless KEEP-ORIGINAL is non-nil, each
converted property is then deleted from the drawer. If anything
was converted, a blank line is inserted before the meta block
(once, however many properties were converted) to separate it
from the drawer/front matter above -- see
`sia-vulpea--ensure-blank-line-before-meta'. Returns the list of
property names converted (empty if none)."
  (save-excursion
    (unless (org-before-first-heading-p) (org-back-to-heading t))
    (let ((converted nil))
      (dolist (prop (org-entry-properties (point) 'standard))
        (let ((name (car prop)) (value (cdr prop)))
          (unless (or (member (upcase name) sia-vulpea-convert-property-blocklist)
                      (null value)
                      (string-empty-p value))
            (sia-vulpea--insert-or-update-meta-line (downcase name) value)
            (push name converted)
            (unless keep-original (org-entry-delete (point) name)))))
      (when converted
        (sia-vulpea--ensure-blank-line-before-meta))
      (nreverse converted))))
#+end_src

*** Fast pre-scan of a file

=sia-vulpea--file-has-convertible-properties-p= reads a file as plain text in a temporary buffer and looks for any =:NAME: value= line whose name is not =PROPERTIES=, =END= or blocklisted and whose value is non-empty. It does not start =org-mode=, so it is cheap. It may produce false positives (a matching line outside a drawer), which only cost an unneeded file visit later, but is meant never to miss a convertible file.

#+begin_src emacs-lisp -i
(defun sia-vulpea--file-has-convertible-properties-p (file)
  "Non-nil if FILE's raw text contains at least one property-drawer
line whose name isn't in `sia-vulpea-convert-property-blocklist'
and whose value is non-empty.

This is a fast, structure-agnostic text scan -- no `org-mode', no
Vulpea db -- meant only as a pre-filter before the real,
buffer-based conversion. It doesn't require FILE to actually be
visited or parsed as Org, just read as text, which is what makes
it cheap. A false positive here (matching something that isn't
really inside a drawer) just means a file gets opened for
nothing during the real pass, which is harmless -- so the regex
doesn't need to be a perfect drawer parser, only a conservative
one that never produces a false *negative*."
  (with-temp-buffer
    (insert-file-contents file)
    (goto-char (point-min))
    (catch 'found
      (while (re-search-forward
              "^[ \t]*:\\([A-Za-z_][A-Za-z0-9_-]*\\):[ \t]+\\(.+\\)$" nil t)
        (let ((name (match-string 1)) (value (match-string 2)))
          (unless (or (member (upcase name) '("PROPERTIES" "END"))
                      (member (upcase name) sia-vulpea-convert-property-blocklist)
                      (string-empty-p (string-trim value)))
            (throw 'found t))))
      nil)))
#+end_src

*** Converting a buffer

=sia-vulpea-convert-buffer-properties-to-meta= converts every node that has an =ID=: the file-level node first, then each heading via =org-map-entries=. Nodes without an ID are left alone. It saves the buffer afterwards, messages a count when called interactively, and returns =(ID . TITLE)= pairs for the nodes it changed. A prefix argument keeps the originals.

#+begin_src emacs-lisp -i
(defun sia-vulpea-convert-buffer-properties-to-meta (&optional keep-original)
  "Convert drawer properties to meta lines for every recognized node
in the current buffer -- the file-level node (if it has an :ID:)
and every heading with an :ID:, i.e. every node Vulpea/org-roam
actually indexes here. Saves the buffer afterwards. Returns a
list of (ID . TITLE) for every node that had at least one
property converted (empty if none)."
  (interactive "P")
  (let (converted-nodes)
    (save-excursion
      (goto-char (point-min))
      (when (org-entry-get (point-min) "ID")
        (when (sia-vulpea--convert-node-properties keep-original)
          (push (cons (org-entry-get (point-min) "ID") (sia-vulpea--node-title))

      (org-map-entries
       (lambda ()

      (message "Converted properties on %d node%s in this buffer"
               (length converted-nodes) (if (= (length converted-nodes) 1) "" "s")))
    (save-buffer)
    (nreverse converted-nodes)))
#+end_src

*** Duration formatting

=sia-vulpea--format-duration= formats a number of seconds as "2m 13s" or "45s" for the ETA display.

  "Return SECONDS formatted as e.g. \"2m 13s\" or \"45s\"."
  (let* ((secs (max 0 (round seconds)))

*** Cooperative file loop

=sia-vulpea--process-files-async= processes a list of files one at a time, visiting each with =find-file-noselect= and calling a per-file function in that buffer. After each file it schedules the next with a zero-second timer, which returns control to the command loop so redisplay happens and =C-g= works between files. The docstring is explicit that this is cooperative yielding, not true background work. A progress reporter shows N/TOTAL and an ETA from the average time per file, and =on-done= receives all results in order at the end. Visited buffers are left open.

#+begin_src emacs-lisp -i
(defun sia-vulpea--process-files-async (files per-file-fn label on-done)
  "Call PER-FILE-FN once per file in FILES, one at a time, without
freezing Emacs for the whole run.

Each file is handled, then the *next* one is scheduled via a
fresh zero-second timer instead of just continuing a tight
`dolist' loop -- that gap is what hands control back to Emacs's
command loop between files, so redisplay happens, `C-g' still
works, and the UI doesn't lock up. To be fully transparent about
what this is and isn't: stock Emacs has no threads that run
Elisp concurrently, so nothing here runs \"in the background\"
while you keep typing in another buffer -- it's cooperative
yielding, not true parallelism. (Emacs 26+ built with
`--with-threads' does have `make-thread', but Elisp execution
under it is still serialized by a global lock, so it wouldn't
actually speed this up or free the UI thread the way OS threads
would -- it's not used here.) What you do get is a UI that stays
responsive and interruptible for the whole duration of a large
batch, which a plain loop over hundreds of files would not give
you.

PER-FILE-FN is called with one file path, current-buffer already
that file's buffer (via `find-file-noselect'); its return value
is collected. LABEL is shown alongside a live N/TOTAL count and
an ETA, estimated from the average time per file so far. ON-DONE
is called with the list of all per-file return values, in the
same order as FILES, once every file has been processed."
  (let* ((total (length files))
         (reporter (make-progress-reporter (format "%s " label) 0 total))
         (start-time (current-time))
         (i 0)
         (results nil))
    (cl-labels
        ((step ()
           (if (null files)
               (progn
                 (progress-reporter-done reporter)
                 (funcall on-done (nreverse results)))
             (let ((file (pop files)))
               (push (with-current-buffer (find-file-noselect file)
                       (funcall per-file-fn file))
                     results)
               (setq i (1+ i))
               (progress-reporter-update
                reporter i
                (format " (%d/%d, ETA %s)" i total
                        (sia-vulpea--format-duration
                         (if (zerop i)
                             0
                           (* (/ (float-time (time-subtract (current-time) start-time)) i)
                              (- total i))))))
               (run-with-timer 0 nil #'step)))))
      (step))))
#+end_src

** Classifying backlinks

*** Meta key at a position

=sia-vulpea--line-meta-key-at= opens the source file (visiting it if needed), goes to the link's position and checks whether that line is a description-list item with a =KEY ::= tag. It returns the key, or nil when the link is in plain prose.

#+begin_src emacs-lisp -i
(defun sia-vulpea--line-meta-key-at (file pos)
  "If POS in FILE sits on a \"- KEY :: ...\" meta line, return KEY.
Otherwise return nil, meaning this link sits in plain prose (a
heading, a paragraph, anywhere that isn't a meta description-list
entry) rather than a structured meta property."
  (with-current-buffer (find-file-noselect file)
    (save-excursion
      (goto-char pos)
      (beginning-of-line)
      (if (looking-at "^[ \t]*-[ \t]+\\([A-Za-z0-9_-]+\\)[ \t]+::[ \t]")
          (match-string 1)
        nil))))
#+end_src

*** Grouping the links

=sia-vulpea-classify-backlinks= asks the Vulpea database for every link pointing at an ID and, for each, looks up the source note and the meta key at the link's position. Notes are collected in a hash table under the key or under Mentions, then returned as an alist of group name and deduplicated notes. The long docstring (which contains a blank line, hence two units) records the assumption that each link is a plist with =:source= and =:pos=, and says those two =plist-get= calls are what to change if the real shape differs.

#+begin_src emacs-lisp -i
(defun sia-vulpea-classify-backlinks (id)
  "Return an alist of (GROUP . NOTES) for every note linking to ID.
GROUP is \"Mentions\" for a plain inline/body link, or the
meta-property key name (e.g. \"pub-author\") for a link found on
a \"- KEY :: [[id:...]]\" line -- see `sia-vulpea--line-meta-key-at'.
NOTES is a deduplicated list of `vulpea-note' structs: the source
of each such link.

This relies on `vulpea-db-query-links-to' returning link plists
with at least :source (a note ID) and :pos (a buffer position in
the source file). I've seen this shape referenced in Vulpea's own
db/changelog material, but haven't been able to confirm it
against a live Emacs session -- if this errors for you, `C-h f
vulpea-db-query-links-to' will show the real return shape, and
the two `plist-get' calls below are the only things that would
need adjusting."
  (let ((groups (make-hash-table :test #'equal)))
    (dolist (link (vulpea-db-query-links-to id))
      (let* ((source-id (plist-get link :source))
             (pos (plist-get link :pos))
             (source-note (and source-id (vulpea-db-get-by-id source-id))))
        (when (and source-note pos)
          (let* ((key (sia-vulpea--line-meta-key-at (vulpea-note-path source-note) pos))
                 (group (or key "Mentions")))
            (puthash group (cons source-note (gethash group groups)) groups)))))
    (let (result)
      (maphash
       (lambda (group notes)
         (push (cons group
                     (seq-uniq notes (lambda (a b)
                                       (equal (vulpea-note-id a) (vulpea-note-id b)))))
               result))
       groups)
      result)))
#+end_src

* sp-vulpea-split.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/vulpea/sp-vulpea-split.el
:END:

This module provides =sp-split-leave-parents=, a wrapper around Vulpea's =vulpea-split-heading= that turns the heading at point into its own note file while keeping the link structure of the notes intact. Compared with the plain split, it records where the note came from in a =parents= meta line, leaves a link to the new note in the source file, renames the new file with Denote's naming scheme, and makes sure footnotes still resolve on both sides of the split.

It depends on =vulpea=, =org-id= and =denote= (version 3 or later), and it hooks into =vulpea-split--write-file=, a private Vulpea function, so a Vulpea update that renames or reshapes that function can break it; the module warns at load time if the function is missing. It is required from =sp-vulpea-ext=. The command is bound to ~C-x s t~ in =org-mode-map= by =sp-org-base=; note that this makes ~C-x s~ a prefix key in Org buffers, which shadows =save-some-buffers= there.

The commentary at the top of the module says:

#+begin_quote
`sp-split-leave-parents' wraps `vulpea-split-heading'.  On top of the
normal split it:

1. Adds a `- parents :: [[id:...][Title]]' meta line to the new note,
   pointing at the note the heading came from.  The source is the
   nearest ancestor heading with an ID, else the file-level note (its
   ID is created when missing).  When the subtree already has a
   `parents' line, the new link is put in front of the old value,
   separated by a comma.

2. Leaves a plain link to the new note in the source file, as a line
   of body text exactly where the heading started (not a heading).
   With a prefix argument no link is left.

3. Renames the new file with Denote's file-naming scheme
   (`ID--title__keywords.org'), using `denote-rename-file', so split
   notes are named like the rest of your Denote files, and adds a
   matching `#+identifier:' line.  The note keeps its org ID, so
   links are unaffected.  Disable with
   `sp-split-denote-names'.

4. Keeps footnotes working across the split (see
   `sp-split-check-footnotes').  Org labels are unique per file and
   this setup uses no footnote section, so a heading that moves away
   from its definitions would lose its sources.  Every heading that
   cites a footnote gets its own copy of the definition, at the end
   of its own text, in the new note, and in the source note for
   definitions that left with the subtree.  Copies after the first
   get a suffixed label (`[fn:smith]', `[fn:smith-2]', ...).

Steps 1, 2 and 4 hook `vulpea-split--write-file', a private function of
vulpea, and only act while `sp-split-leave-parents' is running.  A
plain `vulpea-split-heading' is unchanged.
#+end_quote

*** Finding the parent note

=sp-split--parent-link= finds where the heading with ID lives. It visits the file, walks up the ancestor headings and takes the first one that has an ID property, using its heading text as title. If no ancestor has an ID, it falls back to the file-level note, creating a file-level ID with =org-id-get-create= when there is none (so the source file can be modified as a side effect), and uses the buffer title or the file name. Returns the parent ID together with a ready-made link.

#+begin_src emacs-lisp -i
(defun sp-split--parent-link (id)
  "Return (PARENT-ID . LINK) for the note the heading with ID lives in.
Walks up the ancestors of the heading and takes the first one with an
ID.  If none has one, falls back to the file-level note, creating its
ID when it is missing."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (when-let* ((pos (org-find-entry-with-id id)))
         (goto-char pos)
         (let (pid title)
           (while (and (not pid) (org-up-heading-safe))
             (when-let* ((x (org-entry-get (point) "ID")))
               (setq pid x
                     title (org-link-display-format
                            (org-get-heading t t t t)))))
           (unless pid
             (goto-char (point-min))
             (setq pid (or (org-entry-get (point-min) "ID")
                           (org-id-get-create))
                   title (or (and (fboundp 'vulpea-buffer-title-get)
                                  (vulpea-buffer-title-get))
                             (file-name-base path))))
           (cons pid (sp-split--link-to pid title))))))))
#+end_src

*** Adding the parent to the new note's body

=sp-split--body-with-parent= edits the text that will become the new note. It only looks at the part before the first child heading, so children keep their own parents lines. If a parents line already exists there, the new link is put in front of the old value with a comma, unless that parent is already listed. Otherwise a new parents line is added at the top, directly joined to an existing meta list or separated from ordinary text by a blank line. The comment about reading match data early guards against later calls clobbering it.

#+begin_src emacs-lisp -i
(defun sp-split--body-with-parent (body parent-id link)
  "Return BODY with LINK recorded in its `parents' meta line.
PARENT-ID is the id LINK points to."
  (let* ((case-fold-search nil)
         ;; Only the section before the first child heading: children
         ;; may carry `parents' lines of their own, which stay untouched.
         (top-end (or (string-match "^\\*+ " body) (length body)))
         (top (substring body 0 top-end))
         (rest (substring body top-end)))
    (cond
     ;; A parents line already exists: prepend the new link to its value.
     ((string-match
       "^\\([ \t]*[-+][ \t]+parents[ \t]+::[ \t]*\\)\\(.*\\)$" top)
      ;; Read everything out of the match data before calling anything
      ;; that may clobber it.
      (let* ((mb (match-beginning 0))
             (me (match-end 0))
             (prefix (match-string 1 top))
             (existing (string-trim (match-string 2 top))))
        (if (string-search (concat "id:" parent-id) existing)
            body
          (concat (substring top 0 mb)
                  prefix link
                  (if (string-empty-p existing)
                      ""
                    (concat ", " existing))
                  (substring top me)
                  rest))))
     (t
      (let ((line (concat "- parents :: " link)))
        (cond
         ((string-empty-p body) line)
         ;; Body opens with meta already: join that list.
         ((string-match-p "\\`[ \t]*[-+][ \t]+[^ \t\n]+[ \t]+::" body)
          (concat line "\n" body))
         (t (concat line "\n\n" body))))))))
#+end_src

** Footnotes

Org footnote labels are unique per file, and this setup keeps each definition at the end of the text of the heading that uses it rather than in a footnote section. Splitting a subtree off can therefore leave references without definitions on either side. In these functions a section means a heading's own text, up to the next heading of any level.

*** Background

The comment block introducing the footnote helpers, explaining the problem described above.

#+begin_src emacs-lisp -i
;;;; Footnotes
;;
;; Org footnote labels are unique per file.  Without a footnote section,
;; definitions sit at the end of the text of the heading that uses them,
;; so a split can strand references (definition left in the source) or
;; strand the source (definition left with the subtree).  Sections here
;; are a heading's own text: from the heading to the next heading of
;; any level, children excluded.
#+end_src

*** Scanning footnotes

=sp-split--fn-scan= parses the buffer with =org-element-parse-buffer= and returns three lists: the start positions of all headings, every standard reference with its label and position, and every definition with its label, position and full text. A labelled inline footnote counts as a definition and is rewritten into the standard definition form so it can be copied elsewhere.

#+begin_src emacs-lisp -i
(defun sp-split--fn-scan ()
  "Scan the accessible part of the current Org buffer for footnotes.
Return (HEADS REFS DEFS).  HEADS is the sorted list of heading start
positions.  REFS lists (LABEL BEGIN) for each standard reference
`[fn:LABEL]'.  DEFS lists (LABEL BEGIN TEXT) for each definition, TEXT
being the whole definition as `[fn:LABEL] ...'; a labelled inline
footnote `[fn:LABEL:...]' counts as a definition too."
  (let ((tree (org-element-parse-buffer))
        heads refs defs)
    (org-element-map tree 'headline
      (lambda (h) (push (org-element-property :begin h) heads)))
    (org-element-map tree '(footnote-reference footnote-definition)
      (lambda (el)
        (let ((label (org-element-property :label el))
              (begin (org-element-property :begin el)))
          (when label
            (if (eq (org-element-type el) 'footnote-definition)
                (push (list label begin
                            (string-trim-right
                             (buffer-substring-no-properties
                              begin (org-element-property :end el))))
                      defs)
              (let ((cb (org-element-property :contents-begin el))
                    (ce (org-element-property :contents-end el)))
                (if (eq (org-element-property :type el) 'inline)
                    (when (and cb ce)
                      (push (list label begin
                                  (format "[fn:%s] %s" label
                                          (string-trim
                                           (buffer-substring-no-properties
                                            cb ce))))
                            defs))
                  (push (list label begin) refs))))))))
    (list (sort heads #'<) (nreverse refs) (nreverse defs))))
#+end_src

*** Applying footnote edits

=sp-split--fn-apply= turns the planned additions (definitions to append at the end of given sections) into insertions with sensible blank-line spacing, merges them with the label replacements, and applies everything from the end of the buffer backwards so earlier positions remain valid.

#+begin_src emacs-lisp -i
(defun sp-split--fn-apply (heads adds edits)
  "Apply footnote changes to the current buffer.
ADDS maps a section to the definition texts to put at the end of it
\(newest first).  EDITS is a list of (POS LENGTH STRING) replacements.
Everything is positioned against the buffer as it is now, and applied
from the end so earlier positions stay valid."
  (dolist (a adds)
    (let* ((pos (sp-split--fn-section-end (car a) heads))
           (prefix (cond ((= pos (point-min)) "")
                         ((and (>= (- pos (point-min)) 2)
                               (string= (buffer-substring-no-properties
                                         (- pos 2) pos)
                                        "\n\n"))
                          "")
                         ((save-excursion (goto-char pos) (bolp)) "\n")
                         (t "\n\n")))
           (suffix (if (= pos (point-max)) "\n" "\n\n")))
      (push (list pos 0 (concat prefix
                                (mapconcat #'identity (reverse (cdr a)) "\n\n")
                                suffix))
            edits)))
  (dolist (e (sort edits (lambda (x y) (> (car x) (car y)))))
    (goto-char (car e))
    (delete-region (car e) (+ (car e) (cadr e)))
    (insert (nth 2 e))))
#+end_src

*** Fixing footnotes in the new note

=sp-split--fn-fix-body= works on the new note's body in a temporary Org buffer (with mode hooks delayed for speed). For each cited label it decides which heading sections need their own copy of the definition:
- if the definition is nowhere, neither in the body nor in the source, the label is recorded as dangling,
- if it is only in the source, every citing section gets a copy,
- if it is in the body but cited from several sections, the sections without a definition get a copy.

Each copy after the first gets a fresh suffixed label, and the references in that section are renamed to match (skipping the four characters of the opening bracket and fn colon to reach the label). It returns the new body, the number of copies and the dangling labels.

#+begin_src emacs-lisp -i
(defun sp-split--fn-fix-body (body source-defs)
  "Make the footnotes in BODY self-contained.
SOURCE-DEFS is an alist (LABEL . TEXT) of the source file's definitions.
A heading in BODY that cites a footnote gets its own copy of the
definition when the definition is not in BODY at all, or when the
footnote is cited from several headings and the heading has none of its
own.  Return (NEW-BODY COPIED DANGLING), DANGLING being the labels
cited but defined nowhere."
  (with-temp-buffer
    (delay-mode-hooks (org-mode))
    (insert body)
    (pcase-let* ((`(,heads ,refs ,defs) (sp-split--fn-scan))
                 (used (mapcar #'car defs))
                 (edits nil)
                 (adds nil)
                 (copied 0)
                 (dangling nil))
      (dolist (label (seq-uniq (mapcar #'car refs)))
        (let* ((mine (lambda (e) (equal (car e) label)))
               (rsecs (seq-uniq
                       (mapcar (lambda (r) (sp-split--fn-section (cadr r) heads))
                               (seq-filter mine refs))))
               (dsecs (mapcar (lambda (d) (sp-split--fn-section (cadr d) heads))
                              (seq-filter mine defs)))
               (text (or (nth 2 (assoc label defs))
                         (cdr (assoc label source-defs))))
               (needy (cond ((null text)
                             (push label dangling)
                             nil)
                            ;; Defined only in the source: every citing
                            ;; heading gets a copy.
                            ((null dsecs) rsecs)
                            ;; Defined here, cited from several headings:
                            ;; those without a definition get a copy.
                            ((cdr rsecs)
                             (seq-remove (lambda (s) (memql s dsecs)) rsecs))
                            (t nil))))
          (dolist (sec needy)
            (let ((new (sp-split--fn-fresh label used)))
              (push new used)
              (unless (equal new label)
                (dolist (r (seq-filter
                            (lambda (r)
                              (and (equal (car r) label)
                                   (eql (sp-split--fn-section (cadr r) heads)
                                        sec)))
                            refs))
                  ;; Skip `[fn:' to reach the label itself.
                  (push (list (+ (cadr r) 4) (length label) new) edits)))
              (push (sp-split--fn-def-with-label text new)
                    (alist-get sec adds nil nil #'eql))
              (setq copied (1+ copied))))))
      (sp-split--fn-apply heads adds edits)
      (list (string-trim-right (buffer-string)) copied (nreverse dangling)))))
#+end_src

*** Keeping footnotes in the source

=sp-split--fn-keep-in-source= handles the opposite direction. While the subtree is still in place, it finds definitions inside the subtree that are cited from headings outside it and copies them to each of those headings. The first citing heading can keep the original label because the original definition is about to leave with the subtree. Returns the number of definitions copied.

#+begin_src emacs-lisp -i
(defun sp-split--fn-keep-in-source (id)
  "Keep footnotes usable in the source once the subtree of ID is cut.
Definitions inside the subtree that headings outside it still cite are
copied to those headings.  Must run while the subtree is still in
place.  Return the number of definitions copied."
  (let ((copied 0))
    (when-let* ((note (vulpea-db-get-by-id id))
                (path (vulpea-note-path note)))
      (with-current-buffer (find-file-noselect path)
        (org-with-wide-buffer
         (when-let* ((pos (org-find-entry-with-id id)))
           (goto-char pos)
           (org-back-to-heading t)
           (let ((beg (point))
                 (end (save-excursion (org-end-of-subtree t t) (point))))
             (pcase-let* ((`(,heads ,refs ,defs) (sp-split--fn-scan))
                          (inside (lambda (p) (and (>= p beg) (< p end))))
                          (used (mapcar #'car
                                        (seq-remove
                                         (lambda (d) (funcall inside (cadr d)))
                                         defs)))
                          (edits nil)
                          (adds nil))
               (dolist (d (seq-filter (lambda (d) (funcall inside (cadr d)))
                                      defs))
                 (let* ((label (car d))
                        (outside (seq-filter
                                  (lambda (r)
                                    (and (equal (car r) label)
                                         (not (funcall inside (cadr r)))))
                                  refs))
                        (secs (seq-uniq
                               (mapcar (lambda (r)
                                         (sp-split--fn-section (cadr r) heads))
                                       outside))))
                   ;; The original goes away with the subtree, so the
                   ;; first citing heading may keep the label.
                   (dolist (sec secs)
                     (let ((new (sp-split--fn-fresh label used)))
                       (push new used)
                       (unless (equal new label)
                         (dolist (r (seq-filter
                                     (lambda (r)
                                       (eql (sp-split--fn-section (cadr r) heads)
                                            sec))
                                     outside))
                           (push (list (+ (cadr r) 4) (length label) new)
                                 edits)))
                       (push (sp-split--fn-def-with-label (nth 2 d) new)
                             (alist-get sec adds nil nil #'eql))
                       (setq copied (1+ copied))))))
               (sp-split--fn-apply heads adds edits)))))))
    copied))
#+end_src

*** Safe wrapper for the new note

=sp-split--fn-check-body= runs the body fix when footnote checking is on, records the result in the report, and on any error logs a message and returns the body unchanged, so a footnote problem never aborts the split.

#+begin_src emacs-lisp -i
(defun sp-split--fn-check-body (body id)
  "Return BODY, the body of the note split from ID, with footnotes fixed.
Never aborts the split: on an error BODY is returned unchanged."
  (if (not sp-split-check-footnotes)
      body
    (condition-case err
        (pcase-let ((`(,new ,copied ,dangling)
                     (sp-split--fn-fix-body body (sp-split--fn-source-defs id))))
          (setq sp-split--fn-report
                (list :into-new copied :dangling dangling))
          new)
      (error
       (message "sp-split: footnote check skipped: %s"
                (error-message-string err))
       body))))
#+end_src

*** Safe wrapper for the source

=sp-split--fn-after-write= runs the source-side copy with the same error protection and adds its count to the report.

#+begin_src emacs-lisp -i
(defun sp-split--fn-after-write (id)
  "Copy definitions leaving with the subtree of ID back into the source."
  (when sp-split-check-footnotes
    (condition-case err
        (setq sp-split--fn-report
              (plist-put sp-split--fn-report :into-source
                         (sp-split--fn-keep-in-source id)))
      (error
       (message "sp-split: footnote copy in source skipped: %s"
                (error-message-string err))))))
#+end_src

*** Reporting

=sp-split--fn-message= prints a summary in the echo area if anything was copied or any label was dangling; otherwise it stays silent.

#+begin_src emacs-lisp -i
(defun sp-split--fn-message ()
  "Report what the footnote check did, when it did anything."
  (let ((n (or (plist-get sp-split--fn-report :into-new) 0))
        (m (or (plist-get sp-split--fn-report :into-source) 0))
        (d (plist-get sp-split--fn-report :dangling)))
    (when (or (> n 0) (> m 0) d)
      (message "Footnotes: %d definition(s) copied into the new note, %d into the source%s"
               n m
               (if d
                   (format "; no definition found for: %s"
                           (string-join d ", "))
                 "")))))
#+end_src

** Hooking into Vulpea

*** Advice around the file writer

=sp-split--write-file-advice= wraps =vulpea-split--write-file= and passes straight through unless =sp-split-leave-parents= is running. When active, it receives the path, ID, title, heading, tags, properties and body of the note about to be written. At this point Vulpea has already validated the split and the subtree is still in the source, so it:
- finds the parent link,
- fixes footnotes in the body and adds the parents line,
- inserts the link in the source if wanted,
- calls the original writer, then copies footnotes back into the source.

If writing the new file fails, the inserted source link is removed again and the error is re-signalled, so the source is left as it was.

#+begin_src emacs-lisp -i
(defun sp-split--write-file-advice (fn &rest args)
  "Around advice for `vulpea-split--write-file'.
FN is the original function and ARGS its arguments: PATH ID TITLE HEAD
TAGS PROPERTIES BODY.  Does nothing unless `sp-split-leave-parents' is
running."
  (if (not sp-split--active)
      (apply fn args)
    (pcase-let ((`(,path ,id ,title ,head ,tags ,props ,body) args))
      ;; The subtree is still in the source file at this point, and
      ;; vulpea has already run its checks, so a refused split never gets
      ;; this far.
      (let* ((parent (sp-split--parent-link id))
             (body (sp-split--fn-check-body body id))
             (body (if parent
                       (sp-split--body-with-parent
                        body (car parent) (cdr parent))
                     body))
             (stub (when sp-split--want-link
                     (sp-split--insert-source-link id title))))
        (condition-case err
            ;; The subtree is still in the source once the file is
            ;; written, which is when its footnotes can be copied back.
            (prog1 (funcall fn path id title head tags props body)
              (sp-split--fn-after-write id))
          (error
           ;; Writing the new file failed: take the link back out.
           (when (and stub (marker-buffer (car stub)))
             (with-current-buffer (marker-buffer (car stub))
               (delete-region (car stub) (cdr stub))))
           (signal (car err) (cdr err))))))))
#+end_src

** Denote naming

*** Adding an identifier keyword

=sp-split--add-identifier= reads the Denote identifier from the file name and, if the file has no identifier keyword yet, inserts one after the filetags line or else after the title line, then saves. If neither line is present nothing is inserted.

#+begin_src emacs-lisp -i
(defun sp-split--add-identifier (path)
  "Add a `#+identifier:' line to the note at PATH, from its Denote file name.
Does nothing when the file already has one or its name carries no
Denote identifier.  The line goes after `#+filetags', else after
`#+title'."
  (when-let* ((ident (denote-retrieve-filename-identifier path)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (goto-char (point-min))
       (let ((case-fold-search t))
         (unless (re-search-forward "^#\\+identifier:" nil t)
           (goto-char (point-min))
           (when (or (re-search-forward "^#\\+filetags:.*$" nil t)
                     (re-search-forward "^#\\+title:.*$" nil t))
             (insert "\n#+identifier: " ident)))))
      (save-buffer))))
#+end_src

*** Renaming with Denote

=sp-split--denote-rename= renames the new note's file using =denote-rename-file=, with confirmations off and buffers saved, keeping the title written by the split and using the note's tags as keywords. Because the return value of that function is not relied on, the new name is found by comparing the directory listing before and after. It then adds the identifier keyword, tells Vulpea to forget the old path (using the private =vulpea-db--forget-file=), registers the new location with =org-id=, re-indexes the file, and returns the updated note. If no new file appears, the original note is returned unchanged.

#+begin_src emacs-lisp -i
(defun sp-split--denote-rename (note)
  "Rename the file of NOTE with Denote's naming scheme, then re-sync vulpea.
Return the note as vulpea knows it afterwards.  The org ID stays the
same, so id links keep working.  Denote's own `denote-rename-file' does
the naming (identifier, sluggified title, keywords from the tags); its
return value is not relied on, the new name is found by diffing the
directory."
  (let* ((old (vulpea-note-path note))
         (id (vulpea-note-id note))
         (dir (file-name-directory old))
         (before (directory-files dir nil directory-files-no-dot-files-regexp t)))
    ;; No prompts, and save the front matter Denote rewrites.
    (let ((denote-rename-confirmations nil)
          (denote-save-buffers t))
      ;; TITLE `keep-current' reads the `#+title' written by the split;
      ;; KEYWORDS are the note's tags; no signature, default date.
      (denote-rename-file old 'keep-current (vulpea-note-tags note) nil nil))
    (let ((new (car (seq-difference
                     (directory-files dir nil directory-files-no-dot-files-regexp t)
                     before #'string-equal))))
      (if (not new)
          note
        (let ((new-path (expand-file-name new dir)))
          (sp-split--add-identifier new-path)
          (vulpea-db--forget-file old)
          (org-id-add-location id new-path)
          (vulpea-db-update-file new-path)
          (message "Named with Denote: %s" new)
          (or (vulpea-db-get-by-id id) note))))))
#+end_src

** The command

*** sp-split-leave-parents

The interactive entry point, autoloaded. It binds the active flag, the link flag (off with a prefix argument) and a fresh report, then calls =vulpea-split-heading= interactively. =current-prefix-arg= is cleared so the prefix argument meant for this command does not also trigger Vulpea's own stub option. After the split it renames the file with Denote if enabled and prints the footnote summary. Bound to ~C-x s t~ in Org buffers by =sp-org-base=.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-split-leave-parents (&optional no-link)
  "Run `vulpea-split-heading', recording where the heading came from.
The new note gets a `- parents ::' line linking back to the note the
subtree was split out of, and the source note gets a plain link to the
new note on the line where the heading started.  The new file is then
renamed with Denote's naming scheme when `sp-split-denote-names' is
non-nil.  With a prefix argument NO-LINK, the link in the source is not
left."
  (interactive "P")
  (let* ((sp-split--active t)
         (sp-split--want-link (not no-link))
         ;; Keep vulpea's own stub option (the prefix argument) out of it.
         (current-prefix-arg nil)
         (sp-split--fn-report nil)
         (note (call-interactively #'vulpea-split-heading)))
    (prog1 (if (and note sp-split-denote-names)
               (sp-split--denote-rename note)
             note)
      (sp-split--fn-message))))
#+end_src

** Example query

*** Open questions in relevant literature notes

Selects all vulpea notes whose =relevance-factor= metadata is 4 or higher (notes without it count as 0), takes their files, and uses =org-ql-select= to return the headings in those files with the TODO keyword =OPENQ=. This is a top-level expression rather than a function, so it is meant to be evaluated by hand, for example with =C-x C-e=.

#+begin_src emacs-lisp -i
;;;; Computing the relevance of certain literature notes
(let* ((notes (vulpea-db-query
               (lambda (n)
                 (>= (or (vulpea-note-meta-get n "relevance-factor" 'number) 0) 4))))
       (files (mapcar #'vulpea-note-path notes)))
  (org-ql-select files '(todo "OPENQ")
                 :action #'org-get-heading))
