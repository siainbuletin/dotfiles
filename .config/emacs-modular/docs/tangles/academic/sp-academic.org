Literate source for the academic modules in =libraries/modules/academic/=. This one file tangles five =.el= files: the master module =sp-academic.el= and its four sub-modules =sp-bibprocess.el=, =sp-pdfprocess.el=, =sp-citations.el= and =sp-litnotes.el=. Each module keeps its own file and its own =provide=, and =sp-academic= still loads the others with =require=, so a profile only lists =sp-academic=. The =:tangle= path of each part is set in the =:header-args:emacs-lisp+:= property of its top-level heading (the =#+PROPERTY= line above is the default, for the master module); see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The files have no newline after their last line (except where noted). Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

* sp-academic.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/academic/sp-academic.el
:END:

This is the umbrella module for academic work. It loads four sub-modules (=sp-bibprocess=, =sp-pdfprocess=, =sp-citations= and =sp-litnotes=) so they can be enabled together, and then configures bibliography lookup and BibTeX handling directly: =biblio= for looking up references online, BibTeX citation-key generation, =org-ref= set up to insert =org-cite= citations, =helm-bibtex= paths, a few =citar= file options, the =citar-org-node= bridge, and the =binder= package for Scrivener-like manuscript work.

The long commentary is a roadmap more than a description. It lists planned pieces (DEVONthink integration, deep links into PDFs, semantic search over PDFs, paper fetching) and notes that literature notes are still made with =citar-denote= while =ROAM_REFS= handling goes through =vulpea-citar=. Bibliography files are expected under =~/bibliography/= and PDFs under =~/Documents/literature/=. The module appears in the default module list in =init.el= under Academic.

The file shows signs of accumulated config: BibTeX key settings are made twice with different values (the later ones win), and the =C-c w b b= binding points at a command that is not defined anywhere in the repository.

*** Showing cite keys in descriptive links

=org-ref-make-org-link-cite-key-visible= runs after =org-activate-bracket-links= highlights a link. When the link target starts with one of =org-ref-cite-types=, it removes the invisibility from the whole link and colours it with =org-ref-cite-color=, so the cite key stays visible even when the link has a description. It uses =-sort= from =dash= to try longer cite types first.

#+begin_src emacs-lisp -i
(defun org-ref-make-org-link-cite-key-visible (&rest _)
  "Make the org-ref cite link visible in descriptive links."

  (save-match-data
    (let ((s (match-string 1))
      (beg (match-beginning 0))
      (end (match-end 0))
      (cite-re (format "^\\(%s:\\)"
               (regexp-opt (-sort
                    (lambda (a b)
                      (> (length a) (length b)))
                    org-ref-cite-types))))
      cite-type)

      (when (and s (string-match cite-re s))
    (setq cite-type (match-string 1 s))
    (remove-text-properties beg end
                '(invisible))
    (add-text-properties
     beg end
     `(face (:foreground ,org-ref-cite-color)))))))
#+end_src

* sp-bibprocess.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/academic/sp-bibprocess.el
:END:

This module manages the BibTeX bibliography that the academic modules build on. It defines where the =.bib= files live (=sp-bibtex-dir=, =~/bibliography/= by default), keeps a list of them that is shared with Org's citation system (=org-cite-global-bibliography=) and with =citar= (=citar-bibliography=), configures the built-in =bibtex= mode for BibLaTeX, and adds commands to look up new entries online with the =biblio= package and to audit attachments.

It is not listed directly in the module profiles; instead =sp-academic= loads it with =require=. The second half of the file repeats the variable, the register command and the lookup helper verbatim under a "BIBLIOGRAPHY" heading, apparently pasted in from another source; the repeats are harmless (the later =defvar= is a no-op and the function bodies are identical) but could be removed.

  "Location of BibTeX files and attachments."
  :group 'spcustom
  :type 'directory)
#+end_src

*** List of BibTeX files

=sp-bibtex-files= is filled at load time with every =.bib= file in the directory whose name starts with a letter or digit, or left =nil= if the directory does not exist. The regular expression is loose (the =|= inside the brackets and the unescaped dot are matched literally or as any character) but works for ordinary names.

#+begin_src emacs-lisp -i
(defvar sp-bibtex-files
  (when (file-exists-p sp-bibtex-dir)
    (directory-files sp-bibtex-dir t "^[A-Z|a-z|0-9].+.bib$"))
  "List of BibTeX files. Use `sp-bibtex-register' to configure.")
#+end_src

*** Register BibTeX files

=sp-bibtex-register= rescans =sp-bibtex-dir= and sets =sp-bibtex-files=, =org-cite-global-bibliography= and =citar-bibliography= to the same list, then echoes the registered files. Run it after adding or removing a =.bib= file so citations and =citar= see the change.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-bibtex-register ()
  "Register the contents of the `sp-bibtex-dir' with `sp-bibtex-files`.
Use when adding or removing a BibTeX file from or to `sp-bibtex-dir'."
  (interactive)
  (when (file-exists-p sp-bibtex-dir)
    (let ((bib-files (directory-files sp-bibtex-dir t
				      "^[A-Z|a-z|0-9].+.bib$")))
      (setq sp-bibtex-files bib-files
  	    org-cite-global-bibliography bib-files
	    citar-bibliography bib-files)))
  (message "Registered:\n%s" (mapconcat #'identity sp-bibtex-files "\n")))
#+end_src

*** Combined biblio lookup

=sp--bibtex-combined-biblio-lookup= offers the backends known to =biblio= (such as CrossRef or arXiv) plus an extra "DOI" entry in one completion prompt. Choosing DOI asks for a DOI and inserts its BibTeX directly; any other backend starts an interactive =biblio-lookup= search. It relies on the internal =biblio--named-backends=.

#+begin_src emacs-lisp -i
(defun sp--bibtex-combined-biblio-lookup ()
  "Combines `biblio-lookup' and `biblio-doi-insert-bibtex'."
  (require 'biblio)
  (let* ((dbs (biblio--named-backends))
         (db-list (append dbs '(("DOI" . biblio-doi-backend))))
         (db-selected (biblio-completing-read-alist
                       "Backend:"
                       db-list)))
    (if (eq db-selected 'biblio-doi-backend)
        (let ((doi (read-string "DOI: ")))
          (biblio-doi-insert-bibtex doi))
      (biblio-lookup db-selected))))
#+end_src

*** bibtex

Configures the built-in =bibtex= mode: the BibLaTeX dialect, two extra optional fields offered when creating entries (=keywords= and =file= for attachments), and alignment of field values at the equals sign. =bibtex-aux-opt-alist= carries the same two fields; it used to be saved by Customize in =init.el= and is now set here. After =bibtex= loads it registers the bibliography files, and =C-c w b r= runs =sp-bibtex-register= at any time.

#+begin_src emacs-lisp -i
(use-package bibtex
  :ensure nil
  :custom
  (bibtex-dialect 'biblatex)
  (bibtex-user-optional-fields
   '(("keywords" "Keywords to describe the entry" "")
     ("file"     "Relative or absolute path to attachments" "" )))
  (bibtex-align-at-equal-sign t)
  (bibtex-aux-opt-alist
   '(("keywords" "Keywords to describe the entry" "")
     ("file" "Relative or absolute path to attachments" "")))
  :config
  (sp-bibtex-register)
  :bind
  (("C-c w b r" . sp-bibtex-register))
)
#+end_src

*** Insert a lookup into a bibliography

=sp-bibtex-biblio-lookup= picks the target =.bib= file: the only one if there is a single file, the current buffer if already in =bibtex-mode=, or a completion prompt otherwise. It opens that file, moves to the end, runs the combined lookup and saves. If no BibTeX files are registered it just reports that.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-bibtex-biblio-lookup ()
  "Insert Biblio search results into current buffer or select BibTeX file."
  (interactive)
  (if-let* ((current-mode major-mode)
	   sp-bibtex-files
	   (bibfiles (length sp-bibtex-files))
	   (bibfile (cond ((eq bibfiles 1) (car sp-bibtex-files))
			  ((equal major-mode 'bibtex-mode)
			   (buffer-file-name))
			  (t (completing-read
			      "Select BibTeX file:" sp-bibtex-files)))))
      (progn (find-file bibfile)
	     (goto-char (point-max))
	     (sp--bibtex-combined-biblio-lookup)
	     (save-buffer))
    (message "No BibTeX file(s) defined.")))
#+end_src

** Auditing attachments

Two reports that compare the files stored in =sp-bibtex-dir= against the =file= fields in the BibTeX entries.

*** Collect attachment paths from entries

=sp--bibtex-extract-attachments= re-registers the bibliography and scans each =.bib= file for =file = {...}= fields, splitting multiple attachments on semicolons and expanding each path relative to =sp-bibtex-dir=.

#+begin_src emacs-lisp -i
;; Search for missing BibTeX attachments and filenames
(defun sp--bibtex-extract-attachments ()
  "Extract attachment file names from BibTeX files in `sp-bibtex-dir'."
  (sp-bibtex-register)
  (let ((attachments '()))
    (dolist (bibtex-file sp-bibtex-files)
      (with-temp-buffer
        (insert-file-contents bibtex-file)
        (goto-char (point-min))
        (while (re-search-forward "file.*=.*{\\([^}]+\\)}" nil t)
          (let ((file-paths (split-string (match-string 1)
                                          "[[:space:]]*;[[:space:]]*")))
            (dolist (file-path file-paths)
              (push (expand-file-name (string-trim file-path)
                                      sp-bibtex-dir)
                    attachments))))))
    attachments))
#+end_src

*** Collect files on disk

=sp--bibtex-extract-files= lists every file under =sp-bibtex-dir= recursively, leaving out =.bib= and =.csl= files.

#+begin_src emacs-lisp -i
(defun sp--bibtex-extract-files ()
  "List files recursively in `sp-bibtex-dir', excluding `.bib' and `.csl'."
  (seq-remove (lambda (file)
                (or (string-suffix-p ".bib" file)
                    (string-suffix-p ".csl" file)))
              (mapcar 'expand-file-name
                      (directory-files-recursively sp-bibtex-dir ""))))
#+end_src

*** Files with no entry

=sp-bibtex-missing-files= reports files on disk that no BibTeX entry refers to, printing the count and each path to the =*Messages*= buffer.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-bibtex-missing-files ()
  "List BibTeX attachments not listed in a BibTeX file entry."
  (interactive)
  (let* ((files (sp--bibtex-extract-files))
         (attachments (sp--bibtex-extract-attachments))
         (missing (cl-remove-if
                   (lambda (f) (member f attachments)) files)))
    (message "%s files not registered in bibliography" (length missing))
    (dolist (file missing)
      (message file))))
#+end_src

*** Entries with no file

=sp-bibtex-missing-attachments= does the reverse: it lists attachment paths named in entries that do not exist on disk. The count message calls them "BibTeX files", although it is counting attachment paths. Both reports pass each path to =message= as a format string, so a file name containing a percent sign would be misprinted.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-bibtex-missing-attachments ()
  "List BibTeX file entries with missing attachment(s)."
  (interactive)
  (let* ((files (sp--bibtex-extract-files))
         (attachments (sp--bibtex-extract-attachments))
         (missing (cl-remove-if
                   (lambda (f) (member f files)) attachments)))
    (message "%s BibTeX files without matching attachment." (length missing))
    (dolist (file missing)
      (message file))))
#+end_src

** PDF metadata from Citar

*** Writing title and author into a PDF

=sia-citar-update-pdf-metadata= asks you to pick a reference with =citar-select-ref=, checks that =citar-library-paths= is set, and finds the PDF files attached to that key. If there is more than one it lets you choose. It takes the title from the bibliography and the author, falling back to the editor with " (ed.)" appended. It then copies the PDF into the backup directory and runs =exiftool= to overwrite the Title and Author fields in place.

The =let*= used to refer to =cite-key= (with a hyphen) although the argument is =citekey=, which signalled a void-variable error; it now uses =citekey=. One weakness remains: the shell command is built by string concatenation with single quotes, so a title containing an apostrophe or a path with spaces would break it.

#+begin_src emacs-lisp -i
;;;; Working with PDF metadata from citar
(defun sia-citar-update-pdf-metadata (citekey)
  (interactive (list (citar-select-ref)))
  (citar--check-configuration 'citar-library-paths)
  (unless citar-library-paths
    (user-error "Make sure `citar-library-paths' is non-nil"))
  (let* ((files (gethash citekey (citar-get-files citekey))))
    (unless files
      (user-error (format "There are no PDF files associated with %s" citekey)))
    (let ((file (or (unless (cdr files) (car files)) (completing-read "Please select a PDF file: " files)))
          (title (citar-get-value 'title citekey))
          (author (cond ((citar-get-value 'author citekey)
                         (citar-get-value 'author citekey))
                        ((citar-get-value 'editor citekey)
                         (concat (citar-get-value 'editor citekey) " (ed.)")))))
      (progn
        (copy-file file sia-citar-library-backup-path 1)
        (call-process-shell-command
         (concat "exiftool -overwrite_original_in_place -Title='" title "' -Author='" author "' " file))))))
#+end_src

*** The oc package

Configures the built-in =oc= after Org loads. (use-package oc
  :ensure nil

          (latex csl)

  (org-cite-follow-processor 'citar)

)

*** Citar

Citar provides completing-read based selection of bibliography entries. Under =:custom= it sets the bibliography for both Org-cite and Citar to =sp-bibliography= (overriding the =sp-bibtex-files= value used above when Citar loads), repeats the processor settings, makes Embark the at-point action, adds DOI and URL as extra fields, and defines the display templates, with the note template taken from =sp-citar-note=.

Keybindings: ~C-c w b o~ runs =citar-open= globally, and ~C-c b~ in Org buffers runs =org-cite-insert=. Citar completion at point is added to LaTeX, Org and Markdown buffers.

A *gotcha*: the =when= form setting =citar-symbols= and the =setq= of =citar-notes-paths= are written inside =:custom=, which expects pairs of variable and value. use-package will treat them as attempts to customise variables literally named when and setq, so the icons and notes path are most likely never applied. They would work if moved to =:config=.

#+begin_src emacs-lisp -i
;;;; Citar
;; Do you really need to make use of citar?
(use-package citar
  :ensure t
  :commands (citar-open-notes
             citar-insert-citation)
  
  :custom
  ;; Use with org citation
  (org-cite-global-bibliography `(,sp-bibliography))
  (citar-bibliography `(,sp-bibliography))
  (org-cite-insert-processor 'citar)
  (org-cite-follow-processor 'citar)
  (org-cite-activate-processor 'citar)
  
  ;; Working at point
  (citar-at-point-function 'embark-act) ;; use embark with at-point

  (citar-additional-fields 
    '("doi"
      "url"))   ;; What exactly can you do with these additional fields?

  (citar-templates
        `((main . " ${=key= id:15} ${title:48}")
          (suffix . "${author editor:30}  ${=type=:12}  ${=beref=:12} ${tags keywords:*}")
          (preview . "${author editor} (${year issued date}) ${title}, ${journal journaltitle publisher container-title collection-title}.\n")
          (note . ,sp-citar-note)))

  (when (display-graphic-p)
    ;; nerd-icons has no octicon PDF/text glyph, so those two use
    ;; FontAwesome; link-external maps to the octicon directly.
    (setq citar-symbols
          `((file ,(nerd-icons-faicon  "nf-fa-file_pdf_o"     :face 'error)   . " ")
            (note ,(nerd-icons-faicon  "nf-fa-file_text_o"    :face 'warning) . " ")
            (link ,(nerd-icons-octicon "nf-oct-link_external" :face 'org-link) . " "))))
  ;; edit notes
  (setq citar-notes-paths `(,sp-bib-notes))

  :bind
         (("C-c w b o" . citar-open))
         (:map org-mode-map :package org ("C-c b" . #'org-cite-insert))
         
         :hook
         (LaTeX-mode . citar-capf-setup)
         (org-mode . citar-capf-setup)
         (markdown-mode . citar-capf-setup)
)

* sp-litnotes.el
:PROPERTIES:
:header-args:emacs-lisp+: :tangle ../../../libraries/modules/academic/sp-litnotes.el

This academic module connects bibliography entries to notes. =citar-denote= creates one Denote file per reference (file-level literature notes) in a =litnotes= subdirectory, and =citar-vulpea= supports literature notes as Vulpea nodes inside larger files. Both mark notes with the =litnote= keyword.

It builds on Citar (configured in the citation module) and on Denote and Vulpea. It is required by =sp-academic=. The =C-c w b= prefix holds the literature-note keys.

** File-level literature notes

*** citar-denote

Installs and enables =citar-denote-mode=, which makes Citar use Denote files as notes, and has Citar always create a note when you open notes for a reference that has none. Global keys: =C-c w b c= creates a note, =C-c w b n= opens one, and =C-c w b x= adds a nocite reference. In Org buffers, =C-c w b k= and =C-c w b K= add or remove a citekey from the current note, =C-c w b d= runs the do-what-I-mean command, and =C-c w b e= opens the bibliography entry.

#+begin_src emacs-lisp -i

;;; Commentary:

  :init
