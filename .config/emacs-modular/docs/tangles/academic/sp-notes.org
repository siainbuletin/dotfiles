A small module for a Denote-based notes workflow, adapted from Lambda Emacs. It provides a command that creates a dated workbook entry with Denote, sets up =consult-notes= to search Denote notes, and adds a variant that shows the consult-notes picker in a buffer window instead of the minibuffer.

It needs =denote= (configured in =sp-denote=) and installs =consult-notes=. The comments make clear the workflow has largely moved to ID-based notes with vulpea and org-node, so this module is partly kept for older material. It is loaded in the Academic section of =init.el=. Related bindings live in =sp-keys=, which puts =sp-denote-workbook-create-entry=, =consult-notes= and =consult-notes-search-in-all-notes= on the =n= notes prefix, and =sp-workspaces= calls =sp-denote-notebook=.

* Workbook entries

** sp-denote-workbook-create-entry

Creates a Denote note tagged =workbook= whose title is today's date (for example =2022 Tuesday 14 June=) inside the =workbook= folder of the first Denote directory. As the comment explains, =denote-directory= can now hold several trees, so the folder is built from the first entry of =denote-directories= instead of concatenating strings.

The docstring says it is superseded by =sp-denote-log-entry=, but kept because old entries live in =workbook/=. After creating the note it calls =sp-insert-header-and-time-property=, which is not defined anywhere in this repository, so the command ends with an error after the note is created unless that function comes from outside the repo.

#+begin_src emacs-lisp -i


(defun sp-denote-workbook-create-entry ()
  "Create an entry tagged \\='workbook\\=' with the date as its title.
Superseded by `sp-denote-log-entry' in the user layer, which writes into
log/ instead. Kept because old entries still live in workbook/."
  (interactive)
  (denote
   (format-time-string "%Y %A %e %B")   ; format like Tuesday 14 June 2022
   '("workbook")
   nil
   ;; `denote-directory' holds a list of trees, so the old
   ;; (concat denote-directory "workbook") is a type error here. The workbook
   ;; belongs to the notes tree, which denote returns as the first entry.
   (expand-file-name "workbook" (car (denote-directories)))
   nil
   nil)
  (sp-insert-header-and-time-property))
#+end_src

* Consult notes

** consult-notes

Installs =consult-notes=, a consult interface for picking and searching notes. =C-c w d f= opens the picker and =C-c w d g= searches the text of all notes. Enabling =consult-notes-denote-mode= registers Denote as a source; without a source the picker would be empty. A commented-out =:if= line explains it was not gated because the package should always be available.

#+begin_src emacs-lisp -i
;;;; Consult Notes
;; Adapted from https://github.com/minad/consult/wiki/hrm-notes
;; this is taken from Lambda Emacs
(use-package consult-notes
  :ensure t
  ;; :if (locate-library "consult-notes") ;; I find that it makes the startup a lot slower if I have this turned on, it's not an extra, I want to be able to have it on hand.
  ;; :after consult
  
  :commands
  (consult-notes
             consult-notes-search-in-all-notes)

  :bind
  (("C-c w d f" . consult-notes)
   ("C-c w d g" . consult-notes-search-in-all-notes))

  :config
  ;; Without a source, consult-notes shows an empty picker. The denote
  ;; source lists everything under `denote-directory'.
  (consult-notes-denote-mode 1)
)
#+end_src

** Notebook view

=sp-denote-notebook= runs =consult-notes= with =vertico-buffer-display-action= bound so that, when Vertico is shown in a buffer, the candidates reuse an existing window rather than the minibuffer. The comment notes that Denote is used less now and that an ID-based version would need a different consult plugin.

#+begin_src emacs-lisp -i
;; Creating a notebook is a much more useful way of using consult-notes,
;; instead of the minibuffer. However, I don't make much use of denote
;; anymore, as I prefer having IDs.
;;
;; The better option would be adapting this to the ID-based workflow
;; by making it query IDs.
;; 
;; But this means making use of a different consult plugin.
(defun sp-denote-notebook ()
  "Open `consult-notes in buffer window rather than minibuffer."
  (interactive)
  (let ((vertico-buffer-display-action
         '(display-buffer-reuse-window)))
    (consult-notes)))
#+end_src
