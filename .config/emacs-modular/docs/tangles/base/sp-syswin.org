- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../tangling-instructions.org][Tangling instructions]].

Platform tweaks for running Emacs natively on Windows.

- A guarded block of three =w32-= variables speeds up subprocess communication and file access.
- The Windows entry of the light or dark appearance that =sp-theme-auto-mode= follows (see [[file:../ui/sp-themes.org][sp-themes.org]]), the counterpart of the ones in =sp-macos= and =sp-syslinux=, so the configuration can be used on Windows, Linux and macOS interchangeably.
- The rest is commentary carried over from Lambda-Emacs suggesting WSL as an alternative.

The module is loaded from =init.el=, and everything in it is wrapped in a =system-type= check, so it is harmless on macOS or Linux.

The commentary at the top of the module says:

#+begin_quote
This is the specialized module for dealing with launching Emacs on Windows. Because of issues
with the way that Windows accesses the native binaries for Emacs, it might be a better idea to
run Emacs within WSL.

Lambda-Emacs is developed on macOS and Linux; Windows works but needs a little more care. Put
git (and ideally ripgrep) on your Windows PATH, expect the first-run compilation to take
noticeably longer, and prefer a recent official Emacs build with native compilation. Restarting
Emacs to resume installation usually clears transient build failures.
https://codeberg.org/Lambda-Emacs/lambda-emacs#headline-10
#+end_quote

* Settings

** Faster pipes and file attributes on Windows

Only on =windows-nt=, =cygwin= or =ms-dos=:

- =w32-pipe-read-delay= is set to 0, so Emacs does not wait before reading subprocess output.
- =w32-get-true-file-attributes= is turned off, to avoid expensive file ownership lookups.
- =w32-pipe-buffer-size= is raised to 128 KB, so subprocess output is read in bigger chunks.

These help tools like LSP servers and ripgrep. The block ends with the =provide= form.

#+begin_src emacs-lisp -i
(when (memq system-type '(windows-nt cygwin ms-dos))
  (setq w32-pipe-read-delay 0                 ; Faster IPC
        w32-get-true-file-attributes nil      ; Decrease file IO workload
        w32-pipe-buffer-size (* 128 1024)))   ; Read more at a time


#+end_src

** The Windows appearance

Windows keeps the setting "Choose your default app mode" in the registry, as =AppsUseLightTheme= under =HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize=: =0x0= is dark and =0x1= is light. It is read with =reg query=, which ships with Windows.

Windows does not tell Emacs when the setting changes, so there is no watcher here and =sp-theme-auto-mode= polls with its timer (=sp-theme-auto-interval=). When the value cannot be read, the result is nil and the theme follows the time of day.

#+begin_src emacs-lisp -i
;;;; Windows appearance
(defconst sp-syswin--personalize-key
  "HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Themes\\Personalize"
  "The registry key that holds the app mode.")

(defun sp-syswin--parse-registry (output)
  "Return `light', `dark' or nil from the `reg query' OUTPUT."
  (when (string-match "AppsUseLightTheme[ \t]+REG_DWORD[ \t]+0x\\([0-9a-fA-F]+\\)" output)
    (if (zerop (string-to-number (match-string 1 output) 16)) 'dark 'light)))

(defun sp-syswin-appearance ()
  "Return the Windows app mode, `light' or `dark', or nil if unknown."
  (when (and (memq system-type '(windows-nt cygwin ms-dos))
             (executable-find "reg"))
    (with-temp-buffer
      (when (zerop (call-process "reg" nil (list (current-buffer) nil) nil
                                 "query" sp-syswin--personalize-key
                                 "/v" "AppsUseLightTheme"))
        (sp-syswin--parse-registry (buffer-string))))))

;; Follow the app mode on Windows.
(when (and (memq system-type '(windows-nt cygwin ms-dos))
           (fboundp 'sp-theme-auto-mode))
  (sp-theme-auto-mode 1))

(provide 'sp-syswin)
;; sp-syswin.el ends here
#+end_src

* Tests

They tangle to =tests/sp-syswin-test.el= and run headless with =emacs -Q --batch -l tests/sp-syswin-test.el -f ert-run-tests-batch-and-exit= from the folder of =init.el=. They test the parsing of the registry output, not the registry.

#+begin_src emacs-lisp -i
;;; sp-syswin-test.el --- Tests for sp-syswin  -*- lexical-binding: t; -*-

;;; Code:

(require 'ert)
(load (expand-file-name
       "../libraries/modules/base/sp-syswin.el"
       (file-name-directory (or load-file-name buffer-file-name)))
      nil t)

(ert-deftest sp-syswin-test-registry ()
  (should (eq (sp-syswin--parse-registry
               "\nHKEY_CURRENT_USER\\...\\Personalize\n    AppsUseLightTheme    REG_DWORD    0x0\n")
              'dark))
  (should (eq (sp-syswin--parse-registry
               "    AppsUseLightTheme    REG_DWORD    0x1\n")
              'light))
  (should-not (sp-syswin--parse-registry "ERROR: not found")))

(ert-deftest sp-syswin-test-not-windows ()
  (unless (memq system-type '(windows-nt cygwin ms-dos))
    (should-not (sp-syswin-appearance))))

(provide 'sp-syswin-test)
;;; sp-syswin-test.el ends here
#+end_src
