Literate source for =libraries/modules/base/sp-syslinux.el=.

- Every =emacs-lisp= block below goes into that file, except blocks marked =:tangle no=.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

This module is the Linux counterpart of =sp-syswin=, which handles running Emacs on Windows.

- It is meant to hold settings that only apply when Emacs runs on Linux: paths, clipboard and desktop integration, or anything that should load only when =system-type= is =gnu/linux=.
- The purpose is inferred from the name and from =sp-syswin=.

Status:

- The =.el= file is empty for now, and nothing in =init.el= or =sp-config-profiles.el= loads it.
- The blocks below are a skeleton for when you fill it in.
- Tangling it now replaces the empty file with a valid module that loads and does nothing, so =(sp-require-module 'sp-syslinux)= would succeed.

* Configuration

How to add settings:

- Add the module's settings here, one heading per package or topic, each with an =emacs-lisp= block.
- The file's =#+PROPERTY= line already sends each block to =libraries/modules/base/sp-syslinux.el=, so a new block needs no header arguments.
- Keep the blocks above [[*Provide]] so they tangle before the =provide= form.

* Sandbox

A place to try out configuration before committing to it. Blocks here use =:tangle no=, so they never reach the =.el= file. When something works, move it into [[*Configuration]].

Write candidate settings in this block and evaluate them with =C-c C-c= to try them in the running Emacs.
