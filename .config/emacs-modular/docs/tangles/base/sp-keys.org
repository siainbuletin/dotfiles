Literate source for =libraries/modules/base/sp-keys.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module is the central place for keybindings in the config. Instead of scattering bindings across modules, almost every personal binding lives here, grouped into prefix maps under a single personal leader prefix, =sp-prefix= (=C-x C-SPC= by default). Bindings are made with =bind-keys= and =bind-key= from the =bind-key= library that ships with =use-package=, and with the built-in =keymap-global-set= for plain global keys.

Most of the bound commands are defined elsewhere: =sp-= helpers live in =sp-helper-funct= and other modules, while many targets come from third-party packages such as =consult=, =crux=, =magit=, =git-gutter=, =mu4e=, =denote=, =citar=, =tabspaces=, =ace-window= and =easysession=. A key whose command is not loaded yet simply errors when pressed. The module also installs =ironkey=, =hydra=, =use-package-hydra=, =which-key=, =helm-descbinds= and =keycast=, and defines two =transient= menus (ediff and rectangle editing).

The file has grown in layers: a curated, well-commented part under the leader prefix, followed after the "End keybindings" marker by an older collection of global bindings and package declarations, some of which duplicate earlier settings. It is loaded early in both the default and minimal module lists in =init.el=.

* Sensible-defaults style helpers

Small functions in the style of the sensible-defaults package. They only set bindings when called, and nothing in the repository appears to call the umbrella function, so these are likely inactive.

** Commenting with M-;

=sp-bind-commenting= rebinds =M-;= to =sp-comment-region-or-line=, which is defined in =sp-helper-funct=. It still uses the older =global-set-key= style.

#+begin_src emacs-lisp -i
(defun sp-bind-commenting ()
  "Comment or uncomment a region by hitting M-;."
  (global-set-key (kbd "M-;")
                  'sp-comment-region-or-line))
#+end_src

** Home and End keys

=sp-bind-home-and-end-keys= makes =<home>= and =<end>= move to the beginning and end of the line. The comment above it notes that this is redundant with =C-a= and =C-e= and should probably be removed.

#+begin_src emacs-lisp -i
;; this should be removed because I can already do C-a and C-e on Linux and MacOS to get
;; to the proper end of line.
(defun sp-bind-home-and-end-keys ()
  "Make <home> and <end> move point to the beginning and end of
the line, respectively."
  (keymap-global-set "<home>" 'move-beginning-of-line)
  (keymap-global-set "<end>" 'move-end-of-line))
#+end_src

** Enable all sensible-defaults bindings

=sensible-defaults/use-all-keybindings= calls the two helpers above. No caller was found in the config, so neither binding is applied unless this is invoked by hand.

#+begin_src emacs-lisp -i
(defun sensible-defaults/use-all-keybindings ()
  "Use all of the sensible-defaults keybindings."
  (sp-bind-commenting)
  (sp-bind-home-and-end-keys))
#+end_src

* Protected keys and bind-key

** ironkey

=ironkey= (installed from GitHub) protects selected global bindings from being shadowed by minor or major mode keymaps. =ironkey-iron-alist= lists =M-.= and the =C-x p= project prefix, both mapped to =nil=, which per the inline comments means "keep the global-map definition". =ironkey-update= runs on =after-init-hook= so it picks up bindings made during startup, and =ironkey-mode= is switched on.

#+begin_src emacs-lisp -i
;;;; ironkey setup
;; Protecting keybindings in certain keymaos
(use-package ironkey
  :ensure (:type git :host github :repo "JimDBh/ironkey")
  :demand t
  :hook 
  ((after-init . ironkey-update))
  
  :config
  (setq ironkey-iron-alist `((,(kbd "M-.") . nil) ;; command in global-map
                             (,(kbd "C-x p") . nil))) ;; prefix keymap in global-map
                             
  (ironkey-mode t))
#+end_src

** bind-key settings

=bind-key= is built in (it comes with =use-package=), so =:ensure nil=. Setting =bind-key-describe-special-forms= to =nil= keeps =describe-personal-keybindings= from printing lambda bodies and other special forms in full.

#+begin_src emacs-lisp -i
;;;;; Bind Key
;; Note that bind-key comes with use-package
(use-package bind-key
  :ensure nil
  :config
  (setq bind-key-describe-special-forms nil))
#+end_src

* Leader prefix

Everything personal hangs off one prefix so that it can be remapped in one place.

** The personal prefix

=sp-prefix= is a user option holding the prefix string for all personal keys, =C-x C-SPC= by default. Every prefix map below is built by appending a letter to this string.

#+begin_src emacs-lisp -i
;;;;; Personal Keybindings Prefix
(defcustom sp-prefix "C-x C-SPC"
  "Prefix for all personal keybinds."
  :type 'string
  :group 'sia-lambda)
#+end_src

** Leader keymap

=lem+leader-map= is meant as an overriding keymap for a modal-style leader key. Its declared =:type= is ='string= although the value is a keymap, which only matters if it is edited through Customize. The =bind-keys= call then installs this map as the prefix map on =sp-prefix=.

#+begin_src emacs-lisp -i
;;;;; Personal Leader Key

(defcustom lem+leader-map (make-sparse-keymap)
  "An overriding keymap for <leader> key, for use with modal keybindings."
  :type 'string
  :group 'sia-lambda)

;; Use sp-prefix as leader namespace
(bind-keys :prefix-map lem+leader-map
           :prefix sp-prefix)
#+end_src

** Version control (g)

The four =autoload= calls make the =git-gutter= commands callable before that package is loaded, since it is not declared as a package elsewhere; the comment explains the resulting error behaviour. =lem+vc-keys= then binds Magit status, commit, diff, log, blame and reflog, the merge picker's graph log (=m=, see [[file:../prog/sp-merge-pick.org][sp-merge-pick]]), the git-gutter hunk commands, and =vc-next-action= for a quick commit of the current file.

#+begin_src emacs-lisp -i
;;;;;; Version Control (Git) Keybindings
;; git-gutter is referenced by several bindings here but is not declared
;; in `sp-packages-alist'. Autoload the commands we bind so the keymap
;; entries are `commandp'-true even on a cold boot before the user
;; installs git-gutter; pressing the key without git-gutter installed
;; raises `file-missing' (not `void-function'), and once git-gutter is
;; on `package-user-dir' the autoload resolves the actual command.
(autoload 'git-gutter:popup-hunk    "git-gutter" "Show diff hunk in popup." t)
(autoload 'git-gutter:next-hunk     "git-gutter" "Move to next hunk."       t)
(autoload 'git-gutter:previous-hunk "git-gutter" "Move to previous hunk."   t)
(autoload 'git-gutter-mode          "git-gutter" "Toggle git-gutter-mode."  t)
;; `sp-merge-pick' loads late, after Emacs is idle; this opens its graph log.
(autoload 'sp-merge-pick-log        "sp-merge-pick" "Graph log for picking two commits." t)
(bind-keys :prefix-map  lem+vc-keys
           :prefix (concat sp-prefix " g")
           ("b" .  magit-blame                 )
           ("c" .  magit-commit                )
           ("d" .  magit-diff                  )
           ("h" .  git-gutter:popup-hunk       )
           ("l" .  magit-log                   )
           ;; show history of selected region
           ("L" .  magit-log-buffer-file       )
           ;; graph log in which to pick two commits to review or merge
           ("m" .  sp-merge-pick-log           )
           ("n" .  git-gutter:next-hunk        )
           ("p" .  git-gutter:previous-hunk    )
           ;; quick commit file
           ("q" .  vc-next-action              )
           ("r" .  magit-reflog                )
           ("s" .  magit-status                ))
#+end_src

* Which-key

Which-key is part of Emacs since version 29. This section configures it with plain =setq= forms; a second =use-package= declaration further down configures it again.

** Show which-key on C-h

=which-key-show-early-on-C-h= lets =C-h= after a prefix pop up the which-key buffer immediately instead of waiting for the idle delay.

#+begin_src emacs-lisp -i
;;;;; Which Key (built-in baseline)
;; EMACS-29+ built-in (which-key was merged into Emacs core in 29,
;; not 28). Raw top-level baseline -- C-6 forbids use-package
;; wrapping of built-in baselines. `which-key-mode' is autoloaded
;; in Emacs 29+, so the bare call resolves without an explicit
;; require.

** Popup delays

The comment explains the trade-off of the idle delay, citing a James Cherti article. The popup appears after 0.75 seconds, and once it has been shown, further prefix keys update it after only 0.05 seconds.

#+begin_src emacs-lisp -i
;; Delay for which-key
;; The which-key-idle-delay variable controls how long which-key-mode waits after a prefix
;; key is entered before displaying the available bindings.
;;
;; Reducing the delay makes key discovery appear sooner, but it also increases the likelihood
;; that a popup will appear during an ordinary key sequence. (For experienced users with
;; memorized prefixes, a longer delay can reduce visual interruptions.)
;; 
;; source: https://www.jamescherti.com/emacs-user-interface-better-responsiveness-and-latency/

(setq which-key-idle-delay 0.75)
(setq which-key-idle-secondary-delay 0.05)
#+end_src

** Rectangle region toggle

The comment describes the rectangle transient's lifecycle. =sp-rectangle-toggle-region= is a helper for that menu: if a region is active it deactivates the mark, otherwise it turns on =rectangle-mark-mode=.

  (interactive)
  (if (region-active-p)
      (deactivate-mark)

** Rectangle menu

=sp-rectangle-transient= is a persistent menu for rectangle editing. Movement, kill, yank, copy, open, string insert, clear, exchange point and mark, line numbering and undo all stay in the menu (=:transient t=); =g= quits. Its body enables =rectangle-mark-mode= on entry and adds a one-shot =transient-exit-hook= function that deactivates the mark and removes itself, so every exit path leaves a clean region. Like the ediff menu it has no key binding here.

#+begin_src emacs-lisp -i
(transient-define-prefix sp-rectangle-transient ()
  "Rectangle editing."
  ["Rectangle"
   ["Move"
    ("k" "Up"    rectangle-previous-line :transient t)
    ("j" "Down"  rectangle-next-line     :transient t)
    ("h" "Left"  rectangle-backward-char :transient t)
    ("l" "Right" rectangle-forward-char  :transient t)]
   ["Edit"
    ("d" "Kill"   kill-rectangle           :transient t)
    ("y" "Yank"   yank-rectangle           :transient t)
    ("w" "Copy"   copy-rectangle-as-kill   :transient t)
    ("o" "Open"   open-rectangle           :transient t)
    ("t" "Type"   string-rectangle         :transient t)
    ("c" "Clear"  clear-rectangle          :transient t)]
   ["Mark"
    ("e" "Exchange"     rectangle-exchange-point-and-mark :transient t)
    ("N" "Number lines" rectangle-number-lines            :transient t)
    ("r" "Toggle region" sp-rectangle-toggle-region      :transient t)]
   [""
    ("u" "Undo" undo                :transient t)
    ("g" "Quit" transient-quit-one)]]
  (interactive)
  (rectangle-mark-mode 1)
  (let (cleanup)
    (setq cleanup
          (lambda ()
            (when (region-active-p)
              (deactivate-mark))
            (remove-hook 'transient-exit-hook cleanup)))
    (add-hook 'transient-exit-hook cleanup))
  (transient-setup 'sp-rectangle-transient))
#+end_src
