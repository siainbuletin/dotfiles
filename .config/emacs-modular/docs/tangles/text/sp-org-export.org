Literate source for =libraries/modules/text/sp-org-export.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

This module configures how Org documents are exported. It sets general =ox= options, adds the =ox-pandoc= backend with a long menu of Pandoc output formats, provides helpers for exporting headings to separate files and for exporting the body as HTML to the clipboard, sets up =ox-hugo= with a custom =hugo:= link type, and defines a family of commands that convert the clipboard between Org, Markdown, LaTeX and RTF by piping it through Pandoc.

External programs matter here: =pandoc= for most conversions, LibreOffice for ODT to DOCX conversion, and the macOS tools =pbpaste=, =pbcopy=, =textutil=, =open= and AppleScript for the clipboard and Mail helpers, so much of the module is macOS-only. Some helpers depend on other modules (=sp-bibliography= from =sp-academic=, =sp-copy-whole-buffer-to-clipboard= from =sp-helper-funct=). Many functions come from the Lambda Emacs config (the =lem-= prefix). The module is loaded from =init.el= with the Org modules. A leading comment notes that the export settings should eventually be aligned with the author's typesetting setup.

** ox

Configures the built-in export framework once Org loads. It drops the default hyperref template in LaTeX export (see the linked Stack Exchange answer), exports tables to CSV by default, uses smart quotes, lets broken links pass instead of aborting the export, turns on debugging for async exports, removes the HTML postamble, and makes ODT export produce DOCX.

=sp-odt-org-convert-process= points =org-odt-convert-processes= at LibreOffice's =soffice= in headless mode, but only on macOS and only if LibreOffice is installed in =/Applications=. It is defined and run immediately in =:config=. The DOCX output setting depends on that converter being available.

#+begin_src emacs-lisp -i
;;;; Org Export
;; Useful base export settings
(use-package ox
  :ensure nil
  :after org
  
  :custom
  ;; Don't use bad hyperref value
  ;; https://emacs.stackexchange.com/a/46226/11934
  (org-latex-hyperref-template nil)
  
  ;; Export settings
  (org-table-export-default-format "orgtbl-to-csv") ;; export for org-tables to csv
  (org-export-with-smart-quotes t)
  (org-export-with-broken-links t)
  (org-export-async-debug t)
  (org-html-postamble nil) ;; dont export postamble
  (org-export-async-init-file nil)
  ;; (org-export-backends '(ascii beamer html icalendar latex odt pandoc hugo md))
  ;; org v8 bundled with Emacs 24.4
  (org-odt-preferred-output-format "docx")
  
  :config
  ;; Only OSX need below setup
  (defun sp-odt-org-convert-process ()
    (interactive)
    (let ((cmd "/Applications/LibreOffice.app/Contents/MacOS/soffice"))
      (when (and (eq system-type 'darwin) (file-exists-p cmd))
        ;; org v8
        (setq org-odt-convert-processes '(("LibreOffice" "/Applications/LibreOffice.app/Contents/MacOS/soffice --headless --convert-to %f%x --outdir %d %i"))))))
  (sp-odt-org-convert-process))

* Pandoc export

** ox-pandoc

Installs =ox-pandoc= and loads it when one of the listed export commands is first called. The path to =pandoc= is looked up when the options are applied, so if Pandoc is not on the path at that moment the command will be =nil=. Output is standalone by default except for DOCX, PDFs are produced with XeLaTeX, and Org input is read with the smart typography extension. A commented-out =:if= line would make the whole package conditional on Pandoc being available.

#+begin_src emacs-lisp -i
;;;; Org Export Extensions
;;;;; Ox-Pandoc
;; Export w/pandoc
(use-package ox-pandoc
  :ensure t
  ;; :if (executable-find "pandoc")
  :defer t  ;; Defer loading until needed for export
  :commands (org-pandoc-export-to-html5
             org-pandoc-export-to-html5-and-open
             org-pandoc-export-to-markdown
             org-pandoc-export-to-pdf
             org-pandoc-export-to-latex
             org-pandoc-export-to-docx)
  :custom
  (org-pandoc-command (executable-find "pandoc"))
  (org-pandoc-options '((standalone .  t)))
  (org-pandoc-options-for-docx '((standalone . nil)))
  (org-pandoc-options-for-beamer-pdf '((pdf-engine . "xelatex")))
  (org-pandoc-options-for-latex-pdf '((pdf-engine . "xelatex")))
  (org-pandoc-format-extensions '(org+smart)))

** Running a function on matching top-level headings

=lem-org-map-entries= reads an Org file into a temporary buffer and calls a function at every top-level heading that carries all the given tags. Tags can be given as a single string or a list. It is a simpler, file-based relative of =org-map-entries= taken from a Stack Exchange answer. Nothing in this module calls it.

#+begin_src emacs-lisp -i
;;;;;; Export Top Level Trees to File
;; From a useful [[https://emacs.stackexchange.com/questions/27226/how-to-export-top-level-trees-in-an-org-file-to-corresponding-files][stack exchange]] post
(defun lem-org-map-entries (org-file in-tags func)
  (let ((tags (if (stringp in-tags)
                  (list in-tags)
                in-tags)))

    (with-temp-buffer
      (org-mode)
      (insert-file-contents org-file)

      ;; Execute func at each heading that matches tags.
      (while (< (point) (point-max))

        ;; If find a heading...
        (and (search-forward-regexp "^\* " nil "end")

             ;; ...that matches the given tags...
             (seq-reduce
              (lambda(a b) (and a b))
              (mapcar
               (lambda (tag)
                 (beginning-of-line)
                 (search-forward-regexp
                  (concat ":" tag ":") (line-end-position) "end"))
               tags)
              t)

             ;; ... then execute given function with cursor at beginning of
             ;; heading.
             (progn
               (beginning-of-line)
               (save-excursion
                 (funcall func))
               (end-of-line)))))))
#+end_src

** Export to HTML and copy

=lem-org-export-to-buffer-html-as-body= exports the buffer to HTML in a =*Org HTML Export*= buffer, switches that buffer to =html-mode=, copies its contents to the clipboard and closes its window, then reports that the HTML was copied. Despite the name it exports the full document unless =body-only= is passed, which does not happen when it is called interactively. It calls =lem-copy-whole-buffer-to-clipboard=, which is not defined anywhere in this config (the config defines =sp-copy-whole-buffer-to-clipboard= instead), so the copy step will fail.

  "Export org buffer body to html"
  (interactive)
  (org-export-to-buffer 'html "*Org HTML Export*"
    async nil nil body-only ext-plist
    (lambda ()
      (html-mode)
      (lem-copy-whole-buffer-to-clipboard)))

** A hugo: link type

Defines an Org link type =hugo:= for links between pages of a Hugo site. When you insert such a link with completion, =org-hugo-link-complete= asks for a file and produces a Hugo =ref= shortcode with its relative path; following the link with =org-hugo-follow= opens that file. The link type is registered once Org loads.

#+begin_src emacs-lisp -i
;;;;;; Org-Hugo Links
;; New link type for Org-Hugo internal links
(defun org-hugo-link-complete ()
  "Create link with Hugo ref shortcode"
  (concat "{{% ref " (file-relative-name (read-file-name "File: ")) " %}}"))

(defun org-hugo-follow (link)
  (find-file (expand-file-name link)))

(with-eval-after-load 'org
  (org-link-set-parameters "hugo"
                           :complete 'org-hugo-link-complete
                           :follow 'org-hugo-follow))
#+end_src

* Clipboard conversion through Pandoc

These commands, carried over from Lambda Emacs's helper functions, read the macOS clipboard with =pbpaste=, convert it with Pandoc, put the result on the kill ring and paste it at point. They only work on macOS. Several docstrings were copied from a sibling command and describe the wrong conversion; the headings below describe what the code actually does.

** Org to Markdown

=sp-org-to-markdown= converts the clipboard from Org to Markdown and pastes it.

#+begin_src emacs-lisp -i
;;;; Clipboard conversion through Pandoc 
;; (initially lived in the file for functions in Lambda Emacs)
(defun sp-org-to-markdown ()
  "convert clipboard contents from org to markdown and paste"
  (interactive)
  (kill-new (shell-command-to-string "pbpaste | pandoc -f org -t markdown"))
  (yank))
#+end_src

** Resolving citations to Org

=sp-cite-to-org= is meant to run the clipboard through Pandoc with the user's bibliography so citations are rendered as formatted text, then convert the result to Org. It passes the value of =sp-bibliography= (a =defcustom= in =sp-academic=, =nil= until you set it) to =concat=. It used to pass the quoted symbol ='sp-bibliography=, which =concat= rejects, so it always signalled an error. Set =sp-bibliography= to the path of your =.bib= file first.

#+begin_src emacs-lisp -i
(defun sp-cite-to-org ()
  "convert clipboard contents from markdown to org with citations and paste"
  (interactive)
  (kill-new (shell-command-to-string (concat "pbpaste | pandoc --bibliography=" sp-bibliography " -s -t markdown-native_divs-raw_html-citations | pandoc -f markdown -t org")))
  (yank))
#+end_src

** Resolving citations to Markdown

=sp-cite-to-markdown= does the same but produces Markdown with ATX headings. It reads =sp-bibliography= in the same way, so it needs the variable set too.

#+begin_src emacs-lisp -i
(defun sp-cite-to-markdown ()
  "convert clipboard contents to markdown with citations and paste"
  (interactive)
  (kill-new (shell-command-to-string (concat "pbpaste | pandoc --bibliography=" sp-bibliography " -s -t markdown-native_divs-raw_html-citations --markdown-headings=atx")))
  (yank))
#+end_src

** BibTeX to YAML references

=sp-bibtex-to-yaml-reference= converts BibTeX on the clipboard into YAML reference metadata. It uses =pandoc-citeproc=, which has been removed from recent Pandoc releases. Because the output is piped back to =pbcopy=, the shell command returns nothing and the command pastes an empty string; the converted text ends up on the system clipboard instead.

#+begin_src emacs-lisp -i
(defun sp-bibtex-to-yaml-reference ()
  "convert clipboard bibtex contents to yaml and paste"
  (interactive)
  (kill-new (shell-command-to-string "pbpaste | pandoc-citeproc -y -f bibtex | pbcopy"))
  (yank))
#+end_src

** Markdown or Org to RTF

=sp-md-to-rtf= converts Markdown on the clipboard to RTF and puts it back on the clipboard; like the previous command it also yanks an empty string. =sp-org-to-rtf= converts Org to HTML with Pandoc and then to 14pt Helvetica RTF with the macOS =textutil= tool, so it can be pasted with formatting into other applications. The note above it says piping to =pbcopy= did not seem to work, although the result was ready to paste anyway.

#+begin_src emacs-lisp -i
(defun sp-md-to-rtf ()
  "convert md to rtf and send to clipboard"
  (interactive)
  (kill-new (shell-command-to-string "pbpaste | pandoc -f markdown -t rtf | pbcopy"))
  (yank))


;; NOTE: piping to pbcopy doesn't seem to work but it is ready to paste as is
(defun sp-org-to-rtf ()
  "convert org to rtf and send to clipboard"
  (interactive)
  (kill-new (shell-command-to-string "pbpaste | pandoc -f org -t html | /usr/bin/textutil -stdin -stdout -format html -convert rtf -fontsize 14 -font Helvetica | pbcopy")))
#+end_src

** Org to formatted Mail message

=sp-org-to-mail-rtf= is meant for composing email in Org: copy the buffer, convert it to RTF through HTML, kill the buffer, close the frame, and use AppleScript to paste into the Mail app if it is running. The first call is =(sp-copy-whole-buffer-to-clipboard)=, the helper from =sp-helper-funct=. It used to be written with a quote, as a quoted symbol in function position, which Emacs rejects as an invalid function, so the command failed before doing anything. Note that it closes the current frame unconditionally.

#+begin_src emacs-lisp -i
(defun sp-org-to-mail-rtf ()
  "copy buffer, convert clipboard contents from org to rtf, and send to mail message"
  (interactive)
  (sp-copy-whole-buffer-to-clipboard)
  ;; (kill-new (shell-command-to-string "pbpaste | pandoc -f org -t rtf"))
  (kill-new (shell-command-to-string "pbpaste | pandoc -f org -t html | /usr/bin/textutil -stdin -stdout -format html -convert rtf -fontsize 14 | pbcopy"))
  (kill-buffer)
  (delete-frame)
  (do-applescript "if application \"Mail\" is running then
      tell application \"Mail\"
      activate
      delay 0.35
      tell application \"System Events\"
      keystroke \"v\" using {command down}
      end tell
      end tell
      end if"))
#+end_src
