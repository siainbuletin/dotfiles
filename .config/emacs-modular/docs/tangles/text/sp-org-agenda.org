#+TITLE: sp-org-agenda.el and sp-agenda-views.el: Org agenda settings and views
#+STARTUP: content

Literate source for two modules: =libraries/modules/text/sp-org-agenda.el= (the agenda settings and helpers) and =libraries/modules/text/sp-agenda-views.el= (every custom agenda view). Every line of both modules lives in the =emacs-lisp= blocks below, in order. This file has no file-wide =#+PROPERTY= line for =:tangle=, because that would send every block to one file. Instead each top-level heading carries a =:header-args:emacs-lisp:= property in its own drawer, which says where the blocks under it are written, and the last heading, "Agenda views module", points at =sp-agenda-views.el=. See [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

Configures Org's agenda: the =C-c o a= key, the prefix format of agenda lines, visual styling of the time grid and tags, scheduling and sorting rules, the list of agenda files, and the =org-super-agenda= grouping. It also adds a command to jump to the daily view, automatic refresh of the agenda after a capture, and an alphapapa recipe for showing an agenda limited to the current subtree or region.

It is loaded in the Org section of both module lists in =init.el=, after =sp-org-capture=, and it installs =elegant-agenda-mode=, =org-super-agenda=, =org-ql= and =org-other-agenda=. The custom agenda views are no longer defined here: they live in =sp-agenda-views=, described at the end of this file, which =sp-org-ext= loads. =org-agenda-files= is also set in =sp-org-capture= and in =sp-denote='s save hook, so the effective list depends on load order.

** Agenda settings

Configures the built-in =org-agenda= library, loaded when =org-agenda= is first called. The agenda opens with log mode on, so clocked and closed items for the day are shown. =org-agenda-prefix-format= controls what precedes each line: in the main agenda an 18-character category column and a 10-character time slot, in TODO and tag lists just a space, and in search results an icon and a 12-character category. The format is taken from a Stack Overflow answer.

#+begin_src emacs-lisp -i
;;;; Org Agenda
;;;;; Agenda Settings
(use-package org-agenda
  :ensure nil
  :commands (org-agenda)
  :custom
  ;; Agenda logging
  (org-agenda-start-with-log-mode t)

  ;; from stack overflow https://stackoverflow.com/a/22900459/6277148
  ;; note that the formatting is nicer that just using '%b'
  (org-agenda-prefix-format
   '((agenda . " %-18c%?-10t ")
     (timeline . "  % s")
     (todo . " ")
     (tags . " ")
     (search . " %i %-12:c")))
)
#+end_src

** Refresh after capture

=lem-org-agenda-refresh= rebuilds the =*Org Agenda*= buffer if it exists, and it is added to =org-capture-after-finalize-hook= so a newly captured task appears in an open agenda immediately.

#+begin_src emacs-lisp -i
;;;;; Agenda Refresh
;; automatically refresh the agenda after adding a task
(defun lem-org-agenda-refresh ()
  (interactive)
  (when (get-buffer "*Org Agenda*")
    (with-current-buffer "*Org Agenda*"
      (org-agenda-redo)
      (message "[org agenda] refreshed!"))))
(add-hook 'org-capture-after-finalize-hook 'lem-org-agenda-refresh)
#+end_src

** Agenda styling

Stops Org from aligning tags, puts agenda tags right after the heading, uses two spaces between breadcrumbs, and replaces the block separator with a blank. The time grid shows hours from 08:00 to 20:00 every two hours with light dotted lines, only on today and only when there are timed items, and the current time is marked with a line ending in "Now".

#+begin_src emacs-lisp -i
;;; Appearance of the agenda and rendering
;; Agenda styling
  (setq org-auto-align-tags nil)            ;; Don't align tags
  (setq org-agenda-tags-column 0)           ;; Put tags next to heading
  (setq org-agenda-breadcrumbs-separator "  ")
  (setq org-agenda-block-separator " ")     ;; No default block seperator
  (setq org-agenda-time-grid
   '((daily today require-timed)
     (800 1000 1200 1400 1600 1800 2000)
     " ┄┄┄┄┄ " "┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄"))
  (setq org-agenda-current-time-string
   "–––––––––––––– Now")
#+end_src

** Scheduling and sorting

Done items are hidden from scheduled and timestamp entries. TODO lists hide tasks scheduled in the future and those with distant deadlines. Every view sorts by time ascending, and the calendar week starts on Monday.

#+begin_src emacs-lisp -i
;;; CONFIGURING THE FUNCTIONALITY
;; Scheduling with org-agenda

  (setq org-agenda-skip-scheduled-if-done t)
  (setq org-agenda-skip-timestamp-if-done t)
  (setq org-agenda-todo-ignore-scheduled 'future)
  (setq org-agenda-todo-ignore-deadlines 'far)
  (setq org-agenda-sorting-strategy
   '((agenda time-up) (todo time-up) (tags time-up) (search time-up)))
  (setq calendar-week-start-day 1) ;; Start week on Monday
#+end_src

** org-super-agenda groups

Installs =org-super-agenda= (waiting for it to be built) and sets its date format and groups: overdue DOING items first, then today's tasks (by date and by scheduled date, as two groups with the same name), then habits under "End of Day", then future TODOs, and DONE or CANCELED items last as "Accomplishments". The groups only apply when =org-super-agenda-mode= is enabled, and nothing in the config turns it on, so as it stands this grouping is not used.

#+begin_src emacs-lisp -i
;;; EXTENSIONS FOR ORG-AGENDA
(use-package org-super-agenda
:after org
  :ensure (:wait t)
:init
(setq org-super-agenda-date-format "%A (%e)"
      org-super-agenda-groups
      '((:name "Accomplishments"
         :todo ("DONE" "CANCELED")
         :order 4)
        (:name "End of Day"
         :habit t
         :order 2)
        (:name "Uncompleted Work"
         :todo "DOING"
         :scheduled past
         :order 0)
        (:name "Today's Tasks"
         :date today
         :order 1)
        (:name "Today's Tasks"
         :scheduled today
         :order 1)
        (:name "Future Work"
         :todo "TODO"
         :scheduled future
         :order 3))))
#+end_src

** org-ql

Installs =org-ql=, the Org query language, which can search Org files with structured queries and build agenda-like views from them. This is the install that =sp-vulpea-org-ql=, which calls =org-ql-select=, relies on. It sits right after =org-super-agenda= on purpose: =org-ql= requires =org-super-agenda=, and if it is declared first, Elpaca queues =org-super-agenda= as a dependency and warns =org-super-agenda previously queued as dependency of: (org-ql)= when the explicit declaration follows. See [[file:../../architecture/load-order.org][the load order]].

#+begin_src emacs-lisp -i
;; org-ql requires org-super-agenda, so it has to be declared after it:
;; the other way round, Elpaca queues org-super-agenda as a dependency first
;; and warns that the explicit declaration came too late.
(use-package org-ql
 :ensure t)
#+end_src

** sp-org-agenda-current-subtree-or-region

Shows a search agenda restricted to the current subtree, or to the active region extended to the end of its last subtree, with the header "Subtree" or "Region". With a prefix argument only TODO items are shown. It works from indirect buffers by operating in the base buffer, sorts by priority then timestamp, and removes the restriction lock afterwards. The inline note says that binding the sorting strategy around =org-search-view= appears to have no effect. The command has no keybinding in this module.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-org-agenda-current-subtree-or-region (only-todos)
  "Display an agenda view for the current subtree or region.
 With prefix, display only TODO-keyword items."
  (interactive "P")
  (let ((starting-point (point))
        header)
    (with-current-buffer (or (buffer-base-buffer (current-buffer))
                             (current-buffer))
      (if (use-region-p)
          (progn
            (setq header "Region")
            (put 'org-agenda-files 'org-restrict (list (buffer-file-name (current-buffer))))
            (setq org-agenda-restrict (current-buffer))
            (move-marker org-agenda-restrict-begin (region-beginning))
            (move-marker org-agenda-restrict-end
                         (save-excursion
                           ;; If point is at beginning of line, include
                           ;; heading on that line by moving forward 1.
                           (goto-char (1+ (region-end)))
                           (org-end-of-subtree))))
        ;; No region; restrict to subtree.
        (save-excursion
          (save-restriction
            ;; In case the command was called from an indirect buffer, set point
            ;; in the base buffer to the same position while setting restriction.
            (widen)
            (goto-char starting-point)
            (setq header "Subtree")
            (org-agenda-set-restriction-lock))))
      ;; NOTE: Unlike other agenda commands, binding `org-agenda-sorting-strategy'
      ;; around `org-search-view' seems to have no effect.
      (let ((org-agenda-sorting-strategy '(priority-down timestamp-up))
            (org-agenda-overriding-header header))
        (org-search-view (if only-todos t nil) "*"))
      (org-agenda-remove-restriction-lock t)
      (message nil))))
#+end_src

* Agenda views module
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../../../libraries/modules/text/sp-agenda-views.el :comments no :padline yes :noweb no :mkdirp yes

This heading and everything under it is written to =sp-agenda-views.el=, not =sp-org-agenda.el=. The module holds every custom agenda view in one place: the native views and the main PARA view from =vulpea-para= (which used to live in =sp-vulpea-para=). It is required by =sp-org-ext= right after =sp-vulpea-para=, because the PARA view needs =vulpea-para=. Views are added to =org-agenda-custom-commands= with =add-to-list=, so views that other modules add, such as the issue board of =sp-org-issues=, are kept.

** Native views

All these views are offered by the dispatcher, each added with =add-to-list= after any views that are already there. They used to be separate =setq= forms that replaced each other, which left only a single Daily Agenda view; the clashing keys are now distinct.
- =d= Dashboard: today's agenda, items due today, items due in the next five days, NEXT tasks and tasks tagged =email=.
- =p= Planning: tasks tagged =@planning=, untagged tasks, and unprocessed items from =~/notes/inbox.org=. An older, shorter =p= Planning view without the inbox section is dropped in favour of this one.
- =D= Daily Agenda: today with a seven-day deadline warning plus priority A tasks. It used to share the key =d= with Dashboard.
- =n= NEXT tasks, =W= tasks tagged =work=, and =e= low-effort NEXT tasks under 15 minutes.
- =w= Workflow Status: one section per workflow keyword (WAIT, REVIEW, PLAN, BACKLOG, READY, ACTIVE, COMPLETED, CANCELED).
- =R= Weekly Review: completed and unfinished scheduled tasks for the week. It used to share the key =w= with Workflow Status.
- =r= Research and university: tasks tagged =@research=, =@reading= or =@uni=. As written, the match string means =@research= and the other two tags combined, which may not be the intended "any of".
- =u= Untagged Tasks: tasks that have no tags.

(dolist (view
         '(("d" "Dashboard"
           ((agenda "" ((org-agenda-span 'day)))
           (tags-todo "DEADLINE=\"<today>\""
                     ((org-agenda-overriding-header "Due Today!")))
           (tags-todo "+DEADLINE<\"<+5d>\"+DEADLINE>\"<today>\""
                     ((org-agenda-overriding-header "Due Soon")))
           (todo "NEXT"
                ((org-agenda-overriding-header "Next Tasks")))
           (tags-todo "email" ((org-agenda-overriding-header "Email")))
             ))
        
           ("p" "Planning"
                ((tags-todo "+@planning"
                            ((org-agenda-overriding-header "Planning Tasks")))
                 (tags-todo "-{.*}"
                            ((org-agenda-overriding-header "Untagged Tasks")))
                 (todo ".*" ((org-agenda-files (list (sp-path sp-notes-dir "inbox.org")))
                             (org-agenda-overriding-header "Unprocessed Inbox Items")))))

           ("D" "Daily Agenda"
            ((agenda "" ((org-agenda-span 'day)

                ((org-agenda-overriding-header "Next Tasks")))))

        ("w" "Workflow Status"

                ((org-agenda-overriding-header "Waiting on External")

** Main PARA view

Adds a view bound to the space key in the agenda dispatcher, in front of the other views. It stacks vulpea-para's blocks: items to refile, today, focus items, stuck projects, waiting items, and the current quarter (built by calling a function at load time). It used to be defined in =sp-vulpea-para=.

#+begin_src emacs-lisp -i
;; Getting the custom agenda view for vulpea-para
(add-to-list 'org-agenda-custom-commands
             `(" " "Agenda"
               (,vulpea-para-agenda-cmd-refile
                ,vulpea-para-agenda-cmd-today
                ,vulpea-para-agenda-cmd-focus
