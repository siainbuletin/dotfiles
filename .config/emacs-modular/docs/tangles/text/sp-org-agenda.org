#+TITLE: sp-org-agenda.el and sp-agenda-views.el: Org agenda settings, views and keys
#+STARTUP: content

Literate source for two modules:

- =libraries/modules/text/sp-org-agenda.el=: the agenda settings and helpers.
- =libraries/modules/text/sp-agenda-views.el=: every custom agenda view and every agenda key.

How tangling works here:

- Every line of both modules lives in the =emacs-lisp= blocks below, in order.
- There is no file-wide =#+PROPERTY= line for =:tangle=, because that would send every block to one file.
- Instead each top-level heading carries a =:header-args:emacs-lisp:= property in its own drawer, saying where the blocks under it are written.
- The last heading, "Agenda views module", points at =sp-agenda-views.el=.
- To tangle, see [[file:../../tangling-instructions.org][Tangling instructions]].

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

Configures how Org's agenda looks and behaves. It covers:

- the prefix format of agenda lines,
- visual styling of the time grid and tags,
- scheduling and sorting rules,
- enabling =org-super-agenda= (its groups are set per view in =sp-agenda-views=).

It also adds:

- a command to jump to the daily view,
- automatic refresh of the agenda after a capture,
- an alphapapa recipe for showing an agenda limited to the current subtree or region.

What it no longer does:

- It no longer sets the list of agenda files. =vulpea-para= owns it; see =sp-vulpea-para= and [[file:../../../../../adr/0009-one-agenda-owner-per-setting.org][ADR 0009]].
- It no longer sets any key. All agenda keys are in =sp-agenda-views=.

Loading:

- Loaded early, in the Org section of both module lists in =init.el=.
- Installs =elegant-agenda-mode=, =org-super-agenda=, =org-ql= and =org-other-agenda=.
- The custom agenda views live in =sp-agenda-views=, described at the end of this file. It is one of the last Org modules to load.

** Agenda settings

Configures the built-in =org-agenda= library, loaded when =org-agenda= is first called.

- The agenda opens with log mode on, so clocked and closed items for the day are shown.
- =org-agenda-prefix-format= is the only definition of the prefix.
- Every kind of agenda line starts with vulpea-para's category (the Area and Project path, 36 characters wide).
- The main agenda adds the time slot and the scheduling information. Search results get an icon.
- It used to be set twice (here and in =sp-vulpea-para=), and the second assignment dropped the =tags= and =search= entries.
- All the other =org-agenda-= options of this module (styling, display and scheduling, described under /Appearance/ and /Behaviour/ below) are in the same =:custom= block. They used to be =setq= forms further down the file.

#+begin_src emacs-lisp -i
;;;; Org Agenda
;;;;; Agenda Settings
(use-package org-agenda
  :ensure nil
  :commands (org-agenda)
  :custom
  ;; Agenda logging
  (org-agenda-start-with-log-mode t)

  ;; The Area > Project category is evaluated when an agenda is built, so
  ;; vulpea-para does not have to be loaded yet.
  (org-agenda-prefix-format
   '((agenda . " %(vulpea-para-agenda-category 36) %?-12t %12s")
     (todo   . " %(vulpea-para-agenda-category 36) ")
     (tags   . " %(vulpea-para-agenda-category 36) ")
     (search . " %i %(vulpea-para-agenda-category 36) ")))
  (org-agenda-tags-column 0)  ;; Put tags next to heading
  (org-agenda-breadcrumbs-separator "  ")
  (org-agenda-block-separator " ")  ;; No default block seperator
  (org-agenda-time-grid
   '((daily today require-timed)
     (800 1000 1200 1400 1600 1800 2000)
     " ┄┄┄┄┄ " "┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄"))
  (org-agenda-current-time-string
   "–––––––––––––– Now")
  (org-agenda-tags-column org-tags-column)
  (org-agenda-show-inherited-tags nil)
  (org-agenda-window-setup 'only-window)
  (org-agenda-restore-windows-after-quit t)
  (org-agenda-skip-scheduled-if-done t)
  (org-agenda-skip-timestamp-if-done t)
  (org-agenda-todo-ignore-scheduled 'future)
  (org-agenda-todo-ignore-deadlines 'far)
  (org-agenda-sorting-strategy
   '((agenda time-up) (todo time-up) (tags time-up) (search time-up)))
)
#+end_src

** Refresh after capture

=lem-org-agenda-refresh= rebuilds the =*Org Agenda*= buffer if it exists, and it is added to =org-capture-after-finalize-hook= so a newly captured task appears in an open agenda immediately.

#+begin_src emacs-lisp -i
;;;;; Agenda Refresh
;; automatically refresh the agenda after adding a task
(defun lem-org-agenda-refresh ()
  (interactive)
  (when (get-buffer "*Org Agenda*")
    (with-current-buffer "*Org Agenda*"
      (org-agenda-redo)
      (message "[org agenda] refreshed!"))))
(add-hook 'org-capture-after-finalize-hook 'lem-org-agenda-refresh)
#+end_src

** Scheduling and sorting

Visibility and sorting. All but the last item are =:custom= entries of the =org-agenda= =use-package=; the week start is a Calendar variable, so it stays a =setq=:

- Done items are hidden from scheduled and timestamp entries.
- TODO lists hide tasks scheduled in the future and those with distant deadlines.
- Every view sorts by time ascending.
- The calendar week starts on Monday. That setting moved to [[file:../base/sp-globals.org][sp-globals]] as =sp-calendar-week-start-day=, and a comment in the code says so.

#+begin_src emacs-lisp -i
;;;; CONFIGURING THE FUNCTIONALITY
;; Scheduling with org-agenda

  (setq org-agenda-skip-scheduled-if-done t)
  (setq org-agenda-skip-timestamp-if-done t)
  (setq org-agenda-todo-ignore-scheduled 'future)
  (setq org-agenda-todo-ignore-deadlines 'far)
  (setq org-agenda-sorting-strategy
   '((agenda time-up) (todo time-up) (tags time-up) (search time-up)))
  ;; Moved to `sp-globals': `sp-calendar-week-start-day' (1, Monday).
#+end_src

** org-super-agenda

Installs =org-super-agenda= (waiting for it to be built), sets its date format and turns =org-super-agenda-mode= on.

- No groups are set globally: =org-super-agenda-groups= is nil, so every view is shown as Org builds it.
- A view that wants groups sets them in its own settings. The day agenda of =sp-agenda-views= does.
- Global groups would split every block of the PARA view, whose skip functions and sorting strategies assume a plain list.
- See [[file:../../../../../adr/0012-org-super-agenda-per-view.org][ADR 0012]].

#+begin_src emacs-lisp -i
;;;; EXTENSIONS FOR ORG-AGENDA
(use-package org-super-agenda
  :after org
  :ensure (:wait t)
  :init
  (setq org-super-agenda-date-format "%A (%e)")
  :config
  (org-super-agenda-mode 1))
#+end_src

** org-ql

Installs =org-ql=, the Org query language.

- It searches Org files with structured queries and builds agenda-like views from them.
- This is the install that =sp-vulpea-org-ql=, which calls =org-ql-select=, relies on.
- It sits right after =org-super-agenda= on purpose. =org-ql= requires =org-super-agenda=, and if it is declared first, Elpaca queues =org-super-agenda= as a dependency. It then warns =org-super-agenda previously queued as dependency of: (org-ql)= when the explicit declaration follows.
- See [[file:../../architecture/load-order.org][the load order]].

 :ensure t)

** sp-org-agenda-current-subtree-or-region

Shows a search agenda restricted to the current subtree, or to the active region extended to the end of its last subtree.

- The header is "Subtree" or "Region".
- With a prefix argument only TODO items are shown.
- Works from indirect buffers by operating in the base buffer.
- Sorts by priority, then timestamp.
- Removes the restriction lock afterwards.
- The inline note says that binding the sorting strategy around =org-search-view= appears to have no effect.
- The command has no keybinding in this module.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-org-agenda-current-subtree-or-region (only-todos)
  "Display an agenda view for the current subtree or region.
 With prefix, display only TODO-keyword items."
  (interactive "P")
  (let ((starting-point (point))
        header)
    (with-current-buffer (or (buffer-base-buffer (current-buffer))
                             (current-buffer))
      (if (use-region-p)
          (progn
            (setq header "Region")
            (put 'org-agenda-files 'org-restrict (list (buffer-file-name (current-buffer))))
            (setq org-agenda-restrict (current-buffer))
            (move-marker org-agenda-restrict-begin (region-beginning))
            (move-marker org-agenda-restrict-end
                         (save-excursion
                           ;; If point is at beginning of line, include
                           ;; heading on that line by moving forward 1.
                           (goto-char (1+ (region-end)))
                           (org-end-of-subtree))))
        ;; No region; restrict to subtree.
        (save-excursion
          (save-restriction
            ;; In case the command was called from an indirect buffer, set point
            ;; in the base buffer to the same position while setting restriction.
            (widen)
            (goto-char starting-point)
            (setq header "Subtree")
            (org-agenda-set-restriction-lock))))
      ;; NOTE: Unlike other agenda commands, binding `org-agenda-sorting-strategy'
      ;; around `org-search-view' seems to have no effect.
      (let ((org-agenda-sorting-strategy '(priority-down timestamp-up))
            (org-agenda-overriding-header header))
        (org-search-view (if only-todos t nil) "*"))
      (org-agenda-remove-restriction-lock t)
      (message nil))))
#+end_src

** Native views

Views offered by the dispatcher (the keys are in the table above):

- =d= Dashboard: today's agenda, items due today, items due in the next five days, NEXT tasks and tasks tagged =email=.
- =p= Planning: tasks tagged =@planning=, untagged tasks, and unprocessed items from =~/notes/inbox.org=.
- =D= Daily Agenda: today with a seven-day deadline warning, plus priority A tasks. Today's items are grouped with =org-super-agenda= (=sp-agenda-views-day-groups=, below).
- =l= Coming deadlines: the deadlines of the next 30 days. The splash screen opens it.
- =n= NEXT tasks, =W= tasks tagged =work=, and =e= low-effort NEXT tasks under 15 minutes.
- =w= Workflow Status: one section each for PROG, WAIT, REVIEW and ACTIVE.
  - The sections for PLAN, BACKLOG, READY, COMPLETED and CANCELED are removed. No keyword sequence defines those words, so they never matched anything.
- =R= Weekly Review: completed and unfinished scheduled tasks for the week.
- =r= Research and university: tasks tagged =@research=, =@reading= or =@uni=.
  - As written, the match string means =@research= and the other two tags combined, which may not be the intended "any of".
- =u= Untagged Tasks: tasks that have no tags.

The blocks that restrict =org-agenda-files= (the inbox section of Planning) bind =vulpea-para-agenda-inhibit-files-update=. The no-op =(org-agenda-files org-agenda-files)= settings of the old Workflow and Low Effort views are removed.

The groups of the Daily Agenda (=org-super-agenda=, set for that view only, see [[file:../../../../../adr/0012-org-super-agenda-per-view.org][ADR 0012]]), in order:

- overdue =PROG= or =DOING= items,
- today's tasks (by date and by scheduled date, as two groups with the same name),
- habits under "End of Day",
- future =TODO= items,
- finished items last, as "Accomplishments".

They are the groups that used to be set globally and never applied, with the keywords of =sp-org-keywords=.

** Issue views

The =i= prefix lists the open issues of the issue tracker.

- =sp-org-issues= provides the file through =sp-org-issues--agenda-files=. The views live here.
- =i i= is the issue board (in progress, next, waiting, open, in a buffer named =*Issues*=).
- =i b= lists the issues with a branch.
- They are added only when =sp-org-issues= is loaded.

#+begin_src emacs-lisp -i
(defconst sp-agenda-views-issues

** Config file views

=c= lists every open TODO heading in the Org files of the dotfiles (the yadm repository in =~=): the docs in =docs/tangles/=, =README.org=, =CHANGELOG.org=, the ADRs. Each line starts with the =#+title:= of the file it comes from, in a 36 character column, instead of the Area and Project category the other views show. The file title is the useful label here, because these files are not vulpea-para areas or projects, so they have no category of their own.

It solves the same problem as the issue views, scoping the agenda to one set of files, and copies the approach of [[file:../custom/sp-org-issues.org][=sp-org-issues=]] (its =sp-org-issues--agenda-files= and the =i i= / =i b= views). How it is built, the same way as the issue views:

- It restricts =org-agenda-files= to the config files and binds =vulpea-para-agenda-inhibit-files-update=, otherwise vulpea-para would put the PARA files back before the block runs.
- It uses a =todo= block with an empty match, so every open keyword counts, including the =#+todo:= keywords a file declares for itself. It names no keyword, but it still relies on =org-todo-keywords=: the empty match means "any keyword that is not a done state", and Org decides which words those are from each buffer's keywords (the global =org-todo-keywords= that =sp-org-keywords= sets, or a file's own =#+todo:= line). So a heading whose keyword is in neither list is not a TODO to the view, and a keyword in the done part of its sequence (DONE, CNCL) is left out.
- Only this view changes =org-agenda-prefix-format= (the =todo= entry), through the view's own settings. The global prefix in =sp-org-agenda= is untouched.
- =sp-agenda-views-file-title= reads the title straight from the buffer, with the buffer widened, and falls back to the file name. It runs with point on the entry, which is how the prefix format evaluates =%(...)=.

Where the files come from is the choice =sp-agenda-views-config-source=:

- =yadm= (the default) asks the yadm repository: =git --git-dir=<sp-yadm-repo> --work-tree=~ ls-files -- '*.org'=. This is exactly "the Org files that are part of my configuration", so a new tracked doc shows up with no setting to change, and notes in =~/notes=, which yadm does not track, never leak into the view. It needs =git= on the =PATH= and the repository at =sp-yadm-repo=.
- =dirs= searches every Org file below the folders of =sp-agenda-views-config-dirs= (by default =~/.config/emacs-modular/= and =~/adr/=). It needs no repository, so it also works on a machine without yadm, but it finds untracked files and misses tracked files outside the listed folders.

I chose the yadm mode as the default because the request was for the files of the yadm repository, and kept the folder list as the fallback. If no file is found the command signals a =user-error= that names the source, so an empty view is not mistaken for "nothing to do".

*** Why agenda views like this one matter

The agenda builds a view from two things: which files it reads (=org-agenda-files=) and which headings in them match. Everything else (the PARA blocks, the issue board, this view) is a different combination of the two.

- *TODO keywords say what state a heading is in; tags say what it is about.* The config view asks only about state, with a =todo= block. A tag search (=tags-todo "+work"=) asks about the topic. A heading can answer both, and the views above mix the two where it helps: the issue views use keywords for the board (=PROG=, =NEXT=, =WAIT=, =TODO=) and a tag or property for one repository or for "has a branch".
- *Scoping the files is what makes a view cheap and calm.* The default agenda reads every PARA file, so TODOs written in the docs of the configuration (a "fix this later" under a module's doc) would otherwise be mixed into the daily agenda or never seen. A file-set view collects them in one place, on demand, and leaves the daily agenda alone. Because the view restricts the files itself, nothing about =org-agenda-files= changes for the other views.
- *Showing the file title tells you where to go.* Config TODOs are scattered over many files. The title in the first column is the same breadcrumb that the Area and Project category is in the PARA views, so you can scan for the module the TODO belongs to before you open it.
- *A TODO in the docs is the cheapest way to keep a loose end.* A heading such as "TODO check on a Mac" under the module's own doc stays next to what it is about, and this view brings all of them together. The issue tracker (=i i=, =i b=) is for work that gets a branch and a pull request; the config view is for the small notes that never will.

To add another file-set view, add an entry to =sp-agenda-views-config= (or a list of its own) that binds =org-agenda-files= to a function returning the files, binds =vulpea-para-agenda-inhibit-files-update=, and picks the prefix it needs. Keywords belong in =sp-org-keywords=, the view and its key in this module.

#+begin_src emacs-lisp -i
;;;; Config files

(defcustom sp-agenda-views-config-source 'yadm
  "Where the config view finds the Org files it searches for TODO headings.
`yadm' means the Org files tracked by the yadm repository (`sp-yadm-repo'),
and `dirs' means every Org file below `sp-agenda-views-config-dirs'."
  :type '(choice (const :tag "Org files tracked by yadm" yadm)
                 (const :tag "Org files below the listed folders" dirs))
  :group 'spcustom)

(defcustom sp-agenda-views-config-dirs
  '("~/.config/emacs-modular/" "~/adr/")
  "Folders searched by the config view when the source is `dirs'."
  :type '(repeat directory)
  :group 'spcustom)

(defun sp-agenda-views--yadm-org-files ()
  "Return the Org files tracked by yadm, as absolute names."
  (let ((default-directory (file-name-as-directory (expand-file-name "~"))))
    (with-temp-buffer
      (when (zerop (process-file "git" nil t nil
                                 (concat "--git-dir=" (expand-file-name sp-yadm-repo))
                                 (concat "--work-tree=" default-directory)
                                 "ls-files" "-z" "--" "*.org"))
        (mapcar (lambda (file) (expand-file-name file default-directory))
                (split-string (buffer-string) "\0" t))))))

(defun sp-agenda-views--dirs-org-files ()
  "Return the Org files below `sp-agenda-views-config-dirs'."
  (seq-mapcat (lambda (dir)
                (when (file-directory-p dir)
                  (directory-files-recursively (expand-file-name dir) "\\.org\\'")))
              sp-agenda-views-config-dirs))

(defun sp-agenda-views-config-files ()
  "Return the existing Org files of my configuration, without lock files."
  (let ((files (seq-filter
                (lambda (file)
                  (and (file-regular-p file)
                       (not (string-prefix-p ".#" (file-name-nondirectory file)))))
                (if (eq sp-agenda-views-config-source 'yadm)
                    (sp-agenda-views--yadm-org-files)
                  (sp-agenda-views--dirs-org-files)))))
    (or (delete-dups files)
        (user-error "No Org files found for the config view (source: %s)"
                    sp-agenda-views-config-source))))

(defun sp-agenda-views-file-title ()
  "Return the `#+title:' of the current buffer, as a 36 character column.
Fall back to the file name when the file has no title.  Meant for
`org-agenda-prefix-format', which runs it with point on the entry."
  (let ((title (save-excursion
                 (save-restriction
                   (widen)
                   (goto-char (point-min))
                   (when (re-search-forward "^#\\+title:[ \t]*\\(.+\\)$" nil t)
                     (string-trim (match-string 1)))))))
    (truncate-string-to-width
     (or title (file-name-base (or (buffer-file-name (buffer-base-buffer)) "")))
     36 nil ?\s "…")))

(defconst sp-agenda-views-config
  '(("c" "Config TODOs" todo ""
     ((org-agenda-files (sp-agenda-views-config-files))
      (vulpea-para-agenda-inhibit-files-update t)
      (org-agenda-prefix-format '((todo . " %(sp-agenda-views-file-title) ")))
      (org-agenda-overriding-header "TODOs in the config files")
      (org-agenda-buffer-name "*Config TODOs*"))))
  "The config view, as an `org-agenda-custom-commands' entry.")
#+end_src

** org-ql views

Blocks built with =org-ql-block= (from =org-ql=, installed in =sp-org-agenda=).

- They query the agenda files with structured predicates instead of keyword and tag match strings.
- =q= shows next actions with no date (=NEXT=, neither scheduled nor with a deadline), everything waiting (=WAIT=), and what was finished in the last seven days.
- They search =org-agenda-files=, so the agenda files that =vulpea-para= set apply.
- =org-ql-block= is declared as an autoload, because =org-ql= may not be built yet when this module loads.
- See [[file:../../../../../adr/0011-dashboard-and-org-ql-views.org][ADR 0011]].

#+begin_src emacs-lisp -i
(autoload 'org-ql-block "org-ql")

(defconst sp-agenda-views-ql
  '(("q" "Queries (org-ql)"
     ((org-ql-block '(and (todo "NEXT") (not (scheduled)) (not (deadline)))
                    ((org-ql-block-header "Next actions without a date")))
      (org-ql-block '(todo "WAIT")
                    ((org-ql-block-header "Waiting")))
      (org-ql-block '(and (done) (closed :from -7))
                    ((org-ql-block-header "Done in the last 7 days"))))))
  "The org-ql views, as `org-agenda-custom-commands' entries.")
