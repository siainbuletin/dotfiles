#+TITLE: sp-org-agenda.el and sp-agenda-views.el: Org agenda settings, views and keys
#+STARTUP: content

Literate source for two modules: =libraries/modules/text/sp-org-agenda.el= (the agenda settings and helpers) and =libraries/modules/text/sp-agenda-views.el= (every custom agenda view and every agenda key). Every line of both modules lives in the =emacs-lisp= blocks below, in order. This file has no file-wide =#+PROPERTY= line for =:tangle=, because that would send every block to one file. Instead each top-level heading carries a =:header-args:emacs-lisp:= property in its own drawer, which says where the blocks under it are written, and the last heading, "Agenda views module", points at =sp-agenda-views.el=. See [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

Configures how Org's agenda looks and behaves: the prefix format of agenda lines, visual styling of the time grid and tags, scheduling and sorting rules, and the =org-super-agenda= grouping. It also adds a command to jump to the daily view, automatic refresh of the agenda after a capture, and an alphapapa recipe for showing an agenda limited to the current subtree or region.

It no longer sets the list of agenda files (=vulpea-para= owns it, see =sp-vulpea-para= and [[file:../../../../../adr/0009-one-agenda-owner-per-setting.org][ADR 0009]]) or any key (all agenda keys are in =sp-agenda-views=). It is loaded in the Org section of both module lists in =init.el=, early, and it installs =elegant-agenda-mode=, =org-super-agenda=, =org-ql= and =org-other-agenda=. The custom agenda views live in =sp-agenda-views=, described at the end of this file, which is one of the last Org modules to load.

** Agenda settings

Configures the built-in =org-agenda= library, loaded when =org-agenda= is first called. The agenda opens with log mode on, so clocked and closed items for the day are shown. =org-agenda-prefix-format= is the only definition of the prefix: every kind of agenda line starts with vulpea-para's category (the Area and Project path, 36 characters wide). The main agenda adds the time slot and the scheduling information, and search results an icon. It used to be set twice (here and in =sp-vulpea-para=), and the second assignment dropped the =tags= and =search= entries.

#+begin_src emacs-lisp -i
;;;; Org Agenda
;;;;; Agenda Settings
(use-package org-agenda
  :ensure nil
  :commands (org-agenda)
  :custom
  ;; Agenda logging
  (org-agenda-start-with-log-mode t)

  ;; The Area > Project category is evaluated when an agenda is built, so
  ;; vulpea-para does not have to be loaded yet.
  (org-agenda-prefix-format
   '((agenda . " %(vulpea-para-agenda-category 36) %?-12t %12s")
     (todo   . " %(vulpea-para-agenda-category 36) ")
     (tags   . " %(vulpea-para-agenda-category 36) ")
     (search . " %i %(vulpea-para-agenda-category 36) ")))
)
#+end_src

** Refresh after capture

=lem-org-agenda-refresh= rebuilds the =*Org Agenda*= buffer if it exists, and it is added to =org-capture-after-finalize-hook= so a newly captured task appears in an open agenda immediately.

#+begin_src emacs-lisp -i
;;;;; Agenda Refresh
;; automatically refresh the agenda after adding a task
(defun lem-org-agenda-refresh ()
  (interactive)
  (when (get-buffer "*Org Agenda*")
    (with-current-buffer "*Org Agenda*"
      (org-agenda-redo)
      (message "[org agenda] refreshed!"))))
(add-hook 'org-capture-after-finalize-hook 'lem-org-agenda-refresh)
#+end_src

** Agenda styling

Stops Org from aligning tags, puts agenda tags right after the heading, uses two spaces between breadcrumbs, and replaces the block separator with a blank. The time grid shows hours from 08:00 to 20:00 every two hours with light dotted lines, only on today and only when there are timed items, and the current time is marked with a line ending in "Now".

#+begin_src emacs-lisp -i
;;;; Appearance of the agenda and rendering
;; Agenda styling
  (setq org-auto-align-tags nil)            ;; Don't align tags
  (setq org-agenda-tags-column 0)           ;; Put tags next to heading
  (setq org-agenda-breadcrumbs-separator "  ")
  (setq org-agenda-block-separator " ")     ;; No default block seperator
  (setq org-agenda-time-grid
   '((daily today require-timed)
     (800 1000 1200 1400 1600 1800 2000)
     " ┄┄┄┄┄ " "┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄"))
  (setq org-agenda-current-time-string
   "–––––––––––––– Now")
#+end_src

** Scheduling and sorting

Done items are hidden from scheduled and timestamp entries. TODO lists hide tasks scheduled in the future and those with distant deadlines. Every view sorts by time ascending, and the calendar week starts on Monday.

#+begin_src emacs-lisp -i
;;;; CONFIGURING THE FUNCTIONALITY
;; Scheduling with org-agenda

  (setq org-agenda-skip-scheduled-if-done t)
  (setq org-agenda-skip-timestamp-if-done t)
  (setq org-agenda-todo-ignore-scheduled 'future)
  (setq org-agenda-todo-ignore-deadlines 'far)
  (setq org-agenda-sorting-strategy
   '((agenda time-up) (todo time-up) (tags time-up) (search time-up)))
  (setq calendar-week-start-day 1) ;; Start week on Monday
#+end_src

** org-super-agenda groups

Installs =org-super-agenda= (waiting for it to be built) and sets its date format and groups: overdue PROG or DOING items first, then today's tasks (by date and by scheduled date, as two groups with the same name), then habits under "End of Day", then future TODOs, and DONE or cancelled items last as "Accomplishments". The groups only apply when =org-super-agenda-mode= is enabled, and nothing in the config turns it on, so as it stands this grouping is not used.

#+begin_src emacs-lisp -i
;;;; EXTENSIONS FOR ORG-AGENDA
(use-package org-super-agenda
:after org
  :ensure (:wait t)
:init
(setq org-super-agenda-date-format "%A (%e)"
      org-super-agenda-groups
      '((:name "Accomplishments"
         :todo ("DONE" "CNCL" "CANCELLED")
         :order 4)
        (:name "End of Day"
         :habit t
         :order 2)
        (:name "Uncompleted Work"
         :todo ("PROG" "DOING")
         :scheduled past
         :order 0)
        (:name "Today's Tasks"
         :date today
         :order 1)
        (:name "Today's Tasks"
         :scheduled today
         :order 1)
        (:name "Future Work"
         :todo "TODO"
         :scheduled future
         :order 3))))
#+end_src

** org-ql

Installs =org-ql=, the Org query language, which can search Org files with structured queries and build agenda-like views from them. This is the install that =sp-vulpea-org-ql=, which calls =org-ql-select=, relies on. It sits right after =org-super-agenda= on purpose: =org-ql= requires =org-super-agenda=, and if it is declared first, Elpaca queues =org-super-agenda= as a dependency and warns =org-super-agenda previously queued as dependency of: (org-ql)= when the explicit declaration follows. See [[file:../../load-order.org][the load order]].

** sp-org-agenda-current-subtree-or-region

Shows a search agenda restricted to the current subtree, or to the active region extended to the end of its last subtree, with the header "Subtree" or "Region". With a prefix argument only TODO items are shown. It works from indirect buffers by operating in the base buffer, sorts by priority then timestamp, and removes the restriction lock afterwards. The inline note says that binding the sorting strategy around =org-search-view= appears to have no effect. The command has no keybinding in this module.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-org-agenda-current-subtree-or-region (only-todos)
  "Display an agenda view for the current subtree or region.
 With prefix, display only TODO-keyword items."
  (interactive "P")
  (let ((starting-point (point))
        header)
    (with-current-buffer (or (buffer-base-buffer (current-buffer))
                             (current-buffer))
      (if (use-region-p)
          (progn
            (setq header "Region")
            (put 'org-agenda-files 'org-restrict (list (buffer-file-name (current-buffer))))
            (setq org-agenda-restrict (current-buffer))
            (move-marker org-agenda-restrict-begin (region-beginning))
            (move-marker org-agenda-restrict-end
                         (save-excursion
                           ;; If point is at beginning of line, include
                           ;; heading on that line by moving forward 1.
                           (goto-char (1+ (region-end)))
                           (org-end-of-subtree))))
        ;; No region; restrict to subtree.
        (save-excursion
          (save-restriction
            ;; In case the command was called from an indirect buffer, set point
            ;; in the base buffer to the same position while setting restriction.
            (widen)
            (goto-char starting-point)
            (setq header "Subtree")
            (org-agenda-set-restriction-lock))))
      ;; NOTE: Unlike other agenda commands, binding `org-agenda-sorting-strategy'
      ;; around `org-search-view' seems to have no effect.
      (let ((org-agenda-sorting-strategy '(priority-down timestamp-up))
            (org-agenda-overriding-header header))
        (org-search-view (if only-todos t nil) "*"))
      (org-agenda-remove-restriction-lock t)
      (message nil))))
#+end_src

This heading and everything under it is written to =sp-agenda-views.el=, not =sp-org-agenda.el=. The module holds every custom agenda view and every agenda key, so there is one place to read. =org-agenda-custom-commands= is assigned once, here, from the lists below; no other module adds to it. The module is loaded last among the Org modules (see [[file:../../../../../adr/0009-one-agenda-owner-per-setting.org][ADR 0009]]): the PARA view needs =vulpea-para=, and the issue views need =sp-org-issues=, whose functions they call. ** Native views

Views offered by the dispatcher (the keys are in the table above):
- =d= Dashboard: today's agenda, items due today, items due in the next five days, NEXT tasks and tasks tagged =email=.
- =p= Planning: tasks tagged =@planning=, untagged tasks, and unprocessed items from =~/notes/inbox.org=.
- =D= Daily Agenda: today with a seven-day deadline warning plus priority A tasks.
- =n= NEXT tasks, =W= tasks tagged =work=, and =e= low-effort NEXT tasks under 15 minutes.
- =w= Workflow Status: one section each for PROG, WAIT, REVIEW and ACTIVE. The sections for PLAN, BACKLOG, READY, COMPLETED and CANCELED are removed: no keyword sequence defines those words, so they never matched anything.
- =R= Weekly Review: completed and unfinished scheduled tasks for the week.
- =r= Research and university: tasks tagged =@research=, =@reading= or =@uni=. As written, the match string means =@research= and the other two tags combined, which may not be the intended "any of".
- =u= Untagged Tasks: tasks that have no tags.

The blocks that restrict =org-agenda-files= (the inbox section of Planning) bind =vulpea-para-agenda-inhibit-files-update=. The no-op =(org-agenda-files org-agenda-files)= settings of the old Workflow and Low Effort views are removed.

#+begin_src emacs-lisp -i
(defconst sp-agenda-views-native
  '(("d" "Dashboard"
     ((agenda "" ((org-agenda-span 'day)))
      (tags-todo "DEADLINE=\"<today>\""
                 ((org-agenda-overriding-header "Due Today!")))
      (tags-todo "+DEADLINE<\"<+5d>\"+DEADLINE>\"<today>\""
                 ((org-agenda-overriding-header "Due Soon")))
      (todo "NEXT"
            ((org-agenda-overriding-header "Next Tasks")))
      (tags-todo "email" ((org-agenda-overriding-header "Email")))))

    ("p" "Planning"
     ((tags-todo "+@planning"
                 ((org-agenda-overriding-header "Planning Tasks")))
      (tags-todo "-{.*}"
                 ((org-agenda-overriding-header "Untagged Tasks")))
      (todo ".*" ((org-agenda-files (list (sp-path sp-notes-dir "inbox.org")))
                  (vulpea-para-agenda-inhibit-files-update t)
                  (org-agenda-overriding-header "Unprocessed Inbox Items")))))

    ("D" "Daily Agenda"
     ((agenda "" ((org-agenda-span 'day)
                  (org-deadline-warning-days 7)))
      (tags-todo "+PRIORITY=\"A\""
                 ((org-agenda-overriding-header "High Priority Tasks")))))

    ("n" "Next Tasks"
     ((todo "NEXT"
            ((org-agenda-overriding-header "Next Tasks")))))

    ("W" "Work Tasks" tags-todo "+work")

    ;; Low-effort next actions
    ("e" tags-todo "+TODO=\"NEXT\"+Effort<15&+Effort>0"
     ((org-agenda-overriding-header "Low Effort Tasks")
      (org-agenda-max-todos 20)))

    ("w" "Workflow Status"
     ((todo "PROG"
            ((org-agenda-overriding-header "In Progress")))
      (todo "WAIT"
            ((org-agenda-overriding-header "Waiting on External")))
      (todo "REVIEW"
            ((org-agenda-overriding-header "In Review")))
      (todo "ACTIVE"
            ((org-agenda-overriding-header "Active Projects")))))

    ("R" "Weekly Review"
     ((agenda ""
              ((org-agenda-overriding-header "Completed Tasks")
               (org-agenda-skip-function '(org-agenda-skip-entry-if 'nottodo 'done))
               (org-agenda-span 'week)))

      (agenda ""
              ((org-agenda-overriding-header "Unfinished Scheduled Tasks")
               (org-agenda-skip-function '(org-agenda-skip-entry-if 'todo 'done))
               (org-agenda-span 'week)))))

    ("r" "Research and university" tags-todo "+@research @reading @uni")

    ("u" "Untagged Tasks" tags-todo "-{.*}"))
  "The native views, as `org-agenda-custom-commands' entries.")
#+end_src

** Issue views

The =i= prefix lists the open issues of the issue tracker. =sp-org-issues= provides the file through =sp-org-issues--agenda-files=; the views live here. =i i= is the issue board (in progress, next, waiting, open, in a buffer named =*Issues*=) and =i b= lists the issues with a branch. They are added only when =sp-org-issues= is loaded.

#+begin_src emacs-lisp -i
(defconst sp-agenda-views-issues
  '(("i" . "Issues")
    ("ii" "Issue board"
     ((todo "PROG" ((org-agenda-overriding-header "In progress")))
      (todo "NEXT" ((org-agenda-overriding-header "Next")))
      (todo "WAIT" ((org-agenda-overriding-header "Waiting on review or a reply")))
      (todo "TODO" ((org-agenda-overriding-header "Open"))))
     ((org-agenda-files (sp-org-issues--agenda-files))
      (vulpea-para-agenda-inhibit-files-update t)
      (org-agenda-buffer-name "*Issues*")))
    ("ib" "Issues with a branch" tags-todo "BRANCH<>\"\""
     ((org-agenda-files (sp-org-issues--agenda-files))
      (vulpea-para-agenda-inhibit-files-update t)
      (org-agenda-overriding-header "Issues with a branch"))))
  "The issue views, as `org-agenda-custom-commands' entries.")
