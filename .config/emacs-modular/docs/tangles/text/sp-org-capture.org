The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module sets up =org-capture=: the default inbox file, a handful of capture templates, the global ~C-c c~ binding, and helper functions (inherited from Lambda Emacs, hence the =lem-= prefix) for running capture in a dedicated frame named capture, for example from an external launcher talking to the Emacs server.

It is one of the last Org modules to load (see the load order in [[file:../../../../../adr/0009-one-agenda-owner-per-setting.org][ADR 0009]]), because it is the only place that sets =org-capture-templates=: every template of every module is here, in one =setq=, with no =add-to-list= elsewhere. The task and project templates call functions from =vulpea-para=, and the issue template calls functions from =sp-org-issues=; they are quoted as =(function ...)=, so they are only looked up when you capture. The only inbox is =~/notes/inbox.org=: tasks, ideas and thoughts all go there.

* Capture mechanisms

** Default notes file

Sets =org-default-notes-file= to =inbox.org= inside =org-directory=, the only inbox. The agenda files are not set here any more: =vulpea-para= owns them (see =sp-vulpea-para=).

#+begin_src emacs-lisp -i
;;;; Capture mechanisms

;;;;; Org Directories
;; The only inbox
(setq org-default-notes-file (concat org-directory "inbox.org"))
#+end_src

** Inserting a heading with a creation time

=lem-insert-header-and-time-property= inserts a new top-level heading and gives it a =CREATED= property holding the current timestamp. The comment calls it an example note creation function; it has no keybinding.

#+begin_src emacs-lisp -i
;; Example note creation function
(defun lem-insert-header-and-time-property ()
  "Insert an org heading with a created time string property."
  (interactive)
  (insert "* ")
  (org-set-property "CREATED" (format-time-string "[%Y-%m-%d %T]")))
#+end_src

** Capture templates

Assigns =org-capture-templates= once, with every template of the configuration. Nothing else adds to it.

| Key | Template                        | Goes to                                       | Defined by                      |
|-----+---------------------------------+-----------------------------------------------+---------------------------------|
| t   | Task                            | =~/notes/inbox.org=, under Tasks              | =vulpea-para-capture-task-template= |
| i   | Idea or quick thought           | =~/notes/inbox.org=, under Thoughts           | here                            |
| p   | PARA project                    | A new project in an area                      | =vulpea-para-capture-project-*= |
| I   | Issue                           | The issues area, under a repository           | =sp-org-issues-capture-*=       |
| n   | New note (with Denote)          | A new Denote note                             | here                            |
| l   | Listening log                   | A date tree in =~/notes/inbox/listening-log.org= | here                         |

The idea template used to file into =~/notes/inbox/thoughts-capture.org=, a second inbox; it now files into =inbox.org= like the task template. The PARA meeting template =m= of =vulpea-para-setup-defaults= is not included, as that function is not used.

#+begin_src emacs-lisp -i
(setq org-capture-templates
      `(("t" "Task" entry
         (file+headline "inbox.org" "Tasks")
         (function vulpea-para-capture-task-template))

        ("i" "Idea or quick thought" entry
         (file+headline "inbox.org" "Thoughts")
         "* %?\n%U")

        ("p" "PARA project" entry
         (function vulpea-para-capture-project-target)
         (function vulpea-para-capture-project-template))

        ("I" "Issue" entry
         (function sp-org-issues-capture-target)
         (function sp-org-issues-capture-template))

        ("n" "New note (with Denote)" plain
         (file denote-last-path)
         #'denote-org-capture
         :no-save t
         :immediate-finish nil
         :kill-buffer t
         :jump-to-captured t)

        ("l" "Listening log" entry
         (file+datetree ,(sp-path sp-notes-dir "inbox/listening-log.org"))
         "* %U\n %i\n %a")))
#+end_src

* Capture frames

** Running capture in a capture frame

=lem-activate-capture-frame= is meant to be called through =emacsclient=: it loads Org, selects the frame named capture, switches to a scratch buffer called new and starts =org-capture=. It is not interactive. The comment points to sp-vulpea.el for task capture.

#+begin_src emacs-lisp -i
;; See also sp-vulpea.el for task capturing 

;;;;; Create Capture Frame
;; have these functions available for server
(defun lem-activate-capture-frame ()
  "run org-capture in capture frame"
  (progn
    (require 'org)
    (select-frame-by-name "capture")
    (switch-to-buffer (get-buffer-create "new"))
    (org-capture)))
#+end_src

** Weather journal capture

=lem-weather-journal-capture= does the same frame setup and then calls =lem-org-journal= and =lem-insert-weather=. Neither of those functions is defined anywhere in this configuration, so this command currently fails with a void-function error. It is a leftover from Lambda Emacs.

#+begin_src emacs-lisp -i
;;;;; Weather Capture Frame
(defun lem-weather-journal-capture ()
  (interactive)
  (progn
    (require 'org)
    (select-frame-by-name "capture")
    (switch-to-buffer (get-buffer-create "new"))
    (lem-org-journal)
    (lem-insert-weather)))
#+end_src
