Literate source for =libraries/modules/text/sp-org-taskman-extra.el=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module holds the task management side of the Org setup:

- TODO keyword sequences,
- the tag list with fast-selection keys,
- priorities,
- a helper to turn a heading into a project,
- task dependencies with =org-edna=,
- highlighting and searching of TODO comments with =hl-todo= and =consult-todo=,
- the =org-gtd= workflow under the ~C-c d~ prefix.

The agenda is deliberately kept in a separate module because of its many appearance concerns.

The module is loaded from =init.el= among the text modules. Packages it installs: =org-edna=, =hl-todo=, =consult-todo= and =org-gtd=. =org-inlinetask= ships with Org.

Worth knowing:

- The TODO keywords are not set here any more. =sp-org-keywords= defines every sequence once. Its =TODO NEXT PROG WAIT | DONE CNCL= sequence is the one org-gtd's default keyword mapping points to.
- The org-gtd key that touches the agenda (=C-c .= in the agenda) is bound in =sp-agenda-views=.
- org-gtd's own capture key is not bound: the inbox is =~/notes/inbox.org=, filled by the templates of =sp-org-capture=.

* Keywords, tags and priorities

** TODO keyword sequences

The sequences are defined in =sp-org-keywords= (see its table of use cases). Nothing is set here; this module only reads them through =org-gtd-keyword-mapping= and the faces below.

** Tags

=org-tag-alist= defines tags with single-key shortcuts for ~C-c C-q~: contexts (@home, @uni, @waiting), devices (@computer, @phone), activities (planning, configuration, writing, reading, music, research, errands) and effort categories (deep, shallow, time-eater). The inline comment notes that fast-selection keys can only be a single character.

These are the task tags only. The tags of notes (=person=, =album=, ...) are a separate list, =org-tag-persistent-alist=, kept in =sp-org-tag-registry.el= and linted by =sp-org-tag-lint=.

#+begin_src emacs-lisp -i
;;;; Set up the org tags (task tags; note tags are in sp-org-tag-registry)
(setq org-tag-alist
      '(;; Circumstances
        ("@home" . ?H)
        ("@uni" . ?U)
      ("@waiting" . ?W)

        ;; Devices
        ("@computer" . ?C)
        ("@phone" . ?P)

        ;; Activities
        ("@planning" . ?p)
        ("@configuration" . ?c)
        ("@writing" . ?w)
        ("@reading" . ?s)
        ("@music" . ?m)
        ("@research" . ?r)
        ("@errands" . ?e)

      ;; Effort estimate
      ("deep" . ?d)
      ("shallow" . ?h) ; I wanted to write this as ?sh but it only accepts one symbol
      ("time-eater" . ?t)))
#+end_src

* Projects

** Marking a heading as a project

=my-mark-as-project= is an interactive command that turns the current heading into a project. It:

- adds the project tag,
- sets =COOKIE_DATA= to todo recursive, so the progress cookie counts all TODO descendants,
- makes sure the heading has a TODO keyword and a progress cookie, inserting NEXT and/or a [/] cookie as needed,
- reports what it found in the echo area.

There is a subtle bug in this command:

- It tests the local variable with =bound-and-true-p=, which checks for a dynamic (global) binding.
- Under lexical binding that test is always false. So the command always behaves as if the heading had no TODO keyword, and may insert a second keyword.
- Using the variable directly instead would fix it.
- There is no keybinding.

#+begin_src emacs-lisp -i
;;;; Project management
;;;;; Marking something as a project
(defun my-mark-as-project ()
"This function makes sure that the current heading has
(1) the tag :project:
(2) has property COOKIE_DATA set to \"todo recursive\"
(3) has any TODO keyword and
(4) a leading progress indicator"
    (interactive)
    (org-toggle-tag "project" 'on)
    (org-set-property "COOKIE_DATA" "todo recursive")
    (org-back-to-heading t)
    (let* ((title (nth 4 (org-heading-components)))
           (keyword (nth 2 (org-heading-components))))
       (when (and (bound-and-true-p keyword) (string-prefix-p "[" title))
           (message "TODO keyword and progress indicator found")
           )
       (when (and (not (bound-and-true-p keyword)) (string-prefix-p "[" title))
           (message "no TODO keyword but progress indicator found")
           (forward-whitespace 1)
           (insert "NEXT ")
           )
       (when (and (not (bound-and-true-p keyword)) (not (string-prefix-p "[" title)))
           (message "no TODO keyword and no progress indicator found")
           (forward-whitespace 1)
           (insert "NEXT [/] ")
           )
       (when (and (bound-and-true-p keyword) (not (string-prefix-p "[" title)))
           (message "TODO keyword but no progress indicator found")
           (forward-whitespace 2)
           (insert "[/] ")
           )
       )
)
#+end_src

* TODO comments

** hl-todo

=global-hl-todo-mode= highlights TODO, FIXME and NOTE keywords in comments and text, coloured with the foreground of the =warning=, =error= and =success= faces of the current theme. The colours are read once when the package loads, so they do not follow a later theme change.

#+begin_src emacs-lisp -i
;;;; TODO faces
(use-package hl-todo
  :ensure t
  :config
  (setq hl-todo-keyword-faces
    `(("TODO"   . ,(face-foreground 'warning))
      ("FIXME"  . ,(face-foreground 'error))
      ("NOTE"   . ,(face-foreground 'success))))
  (global-hl-todo-mode 1))
#+end_src

* Getting Things Done

** org-gtd

Sets up =org-gtd= (version 4) eagerly after Org, with its files in =~/notes/area/org-gtd/=.

- The upgrade acknowledgement variable is set in =:init= to silence the version 4 upgrade warning.
- =org-gtd-keyword-mapping= is not set any more. org-gtd's default maps its states to =TODO=, =NEXT=, =WAIT=, =DONE= and =CNCL=, which is the task sequence of =sp-org-keywords=. org-gtd checks that all of them are in one sequence of =org-todo-keywords=. See [[file:../../../../../adr/0013-org-gtd-keywords-and-inbox.org][ADR 0013]].
- Adding the GTD directory to the agenda is commented out because it raised an error.
- =org-edna-mode= is enabled again here, since org-gtd relies on it.

Keybindings:
- ~C-c d p~ processes the GTD inbox. There is no key for org-gtd's own capture (~C-c d c~ was unbound): capture goes to =~/notes/inbox.org= through =sp-org-capture=.
- ~C-c d e~ opens the engage view, ~C-c d n~ shows all next actions, ~C-c d s~ shows stuck projects.
- ~C-c c~ in clarify buffers runs =org-gtd-organize=. This shadows the global =org-capture= key only inside those buffers.
- ~C-c .~ in the agenda opens =org-gtd-agenda-transient= for quick actions on tasks. It is bound in =sp-agenda-views=, where every agenda key lives.

#+begin_src emacs-lisp -i
;;;; Org-gtd package
(use-package org-gtd
  :ensure (:wait t)
  :after org
  :demand t
  :init
  ;; Suppress upgrade warnings (must be set before package loads)
  (setq org-gtd-update-ack "4.0.0")
  :custom
  ;; Where org-gtd will keep its files (defaults to ~/gtd/)
  (org-gtd-directory (sp-path sp-notes-dir "area/org-gtd/"))

  ;; Configure TODO keyword states (options like "TODO(t)" or "DONE(d!)" are fine)
  ;; TODO keyword are configured elsewhere

  ;; `org-gtd-keyword-mapping' is not set: org-gtd's default (TODO, NEXT,
  ;; WAIT, DONE, CNCL) is the task sequence of sp-org-keywords, and org-gtd
  ;; needs all of them in one sequence (adr/0013).

  ;; Add org-gtd files to your agenda
  ;; (org-agenda-files (list org-gtd-directory)) ;; this errors out so it's commented

  :config
  (org-edna-mode 1)

  :bind 
  (("C-c d e" . org-gtd-engage)
   ("C-c d p" . org-gtd-process-inbox)
   ("C-c d n" . org-gtd-show-all-next)
   ("C-c d s" . org-gtd-reflect-stuck-projects)

   :map org-gtd-clarify-mode-map
   ("C-c c" . org-gtd-organize))) ;; (only works in clarify buffers)
;; The agenda key of org-gtd (C-c . for `org-gtd-agenda-transient') is
;; bound in sp-agenda-views, with every other agenda key.
#+end_src

** Lazy inline tasks

Declares the built-in =org-inlinetask= without installing anything (=:ensure nil=) and makes =org-inlinetask-insert-task= an autoloaded command.

- Inline tasks are task headings placed deep inside the body of another entry without breaking its structure.
- The plain =require= above is now commented out, so this is the only place the library is set up. It loads on first use.

#+begin_src emacs-lisp -i
;;;;; Org Inline Tasks
(use-package org-inlinetask :ensure nil
  :commands org-inlinetask-insert-task)
#+end_src
