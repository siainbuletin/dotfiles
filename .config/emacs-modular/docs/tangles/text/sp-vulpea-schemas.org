The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

Declares the note types (schemas) used in the Vulpea knowledge base, with =vulpea-schema-define=. Each schema says which notes it applies to, through a predicate that checks for a particular Org tag, and which meta fields such notes should have: their key, type (=string=, =number= or =note= for a link to another note), whether they are required, whether they may hold several values, and for links which tags the target note should carry. Schemas can inherit fields from another with =:include=.

The schemas cover music (albums, musicians, groups), questions and research inquiries, people and organisations, software, and literature notes. The table and sidebar code in =sp-vulpea-ui= and =sp-vulpea-table-views= builds on these definitions. The module is required from =sp-org-ext= after =sp-vulpea-base=, and it assumes Vulpea is already loaded since it calls =vulpea-schema-define= at top level.

* Music

** Albums

The =album= schema applies to notes tagged =album=. It requires a =creator= link to a note tagged musician, person or group, at least one =genre= link to genre notes, and a numeric =year=. Optional fields are a =name=, extra =genre-influences= links and a numeric =rating=.

#+begin_src emacs-lisp -i
;;;; Schema definition
;;;;; Schema for albums
(vulpea-schema-define 'album
  :predicate (lambda (note) (member "album" (vulpea-note-tags note)))
  :fields
  '(
    (:key "creator" :type note   :required t :target-tags ("musician" "person" "group"))
    (:key "name"     :type string :required nil)
    (:key "genre"   :type note :required t :multiple t :target-tags ("genre"))
    (:key "genre-influences" :type note :multiple t :target-tags ("genre"))
    (:key "year"   :type number   :required t :multiple nil)
    (:key "rating"   :type number   :required nil :multiple nil)
))
#+end_src

* Inquiries

** Base inquiry schema

=inquiry= applies to notes tagged =inquiry= and requires a =q-status= field that is either =solved= or =unsolved=. These allowed values are written as symbols, while other schemas below use strings for =:one-of=, so it is worth checking that both forms match as intended.

#+begin_src emacs-lisp -i
;;;;; Schema for inquiries
(vulpea-schema-define 'inquiry
  :predicate (lambda (note) (member "inquiry" (vulpea-note-tags note)))
  :fields
  '(
    (:key "q-status" :type string :required t :one-of (solved unsolved))
))
#+end_src

* Software

** Software

=software= applies to notes tagged =software=. It requires =source= (closed-source or open-source) and =maintenance= (current, abandoned or spotty), and optionally lists =languages= as links to other notes.

#+begin_src emacs-lisp -i
;; Schema for software-related stuff
(vulpea-schema-define 'software
		      :predicate (lambda (note) (member "software" (vulpea-note-tags note)))
		      :fields
		      '((:key "source" :type string :required t :one-of ("closed-source" "open-source"))
			(:key "languages" :type note :required nil :multiple t)
			(:key "maintenance" :type string :required t :one-of ("current" "abandoned" "spotty")))
		      )
#+end_src

* Literature notes

** Base text schema

=base-text= applies to notes tagged =text= and holds the bibliographic core: =pub-author= links (several allowed), a required numeric =pub-year=, a required =pub-title=, and an optional free-text =relevance= note.

#+begin_src emacs-lisp -i
;; Schema for literature notes
(vulpea-schema-define 'base-text
		      :predicate (lambda (note) (member "text" (vulpea-note-tags note)))
		      :fields
		      '((:key "pub-author" :type note :multiple t)
			(:key "pub-year" :type number :required t)
			(:key "pub-title" :type string :required t)
			(:key "relevance" :type string :required nil))
)
#+end_src
