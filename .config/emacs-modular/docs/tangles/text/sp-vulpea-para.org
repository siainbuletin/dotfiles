The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module wires the =vulpea-para= library into Org's agenda and capture. vulpea-para organises notes along the PARA method (projects, areas, resources, archives) on top of the =vulpea= note database; a copy of it is kept under =libraries/modules/cloned/vulpea-para/=. Here it filters which notes count as agenda files, defines the main agenda view from vulpea-para's building blocks, sets an Area and Project prefix in agenda lines, and defines task and project capture templates.

It is required by =sp-org-ext=, after =sp-org-capture= and =sp-org-agenda=. It adds its agenda view and its capture templates to =org-agenda-custom-commands= and =org-capture-templates= with =add-to-list=, so the views and templates those earlier modules set stay available. It used to assign both variables with plain =setq=, which replaced them. =org-agenda-prefix-format= is still assigned with =setq=, so the value here replaces whatever an earlier module set for it.

** Agenda file filter

=vulpea-para-agenda-files-filter= is given a predicate that excludes any note tagged =cemetery=, so retired notes never become agenda files.

#+begin_src emacs-lisp -i
;; keep a cemetery (or anything) out of the agenda file list
(setq vulpea-para-agenda-files-filter
      (lambda (note)
        (not (vulpea-note-tagged-any-p note "cemetery"))))
#+end_src

* Agenda

** Main agenda view

Adds a view bound to the space key in the agenda dispatcher, in front of the views from =sp-org-agenda=. It stacks vulpea-para's blocks: items to refile, today, focus items, stuck projects, waiting items, and the current quarter (built by calling a function at load time). A comment wonders whether this belongs in the agenda module instead.

#+begin_src emacs-lisp -i
;; Getting the custom agenda view for vulpea-para
;; Should this be moved to the org-agenda file, since it's a special command?
(add-to-list 'org-agenda-custom-commands
             `(" " "Agenda"
               (,vulpea-para-agenda-cmd-refile
                ,vulpea-para-agenda-cmd-today
                ,vulpea-para-agenda-cmd-focus
                ,vulpea-para-agenda-cmd-stuck-projects
                ,vulpea-para-agenda-cmd-waiting
                ,(vulpea-para-agenda-cmd-current-quarter))))
#+end_src

** Agenda line prefix

Sets the agenda prefix so each line starts with vulpea-para's category string, its Area and Project path truncated to 36 characters, followed by the time and scheduling information in the agenda view, or just the category in TODO lists.

#+begin_src emacs-lisp -i
;; the Area > Project prefix in the agenda
(setq org-agenda-prefix-format
      '((agenda . " %(vulpea-para-agenda-category 36) %?-12t %12s")
        (todo   . " %(vulpea-para-agenda-category 36) ")))
#+end_src

* Capture

** Capture templates

Adds two entries to =org-capture-templates=, after any set by earlier modules: =t= files a task under the Tasks heading of =inbox.org= in =org-directory= using vulpea-para's task template, and =p= creates a project, where both the target location and the template come from vulpea-para functions.

#+begin_src emacs-lisp -i
;; Wiring org-capture into vulpea-para
(dolist (template
         '(("t" "task" entry
            (file+headline "inbox.org" "Tasks")
            (function vulpea-para-capture-task-template))

           ("p" "project" entry
            (function vulpea-para-capture-project-target)
            (function vulpea-para-capture-project-template))))
  (add-to-list 'org-capture-templates template t))
#+end_src
