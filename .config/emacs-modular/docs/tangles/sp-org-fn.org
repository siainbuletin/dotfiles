The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

An experiment in placing Org footnote definitions inside the subtree they belong to rather than in one section at the end of the file. The motivation is that commands like =vulpea-split-heading= move a heading into a new file but leave its footnotes behind. The plan was to keep file-end footnotes only for small files and otherwise attach a footnote section to the nearest heading no deeper than a configurable level.

The module's own commentary says the current logic does not work and actually blocks creating new footnotes, because it advises =org-footnote-new=. It is commented out in =init.el=. There is also a load-time bug: =(org-footnote-auto-adjust t)= is written as a function call, but =org-footnote-auto-adjust= is a variable, so loading the file would signal a void-function error. It probably came from a =:custom= block and was meant to be a =setq=.

** The problem with file-end footnotes

Explains the motivation: footnotes normally collect at the end of the file, so refiling or splitting a heading into another file loses them. The goal is to limit how deep footnote sections can go and to keep the usual file-end behaviour for small files.

#+begin_src emacs-lisp -i
;; Org footnotes typically get placed at the end of the file in a footnote section. This
;; behaviour is generally very useful, however, in the case of wanting to refile a heading
;; to a different file with a function like ~vulpea-split-heading~, the footnotes don't get
;; copied over as well, which creates a lot of manual work.
;;
;; Working with Claude, I want to define custom logic for the footnotes so that I can restrict
;; how deep into the sections the footnotes can go, and when to decide when to actually keep
;; the regular footnotes at the end of the file (for much smaller files)
#+end_src

** Automatic renumbering

Intended to turn on =org-footnote-auto-adjust=, which renumbers and sorts footnotes after each insertion or deletion. The comment warns this is only safe once nested headings work, since renumbering makes it easy to get references wrong when moving notes. As noted above, this line is a function call on a variable and would error when the file loads.

#+begin_src emacs-lisp -i
;; Autorenumbering for footnotes
;; this should only be kept on if you have the proper logic for nested headings working well
;; enough, because it makes sifting through for the correct reference really easy to get wrong
;; when trying to move notes around.
(org-footnote-auto-adjust t) ;; renumber footnotes
#+end_src

** Maximum heading level

=sp-fn-max-lvl= is the deepest heading level allowed to own a footnote section. Deeper headings defer to their ancestor at this level.

#+begin_src emacs-lisp -i
;; Defining the custom variables for this
(defvar sp-fn-max-lvl 3
  "Deepest heading level that may own a footnote section.")
#+end_src

** Small file threshold

=sp-fn-small-file-max-lvl= is the number of top-level headings at or below which a file counts as small and keeps a single file-end footnotes section. Despite the name, it counts headings rather than levels.

#+begin_src emacs-lisp -i
(defvar sp-fn-small-file-max-lvl 2
  "Files with at most this many level-1 headings keep a file-end section.")
#+end_src

* Scoping logic

** Counting top-level headings

=sp-org-count-top-headings= widens the buffer temporarily and counts lines starting with a single star and a space.

#+begin_src emacs-lisp -i
(defun sp-org-count-top-headings ()
  (org-with-wide-buffer
   (goto-char (point-min))
   (let ((n 0))
     (while (re-search-forward "^\\* " nil t) (cl-incf n))
     n)))
#+end_src

** The around advice

=sp-org-fn-scoped= wraps the original footnote command. In a small file, or when point is before the first heading, it binds =org-footnote-section= to "Footnotes" and calls the original, giving normal file-end behaviour. Otherwise it walks up from the current heading until it reaches =sp-fn-max-lvl=, narrows to that subtree, and calls the original there, hoping Org will place the definition inside the narrowed region.

Because point is moved inside =save-excursion=, the footnote reference is not inserted where the cursor was, which is likely part of why the author reports that it blocks footnote creation.

#+begin_src emacs-lisp -i
(defun sp-org-fn-scoped (orig &rest args)
  (if (or (<= (sp-org-count-top-headings) sp-fn-small-file-max-lvl)
          (org-before-first-heading-p))
      (let ((org-footnote-section "Footnotes"))
        (apply orig args))
    (save-excursion
      (save-restriction
        (org-back-to-heading t)
        (while (and (> (org-current-level) sp-fn-max-lvl)
                    (org-up-heading-safe)))
        (org-narrow-to-subtree)
        (let ((org-footnote-section "Footnotes"))
          (apply orig args))))))
#+end_src

** Installing the advice

Puts =sp-org-fn-scoped= around =org-footnote-new=, the command behind =C-c C-x f=.

#+begin_src emacs-lisp -i
(advice-add 'org-footnote-new :around #'sp-org-fn-scoped)
#+end_src
