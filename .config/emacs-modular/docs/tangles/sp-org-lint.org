How detection works:

- Where it looks :: it checks the current line first, including continuation text under an item. If that isn’t part of a list, it tries the previous non-blank line, then the next non-blank line. So you can sit on a blank line just below or above a list and it still finds it.
- Start of the region :: it starts at the first item of the outermost list. That holds even if point is inside a nested sublist.
- End of the region :: it ends at the last non-blank line that belongs to the list, so trailing blank lines before the next paragraph or heading are not included or touched.
- Optional marking :: ~M-x sp-org-mark-list~ selects the detected list so you can see what the commands would act on. The two lint commands don’t need it.

- Org’s own list rules :: detection relies on ~org-list-struct~, so it follows Org’s rules for where a list ends. By default, two consecutive blank lines end a list. Items separated by two or more blank lines count as separate lists, and only the one at point is processed.

(defun sp-org--item-near-point ()

On any other line nil is returned."

(defun sp-org--normalize-url (url)
  "Return URL in a canonical form for comparison.
Trailing punctuation, an unbalanced closing parenthesis and trailing
slashes are dropped, and the host is lower-cased."
  (setq url (replace-regexp-in-string "[.,;:!?]+\\'" "" url))
  (when (and (string-suffix-p ")" url) (not (string-match-p "(" url)))
    (setq url (substring url 0 -1)))
  (setq url (replace-regexp-in-string "/+\\'" "" url))
  (if (string-match "\\`\\(https://[^/?#]*\\)" url)
      (concat (downcase (match-string 1 url)) (substring url (match-end 1)))
    url))

  "Return the normalized https:// URL of the item from ITEM-BEG to ITEM-END.

  (save-excursion
    (goto-char item-beg)
    (forward-line 1)
    (let ((own-end (save-excursion
                     (if (re-search-forward sp-org--item-re item-end t)
                         (line-beginning-position)
                       item-end))))

      (when (re-search-forward sp-org--url-re own-end t)
        (sp-org--normalize-url (match-string 0))))))

(defun sp-org--remove-duplicate-links (beg end-marker)
  "Remove list items whose https:// link already appeared earlier.
The first occurrence is kept.  Items without a link are never removed,
and neither are duplicates that have nested items.
Return (REMOVED . KEPT-BECAUSE-NESTED)."
  (let ((seen (make-hash-table :test #'equal))
        (removed 0)
        (kept 0))
    (save-excursion
      (goto-char beg)
      (while (and (< (point) end-marker)
                  (re-search-forward sp-org--item-re end-marker t))
        (beginning-of-line)
        (if (not (org-in-item-p))
            (end-of-line)

                 (struct (org-list-struct))
                 (item-end (org-list-get-item-end-before-blank pos struct))
                 (url (sp-org--item-url pos item-end)))

             ((or (null url) (not (gethash url seen)))
              (when url (puthash url t seen))
              (end-of-line))
             ((org-list-has-child-p pos struct)
              (setq kept (1+ kept))
              (end-of-line))
             (t
              (delete-region pos item-end)
              (setq removed (1+ removed))))))))
    (cons removed kept)))

How the new steps work:

- Conversion: only plain paragraph lines that are outside any list are toggled, one line at a time.
   + Headings, ~#+~ lines, drawers, tables, blocks and indented continuation text under an item are left alone.
   + The region is hidden from ~org-toggle-item~ during each call, because otherwise it would act on the whole region at once.
- Duplicates: the key is the first ~https://~ URL in an item’s own text, so [[https://x.com/a][Title]] and a bare https://x.com/a count as the same link.
   + Comparison ignores a trailing slash, trailing punctuation and the case of the host.
   + The first occurrence stays, and later ones are deleted.
- Items kept: items without an ~https://~ link are never removed.
   + A duplicate that has nested items is kept and reported in the echo-area message, so sub-notes aren’t lost silently.
   + For other schemes, change the regex to ~https?://~.
- No region marked: the list at point is used as before.
   + If point isn’t on or next to a list, the block of consecutive non-blank lines around point is used, so a pasted run of bare URLs works.
   + For a list with plain lines directly below it, mark the region yourself.
- Sort order: items are sorted by the text you see, so link descriptions are used rather than the raw [[https://... target.
