This module makes Emacs see the same environment as a login shell, which matters mostly on macOS where GUI apps do not inherit the shell's =PATH=. It uses =exec-path-from-shell=, configured after John Wiegley's setup.

It also keeps a commented-out alternative from the modular configuration it was originally based on, and defines a command for piping the region through a shell command. The commentary notes that Windows and Linux still need their own solution.

* Overview

* Importing the shell environment

** exec-path-from-shell

The package is only used under graphical window systems (mac, ns, x and pgtk), since a terminal Emacs already inherits the shell environment. =exec-path-from-shell-initialize= copies =PATH= and =MANPATH=, and the loop then copies a list of further variables: spelling config, editor, GnuPG and pass locations, SSH agent socket, SSL certificate paths (including the Nix and Node ones) and StarDict data.

#+begin_src emacs-lisp -i
;; This configuration of exec-path-from-shell is taken from John Wiegley
(use-package exec-path-from-shell
  :ensure t
  :when (memq window-system '(mac ns x pgtk))
  :config
  (exec-path-from-shell-initialize)
  (dolist (var '("ASPELL_CONF"
                 "EDITOR"
                 "GNUPGHOME"
                 "NIX_SSL_CERT_FILE"
                 "NODE_EXTRA_CA_CERTS"
                 "PASSWORD_STORE_DIR"
                 "SSH_AUTH_SOCK"
                 "SSL_CERT_FILE"
                 "STARDICT_DATA_DIR"))
    (exec-path-from-shell-copy-env var)))
#+end_src

** Daemon mode

When Emacs runs as a daemon, =window-system= is nil at startup so the block above is skipped. This form initialises the environment anyway in that case. It assumes the package is installed and autoloaded, which holds after the =use-package= above has run once.

#+begin_src emacs-lisp -i
(when (daemonp)
  (exec-path-from-shell-initialize))
#+end_src

* Shell commands on text

** Replacing the region with shell output

=sp-replace-with-shell= prompts for a shell command, runs it with the region as input, and replaces the region with the output. It refuses to run if no mark is set. The work happens in a temporary buffer, and if the =*Shell Command Output*= buffer did not exist before, it is killed afterwards so no clutter is left behind. Unlike the built-in ~C-u M-|~, it hides messages while running.

#+begin_src emacs-lisp -i
(defun sp-replace-with-shell (posBegin posEnd command)
  "Pipe region through shell command and replace"
  (interactive (let (command)
		 (unless (mark)
		   (user-error "The mark is not set now, so there is no region"))
                 (setq command (read-shell-command "Shell command on region: "))
                 (list (region-beginning) (region-end) command)))
  (with-temp-message ""
    (let ((string (buffer-substring-no-properties posBegin posEnd))
          (buffer (current-buffer))
          (shell-output-exists (get-buffer "*Shell Command Output*")))
      (with-temp-buffer
        (insert string)
        (shell-command-on-region (point-min) (point-max) command (current-buffer) t)
        (setq string (buffer-substring-no-properties (point-min) (point-max))))
      (delete-region posBegin posEnd)
      (insert string)
      ;; If *Shell Command Output* wasn't opened before, kill it
      (unless shell-output-exists
        (let ((output-buffer (get-buffer "*Shell Command Output*")))
          (when output-buffer
            (kill-buffer output-buffer)))))))
#+end_src

** Keybinding

Binds ~C-M-|~ to =sp-replace-with-shell=, next to the built-in ~M-|~ (=shell-command-on-region=).
