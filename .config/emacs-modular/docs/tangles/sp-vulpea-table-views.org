Literate source for =libraries/modules/funct/sp-vulpea-table-views.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. Tangling this file (=C-c C-v t=) rewrites that =.el= file from these blocks; nothing is tangled unless you run it.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module is the third piece of a small set of home-grown Vulpea table tools. =sp-vulpea-dblock= provides the =vulpea-table= Org dynamic block (static text output) along with the parent-of helpers, and =sp-vulpea-vui-table= provides the interactive =sia-vulpea-table= component built with =vui= and the =sia-vulpea-open-table= command. On top of those, this file adds named views (a saved combination of tag filter, columns, sort column and parent filter) persisted to a file, commands to open or insert a saved view, and a way to swap the static dynamic-block text in a note for a live, clickable =vui= table in place.

It is not listed in the module list in =init.el= directly; it is loaded through =sp-vulpea-ext=, which in turn is required by =sp-org-ext=. It requires =vui=, =vulpea= and the two sibling modules above.

* Named views

Views are kept in an alist keyed by name and written to disk as an annotated Lisp file whenever they change.

** Views file

=sp-vulpea-table-views-file= is where saved views are stored, by default =sp-vulpea-table-views.el= in =user-emacs-directory=. Note that this is the same file name as the module itself; if the Emacs directory were ever on the =load-path= ahead of the modules directory, =(require 'sp-vulpea-table-views)= could pick up the data file instead. That is a potential gotcha rather than something visibly happening.

#+begin_src emacs-lisp -i
;;; Named views ---------------------------------------------------------

(defcustom sp-vulpea-table-views-file
  (expand-file-name "sp-vulpea-table-views.el" user-emacs-directory)
  "File where named Vulpea table views are persisted."
  :type 'file
  :group 'vulpea)
#+end_src

** Views alist

=sp-vulpea-table-views= holds the saved views. The docstring lists three fields, but entries actually carry five after the name: tags, columns, sort column, parent-of and parent property, as the save and open commands show.

#+begin_src emacs-lisp -i
(defvar sp-vulpea-table-views nil
  "Alist of (NAME . (TAGS COLUMNS SORT-BY)) for saved Vulpea table views.")
#+end_src

** Loading views

=sp-vulpea-table-views-load= reads the whole file back as a single Lisp form, or sets the alist to nil when the file does not exist.

#+begin_src emacs-lisp -i
(defun sp-vulpea-table-views-load ()
  "Load saved views from `sp-vulpea-table-views-file', if present."
  (setq sp-vulpea-table-views
        (when (file-exists-p sp-vulpea-table-views-file)
          (with-temp-buffer
            (insert-file-contents sp-vulpea-table-views-file)
            (read (current-buffer))))))
#+end_src

** Writing one entry

=sia-vulpea--insert-view-entry= writes one view as an indented form with each field on its own line followed by a comment naming the field, so the saved file can be read and hand-edited.

#+begin_src emacs-lisp -i
(defun sia-vulpea--insert-view-entry (entry)
  "Insert ENTRY -- a (NAME TAGS COLUMNS SORT-BY PARENT-OF PARENT-PROP)
list, as stored in `sp-vulpea-table-views' -- as one annotated,
indented Lisp form, each field on its own line with a trailing
comment naming it."
  (pcase-let ((`(,name ,tags ,columns ,sort-by ,parent-of ,parent-prop) entry))
    (insert (format " (%S\n" name))
    (insert (format "  %-28S ; tags\n" tags))
    (insert (format "  %-28S ; columns\n" columns))
    (insert (format "  %-28S ; sort-by\n" sort-by))
    (insert (format "  %-28S ; parent-of\n" parent-of))
    (insert (format "  %-28S) ; parent-prop\n" parent-prop))))
#+end_src

** Saving views to disk

=sp-vulpea-table-views-save-to-disk= rewrites the views file with a comment header describing every field and then each entry. Comments are ignored by the Lisp reader, so the file still loads as one plain list.

#+begin_src emacs-lisp -i
(defun sp-vulpea-table-views-save-to-disk ()
  "Persist `sp-vulpea-table-views' to `sp-vulpea-table-views-file'.
Written as annotated, human-readable Lisp rather than a single
compact `prin1' dump -- comments are transparent to the Lisp
reader, so `sp-vulpea-table-views-load' still reads this back
as one plain sexp, but the file itself can also be read (or
hand-edited) without decoding a bare space-separated property
list."
  (with-temp-file sp-vulpea-table-views-file
    (insert ";; Saved Vulpea table views -- generated by `sia-vulpea-table-view-save'.\n")
    (insert ";; Each entry below: (NAME TAGS COLUMNS SORT-BY PARENT-OF PARENT-PROP)\n")
    (insert ";;   NAME         view name, as typed when saving\n")
    (insert ";;   TAGS         list of tags a note must have ALL of (nil = no filter)\n")
    (insert ";;   COLUMNS      ordered fields to show: :title/:tags/:id/:file, or a\n")
    (insert ";;                string naming a meta key\n")
    (insert ";;   SORT-BY      column to sort by (nil = unsorted)\n")
    (insert ";;   PARENT-OF    a note ID, the literal \"self\", or nil (no parent filter)\n")
    (insert ";;   PARENT-PROP  meta key checked against PARENT-OF (nil = default \"parents\")\n")
    (insert "(\n")
    (dolist (entry sp-vulpea-table-views)
      (sia-vulpea--insert-view-entry entry))
    (insert ")\n")))
#+end_src

** Prompt helpers

Small readers for the save command. =sia-vulpea--read-column-list= reads space-separated column names, turning names starting with a colon into keywords (=:title=, =:tags=, =:id=, =:file=) and leaving the rest as meta-key strings, with =:title= as the default. =sia-vulpea--read-tags= reads a tag list, and =sia-vulpea--read-sort-by= reads an optional single sort column the same way.

#+begin_src emacs-lisp -i
(defun sia-vulpea--read-column-list (&optional prompt)
  "Read a space-separated list of columns as keywords/strings."
  (mapcar (lambda (c) (if (string-prefix-p ":" c) (intern c) c))
          (split-string (read-string (or prompt "Columns: ") ":title") nil t)))

(defun sia-vulpea--read-tags ()
  "Read a space-separated list of tags."
  (split-string (read-string "Filter by tags (space-separated, blank for all): ") nil t))

(defun sia-vulpea--read-sort-by ()
  "Read an optional single sort column."
  (let ((s (read-string "Sort by column (blank for none): ")))
    (unless (string-empty-p s) (if (string-prefix-p ":" s) (intern s) s))))
#+end_src

** Saving a view

=sia-vulpea-table-view-save= prompts for a name, tags, columns, sort column, parent filter (via =sia-vulpea-read-parent= from =sp-vulpea-dblock=, which offers None, the current note as self, or any note) and an optional parent meta property. A self choice is stored literally and resolved each time the view is used, so the view means children of whatever note you are in. The view replaces any existing one with the same name and is written to disk. Bound to =C-c w V= below.

#+begin_src emacs-lisp -i
(defun sia-vulpea-table-view-save (name tags columns sort-by parent-of parent-prop)
  "Save (or overwrite) a named Vulpea table view, persisted to disk.
PARENT-OF is chosen via `sia-vulpea-read-parent' -- \"None\",
\"Current note (self)\", or any note picked through
`sia-vulpea-select-note' (candidates show their tags). A
\"self\" choice is stored as-typed, not resolved now -- it's
resolved fresh every time the view is opened, so a \"self\" view
means \"children of whatever note I'm in right now\", wherever
you invoke it from."
  (interactive
   (list (read-string "Save view as: ")
         (sia-vulpea--read-tags)
         (sia-vulpea--read-column-list
          "Columns (space-separated; :title/:tags/:id/:file or meta keys): ")
         (sia-vulpea--read-sort-by)
         (sia-vulpea-read-parent t)
         (let ((s (read-string "Parent meta property (blank for \"parents\"): ")))
           (unless (string-empty-p s) s))))
  (setf (alist-get name sp-vulpea-table-views nil nil #'string=)
        (list tags columns sort-by parent-of parent-prop))
  (sp-vulpea-table-views-save-to-disk)
  (message "Saved Vulpea table view \"%s\"" name))
#+end_src

** Deleting a view

=sia-vulpea-table-view-delete= removes a view chosen with completion and rewrites the file.

#+begin_src emacs-lisp -i
(defun sia-vulpea-table-view-delete (name)
  "Delete a saved Vulpea table view by NAME, with completion."
  (interactive (list (completing-read "Delete view: "
                                       (mapcar #'car sp-vulpea-table-views) nil t)))
  (setq sp-vulpea-table-views (assoc-delete-all name sp-vulpea-table-views))
  (sp-vulpea-table-views-save-to-disk)
  (message "Deleted Vulpea table view \"%s\"" name))
#+end_src

** Selecting a view

=sia-vulpea--select-view= prompts for a view name and returns its fields with parent-of still unresolved. It raises an error when no views have been saved yet.

#+begin_src emacs-lisp -i
(defun sia-vulpea--select-view ()
  "Prompt for a saved view name with completion.
Return (TAGS COLUMNS SORT-BY PARENT-OF PARENT-PROP), PARENT-OF
still unresolved (may literally be \"self\")."
  (unless sp-vulpea-table-views
    (user-error "No saved Vulpea table views yet -- use `sia-vulpea-table-view-save' first"))
  (let ((name (completing-read "View: " (mapcar #'car sp-vulpea-table-views) nil t)))
    (cdr (assoc name sp-vulpea-table-views))))
#+end_src

** Opening a saved view

=sia-vulpea-open-saved-table= picks a view and opens it as a live table with =sia-vulpea-open-table=, passing the view name so each view gets its own reusable buffer. A self parent is resolved against the buffer you called it from, before the table buffer takes over. It repeats the selection logic of =sia-vulpea--select-view= instead of calling it, because it also needs the name. Bound to =C-c w v= below.

#+begin_src emacs-lisp -i
(defun sia-vulpea-open-saved-table ()
  "Select a saved Vulpea table view (minibuffer completion) and open it live.
Opens into a buffer named after the view (e.g. \"*vulpea:
NAME*\"), so different saved views stay in their own separate,
independently reusable buffers rather than sharing one. A
\"self\" parent-of in the view is resolved against the buffer
this command was called from, before the new table buffer takes
over -- same reasoning as in `sia-vulpea-open-table'."
  (interactive)
  (unless sp-vulpea-table-views
    (user-error "No saved Vulpea table views yet -- use `sia-vulpea-table-view-save' first"))
  (let* ((name (completing-read "View: " (mapcar #'car sp-vulpea-table-views) nil t))
         (view (cdr (assoc name sp-vulpea-table-views))))
    (pcase-let ((`(,tags ,columns ,sort-by ,parent-of ,parent-prop) view))
      (sia-vulpea-open-table tags columns sort-by
                             (sia-vulpea--resolve-parent-of parent-of)
                             parent-prop
                             name))))
#+end_src

* Inline mounting

These functions replace the text of each =vulpea-table= dynamic block in an Org buffer with a live =vui= table, and put the static text back before saving so the file always contains real content.

** Buffer-local state

=sia-vulpea--inline-table-instances= records the marker and =vui= instance of every live table in the buffer. =sia-vulpea--inline-tables-active= says whether live tables should be shown, and is what lets them come back after a save.

#+begin_src emacs-lisp -i
;;; Inline mounting -------------------------------------------------------

(defvar-local sia-vulpea--inline-table-instances nil
  "Alist of (MARKER . VUI-INSTANCE) for live inline Vulpea tables
currently mounted in this buffer.")

(defvar-local sia-vulpea--inline-tables-active nil
  "Non-nil if inline Vulpea tables are meant to stay live in this
buffer -- survives save/reopen via the hooks below.")
#+end_src

** Finding vulpea-table blocks

=sia-vulpea--dblock-vulpea-table-regions= scans the buffer for =vulpea-table= dynamic blocks, reads the parameters on each begin line as a property list, and returns those parameters with the start and end of the block's content. Blocks whose parameters cannot be read are skipped.

#+begin_src emacs-lisp -i
(defun sia-vulpea--dblock-vulpea-table-regions ()
  "Return (PARAMS CONTENT-BEGIN CONTENT-END) for each vulpea-table
dblock in the buffer, top-to-bottom."
  (let (blocks)
    (save-excursion
      (goto-char (point-min))
      (while (re-search-forward "^[ \t]*#\\+BEGIN:[ \t]+vulpea-table\\(.*\\)$" nil t)
        (let* ((params-str (match-string 1))
               (params (ignore-errors (car (read-from-string (format "(%s)" params-str)))))
               (content-begin (progn (forward-line 1) (point)))
               (content-end (if (re-search-forward "^[ \t]*#\\+END:" nil t)
                                 (line-beginning-position)
                               (point))))
          (when params (push (list params content-begin content-end) blocks)))))
    (nreverse blocks)))
#+end_src

** Mounting live tables

=sia-vulpea-inline-tables-mount= first clears any existing live tables, then for every block (bottom to top, so earlier positions stay valid) deletes the static content and mounts a =sia-vulpea-table= component there with =vui-mount-inline=. The parent-of parameter is resolved in the note's own buffer so self means this note, matching the dblock writer.

#+begin_src emacs-lisp -i
(defun sia-vulpea-inline-tables-mount ()
  "Replace every vulpea-table dblock's content in this buffer with a
live, clickable `sia-vulpea-table' component. Blocks are processed
bottom-to-top so earlier positions stay valid as later ones are
rewritten."
  (interactive)
  (sia-vulpea--inline-tables-clear)
  (dolist (block (reverse (sia-vulpea--dblock-vulpea-table-regions)))
    (pcase-let ((`(,params ,cbeg ,cend) block))
      (let ((tags (plist-get params :tags))
            (columns (plist-get params :columns))
            (sort-by (plist-get params :sort-by))
            ;; Resolved here, in this note's own buffer, so "self"
            ;; means this note -- same as the dblock writer does.
            (parent-of (sia-vulpea--resolve-parent-of (plist-get params :parent-of)))
            (parent-prop (plist-get params :parent-prop)))
        (goto-char cbeg)
        (delete-region cbeg cend)
        (let* ((component (vui-component 'sia-vulpea-table
                            :tags tags
                            :columns columns
                            :sort-by sort-by
                            :parent-of parent-of
                            :parent-prop parent-prop))
               (instance (vui-mount-inline component)))
          (push (cons (copy-marker cbeg) instance) sia-vulpea--inline-table-instances)))))
  (setq sia-vulpea--inline-tables-active t))
#+end_src

** Clearing live tables

=sia-vulpea--inline-tables-clear= unmounts every live instance and then reruns =org-dblock-update= on each =vulpea-table= block to regenerate its static text. It does not change the active flag, which lets the save hooks use it temporarily.

#+begin_src emacs-lisp -i
(defun sia-vulpea--inline-tables-clear ()
  "Unmount live inline tables and regenerate plain dblock text in
their place, without touching `sia-vulpea--inline-tables-active'."
  (dolist (cell sia-vulpea--inline-table-instances)
    (vui-unmount (cdr cell)))
  (setq sia-vulpea--inline-table-instances nil)
  (save-excursion
    (goto-char (point-min))
    (while (re-search-forward "^[ \t]*#\\+BEGIN:[ \t]+vulpea-table" nil t)
      (beginning-of-line)
      (ignore-errors (org-dblock-update)))))
#+end_src

** Unmount and toggle

=sia-vulpea-inline-tables-unmount= clears the live tables and turns the active flag off. =sia-vulpea-inline-tables-toggle= switches between the two states and reports the new state; it is bound to =C-c w t= below.

#+begin_src emacs-lisp -i
(defun sia-vulpea-inline-tables-unmount ()
  "Unmount all live inline Vulpea tables in this buffer, restoring
plain (static) dblock text so the buffer has real content to save."
  (interactive)
  (sia-vulpea--inline-tables-clear)
  (setq sia-vulpea--inline-tables-active nil))

(defun sia-vulpea-inline-tables-toggle ()
  "Toggle live, clickable inline Vulpea tables in the current buffer."
  (interactive)
  (if sia-vulpea--inline-tables-active
      (progn (sia-vulpea-inline-tables-unmount)
             (message "Inline Vulpea tables: off"))
    (sia-vulpea-inline-tables-mount)
    (message "Inline Vulpea tables: on")))
#+end_src

** Save hooks

Before saving, live tables are cleared so the file receives the static block text; after saving, they are mounted again if the buffer had them active. An =org-mode-hook= installs both functions as buffer-local =before-save-hook= and =after-save-hook= entries in every Org buffer.

#+begin_src emacs-lisp -i
(defun sia-vulpea--inline-tables-before-save ()
  "Unmount live inline tables before saving, so the file gets real
text instead of ephemeral widget state."
  (when sia-vulpea--inline-table-instances
    (sia-vulpea--inline-tables-clear)))

(defun sia-vulpea--inline-tables-after-save ()
  "Remount live inline tables after saving, if they were active."
  (when sia-vulpea--inline-tables-active
    (sia-vulpea-inline-tables-mount)))

(add-hook 'org-mode-hook
          (lambda ()
            (add-hook 'before-save-hook #'sia-vulpea--inline-tables-before-save nil t)
            (add-hook 'after-save-hook #'sia-vulpea--inline-tables-after-save nil t)))
#+end_src

* Inserting a dblock from a view

** Insert table from view

=sia-vulpea-insert-table-from-view= creates a =vulpea-table= dynamic block at point from a saved view and fills it immediately. A self parent is inserted literally, so the block always tracks the children of the note it lives in.

#+begin_src emacs-lisp -i
;;; Insert a dblock from a saved view --------------------------------------

(defun sia-vulpea-insert-table-from-view ()
  "Insert a vulpea-table dblock at point, using a saved view
selected via minibuffer completion. PARENT-OF is inserted as-is
(including a literal \"self\") -- the dblock writer resolves it
fresh on every update, so a \"self\" view dropped into a note
always tracks that note's own children, not whichever note it
was inserted from."
  (interactive)
  (pcase-let ((`(,tags ,columns ,sort-by ,parent-of ,parent-prop) (sia-vulpea--select-view)))
    (org-create-dblock (list :name "vulpea-table" :tags tags :columns columns
                              :sort-by sort-by :parent-of parent-of :parent-prop parent-prop))
    (org-update-dblock)))
#+end_src
