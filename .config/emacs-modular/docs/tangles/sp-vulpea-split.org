* Hooking sp-vulpea-split into denote-create

[2026-10-16 Fri]

Hook sp-split-leave-parents and all the linked functions into a denote naming scheme (without actually running Denote), to maintain consistent file-naming.
- ~sp-split-leave-parents~ now renames the new note with Denote’s naming scheme.
- ~vulpea-split-heading~, by default, writes the file itself under a slug.org name.

What I did instead:

- Rename after the split :: once vulpea has written the new note, the command calls ~denote-rename-file~ on it. That gives you ~20261016T101500--some-heading__tag1_tag2.org~.
- Settings it relies on :: Denote’s own settings apply, including ~denote-file-name-components-order~ and the slug functions.
- Title and keywords :: the title comes from the ~#+title~ vulpea wrote, and the keywords are the note’s tags.
- No prompts, links unaffected :: confirmations are turned off for that call. Denote rewrites ~#+title~ and ~#+filetags~ and saves. The org ID doesn’t change, so id links and the parents and source links aren’t affected.
- Database re-sync :: the command then forgets the old path in the vulpea database and indexes the new one.
- Opting out :: set ~sp-split-denote-names~ to ~nil~ to turn the renaming off.

Limitations:

- Existing slug file :: vulpea still checks for an existing slug.org before writing, so a leftover file with that name makes it refuse the split.
- Finding the new name :: I find it by comparing the directory before and after the rename, because I couldn’t confirm what ~denote-rename-file~ returns. That could pick the wrong file if something else creates a file in that directory at that instant.
- Front matter :: the note gets no ~#+identifier~ line, since Denote only needs the identifier in the file name.
- Private vulpea function :: the re-sync calls ~vulpea-db--forget-file~, which is private, like the existing hook on ~vulpea-split--write-file~.
- You’ll also need Denote installed (the module now requires it), and your denote-directory should cover wherever the split notes land.

** Resulting elisp file

#+begin_src elisp
;;; sp-vulpea-split.el --- Split a vulpea heading out with parents and a link left behind -*- lexical-binding: t; -*-

;; Package-Requires: ((emacs "28.1") (denote "3.0"))

;;; Commentary:

;; `sp-split-leave-parents' wraps `vulpea-split-heading'.  On top of the
;; normal split it:
;;
;; 1. Adds a `- parents :: [[id:...][Title]]' meta line to the new note,
;;    pointing at the note the heading came from.  The source is the
;;    nearest ancestor heading with an ID, else the file-level note (its
;;    ID is created when missing).  When the subtree already has a
;;    `parents' line, the new link is put in front of the old value,
;;    separated by a comma.
;;
;; 2. Leaves a plain link to the new note in the source file, as a line
;;    of body text exactly where the heading started (not a heading).
;;    With a prefix argument no link is left.
;;
;; 3. Renames the new file with Denote's file-naming scheme
;;    (`ID--title__keywords.org'), using `denote-rename-file', so split
;;    notes are named like the rest of your Denote files.  The note keeps
;;    its org ID, so links are unaffected.  Disable with
;;    `sp-split-denote-names'.
;;
;; Steps 1 and 2 hook `vulpea-split--write-file', a private function of
;; vulpea, and only act while `sp-split-leave-parents' is running.  A
;; plain `vulpea-split-heading' is unchanged.

;;; Code:

(require 'org)
(require 'org-id)
(require 'subr-x)
(require 'seq)
(require 'vulpea)
(require 'denote)

;; These must be defined before the functions below use them in `let',
;; so that the bindings are dynamic.
(defvar sp-split--active nil
  "Non-nil while `sp-split-leave-parents' is running.")

(defvar sp-split--want-link t
  "Non-nil when the split should leave a plain link in the source file.")

(defgroup sp-split nil
  "Split vulpea headings out with parents and a link left behind."
  :group 'applications)

(defcustom sp-split-denote-names t
  "When non-nil, name split-out notes with Denote's file-naming scheme."
  :type 'boolean
  :group 'sp-split)

(defun sp-split--link-to (id fallback-title)
  "Return an id link to ID, titled from the database or FALLBACK-TITLE."
  (org-link-make-string
   (concat "id:" id)
   (if-let* ((note (vulpea-db-get-by-id id)))
       (vulpea-note-title note)
     fallback-title)))

(defun sp-split--parent-link (id)
  "Return (PARENT-ID . LINK) for the note the heading with ID lives in.
Walks up the ancestors of the heading and takes the first one with an
ID.  If none has one, falls back to the file-level note, creating its
ID when it is missing."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (when-let* ((pos (org-find-entry-with-id id)))
         (goto-char pos)
         (let (pid title)
           (while (and (not pid) (org-up-heading-safe))
             (when-let* ((x (org-entry-get (point) "ID")))
               (setq pid x
                     title (org-link-display-format
                            (org-get-heading t t t t)))))
           (unless pid
             (goto-char (point-min))
             (setq pid (or (org-entry-get (point-min) "ID")
                           (org-id-get-create))
                   title (or (and (fboundp 'vulpea-buffer-title-get)
                                  (vulpea-buffer-title-get))
                             (file-name-base path))))
           (cons pid (sp-split--link-to pid title))))))))

(defun sp-split--body-with-parent (body parent-id link)
  "Return BODY with LINK recorded in its `parents' meta line.
PARENT-ID is the id LINK points to."
  (let* ((case-fold-search nil)
         ;; Only the section before the first child heading: children
         ;; may carry `parents' lines of their own, which stay untouched.
         (top-end (or (string-match "^\\*+ " body) (length body)))
         (top (substring body 0 top-end))
         (rest (substring body top-end)))
    (cond
     ;; A parents line already exists: prepend the new link to its value.
     ((string-match
       "^\\([ \t]*[-+][ \t]+parents[ \t]+::[ \t]*\\)\\(.*\\)$" top)
      ;; Read everything out of the match data before calling anything
      ;; that may clobber it.
      (let* ((mb (match-beginning 0))
             (me (match-end 0))
             (prefix (match-string 1 top))
             (existing (string-trim (match-string 2 top))))
        (if (string-search (concat "id:" parent-id) existing)
            body
          (concat (substring top 0 mb)
                  prefix link
                  (if (string-empty-p existing)
                      ""
                    (concat ", " existing))
                  (substring top me)
                  rest))))
     (t
      (let ((line (concat "- parents :: " link)))
        (cond
         ((string-empty-p body) line)
         ;; Body opens with meta already: join that list.
         ((string-match-p "\\`[ \t]*[-+][ \t]+[^ \t\n]+[ \t]+::" body)
          (concat line "\n" body))
         (t (concat line "\n\n" body))))))))

(defun sp-split--insert-source-link (id title)
  "Insert a plain link to ID on the line where its heading starts.
TITLE is the fallback description.  The link goes in front of the
heading, so it is still there once vulpea cuts the subtree.  Return a
cons of markers around the inserted text, or nil."
  (when-let* ((note (vulpea-db-get-by-id id))
              (path (vulpea-note-path note)))
    (with-current-buffer (find-file-noselect path)
      (org-with-wide-buffer
       (when-let* ((pos (org-find-entry-with-id id)))
         (goto-char pos)
         (let ((beg (copy-marker pos)))
           (insert (sp-split--link-to id (org-link-display-format title))
                   "\n")
           (cons beg (copy-marker (point)))))))))

(defun sp-split--write-file-advice (fn &rest args)
  "Around advice for `vulpea-split--write-file'.
FN is the original function and ARGS its arguments: PATH ID TITLE HEAD
TAGS PROPERTIES BODY.  Does nothing unless `sp-split-leave-parents' is
running."
  (if (not sp-split--active)
      (apply fn args)
    (pcase-let ((`(,path ,id ,title ,head ,tags ,props ,body) args))
      ;; The subtree is still in the source file at this point, and
      ;; vulpea has already run its checks, so a refused split never gets
      ;; this far.
      (let* ((parent (sp-split--parent-link id))
             (body (if parent
                       (sp-split--body-with-parent
                        body (car parent) (cdr parent))
                     body))
             (stub (when sp-split--want-link
                     (sp-split--insert-source-link id title))))
        (condition-case err
            (funcall fn path id title head tags props body)
          (error
           ;; Writing the new file failed: take the link back out.
           (when (and stub (marker-buffer (car stub)))
             (with-current-buffer (marker-buffer (car stub))
               (delete-region (car stub) (cdr stub))))
           (signal (car err) (cdr err))))))))

(defun sp-split--denote-rename (note)
  "Rename the file of NOTE with Denote's naming scheme, then re-sync vulpea.
Return the note as vulpea knows it afterwards.  The org ID stays the
same, so id links keep working.  Denote's own `denote-rename-file' does
the naming (identifier, sluggified title, keywords from the tags); its
return value is not relied on, the new name is found by diffing the
directory."
  (let* ((old (vulpea-note-path note))
         (id (vulpea-note-id note))
         (dir (file-name-directory old))
         (before (directory-files dir nil directory-files-no-dot-files-regexp t)))
    ;; No prompts, and save the front matter Denote rewrites.
    (let ((denote-rename-confirmations nil)
          (denote-save-buffers t))
      ;; TITLE `keep-current' reads the `#+title' written by the split;
      ;; KEYWORDS are the note's tags; no signature, default date.
      (denote-rename-file old 'keep-current (vulpea-note-tags note) nil nil))
    (let ((new (car (seq-difference
                     (directory-files dir nil directory-files-no-dot-files-regexp t)
                     before #'string-equal))))
      (if (not new)
          note
        (let ((new-path (expand-file-name new dir)))
          (vulpea-db--forget-file old)
          (org-id-add-location id new-path)
          (vulpea-db-update-file new-path)
          (message "Named with Denote: %s" new)
          (or (vulpea-db-get-by-id id) note))))))

;;;###autoload
(defun sp-split-leave-parents (&optional no-link)
  "Run `vulpea-split-heading', recording where the heading came from.
The new note gets a `- parents ::' line linking back to the note the
subtree was split out of, and the source note gets a plain link to the
new note on the line where the heading started.  The new file is then
renamed with Denote's naming scheme when `sp-split-denote-names' is
non-nil.  With a prefix argument NO-LINK, the link in the source is not
left."
  (interactive "P")
  (let* ((sp-split--active t)
         (sp-split--want-link (not no-link))
         ;; Keep vulpea's own stub option (the prefix argument) out of it.
         (current-prefix-arg nil)
         (note (call-interactively #'vulpea-split-heading)))
    (if (and note sp-split-denote-names)
        (sp-split--denote-rename note)
      note)))

(unless (fboundp 'vulpea-split--write-file)
  (display-warning
   'sp-vulpea-split
   "`vulpea-split--write-file' not found; this vulpea version is not supported"))
(advice-add 'vulpea-split--write-file :around #'sp-split--write-file-advice)

(provide 'sp-vulpea-split)
;;; sp-vulpea-split.el ends here
#+end_src

I’ve updated ~sp-vulpea-split.el~ so the new note gets a ~#+identifier:~ line.

After the Denote rename, the module reads the identifier from the new file name with ~denote-retrieve-filename-identifier~, so the line always matches the name. For example, ~20261016T101500--some-heading__tag1_tag2.org~ gets ~#+identifier: 20261016T101500~.

- Placement :: the line goes right after ~#+filetags:~, or after #+title: if there are no tags. It stays below the property drawer, so the org ID is still first in the file.
- No duplicates :: if the file already has an ~#+identifier:~ line, nothing is added.
- Ordering :: the line is added and saved before the file is re-indexed in vulpea.
- Opting out :: it’s part of the Denote naming step, so setting ~sp-split-denote-names~ to ~nil~ turns it off along with the renaming.

The new note has no ~#+date:~ line, so the front matter is title, filetags and identifier, in that order.

** Adding a way to manage stray footnotes

[2026-10-17 Sat]

#+begin_quote
I don't use footnote sections in org-mode. However, when splitting headings into different files, the corresponding footnotes don't always get carried over, and they get lost as the sources from which I got certain information. can you add a checker to this function, which makes sure that repeat occurences of a footnote across different headings receives redundancy, and the source note doesn't lose the footnote definition once it moves to another file, instead getting copied in place for the relevant headings?
#+end_quote

I’ve added a footnote check to sp-vulpea-split.el. It runs as part of sp-split-leave-parents. I haven’t run any of it, since there’s no Emacs in my sandbox. I only checked that the parentheses balance. Please try it on a throwaway copy of a note first.

*** What it does

- References left without a definition :: if the subtree cites a footnote whose definition is elsewhere in the source file, each heading in the new note that cites it gets its own copy. The copy goes at the end of that heading’s own text, since you don’t use a footnote section.
- Definitions that leave with the subtree :: if a definition sits inside the subtree but headings that stay in the source still cite it, those headings get a copy before the subtree is cut. The source keeps its sources.
- Repeated citations :: when the same footnote is cited from several headings in the new note, each heading without its own definition gets one.
- Dangling references :: if a footnote is cited but has no definition anywhere, the echo area says so, and the reference is left as it was.
- Summary :: after the split, a message such as “Footnotes: 2 definition(s) copied into the new note, 1 into the source” appears.

*Labels:* Org doesn’t allow the same label to be defined twice in one file.
- In each file, the first copy keeps the original label, and later ones become [fn:smith-2], [fn:smith-3] and so on, with the references in that heading renamed to match.
- If you’d rather have unlabelled inline footnotes ([fn::text]) for the copies, say so, because that’s a different approach.

*** Details

- Inline footnotes: ~[fn:name:text]~ is treated as a definition, and copies are written as normal ~[fn:name] text~ definitions.
- Definitions in a footnote section :: definitions in a ~* Footnotes~ section of the source are found and copied like any others.
- Footnotes I leave alone :: footnotes that don’t need the check, such as ones whose definition is already in the same heading, are left alone.
- Failures :: if the footnote step fails for any reason, the split carries on and a message says the footnote step was skipped.
- Turning it off :: set sp-split-check-footnotes to nil.
