** Choosing between ~citar-vulpea~ and ~citar-denote~
Do citar-vulpea and citar-denote conflict in their functionalities?

Yes, in practice they compete, but only for one thing: which system citar uses as its notes backend.

Both packages plug into citar’s notes-source mechanism.
citar-vulpea-mode makes citar create, open, and look up literature notes in your vulpea collection.
citar-denote does the same for Denote, where notes are files identified by their filenames.
Citar uses one active notes source at a time (the citar-notes-source variable). If you enable both modes, whichever one activates last takes over, and the other is silently ignored. As far as I know they don’t break each other in any other way.

The two note systems are also separate:

Storage: vulpea indexes org files into a database, while Denote relies on its filename convention.
Linking and queries: each package works with its own system’s links, metadata, and lookups.
Result: if you ran both, you’d end up with two parallel sets of literature notes that don’t know about each other.

If your notes live in vulpea, which is what you’ve been setting up, install only citar-vulpea and leave citar-denote out. If you do keep both packages around, for example to read an old Denote collection, you can switch between them by toggling the relevant mode or setting citar-notes-source explicitly. Don’t leave both enabled.

Denote itself can also coexist with vulpea as a separate tool. The only conflict is at the citar layer, where you have to choose one.
