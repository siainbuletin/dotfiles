The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module sets up the =elfeed= feed reader, =elfeed-org= for keeping the feed list in an Org file, and a command for capturing feed entries into Org through =org-protocol=. It is not in any module list in =init.el=, and the notes in =conditional-loading.org= describe it as unconfigured, so it is a work in progress that does not currently load.

The file ends with =(provide 'sp-rss)=, the =elfeed-org= block sets =rmh-elfeed-org-files= (it used to wrap a =setq= in =:custom=), and the capture command stubs =raise-frame= with =cl-letf= (it used the obsolete =flet=). A closing comment wonders how feeds could tie into bibliography management, as in Emacs Writing Studio.

** Elfeed

Configures =elfeed= with its database in an =elfeed= folder in =user-emacs-directory=, shows entries with =display-buffer= so they open alongside the search list, and binds =C-c w e= to open it. There is no =:ensure= here, so it relies on the package being installed some other way.

#+begin_src emacs-lisp -i
(use-package elfeed
  :custom
  (elfeed-db-directory
   (expand-file-name "elfeed" user-emacs-directory))
  (elfeed-show-entry-switch 'display-buffer)
  :bind
  ("C-c w e" . elfeed))
#+end_src

** elfeed-org

Installs =elfeed-org= and runs =(elfeed-org)= to read the feed list from Org files. The =:custom= section sets =rmh-elfeed-org-files=, the variable =elfeed-org= reads, to =~/Documents/elfeed.org=. It used to wrap a =setq= of a made-up variable =sia-elfeed-org-files= in the list, which =use-package= reads as setting a variable called =setq=, so it signalled an error instead of setting the file list.

#+begin_src emacs-lisp -i
(use-package elfeed-org
  :ensure t
  :config
  (elfeed-org)
  :custom
  (rmh-elfeed-org-files (list (sp-path sp-documents-dir "elfeed.org"))))
#+end_src

* Capturing entries

** Capture selected entries

=yant/elfeed-capture-entry=, judging by its prefix adapted from another user's config, tags the selected search entries as opened, marks them read and, for each one with a link, calls =org-protocol-capture= with template =B=, the link, a title combining feed and entry names, and the entry itself. =raise-frame= is temporarily stubbed out so capturing does not pop frames. It then refreshes the entries and moves to the next line. Template =B= must exist in the capture templates. The stub uses =cl-letf= because =flet= is obsolete and no longer available in current Emacs.

#+begin_src emacs-lisp -i
(defun yant/elfeed-capture-entry ()
  "Capture selected entries into inbox."
  (interactive)
  (elfeed-search-tag-all 'opened)
  (previous-logical-line)
  (let ((entries (elfeed-search-selected)))
    (cl-loop for entry in entries
             do (elfeed-untag entry 'unread)
             when (elfeed-entry-link entry)
             do (cl-letf (((symbol-function 'raise-frame) #'ignore))
                  (org-protocol-capture (list :template "B"
                                              :url it
                                              :title (format "%s: %s"
                                                             (elfeed-feed-title (elfeed-entry-feed entry))
                                                             (elfeed-entry-title entry))
                                              :elfeed-data entry))))
    (mapc #'elfeed-search-update-entry entries)
    (unless (use-region-p) (forward-line))))
#+end_src
