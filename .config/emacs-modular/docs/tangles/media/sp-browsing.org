This module is meant to set up an environment for browsing from within Emacs: EWW, Elpher (for Gopher and Gemini) and =consult-omni=. Most of it is still an outline of section headers; the code is a command for opening a link either in EWW or in the macOS default browser, and the =consult-omni= setup: a vendored copy of the package, the search commands by scope (=consult-omni-web=, =consult-omni-local=, =consult-omni-scholar=) and a =Vulpea= source.

The link command depends on =consult= and =consult-omni= and on the macOS =open= program. The module ends with a =provide= form and is listed in =sp-late-modules= in =init.el=, so it loads after startup.

* EWW helpers

** Open a link in EWW or the system browser

=open-link-at-point-or-minibuffer-with-choice= finds a URL by trying, in order:

1. the URL at point,
2. a =consult= selection over URLs in the buffer,
3. a =consult-omni= search,
4. a plain prompt.

Then:

- It asks whether to open the URL in the macOS browser (via the shell =open= command) or in EWW.
- For EWW it splits the window: the original keeps the top 20% and EWW gets the bottom 80%.

Some caveats: =thing-at-point--list= does not appear to be a standard Emacs function, so the second fallback may error; =consult-omni= is called for its return value, which may not be a URL; and the =open= command only works on macOS.

#+begin_src emacs-lisp -i
;;;;; Helper functions for eww

;; Open link in eww or browser
(defun open-link-at-point-or-minibuffer-with-choice ()
  "Use `consult` to select a link at point, in the buffer, from `consult-omni` results, or prompt for a URL.
  Then choose to open it in macOS default browser or eww.
  If 'eww' is chosen, the link is opened in a window that occupies 80% of the frame height below the current one."
  (interactive)
  (let* ((url (or (thing-at-point 'url)                             ;; Check if there's a URL at point
                (consult--read (thing-at-point--list 'url))       ;; Use consult to select a URL from the buffer
                (consult-omni)                                    ;; Use consult-omni results to select a link
                (read-string "Enter URL: "))))                    ;; Fall back to manual URL entry
    (if url
      (let ((choice (completing-read "Open link in: " '("macOS Browser" "eww"))))
        (cond
         ((string-equal choice "macOS Browser")
          (shell-command (concat "open " (shell-quote-argument url))))
         ((string-equal choice "eww")
          ;; Calculate the height for the top window (20% of the frame height)
          (let ((window (selected-window))
                (top-window-height (floor (* 0.2 (window-total-height)))))
            ;; Split window with 20% height on top and 80% height for eww on the bottom
            (select-window (split-window window top-window-height))
            (eww url)))))
      (message "No URL provided."))))
#+end_src

** consult-omni

*** Explainer for the functionality

=consult-omni= searches many sources from one minibuffer prompt. This module keeps a copy of it in =libraries/modules/cloned/consult-omni/= ([[file:../../../libraries/modules/cloned/consult-omni/VENDORED.org][VENDORED.org]] has the upstream commit, the license and the local patches), so it can be fixed here, and loads it from there instead of letting Elpaca install it. [[file:../academic/sp-fetch-academic.org][sp-fetch-academic]] uses it for scholarly searches.

The =browser-history= source requires =browser-hist=, which is not vendored: it is installed with =use-package= and an Elpaca recipe (=agzam/browser-hist.el=) before =consult-omni=, which waits for it with =:after=.

Every source requires the package it searches (=elfeed=, =notmuch=, =consult-gh=, =consult-mu=...), and one that is not installed made the =:config= fail with =Cannot open load file ... elfeed=: =require= with =NOERROR= does not cover the packages a file requires in turn. =sp-consult-omni-load-module= replaces the loader's =consult-omni-sources--load-module= and skips such a source with a message in =*Messages*=. Install the package to get the source.

To set consult-omni up properly, you should provide sources for the information that will show up. Currently, the ones that I want are:

| Litdb          | Should work directly with the database of articles that I already have on hand. | Done: the =litdb= source ([[*Consulting litdb][below]])                                 |
| DEVONThink     | Curious if the backend would even allow such usage at any point                 | Not done, see the TODO below                                        |
| Vulpea         | Search the titles of my notes without ripgrep                                    | Done: the =Vulpea= source ([[*A Vulpea source for the local search][below]])                      |

See what sources should have dynamic commands (meaning completion)
- sending the query to the servers multiple times especially if you type slowly! Depending on the service provider and the API model, you may want to avoid hitting the server too frequently

Define when you actually need ~consult-omni~ for multiple sources.

You can also use this for querying local sources, if needed.

*** Why the search failed with "Args out of range"

The error was =Args out of range: [], 0=. =[]= is an empty vector, and the only place in consult-omni that takes element 0 of the vector of enabled sources is =consult-omni--multi-lookup=. So every search ran with *no enabled source at all*.

The cause was in the old configuration, not in the package:

1. =(require 'consult-omni-sources)= does not define any source. It only defines the loader =consult-omni-sources-load-modules=. The call to the loader sat in a block marked =:tangle no= (the "Scoped source search" block of the old doc), so it never ran and =consult-omni--sources-alist= stayed empty.
2. Every name in =consult-omni-multi-sources= is looked up in that alist; names that are not there are silently dropped. All of them were dropped, so =consult-omni-multi= asked for a vector of zero sources.
3. Even with the sources loaded, a source whose =:enabled= test fails is dropped too: =Google= without =consult-omni-google-customsearch-key=, =Scopus= without its key, =GitHub= without the =consult-gh= package, =Notes Search= without =consult-omni-notes-files=. A list made only of such names fails the same way.

The loader is now called in =:config=, after the API keys are loaded. Besides that, the vendored copy has a guard: when no source is enabled it says so (=consult-omni: no enabled sources; ...=) instead of failing in =aref=.

There was a second bug in the three scope commands. They called =consult-omni-multi= with =args= in the position of =min-input= (the signature is =initial prompt sources no-callback min-input &rest args=), which made the minimum input length a list. They now go through one helper.

Checked in Emacs 29.3 in batch: the vendored files read without syntax errors and the new guard signals the =user-error= on an empty vector. Not run with a real =consult-omni= session (the container has no MELPA access and no consult checkout was loaded), so a first search on the Mac is still the real test.

*** Bootstrapping the package

=:ensure nil= with =:load-path= loads the vendored copy; the paths are in constants, because =:load-path= evaluates the symbols in its list as variables (the same pattern as =sp-consult-snapfile=). The secrets file is where the API keys go, see [[*Per source customization][Per source customization]].

#+begin_src emacs-lisp -i
;;;; consult-omni

;; A copy of consult-omni (GPL-3.0-or-later, Armin Darvish) lives in
;; `libraries/modules/cloned/consult-omni/'; see VENDORED.org there for the
;; version and the local patches.

(defconst sp-consult-omni-dir
  (expand-file-name "libraries/modules/cloned/consult-omni/" sp-emacs-dir)
  "Folder with the vendored copy of consult-omni.")

(defconst sp-consult-omni-sources-dir
  (expand-file-name "sources/" sp-consult-omni-dir)
  "Folder with the source modules (Google, OpenAlex, ...) of consult-omni.")

(defcustom sp-consult-omni-secrets-file
  (expand-file-name "consult-omni-secrets.el" sp-var-dir)
  "File with the API keys of the consult-omni sources.
It is loaded when consult-omni starts and is not tracked by Git (`var/' is
ignored).  Put plain `setq' forms in it, for example
\(setq consult-omni-brave-api-key \"...\")."
  :group 'spcustom
  :type 'file)

;; `:load-path' reads a list as a list of paths and evaluates each symbol in it
;; as a variable, so the paths go through variables.
(use-package browser-hist
  :ensure (browser-hist :host github :repo "agzam/browser-hist.el")
  :demand t) ; `consult-omni-browser-history' requires it

(defun sp-consult-omni-load-module (symbol)
  "Load the consult-omni source SYMBOL; skip it when a package it needs is missing."
  (condition-case err
      (require symbol nil t)
    (error
     (message "consult-omni: source `%s' skipped: %s" symbol (error-message-string err))
     nil)))

(use-package consult-omni
  :ensure nil
  :load-path (sp-consult-omni-dir sp-consult-omni-sources-dir)
  :after (consult browser-hist)

  :custom
  (consult-omni-show-preview t) ;;; show previews
  (consult-omni-preview-key "C-o") ;;; set the preview key to C-o
  (consult-omni-highlight-matches-in-minibuffer t) ;;; highlight matches in minibuffer
  (consult-omni-highlight-matches-in-file t) ;;; highlight matches in files
  (consult-omni-default-count 5) ;;; set default count
  (consult-omni-default-page 0) ;;; set the default page (default is 0 for the first page)

  (consult-omni-default-format-candidate 'consult-omni--higlight-format-candidate) ;; show annotations for the results

  ;; Adjust these (e.g. increase to avoid hitting a source such as an API too frequently)
  (consult-omni-dynamic-input-debounce 0.8)
  (consult-omni-dynamic-input-throttle 1.6)
  (consult-omni-dynamic-refresh-delay 0.8)
  ;; Optionally set backend for http request (either 'url, 'request, or 'plz)
  ;; (consult-omni-http-retrieve-backend 'plz)

  :config
  ;; API keys first: a source is only enabled once its key is set.
  (load sp-consult-omni-secrets-file t t)
  ;; `(require 'consult-omni-sources)' only defines the loader; the sources
  ;; themselves are defined when the loader runs.  Without this call the list
  ;; of sources stays empty and any search fails with "Args out of range: [], 0".
  (require 'consult-omni-sources)
  ;; A source requires the package it searches (`elfeed', `notmuch', `consult-gh'...).
  ;; `require' with NOERROR only covers the source file itself, so one missing
  ;; package aborted this whole `:config'.  Skip that source and say so.
  (advice-add 'consult-omni-sources--load-module :override #'sp-consult-omni-load-module)
  (consult-omni-sources-load-modules)
  ;; Embark actions on the results
  (with-eval-after-load 'embark-consult
    (require 'consult-omni-embark)))
#+end_src

*** Results first: never search the web by accident

In =consult-omni-multi= the results arrive while you type. Pressing =RET= when the cursor is not on a result (the results are not there yet, or nothing matched) submits the input as a new candidate, and the default =consult-omni-default-new-function= (=consult-omni-external-search=) sends it to the search engine in the browser, which opened Google. =sp-consult-omni-ignore-new= replaces it: it does nothing but say so in the echo area. Only =RET= on a result calls the source's callback and opens it with =consult-omni-default-browse-function= (=browse-url=); =consult-omni-external-search= is still there when you do want a web search.

#+begin_src emacs-lisp -i
;; A search whose input matches no result must not leave Emacs: the default
;; (`consult-omni-external-search') sends it to a web search engine in the
;; browser when RET is pressed before the results have arrived.
(defun sp-consult-omni-ignore-new (cand)
  "Do nothing with the input CAND that is not one of the results."
  (message "consult-omni: \"%s\" is not a result, nothing was opened; wait for the results, or use `consult-omni-external-search' to search the web"
           (if (stringp cand) (substring-no-properties cand) cand))
  nil)

(setq consult-omni-default-new-function #'sp-consult-omni-ignore-new)
#+end_src

*** Better scope for searches

Adding different interactive commands from the consult-omni-multi, which will just perform a search for everything.
- these work as regular interactive commands

All three go through one helper. It calls =consult-omni-multi= with =apply=, so the extra =ARGS= are spread and the =min-input= argument stays unset, and the commands are =(interactive)= with no prefix argument (a prefix argument is not a valid initial input).

#+begin_src emacs-lisp -i
(defun sp--consult-omni-scoped (label default-sources initial prompt sources no-callback args)
  "Run `consult-omni-multi' on SOURCES, or on DEFAULT-SOURCES when nil.
LABEL names the search in the prompt unless PROMPT is given.  INITIAL,
NO-CALLBACK and ARGS are passed on; the minimum input length is left unset."
  (let ((prompt (or prompt
                    (concat "[" (propertize label 'face 'consult-omni-prompt-face) "]" " Search:  "))))
    (apply #'consult-omni-multi initial prompt (or sources default-sources) no-callback nil args)))
#+end_src

**** Consulting litdb

[[https://github.com/jkitchin/litdb][litdb]] is the database of articles I already have. Two sources call its command line program (=sp-consult-omni-litdb-command=, found on =exec-path=; the source is disabled when it is not):

- =litdb= (narrow with =l=): =litdb fulltext=, quick, and part of =consult-omni-multi-sources=, so a default search lists its results with the others.
- =litdb semantic= (narrow with =L=, command =consult-omni-litdb-semantic=): =litdb vsearch=, by meaning. It loads the embedding model on every call, so it is a command of its own and not in the default list.

The program runs asynchronously and the previous call is killed when you type on, so Emacs does not freeze; =sp-consult-omni-litdb-timeout= (60 s) stops a call that hangs. *The first call after a start is slow* (litdb imports its libraries, and the semantic search the model), and results only show up after it. litdb prints through =rich=, so the command is given a =--fmt= template that puts one result on one line with printable separators (=␟= between source, score and text, =␞= after a result) and =COLUMNS=100000= so =rich= does not wrap it. A result is a web address (an OpenAlex work, a DOI) or a file, whatever litdb stored as its source: =RET= opens the address with =consult-omni-default-browse-function= or visits the file. Nothing in it is specific to the articles, so records that another tool puts into litdb (for example DEVONthink, see the TODO below) turn up too.

Not run against a real litdb: the container has neither Emacs nor a litdb database. The command line options (=-n=, =-f=) and the =source=, =score=, =snippet=, =text= template variables were read from litdb 2.2.3.

#+begin_src emacs-lisp -i
;;;;; A litdb source for the local article database

(defcustom sp-consult-omni-litdb-command "litdb"
  "Name or path of the litdb command line program."
  :group 'spcustom
  :type 'string)

(defcustom sp-consult-omni-litdb-timeout 60
  "Seconds to wait for litdb before the search is given up.
The first call after a start can take long: litdb imports its
libraries (and, for the semantic search, loads the embedding model)."
  :group 'spcustom
  :type 'integer)

(defvar sp--consult-omni-litdb-process nil
  "The litdb process of the search in progress, if any.")

(defconst sp--consult-omni-litdb-field-separator "␟"
  "Printable character between the fields of a litdb result.")

(defconst sp--consult-omni-litdb-record-separator "␞"
  "Printable character after each litdb result.")

(defun sp--consult-omni-litdb-format (field)
  "Return the jinja template for the litdb result column FIELD.
Newlines and square brackets are replaced: litdb prints through rich,
which reads brackets as markup, and one result must stay on one line."
  (format "%s|replace('\\n',' ')|replace('[','(')|replace(']',')')"
          field))

(defun sp--consult-omni-litdb-template (kind)
  "Return the `--fmt' template of litdb for KIND, `fulltext' or `semantic'."
  (let ((sep sp--consult-omni-litdb-field-separator))
    (concat "{{ source }}" sep "{{ score|round(3) }}" sep "{{ "
            (sp--consult-omni-litdb-format
             (if (eq kind 'fulltext) "snippet" "text[:200]"))
            " }}" sp--consult-omni-litdb-record-separator)))

(defun sp--consult-omni-litdb-arguments (kind query count)
  "Return the litdb arguments that search for QUERY.
KIND is `fulltext' or `semantic'; COUNT is the number of results."
  (if (eq kind 'fulltext)
      ;; Quote each word: the full text index reads `-' and `:' as operators.
      (append (list "fulltext" "-n" (number-to-string count)
                    "-f" (sp--consult-omni-litdb-template kind))
              (mapcar (lambda (word) (format "\"%s\"" (replace-regexp-in-string "\"" "" word)))
                      (split-string query "[ \t]+" t)))
    (append (list "vsearch" "-n" (number-to-string count)
                  "-f" (sp--consult-omni-litdb-template kind))
            (split-string query "[ \t]+" t))))

(defun sp--consult-omni-litdb-address (source)
  "Return the web address of the litdb SOURCE, or nil.
A DOI is turned into a doi.org address."
  (cond ((string-match-p "\\`https?://" source) source)
        ((string-match-p "\\`10\\.[0-9]+/" source) (concat "https://doi.org/" source))
        ((string-match-p "\\`doi:" source)
         (concat "https://doi.org/" (substring source 4)))))

(defun sp--consult-omni-litdb-candidate (record query name)
  "Return the consult-omni candidate for the litdb RECORD found with QUERY.
RECORD is the text of one result; NAME is the name of the source."
  (let* ((fields (split-string record sp--consult-omni-litdb-field-separator))
         (source (string-trim (or (nth 0 fields) "")))
         (score (string-trim (or (nth 1 fields) "")))
         (text (string-trim (or (nth 2 fields) "")))
         (title (if (string-empty-p text) source text)))
    (unless (string-empty-p source)
      (consult-omni-propertize-by-plist
       (copy-sequence title)
       `(:title ,title :source ,name :url ,(sp--consult-omni-litdb-address source)
         :search-url nil :query ,query :litdb-source ,source :score ,score)
       0 1))))

(defun sp--consult-omni-litdb-parse (output query name)
  "Return the candidates of the litdb OUTPUT for QUERY, found by source NAME."
  (delq nil
        (mapcar (lambda (record) (sp--consult-omni-litdb-candidate record query name))
                (split-string output sp--consult-omni-litdb-record-separator t "[ \t\n]+"))))

(defun sp--consult-omni-litdb-run (kind name input callback args)
  "Search litdb for INPUT without blocking Emacs and pass the results to CALLBACK.
KIND is `fulltext' or `semantic'; NAME is the name of the consult-omni
source; ARGS are the arguments consult-omni received."
  (pcase-let* ((`(,query . _) (consult-omni--split-command
                               input (seq-difference args (list :callback callback))))
               (program (executable-find sp-consult-omni-litdb-command)))
    (when (process-live-p sp--consult-omni-litdb-process)
      (delete-process sp--consult-omni-litdb-process))
    (when (and program query (not (string-blank-p query)))
      (let* ((buffer (generate-new-buffer " *consult-omni-litdb*"))
             ;; rich wraps lines at 80 columns when it does not print to a terminal;
             ;; sh below drops standard error so warnings do not mix into the results
             (process-environment (cons "COLUMNS=100000" process-environment))
             (timer nil)
             (process
              (make-process
               :name "consult-omni-litdb" :buffer buffer :noquery t
               :command (append (list "sh" "-c" "exec \"$@\" 2>/dev/null" "sh" program)
                               (sp--consult-omni-litdb-arguments
                                kind query (max 1 (or consult-omni-default-count 5))))
               :sentinel
               (lambda (proc _event)
                 (when (memq (process-status proc) '(exit signal))
                   (when timer (cancel-timer timer))
                   (let ((results (and (eq proc sp--consult-omni-litdb-process)
                                       (zerop (process-exit-status proc))
                                       (with-current-buffer buffer
                                         (sp--consult-omni-litdb-parse (buffer-string) query name)))))
                     (when (and (not (zerop (process-exit-status proc)))
                                (eq proc sp--consult-omni-litdb-process))
                       (message "litdb: search failed (exit %s); see `M-x list-processes'"
                                (process-exit-status proc)))
                     (when (and results (functionp callback))
                       (funcall callback results)))
                   (kill-buffer buffer))))))
        (setq sp--consult-omni-litdb-process process)
        (setq timer (run-at-time sp-consult-omni-litdb-timeout nil
                                 (lambda () (when (process-live-p process)
                                              (delete-process process)))))))
    nil))

**** Consulting local files (=consult-omni-local=):

***** A Vulpea source for the local search

The =Vulpea= source answers the TODO "enter this search into vulpea without ripgrep". It is a dynamic source: for each input it runs =vulpea-db-query= with a predicate that keeps the notes whose title contains every word of the input (case-insensitive), and shows up to =consult-omni-default-count= of them. Selecting one visits the note. It searches titles only, not the text; ripgrep stays in the list for that.

Not tested against the real Vulpea database: the container has no Vulpea. The calls (=vulpea-db-query= with a filter function, =vulpea-note-title=, =vulpea-note-path=) are the ones other modules of this configuration use, and =vulpea-visit= is used when it exists.

#+begin_src emacs-lisp -i
;;;;; A Vulpea source for the local search

(defun sp--consult-omni-vulpea-items (query)
  "Return the Vulpea notes whose title contains every word of QUERY."
  (let ((case-fold-search t)
        (words (mapcar #'regexp-quote (split-string query "[ \t]+" t))))
    (when words
      (vulpea-db-query
       (lambda (note)
         (let ((title (vulpea-note-title note)))
           (and (stringp title)
                (cl-every (lambda (word) (string-match-p word title)) words))))))))

(defun sp--consult-omni-vulpea-candidate (note query)
  "Return the consult-omni candidate for the Vulpea NOTE found with QUERY."
  (consult-omni-propertize-by-plist
   (copy-sequence (vulpea-note-title note))
   `(:title ,(vulpea-note-title note) :source "Vulpea" :url nil :search-url nil
     :query ,query :note ,note)
   0 1))

(defun sp-consult-omni-vulpea-callback (cand)
  "Visit the Vulpea note of the consult-omni candidate CAND."
  (when-let* ((note (get-text-property 0 :note cand)))
    (if (fboundp 'vulpea-visit)
        (vulpea-visit note)
      (find-file (vulpea-note-path note)))))

(cl-defun sp-consult-omni-vulpea-fetch-results (input &rest args &key callback &allow-other-keys)
  "Find the Vulpea notes whose title matches INPUT and pass them to CALLBACK."
  (pcase-let* ((`(,query . _) (consult-omni--split-command input (seq-difference args (list :callback callback))))
               (results (mapcar (lambda (note) (sp--consult-omni-vulpea-candidate note query))
                                (seq-take (sp--consult-omni-vulpea-items query)
                                          (max 1 (or consult-omni-default-count 5))))))
    (when (and results (functionp callback))
      (funcall callback results))
    results))

  (consult-omni-define-source "Vulpea"
                              :narrow-char ?v

                              :require-match nil

                              :on-return #'identity
                              :on-callback #'sp-consult-omni-vulpea-callback
                              :preview-key consult-omni-preview-key
                              :search-hist 'consult-omni--search-history
                              :select-hist 'consult-omni--selection-history
                              :enabled (lambda () (fboundp 'vulpea-db-query))
                              :group #'consult-omni--group-function
                              :sort t
                              :interactive consult-omni-intereactive-commands-type))

*** Google Scholar: biblio-gscholar or consult-omni

The question: add a Google Scholar source to consult-omni, or keep =biblio-gscholar= (loaded in =sp-fetch-academic=)?

*Recommendation: keep =biblio-gscholar= for Google Scholar and do not write a consult-omni source for it. Use the consult-omni scholar search with OpenAlex, PubMed and Scopus for exploring, and join the two at the DOI.* This is from reading both sources; I could not reach Google Scholar from the container, so nothing below was measured.

| | =biblio-gscholar= (existing) | A Google Scholar source for consult-omni |
|-+-+-|
| Data | Scrapes =scholar.google.com= HTML (there is no API), with a made-up cookie | Would have to scrape the same page; consult-omni has no Scholar source (upstream's README leaves scholar commands to the user) |
| Requests per search | One search page, then one request per result for its BibTeX (synchronous, in the parser) | The same, repeated as you type: consult-omni is a dynamic search, re-run after =consult-omni-dynamic-input-debounce= (0.8 s) and at most every =-throttle= (1.6 s), and it queries every source of the list at once |
| When Google blocks | You search when you decide to, so one CAPTCHA wall is rare and visible | Keystroke-driven searching is the pattern Scholar blocks first; the source would fail quietly in the middle of a list of sources, with Scholar's HTML error page parsed as "no results" |
| What you get | Full BibTeX, ready to insert, through =biblio= | Titles and authors; the BibTeX needs the per-result request again, or a DOI lookup |
| Merging sources | Separate command | One list with OpenAlex, PubMed, Scopus, notes |
| Maintenance | Small, existing, one scraper | A second scraper to keep, or a dependency on =gscholar-bibtex= from the source |

Why OpenAlex covers most of what Scholar was for: it is an open API (no key), indexes hundreds of millions of works, returns the DOI and, for open access works, the PDF address, which is exactly what =sp-fetch-academic-omni= needs. What Scholar has that OpenAlex lacks (ranking by citations, "cited by", books and theses coverage) are the reasons to keep =biblio-gscholar=: one explicit search at a time, with the BibTeX in hand.

Revisit if =biblio-gscholar= stops working (Scholar changes its markup) or if a Scholar result list inside the consult-omni list becomes worth the CAPTCHA risk. A source that only runs on =RET= (=consult-omni-multi-static=) would lower the risk but not remove the scraper.
