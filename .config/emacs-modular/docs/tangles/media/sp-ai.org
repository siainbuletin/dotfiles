Literate source for =libraries/modules/media/sp-ai.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

This module installs packages for working with large language models and coding agents from inside Emacs. Most of them are only installed; apart from the Anthropic login for =agent-shell= and turning on =vulpea-mcp=, none of them get keybindings, backends or API keys here, so their defaults (or settings made elsewhere) apply.

The packages are =gptel= (a general chat client for many LLM providers) with =gptel-agent=, =claude-code= (runs the Claude Code CLI inside Emacs), =eca= (Editor Code Assistant), =agent-shell= (a shell-like interface to coding agents), =efrit= (an agent that runs Claude-driven commands inside Emacs), =monet= (the Claude Code IDE protocol for Emacs) and =vulpea-mcp=, which exposes the Vulpea note database to LLMs over the Model Context Protocol. =claude-code= waits for =inheritenv= (from =sp-env=), =vterm= and =eat= (from =sp-terminal=), and =vulpea-mcp= ties this module to the Vulpea setup in =sp-vulpea-base=.

** gptel

After the =Code= marker, installs =gptel=. The =(:wait t)= recipe tells Elpaca to finish installing it before continuing, presumably so later packages that build on gptel, such as =gptel-agent= just below, find it available.

#+begin_src emacs-lisp -i
;;; Code:
;;;; Agents that require an API key
;;;; gptel
(use-package gptel
  :ensure (:wait t))
#+end_src

** claude-code

Installs =claude-code= from Steve Molitor's GitHub repository. It runs the Claude Code command-line tool in a terminal buffer inside Emacs. =:after= makes it load only once =inheritenv=, =vterm= and =eat= have all loaded, since it can use either terminal backend and uses inheritenv to pass the Emacs environment to the process. If any of the three never loads (see the note on =inheritenv= in =sp-env=), claude-code is never configured either.

#+begin_src emacs-lisp -i
;;;; claude-code
(use-package claude-code
  :ensure (:type git :host github :repo "stevemolitor/claude-code.el")
  :after (inheritenv vterm eat))
#+end_src

** agent-shell

Installs =agent-shell=, which runs coding agents in a comint-style buffer. Its Anthropic authentication is set to log in (=:login t=) rather than use an API key, so the Claude agent signs in with an account. No other agents are configured here.

#+begin_src emacs-lisp -i
;;;; agent-shell
(use-package agent-shell
  :ensure t
  :config
  (setq agent-shell-anthropic-authentication
        (agent-shell-anthropic-make-authentication
         :login t)))
#+end_src

Installs =efrit= from GitHub. Efrit is an AI coding agent that lets Claude carry out natural-language commands by running code inside Emacs. Nothing is configured or bound.

* Working with AI with my knowledge base

** vulpea-mcp

The comment explains the goal: letting an LLM see the Vulpea notes. =vulpea-mcp= is installed straight from its Codeberg git repository and serves the Vulpea database to MCP-capable agents.

#+begin_src emacs-lisp -i
;;;; Working with AI with my knowledge base
;; Making an LLM recognise my vulpea notes
(use-package vulpea-mcp
  :ensure (:type git :repo "https://codeberg.org/nicolas-graves/vulpea-mcp.git")
  :config
  (vulpea-mcp-enable))
#+end_src

** Enabling vulpea-mcp

=vulpea-mcp-enable= is called from the =:config= of the form above. It used to be called at top level, while the module loaded, which only works if the function is already available then. Elpaca runs =use-package= bodies once the package is built, and since =sp-ai= is one of the late modules (loaded after startup, see [[file:../../load-order.org][the load order]]) the package is never there yet at that point, so the call failed and the rest of the module (=monet= and the =provide=) was skipped. In =:config= it runs after the package is loaded.

* Claude Code integration

** monet

Installs =monet=, also by Steve Molitor, which implements the Claude Code IDE protocol over a WebSocket. With it, Claude Code can see the current selection and diagnostics and show proposed changes as diffs in Emacs. It is only installed here, not enabled or hooked into =claude-code=.

#+begin_src emacs-lisp -i
;;; Enhacing the experience of Claude Code
(use-package monet
  :ensure (:type git :host github :repo "stevemolitor/monet"))
#+end_src
