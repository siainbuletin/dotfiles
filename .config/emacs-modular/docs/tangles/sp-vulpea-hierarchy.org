* Parent/child views of vulpea notes

** Context

My notes follow a Zettelkasten pattern. One file is one idea. A sub-note records its parent with a =- parents :: [[id:…][Title]]= line in its zeroth section, and vulpea stores that as metadata. =vulpea-graph= draws the links but doesn't show the hierarchy, so this module reads the =parent= metadata and builds the tree itself.

Two commands use the same tree:

- =vulpea-hierarchy-outline= shows the tree as a foldable Org buffer. Each heading is a link to its note.
- =vulpea-hierarchy-graph= draws the tree with Graphviz and shows the SVG.

As a proposal for the future, it would be nice to try to use Emacs 32's new Canvas feature (Emacs's proposed image type with a pixel buffer) to draw this buffer, but for now, we're falling back on a Graphviz architecture.

** Loading it

The module is loaded from =init.el=, in the Academic block of =lem--default-modules=, right after =sp-dgraphs=:

#+begin_src emacs-lisp :tangle no
'sp-vulpea-hierarchy
#+end_src

Graph view needs Graphviz (=brew install graphviz= on macOS).

*** Building the tree (lines 38–64)

This function returns a plist with three keys: =:notes= (id to note), =:children= (parent id to child ids) and =:roots= (parents that have no parent of their own).

- Lines 40-43 create two hash tables (=notes=, =children=) and one for =has-parent=, plus an empty =parent-ids= list. The tables use =equal= so UUID strings work as keys.
- Line 44 gets every note that has the parent key, using =vulpea-db-query-by-meta-key=.
- Line 45 records that note in =notes=.
- Lines 46-47 read the parent links of the note as =link= values. Each one is an id (the target note's UUID).
- Line 48 marks the note as having a parent, which keeps it out of the roots.
- Line 49 adds the note to its parent's child list.
- Line 50 collects the parent id, so the roots can be worked out later.
- Lines 51-55 load the parent notes themselves, when they don't carry a parent key. Without this their titles would show as =<missing …>=.
- Lines 56-64 return the plist. The roots are the collected parent ids minus the ids with a parent, sorted by title. =delete-dups= removes repeated parents, since one parent can have several children.

#+begin_src emacs-lisp
(defun vulpea-hierarchy--build ()
  "Return a plist describing the hierarchy.
:notes maps id to note, :children maps parent id to child ids,
:roots lists ids that are parents but have no parent themselves."
  (let ((notes (make-hash-table :test #'equal))
        (children (make-hash-table :test #'equal))
        (has-parent (make-hash-table :test #'equal))
        parent-ids)
    (dolist (note (vulpea-db-query-by-meta-key vulpea-hierarchy-parent-key))
      (puthash (vulpea-note-id note) note notes)
      (dolist (pid (vulpea-note-meta-get-list
                    note vulpea-hierarchy-parent-key 'link))
        (puthash (vulpea-note-id note) t has-parent)
        (push (vulpea-note-id note) (gethash pid children))
        (push pid parent-ids)))
    ;; Parents that carry no parent key themselves are not loaded yet.
    (dolist (note (vulpea-db-query-by-ids
                   (seq-remove (lambda (id) (gethash id notes))
                               (delete-dups parent-ids))))
      (puthash (vulpea-note-id note) note notes))
    (list :notes notes
          :children children
          :roots (sort (seq-remove (lambda (id) (gethash id has-parent))
                                   (delete-dups (copy-sequence parent-ids)))
                       (lambda (a b)
                         (string< (vulpea-hierarchy--title a notes)
                                  (vulpea-hierarchy--title b notes)))))))
#+end_src

(defun vulpea-hierarchy--title (id notes)
  "Title of note ID from NOTES, or a marker for a dangling link."
  (if-let ((note (gethash id notes)))
      (vulpea-note-title note)
    (format "<missing %s>" id)))

(defun vulpea-hierarchy--sorted-children (id tree)
  "Child ids of ID in TREE, sorted by title."
  (let ((notes (plist-get tree :notes)))
    (sort (copy-sequence (gethash id (plist-get tree :children)))
          (lambda (a b)
            (string< (vulpea-hierarchy--title a notes)
                     (vulpea-hierarchy--title b notes))))))

;;; Outline view

(defun vulpea-hierarchy--insert-outline (id tree depth seen)
  "Insert ID and its descendants from TREE as Org headings at DEPTH.
SEEN guards against parent cycles."
  (let* ((notes (plist-get tree :notes))
         (note (gethash id notes))
         (kids (vulpea-hierarchy--sorted-children id tree)))
    (insert (make-string depth ?*) " "
            (format "[[id:%s][%s]]" id (vulpea-hierarchy--title id notes)))
    (when kids
      (insert (format " [%d]" (length kids))))
    (when-let ((tags (and note (vulpea-note-tags note))))
      (insert " :" (string-join tags ":") ":"))
    (insert "\n")
    (if (member id seen)
        (insert (make-string (1+ depth) ?*) " cycle back to this note\n")
      (dolist (kid kids)
        (vulpea-hierarchy--insert-outline kid tree (1+ depth) (cons id seen))))))
#+end_src

#+begin_src emacs-lisp

;;;###autoload
(defun vulpea-hierarchy-outline ()
  "Show the note hierarchy as a foldable Org outline of id links."
  (interactive)
  (let ((tree (vulpea-hierarchy--build))
        (buf (get-buffer-create "*vulpea hierarchy*")))
    (with-current-buffer buf
      (let ((inhibit-read-only t))
        (erase-buffer)
        (org-mode)
        (dolist (root (plist-get tree :roots))
          (vulpea-hierarchy--insert-outline root tree 1 nil))
        (goto-char (point-min))
        (org-content 2))
      (setq buffer-read-only t))
    (pop-to-buffer buf)))
#+end_src

*** Graphviz source (lines 119–150)

This function returns Graphviz (DOT) text for the tree.

- Lines 119-122 bind the notes, the children, and a =drawn= table so a note is written only once.
- Lines 123-127 write the =digraph= header, the layout direction, and the default box style for nodes and edges.
- Lines 128-131 loop over the roots. Each root gets a numbered =subgraph cluster=. =style=invis= hides the cluster box, so it only groups nodes.
- Lines 132-141 walk the tree breadth first from the root. Each node is written once, with its title as the label. The root gets a blue fill and a thicker border, so top-level notes stand out.
- Line 142 closes the cluster.
- Lines 143-146 write one edge per parent to child link, after all the nodes.
- Lines 147-148 close the graph and return the text.

#+begin_src emacs-lisp
(defun vulpea-hierarchy--dot (tree)
  "Return Graphviz source for TREE, one cluster per root."
  (let ((notes (plist-get tree :notes))
        (children (plist-get tree :children))
        (drawn (make-hash-table :test #'equal)))
    (with-temp-buffer
      (insert "digraph vulpea {\n"
              (format "  rankdir=%s;\n" vulpea-hierarchy-rankdir)
              "  node [shape=box, style=\"rounded,filled\", fillcolor=\"#f4f4f4\","
              " fontname=\"Helvetica\"];\n"
              "  edge [color=\"#888888\"];\n")
      (let ((n 0))
        (dolist (root (plist-get tree :roots))
          (insert (format "  subgraph cluster_%d {\n    style=invis;\n" (cl-incf n)))
          (let ((queue (list root)))
            (while queue
              (let ((id (pop queue)))
                (unless (gethash id drawn)
                  (puthash id t drawn)
                  (insert (format "    %S [label=%S%s];\n"
                                  id (vulpea-hierarchy--title id notes)
                                  (if (equal id root)
                                      ", fillcolor=\"#d8e6f5\", penwidth=2"
                                    "")))
                  (setq queue (append queue (gethash id children)))))))
          (insert "  }\n")))
      (maphash (lambda (pid kids)
                 (dolist (kid kids)
                   (insert (format "  %S -> %S;\n" pid kid))))
               children)
      (insert "}\n")
      (buffer-string))))
#+end_src

#+begin_src emacs-lisp

;;;###autoload
(defun vulpea-hierarchy-graph ()
  "Render the note hierarchy with Graphviz and display the SVG."
  (interactive)
  (unless (executable-find "dot")
    (user-error "Graphviz `dot' not found on PATH"))
  (let ((dot (vulpea-hierarchy--dot (vulpea-hierarchy--build))))
    (with-temp-buffer
      (insert dot)
      (unless (zerop (call-process-region (point-min) (point-max) "dot" nil t nil
                                          "-Tsvg" "-o" vulpea-hierarchy-graph-file))
        (error "Graphviz failed: %s" (buffer-string))))
    (let ((buf (find-file-noselect vulpea-hierarchy-graph-file)))
      (with-current-buffer buf
        (revert-buffer t t))
      (pop-to-buffer buf))))
#+end_src
