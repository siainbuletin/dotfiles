Literate source for =libraries/modules/ui/lem-dashboard.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module configures the =dashboard= package, giving a start page with recent files, bookmarks, agenda items and registers. It is a lightly modified version of the Lambda Emacs dashboard (hence the =lem-= prefix), rewritten for readability.

It depends on =nerd-icons= for icons, optionally =page-break-lines=, the =sp-library-dir= variable for the banner images, and =sp-load-extras= from =early-init.el=. Nothing in this module calls =dashboard-setup-startup-hook=, so the dashboard is opened on demand with =dashboard-open=, =lem-dashboard= or =sp-goto-dashboard= rather than shown automatically at startup. =init.el= lists this module twice in its load list, which is harmless since =require= only loads it once.

* Dependencies

** nerd-icons

Loads =nerd-icons= eagerly when it is installed, because the dashboard needs icon functions available as soon as it renders.

#+begin_src emacs-lisp -i
;;;; Dependencies
;; Load dependencies from Lambda-Emacs. Note these packages are usually deferred
;; but they must be loaded with dashboard since it requires icons.
(when (locate-library "nerd-icons")
  (require 'nerd-icons))
#+end_src

** page-break-lines

Declares =page-break-lines= (which draws form-feed characters as horizontal rules, used by dashboard between sections) when extras are enabled and it is installed. Its config makes the rule character use the default font family so the line has no gaps.

#+begin_src emacs-lisp -i
;; dashboard dependency
(use-package page-break-lines
  :if (and sp-load-extras (locate-library "page-break-lines"))
  :defer t
  :config
  (set-fontset-font "fontset-default"
                    (cons page-break-lines-char page-break-lines-char)
                    (face-attribute 'default :family)))
#+end_src

** Theme-dependent logo

Picks the white or black Lambda logo from =sp-library-dir= depending on whether the first enabled theme is =lambda-dark=. The theme is checked once, when the module loads, so switching themes later does not change the logo. This value is overwritten in the next block anyway.

#+begin_src emacs-lisp -i
;;;; Header
(setq dashboard-startup-banner (concat sp-library-dir
                                  (if (eq (car custom-enabled-themes) 'lambda-dark)
                                      "lambda-logo-white.png"
                                   "lambda-logo-black.png")))

;; this if loop makes it easy to just choose between the different versons without
;; overcomplicating the color scheme that is being chosen
#+end_src

* Dashboard functions

** Hiding the mode line

=lem-dashboard-hide-modeline= turns off =hl-line-mode= and removes the mode line and header line in the =*dashboard*= buffer. The comments weigh the cleaner look against losing mode line information. It is currently not hooked up anywhere, since the hook in the =use-package= form is commented out.

#+begin_src emacs-lisp -i
;;;; Dashboard Functions
;; Hide modeline
;; this makes the dashboard a little bit cleaner
;; but the important stuff that shows up in the modeline should somehow be supplemented by the dashboard
;; this can also be held up by the fact that the minibuffer shows up at the top instead of the bottom
(defun lem-dashboard-hide-modeline ()
  "Hide modeline in the dashboard buffer."
  (let* ((dash-buffer (get-buffer "*dashboard*")))
    (with-current-buffer dash-buffer
      (hl-line-mode -1)
      (setq-local mode-line-format nil)
      (setq-local header-line-format nil))))
#+end_src

** Reopening the dashboard

=lem-dashboard= rebuilds the dashboard with =dashboard-insert-startupify-lists= if its buffer was killed or never created, switches to it, and makes it the only window. It assumes dashboard is already loaded, since that function is not autoloaded.

#+begin_src emacs-lisp -i
;; Functions to call dashboard when it kas been killed or not loaded
(defun lem-dashboard ()
  "Load dashboard and swith to buffer."
  (interactive)
  (let ((buffer "*dashboard*"))
    (when (not (get-buffer buffer))
      (dashboard-insert-startupify-lists))
    (switch-to-buffer buffer))
  (delete-other-windows))
#+end_src

** Going to the dashboard

=sp-goto-dashboard= simply switches to the =*dashboard*= buffer. Unlike =lem-dashboard= it does not recreate it, so if the buffer does not exist it creates an empty buffer with that name.

#+begin_src emacs-lisp -i
(defun sp-goto-dashboard ()
  "Goto the dashboard."
  (interactive)
  (switch-to-buffer "*dashboard*"))
#+end_src
