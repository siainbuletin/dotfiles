Literate source for =libraries/modules/ui/sp-posframe.el=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

The original file has no newline after its last line. Org always ends a tangled file with one, so tangling adds that final newline and changes nothing else.

This module uses =vertico-posframe= to show the minibuffer (the prompt and Vertico's candidates) in a child frame in the centre of the screen, like a quick switcher. It replaces the former =sp-mini-frame= (see "Why the name changed" below). For a few chosen commands (opening files and finding notes) it also dims the text of the windows behind it, so the focus stays on the prompt.

Dimming:

- Implemented here with buffer-local face remapping, using colour helpers from the built-in =color= library.
- It reacts to =find-file=, =vulpea-find= and =org-node-find=, so it ties in with the vulpea and org-node note setup.
- The colour blending relies on =color-blend=, which is not in Emacs 29 and only exists in newer =color.el= versions.
- The module is loaded in the window-management part of =init.el=, after =sp-tabs=.

The commentary at the top of the module says:

#+begin_quote
This configuration for vertico-posframe makes sure that the minibuffer is being
dimmed and centered when I'm looking for a particular file, or wanting to insert a
link. Inserting should still be placed somewhere in the bottom, so it can follow what
I'm writing in the current buffer without interrupting the focus on screen
#+end_quote

* Why the name changed

The module was called =sp-mini-frame= after the =mini-frame= package it was built on. That package is gone, so the name was wrong:

- =mini-frame-mode= hung Emacs on macOS (the CPU at 98% in =M-x=) with every setup tried: a tall frame, a frame resized to its content (#119), a fixed height (#122, #128) and the plain original (#134). Removing the styling did not change it, so the cause was the package in this setup, not the module's own code.
- =vertico-posframe= is built on =posframe=, the child-frame library many packages use, and is written for Vertico, which =sp-completion= already configures. It takes its size from Vertico's own candidates (=vertico-count=), so this module sets no height and has no resizing code.
- The name now says what is used: a posframe. The file, the feature and the doc are renamed, and =init.el= loads =sp-posframe= at the position where it loaded =sp-mini-frame=. Nothing else required the old feature.

The old name appears in the history of the CHANGELOG and in notes of the mode line modules (#114, #115), which describe what was true then.

* The posframe

** vertico-posframe-mode

Installs =vertico-posframe= (and =posframe= with it) and turns on =vertico-posframe-mode=, which draws Vertico's minibuffer in a child frame instead of at the bottom of the frame.

- =vertico-posframe-poshandler= is =posframe-poshandler-frame-center=: the frame is centred horizontally and vertically.
- =vertico-posframe-min-width= is 80 columns, wide enough for notes and their tags.
- =vertico-posframe-border-width= is 4: the padding around the text.
- The number of candidates is Vertico's own =vertico-count= (13, set in =sp-completion=); the posframe fits its content, so there is no blank box and no fixed height. (The frame is not given a height, which is what hung Emacs with =mini-frame=.)
- =vertico-posframe-fallback-mode= is =vertico-buffer-mode=, which is used in a terminal, where child frames do not exist.

#+begin_src emacs-lisp -i
(use-package vertico-posframe
  :ensure t
  :after vertico

  :custom
  (vertico-posframe-poshandler #'posframe-poshandler-frame-center) ; centered both ways
  (vertico-posframe-min-width 80)    ; wide enough for notes and their tags
  (vertico-posframe-border-width 4)  ; padding around the text
  (vertico-posframe-fallback-mode 'vertico-buffer-mode) ; terminals have no child frames
  ;; `vertico-count' (13) sets the number of candidates; the frame fits them.

  :config
  (vertico-posframe-mode 1)
)
#+end_src

* The nano-style M-x prompt

The prompt of =M-x= is styled like the one in nano-emacs, with the same code that was removed from the former =sp-mini-frame= while it was being made to work, now on the posframe. Only the text styling and the boxes are used; the frame is the same as for every other prompt.

- =sp-posframe-nano-commands= lists the commands styled this way: =execute-extended-command=, =amx=, =counsel-M-x= and =smex=.
- The prompt is shown in inverse video, bold, with a one-pixel box (a remap of =minibuffer-prompt= in that minibuffer only).
- A dotted line of =sp-posframe-divider-char= (=┈=; =nil= for none) is drawn under the input, in the divider colour of =sp-nano-style= (or the =shadow= face), with =sp-posframe-divider-priority= to order it against Vertico's own overlay. The line has 300 characters and =truncate-lines= is on in that minibuffer, so the window cuts it and it never wraps when the frame is narrow, which it did before.
- The styling is in =condition-case=: an error is shown in the echo area and the prompt still opens.

#+begin_src emacs-lisp -i
(defcustom sp-posframe-nano-commands
  '(execute-extended-command amx counsel-M-x smex)
  "Commands whose prompt is styled like nano's M-x."
  :type '(repeat function)
  :group 'minibuffer)

(defcustom sp-posframe-divider-char ?┈
  "Character repeated for the dotted line under the M-x input, or nil for none."
  :type '(choice character (const :tag "No line" nil))
  :group 'minibuffer)

(defcustom sp-posframe-divider-priority -50
  "Priority of the overlay with the dotted line under the M-x input."
  :type 'integer
  :group 'minibuffer)

(defconst sp-posframe--divider-length 300
  "Characters in the dotted line; the window cuts it at its edge.")

(defun sp-posframe--nano-p ()
  "Return non-nil when the prompt being shown is a nano-style M-x."
  (memq this-command sp-posframe-nano-commands))

(defun sp-posframe--divider-color ()
  "Return the colour of the dotted line."
  (or (and (fboundp 'sp-nano-style-divider-colour)
           (sp-nano-style-divider-colour))
      (face-foreground 'shadow nil t)))

(defun sp-posframe--style-nano ()
  "Give the M-x prompt nano's block and the input a dotted line below it.
The line is longer than any window and `truncate-lines' cuts it, so it never
wraps. An error is reported in the echo area and does not abort the prompt."
  (condition-case err
      (when (and (bound-and-true-p vertico-posframe-mode) (sp-posframe--nano-p))
        (face-remap-add-relative
         'minibuffer-prompt
         :inverse-video t :weight 'bold :box '(:line-width 1))
        (when sp-posframe-divider-char
          (setq-local truncate-lines t)
          (let ((ov (make-overlay (point-max) (point-max) nil nil t)))
            (overlay-put ov 'priority sp-posframe-divider-priority)
            (overlay-put ov 'after-string
                         (concat "\n"
                                 (propertize (make-string sp-posframe--divider-length
                                                          sp-posframe-divider-char)
                                             'face `(:foreground ,(sp-posframe--divider-color))))))))
    (error (message "sp-posframe: styling the prompt failed: %s" err))))

(add-hook 'minibuffer-setup-hook #'sp-posframe--style-nano)
#+end_src

* Dimming the background

When one of the listed commands opens the minibuffer, every buffer visible in the frame behind gets its face colours blended toward the background. Leaving the minibuffer restores them.

#+end_src

** Commands that dim

=sp-posframe-dim-commands= lists the commands that trigger dimming: =find-file=, =vulpea-find= and =org-node-find=.

#+begin_src emacs-lisp -i
(defvar sp-posframe-dim-commands '(find-file vulpea-find org-node-find)
  "Commands whose minibuffer should dim the underlying frame.")
#+end_src

** Dim amount

=sp-posframe-dim-amount= (0.45) is the blending factor passed to the colour blend.

#+begin_src emacs-lisp -i
(defvar sp-posframe-dim-amount 0.45
  "How far to blend text colors toward the background (0 = none, 1 = invisible).")
#+end_src

** Functions that dim

=sp-posframe-dim-functions= lists functions whose prompts dim the frame behind whoever calls them: =sp-select-note=, =sp-insert-note= and =sp-collec-query-select-note=. Each is advised with =:around= to bind =sp-posframe--dim-requested= while it runs; functions that are not defined yet are advised when a file is loaded.

#+begin_src emacs-lisp -i
(defvar sp-posframe-dim-functions
  '(sp-select-note sp-insert-note sp-collec-query-select-note)
  "Functions whose minibuffer should dim the underlying frame, whoever calls them.")

(defvar sp-posframe--dim-requested nil
  "Non-nil while a function in `sp-posframe-dim-functions' is running.")

(defun sp-posframe--request-dim (fn &rest args)
  "Call FN with ARGS, asking for the frame behind the minibuffer to be dimmed."
  (let ((sp-posframe--dim-requested t))
    (apply fn args)))

(defun sp-posframe-advise-dim-functions ()
  "Advise the functions in `sp-posframe-dim-functions' that are defined."
  (dolist (fn sp-posframe-dim-functions)
    (when (fboundp fn)
      (advice-add fn :around #'sp-posframe--request-dim))))

(sp-posframe-advise-dim-functions)
(add-hook 'after-load-functions (lambda (_file) (sp-posframe-advise-dim-functions)))
#+end_src

** Dimming state

=sp-posframe--dim-cookies= holds, per buffer, the face remapping cookies so they can be removed later. =sp-posframe--dimmed-buffers= records which buffers were dimmed.

#+begin_src emacs-lisp -i
(defvar-local sp-posframe--dim-cookies nil)
(defvar sp-posframe--dimmed-buffers nil)
#+end_src

** Blend two colours

=sp-posframe--blend= converts a foreground and background colour name to RGB, blends them by the given amount and returns a hex colour string. It returns nil when either colour is not a usable string.

#+begin_src emacs-lisp -i
(defun sp-posframe--blend (fg bg amount)
  (let ((f (and (stringp fg) (color-name-to-rgb fg)))
        (b (and (stringp bg) (color-name-to-rgb bg))))
    (when (and f b)
      (apply #'color-rgb-to-hex
             (append (color-blend f b amount) '(2))))))
#+end_src

** Dim a frame

=sp-posframe-dim= goes through each distinct buffer shown in the frame's windows.

- For every defined face that has a foreground colour, it adds a buffer-local remap to the blended colour, storing the cookie.
- A buffer that is already dimmed is left alone.
- Looping over the whole =face-list= for each buffer makes this somewhat heavy when many faces are defined.

#+begin_src emacs-lisp -i
(defun sp-posframe-dim (frame)
  "Dim all text in the buffers shown in FRAME."
  (let ((bg (face-background 'default frame)))
    (dolist (buf (delete-dups
                  (mapcar #'window-buffer (window-list frame 'no-minibuf))))
      (with-current-buffer buf
        (unless sp-posframe--dim-cookies
          (dolist (face (face-list))
            (let* ((fg (face-attribute face :foreground frame))
                   (dim (and (not (eq fg 'unspecified))
                             (sp-posframe--blend fg bg sp-posframe-dim-amount))))
              (when dim
                (push (face-remap-add-relative face :foreground dim)
                      sp-posframe--dim-cookies))))
          (push buf sp-posframe--dimmed-buffers))))))
#+end_src

** Undim

=sp-posframe-undim= removes all stored remappings from the dimmed buffers that still exist and clears the list.

#+begin_src emacs-lisp -i
(defun sp-posframe-undim ()
  (dolist (buf sp-posframe--dimmed-buffers)
    (when (buffer-live-p buf)
      (with-current-buffer buf
        (mapc #'face-remap-remove-relative sp-posframe--dim-cookies)
        (setq sp-posframe--dim-cookies nil))))
  (setq sp-posframe--dimmed-buffers nil))
#+end_src

** Only dim for chosen commands

=sp-posframe--maybe-dim= dims the frame of the window that was selected before the minibuffer opened, but only when =vertico-posframe-mode= is on and either the command running is one of =sp-posframe-dim-commands= or a function of =sp-posframe-dim-functions= asked for it.

#+begin_src emacs-lisp -i
(defun sp-posframe--maybe-dim ()
  (when (and (bound-and-true-p vertico-posframe-mode)
             (or sp-posframe--dim-requested
                 (memq this-command sp-posframe-dim-commands))
             (minibuffer-selected-window))
    (sp-posframe-dim (window-frame (minibuffer-selected-window)))))
#+end_src

** Hooks

Runs the dimming check whenever a minibuffer is set up and undims on every minibuffer exit. Since the exit hook undims everything, leaving a nested minibuffer also restores the colours while the outer prompt is still open.

#+begin_src emacs-lisp -i
(add-hook 'minibuffer-setup-hook #'sp-posframe--maybe-dim)
(add-hook 'minibuffer-exit-hook #'sp-posframe-undim)
#+end_src
