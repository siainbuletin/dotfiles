Literate source for =libraries/modules/ui/sp-theme-engine.el=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

This module builds the themes of the =sp= family, =sp-dark= and =sp-light= (files in =libraries/themes/sp/=). A theme there is three lines: the engine, a flavor and a name. Everything else is data that can be edited:

1. *Flavors* (=sp-theme-flavors=): twelve base colours for a dark and a light variant, in the style of Catppuccin's flavors. The dark flavor is a simplified =ef-dream= palette. The only hex codes of the system are here.
2. *Palette*: from a flavor, the 26 keys of the Doric palette (shadow, neutral and accent shades, six hues with a foreground and a background each) are derived by blending, not typed.
3. *Faces from Doric's bundles*: the theme calls =doric-themes-define-theme=, so about 1,300 faces come from the bundles of =doric-themes= (bold, italic, shadow, diff, error and so on) and not from hand-written lists.
4. *Semantic mappings* (=sp-theme-mappings=): Modus-style roles such as =bg-region=, =fg-heading-1=, =err= or =bg-search-current=, each pointing at a palette key. A flavor can point a role somewhere else.
5. *Mapped faces* (=sp-theme-mapped-faces=): the faces that are written against roles (region, mode line, links, headings, search, Org code). They override the bundles, so changing one mapping changes every face that uses it.
6. *Semantic face names* (=sp-theme-semantic=): faces such as =sp-urgent= and =sp-crucial=, after the Lambda themes, for modules that want a colour without knowing which theme is active. A flavor can override them.
7. *Ported Modus mechanisms*: headings (=sp-theme-headings=), fixed-pitch text in variable-pitch buffers (=sp-theme-mixed-fonts=) and variable-pitch UI (=sp-theme-variable-pitch-ui=). They are the settings a palette cannot hold. Bold and italic need no option here: they come from the Doric bundles.

Related notes: [[file:../../architecture/theme-system-design.org][theme-system-design.org]] and [[file:../../architecture/modus-faces-outside-global-system.org][modus-faces-outside-global-system.org]].

* Flavors

** The data

A flavor is a symbol, =dark= or =light=, with three parts:

- =:colors=: twelve base colours. =accent-1= is the warm accent (gold) and =accent-2= the cool one (lavender).
- =:tint=: how much of a hue is mixed into a background (=bg-red=, =bg-accent-primary=, …). It is higher on the dark flavor, where backgrounds need more colour to be seen.
- =:mappings= and =:semantic=: this flavor's changes to the shared tables below. Empty by default.

The dark colours are those of =ef-dream= (=bg-main=, =fg-main=, =red=, =green=, =yellow=, =blue=, =magenta=, =cyan=, the gold of =yellow-warmer=, the lavender of =magenta-cooler=, its cursor and border), without its fifty-odd tints. The light colours are the matching ones of =ef-day=, the warm light sibling of =ef-dream=, with a teal cyan instead of its blue one.

** Reading and changing colours

=sp-theme-color= and =sp-theme-set-color= work like =catppuccin-color= and =catppuccin-set-color=. After a change, =sp-theme-reload= loads the current theme again.

#+begin_src emacs-lisp -i
(defun sp-theme--flavor (flavor)
  "Return the plist of FLAVOR, an error if there is no such flavor."
  (or (alist-get flavor sp-theme-flavors)
      (error "No flavor `%s' in `sp-theme-flavors'" flavor)))

(defun sp-theme-color (name &optional flavor)
  "Return the base colour NAME of FLAVOR (default: the current flavor)."
  (alist-get name (plist-get (sp-theme--flavor (or flavor (sp-theme-current-flavor)))
                             :colors)))

(defun sp-theme-set-color (name value &optional flavor)
  "Set the base colour NAME of FLAVOR to VALUE and reload the theme."
  (interactive
   (let* ((flavor (intern (completing-read "Flavor: " '("dark" "light") nil t)))
          (names (mapcar (lambda (c) (symbol-name (car c)))
                         (plist-get (sp-theme--flavor flavor) :colors)))
          (name (intern (completing-read "Colour: " names nil t))))
     (list name (read-string (format "%s of %s: " name flavor)
                             (sp-theme-color name flavor))
           flavor)))
  (let* ((flavor (or flavor (sp-theme-current-flavor)))
         (colors (plist-get (sp-theme--flavor flavor) :colors)))
    (setcdr (assq name colors) value)
    (sp-theme-reload)))

(defun sp-theme-current-flavor ()
  "Return the flavor of the enabled sp theme, `dark' if there is none."
  (or (seq-some (lambda (theme) (get theme 'sp-theme-flavor)) custom-enabled-themes)
      'dark))

(defun sp-theme-reload ()
  "Load the current sp theme again, to pick up changed colours."
  (interactive)
  (when-let* ((theme (seq-find (lambda (th) (string-prefix-p "sp-" (symbol-name th)))
                               custom-enabled-themes)))
    (disable-theme theme)
    (load-theme theme t)))
#+end_src

* Palette

** Blending

=sp-theme-blend= returns the colour that is WEIGHT of B and the rest of A. It parses =#rrggbb= itself, so it works without a display.

#+begin_src emacs-lisp -i
;;;; Palette
(defun sp-theme--rgb (hex)
  "Return the (R G B) components, 0 to 255, of the colour HEX."
  (unless (string-match "\\`#\\([[:xdigit:]]\\{2\\}\\)\\([[:xdigit:]]\\{2\\}\\)\\([[:xdigit:]]\\{2\\}\\)\\'" hex)
    (error "Not a #rrggbb colour: %S" hex))
  (mapcar (lambda (i) (string-to-number (match-string i hex) 16)) '(1 2 3)))

(defun sp-theme-blend (a b weight)
  "Return the colour made of WEIGHT (0 to 1) of B and the rest of A."
  (apply #'format "#%02x%02x%02x"
         (cl-mapcar (lambda (x y) (round (+ (* x (- 1 weight)) (* y weight))))
                    (sp-theme--rgb a) (sp-theme--rgb b))))
#+end_src

** The Doric palette of a flavor

=sp-theme-palette= returns the 26 keys that =doric-themes-define-theme= reads, as a list of =(KEY "#rrggbb")=. The recipe, for flavor colours =bg=, =fg= and the hues:

- shadow and neutral shades: =bg= pulled towards =fg= (8% and 18%), and =fg= pulled towards =bg= (35% and 12%);
- intense shadow and the two accents: =bg= tinted with =accent-1= or =accent-2= (the flavor's tint, and the tint plus 12%), with the accent itself, lightly mixed with =fg=, as the foreground;
- the six hues: the colour is the foreground, and =bg= tinted with it is the background.

#+begin_src emacs-lisp -i
(defun sp-theme-palette (&optional flavor)
  "Return the Doric palette of FLAVOR, a list of (KEY COLOR)."
  (let* ((flavor (or flavor (sp-theme-current-flavor)))
         (tint (plist-get (sp-theme--flavor flavor) :tint))
         (c (lambda (name) (sp-theme-color name flavor)))
         (bg (funcall c 'bg-main))
         (fg (funcall c 'fg-main))
         (a1 (funcall c 'accent-1))
         (a2 (funcall c 'accent-2)))
    `((cursor ,(funcall c 'cursor))
      (bg-main ,bg)
      (fg-main ,fg)
      (border ,(funcall c 'border))
      (bg-shadow-subtle ,(sp-theme-blend bg fg 0.08))
      (fg-shadow-subtle ,(sp-theme-blend fg bg 0.35))
      (bg-neutral ,(sp-theme-blend bg fg 0.18))
      (fg-neutral ,(sp-theme-blend fg bg 0.12))
      (bg-shadow-intense ,(sp-theme-blend bg a1 (+ tint 0.12)))
      (fg-shadow-intense ,a1)
      (bg-accent-primary ,(sp-theme-blend bg a1 tint))
      (fg-accent-primary ,(sp-theme-blend a1 fg 0.25))
      (bg-accent-secondary ,(sp-theme-blend bg a2 tint))
      (fg-accent-secondary ,(sp-theme-blend a2 fg 0.25))
      ,@(mapcan (lambda (hue)
                  (let ((color (funcall c hue)))
                    (list (list (intern (format "fg-%s" hue)) color)
                          (list (intern (format "bg-%s" hue))
                                (sp-theme-blend bg color tint)))))
                '(red green yellow blue magenta cyan)))))
#+end_src

* Semantic mappings

** Roles

=sp-theme-mappings= is the Modus idea: a face asks for a role (=bg-region=), the mapping says which palette key plays it. A target is a palette key, another role (the chain is followed) or a literal =#rrggbb= string. A flavor's =:mappings= change single roles for that flavor only.

#+begin_src emacs-lisp -i
;;;; Semantic mappings
(defvar sp-theme-mappings
  '((fg-link . fg-blue)
    (fg-link-visited . fg-magenta)
    (bg-region . bg-accent-primary)
    (fg-region . fg-main)
    (bg-hl-line . bg-shadow-subtle)
    (bg-mode-line-active . bg-neutral)
    (fg-mode-line-active . fg-main)
    (bg-mode-line-inactive . bg-shadow-subtle)
    (fg-mode-line-inactive . fg-shadow-subtle)
    (bg-search-current . bg-yellow)
    (bg-search-lazy . bg-accent-secondary)
    (err . fg-red)
    (warning . fg-yellow)
    (success . fg-green)
    (info . fg-cyan)
    (fg-heading-1 . fg-accent-primary)
    (fg-heading-2 . fg-accent-secondary)
    (fg-heading-3 . fg-green)
    (fg-heading-4 . fg-blue)
    (fg-heading-other . fg-shadow-intense)
    (fg-prose-code . fg-cyan)
    (fg-prose-verbatim . fg-yellow)
    (bg-prose-block . bg-shadow-subtle)
    (fg-prose-block-delimiter . fg-shadow-subtle))
  "Semantic roles of the sp themes, an alist of (ROLE . TARGET).
TARGET is a key of the palette, another role, or a #rrggbb string.")

(defun sp-theme-role (role &optional flavor)
  "Return the colour that ROLE has in FLAVOR, or nil if it has none."
  (let* ((flavor (or flavor (sp-theme-current-flavor)))
         (palette (sp-theme-palette flavor))
         (own (plist-get (sp-theme--flavor flavor) :mappings))
         (target role)
         (steps 0))
    (while (and target (symbolp target) (< steps 10))
      (setq steps (1+ steps)
            target (or (alist-get target own)
                       (alist-get target sp-theme-mappings)
                       (cadr (assq target palette)))))
    (when (stringp target) target)))

(defun sp-theme-set-mapping (role target &optional flavor)
  "Make ROLE point at TARGET in FLAVOR, or in every flavor if nil, and reload."
  (interactive
   (list (intern (completing-read "Role: " (mapcar (lambda (m) (symbol-name (car m)))
                                                    sp-theme-mappings)
                                  nil t))
         (intern (read-string "Target (palette key or role): "))
         nil))
  (dolist (flavor (if flavor (list flavor) (mapcar #'car sp-theme-flavors)))
    (let ((cell (plist-member (sp-theme--flavor flavor) :mappings)))
      (setcar (cdr cell) (cons (cons role target) (assq-delete-all role (cadr cell))))))
  (sp-theme-reload))
#+end_src

** The faces written against roles

=sp-theme-mapped-faces= lists the faces that use roles. Each entry is =(FACE ATTRIBUTE VALUE …)=; the value of a colour attribute (=:foreground=, =:background=, =:distant-foreground=, =:overline=) that names a role is replaced by its colour, other values are used as they are. These faces are set after the Doric bundles, so they win. To restyle a face, change its entry; to recolour a group of faces, change the role.

(defconst sp-theme--colour-attributes
  '(:foreground :background :distant-foreground :overline)
  "The face attributes whose value may be a role.")

(defun sp-theme--face-attributes (entry flavor)
  "Return the attribute list of ENTRY in FLAVOR, with the roles replaced."
  (let ((attrs (cdr entry)) result)
    (while attrs
      (let* ((attr (pop attrs))
             (value (pop attrs)))
        (when (and (memq attr sp-theme--colour-attributes) (symbolp value))
          (setq value (sp-theme-role value flavor)))
        (when value
          (setq result (append result (list attr value))))))
    result))

** Headings

=sp-theme-headings= is =modus-themes-headings=: an alist of =(LEVEL . ATTRIBUTES)= with the attributes of that heading level (=:height=, =:weight=, =:slant=, =:inherit variable-pitch= …). The level =t= applies to the levels not listed, and =title= is the document title. =sp-theme-heading-faces= says which faces are the headings of each level.

(defun sp-theme--heading-faces ()
  "Return a list of (FACE . ATTRIBUTES) for `sp-theme-headings'."
  (mapcan (lambda (level)
            (when-let* ((attrs (or (cdr (assq (car level) sp-theme-headings))
                                   (and (integerp (car level))
                                        (cdr (assq t sp-theme-headings))))))
              (mapcar (lambda (face) (cons face attrs))
                      (cdr level))))
          sp-theme-heading-faces))

* Defining a theme

** Extending a Doric theme

=sp-theme--extend= adds everything the bundles do not have to a theme that =doric-themes-define-theme= has just defined, in this order, so later entries win: the mapped faces, the semantic faces, the headings, the fixed-pitch faces, the variable-pitch UI. For the semantic faces the flavor's own entries replace those of the shared table.

A face that two of these steps (or a Doric bundle) touch keeps the attributes of both: =sp-theme--set-face= merges the new attributes into the face's current record in the theme (the =theme-settings= property, because the face property is only filled when the theme is enabled) instead of replacing them, and joins =:inherit= lists. That is why the fixed-pitch step does not lose the colour of =org-code=. Emacs keeps every call as a separate record in the theme and enables the oldest one, so the older records of the face are dropped (=sp-theme--drop-old-settings=); without that a second call would silently do nothing.

#+begin_src emacs-lisp -i
;;;; Defining a theme
(defun sp-theme--plist (attrs)
  "Return ATTRS as a plain plist, whether it is one or a list holding one."
  (if (and (= (length attrs) 1) (listp (car attrs))) (car attrs) attrs))

(defun sp-theme--merge-attrs (old new)
  "Return the plist OLD with the attributes of the plist NEW added.
`:inherit' values are joined, any other attribute of NEW replaces the old one."
  (let ((result (copy-sequence (sp-theme--plist old))))
    (while new
      (let ((attr (pop new))
            (value (pop new)))
        (if (eq attr :inherit)
            (let ((joined (delete-dups
                           (append (ensure-list (plist-get result :inherit))
                                   (ensure-list value)))))
              (setq result (plist-put result :inherit
                                      (if (cdr joined) joined (car joined)))))
          (setq result (plist-put result attr value)))))
    result))

(defun sp-theme--drop-old-settings (theme face)
  "Keep only the newest setting of FACE in THEME.
Emacs records every `custom-theme-set-faces' call of a theme, and when the
theme is enabled the oldest record of a face wins, so a second call would
have no effect."
  (let* ((same (lambda (setting)
                 (and (eq (car setting) 'theme-face) (eq (cadr setting) face))))
         (settings (get theme 'theme-settings))
         (newest (seq-find same settings)))
    (put theme 'theme-settings (cons newest (seq-remove same settings)))))

(defun sp-theme--set-face (theme face attrs)
  "Add ATTRS to FACE in THEME, keeping what THEME already sets for it."
  (let* ((old (nth 3 (seq-find (lambda (setting)
                                 (and (eq (car setting) 'theme-face)
                                      (eq (cadr setting) face)))
                               (get theme 'theme-settings))))
         (clauses (or old '((t)))))
    (custom-theme-set-faces
     theme
     (list face (mapcar (lambda (clause)
                          (cons (car clause)
                                (sp-theme--merge-attrs (cdr clause) attrs)))
                        clauses)))
    (sp-theme--drop-old-settings theme face)))

(defun sp-theme--merge (shared own)
  "Return SHARED with the entries of OWN replacing those of the same name."
  (append (seq-remove (lambda (e) (assq (car e) own)) shared) own))

(defun sp-theme--extend (theme flavor)
  "Add the mapped, semantic and ported faces to THEME of FLAVOR."
  (put theme 'sp-theme-flavor flavor)
  (let ((own-semantic (plist-get (sp-theme--flavor flavor) :semantic)))
    (dolist (entry (append sp-theme-mapped-faces
                           (sp-theme--merge sp-theme-semantic own-semantic)))
      (sp-theme--set-face theme (car entry) (sp-theme--face-attributes entry flavor))))
  (dolist (entry (sp-theme--heading-faces))
    (sp-theme--set-face theme (car entry) (cdr entry)))
  (when sp-theme-mixed-fonts
    (dolist (face sp-theme-fixed-pitch-faces)
      (sp-theme--set-face theme face '(:inherit fixed-pitch))))
  (when sp-theme-variable-pitch-ui
    (dolist (face sp-theme-ui-faces)
      (sp-theme--set-face theme face '(:inherit variable-pitch)))))
#+end_src

** The macro

=sp-theme-define= is all a theme file contains. It computes the palette of the flavor into =NAME-palette=, which is where =doric-themes-define-theme= (a macro that reads the palette when it expands) and =doric-themes-with-colors= look for it, lets Doric define the theme from its bundles, and then adds the rest with =sp-theme--extend=. The flavor is also the background mode of the theme, so it is =dark= or =light=.

The palette is computed twice on purpose: once while the macro expands, so Doric's macro can read it, and once when the theme file is loaded, so the variable holds the current colours after =sp-theme-set-color=.

#+begin_src emacs-lisp -i
(defmacro sp-theme-define (name flavor &optional description)
  "Define the theme NAME from FLAVOR, `dark' or `light'.
DESCRIPTION is the one-line description of the theme."
  (declare (indent 0))
  (let ((palette (intern (format "%s-palette" name))))
    (set palette (sp-theme-palette flavor))
    `(progn
       (defvar ,palette nil)
       (setq ,palette ',(sp-theme-palette flavor))
       (doric-themes-define-theme ,name ,flavor ,description)
       (sp-theme--extend ',name ',flavor))))
#+end_src
