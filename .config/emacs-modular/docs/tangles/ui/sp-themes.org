Literate source for =libraries/modules/ui/sp-themes.el=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

Sets up where the themes are, how they are grouped and how they are loaded. It:

- puts the vendored theme engines on =load-path= and the theme folders of =libraries/themes/= on =custom-theme-load-path= (nothing is installed by Elpaca any more, only =easy-theme-preview=),
- groups the themes in use in four families (hard light, faded light, faded dark, hard dark) and lists the rest under =library=,
- makes =sp-load-theme= the only way to load a theme: no confirmation, and the old theme is only disabled after the new one has loaded,
- sets the few options of the theme packages that do something, and optional palette overrides,
- maps the system light and dark appearance to a theme (used by =sp-macos= and the toggle) and defines a hook that runs after any =load-theme=.
- The design and the reasons are in [[file:../../architecture/theme-system-design.org][theme-system-design.org]]; the faces a palette-only system would leave out are in [[file:../../architecture/modus-faces-outside-global-system.org][modus-faces-outside-global-system.org]].
- Loaded in the UI section of =init.el=.
- =sp-load-theme= is bound to =t= and =sp-load-theme-family= to =T= in the toggle prefix map in =sp-keys= (under =sp-prefix= followed by =t=).
- Automatic switching to match the macOS system appearance lives in =sp-macos=, which calls =sp-theme-load-appearance=.
- The menubar helpers call an external =dark-mode= command-line tool.

The commentary at the top of the module says:

#+begin_quote
Every theme is vendored in =libraries/themes/= and every theme is loaded with =sp-load-theme=. Themes are grouped in four families, after the Lambda themes: hard light, faded light, faded dark and hard dark.
#+end_quote

* Folders

** Never ask whether a theme is safe

=custom-safe-themes= is set to =t= here, in code, so loading a theme never shows the confirmation prompt. Customize is never loaded (=custom-file= in =early-init.el= points to a file that no module reads), so the setting must not be left to the "Save for future sessions" answer of that prompt, which would write the theme's hash into =custom.el=. The advice further down makes the same promise for any caller of =load-theme=, in case something resets the variable.

#+begin_src emacs-lisp -i
;;;; No-confirm themes
;; Hard-coded on purpose: custom.el is never loaded (see early-init.el).
(setq custom-safe-themes t)
#+end_src

** The themes folder

=sp-custom-themes-dir= is =libraries/themes/=. It is also =custom-theme-directory=, so a theme saved there is found without any other setting. The folder holds:

- =lib/=: the theme engines (=modus-themes.el=, =ef-themes.el=, =doric-themes.el=, =lambda-themes.el=). Ef needs Modus, and every Ef theme file does =(require 'ef-themes)=, so this folder goes on =load-path=.
- =active/=: the theme files in use.
- =sp/=: themes written for this configuration.
- =library/=: every other theme of the packages, one folder per package, for trying palettes out.

#+begin_src emacs-lisp -i
;;;; Configuring the custom theme folder
(defcustom sp-custom-themes-dir (concat sp-library-dir "themes/")
  "The folder with the vendored themes, see its README.org."
  :group 'spcustom
  :type 'directory)

(setq-default custom-theme-directory sp-custom-themes-dir)
#+end_src

** Load paths

The engines go on =load-path=. The theme folders go at the front of =custom-theme-load-path=, so the vendored =modus-operandi= (and the other Modus themes in =library/=) win over the older copies in Emacs's own =etc/themes=.

#+begin_src emacs-lisp -i
;;;; Paths
(defun sp-themes--subdirs (dir)
  "Return the subfolders of DIR, or nil if DIR does not exist."
  (when (file-directory-p dir)
    (seq-filter #'file-directory-p
                (directory-files dir t directory-files-no-dot-files-regexp))))

(defun sp-themes-library-dirs ()
  "Return the package folders of the theme library."
  (sp-themes--subdirs (expand-file-name "library/" sp-custom-themes-dir)))

(add-to-list 'load-path (expand-file-name "lib/" sp-custom-themes-dir))

(dolist (dir (append (sp-themes-library-dirs)
                     (list (expand-file-name "sp/" sp-custom-themes-dir)
                           (expand-file-name "active/" sp-custom-themes-dir))))
  (add-to-list 'custom-theme-load-path dir))
#+end_src

* Families

** The four families

=sp-theme-families= lists the themes in use, grouped the way the Lambda themes are. The first theme of a family is the one =sp-load-theme-family= loads. Move a theme between families, or add one from =library/= (and copy its file to =active/=), by editing this list.

- =hard-light=: full contrast on a white background, for a bright room or daylight.
- =faded-light=: softer contrast and a warm paper background, the everyday light theme.
- =faded-dark=: dark grey or brown, for the evening.
- =hard-dark=: near-black, for a dark room.

Contrast ratios between the main foreground and background: =lambda-light= 19.3, =lambda-light-faded= 13.5, =ef-day= 8.7, =ef-melissa-light= 9.0, =lambda-dark-faded= 12.2, =doric-fire= 10.5, =ef-dream= 11.5. The last two have almost the same near-black background, so =doric-fire= could also sit in =hard-dark=.

#+begin_src emacs-lisp -i
;;;; Theme families
(defcustom sp-theme-families
  '((hard-light  lambda-light)
    (faded-light lambda-light-faded ef-day ef-melissa-light)
    (faded-dark  lambda-dark-faded doric-fire)
    (hard-dark   ef-dream))
  "The themes in use, in families: a list of (FAMILY THEME...).
The first THEME of a family is the one `sp-load-theme-family' loads."
  :group 'spcustom
  :type '(alist :key-type symbol :value-type (repeat symbol)))
#+end_src

** Which themes there are

=sp-themes-library= reads the file names in =library/=, one entry per =NAME-theme.el=, so a theme copied there shows up without any registration. The ones in a family are listed first by =sp-load-theme=, the others under =library=.

#+begin_src emacs-lisp -i
(defun sp-themes-library ()
  "Return an alist of (THEME . PACKAGE) for every theme in the library."
  (let (themes)
    (dolist (dir (sp-themes-library-dirs))
      (dolist (file (directory-files dir nil "-theme\\.el\\'"))
        (push (cons (intern (string-remove-suffix "-theme.el" file))
                    (file-name-nondirectory dir))
              themes)))
    (sort themes (lambda (a b) (string< (car a) (car b))))))

(defun sp-theme-family (theme)
  "Return the family of THEME, or nil if it is not in one."
  (car (seq-find (lambda (family) (memq theme (cdr family)))
                 sp-theme-families)))
#+end_src

** Light or dark

=sp-theme-dark-p= looks at the background of the default face, so it is right for any theme, not only the ones that set =frame-background-mode=. The dashboard uses it to choose the light or dark logo.

#+begin_src emacs-lisp -i
(defun sp-theme-dark-p ()
  "Return non-nil if the default background is dark."
  (when-let* ((bg (face-background 'default nil t))
              (rgb (ignore-errors (color-values bg))))
    (< (apply #'+ rgb) (* 3 32768))))
#+end_src

* Loading

** No confirmation, whoever calls

This advice makes every =load-theme= call skip the confirmation, including =M-x load-theme= and the commands of packages such as =easy-theme-preview=.

#+begin_src emacs-lisp -i
;;;; Never ask for confirmation
(define-advice load-theme (:filter-args (args) sp-no-confirm)
  "Always pass NO-CONFIRM, so a theme is never refused or asked about."
  (list (nth 0 args) t (nth 2 args)))
#+end_src

** Options of the packages

Only options that do something remain. The Ef themes are built on the Modus engine, so they read the =modus-themes-*= options; =modus-themes-prompts=, =-completions=, =-org-blocks= and =-disable-other-themes= are gone (obsolete since Modus 5.3.0, never defined, or read only by commands this configuration does not use). The Lambda options are plain =setq= forms: =setopt= would run their setters, which reload the active theme.

#+begin_src emacs-lisp -i
;;;; Options of the theme packages
;; Modus engine (also used by the Ef themes)
(setq modus-themes-italic-constructs t
      modus-themes-bold-constructs nil
      modus-themes-mixed-fonts t
      modus-themes-variable-pitch-ui nil)

;; Lambda themes
(setq lambda-themes-set-italic-comments t
      lambda-themes-set-italic-keywords t
      lambda-themes-set-variable-pitch t)
#+end_src

** Palette overrides

=sp-theme-palette-overrides= is an alist of (THEME . OVERRIDES), where OVERRIDES is a list like =((cursor "#ff0000") (bg-main "#1a1a1a"))=. It is applied to the Ef and Modus themes, which already have this mechanism (=THEME-palette-overrides=), just before the theme loads. The Doric and Lambda themes have no such mechanism, so an entry for them is ignored with a message.

#+begin_src emacs-lisp -i
;;;; Palette overrides
(defcustom sp-theme-palette-overrides nil
  "Palette overrides per theme, an alist of (THEME . OVERRIDES).
OVERRIDES is a list of (NAME COLOR) as in `ef-day-palette-overrides'.
Only the Ef and Modus themes support them."
  :group 'spcustom
  :type '(alist :key-type symbol
                :value-type (repeat (list symbol (choice symbol string)))))

(defun sp-theme--apply-overrides (theme)
  "Set the palette overrides of THEME, if it has any."
  (when-let* ((overrides (alist-get theme sp-theme-palette-overrides)))
    (if (string-match-p "\\`\\(ef\\|modus\\)-" (symbol-name theme))
        (set (intern (format "%s-palette-overrides" theme)) overrides)
      (message "sp-themes: %s has no palette overrides, ignoring them" theme))))
#+end_src

** The command

=sp-load-theme= is the only way a theme is loaded.

- It asks for the theme first. The old command disabled every theme before asking, so quitting the prompt, or a theme that failed to load, left the plain white default theme on screen.
- It never disables a theme before the new one has loaded. After a successful load, =sp-theme-disable-others= decides what happens to the previous themes: =after-load= (the default) disables them, so faces of the old theme do not mix with the new one, and nil leaves them enabled.
- The old fallback mode line and the end of =window-divider-mode= that =sp-disable-all-themes= forced are gone with it.
- Everything else (the family lookup, the overrides, the hook) happens here, so the macOS appearance code and the toggle only call this function.

#+begin_src emacs-lisp -i
;;;; The one way to load a theme
(defcustom sp-theme-disable-others 'after-load
  "What `sp-load-theme' does to the themes that were enabled.
`after-load' disables them once the new theme has loaded.  Nil leaves
them enabled, so their faces stay under the new theme."
  :group 'spcustom
  :type '(choice (const :tag "Disable after the new theme loads" after-load)
                 (const :tag "Leave enabled" nil)))

(defvar sp-theme-history nil
  "Minibuffer history of `sp-load-theme'.")

(defun sp-theme--candidates ()
  "Return an alist of (NAME . GROUP) for the themes `sp-load-theme' offers."
  (let (cands)
    (dolist (family sp-theme-families)
      (dolist (theme (cdr family))
        (push (cons (symbol-name theme) (symbol-name (car family))) cands)))
    (dolist (entry (sp-themes-library))
      (unless (assoc (symbol-name (car entry)) cands)
        (push (cons (symbol-name (car entry))
                    (format "library: %s" (cdr entry)))
              cands)))
    (nreverse cands)))

(defun sp-theme--read (prompt)
  "Read a theme name with PROMPT, grouped by family, and return the symbol."
  (let* ((cands (sp-theme--candidates))
         (table (lambda (string pred action)
                  (if (eq action 'metadata)
                      `(metadata
                        (display-sort-function . identity)
                        (cycle-sort-function . identity)
                        (group-function
                         . ,(lambda (cand transform)
                              (if transform cand (cdr (assoc cand cands))))))
                    (complete-with-action action cands string pred)))))
    (intern (completing-read prompt table nil t nil 'sp-theme-history
                             (when custom-enabled-themes
                               (symbol-name (car custom-enabled-themes)))))))

(defun sp-load-theme (theme)
  "Load THEME, the one way themes are loaded in this configuration.
Interactively, choose among the families first and the library after."
  (interactive (list (sp-theme--read "Load theme: ")))
  (let ((previous custom-enabled-themes))
    (sp-theme--apply-overrides theme)
    (load-theme theme t)
    (when (eq sp-theme-disable-others 'after-load)
      (dolist (old (remq theme previous))
        (disable-theme old)))
    theme))

(defun sp-load-theme-family (family)
  "Load the first theme of FAMILY, see `sp-theme-families'."
  (interactive
   (list (intern (completing-read "Theme family: "
                                  (mapcar (lambda (f) (symbol-name (car f)))
                                          sp-theme-families)
                                  nil t))))
  (sp-load-theme (cadr (assq family sp-theme-families))))
#+end_src

** Light and dark appearance

=sp-theme-appearance-themes= says which theme goes with the system appearance. =sp-theme-load-appearance= is what =sp-macos= calls when macOS switches, and what the toggle command uses. It does nothing when the target is already the current theme, which keeps the macOS hook from reloading a theme on every notification.

#+begin_src emacs-lisp -i
;;;; Light and dark
(defcustom sp-theme-appearance-themes
  '((light . lambda-light-faded)
    (dark  . ef-dream))
  "The theme for the system appearance, an alist of (APPEARANCE . THEME)."
  :group 'spcustom
  :type '(alist :key-type (choice (const light) (const dark))
                :value-type symbol))

(defun sp-theme-load-appearance (appearance)
  "Load the theme for APPEARANCE, `light' or `dark', unless it is current."
  (let ((target (alist-get appearance sp-theme-appearance-themes)))
    (unless (or (null target) (eq target (car custom-enabled-themes)))
      (sp-load-theme target))))

(defun toggle-dark-light-theme ()
  "Switch between the light and the dark theme of `sp-theme-appearance-themes'."
  (interactive)
  (sp-theme-load-appearance (if (sp-theme-dark-p) 'light 'dark)))
#+end_src

** After-load-theme hook

Defines =sp-after-load-theme-hook= and advises =load-theme= to run it after every theme load, giving other modules one place to reapply face tweaks after a theme change. =kind-icon= is the one user: its icon cache is flushed so completion icons pick up the new colours (this used to happen only for Lambda themes).

#+begin_src emacs-lisp -i
;;;; After Load Theme Hook
(defvar sp-after-load-theme-hook nil
  "Hook run after a color theme is loaded using `load-theme'.")
(define-advice load-theme (:after (&rest _) sp-run-after-load-theme-hook)
  "Run `sp-after-load-theme-hook'."
  (run-hooks 'sp-after-load-theme-hook))

(with-eval-after-load 'kind-icon
  (add-hook 'sp-after-load-theme-hook #'kind-icon-reset-cache))
#+end_src

** Toggling the menubar

(defun sp-osx-toggle-menubar-theme ()
