Literate source for =libraries/modules/ui/sp-themes.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

Sets up how colour themes are found, loaded and switched. It points =custom-theme-directory= at =libraries/themes/= and adds every subfolder there to the theme load path, provides a clean theme-switching command that disables all active themes first, and installs several theme families: Modus, Ef, Doric and Lambda themes, plus =easy-theme-preview= for trying them out. It also defines a light/dark toggle and a hook that runs after any =load-theme=.

Much of it comes from Lambda-Emacs. It is loaded in the UI section of =init.el=. The command =sp-load-theme= is bound to =t= in the toggle prefix map in =sp-keys= (under =sp-prefix= followed by =t=). Automatic switching to match the macOS system appearance lives in =sp-macos=, not here. The menubar helpers call an external =dark-mode= command-line tool.

* Theme loading infrastructure

** Trust all themes

Setting =custom-safe-themes= to =t= treats every theme as safe, so loading one never asks for confirmation. The comment questions whether this needs to come first; it does need to be set before any =load-theme= call that would otherwise prompt.

** Creating and registering the directory

** Adding theme subfolders to the load path

Walks the themes directory and adds each subdirectory to =custom-theme-load-path=, so themes kept in their own folders (for example cloned theme repositories) can be loaded by name.

#+begin_src emacs-lisp -i
;;;;; find all themes recursively in custom-theme-folder
(let ((basedir custom-theme-directory))
  (dolist (f (directory-files basedir))
    (if (and (not (or (equal f ".") (equal f "..")))
             (file-directory-p (concat basedir f)))
        (add-to-list 'custom-theme-load-path (concat basedir f)))))
#+end_src

** Disabling all themes

=sp-disable-all-themes= disables every enabled theme, which avoids the colour mixing that happens when =load-theme= stacks a new theme on top of old ones. It also turns off =window-divider-mode=, clears the header line, and installs a plain fallback mode line showing buffer name, major mode, a red =(**)= marker for unsaved file buffers or =(RO)= for read-only ones, and line and column. Resetting the mode line is a holdover from Lambda-Emacs; presumably the theme or mode-line package being loaded next replaces it again. The comment at the top shows the author is unsure why this step is needed.

#+begin_src emacs-lisp -i
;; why is this necessary in order to do sp-load-theme?
(defun sp-disable-all-themes ()
  "Disable all active themes & reset mode-line."
  (interactive)
  (progn
    (dolist (i custom-enabled-themes)
      (disable-theme i))
    ;; disable window-divider mode
    (window-divider-mode -1)
    ;; revert to mode line
    (setq-default header-line-format nil)
    (setq-default mode-line-format
                  '((:eval
                     (list
                      "%b "
                      "%m "
                      (cond ((and buffer-file-name (buffer-modified-p))
                             (propertize "(**)" 'face `(:foreground "#f08290")))
                            (buffer-read-only "(RO)" ))
                      " %l:%c %0"
                      " "
                      ))))
    (force-mode-line-update)))
#+end_src

** Theme loading wrapper

=sp-load-theme= disables all themes and then calls =load-theme= interactively, so you pick a theme from the usual prompt and get a clean switch. This is the command on the theme toggle key.

#+begin_src emacs-lisp -i
;;;; Load Theme Wrapper
(defun sp-load-theme ()
  (interactive)
  (progn
    (sp-disable-all-themes)
    (call-interactively 'load-theme)))
#+end_src

#+end_src

** Modus appearance options

Italic but not bold constructs, mixed fonts, no variable-pitch UI elements, and =modus-themes-disable-other-themes= so loading a Modus theme turns off others. Minibuffer prompts are italic and bold. In completion lists, matching characters are extra bold and the selected candidate is semibold italic, with the styling applied to its text too.

#+begin_src emacs-lisp -i
;; In all of the following, WEIGHT is a symbol such as `semibold',
;; `light', `bold', or anything mentioned in `modus-themes-weights'.
(setq modus-themes-italic-constructs t
      modus-themes-bold-constructs nil
      modus-themes-mixed-fonts t
      modus-themes-variable-pitch-ui nil
      modus-themes-disable-other-themes t

      ;; Options for `modus-themes-prompts' are either nil (the
      ;; default), or a list of properties that may include any of those
      ;; symbols: `italic', `WEIGHT'
      modus-themes-prompts '(italic bold)

      ;; The `modus-themes-completions' is an alist that reads two
      ;; keys: `matches', `selection'.  Each accepts a nil value (or
      ;; empty list) or a list of properties that can include any of
      ;; the following (for WEIGHT read further below):
      ;;
      ;; `matches'   :: `underline', `italic', `WEIGHT'
      ;; `selection' :: `underline', `italic', `WEIGHT'
      modus-themes-completions
      '((matches . (extrabold))
        (selection . (semibold italic text-also))))
#+end_src

** Refreshing kind-icon after a theme change

Once =kind-icon= is loaded, flushes its icon cache whenever a Lambda theme loads, so completion icons pick up the new colours. Note this is tied to =lambda-themes-after-load-theme-hook= only, so switching to a Modus or Ef theme does not reset the cache.

#+begin_src emacs-lisp -i
;; kind-icon needs to have its cache flushed after theme change
(with-eval-after-load 'kind-icon
  (add-hook 'lambda-themes-after-load-theme-hook #'kind-icon-reset-cache))
#+end_src

* Toggles and hooks

** Light/dark toggle

=toggle-dark-light-theme= flips between two Ef themes: if =ef-day= is active it loads =ef-dream=, otherwise it loads =ef-day=, disabling all themes first. The docstring still talks about Lambda variants and defaulting to =ef-dream=, so it no longer matches the code. Its keybinding in =sp-keys= is commented out in favour of =sp-load-theme=.

#+begin_src emacs-lisp -i
;;;;; Theme toggle
(defun toggle-dark-light-theme ()
  "Flip the active lambda variant between light and dark.
If neither lambda variant is currently active (the user loaded some
other theme), default to `ef-dream'. The macOS system-appearance
hook is left untouched; the next macOS Light/Dark change will resync."
  (interactive)
  (let* ((current (car custom-enabled-themes))
         (target (if (eq current 'ef-day) 'ef-dream 'ef-day)))
    (sp-disable-all-themes)
    (load-theme target t)))
#+end_src

** After-load-theme hook

Defines =sp-after-load-theme-hook= and advises =load-theme= to run it after every theme load, giving other modules one place to reapply face tweaks after a theme change. Nothing else in the config currently adds to this hook.

#+begin_src emacs-lisp -i
;;;;; After Load Theme Hook
(defvar sp-after-load-theme-hook nil
  "Hook run after a color theme is loaded using `load-theme'.")
(define-advice load-theme (:after (&rest _) sp-run-after-load-theme-hook)
  "Run `sp-after-load-theme-hook'."
  (run-hooks 'sp-after-load-theme-hook))
#+end_src
