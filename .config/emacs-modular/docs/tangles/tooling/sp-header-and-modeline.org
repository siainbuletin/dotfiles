Literate source for =libraries/modules/tooling/sp-header-and-modeline.el=. This module used to be called =sp-lambda-line=.

- Every line of the module lives in the =emacs-lisp= blocks below, in order.
- The =:tangle= path in the =#+PROPERTY= line at the top says where they are written.
- To tangle, see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README.

This module installs and configures =lambda-line=, the minimal status line from the Lambda Emacs project, fetched from Codeberg, and gives it a header line as well.

- Loaded in both the default and minimal module lists.
- An alternative, =sp-prot-modeline=, is a native mode line adapted from Prot's. Load only one of the two, because both set =mode-line-format=.
- =sp-choose-modeline= can also pick between =lambda-line= and =doom-modeline=. It is commented out in those lists.

What it does:

- *Layout.* =sp-header-and-modeline-layout= is =both= (lambda-line in the mode line at the bottom of each window, plus a header line), =modeline= (no header) or =header= (everything in the header line, which lambda-line calls =top=, and the mode line shrinks to a thin divider).
- *Header line.* The path of the file (the directory for a buffer with no file) on the left, the project name on the right. It is drawn with =lambda-line-compose=, so it follows the same faces as the mode line. =keycast-header-line-mode=, which =sp-frame= turns on, is turned off and on again so that its keys are shown next to the header.
- *Tag emoji.* lambda-line never displays =global-mode-string=, where =sp-tag-emoji= puts its segment. An advice on =lambda-line-compose= appends =sp-tag-emoji-modeline-string= to the middle (primary) part of every mode line, whatever the major mode. The emoji keep their tooltip, but lambda-line's face for that part replaces their faces.
- *Theme colours.* =sp-header-and-modeline-theme-faces= sets the lambda-line faces from the faces of the theme in use: the =mode-line= and =mode-line-inactive= faces for the selected and the other windows, =mode-line-buffer-id= for the name and =success=, =warning= and =error= for the status symbol. It runs when the module loads and after each theme loads (=sp-after-load-theme-hook=).

Untested in a running Emacs: the container that wrote it has no Emacs. Things to check are the header line next to keycast, the tag emoji in an Org buffer and the colours after =sp-load-theme=.

The clock icon option relies on the ClockFace font being installed, and the status symbols use non-ASCII glyphs that need a font able to display them.

** Header line

The header is composed with =lambda-line-compose=, so it has the same prefix symbol and faces as the mode line. The variable =sp-header-and-modeline--composing-header= tells the tag emoji advice (below) not to add the emoji a second time. The project name is looked up only for local buffers, because asking a remote one for its project can be slow.

#+begin_src emacs-lisp -i
(defvar sp-header-and-modeline--composing-header nil
  "Non-nil while the header line is being composed.")

(defun sp-header-and-modeline--path ()
  "Return the path shown at the left of the header line."
  (abbreviate-file-name (or buffer-file-name
                            (and (derived-mode-p 'dired-mode) default-directory)
                            (buffer-name))))

(defun sp-header-and-modeline--project ()
  "Return the name of the current project, or an empty string."
  (or (and (not (file-remote-p default-directory))
           (when-let* ((project (project-current)))
             (project-name project)))
      ""))

(defun sp-header-and-modeline-header ()
  "Return the header line string: the path and the project name."
  (let ((sp-header-and-modeline--composing-header t))
    (lambda-line-compose nil
                         (sp-header-and-modeline--path)
                         ""
                         ""
                         (sp-header-and-modeline--project))))

(defconst sp-header-and-modeline-header-format
  '(:eval (sp-header-and-modeline-header))
  "The `header-line-format' used by the `both' layout.")
(put 'sp-header-and-modeline-header-format 'risky-local-variable t)
#+end_src

** Tag emoji

The advice adds the tag emoji of the heading or file at point to the primary part (the middle one, next to the major mode) of every mode line lambda-line composes. All the mode formats go through =lambda-line-compose=, so no format needs to be rewritten.

#+begin_src emacs-lisp -i
(defun sp-header-and-modeline--add-tag-emoji (args)
  "Append the tag emoji to the primary part in ARGS of `lambda-line-compose'."
  (let ((tags (and (not sp-header-and-modeline--composing-header)
                   (fboundp 'sp-tag-emoji-modeline-string)
                   (ignore-errors (sp-tag-emoji-modeline-string)))))
    (if (and (stringp tags) (not (string-blank-p tags)))
        (let ((args (copy-sequence args)))
          (setf (nth 2 args) (concat (or (nth 2 args) "") tags))
          args)
      args)))
#+end_src

** Theme colours

lambda-line defines its faces with fixed colours ("green", "yellow", "red", "grey75"...). This function replaces them with colours read from the theme in use. The selected window uses =mode-line=, the others use =mode-line-inactive=, and the status symbol takes its colour from =success= (read-write), =warning= (read-only) and =error= (modified).

#+begin_src emacs-lisp -i
(defun sp-header-and-modeline--foreground (face fallback)
  "Return the foreground of FACE in the current theme, or FALLBACK."
  (let ((color (face-foreground face nil t)))
    (if (and (stringp color) (not (string-prefix-p "unspecified" color)))
        color
      fallback)))

(defun sp-header-and-modeline-theme-faces (&rest _)
  "Set the lambda-line faces from the faces of the current theme."
  (when (facep 'lambda-line-active)
    (set-face-attribute 'lambda-line nil :inherit 'mode-line)
    (set-face-attribute 'lambda-line-inactive nil
                        :inherit 'mode-line-inactive
                        :weight 'unspecified :box 'unspecified
                        :foreground 'unspecified :background 'unspecified)
    (set-face-attribute 'lambda-line-active-name nil
                        :inherit '(mode-line-buffer-id lambda-line))
    (set-face-attribute 'lambda-line-active-secondary nil
                        :inherit '(shadow lambda-line))
    (let ((muted (sp-header-and-modeline--foreground 'shadow "gray50")))
      (dolist (status '("RO" "RW" "MD"))
        (set-face-attribute (intern (format "lambda-line-inactive-status-%s" status))
                            nil :inherit 'lambda-line-inactive :foreground muted)))
    (set-face-attribute 'lambda-line-active-status-RW nil
                        :foreground (sp-header-and-modeline--foreground 'success "green"))
    (set-face-attribute 'lambda-line-active-status-RO nil
                        :foreground (sp-header-and-modeline--foreground 'warning "yellow"))
    (set-face-attribute 'lambda-line-active-status-MD nil
                        :foreground (sp-header-and-modeline--foreground 'error "red"))
    (force-mode-line-update t)))
#+end_src

** Layout

The layout is applied after =lambda-line-mode=, which clears both formats when it starts. For =header= the mode line is reduced to the divider =%_=, which is the trick lambda-line's examples use when the line is at the top. For =both= the header format is set, and keycast's header line mode is switched off and on again, so that it adds its keys to the new format instead of the one that was replaced.

#+begin_src emacs-lisp -i
(defun sp-header-and-modeline-apply-layout ()
  "Set the mode line and the header line from `sp-header-and-modeline-layout'."
  (pcase sp-header-and-modeline-layout
    ('header
     (setq-default mode-line-format (list "%_"))
     (setq mode-line-format (list "%_")))
    ('both
     (setq-default header-line-format sp-header-and-modeline-header-format)
     (when (bound-and-true-p keycast-header-line-mode)
       (keycast-header-line-mode -1)
       (keycast-header-line-mode 1))))
  (force-mode-line-update t))
#+end_src

** lambda-line

The =:custom= block sets the look of the status line:

- a clock icon drawn with the ClockFaceRect font face,
- the line placed at the bottom of each window, or at the top for the =header= layout,
- abbreviated major mode names,
- extra horizontal spacing, a prefix symbol with padding, and no inverted colours for the status indicator,
- custom symbols for read-only, modified and unmodified buffers in graphical frames,
- vertical padding above and below the line and a small vertical offset for the symbols.

In =:config=, the tag emoji advice is added, =lambda-line-mode= is activated, and the layout and the theme colours are applied. The theme colours are applied again after every theme load.

#+begin_src emacs-lisp -i
(use-package lambda-line
    :ensure (:type git :repo "https://codeberg.org/Lambda-Emacs/lambda-line")

    :custom
    (lambda-line-icon-time t) ;; requires ClockFace font (see below)
    (lambda-line-clockface-update-fontset "ClockFaceRect") ;; set clock icon
    (lambda-line-position (if (eq sp-header-and-modeline-layout 'header) 'top 'bottom))
    (lambda-line-abbrev t) ;; abbreviate major modes
    (lambda-line-hspace "  ")  ;; add some cushion
    (lambda-line-prefix t) ;; use a prefix symbol
    (lambda-line-prefix-padding t) ;; extra space for prefix
    (lambda-line-status-invert nil)  ;; no invert colors
    (lambda-line-gui-ro-symbol  " ⨂") ;; symbols
    (lambda-line-gui-mod-symbol " ⬤")
    (lambda-line-gui-rw-symbol  " ◯")
    (lambda-line-space-top +.70)  ;; padding on top and bottom of line
    (lambda-line-space-bottom -.70)
    (lambda-line-symbol-position 0.1) ;; adjust the vertical placement of symbol

    :config
    (advice-add 'lambda-line-compose :filter-args
                #'sp-header-and-modeline--add-tag-emoji)
    (lambda-line-mode)  ;; activate lambda-line
    (sp-header-and-modeline-theme-faces)
    (sp-header-and-modeline-apply-layout)
    (add-hook 'sp-after-load-theme-hook #'sp-header-and-modeline-theme-faces))
#+end_src
