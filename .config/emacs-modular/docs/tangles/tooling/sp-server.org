The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

Starts the Emacs server so =emacsclient= can connect, and provides two commands for killing stray Emacs processes. It is part of both the default and minimal module lists in =init.el=. The kill commands shell out to =pgrep= and =pkill=, and one of them assumes the macOS application path =/Applications/Emacs.app=.

* Server

** Starting the server

The long comment explains a past bug: the server used to start only when =window-system= was non-nil, which is false for a launchd-managed =--fg-daemon= before any frame exists. That daemon never created its socket, so each =emacsclient= call with an empty =ALTERNATE_EDITOR= spawned its own extra daemon. The guard is now =window-system= or =daemonp=.

The built-in =server= package is loaded two seconds after startup. =server-client-instructions= is turned off so clients do not show the "When done with a buffer, type C-x #" message, and =server-start= runs only if no server is already running, which avoids the warning about an existing socket. A commented-out =:hook= line shows the older approach of enabling =server-mode= after init.

#+begin_src emacs-lisp -i
;; -*- lexical-binding: t -*-
;; sp-server.el --- emacs server configuration 

;;; Server
;; start server for emacsclient. The original guard was `:if
;; window-system', which is nil when emacs starts under launchd as
;; `--fg-daemon' before any GUI client connects. That meant the
;; launchd-managed daemon never called `(server-start)' and never
;; created /tmp/emacsUID/server, which forced every `emacsclient'
;; with ALTERNATE_EDITOR="" to spawn its own one-shot bg-daemon to
;; fill the socket gap -- the source of the "two daemons" pattern.
;; Run the server whenever this Emacs is GUI OR daemon-mode.
(use-package server
  :ensure nil
  :if (or window-system (daemonp))
  ;; :hook (after-init . server-mode)
  :defer 2
  :config
  ;; t/nil for instructions
  (setq server-client-instructions nil)
  ;; avoid warning screen
  (or (server-running-p)
      (server-start)))
#+end_src

* Killing Emacs processes

** Kill every Emacs

=lem-kill-all-emacsen= lists every process whose name matches "emacs" (case-insensitive, via =pgrep -i=), sends =TERM= to all of them except the current one, and then exits the current Emacs with =save-buffers-kill-emacs= so unsaved buffers get a prompt. Because the match is by name, it also catches anything else with emacs in its name, such as =emacsclient=.

#+begin_src emacs-lisp -i
;; functions for killing server-related emacsen
(defun lem-kill-all-emacsen ()
  (interactive)
  (dolist (pid (mapcar #'string-to-number
                       (split-string (shell-command-to-string "pgrep -i emacs") "\n" t)))
    (unless (= pid (emacs-pid))
      (signal-process pid 'TERM)))
  (save-buffers-kill-emacs))
#+end_src

** Kill the capture daemon

=lem-kill-emacs-capture-daemon= runs =pkill -f= against the macOS Emacs.app binary path. Judging by the name it is meant to stop a separate daemon used for quick capture, though the pattern matches any Emacs launched from that path, possibly including the current one.

#+begin_src emacs-lisp -i
(defun lem-kill-emacs-capture-daemon ()
  (interactive)
  (shell-command-to-string "pkill -f /Applications/Emacs.app/Contents/MacOS/emacs"))
#+end_src
