The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

* Basic functionality

This module keeps the issues of my code work (the yadm dotfiles first, vulpea-mcp next) in one Org file, and makes that file a vulpea-para *area* titled "Issues". Being an area is what plugs it into the rest of the system:

- vulpea-para sees it in =vulpea-para-areas=, so =M-x vulpea-para-agenda-area= can restrict the agenda to it, and the "Area > Project" category prefix in agenda lines reads =Issues > dotfiles=.
- The file uses the org-gtd keywords (=TODO NEXT PROG WAIT | DONE CNCL=, the same ones =org-gtd-keyword-mapping= names in =sp-org-taskman-extra=).
   + They are set with a =#+todo:= line in the file itself, so the issues work even though the global =org-todo-keywords= is currently overwritten at the end of =sp-org-taskman-extra= with a =TODO WAITING DOING= sequence.
- Every issue carries =ORG_GTD: Actions=, which makes it an org-gtd single action. Once an issue is =NEXT= it appears in =org-gtd-engage= (=C-c d e=) with the other next actions.
- =M-x sp-org-issues-morning= (and the first start of Emacs each day) ranks the open issues together with the open pull requests of the same repositories into one list of what to do next; see [[*Morning list]].
- Each issue records =BRANCH=, =WORKTREE=, =PR= and =THREAD= (the Claude thread link) in its drawer, and =sp-org-issues-start= gives it its own git worktree and opens Magit there.

* How the file is laid out

An area in vulpea-para is one whole file tagged =area=, with =* Notes=, =* Tasks= and =* Archive= headings. The issues file keeps that shape. Under =* Tasks= there is one heading per code base.

A code base is ongoing, so it is not a PARA project (a project has an end); it is a plain heading that holds the repository's settings as properties, inherited by every issue below it.

*Managing complexity:* An issue that grows into several steps can be tagged =:project:= on its own, and vulpea-para then treats it as a project.

=M-x sp-org-issues-create-area= writes this file with =vulpea-create=, so it gets a real =ID= and lands in the vulpea database. It goes where vulpea-para puts every new area (=vulpea-para-capture-area-file-name=, =~/notes/area/<timestamp>-issues.org=). This is what it looks like, with one captured issue in it:

The keywords mean:

| Keyword | Meaning                                         | org-gtd     |
|---------+-------------------------------------------------+-------------|
| =TODO=  | Filed, not yet decided on                       | todo        |
| =NEXT=  | The next thing to pick up                       | next action |
| =PROG=  | Being worked on in its worktree (logs the time) |             |
| =WAIT=  | Waiting on a PR review or a reply (asks a note) | wait        |
| =DONE=  | Merged or otherwise finished (logs the time)    |             |
| =CNCL=  | Dropped (asks a note)                           | canceled    |

=#+archive: ::* Archive= makes =C-c C-x C-s= move a finished issue under the file's own =* Archive= heading, where it gets an =ARCHIVE_TIME= and vulpea-para counts it as archived.

* The issues area

** Repository headings

=sp-org-issues--repo-heading= writes one repository heading. Its =CATEGORY= uses vulpea-para's own "Area > Project" format, and the git settings sit in the drawer for the issues below to inherit.

#+begin_src emacs-lisp -i
;;;; The issues area

(defun sp-org-issues--repo-heading (name plist)
  "Return the Org text of the repository heading NAME described by PLIST."
  (string-join
   (delq nil
         (list (format "** %s :%s:" name (plist-get plist :tag))
               ":PROPERTIES:"
               (format ":ID:       %s" (org-id-new))
               (format ":CATEGORY: %s"
                       (vulpea-para-category sp-org-issues-area-title name))
               (format ":GIT_DIR:  %s" (plist-get plist :git-dir))
               (format ":WORKTREE_ROOT: %s" (plist-get plist :worktree-root))
               (format ":BASE:     %s" (or (plist-get plist :base) "main"))
               (when (plist-get plist :url)
                 (format ":URL:      %s" (plist-get plist :url)))
               ":END:"))
   "\n"))
#+end_src

The body handed to =vulpea-create=: Notes, Tasks with one heading per repository, and Archive.

** Finding the area

The area is found in the vulpea database by its title, so the file can live anywhere and be renamed freely.

#+begin_src emacs-lisp -i
(defun sp-org-issues-area ()
  "Return the issues area note, or nil when there is none yet."
  (seq-find (lambda (note)
              (string= (vulpea-note-title note) sp-org-issues-area-title))
            (vulpea-para-areas)))

(defun sp-org-issues-file ()
  "Return the path of the issues file."
  (if-let* ((area (sp-org-issues-area)))
      (vulpea-note-path area)
    (user-error "No %s area yet, run M-x sp-org-issues-create-area"
                sp-org-issues-area-title)))
#+end_src

** Creating the area

=sp-org-issues-create-area= is the one-time setup. It creates the file like =vulpea-para-capture-area= does (same file-name template and =area= tag) and adds the keyword and archive lines through =vulpea-create='s =:head=. When the area already exists it just visits it. =sp-org-issues-find= opens the file.

#+begin_src emacs-lisp -i
(defun sp-org-issues-create-area ()
  "Create the issues area, or visit it when it already exists."
  (interactive)
  (if-let* ((area (sp-org-issues-area)))
      (vulpea-visit area)
    (vulpea-visit
     (vulpea-create sp-org-issues-area-title
                    vulpea-para-capture-area-file-name
                    :tags (list vulpea-para-area-tag)
                    :head (concat sp-org-issues-todo-line
                                  "\n#+archive: ::* Archive")
                    :body (sp-org-issues--area-body)))))

(defun sp-org-issues-find ()
  "Visit the issues file."
  (interactive)
  (find-file (sp-org-issues-file)))
#+end_src

* Capture

** Repository target

Finds the level-2 heading of a repository, or adds it at the end of =* Tasks= when a repository from =sp-org-issues-repos= has no heading yet.

#+begin_src emacs-lisp -i
;;;; Capture

(defun sp-org-issues--goto-repo (name)
  "Move point to the repository heading NAME, creating it when missing."
  (goto-char (point-min))
  (let ((re (format org-complex-heading-regexp-format (regexp-quote name)))
        found)
    (while (and (not found) (re-search-forward re nil t))
      (when (= (org-current-level) 2)
        (setq found t)))
    (if found
        (beginning-of-line)
      (vulpea-para--goto-tasks-end)
      (insert (sp-org-issues--repo-heading
               name (cdr (assoc name sp-org-issues-repos)))
              "\n")
      (sp-org-issues--goto-repo name))))
#+end_src

** Issue template

Org runs the template before the target, so the template asks for the repository and stores it on the capture, the same way vulpea-para's project template stores the area. The issue gets an =ID=, a =CREATED= stamp, =ORG_GTD: Actions= and empty =BRANCH=, =PR= and =THREAD= fields. =%^g= offers the file's tags (=emacs=, =vulpea= and so on).

#+begin_src emacs-lisp -i
(defun sp-org-issues-capture-template ()
  "Return the capture template of an issue, after asking for its repository."
  (org-capture-put :issue-repo
                   (completing-read "Repository: " sp-org-issues-repos
                                    nil t))
  (string-join
   (list "* TODO %^{Issue} %^g"
         ":PROPERTIES:"
         (format ":ID:       %s" (org-id-new))
         (format ":CREATED:  %s" (format-time-string "[%Y-%m-%d %H:%M]"))
         ":ORG_GTD:  Actions"
         ":BRANCH:"
         ":PR:"
         ":THREAD:"
         ":END:"
         "%?")
   "\n"))
#+end_src

** Custom commands

Adds an =i= prefix to the agenda dispatcher (=C-c o a=):

- =i i= Issue board: in progress, next, waiting, and open issues, in that order, in a buffer named =*Issues*=.
- =i b= Issues with a branch: every open issue whose =BRANCH= is set.

From the agenda, =t= changes an issue's state, =:= sets its tags, =C-c C-x p= sets a property such as =PR=, and =RET= jumps to it.

#+begin_src emacs-lisp -i
(dolist (command
         `(("i" . "Issues")
           ("ii" "Issue board"
            ((todo "PROG" ((org-agenda-overriding-header "In progress")))
             (todo "NEXT" ((org-agenda-overriding-header "Next")))
             (todo "WAIT" ((org-agenda-overriding-header "Waiting on review or a reply")))
             (todo "TODO" ((org-agenda-overriding-header "Open"))))
            ((org-agenda-files (sp-org-issues--agenda-files))
             (org-agenda-buffer-name "*Issues*")))
           ("ib" "Issues with a branch" tags-todo "BRANCH<>\"\""
            ((org-agenda-files (sp-org-issues--agenda-files))
             (org-agenda-overriding-header "Issues with a branch")))))
  (add-to-list 'org-agenda-custom-commands command t))
#+end_src

* Branches and worktrees

The user should be able to quickly act on issues that are listed in the repository here.
- This workflow should replace keeping a ~todo.org~ file in the ~docs/~ repository.

** Acting on the issue at point

Lets the commands below work both in the issues file and on an agenda line.

#+begin_src emacs-lisp -i
;;;; Branches and worktrees

(defmacro sp-org-issues--at-issue (&rest body)
  "Run BODY at the issue heading at point, in Org or in the agenda."
  (declare (indent 0))
  `(let ((marker (if (derived-mode-p 'org-agenda-mode)
                     (or (org-get-at-bol 'org-marker)
                         (user-error "No issue on this line"))
                   (point-marker))))
     (with-current-buffer (marker-buffer marker)
       (org-with-wide-buffer
        (goto-char marker)
        (org-back-to-heading t)
        ,@body))))
#+end_src

** Running git

All git calls name the repository with =--git-dir=, so they work the same for the yadm repository (whose worktree is the home folder) and for an ordinary clone. They run from the home folder, so a TRAMP buffer never sends them to another host.

#+begin_src emacs-lisp -i
(defun sp-org-issues--git (git-dir &rest args)
  "Run git on GIT-DIR with ARGS and return its output.
Signal an error with git's message when it fails."
  (let ((default-directory (expand-file-name "~/")))
    (with-temp-buffer
      (let ((status (apply #'process-file "git" nil t nil
                           (concat "--git-dir=" (expand-file-name git-dir))
                           args)))
        (unless (zerop status)
          (user-error "git %s: %s" (string-join args " ")
                      (string-trim (buffer-string))))
        (string-trim (buffer-string))))))

(defun sp-org-issues--ref-p (git-dir ref)
  "Return non-nil when REF exists in GIT-DIR."
  (ignore-errors
    (sp-org-issues--git git-dir "rev-parse" "--verify" "--quiet" ref)
    t))

(defun sp-org-issues--slug (string)
  "Return STRING as a short branch or directory name."
  (let ((slug (replace-regexp-in-string "[^a-z0-9/]+" "-" (downcase string))))
    (string-trim (truncate-string-to-width slug 40) "-" "-")))

(defun sp-org-issues--nonempty (value)
  "Return VALUE unless it is nil or blank."
  (and value (not (string-blank-p value)) value))
#+end_src

** Adding a worktree

Uses the local branch when there is one, tracks =origin/BRANCH= when only GitHub has it (a branch a Claude thread pushed, for example), and otherwise starts a new branch from the repository's =BASE=.

#+begin_src emacs-lisp -i
(defun sp-org-issues-worktree-add (git-dir dir branch base)
  "Add a worktree at DIR for BRANCH of GIT-DIR.
Use the local BRANCH when it exists, else track origin/BRANCH, else
start BRANCH from BASE."
  (cond
   ((sp-org-issues--ref-p git-dir (concat "refs/heads/" branch))
    (sp-org-issues--git git-dir "worktree" "add" dir branch))
   ((sp-org-issues--ref-p git-dir (concat "refs/remotes/origin/" branch))
    (sp-org-issues--git git-dir "worktree" "add" "--track" "-b" branch dir
                        (concat "origin/" branch)))
   (t
    (sp-org-issues--git git-dir "worktree" "add" "-b" branch dir base))))
#+end_src

** Starting an issue

=M-x sp-org-issues-start= on an issue (or its agenda line) asks for a branch name when the issue has none, offering =issue/<title>=, adds the worktree under =WORKTREE_ROOT= when it is missing, writes =BRANCH= and =WORKTREE= into the drawer, moves a =TODO= or =NEXT= issue to =PROG=, and opens =magit-status= in the worktree. Run it again later and it goes straight to Magit.

#+begin_src emacs-lisp -i
(defun sp-org-issues-start ()
  "Work on the issue at point in its own worktree, then open Magit there.

Asks for a branch when the issue has none, adds the worktree under the
repository's WORKTREE_ROOT when it is missing, records BRANCH and
WORKTREE on the issue, and moves a TODO or NEXT issue to PROG."
  (interactive)
  (let ((dir
         (sp-org-issues--at-issue
           (let* ((git-dir (or (org-entry-get nil "GIT_DIR" t)
                               (user-error "This heading is not in a repository")))
                  (root (or (org-entry-get nil "WORKTREE_ROOT" t)
                            (user-error "The repository has no WORKTREE_ROOT")))
                  (base (or (org-entry-get nil "BASE" t) "main"))
                  (branch (or (sp-org-issues--nonempty (org-entry-get nil "BRANCH"))
                              (read-string
                               "Branch: "
                               (concat "issue/"
                                       (sp-org-issues--slug
                                        (org-get-heading t t t t))))))
                  (dir (expand-file-name

             (when (member (org-get-todo-state) '("TODO" "NEXT"))
               (org-todo "PROG"))
             dir))))
    (magit-status dir)))

* Morning list

Every morning, or whenever =M-x sp-org-issues-morning= is run, the module builds one ranked list of what to do next across the issues file and the open pull requests of the same repositories, and shows it in a =*Morning*= buffer. The first time Emacs starts on a new day it shows the list by itself.

** The priority rule

Every item gets a score and the list is sorted by it, highest first. The scores are in =sp-org-issues-morning-scores=, so the order can be changed without touching code. The rule has three ideas:

1. *Things only I can unblock come first.* A pull request whose checks fail, one with a merge conflict and one with requested changes are stopped until I act. An approved pull request with green checks is a merge away, and merging clears the way for those stacked on it. A pull request that just waits for a review comes next.
2. *Then the work I am doing.* An issue in =PROG= scores above =NEXT=, which scores above =WAIT= (waiting on somebody else) and =TODO= (not yet chosen). A deadline raises an issue: +30 when it is today or past, +15 within three days. A schedule of today or past adds +10.
3. *A pull request stacked on another waits for it.* Each level of stack costs 15 points, so in #17, #18, #19 the list asks for #17 first and says that the others come after it. Only open pull requests of the same repository count as parents.

On top of the base score, a pull request that is waiting for me gains one point for each day since its last update, up to ten, so that old ones rise.

| Item                                    | Score |
|-----------------------------------------+-------|
| Checks failing                          |   100 |
| Merge conflict                          |    90 |
| Changes requested                       |    85 |
| Issue whose pull request is gone        |    75 |
| Approved, checks green: ready to merge  |    80 |
| Waiting for my review                   |    70 |
| Issue in PROG                           |    60 |
| Issue in NEXT                           |    50 |
| Checks still running                    |    30 |
| Issue in WAIT                           |    20 |
| Draft pull request                      |    10 |
| Issue in TODO                           |    10 |

An issue that links an open pull request (the =PR= property) is shown once, with the better of the two scores and the reason of the pull request. When the pull request is no longer open but the issue still is, the issue is flagged "no longer open: close the issue", since that is normally a merge that was not recorded.

** Reading GitHub's answer

=gh pr list --json= answers with a list of objects. =statusCheckRollup= mixes two shapes: check runs (=status= and =conclusion=) and commit statuses (=state=). A failure anywhere makes the pull request =failure=, even while other checks still run; otherwise anything unfinished makes it =pending=, and an empty list means no checks, which is treated like green.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--ci (rollup)
  "Return `failure', `pending' or `success' for the check ROLLUP.
Return nil when ROLLUP is empty."
  (let (failed pending)
    (dolist (check rollup)
      (let ((conclusion (alist-get 'conclusion check))
            (status (alist-get 'status check))
            (state (alist-get 'state check)))
        (cond
         ((member conclusion '("FAILURE" "TIMED_OUT" "CANCELLED" "ACTION_REQUIRED"
                               "STARTUP_FAILURE"))
          (setq failed t))
         ((member state '("FAILURE" "ERROR")) (setq failed t))
         ((member state '("PENDING" "EXPECTED")) (setq pending t))
         ((and status (not (equal status "COMPLETED"))) (setq pending t)))))
    (cond (failed 'failure) (pending 'pending) (rollup 'success))))

(defun sp-org-issues-morning--parse-prs (json label)
  "Return the pull requests in the JSON of `gh pr list'.
Tag each with the repository LABEL."
  (mapcar (lambda (pr)
            (list :repo label
                  :number (alist-get 'number pr)
                  :title (alist-get 'title pr)
                  :url (alist-get 'url pr)
                  :draft (and (alist-get 'isDraft pr) t)
                  :decision (or (alist-get 'reviewDecision pr) "")
                  :mergeable (alist-get 'mergeable pr)
                  :base (alist-get 'baseRefName pr)
                  :head (alist-get 'headRefName pr)
                  :updated (alist-get 'updatedAt pr)
                  :ci (sp-org-issues-morning--ci (alist-get 'statusCheckRollup pr))))
          (json-parse-string json :object-type 'alist :array-type 'list
                             :null-object nil :false-object nil)))

** Categories, stacks and scores of pull requests

A pull request is in exactly one category, the first that fits in this order: draft, failing checks, conflict, requested changes, approved (ready when its checks are not still running), checks still running, and otherwise waiting for review. A stack is read from the branch names: a pull request is stacked on another open pull request of the same repository when its base is that one's head. =sp-org-issues-morning--stack-depth= returns the number of levels and the number of the parent, and ends on a cycle.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--pr-category (pr)
  "Return the category of the pull request PR."
  (let ((ci (plist-get pr :ci))
        (decision (plist-get pr :decision)))
    (cond
     ((plist-get pr :draft) 'draft)
     ((eq ci 'failure) 'ci-failed)
     ((equal (plist-get pr :mergeable) "CONFLICTING") 'conflict)
     ((equal decision "CHANGES_REQUESTED") 'changes-requested)
     ((and (equal decision "APPROVED") (not (eq ci 'pending))) 'ready)
     ((eq ci 'pending) 'ci-pending)
     (t 'review))))

(defun sp-org-issues-morning--stack-depth (pr prs)
  "Return (DEPTH . PARENT) of PR among PRS.
DEPTH is how many open pull requests PR is stacked on and PARENT is the
number of the one directly below it, or nil."
  (let ((depth 0) (parent nil) (current pr) (limit (length prs)))
    (while (and (< depth limit)
                (when-let* ((below (seq-find
                                    (lambda (other)
                                      (and (equal (plist-get other :repo)
                                                  (plist-get current :repo))
                                           (equal (plist-get other :head)
                                                  (plist-get current :base))))
                                    prs)))
                  (unless parent (setq parent (plist-get below :number)))
                  (setq current below)
                  (cl-incf depth))))
    (cons depth parent)))

(defconst sp-org-issues-morning--reasons
  '((ci-failed . "checks are failing")
    (conflict . "merge conflict")
    (changes-requested . "changes were requested")
    (ready . "approved, ready to merge")
    (review . "waiting for your review")
    (ci-pending . "checks are still running")
    (draft . "draft"))
  "Why a pull request of each category is in the list.")

(defun sp-org-issues-morning--age-days (updated now)
  "Return the whole days from the ISO time UPDATED to NOW."
  (if updated
      (max 0 (floor (/ (float-time (time-subtract now (date-to-time updated)))
                       86400)))
    0))

(defun sp-org-issues-morning--pr-score (pr prs now)
  "Return (SCORE . REASON) of the pull request PR among PRS at NOW."
  (let* ((category (sp-org-issues-morning--pr-category pr))
         (stack (sp-org-issues-morning--stack-depth pr prs))
         (age (if (memq category '(review ready changes-requested))
                  (min 10 (sp-org-issues-morning--age-days (plist-get pr :updated) now))
                0))
         (reason (alist-get category sp-org-issues-morning--reasons)))
    (cons (+ (alist-get category sp-org-issues-morning-scores)
             age
             (* -15 (car stack)))
          (if (cdr stack)
              (format "%s, but only after #%d" reason (cdr stack))
            reason))))
#+end_src

** Reading the issues

The issues come straight from the file with =org-map-entries=, so the file's own =#+todo:= line decides which headings are issues. Closed ones (=DONE=, =CNCL=) are left out. The repository is the second element of the outline path, which is the heading under =* Tasks=.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--issues-in-buffer ()
  "Return the open issues of the Org buffer, as plists."
  (let (issues)
    (org-with-wide-buffer
     (org-map-entries
      (lambda ()
        (let ((state (org-get-todo-state)))
          (when (member state '("TODO" "NEXT" "PROG" "WAIT"))
            (push (list :title (org-get-heading t t t t)
                        :state (intern (downcase state))
                        :repo (nth 1 (org-get-outline-path))
                        :id (org-entry-get nil "ID")
                        :pr (sp-org-issues-morning--pr-number
                             (org-entry-get nil "PR"))
                        :branch (sp-org-issues--nonempty (org-entry-get nil "BRANCH"))
                        :thread (sp-org-issues--nonempty (org-entry-get nil "THREAD"))
                        :deadline (when-let* ((d (org-entry-get nil "DEADLINE")))
                                    (org-time-string-to-time d))
                        :scheduled (when-let* ((s (org-entry-get nil "SCHEDULED")))
                                     (org-time-string-to-time s)))
                  issues))))))
    (nreverse issues)))

(defun sp-org-issues-morning--issues (file)
  "Return the open issues of the Org FILE."
  (with-current-buffer (find-file-noselect file)
    (sp-org-issues-morning--issues-in-buffer)))

(defun sp-org-issues-morning--days-from (time now)
  "Return the calendar days from NOW to TIME, negative when TIME is past."
  (- (time-to-days time) (time-to-days now)))

(defun sp-org-issues-morning--issue-score (issue now)
  "Return (SCORE . REASON) of the open ISSUE at NOW."
  (let* ((state (plist-get issue :state))
         (deadline (plist-get issue :deadline))
         (scheduled (plist-get issue :scheduled))
         (deadline-days (and deadline (sp-org-issues-morning--days-from deadline now)))
         (score (alist-get state sp-org-issues-morning-scores)))
    (cons (+ score
             (cond ((null deadline-days) 0)
                   ((<= deadline-days 0) 30)
                   ((<= deadline-days 3) 15)
                   (t 0))
             (if (and scheduled (<= (sp-org-issues-morning--days-from scheduled now) 0))
                 10 0))
          (concat (pcase state
                    ('prog "in progress") ('next "next action")
                    ('wait "waiting") ('todo "not started"))
                  (cond ((null deadline-days) "")
                        ((< deadline-days 0) ", overdue")
                        ((= deadline-days 0) ", due today")
                        ((<= deadline-days 3)
                         (format ", due in %d day%s" deadline-days
                                 (if (= deadline-days 1) "" "s")))
                        (t ""))))))
#+end_src

** One list

=sp-org-issues-morning--items= turns pull requests and issues into one list of items (plists with =:score=, =:reason=, =:title=, =:repo=, =:number=, =:url= and =:id=), best first. An issue that links an open pull request takes that pull request over: one line, the better score, and the pull request's reason when it is the better one. FETCHED lists the repositories GitHub was reached for; only for those can an issue's missing pull request be called gone. Ties keep the order of the issues file.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--items (issues prs now &optional fetched)
  "Return the ranked items for ISSUES and PRS at NOW, best first.
FETCHED lists the repositories whose pull requests were read."
  (let ((rest-prs (copy-sequence prs))
        items)
    (dolist (issue issues)
      (let* ((repo (plist-get issue :repo))
             (number (plist-get issue :pr))
             (pr (and number
                      (seq-find (lambda (p) (and (equal (plist-get p :repo) repo)
                                                 (eql (plist-get p :number) number)))
                                prs)))
             (own (sp-org-issues-morning--issue-score issue now))
             (best own))
        (cond
         (pr
          (setq rest-prs (delq pr rest-prs))
          (let ((theirs (sp-org-issues-morning--pr-score pr prs now)))
            (when (> (car theirs) (car own)) (setq best theirs))))
         ((and number (member repo fetched))
          (setq best (cons (+ (alist-get 'pr-gone sp-org-issues-morning-scores)
                              (- (car own) (alist-get (plist-get issue :state)
                                                      sp-org-issues-morning-scores)))
                           (format "PR #%d is no longer open: close the issue" number)))))
        (push (list :score (car best) :reason (cdr best)
                    :title (plist-get issue :title) :repo repo
                    :number (or number (and pr (plist-get pr :number)))
                    :url (and pr (plist-get pr :url)) :id (plist-get issue :id))
              items)))
    (dolist (pr rest-prs)
      (let ((score (sp-org-issues-morning--pr-score pr prs now)))
        (push (list :score (car score) :reason (cdr score)
                    :title (plist-get pr :title) :repo (plist-get pr :repo)
                    :number (plist-get pr :number) :url (plist-get pr :url))
              items)))
    (seq-sort-by (lambda (item) (plist-get item :score)) #'> (nreverse items))))
#+end_src

** The text of the list

The list is Org text, so the links work: a pull request links to GitHub (=C-c C-o= or =RET=), an issue to its heading by =id:=. Items score at least =sp-org-issues-morning-park-below= and fill =sp-org-issues-morning-limit= places go under Today, the rest under Parked. NOTES carry anything the reader should know, such as a repository GitHub could not be reached for.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--line (item)
  "Return the Org list line of ITEM."
  (let* ((title (plist-get item :title))
         (id (plist-get item :id))
         (url (plist-get item :url))
         (number (plist-get item :number))
         (repo (plist-get item :repo))
         (where (cond ((and url number) (format "[[%s][%s #%s]]" url repo number))
                      (number (format "%s #%s" repo number))
                      (t repo))))
    (format "- %s :: %s (%d)"
            (if id
                (format "[[id:%s][%s]] (%s)" id title where)
              (format "%s %s" where title))
            (plist-get item :reason)
            (plist-get item :score))))

(defun sp-org-issues-morning--render (items now &optional notes)
  "Return the Org text of the morning list for ITEMS at NOW, with NOTES."
  (let* ((today (seq-take (seq-filter (lambda (item)
                                        (>= (plist-get item :score)
                                            sp-org-issues-morning-park-below))
                                      items)
                          sp-org-issues-morning-limit))
         (parked (seq-remove (lambda (item) (memq item today)) items)))
    (concat
     (format-time-string "#+title: Morning %F %a\n" now)
     "Ranked by score, see `sp-org-issues-morning-scores'.  Press g to refresh.\n"
     (mapconcat (lambda (note) (format "\n/%s/\n" note)) notes "")
     "\n* Today\n"
     (if today
         (concat (mapconcat #'sp-org-issues-morning--line today "\n") "\n")
       "Nothing needs you today.\n")
     (when parked
       (concat "\n* Parked\n"
               (mapconcat #'sp-org-issues-morning--line parked "\n")
               "\n")))))
#+end_src

** Fetching the pull requests

One =gh pr list= per repository, run one after the other without blocking Emacs. A repository that fails (not logged in, no access, offline) is reported by its label and the others still count. The standard error of =gh= goes to its own buffer so that a warning cannot corrupt the JSON.

#+begin_src emacs-lisp -i
(defun sp-org-issues-morning--fetch (repos callback)
  "Read the open pull requests of REPOS, then call CALLBACK.
REPOS is a list of (LABEL . OWNER/NAME).  CALLBACK gets the pull requests
and the labels of the repositories that could not be read."
  (let ((prs nil) (failed nil) (todo (copy-sequence repos)))
    (cl-labels
        ((next ()
           (if (null todo)
               (funcall callback prs (nreverse failed))
             (let* ((repo (pop todo))
                    (out (generate-new-buffer " *sp-gh*"))
                    (err (generate-new-buffer " *sp-gh-err*")))
               (make-process
                :name "sp-gh" :buffer out :stderr err :noquery t
                :command (list sp-org-issues-gh-program "pr" "list"
                               "--repo" (cdr repo) "--state" "open"
                               "--limit" "50"
                               "--json" sp-org-issues-morning--pr-fields)
                :sentinel
                (lambda (process _event)
                  (unless (process-live-p process)
                    (condition-case nil
                        (if (zerop (process-exit-status process))
                            (setq prs (append prs (sp-org-issues-morning--parse-prs
                                                   (with-current-buffer out (buffer-string))
                                                   (car repo))))
                          (push (car repo) failed))
                      (error (push (car repo) failed)))
                    (kill-buffer out)
                    (kill-buffer err)
                    (next))))))))
      (next))))
#+end_src

** The buffer, the command and the daily greeting

=sp-org-issues-morning= reads the issues at once and the pull requests in the background, and shows the buffer when they arrive. Without =gh= it shows the issues alone and says so. The greeting is a command run once per day from an idle timer after startup; it writes today's date to =sp-org-issues-morning-stamp-file= before it runs, and an error in it (say, no Issues area yet) is only a message, never a broken startup.

FAILED lists the repositories that could not be read, out of REPOS.
NOTES are extra remarks for the top of the list."

(defun sp-org-issues-morning--schedule ()

      (delete-file script))
    result))
