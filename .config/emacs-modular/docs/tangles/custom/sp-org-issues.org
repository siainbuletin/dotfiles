Literate source for =libraries/modules/custom/sp-org-issues.el=. Every line of the module lives in the =emacs-lisp= blocks below, in order. The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

* Basic functionality

This module keeps the issues of my code work (the yadm dotfiles first, vulpea-mcp next) in one Org file, and makes that file a vulpea-para *area* titled "Issues". Being an area is what plugs it into the rest of the system:

- vulpea-para sees it in =vulpea-para-areas=, so =M-x vulpea-para-agenda-area= can restrict the agenda to it, and the "Area > Project" category prefix in agenda lines reads =Issues > dotfiles=.
- The file uses the org-gtd keywords (=TODO NEXT PROG WAIT | DONE CNCL=, the same ones =org-gtd-keyword-mapping= names in =sp-org-taskman-extra=).
   + They are set with a =#+todo:= line in the file itself, so the issues work even though the global =org-todo-keywords= is currently overwritten at the end of =sp-org-taskman-extra= with a =TODO WAITING DOING= sequence.
- Every issue carries =ORG_GTD: Actions=, which makes it an org-gtd single action. Once an issue is =NEXT= it appears in =org-gtd-engage= (=C-c d e=) with the other next actions.
- Each issue records =BRANCH=, =WORKTREE=, =PR= and =THREAD= (the Claude thread link) in its drawer, and =sp-org-issues-start= gives it its own git worktree and opens Magit there.

* How the file is laid out

An area in vulpea-para is one whole file tagged =area=, with =* Notes=, =* Tasks= and =* Archive= headings. The issues file keeps that shape. Under =* Tasks= there is one heading per code base.

A code base is ongoing, so it is not a PARA project (a project has an end); it is a plain heading that holds the repository's settings as properties, inherited by every issue below it.

*Managing complexity:* An issue that grows into several steps can be tagged =:project:= on its own, and vulpea-para then treats it as a project.

=M-x sp-org-issues-create-area= writes this file with =vulpea-create=, so it gets a real =ID= and lands in the vulpea database. It goes where vulpea-para puts every new area (=vulpea-para-capture-area-file-name=, =~/notes/area/<timestamp>-issues.org=). This is what it looks like, with one captured issue in it:

The keywords mean:

| Keyword | Meaning                                         | org-gtd     |
|---------+-------------------------------------------------+-------------|
| =TODO=  | Filed, not yet decided on                       | todo        |
| =NEXT=  | The next thing to pick up                       | next action |
| =PROG=  | Being worked on in its worktree (logs the time) |             |
| =WAIT=  | Waiting on a PR review or a reply (asks a note) | wait        |
| =DONE=  | Merged or otherwise finished (logs the time)    |             |
| =CNCL=  | Dropped (asks a note)                           | canceled    |

=#+archive: ::* Archive= makes =C-c C-x C-s= move a finished issue under the file's own =* Archive= heading, where it gets an =ARCHIVE_TIME= and vulpea-para counts it as archived.

* The issues area

** Repository headings

=sp-org-issues--repo-heading= writes one repository heading. Its =CATEGORY= uses vulpea-para's own "Area > Project" format, and the git settings sit in the drawer for the issues below to inherit.

#+begin_src emacs-lisp -i
;;;; The issues area

(defun sp-org-issues--repo-heading (name plist)
  "Return the Org text of the repository heading NAME described by PLIST."
  (string-join
   (delq nil
         (list (format "** %s :%s:" name (plist-get plist :tag))
               ":PROPERTIES:"
               (format ":ID:       %s" (org-id-new))
               (format ":CATEGORY: %s"
                       (vulpea-para-category sp-org-issues-area-title name))
               (format ":GIT_DIR:  %s" (plist-get plist :git-dir))
               (format ":WORKTREE_ROOT: %s" (plist-get plist :worktree-root))
               (format ":BASE:     %s" (or (plist-get plist :base) "main"))
               (when (plist-get plist :url)
                 (format ":URL:      %s" (plist-get plist :url)))
               ":END:"))
   "\n"))
#+end_src

** File body

The body handed to =vulpea-create=: Notes, Tasks with one heading per repository, and Archive.

#+begin_src emacs-lisp -i
(defun sp-org-issues--area-body ()
  "Return the body of a new issues area."
  (concat
   "* Notes\n"
   "One heading per code base under Tasks.  Each issue is a TODO under its\n"
   "repository, with BRANCH, WORKTREE, PR and THREAD in its drawer.\n"

** Finding the area

The area is found in the vulpea database by its title, so the file can live anywhere and be renamed freely.

#+begin_src emacs-lisp -i
(defun sp-org-issues-area ()
  "Return the issues area note, or nil when there is none yet."
  (seq-find (lambda (note)
              (string= (vulpea-note-title note) sp-org-issues-area-title))
            (vulpea-para-areas)))

(defun sp-org-issues-file ()
  "Return the path of the issues file."
  (if-let* ((area (sp-org-issues-area)))
      (vulpea-note-path area)
    (user-error "No %s area yet, run M-x sp-org-issues-create-area"
                sp-org-issues-area-title)))
#+end_src

** Creating the area

=sp-org-issues-create-area= is the one-time setup. It creates the file like =vulpea-para-capture-area= does (same file-name template and =area= tag) and adds the keyword and archive lines through =vulpea-create='s =:head=. When the area already exists it just visits it. =sp-org-issues-find= opens the file.

#+begin_src emacs-lisp -i
(defun sp-org-issues-create-area ()
  "Create the issues area, or visit it when it already exists."
  (interactive)
  (if-let* ((area (sp-org-issues-area)))
      (vulpea-visit area)
    (vulpea-visit
     (vulpea-create sp-org-issues-area-title
                    vulpea-para-capture-area-file-name
                    :tags (list vulpea-para-area-tag)
                    :head (concat sp-org-issues-todo-line
                                  "\n#+archive: ::* Archive")
                    :body (sp-org-issues--area-body)))))

(defun sp-org-issues-find ()
  "Visit the issues file."
  (interactive)
  (find-file (sp-org-issues-file)))
#+end_src

* Capture

** Repository target

Finds the level-2 heading of a repository, or adds it at the end of =* Tasks= when a repository from =sp-org-issues-repos= has no heading yet.

#+begin_src emacs-lisp -i
;;;; Capture

(defun sp-org-issues--goto-repo (name)
  "Move point to the repository heading NAME, creating it when missing."
  (goto-char (point-min))
  (let ((re (format org-complex-heading-regexp-format (regexp-quote name)))
        found)
    (while (and (not found) (re-search-forward re nil t))
      (when (= (org-current-level) 2)
        (setq found t)))
    (if found
        (beginning-of-line)
      (vulpea-para--goto-tasks-end)
      (insert (sp-org-issues--repo-heading
               name (cdr (assoc name sp-org-issues-repos)))
              "\n")
      (sp-org-issues--goto-repo name))))
#+end_src

** Issue template

Org runs the template before the target, so the template asks for the repository and stores it on the capture, the same way vulpea-para's project template stores the area. The issue gets an =ID=, a =CREATED= stamp, =ORG_GTD: Actions= and empty =BRANCH=, =PR= and =THREAD= fields. =%^g= offers the file's tags (=emacs=, =vulpea= and so on).

#+begin_src emacs-lisp -i
(defun sp-org-issues-capture-template ()
  "Return the capture template of an issue, after asking for its repository."
  (org-capture-put :issue-repo
                   (completing-read "Repository: " sp-org-issues-repos
                                    nil t))
  (string-join
   (list "* TODO %^{Issue} %^g"
         ":PROPERTIES:"
         (format ":ID:       %s" (org-id-new))
         (format ":CREATED:  %s" (format-time-string "[%Y-%m-%d %H:%M]"))
         ":ORG_GTD:  Actions"
         ":BRANCH:"
         ":PR:"
         ":THREAD:"
         ":END:"
         "%?")
   "\n"))
#+end_src

** Custom commands

Adds an =i= prefix to the agenda dispatcher (=C-c o a=):

- =i i= Issue board: in progress, next, waiting, and open issues, in that order, in a buffer named =*Issues*=.
- =i b= Issues with a branch: every open issue whose =BRANCH= is set.

From the agenda, =t= changes an issue's state, =:= sets its tags, =C-c C-x p= sets a property such as =PR=, and =RET= jumps to it.

#+begin_src emacs-lisp -i
(dolist (command
         `(("i" . "Issues")
           ("ii" "Issue board"
            ((todo "PROG" ((org-agenda-overriding-header "In progress")))
             (todo "NEXT" ((org-agenda-overriding-header "Next")))
             (todo "WAIT" ((org-agenda-overriding-header "Waiting on review or a reply")))
             (todo "TODO" ((org-agenda-overriding-header "Open"))))
            ((org-agenda-files (sp-org-issues--agenda-files))
             (org-agenda-buffer-name "*Issues*")))
           ("ib" "Issues with a branch" tags-todo "BRANCH<>\"\""
            ((org-agenda-files (sp-org-issues--agenda-files))
             (org-agenda-overriding-header "Issues with a branch")))))
  (add-to-list 'org-agenda-custom-commands command t))
#+end_src

* Branches and worktrees

The user should be able to quickly act on issues that are listed in the repository here.
- This workflow should replace keeping a ~todo.org~ file in the ~docs/~ repository.

** Acting on the issue at point

Lets the commands below work both in the issues file and on an agenda line.

#+begin_src emacs-lisp -i
;;;; Branches and worktrees

(defmacro sp-org-issues--at-issue (&rest body)
  "Run BODY at the issue heading at point, in Org or in the agenda."
  (declare (indent 0))
  `(let ((marker (if (derived-mode-p 'org-agenda-mode)
                     (or (org-get-at-bol 'org-marker)
                         (user-error "No issue on this line"))
                   (point-marker))))
     (with-current-buffer (marker-buffer marker)
       (org-with-wide-buffer
        (goto-char marker)
        (org-back-to-heading t)
        ,@body))))
#+end_src

** Running git

All git calls name the repository with =--git-dir=, so they work the same for the yadm repository (whose worktree is the home folder) and for an ordinary clone. They run from the home folder, so a TRAMP buffer never sends them to another host.

#+begin_src emacs-lisp -i
(defun sp-org-issues--git (git-dir &rest args)
  "Run git on GIT-DIR with ARGS and return its output.
Signal an error with git's message when it fails."
  (let ((default-directory (expand-file-name "~/")))
    (with-temp-buffer
      (let ((status (apply #'process-file "git" nil t nil
                           (concat "--git-dir=" (expand-file-name git-dir))
                           args)))
        (unless (zerop status)
          (user-error "git %s: %s" (string-join args " ")
                      (string-trim (buffer-string))))
        (string-trim (buffer-string))))))

(defun sp-org-issues--ref-p (git-dir ref)
  "Return non-nil when REF exists in GIT-DIR."
  (ignore-errors
    (sp-org-issues--git git-dir "rev-parse" "--verify" "--quiet" ref)
    t))

(defun sp-org-issues--slug (string)
  "Return STRING as a short branch or directory name."
  (let ((slug (replace-regexp-in-string "[^a-z0-9/]+" "-" (downcase string))))
    (string-trim (truncate-string-to-width slug 40) "-" "-")))

(defun sp-org-issues--nonempty (value)
  "Return VALUE unless it is nil or blank."
  (and value (not (string-blank-p value)) value))
#+end_src

** Adding a worktree

Uses the local branch when there is one, tracks =origin/BRANCH= when only GitHub has it (a branch a Claude thread pushed, for example), and otherwise starts a new branch from the repository's =BASE=.

#+begin_src emacs-lisp -i
(defun sp-org-issues-worktree-add (git-dir dir branch base)
  "Add a worktree at DIR for BRANCH of GIT-DIR.
Use the local BRANCH when it exists, else track origin/BRANCH, else
start BRANCH from BASE."
  (cond
   ((sp-org-issues--ref-p git-dir (concat "refs/heads/" branch))
    (sp-org-issues--git git-dir "worktree" "add" dir branch))
   ((sp-org-issues--ref-p git-dir (concat "refs/remotes/origin/" branch))
    (sp-org-issues--git git-dir "worktree" "add" "--track" "-b" branch dir
                        (concat "origin/" branch)))
   (t
    (sp-org-issues--git git-dir "worktree" "add" "-b" branch dir base))))
#+end_src

** Starting an issue

=M-x sp-org-issues-start= on an issue (or its agenda line) asks for a branch name when the issue has none, offering =issue/<title>=, adds the worktree under =WORKTREE_ROOT= when it is missing, writes =BRANCH= and =WORKTREE= into the drawer, moves a =TODO= or =NEXT= issue to =PROG=, and opens =magit-status= in the worktree. Run it again later and it goes straight to Magit.

#+begin_src emacs-lisp -i
(defun sp-org-issues-start ()
  "Work on the issue at point in its own worktree, then open Magit there.

Asks for a branch when the issue has none, adds the worktree under the
repository's WORKTREE_ROOT when it is missing, records BRANCH and
WORKTREE on the issue, and moves a TODO or NEXT issue to PROG."
  (interactive)
  (let ((dir
         (sp-org-issues--at-issue
           (let* ((git-dir (or (org-entry-get nil "GIT_DIR" t)
                               (user-error "This heading is not in a repository")))
                  (root (or (org-entry-get nil "WORKTREE_ROOT" t)
                            (user-error "The repository has no WORKTREE_ROOT")))
                  (base (or (org-entry-get nil "BASE" t) "main"))
                  (branch (or (sp-org-issues--nonempty (org-entry-get nil "BRANCH"))
                              (read-string
                               "Branch: "
                               (concat "issue/"
                                       (sp-org-issues--slug
                                        (org-get-heading t t t t))))))
                  (dir (expand-file-name
                        (or (sp-org-issues--nonempty (org-entry-get nil "WORKTREE"))
                            (expand-file-name
                             (replace-regexp-in-string "/" "-" branch) root)))))
             (unless (file-directory-p dir)
               (sp-org-issues-worktree-add git-dir dir branch base))
             (org-entry-put nil "BRANCH" branch)
             (org-entry-put nil "WORKTREE" (abbreviate-file-name dir))
             (when (member (org-get-todo-state) '("TODO" "NEXT"))
               (org-todo "PROG"))
             dir))))
    (magit-status dir)))
#+end_src

** Closing an issue

When an issue becomes =DONE= or =CNCL= and still has a worktree, the module offers to remove it. =git worktree remove= refuses when the worktree has uncommitted changes, and the message says so. The branch itself is kept.

#+begin_src emacs-lisp -i
(defun sp-org-issues--offer-worktree-removal ()
  "Offer to remove the worktree of an issue that was just closed."
  (when-let* (((and sp-org-issues-offer-worktree-removal
                    (member org-state '("DONE" "CNCL"))))
              (git-dir (org-entry-get nil "GIT_DIR" t))
              (dir (sp-org-issues--nonempty (org-entry-get nil "WORKTREE")))
              ((file-directory-p dir))
              ((y-or-n-p (format "Remove the worktree %s? " dir))))
    (condition-case err
        (progn
          (sp-org-issues--git git-dir "worktree" "remove" (expand-file-name dir))
          (org-entry-delete nil "WORKTREE"))
      (user-error (message "%s" (error-message-string err))))))

(add-hook 'org-after-todo-state-change-hook
          #'sp-org-issues--offer-worktree-removal)
#+end_src

** Untracked files in yadm worktrees

In a status buffer for a worktree of the yadm repository, this sets =magit-status-show-untracked-files= locally, so new files show up there. Magit gives the buffer-local value of that variable priority over the repository's =status.showUntrackedFiles=, which stays =no= for the home folder.

#+begin_src emacs-lisp -i
(defun sp-org-issues--show-untracked-in-yadm-worktrees ()
  "List untracked files in Magit when this is a worktree of the yadm repo."
  (when-let* ((gitdir (magit-gitdir)))
    (when (string-prefix-p
           (file-name-as-directory
            (expand-file-name "worktrees" sp-org-issues-yadm-repo))
           (expand-file-name gitdir))
      (setq-local magit-status-show-untracked-files t))))

(with-eval-after-load 'magit
  (add-hook 'magit-status-mode-hook
            #'sp-org-issues--show-untracked-in-yadm-worktrees))
#+end_src
