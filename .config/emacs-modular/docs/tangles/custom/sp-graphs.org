- They all draw or analyse graphs of notes. Only two of them install a package. The others are code of my own.

2. *Custom code*: the relationship annotator, which reads relations between Vulpea notes and draws them, and its live view, a small web server inside Emacs that shows the same page and reloads it when the notes change. Both are written here, in full.

** How they differ

- *Package or my code.* =discourse-graphs= and =vulpea-graph= are other people's code. What I own here is their recipe and, for =discourse-graphs=, their settings. The annotator and the live view are mine, so a bug in them is mine to fix and they are documented line by line below.
- *Who owns the data.* =discourse-graphs= keeps a database of its own and has to scan the notes to fill it (=dg-rebuild-cache=). The annotator and the live view keep nothing: they ask Vulpea each time. =vulpea-graph= also works on Vulpea notes.
- *Same vocabulary, different model.* The annotator was written to read the notes that =discourse-graphs= reads: the property names (=DG_TYPE=, =DG_SUPPORTS=), the four relations and the formulas are the same. The differences, and what I did not port, are in [[file:../../architecture/relationship-annotator-vs-discourse-graphs.org][relationship-annotator-vs-discourse-graphs]]. The settings of =discourse-graphs= below (=dg-node-types=, =dg-relation-types=) and the annotator's (=relationship-annotator-relations=, =relationship-annotator-node-types=) describe the same four relations twice; changing one does not change the other.
- *Two ways to serve a graph to a browser.* =vulpea-graph= needs =websocket= and =simple-httpd=. The live view uses neither: it has its own server on =make-network-process=, bound to =127.0.0.1=, because =simple-httpd= is one global server that listens on every interface by default (reasons in [[*Why a small server of its own][Why a small server of its own]]).
- *Static or live.* =rel-anno-graph-static= writes a self-contained HTML file and opens it from disk, a snapshot. =rel-anno-graph= opens the live view. The page, the data and the drawing are the same.
- *What I could not check.* I did not read the source of =vulpea-graph=, so the table says only what its recipe, its commands and its dependencies show. The =discourse-graphs= column rests on the existing comparison document.

** discourse-graphs (from =sp-dgraphs=)

This installs and configures =discourse-graphs=, a package by LuciusChen.

- It treats Org headings in a notes directory as typed nodes: questions, claims, evidence, sources, theories.
- The nodes are connected by typed relations: supports, opposes, informs, answers.
- It stores them in an SQLite database.
- It offers a context panel, heading overlays and a browser-based UI.
- It was kept in a module of its own so it can be set up on its own.
- Some variables from Lambda Emacs are still needed for it to work well: =sp-notes-dir= and =sp-path=, from =sp-globals= (the former =sp-paths=).

Setup:

- The package is fetched from GitHub through Elpaca, including the prebuilt HTML and assets of its web UI.
- Notes are scanned recursively under =sp-notes-dir= (=~/notes/= unless =SP_NOTES_DIR= says otherwise), with Denote integration turned on.
- The database is configured to live in =~/.config/emacs-include/=.
- A =discourse-graphs.db= file also sits at the root of this repository, which suggests the location has changed at some point.

Everything under this heading is settings and the =use-package= form for the package. None of it is a function of mine.

*** Installing the package

**** use-package discourse-graphs

Installs =discourse-graphs= from GitHub with the Elisp files and the built web UI files. Once loaded, it:

- sets the directories to scan (=~/notes/=),
- turns on recursive scanning,
- sets the SQLite database path,
- enables the global =discourse-graphs-mode=.

The options of the package (the =dg-= variables below) are in =:custom=. The directories, recursion and database path stay as =setq= forms in =:config=.

The closing parenthesis on its own line ends the =use-package= form.

*** Display and behaviour options

These are in the =:custom= block of the =use-package= form above. They used to be plain =setq= calls after the form, which ran after =discourse-graphs-mode= had been turned on in =:config=; now they are set first. The package's =defcustom= forms do not override values that are already set.

**** Denote integration

Sets =dg-use-denote= so that nodes are handled as Denote notes.


**** Context panel

The context panel takes 30 percent of the frame width, updates automatically as point moves between nodes, and shows at most 30 lines per node.


**** Overlays and synthesis file

Turns on overlays on node headings and sets the synthesis dashboard file to =~/notes/dg-synthesis.org=.


*** Discourse model

The vocabulary of the graph: computed attributes, node types, relation types, and which node types each relation may connect. These are also =:custom= entries of the =use-package= form above.

**** Computed attributes

=dg-discourse-attributes= defines formulas over relation counts.

- Claims get an evidence score (supporting minus opposing evidence) and a robustness score that also counts supporting claims at half weight. The evidence score is shown in the heading overlay.
- Questions get an answer count, which is their overlay.
- A comment leaves room for more types.


**** Node types

=dg-node-types= defines five node types, each with a three-letter tag, a colour and a description: question (QUE), claim (CLM), evidence (EVD), source (SRC, described as reference material or philosophical text) and theory (THY).


**** Relation types

=dg-relation-types= defines four relations with the label used for the inverse direction and the colour and line style used when drawing them: supports (green, solid), opposes (red, dashed), informs (blue, solid) and answers (purple, solid).


**** Relation patterns

=dg-relation-patterns= restricts which node types each relation connects: evidence supports or opposes claims, sources inform evidence, and claims answer questions. Theory nodes do not appear in any pattern, so as configured they cannot take part in relations.

** Relationship annotator (from =sp-relationship-annotator=)

Literate source for the first custom part.

- The text under this heading is the old document of =sp-relationship-annotator=, with its line numbers removed. The tangled file is now the whole of =sp-graphs.el=, and the numbers would be wrong.

*** Context

My notes follow a Zettelkasten pattern.

- One file is one idea.
- A sub-note records its parents with a =- parents :: [[id:…][Title]]= line in its zeroth section. vulpea stores that as metadata.
- A note can have several parents: one link after another on the same line separated by commas, or one =- parents ::= line per parent.
- =vulpea-graph= doesn't draw this hierarchy. It analyses links for retrieval and shows lists.
- So this module reads the =parents= metadata and builds the tree itself.

Besides =parents=, a note can relate to other notes in other ways.

- Relations: =supports=, =opposes=, =informs=, =answers=, or any relation you declare in =relationship-annotator-relations=.
- Each relation lists the places it is read from:
  - a metadata key on the note,
  - the inverse of a key on the other note (=children= for =parents=),
  - a file property such as =DG_SUPPORTS=, which is how =discourse-graphs= stores its relations.
- Parents and children build the tree.
- The other relations are drawn as labelled, coloured, dashed links between two notes that are both in view.

Tags and tinting:

- Boxes are tinted by file tag.
- =relationship-annotator-tag-colors= maps a tag to a colour. A note takes the colour of the first of its tags that is listed.

Layout in the browser:

- The position of every box comes from the fCoSE layout (see =vendor/relationship-annotator/README.org=).
- Parents go above their children.
- Each relation can say in which direction its object goes, with =:direction= in =relationship-annotator-relations=.

Navigation:

- A click on a box, or Tab to it and Enter, recentres the graph on it and cuts the tree again from there.
- The page holds the tree down to =relationship-annotator-embed-depth= levels (4). The depth buttons and Backspace move through it.
- Emacs cuts the tree there, so a large vault doesn't make the page large. To go further, run the command again from another note.
- A small marker on a box folds its branch.

The module was called =sp-vulpea-hierarchy= until it took over the logic of the =discourse-graphs= package.

- Notes can have a /type/ (=question=, =claim=, =evidence= or =source=), read from a =DG_TYPE= property, a =type= metadata field or a file tag.
- A relation can say which types it should connect. A =supports= edge from a question is flagged as an anomaly: a warning sign in the browser, a line in the review buffer.
- Notes can have /attributes/: numbers computed from formulas such as ={count:Supported By:evidence} - {count:Opposed By:evidence}=. One of them is shown in brackets after the title.
- =rel-anno-review= lists the anomalies, the claims with gaps in their argument, and how well each answer to a question stands.
- For how this compares with the package, see [[file:../../architecture/relationship-annotator-vs-discourse-graphs.org][relationship-annotator-vs-discourse-graphs]].

A vault of this size is too large to draw whole. So every command first asks for a *starting note* and a *depth*, and shows only that part: the starting note, its children, their children, down to the depth.

**** Customisation

- Create the =relationship-annotator= group under =vulpea=, so the options show up in =M-x customize-group=.
- Define =relationship-annotator-relations=, the list of relations between notes. Each entry has a name, a label, a colour, a direction for the views, the name of its inverse, the node types it should connect, and a list of /sources/ that say where to look for its edges.
- Define =parent=, the relation that builds the tree. It has two sources: the =parents= key on a sub-note, and the =children= key on a parent, so a note can list its children as well as its parents. It has no direction, because parents always go above their children, and its inverse is "children".
- Define =supports=, =opposes=, =informs= and =answers=, the typed relations that =discourse-graphs= uses. Each reads a metadata key (=- supports :: [[id:…][Title]]=) and the same name as a file property (=DG_SUPPORTS=), so notes written for either work. Each has a =:direction=: where the /object/ of the relation is drawn, seen from its subject. =supports= puts it to the right and =opposes= to the left, so supporters end up on the left of a claim and opponents on its right. =informs= uses an angle of 45 degrees (up and to the right), and =answers= puts the question above its answer.
- Each of these four also has an =:inverse= label, which is how a formula names the relation seen from its object, and the two lists of types it should connect: =:subject-types= and =:object-types=. These are the /relation patterns/ of =discourse-graphs=: evidence supports or opposes a claim, a source informs evidence, and a claim answers a question.
- The documentation string: an edge reads "subject name object", the four kinds of source are =meta=, =meta-inverse=, =property= and =property-inverse=, and a direction is =up=, =down=, =left=, =right= or an angle in degrees, where 0 is right and 90 is up. It explains the inverse name and the types: an edge between other types is not refused, only reported.
- Gives the option its type.
- Define =relationship-annotator-tag-colors=, which maps a file tag to a colour. **** Reading the relations of a note

A note may name several parents, or several targets of another relation.

- Either on one line, separated by commas, or on one line per value.
- vulpea keeps one entry per line, and a comma-separated line stays one entry. So =vulpea-note-meta-get-list= with the =link= type would only return the first link of each.
- The functions here read every link themselves.
- They work for every relation and every kind of source.

- Define =relationship-annotator--value-ids=. It takes a list of strings and returns the ids in them. It scans each string for every bracket link (165), keeps the ones that start with =id:= (168-169) and moves on after each (170). A string with no link at all is read as bare ids separated by commas or spaces (171-173), which is how a file property usually holds them. Duplicates are dropped (174).
- Define =relationship-annotator--source-values=. For a metadata source it returns the strings stored under the key (179-180). For a property source it returns the property's value as a one-element list (181-183). The =-inverse= forms read the same place.
- Define =relationship-annotator--source-notes=: the notes that might hold a source. Metadata sources use the database's key index (188-189). The database has no index of properties, so property sources test every note (190-192).
- Define =relationship-annotator--edges=, which goes over every relation and every source and returns all the edges as =(subject relation object)=, plus a table of the notes it read.
- Bind the notes table, a =seen= table that drops an edge written twice (when a relation is declared both ways), and the list of edges.
- Go over each relation, each of its sources, and each note that may hold it.
- Get the ids that note names under that source.
- Build the edge. For a normal source the note is the subject, and for an inverse source it is the object.
- Keep the edge the first time it is seen.
- Returns the edges and the notes.

#+begin_src emacs-lisp
(defun relationship-annotator--value-ids (values)
  "Return the ids named in VALUES, a list of strings.
A value may hold several links, separated by commas or not.  Every link
counts, not only the first one in a value.  A value with no link is
read as bare ids separated by commas or spaces."
  (let (ids)
    (dolist (value values)
      (let ((pos 0) (found nil))
        (while (string-match org-link-bracket-re value pos)
          (setq found t)
          (let ((link (match-string 1 value)))
            (when (string-prefix-p "id:" link)
              (push (string-remove-prefix "id:" link) ids)))
          (setq pos (match-end 0)))
        (unless found
          (dolist (word (split-string value "[ ,]+" t))
            (push word ids)))))
    (delete-dups (seq-remove #'string-empty-p (nreverse ids)))))

(defun relationship-annotator--source-values (note source)
  "Return the strings that SOURCE finds in NOTE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (cdr (assoc key (vulpea-note-meta note))))
    ((or `(property ,key) `(property-inverse ,key))
     (when-let* ((value (cdr (assoc key (vulpea-note-properties note)))))
       (list value)))))

(defun relationship-annotator--source-notes (source)
  "Return the notes that may hold SOURCE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (vulpea-db-query-by-meta-key key))
    ((or `(property ,key) `(property-inverse ,key))
     (vulpea-db-query
      (lambda (note) (assoc key (vulpea-note-properties note)))))))

(defun relationship-annotator--edges ()
  "Return every edge as (SUBJECT RELATION OBJECT), and the notes read.
The second value is a hash table from id to note."
  (let ((notes (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        edges)
    (pcase-dolist (`(,relation . ,plist) relationship-annotator-relations)
      (dolist (source (plist-get plist :sources))
        (dolist (note (relationship-annotator--source-notes source))
          (puthash (vulpea-note-id note) note notes)
          (dolist (id (relationship-annotator--value-ids
                       (relationship-annotator--source-values note source)))
            (let* ((inverse (memq (car source) '(meta-inverse property-inverse)))
                   (edge (if inverse
                             (list id relation (vulpea-note-id note))
                           (list (vulpea-note-id note) relation id))))
              (unless (gethash edge seen)
                (puthash edge t seen)
                (push edge edges)))))))
    (cons (nreverse edges) notes)))

**** Building the whole tree

This function returns a plist with four keys: =:notes= (id to note), =:children= (parent id to child ids), =:links= (the edges of every other relation) and =:roots= (parents that have no parent of their own).

- Define the function and say what it returns.
- Read all edges (220) and create the =children= and =has-parent= tables, which use =equal= so UUID strings work as keys, and empty lists for the parent ids, the links and every id met.
- Go over each edge and collect both ends.
- Handle a =parent= edge: the subject (the child) is marked as having a parent, which keeps it out of the roots (230), is added to its parent's list of children (231), and the parent id is collected (232).
- Keeps an edge of any other relation as a link.
- Load the notes that only appear as the end of an edge and were not read yet, in one query, so their titles are known.
- Return the plist. The roots are the parents that have no parent, sorted by title.

#+begin_src emacs-lisp
(defun relationship-annotator--build ()
  "Return a plist describing the whole hierarchy.
:notes maps id to note, :children maps parent id to child ids,
:roots lists ids that are parents but have no parent themselves, and
:links lists the edges (SUBJECT RELATION OBJECT) of every other relation."
  (pcase-let* ((`(,edges . ,notes) (relationship-annotator--edges))
               (children (make-hash-table :test #'equal))
               (has-parent (make-hash-table :test #'equal))
               (parent-ids nil)
               (links nil)
               (ids nil))
    (pcase-dolist (`(,subject ,relation ,object) edges)
      (push subject ids)
      (push object ids)
      (if (eq relation 'parent)
          (progn (puthash subject t has-parent)
                 (push subject (gethash object children))
                 (push object parent-ids))
        (push (list subject relation object) links)))
    ;; Notes that only appear as the object of an edge are not loaded yet.
    (dolist (note (vulpea-db-query-by-ids
                   (seq-remove (lambda (id) (gethash id notes))
                               (delete-dups ids))))
      (puthash (vulpea-note-id note) note notes))
    (list :notes notes
          :children children
          :links (nreverse links)
          :roots (sort (seq-remove (lambda (id) (gethash id has-parent))
                                   (delete-dups (copy-sequence parent-ids)))
                       (lambda (a b)
                         (string< (relationship-annotator--title a notes)
                                  (relationship-annotator--title b notes)))))))

**** Cutting the part to show

This function takes the whole tree and keeps only what is within =depth= levels of =start=. It works breadth first.

- Define the function and describe the result: the same keys as the tree, plus =:more= (how many children a last-level note hides) and =:nodes= (the ids in scope), with =:roots= set to just the start. =:links= keeps only the links between two notes that are in scope.
- Set up the state: the shared notes table, a new =children= table for the cut tree, the =more= table, the =seen= table, the list of =nodes= and a queue of =(id . level)= pairs.
- Marks the start note as seen.
- Take the next pair from the queue.
- Gets the note's children, sorted, from the full tree.
- Handle a note above the last level: every child gets an edge (273-274). The first time a child is met, it is marked (276), added to the nodes (277) and queued one level down (278). A child that was already seen still gets its edge, so a note with two parents shows under both.
- Handle a note on the last level: its children are not shown, only counted in =more=.
- Puts the nodes in the order they were found.
- Return the cut tree, with the links filtered to the notes that were seen (287-289).

#+begin_src emacs-lisp
(defun relationship-annotator--scope (tree start depth)
  "Return the part of TREE reached from START within DEPTH levels.
The result has the same keys as the tree, plus :more, which maps an
id at the last level to how many children it hides, and :nodes, the
ids in scope.  :roots is just (START).  :links keeps the other
relations between two notes that are both in scope."
  (let ((notes (plist-get tree :notes))
        (children (make-hash-table :test #'equal))
        (more (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        (nodes (list start))
        (queue (list (cons start 0))))
    (puthash start t seen)
    (while queue
      (pcase-let ((`(,id . ,level) (pop queue)))
        (let ((kids (relationship-annotator--sorted-children id tree)))
          (if (< level depth)
              (dolist (kid kids)
                (puthash id (append (gethash id children) (list kid)) children)
                (unless (gethash kid seen)
                  (puthash kid t seen)
                  (push kid nodes)
                  (setq queue (append queue (list (cons kid (1+ level)))))))
            (when kids
              (puthash id (length kids) more))))))
    (setq nodes (nreverse nodes))
    (list :notes notes
          :children children
          :more more
          :roots (list start)
          :nodes nodes
          :links (seq-filter (pcase-lambda (`(,subject ,_ ,object))
                               (and (gethash subject seen) (gethash object seen)))
                             (plist-get tree :links)))))

**** Discourse layer: the pattern check

- Define =relationship-annotator--all-edges=. The tree keeps the parent edges apart from the links, as a table from parent to children. This puts them back together as one list of =(SUBJECT RELATION OBJECT)=, so the checks below treat =parent= like every other relation.

(defun relationship-annotator--all-edges (tree)
  "Return every edge of TREE as (SUBJECT RELATION OBJECT), parent edges included."
  (let (edges)
    (maphash (lambda (parent kids)
               (dolist (kid kids)
                 (push (list kid 'parent parent) edges)))
             (plist-get tree :children))
    (append (nreverse edges) (plist-get tree :links))))

(defun relationship-annotator--anomaly (subject-type relation object-type)
  "Return a message when SUBJECT-TYPE RELATION OBJECT-TYPE breaks the patterns.
The patterns are :subject-types and :object-types in
`relationship-annotator-relations'.  Return nil when the edge fits, when
the relation has no patterns, or when a type is nil (an untyped note
is not checked)."
  (let* ((plist (cdr (assq relation relationship-annotator-relations)))
         (want-subject (plist-get plist :subject-types))
         (want-object (plist-get plist :object-types))
         (bad-subject (and want-subject subject-type
                           (not (memq subject-type want-subject))))
         (bad-object (and want-object object-type
                          (not (memq object-type want-object)))))
    (cond
     ((and bad-subject bad-object)
      (format "%s %s %s, expected %s %s %s" subject-type relation object-type
              (relationship-annotator--type-names want-subject) relation
              (relationship-annotator--type-names want-object)))
     (bad-subject
      (format "%s %s %s, the subject should be %s" subject-type relation
              object-type (relationship-annotator--type-names want-subject)))
     (bad-object
      (format "%s %s %s, the object should be %s" subject-type relation
              object-type (relationship-annotator--type-names want-object))))))

(defun relationship-annotator--anomalies (tree)
  "Return the edges of TREE that break the patterns, as (SUBJECT RELATION OBJECT MESSAGE)."
  (let ((notes (plist-get tree :notes)) found)
    (pcase-dolist (`(,subject ,relation ,object)
                   (relationship-annotator--all-edges tree))
      (when-let* ((message (relationship-annotator--anomaly
                           (relationship-annotator--note-type
                            (relationship-annotator--note subject notes))
                           relation
                           (relationship-annotator--note-type
                            (relationship-annotator--note object notes)))))
        (push (list subject relation object message) found)))
    (nreverse found)))

**** Formulas: reading

This is the formula language of the package: arithmetic with =+ - * /= and parentheses over numbers and terms in braces.

- The package parses it with a global list of tokens, which can't run twice at once.
- The version here has no global state.

- Define a variable that holds the attributes being computed. A formula that refers to itself would otherwise recurse forever (the package has no guard); this list lets the evaluator stop with a message.
- Define =relationship-annotator--parse-term=, which turns the text between braces into =(func OP RELATION TYPE ATTRIBUTE)=. The text is split at colons. The operation is =count=, =sum=, or =avg= (also written =average=), and anything else stops with a message. A term needs a relation, and =sum= and =avg= need an attribute to add up. The type and the attribute are optional; an empty one counts as none.
- Define =relationship-annotator--tokenize=, which splits a formula into tokens. Blanks are skipped. The characters =+ - * /= become the symbols of the same name, and the parentheses become =open= and =close=. A brace starts a term, which runs to the next closing brace (an unclosed one is an error) and goes through the function above. A number is read as a float. Any other character stops with a message that names it.

#+begin_src emacs-lisp
;;;;; Formulas

(defvar relationship-annotator--computing nil
  "Attributes being computed, as (ID . NAME), to catch formulas that refer to themselves.")

(defun relationship-annotator--parse-term (spec formula)
  "Return the term (func OP RELATION TYPE ATTRIBUTE) written SPEC in FORMULA.
SPEC is the text between braces."
  (pcase-let* ((`(,op ,relation ,type ,attribute) (split-string spec ":"))
               (op (pcase (and op (downcase op))
                     ("count" 'count) ("sum" 'sum)
                     ((or "avg" "average") 'avg)
                     (_ (user-error "Unknown operation in {%s} in formula %S"
                                    spec formula)))))
    (unless (and relation (not (string-empty-p relation)))
      (user-error "No relation in {%s} in formula %S" spec formula))
    (when (and (memq op '(sum avg)) (not (and attribute (not (string-empty-p attribute)))))
      (user-error "%s needs an attribute in {%s} in formula %S" op spec formula))
    (list 'func op relation
          (and type (not (string-empty-p type)) (intern (downcase type)))
          (and attribute (not (string-empty-p attribute)) (intern attribute)))))

(defun relationship-annotator--tokenize (formula)
  "Split FORMULA into numbers, operator symbols and terms."
  (let ((pos 0) tokens)
    (while (< pos (length formula))
      (let ((char (aref formula pos)))
        (cond
         ((memq char '(?\s ?\t)) (cl-incf pos))
         ((memq char '(?+ ?- ?* ?/))
          (push (intern (string char)) tokens) (cl-incf pos))
         ((eq char ?\() (push 'open tokens) (cl-incf pos))
         ((eq char ?\)) (push 'close tokens) (cl-incf pos))
         ((eq char ?{)
          (let ((end (string-search "}" formula pos)))
            (unless end (user-error "Unclosed { in formula %S" formula))
            (push (relationship-annotator--parse-term
                   (substring formula (1+ pos) end) formula)
                  tokens)
            (setq pos (1+ end))))
         ((eq pos (string-match "[0-9]+\\(?:\\.[0-9]+\\)?" formula pos))
          (push (float (string-to-number (match-string 0 formula))) tokens)
          (setq pos (match-end 0)))
         (t (user-error "Unexpected %c in formula %S" char formula)))))
    (nreverse tokens)))
#+end_src

**** Formulas: parsing

- Define =relationship-annotator--parse-formula=, a recursive-descent parser that returns a tree. A tree is a number, a term, or =(OPERATOR LEFT RIGHT)=. The local functions =expr=, =term= and =factor= follow the usual precedence: =expr= reads terms joined by =+= and =-=, =term= reads factors joined by =*= and =/=, and =factor= reads a number, a term, a parenthesised expression, or a minus sign followed by a factor (which becomes =0 - factor=). The tokens are kept in a local variable, so the parser can be called again at any time. A leftover token or a missing parenthesis is an error that quotes the formula.

#+begin_src emacs-lisp
(defun relationship-annotator--parse-formula (formula)
  "Return the parse tree of FORMULA.
A tree is a number, a term (func ...), or (OPERATOR LEFT RIGHT) with
OPERATOR one of + - * /."
  (let ((tokens (relationship-annotator--tokenize formula)))
    (cl-labels
        ((peek () (car tokens))
         (next () (pop tokens))
         (expr ()
           (let ((left (term)))
             (while (memq (peek) '(+ -))
               (let ((op (next)))
                 (setq left (list op left (term)))))
             left))
         (term ()
           (let ((left (factor)))
             (while (memq (peek) '(* /))
               (let ((op (next)))
                 (setq left (list op left (factor)))))
             left))
         (factor ()
           (let ((token (next)))
             (cond
              ((numberp token) token)
              ((eq token 'open)
               (prog1 (expr)
                 (unless (eq (next) 'close)
                   (user-error "Missing ) in formula %S" formula))))
              ((eq token '-) (list '- 0.0 (factor)))
              ((eq (car-safe token) 'func) token)
              (t (user-error "Unexpected %s in formula %S"
                             (or token "end") formula))))))
      (prog1 (expr)
        (when tokens (user-error "Unexpected %s in formula %S" (car tokens) formula))))))
#+end_src

**** Formulas: evaluating

- Define =relationship-annotator--index=, which stands in for the SQL queries of the package. It makes two tables from the edges: one from =(SUBJECT . RELATION)= to the objects, and one from =(OBJECT . RELATION)= to the subjects. "How many notes does this claim have supporting it" is then one lookup.
- Define =relationship-annotator--context=, the bundle a formula runs against: the notes, the index, and a cache of results.
- Define a helper that gives the type of a note by id.
- Define =relationship-annotator--resolve-relation=. A term names a relation either by its name (follow the edges from the note) or by its =:inverse= label (follow them backwards), ignoring case. The package keeps a table of the four default relations for this; here the names come from =relationship-annotator-relations=, so a relation you declare works in formulas too.
- Define =relationship-annotator--eval=, which evaluates a tree for one note. A number is itself. A term looks up the related notes in the right table, keeps those of the requested type, and then counts them, or adds up or averages their attribute (an average of none is 0). An operator evaluates both sides and combines them, and a division by zero gives 0.

#+begin_src emacs-lisp
(defun relationship-annotator--index (tree)
  "Return (OUTGOING . INCOMING) tables for the edges of TREE.
OUTGOING maps (SUBJECT . RELATION) to the objects and INCOMING maps
(OBJECT . RELATION) to the subjects."
  (let ((out (make-hash-table :test #'equal))
        (in (make-hash-table :test #'equal)))
    (pcase-dolist (`(,subject ,relation ,object)
                   (relationship-annotator--all-edges tree))
      (push object (gethash (cons subject relation) out))
      (push subject (gethash (cons object relation) in)))
    (cons out in)))

(defun relationship-annotator--context (tree)
  "Return what formulas need to run on TREE."
  (list :notes (plist-get tree :notes)
        :index (relationship-annotator--index tree)
        :cache (make-hash-table :test #'equal)))

(defun relationship-annotator--type-of (id context)
  "Return the node type of note ID, using CONTEXT."
  (relationship-annotator--note-type
   (relationship-annotator--note id (plist-get context :notes))))

(defun relationship-annotator--resolve-relation (name)
  "Return (RELATION . DIRECTION) for NAME, `out' or `in', or nil.
NAME is a relation name, or an :inverse label, ignoring case."
  (let ((name (downcase name)))
    (seq-some
     (pcase-lambda (`(,relation . ,plist))
       (cond ((string= name (downcase (symbol-name relation)))
              (cons relation 'out))
             ((let ((inverse (plist-get plist :inverse)))
                (and inverse (string= name (downcase inverse))))
              (cons relation 'in))))
     relationship-annotator-relations)))

(defun relationship-annotator--eval (tree id context)
  "Evaluate the parse TREE of a formula for note ID, using CONTEXT."
  (pcase tree
    ((pred numberp) tree)
    (`(func ,op ,name ,type ,attribute)
     (pcase-let* ((`(,relation . ,direction)
                   (or (relationship-annotator--resolve-relation name)
                       (user-error "Unknown relation %S in a formula" name)))
                  (index (plist-get context :index))
                  (related (gethash (cons id relation)
                                    (if (eq direction 'out) (car index) (cdr index))))
                  (related (if type
                               (seq-filter
                                (lambda (other)
                                  (eq (relationship-annotator--type-of other context)
                                      type))
                                related)
                             related)))
       (if (eq op 'count)
           (length related)
         (let ((total (apply #'+ (mapcar (lambda (other)
                                           (relationship-annotator--attribute
                                            other attribute context))
                                         related))))
           (if (eq op 'sum)
               total
             (if related (/ total (float (length related))) 0))))))
    (`(,op ,left ,right)
     (let ((a (relationship-annotator--eval left id context))
           (b (relationship-annotator--eval right id context)))
       (pcase op
         ('+ (+ a b)) ('- (- a b)) ('* (* a b))
         ('/ (if (zerop b) 0 (/ (float a) b))))))))

**** Attributes and badges

- Define =relationship-annotator--attribute=, which gives one attribute of one note. It finds the formula in =relationship-annotator-attributes= by the type of the note, and a note whose type has no such attribute gets 0. If the attribute is already being computed, the formula refers to itself, and it stops with a message. Otherwise it looks in the cache, parses and evaluates the formula, and stores the result. The cache tells "not computed" apart from a value of 0, which the package does not.
- Define =relationship-annotator--attributes=, all the attributes of one note as an alist.
- Define a helper that writes a number without a fraction when it is whole.
- Define =relationship-annotator--badge=, the attribute to show after the title, in brackets, such as =[2]=, or nil when the type has none. The package picks a format per attribute name (=[+3/-1]= and so on); here the badge is the plain number, and the name of the attribute is the one set by =:overlay=.

#+begin_src emacs-lisp
(defun relationship-annotator--attribute (id name context)
  "Return attribute NAME of note ID, a number, using CONTEXT.
A note whose type has no such attribute gets 0."
  (let* ((type (relationship-annotator--type-of id context))
         (formula (cdr (assq name (plist-get
                                   (cdr (assq type relationship-annotator-attributes))
                                   :attributes))))
         (key (cons id name))
         (cache (plist-get context :cache)))
    (cond
     ((null formula) 0)
     ((member key relationship-annotator--computing)
      (user-error "The attribute %s of %s refers to itself" name id))
     (t
      (let ((hit (gethash key cache 'none)))
        (if (not (eq hit 'none))
            hit
          (let* ((relationship-annotator--computing
                  (cons key relationship-annotator--computing))
                 (parsed (or (gethash formula cache)
                             (puthash formula
                                      (relationship-annotator--parse-formula formula)
                                      cache))))
            (puthash key (relationship-annotator--eval parsed id context)
                     cache))))))))

(defun relationship-annotator--attributes (id context)
  "Return the attributes of note ID as ((NAME . VALUE) ...), using CONTEXT."
  (let ((type (relationship-annotator--type-of id context)))
    (mapcar (pcase-lambda (`(,name . ,_))
              (cons name (relationship-annotator--attribute id name context)))
            (plist-get (cdr (assq type relationship-annotator-attributes))
                       :attributes))))

(defun relationship-annotator--number (value)
  "Format VALUE without a fraction when it is whole."
  (if (= value (ftruncate (float value)))
      (format "%d" value)
    (format "%.1f" value)))

(defun relationship-annotator--badge (id context)
  "Return the overlay attribute of note ID as \"[N]\", or nil."
  (let* ((type (relationship-annotator--type-of id context))
         (name (plist-get (cdr (assq type relationship-annotator-attributes))
                          :overlay)))
    (when name
      (format "[%s]" (relationship-annotator--number
                      (relationship-annotator--attribute id name context))))))

**** Argument gaps

- Define =relationship-annotator--argument-gaps=, for a claim. It lists the gaps in its argument: =no-support= when no evidence supports it, =no-source= when some does but none of that evidence has a source informing it, and =unanswered-opposition= when opposing evidence is at least as plentiful as supporting evidence.
- Define =relationship-annotator--strength=, how well a claim stands, as one word: =unsupported= with no support, =challenged= with unanswered opposition, =contested= when there is opposition at all, =supported= when there is support, and =unknown= otherwise. The order of the checks is the one of the package.

#+begin_src emacs-lisp
;;;;; Argument gaps

(defun relationship-annotator--argument-gaps (id context)
  "Return the gaps in the argument for claim ID, a list of symbols.
`no-support' means no evidence supports it.  `no-source' means some
does, but none of that evidence has a source informing it.
`unanswered-opposition' means opposing evidence is at least as plentiful
as supporting evidence."
  (let* ((index (plist-get context :index))
         (supporters (gethash (cons id 'supports) (cdr index)))
         (opposers (gethash (cons id 'opposes) (cdr index))))
    (append
     (unless supporters '(no-support))
     (when (and supporters
                (not (seq-some (lambda (evidence)
                                 (gethash (cons evidence 'informs) (cdr index)))
                               supporters)))
       '(no-source))
     (when (and opposers (<= (length supporters) (length opposers)))
       '(unanswered-opposition)))))

(defun relationship-annotator--strength (id context)
  "Return how well claim ID stands, as a symbol.
One of `unsupported', `challenged', `contested', `supported' or
`unknown'."
  (let* ((gaps (relationship-annotator--argument-gaps id context))
         (index (plist-get context :index)))
    (cond ((memq 'no-support gaps) 'unsupported)
          ((memq 'unanswered-opposition gaps) 'challenged)
          ((gethash (cons id 'opposes) (cdr index)) 'contested)
          ((gethash (cons id 'supports) (cdr index)) 'supported)
          (t 'unknown))))

(defun rel-anno-review ()
  "List edges that break the type patterns, gaps in claims, and answers.

with gaps in their argument, and each question with its answers and how
well each stands.  RET on a title visits the note."

                                                 answer context))
                                        'face 'shadow)))))))
          (unless any (insert "  none\n")))

**** Building the page

The page holds the tree cut to =relationship-annotator-embed-depth= levels, so it can recentre on any note in it and cut the part to show by itself.

- Define =relationship-annotator--relation-style=: it reads one setting, such as the label, colour or direction, of a relation from =relationship-annotator-relations=, with a default.
- Define =relationship-annotator--direction-vector=, which turns a direction into a vector =[dx dy]= on the screen. A name becomes an angle (right 0, up 90, left 180, down 270), a number is taken as the angle, and anything else counts as right. The cosine gives =dx= and the sine, negated because the screen's y grows downward, gives =dy=. Both are rounded to three decimals, so the JSON stays short.
- Define =relationship-annotator--relations-json=. It lists the name, label, colour and direction vector of every relation that has a link, so the page can colour the links, fill its legend and place the boxes.
- Define =relationship-annotator--tag-color=. It returns a name and a colour for a note: the first tag of the note that is listed in =relationship-annotator-tag-colors=, together with its colour. When no tag is listed but the note has a type, it returns the type's name and colour instead. Otherwise nothing. Tags win, so you can mark a note by hand; the type colour is the default.
- Define the page function: it takes the tree (already cut to the embed depth), the start id and the depth.
- Reads the notes table, and makes the context the formulas need (see the discourse layer).
- Collect the id of every note in the tree: the start, every parent and child, and both ends of every link. They are sorted, so the page is the same each time.
- Build the nodes. For every id it looks up the note and its colour, and makes an entry with the id, the title, the file path (empty when unknown), the file tags (as a JSON array, empty when there are none), the name that gave the colour, the colour, and the =badge=: the number in brackets that the page writes after the title, or nothing.
- Build the edges: the children table is turned into a list of pairs, and every parent and child pair becomes a two-element vector.
- Build the links: one object with the subject, the object and the relation name for each link, and an =anomaly= field. The field holds the message of =relationship-annotator--anomaly= for the types of the two notes, or nothing. The page draws a warning sign on the label of such a link.
- Collect the root, the depth, the nodes, the edges, the links, the hidden-children counts and the relations into one object. It turns the =:more= table of the cut into pairs of a note id and the number of children the cut left out, so the page can show =+N= on notes at the edge of what it holds.
- The last lines put the encoded data into the template in place of =__DATA__=, after the scripts have been put in place of =__LIBS__=.

(defun relationship-annotator--direction-vector (direction)
  "Return DIRECTION as a unit vector [DX DY] on a screen, where DY grows downward."
  (let ((degrees (pcase direction
                   ('right 0) ('up 90) ('left 180) ('down 270)
                   ((pred numberp) direction)
                   (_ 0))))
    (vector (/ (round (* 1000 (cos (degrees-to-radians degrees)))) 1000.0)
            (/ (round (* -1000 (sin (degrees-to-radians degrees)))) 1000.0))))

  (vconcat
   (mapcar (lambda (relation)
             `((name . ,(symbol-name relation))
               (label . ,(relationship-annotator--relation-style
                          relation :label (symbol-name relation)))

(defun relationship-annotator--tag-color (note)

(defun relationship-annotator--html (tree start depth)
  "Return a self-contained HTML page showing TREE from START to DEPTH.
TREE is already cut to the levels the page holds, see
`relationship-annotator--scope'.  The page can recentre on any note
in it and cut the part to show by itself."
  (let* ((notes (plist-get tree :notes))
         (context (relationship-annotator--context tree))
         (ids (let ((acc (make-hash-table :test #'equal)))
                (puthash start t acc)
                (maphash (lambda (k v)
                           (puthash k t acc)
                           (dolist (kid v) (puthash kid t acc)))
                         (plist-get tree :children))
                (pcase-dolist (`(,subject ,_ ,object) (plist-get tree :links))
                  (puthash subject t acc)
                  (puthash object t acc))
                (sort (hash-table-keys acc) #'string<)))
         (nodes
          (vconcat
           (mapcar
            (lambda (id)
              (let* ((note (relationship-annotator--note id notes))
                     (color (relationship-annotator--tag-color note)))
                `((id . ,id)
                  (title . ,(relationship-annotator--title id notes))
                  (path . ,(and note (vulpea-note-path note)))
                  (tags . ,(vconcat (and note (vulpea-note-tags note))))
                  (colorTag . ,(car color))
                  (color . ,(cdr color))
                  (badge . ,(relationship-annotator--badge id context)))))
            ids)))
         (edges
          (vconcat
           (cl-loop for (parent . kids) in
                    (let (acc)
                      (maphash (lambda (k v) (push (cons k v) acc))
                               (plist-get tree :children))
                      acc)
                    append (mapcar (lambda (kid) (vector parent kid)) kids))))
         (links
          (vconcat
           (mapcar (pcase-lambda (`(,subject ,relation ,object))
                     `((from . ,subject) (to . ,object)
                       (rel . ,(symbol-name relation))
                       (anomaly
                        . ,(relationship-annotator--anomaly
                            (relationship-annotator--type-of subject context)
                            relation
                            (relationship-annotator--type-of object context)))))
                   (plist-get tree :links))))
         (data `((root . ,start)
                 (depth . ,depth)
                 (nodes . ,nodes)
                 (edges . ,edges)
                 (links . ,links)
                 (hidden . ,(let (acc)
                              (maphash (lambda (id count) (push (cons id count) acc))
                                       (plist-get tree :more))
                              acc))
                 (relations . ,(relationship-annotator--relations-json
                                (plist-get tree :links))))))
    (string-replace "__DATA__" (relationship-annotator--json-for-html data)
                    (string-replace "__LIBS__" (relationship-annotator--libraries)
                                    (relationship-annotator--html-template)))))

**** Wrapping and labelling for Graphviz

Graphviz doesn't wrap text, so the module does it before writing the label. The browser page does its own wrapping in JavaScript, because only the browser knows how wide the text is.

- The section comment.
- Define =relationship-annotator--wrap=, which cuts a text into lines of at most =width= characters. It fills a line word by word, starts a new line when the next word wouldn't fit, and cuts a word that is longer than a whole line.
- Define =relationship-annotator--label=, which returns the title followed by the file tags of the note, written as =:tag1:tag2:=. A note without tags, or a missing one, gets just the title.
- Define =relationship-annotator--dot-label=. It wraps that label to =relationship-annotator-wrap-width=, puts a backslash before every double quote and backslash so the text is safe inside a Graphviz string, and joins the lines with the two characters =\n=, which Graphviz reads as a line break.
- Define =relationship-annotator--dot-fill=, the colour attributes of a node. A note with a coloured tag gets that colour with the hex transparency =66= added (1154), about 40%, so it works as a tint. The centre note gets a thicker border (1156), and a light blue fill when it has no coloured tag (1155).

#+begin_src emacs-lisp
;;;; Static SVG export (Graphviz)

(defun relationship-annotator--wrap (text width)
  "Return TEXT as a list of lines no longer than WIDTH, breaking long words."
  (let (lines (line ""))
    (dolist (word (split-string text))
      (while (> (length word) width)
        (when (> (length line) 0) (push line lines) (setq line ""))
        (push (substring word 0 width) lines)
        (setq word (substring word width)))
      (cond ((string-empty-p line) (setq line word))
            ((<= (+ (length line) 1 (length word)) width)
             (setq line (concat line " " word)))
            (t (push line lines) (setq line word))))
    (unless (string-empty-p line) (push line lines))
    (nreverse (or lines (list "")))))

(defun relationship-annotator--label (id notes)
  "Return the title of ID from NOTES followed by its file tags, like :a:b:."
  (let* ((note (relationship-annotator--note id notes))
         (tags (and note (vulpea-note-tags note))))
    (concat (relationship-annotator--title id notes)
            (and tags (format " :%s:" (string-join tags ":"))))))

(defun relationship-annotator--dot-label (id notes)
  "Return the wrapped, escaped Graphviz label text for ID."
  (mapconcat (lambda (line) (replace-regexp-in-string "[\"\\\\]" "\\\\\\&" line))
             (relationship-annotator--wrap (relationship-annotator--label id notes)
                                     relationship-annotator-wrap-width)
             "\\n"))

(defun relationship-annotator--dot-fill (note rootp)
  "Return the Graphviz attributes for the fill of NOTE.
A note with a coloured tag gets that colour as a tint.  The root gets a
thick border, and a blue fill when it has no coloured tag."
  (let ((color (cdr (relationship-annotator--tag-color note))))
    (concat (cond (color (format ", fillcolor=\"%s66\"" color))
                  (rootp ", fillcolor=\"#d8e6f5\""))
            (and rootp ", penwidth=2"))))

**** Graphviz source

This function returns Graphviz (DOT) text for the cut tree.

- Define the function and bind the notes, the children and a =drawn= table, so a note is written once.
- Write the =digraph= header, the layout direction and the default style of nodes and edges.
- Loop over the roots (just the start note) and open a hidden cluster for each.
- Walk the tree breadth first. Each node is written once. Its label comes from =relationship-annotator--dot-label= (1178) and its colours from =relationship-annotator--dot-fill= (1179-1181).
- Closes the cluster.
- Write one edge per parent and child pair.
- Write the links of the other relations. Each is dashed, has the relation's label and colour, and has =constraint=false=, so it doesn't pull the layout out of the tree.
- Close the graph and return the text.

#+begin_src emacs-lisp
(defun relationship-annotator--dot (tree)
  "Return Graphviz source for TREE, one cluster per root."
  (let ((notes (plist-get tree :notes))
        (children (plist-get tree :children))
        (drawn (make-hash-table :test #'equal)))
    (with-temp-buffer
      (insert "digraph vulpea {\n"
              (format "  rankdir=%s;\n" relationship-annotator-rankdir)
              "  node [shape=box, style=\"rounded,filled\", fillcolor=\"#f4f4f4\","
              " fontname=\"Helvetica\"];\n"
              "  edge [color=\"#888888\"];\n")
      (let ((n 0))
        (dolist (root (plist-get tree :roots))
          (insert (format "  subgraph cluster_%d {\n    style=invis;\n" (cl-incf n)))
          (let ((queue (list root)))
            (while queue
              (let ((id (pop queue)))
                (unless (gethash id drawn)
                  (puthash id t drawn)
                  (insert (format "    %S [label=\"%s\"%s];\n"
                                  id (relationship-annotator--dot-label id notes)
                                  (relationship-annotator--dot-fill
                                   (relationship-annotator--note id notes)
                                   (equal id root))))
                  (setq queue (append queue (gethash id children)))))))
          (insert "  }\n")))
      (maphash (lambda (pid kids)
                 (dolist (kid kids)
                   (insert (format "  %S -> %S;\n" pid kid))))
               children)
      (pcase-dolist (`(,subject ,relation ,object) (plist-get tree :links))
        (insert (format "  %S -> %S [constraint=false, style=dashed, label=%S, fontsize=10, color=%S, fontcolor=%S];\n"
                        subject object
                        (relationship-annotator--relation-style

function cut() {
  kids = new Map(); more = new Map(); collapsed.clear(); infoCache.clear();
  const seen = new Set([root]), queue = [[root, 0]];
  while (queue.length) {
    const [id, level] = queue.shift(), ks = allKids.get(id) || [];
    if (level < depth) {
      for (const k of ks) {
        if (!kids.has(id)) kids.set(id, []);
        kids.get(id).push(k);
        if (!seen.has(k)) { seen.add(k); queue.push([k, level + 1]); }
      }
    }
    const h = hidden[id] || 0;
    const beyond = level < depth ? 0 : ks.length;
    if (beyond + h) more.set(id, beyond + h);
  }
}

  const t = n.title.split(/\s+/).filter(Boolean).map(w => ({ text: w, cls: '' }));
  if (n.tags && n.tags.length) t.push({ text: ':' + n.tags.join(':') + ':', cls: 'tags' });

function breakToken(tok) {
  const out = [];
  let rest = tok.text;
  while (measure(rest) > TEXT_W && rest.length > 1) {
    let i = rest.length;
    while (i > 1 && measure(rest.slice(0, i)) > TEXT_W) i--;
    out.push({ text: rest.slice(0, i), cls: tok.cls });
    rest = rest.slice(i);
  }
  out.push({ text: rest, cls: tok.cls });
  return out;
}

function wrap(tokens) {
  const lines = [], space = measure(' ');
  let line = [], width = 0;
  for (const tok0 of tokens) {
    for (const tok of breakToken(tok0)) {
      const w = measure(tok.text);
      if (line.length && width + space + w > TEXT_W) { lines.push(line); line = []; width = 0; }
      width += (line.length ? space : 0) + w;
      line.push(tok);
    }
  }
  if (line.length) lines.push(line);
  return lines;
}

function constraints(ids, level) {
  const before = { x: new Map(), y: new Map() }, out = [];
  const reaches = (axis, from, to) => {
    const seen = new Set(), stack = [from];
    while (stack.length) {
      const n = stack.pop();
      if (n === to) return true;
      if (seen.has(n)) continue;
      seen.add(n);
      stack.push(...(before[axis].get(n) || []));
    }
    return false;
  };
  const add = (axis, first, second, gap) => {
    if (first === second || reaches(axis, second, first)) return;
    if (!before[axis].has(first)) before[axis].set(first, []);
    before[axis].get(first).push(second);
    out.push(axis === 'y' ? { top: first, bottom: second, gap } : { left: first, right: second, gap });
  };
  const gapY = (a, b) => (info(a).h + info(b).h) / 2 + GAPY;
  for (const id of ids) {
    for (const c of childrenOf(id)) if (ids.has(c) && level.get(c) > level.get(id)) add('y', id, c, gapY(id, c));
  }
  for (const l of D.links) {
    if (!ids.has(l.from) || !ids.has(l.to)) continue;
    const [dx, dy] = (relStyle.get(l.rel) || { direction: [1, 0] }).direction;
    if (Math.abs(dx) >= 0.38) {
      if (dx > 0) add('x', l.from, l.to, W + GAPX); else add('x', l.to, l.from, W + GAPX);
    }
    if (Math.abs(dy) >= 0.38) {
      if (dy > 0) add('y', l.from, l.to, gapY(l.from, l.to)); else add('y', l.to, l.from, gapY(l.from, l.to));
    }
  }
  const rows = new Map();
  for (const id of ids) {
    const l = level.get(id);
    if (!rows.has(l)) rows.set(l, []);
    const row = rows.get(l);
    if (!row.some(o => reaches('y', id, o) || reaches('y', o, id))) row.push(id);
  }
  return { relative: out, align: { horizontal: [...rows.values()].filter(r => r.length > 1) } };
}

function separate() {
  const boxes = [...pos.values()];
  for (let pass = 0; pass < 80; pass++) {
    let moved = false;
    for (let i = 0; i < boxes.length; i++) {
      for (let j = i + 1; j < boxes.length; j++) {
        const a = boxes[i], b = boxes[j];
        const ox = Math.min(a.x, b.x) + W - Math.max(a.x, b.x) + GAPX / 2;
        const oy = Math.min(a.y + a.h, b.y + b.h) - Math.max(a.y, b.y) + GAPY / 4;
        if (ox <= 0 || oy <= 0) continue;
        moved = true;
        if (ox <= oy * 2.5) {
          const d = ox / 2 * (a.x <= b.x ? 1 : -1);
          a.x -= d; b.x += d;
        } else {
          const d = oy / 2 * (a.y <= b.y ? 1 : -1);
          a.y -= d; b.y += d;
        }
      }
    }
    if (!moved) break;
  }
}

function border(box, toward) {
  const cx = box.x + W / 2, cy = box.y + box.h / 2, dx = toward.x - cx, dy = toward.y - cy;
  const t = Math.min(dx ? (W / 2) / Math.abs(dx) : Infinity, dy ? (box.h / 2) / Math.abs(dy) : Infinity);
  return { x: cx + dx * t, y: cy + dy * t };
}

function freeSpot(p, q) {
  for (const t of [0.5, 0.4, 0.6, 0.3, 0.7, 0.2, 0.8]) {
    const x = p.x + (q.x - p.x) * t, y = p.y + (q.y - p.y) * t;
    const clear = ![...pos.values()].some(b => x > b.x - 30 && x < b.x + W + 30 && y > b.y - 8 && y < b.y + b.h + 8);
    if (clear) return { x, y };
  }
  return { x: (p.x + q.x) / 2, y: (p.y + q.y) / 2 };
}

*** Layout backend of the browser page: what changed and why

What changed in the page layout:

- Before, the page placed boxes with its own tidy-tree code: depth gave the column, and a parent was centred on its children.
- That can't say "this relation goes to the right of its subject", because a link joins boxes that the tree has already placed.
- Now the page asks the fCoSE layout for the positions.
- It keeps its own SVG drawing: text wrapping, tags, tints, fold markers, links.

| Gained                                                                 | Lost or costs                                                                                            |
|------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------|
| Directions per relation, with diagonals, solved together with the tree | About 560 KB of vendored scripts (=vendor/relationship-annotator/=), pasted into every page              |
| A note with several parents is drawn once, joined to all of them       | Layout is heuristic: a crowded graph breaks some direction rules, and the result is not tidy like a tree |
| Rows of siblings are aligned, and the layout is deterministic          | A layout takes about 0.5 s for 120 boxes and grows quickly above that                                    |
| No dependency on the network; the scripts are MIT licensed             | The scripts must be updated by hand (=vendor/relationship-annotator/README.org=)                         |
| Drawing is unchanged, so wrapping, tags and tints still work           | The SVG export (Graphviz) ignores directions                                                             |

Other backends considered:

- Cytoscape.js with its own renderer: less control over wrapped text and muted tags.
- ELK: layered, but one direction for the whole graph.
- d3-force: smaller, but no hard rules and no rectangles.
- Graphviz in the browser: a static layout that can't take rules.

fCoSE is the only one with built-in relative placement rules.

*** Design considerations

** Live view (from =sp-relationship-annotator-live=)

Literate source for the second custom part, the live browser view for the annotator.

*** Context

The graph used to be a static HTML file: =rel-anno-graph-static= (see [[*Relationship annotator][Relationship annotator]]) writes a self-contained page to =relationship-annotator-html-file= and opens it from disk. The page is a snapshot: after I edit a note or add a =supports= relation, I have to run the command again and open a new file.

This module serves the same page from Emacs on =http://127.0.0.1:8765/=.

- =rel-anno-graph= is now the command that opens it.
- Every page load is rendered fresh from the vulpea database.
- An open page holds one connection to Emacs. Emacs sends a message on it only when the graph that page shows has changed.
- The page then reloads, on the same note and depth. Its zoom, position, folded branches and the note it was recentred on are kept.

**** What "changed" means, without polling

Nothing asks Emacs on a timer. Three steps, each driven by an event:

1. *The database file changes.* Emacs watches the folder of =vulpea-db-location= with =file-notify= (inotify, kqueue or fsevents, whichever the system has) and only looks at the database and its =-wal= file. =vulpea-db-autosync-mode= writes there when a note is saved. The watch records the size and modification time it saw last, so an event that changed nothing (a read) is ignored.
2. *Emacs waits until it is idle.* The check is an idle timer of =relationship-annotator-live-debounce= seconds, restarted by each new event. A burst of writes, such as a sync of many files, costs one check, and a check never runs while I am typing.
3. *The graph data is compared.* For each open page Emacs cuts the tree the way the page was cut, serialises the data the page would be given, and compares its SHA-1 with the one the page was rendered from. Only a different hash sends a message. Editing a note that is not in the graph, or its body text, changes the file but not the data, so no page reloads.

The full tree is built once per check, and every open page cuts its own part from it.

**** Why a small server of its own

- The config already has =simple-httpd= (in =sp-base-libraries=) and =websocket= (used by =vulpea-graph=). =simple-httpd= is one global server with its root at =/var/www=, which other things may start or stop, and its default is to listen on every interface. Serving my notes needs a server that is certainly bound to loopback and that nothing else touches.
- It needs about a hundred and fifty lines with =make-network-process=, adds no dependency, and can be tested without installing any package.
- A page load is one short request (=Connection: close=). The push channel is a /Server-Sent Events/ stream: a plain HTTP response that stays open, which the browser reads with =EventSource=. It only goes from Emacs to the page, which is all that is needed, and the browser reconnects by itself if Emacs restarts. A websocket would need a handshake and frame encoding for no gain.

**** On =vulpea-graph=

Analysis of =vulpea-graph= (the =vulpea-retrieve= package in =~/cloned-scan-ai=):

- It has no rendering code to reuse: it computes metrics in Python and shows lists in Emacs.
- The only idea taken from it is its neighbour lookup, a breadth-first walk from a note. That is already done here by =relationship-annotator--scope=.
- The drawing stays the existing page (cytoscape's fCoSE layout in SVG).
- I did not read =vulpea-graph-ui=, which this module installs and which does use =websocket= and =simple-httpd=. So I cannot say how it draws or pushes.

**** What it protects against

- It listens on =127.0.0.1= only. The host is a constant, not an option.
- It answers =GET= only, and it refuses any request whose =Host= header is not =127.0.0.1=, =localhost= or =[::1]= with the right port. That stops a web page on another site from reaching the server through a rebinding trick.
- It runs inside Emacs, so building a page or a check blocks Emacs while the tree is built.

**** Pages and data

- =--tree= cuts the tree the way the static command does: down to the larger of the depth and the embed depth. It uses =--full-tree= when a check has already built it.
- =--json= asks =relationship-annotator--html= with the template and the scripts replaced, so that what comes back is the data alone: root, depth, nodes, edges, links, hidden and relations. =cl-letf= is local to the call. It is the page's data exactly, so it is what is compared.
- =--hash= is a short SHA-1 of that JSON. A page is rendered from one hash, and a later check compares against it.
- =--script= goes at the end of every page. It opens the event stream with the hash the page was rendered from. On a =changed= message it saves the note it is centred on, the depth, the pan and zoom and the folded branches in =sessionStorage=, and goes to the address of the page it started as. The new page reads that state back, recentres on the same note and draws the same view. =root=, =depth=, =view=, =collapsed=, =recentre=, =render= and =apply= are the page's own names. While the stream is down the title says so; the browser reconnects by itself and Emacs then compares hashes, so a change made meanwhile is not lost.
- =--page= renders the page with =relationship-annotator--html= and puts the script before the last =</body>=.

#+begin_src emacs-lisp
(defun relationship-annotator-live--tree (start depth)
  "Return the tree below START, cut like `rel-anno-graph-static' does."
  (relationship-annotator--scope
   (or relationship-annotator-live--full-tree (relationship-annotator--build))
   start (max depth relationship-annotator-embed-depth)))

(defun relationship-annotator-live--json (tree start depth)
  "Return the data of the page for TREE, START and DEPTH, as a JSON string."
  (cl-letf (((symbol-function 'relationship-annotator--html-template)
             (lambda () "__DATA__"))
            ((symbol-function 'relationship-annotator--libraries)
             (lambda () "")))
    (relationship-annotator--html tree start depth)))

(defun relationship-annotator-live--hash (json)
  "Return a short token for JSON."
  (substring (secure-hash 'sha1 json) 0 12))

(defun relationship-annotator-live--script (start depth hash)
  "Return the script that follows the data of START and DEPTH, rendered as HASH."
  (format "<script>
(() => {
  const startRoot = %s, startDepth = %d, hash = %s, base = document.title;
  const key = 'rel-anno-live';
  try {
    const saved = JSON.parse(sessionStorage.getItem(key) || 'null');
    sessionStorage.removeItem(key);
    if (saved && byId.has(saved.root)) {
      if (saved.root !== root || saved.depth !== depth) recentre(saved.root, saved.depth, false);
      saved.collapsed.forEach(id => collapsed.add(id));
      render(false);
      Object.assign(view, saved.view);
      apply();
    }
  } catch (e) {}
  const events = new EventSource('/events?root=' + encodeURIComponent(startRoot)
                                 + '&depth=' + startDepth + '&since=' + hash);
  events.onopen = () => { document.title = base; };
  events.onerror = () => { document.title = base + ' (offline)'; };
  events.addEventListener('changed', () => {
    try {
      sessionStorage.setItem(key, JSON.stringify(
        { root, depth, view, collapsed: [...collapsed] }));
    } catch (e) {}
    location.replace('/?root=' + encodeURIComponent(startRoot) + '&depth=' + startDepth);
  });
})();
</script>
"
          (json-encode-string start) depth (json-encode-string hash)))

(defun relationship-annotator-live--page (start depth)
  "Return the page for START and DEPTH, with the script that follows the database."
  (let* ((tree (relationship-annotator-live--tree start depth))
         (html (relationship-annotator--html tree start depth))
         (script (relationship-annotator-live--script
                  start depth
                  (relationship-annotator-live--hash
                   (relationship-annotator-live--json tree start depth))))
         (end (string-match-p "</body>\\s-*</html>\\s-*\\'" html)))
    (if end
        (concat (substring html 0 end) script (substring html end))
      (concat html script))))
#+end_src

**** Event streams

- =--notify= sends one =changed= message on a connection.
- =--check-client= compares the hash of the data the connection's page would get now with the hash it was last given, and sends =changed= only when they differ. A build that fails counts as a change, so the page reloads and shows the error. With FORCE it always sends.
- =--check-all= does that for every open connection, building the full tree once. Dead connections are dropped first, and nothing is built when none is open.

#+begin_src emacs-lisp
(defun relationship-annotator-live--notify (process hash)
  "Tell the page on PROCESS that its data changed, and remember HASH for it."
  (process-put process :hash hash)
  (process-send-string process "event: changed\ndata: reload\n\n"))

(defun relationship-annotator-live--check-client (process &optional force)
  "Send `changed' on PROCESS when its page is out of date, or always with FORCE."
  (let ((hash (condition-case nil
                  (let ((root (process-get process :root))
                        (depth (process-get process :depth)))
                    (relationship-annotator-live--hash
                     (relationship-annotator-live--json
                      (relationship-annotator-live--tree root depth) root depth)))
                (error "error"))))
    (when (or force (not (equal hash (process-get process :hash))))
      (relationship-annotator-live--notify process hash))))

(defun relationship-annotator-live--check-all (&optional force)
  "Check every open page, building the tree once.  With FORCE, reload them all."
  (setq relationship-annotator-live--timer nil
        relationship-annotator-live--clients
        (seq-filter #'process-live-p relationship-annotator-live--clients))
  (when relationship-annotator-live--clients
    (let ((relationship-annotator-live--full-tree
           (ignore-errors (relationship-annotator--build))))
      (dolist (process relationship-annotator-live--clients)
        (relationship-annotator-live--check-client process force)))))
#+end_src

**** Watching the database

- =--files= lists the database file and its write-ahead log. =--signature= is the modification time and size of those that exist.
- =--on-file-change= receives every =file-notify= event of the folder. It ignores other files, such as the =-shm= file that readers touch, and events after which the signature is the one already seen. Otherwise it restarts the idle timer.
- =--watch-start= and =--watch-stop= add and remove the watch. A system without file notification gets a message, and =rel-anno-live-refresh= remains.

#+begin_src emacs-lisp
(defun relationship-annotator-live--files ()
  "Return the vulpea database file and its write-ahead log."
  (when-let* ((db (and (boundp 'vulpea-db-location) vulpea-db-location)))
    (list (expand-file-name db) (concat (expand-file-name db) "-wal"))))

(defun relationship-annotator-live--signature ()
  "Return the modification time and size of the database files."
  (mapcar (lambda (file)
            (when-let* ((attributes (file-attributes file)))
              (list (file-attribute-modification-time attributes)
                    (file-attribute-size attributes))))
          (relationship-annotator-live--files)))

(defun relationship-annotator-live--on-file-change (event)
  "React to a `file-notify' EVENT when it changed a database file."
  (let ((file (nth 2 event)))
    (when (and file
               (member (expand-file-name file) (relationship-annotator-live--files))
               (not (equal (relationship-annotator-live--signature)
                           relationship-annotator-live--seen)))
      (setq relationship-annotator-live--seen (relationship-annotator-live--signature))
      (when (timerp relationship-annotator-live--timer)
        (cancel-timer relationship-annotator-live--timer))
      (setq relationship-annotator-live--timer
            (run-with-idle-timer relationship-annotator-live-debounce nil
                                 #'relationship-annotator-live--check-all)))))

(defun relationship-annotator-live--watch-start ()
  "Watch the folder of the vulpea database for changes."
  (when-let* ((file (car (relationship-annotator-live--files)))
              ((file-directory-p (file-name-directory file)))
              ((not relationship-annotator-live--watch)))
    (setq relationship-annotator-live--seen (relationship-annotator-live--signature))
    (condition-case err
        (setq relationship-annotator-live--watch
              (file-notify-add-watch (file-name-directory file) '(change)
                                     #'relationship-annotator-live--on-file-change))
      (error (message "Live graph: cannot watch the database (%s); use rel-anno-live-refresh"
                      (error-message-string err))))))

(defun relationship-annotator-live--watch-stop ()
  "Stop watching the database."
  (when relationship-annotator-live--watch
    (ignore-errors (file-notify-rm-watch relationship-annotator-live--watch))
    (setq relationship-annotator-live--watch nil))
  (when (timerp relationship-annotator-live--timer)
    (cancel-timer relationship-annotator-live--timer))
  (setq relationship-annotator-live--timer nil))
#+end_src

**** Answering a request

- =--respond= builds the status line and headers by hand, encodes the body as UTF-8, sends it, and closes the connection. =Cache-Control: no-store= keeps the browser from showing an old page.
- =--host-ok= accepts only the three names of the local machine, with this server's port or none.
- =--params= reads =root= and =depth= from the query, falling back to the last start note. The depth is kept between 1 and 20.
- =--subscribe= answers =/events= with a stream header and keeps the connection open. It remembers the note, depth and hash the page was rendered from, and checks at once, so a change made while the page was disconnected is caught.
- =--route= answers the other paths. =/= and =/graph.json= take the note and depth from =--params=. A root that is not in the database gets a 404. The browser's request for =/favicon.ico= gets an empty 204 so that it doesn't show as an error. Anything else is a 404.
- =--handle= reads the request line and the headers, refuses other methods (405) and other hosts (403), and turns an error in a route into a 500 with the message, which only the local machine can read.

#+begin_src emacs-lisp
(defun relationship-annotator-live--respond (process status type body)
  "Send BODY with STATUS and content TYPE on PROCESS, then close it."
  (let ((bytes (encode-coding-string body 'utf-8)))
    (process-send-string
     process
     (concat
      (encode-coding-string
       (format (concat "HTTP/1.1 %s\r\nContent-Type: %s; charset=utf-8\r\n"
                       "Content-Length: %d\r\nCache-Control: no-store\r\n"
                       "Connection: close\r\n\r\n")
               status type (length bytes))
       'utf-8)
      bytes))
    (delete-process process)))

(defun relationship-annotator-live--host-ok (host)
  "Non-nil when the Host header HOST names this machine and this port."
  (and host
       (string-match "\\`\\(localhost\\|127\\.0\\.0\\.1\\|\\[::1\\]\\)\\(?::\\([0-9]+\\)\\)?\\'" host)
       (let ((port (match-string 2 host)))
         (or (null port)
             (= (string-to-number port) relationship-annotator-live-port)))))

(defun relationship-annotator-live--params (query)
  "Return (ROOT . DEPTH) from the parsed QUERY, or from the last start note."
  (cons (or (cadr (assoc "root" query)) relationship-annotator-live--root)
        (max 1 (min 20 (or (and (cadr (assoc "depth" query))
                                (string-to-number (cadr (assoc "depth" query))))
                           relationship-annotator-live--depth
                           relationship-annotator-default-depth)))))

(defun relationship-annotator-live--subscribe (process query)
  "Keep PROCESS open as an event stream for the page described by QUERY."
  (pcase-let ((`(,root . ,depth) (relationship-annotator-live--params query)))
    (process-send-string
     process (concat "HTTP/1.1 200 OK\r\nContent-Type: text/event-stream\r\n"
                     "Cache-Control: no-store\r\nConnection: keep-alive\r\n\r\n"
                     "retry: 3000\n\n"))
    (process-put process :root root)
    (process-put process :depth depth)
    (process-put process :hash (cadr (assoc "since" query)))
    (push process relationship-annotator-live--clients)
    (relationship-annotator-live--check-client process)))

(defun relationship-annotator-live--route (path query)
  "Return (STATUS TYPE BODY) for PATH and the parsed QUERY."
  (pcase-let ((`(,root . ,depth) (relationship-annotator-live--params query)))
    (cond
     ((equal path "/favicon.ico")
      (list "204 No Content" "text/plain" ""))
     ((not (member path '("/" "/graph.json")))
      (list "404 Not Found" "text/plain" "Not found"))
     ((null root)
      (list "200 OK" "text/plain"
            "Run M-x rel-anno-graph in Emacs to pick a note."))
     ((not (vulpea-db-query-by-ids (list root)))
      (list "404 Not Found" "text/plain" (format "No note with id %s" root)))
     ((equal path "/graph.json")
      (list "200 OK" "application/json"
            (relationship-annotator-live--json
             (relationship-annotator-live--tree root depth) root depth)))
     (t
      (list "200 OK" "text/html" (relationship-annotator-live--page root depth))))))

(defun relationship-annotator-live--handle (process request)
  "Answer REQUEST, the text of a request head, on PROCESS."
  (let* ((lines (split-string request "\r\n"))
         (first (split-string (car lines) " "))
         (method (nth 0 first))
         (target (or (nth 1 first) ""))
         (host (cl-some (lambda (line)
                          (when (string-match "\\`[Hh]ost:[ \t]*\\(.*?\\)[ \t]*\\'" line)
                            (match-string 1 line)))
                        (cdr lines)))
         (parts (split-string target "?"))
         (query (url-parse-query-string (or (cadr parts) ""))))
    (cond
     ((not (equal method "GET"))
      (relationship-annotator-live--respond
       process "405 Method Not Allowed" "text/plain" "GET only"))
     ((not (relationship-annotator-live--host-ok host))
      (relationship-annotator-live--respond
       process "403 Forbidden" "text/plain" "Forbidden"))
     ((equal (car parts) "/events")
      (relationship-annotator-live--subscribe process query))
     (t
      (condition-case err
          (apply #'relationship-annotator-live--respond process
                 (relationship-annotator-live--route (car parts) query))
        (error
         (relationship-annotator-live--respond
          process "500 Internal Server Error" "text/plain"
          (error-message-string err))))))))
#+end_src

**** The server process

- =--filter= collects the bytes of a connection until the blank line that ends the head, then handles it. A head larger than 16 KB is dropped.
- =--sentinel= takes a closed connection out of the list of event streams.
- =-start= opens the listening socket on the loopback address only, with no query on exit, starts the watch on the database, and tells where the page is.
- =-stop= closes the socket, the watch and every open stream. A port that is already in use is reported as an error.

#+begin_src emacs-lisp
(defun relationship-annotator-live--filter (process string)
  "Collect STRING from PROCESS until the request head is complete, then answer."
  (let ((data (concat (or (process-get process :data) "") string)))
    (process-put process :data data)
    (cond
     ((process-get process :root))
     ((string-search "\r\n\r\n" data)
      (process-put process :data nil)
      (relationship-annotator-live--handle process data))
     ((> (length data) 16384)
      (delete-process process)))))

(defun relationship-annotator-live--sentinel (process _event)
  "Forget PROCESS as an event stream once it is closed."
  (unless (process-live-p process)
    (setq relationship-annotator-live--clients
          (delq process relationship-annotator-live--clients))))

** Force-directed graph (=rel-anno-fa2=)

A third view of the same scope as the browser graph, drawn in an Emacs buffer by =graph-fa2=. It reuses =relationship-annotator--read-scope= (starting note and depth), =relationship-annotator--build= and =relationship-annotator--scope=, so it shows the same notes as the browser page, and the depth you give still cuts the tree.

- *Depth*: each node's radius follows its level below the starting note (=relationship-annotator-fa2-radius=, root 18, 3 less per level, never below 7), so the start is largest and deeper notes shrink. A node at the last level shows =(+N)= for the children it hides. With the 3d engine the layout also has its own perspective depth.
- *Labels*: the title, then the tags as =#tag=.
- *Colours*: the group (=sp-org-tag-group-of=, =sp-org-tag-groups-colors=) of the first tag that has a group gives a Notion colour name; =relationship-annotator-fa2-group-faces= maps that name to a face, and the node takes the foreground of that face in the theme in use (=warning= for orange, =success= for green, =shadow= for gray, ...). Text, edge labels and edges follow the theme's =default= and =shadow= faces, so the graph follows =load-theme= each time the command runs. Untagged notes use the theme's foreground.
- *Room*: graph-fa2 lays nodes out without knowing the label sizes, so the nodes are drawn =relationship-annotator-fa2-spread= (4) times farther apart on a canvas that many times larger. The labels keep their size, so zoom in to read. Two pieces of advice do it (=graph-fa2-normalise-coords= and its inverse, so dragging and clicking still match). In a headless test of the layout, 12 to 60 boxes overlapped in 6 to 33 pairs at spread 1 and in none at spread 4.
- *Boxes*: after each frame is written, a rounded box in the node's colour at 75% opacity (=relationship-annotator-fa2-box-opacity=) is put behind the label, and the text takes the theme's foreground or background, whichever contrasts. This post-processes graph-fa2's SVG text (advice on =graph-fa2--render-svg=), so a change in how the package writes labels could stop it; the graph then shows without boxes.
- *Links*: parent links read "parent", the others read their relation label (=supports=, =opposes=, ...) in the colour set in =relationship-annotator-relations=; all are arrows.
- Clicking a node visits its note.
- Tested in a headless Emacs 29 (layout, SVG output and overlap counts). Not seen on screen: the colours on your themes, the zoom level and the click.

#+begin_src emacs-lisp
;;;; Force-directed graph in a buffer

(defcustom relationship-annotator-fa2-radius '(18 . 7)
  "Node radius as (ROOT . MINIMUM): the starting note gets ROOT, each level 3 less, never below MINIMUM."
  :type '(cons integer integer)
  :group 'spcustom)

(defun relationship-annotator-fa2--levels (scope start)
  "Return a hash table from id to its level below START in SCOPE."
  (let ((levels (make-hash-table :test #'equal))
        (queue (list start)))
    (puthash start 0 levels)
    (while queue
      (let ((id (pop queue)))
        (dolist (kid (gethash id (plist-get scope :children)))
          (unless (gethash kid levels)
            (puthash kid (1+ (gethash id levels)) levels)
            (setq queue (append queue (list kid)))))))
    levels))

;; Colours come from the theme in use, not from the palette of
;; `sp-org-tag-groups': each group's Notion colour name is looked up here
;; and read from the foreground of the face, so the graph follows
;; `load-theme'.
(defcustom relationship-annotator-fa2-group-faces
  '((default . default) (gray . shadow) (brown . font-lock-variable-name-face)
    (orange . warning) (yellow . font-lock-type-face) (green . success)
    (blue . font-lock-function-name-face) (purple . font-lock-keyword-face)
    (pink . font-lock-string-face) (red . error))
  "Face whose foreground colours the nodes of a tag group, by its colour name.
The names are those of `sp-org-tag-groups-colors'."
  :type '(alist :key-type symbol :value-type face)
  :group 'spcustom)

(defcustom relationship-annotator-fa2-spread 4.0
  "How many times farther apart than the layout puts them the nodes are drawn.
The labels keep their size, so a larger value leaves more room between
them; the whole graph is drawn on a canvas this many times larger, so
zoom in to read it."
  :type 'number
  :group 'spcustom)

(defcustom relationship-annotator-fa2-box-opacity 0.75

  :type 'number
  :group 'spcustom)

(defvar relationship-annotator-fa2--active nil

(defun relationship-annotator-fa2--hex (colour &optional fallback)
  "COLOUR, a name or hex string, as \"#rrggbb\"; FALLBACK when it is not a colour."
  (if-let* ((values (and (stringp colour)
                         (not (member colour '("unspecified" "unspecified-fg" "unspecified-bg")))
                         (color-values colour))))
      (apply #'format "#%02x%02x%02x" (mapcar (lambda (v) (ash v -8)) values))
    fallback))

(defun relationship-annotator-fa2--face-colour (face)
  "Foreground of FACE in the current theme as hex, or nil."
  (relationship-annotator-fa2--hex (face-foreground face nil t)))

(defun relationship-annotator-fa2--theme-colour (kind)
  "The theme's `fg' or `bg' as hex."
  (if (eq kind 'fg)
      (relationship-annotator-fa2--hex (face-foreground 'default nil t) "#d4d4d4")
    (relationship-annotator-fa2--hex (face-background 'default nil t) "#1e1e2e")))

(defun relationship-annotator-fa2--luminance (hex)
  "Relative luminance of HEX, from 0 to 1."
  (pcase-let ((`(,r ,g ,b) (color-name-to-rgb hex)))
    (+ (* 0.2126 r) (* 0.7152 g) (* 0.0722 b))))

(defun relationship-annotator-fa2--contrast (fill)
  "The theme's foreground or background, whichever reads better on FILL."
  (let ((fg (relationship-annotator-fa2--theme-colour 'fg))
        (bg (relationship-annotator-fa2--theme-colour 'bg)))
    (if (> (abs (- (relationship-annotator-fa2--luminance fill)
                   (relationship-annotator-fa2--luminance fg)))
           (abs (- (relationship-annotator-fa2--luminance fill)
                   (relationship-annotator-fa2--luminance bg))))
        fg bg)))

(defun relationship-annotator-fa2--colour (note)
  "Fill colour of NOTE: the theme colour of the group of its first grouped tag."
  (let* ((group (seq-some (lambda (tag) (car (sp-org-tag-group-of tag)))
                          (and note (vulpea-note-tags note))))
         (name (or (cdr (assoc group sp-org-tag-groups-colors)) 'default)))
    (or (relationship-annotator-fa2--face-colour
         (or (cdr (assq name relationship-annotator-fa2-group-faces)) 'default))
        (relationship-annotator-fa2--theme-colour 'fg))))

(defun relationship-annotator-fa2--nodes (scope start)
  "Return the graph-fa2 nodes for SCOPE: title and tags as label, tag-group colour, size by level."
  (let ((notes (plist-get scope :notes))
        (levels (relationship-annotator-fa2--levels scope start)))
    (mapcar
     (lambda (id)
       (let* ((note (relationship-annotator--note id notes))
              (hidden (gethash id (plist-get scope :more)))
              (tags (and note (mapcar (lambda (tag) (concat "#" tag))
                                      (vulpea-note-tags note)))))
         (list :id id
               :label (string-join
                       (delq nil (list (relationship-annotator--title id notes)
                                       (and tags (string-join tags " "))
                                       (and hidden (format "(+%d)" hidden))))
                       " ")
               :colour (relationship-annotator-fa2--colour note)
               :radius (float (max (cdr relationship-annotator-fa2-radius)
                                   (- (car relationship-annotator-fa2-radius)
                                      (* 3 (gethash id levels 0))))))))
     (plist-get scope :nodes))))

(defun relationship-annotator-fa2--edges (scope)
  "Return the graph-fa2 edges for SCOPE, each labelled with its relation."
  (let (edges)
    (maphash
     (lambda (parent kids)
       (dolist (kid kids)
         (push (list :from parent :to kid :directed t
                     :label (relationship-annotator--relation-style 'parent :label "parent")
                     :colour (relationship-annotator--relation-style 'parent :color "#888888"))
               edges)))
     (plist-get scope :children))
    (pcase-dolist (`(,subject ,relation ,object) (plist-get scope :links))
      (push (list :from subject :to object :directed t
                  :label (relationship-annotator--relation-style
                          relation :label (symbol-name relation))
                  :colour (relationship-annotator--relation-style relation :color "#888888"))
            edges))
    (nreverse edges)))

;;;; Boxes behind labels, and room between nodes
;; graph-fa2 draws a label as bare text and lays the nodes out in a space
;; that doesn't know how big the labels are.  Two pieces of advice fix
;; that for `rel-anno-fa2' without changing the package: the nodes are
;; spread by `relationship-annotator-fa2-spread', and after each frame is
;; written a box is put behind every node label.

(defun relationship-annotator-fa2--spread-args (args)
  "Scale the X and Y of ARGS, the arguments of `graph-fa2-normalise-coords'."
  (if relationship-annotator-fa2--active
      (pcase-let ((`(,x ,y ,z) args))
        (list (* x relationship-annotator-fa2-spread)
              (* y relationship-annotator-fa2-spread) z))
    args))

(defun relationship-annotator-fa2--unspread (coords)
  "Undo the spread on COORDS, the result of `graph-fa2-denormalise-coords'."
  (if (and relationship-annotator-fa2--active coords)
      (pcase-let ((`(,x ,y ,z) coords))
        (list (truncate (/ x relationship-annotator-fa2-spread))
              (truncate (/ y relationship-annotator-fa2-spread)) z))
    coords))

(defconst relationship-annotator-fa2--label-regexp
  (concat "  <circle [^>]*fill=\"\\(#[0-9a-fA-F]+\\)\"[^>]*/>\n"
          "  <text fill=\"[^\"]*\" font-size=\"\\([0-9.]+\\)\"")
  "A node circle followed by its label text; group 1 is the fill, 2 the size.")

(defun relationship-annotator-fa2--box-labels (start end)
  "Put a box behind each node label between START and END, and recolour the text."
  (let ((end (copy-marker end))
        (bg (relationship-annotator-fa2--theme-colour 'bg)))
    (save-excursion
      (goto-char start)
      ;; Edge labels have a fixed dark outline; follow the theme instead.
      (while (search-forward "stroke=\"#1e1e2e\"" end t)
        (replace-match (format "stroke=\"%s\"" bg) t t))
      (goto-char start)
      (while (re-search-forward relationship-annotator-fa2--label-regexp end t)
        (let* ((fill (match-string 1))
               (size (string-to-number (match-string 2)))
               (text-start (save-excursion (goto-char (match-end 0))
                                           (line-beginning-position)))
               (text-end (save-excursion (search-forward "</text>" end t) (point)))
               (lines nil) (x 0.0) (top nil) (bottom nil))
          (save-excursion
            (goto-char text-start)
            (while (re-search-forward
                    "<tspan x=\"\\([-0-9.]+\\)\" y=\"\\([-0-9.]+\\)\">\\([^<]*\\)</tspan>"
                    text-end t)
              (setq x (string-to-number (match-string 1)))
              (let ((y (string-to-number (match-string 2))))
                (setq top (min (or top y) y) bottom (max (or bottom y) y)))
              (push (length (match-string 3)) lines)))
          (when lines
            (let* ((width (+ 8 (* 0.6 size (apply #'max lines))))
                   (rect (format "  <rect x=\"%.2f\" y=\"%.2f\" width=\"%.2f\" height=\"%.2f\" rx=\"4\" fill=\"%s\" fill-opacity=\"%.2f\" />\n"
                                 (- x (/ width 2)) (- top size) width
                                 (+ 6 size (- bottom top)) fill
                                 relationship-annotator-fa2-box-opacity)))
              (goto-char text-start)
              (insert rect)
              (when (re-search-forward "<text fill=\"[^\"]*\"" end t)
                (replace-match (format "<text fill=\"%s\""
                                       (relationship-annotator-fa2--contrast fill))
                               t t))
              (goto-char (search-forward "</text>" end t)))))))))

(defun relationship-annotator-fa2--render-advice (original ctx len)
  "Call ORIGINAL on CTX and LEN, then box the labels it wrote."
  (let ((start (point-marker)))
    (prog1 (funcall original ctx len)
      (when relationship-annotator-fa2--active
        (relationship-annotator-fa2--box-labels start (point))))))

(defun rel-anno-fa2 ()
  "Ask for a starting note and depth, then show a force-directed graph in a buffer.
Nodes carry the title and tags in a box and are coloured by tag group in the colours of the theme; links carry
the relation.  Clicking a node visits its note."
  (interactive)
  (require 'graph-fa2)
  (pcase-let* ((`(,start . ,depth) (relationship-annotator--read-scope))
               (tree (relationship-annotator--build))
               (scope (relationship-annotator--scope tree start depth))
               (buffer (get-buffer-create "*rel-anno-fa2*")))
    (setq relationship-annotator-fa2--active t
          graph-fa2-canvas-size (* 500.0 relationship-annotator-fa2-spread)
          graph-fa2-label-colour (relationship-annotator-fa2--theme-colour 'fg)
          graph-fa2-edge-label-colour (relationship-annotator-fa2--theme-colour 'fg)
          graph-fa2-edge-colour (or (relationship-annotator-fa2--face-colour 'shadow)
                                    graph-fa2-edge-colour))
    ;; The cache is keyed on the nodes and edges, not on these settings.
    (graph-fa2-clear-cache)
    (with-current-buffer buffer
      (graph-fa2-mode 1)
      (add-hook 'graph-fa2-node-clicked-functions
                (lambda (id) (relationship-annotator--visit id tree))
                nil t))
    (graph-fa2-start buffer
                     (relationship-annotator-fa2--nodes scope start)
                     (relationship-annotator-fa2--edges scope))
    (pop-to-buffer buffer)))
