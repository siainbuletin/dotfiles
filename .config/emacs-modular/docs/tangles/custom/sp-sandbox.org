The =:tangle= path in the =#+PROPERTY= line at the top of this file says where they are written; see [[file:../../../README.org::*Tangling the literate files][Tangling the literate files]] in the README for how to tangle.

This module puts the fish function =emacs-pr= (=~/.config/fish/functions/emacs-pr.fish=, described in [[file:../../../README.org::*Testing a pull request in a sandbox][Testing a pull request in a sandbox]]) behind =M-x= commands, so a sandbox can be started from the Emacs I already work in. The sandbox is a separate Emacs process, so the live one is untouched and keeps running. The commands run fish in a process of their own and show its output in =*emacs-pr*=; fish and =emacs= must be on Emacs's =exec-path=, which =sp-env= arranges on macOS.

It has no dependencies and is loaded after =sp-org-issues= in the module list of =init.el=.

#+end_quote

* Settings

The group, and the shell that has =emacs-pr= defined.

#+begin_src emacs-lisp -i
(defgroup sp-sandbox nil
  "Run pull requests of the dotfiles in a sandboxed Emacs."
  :group 'tools)

(defcustom sp-sandbox-shell "fish"
  "Shell that has the `emacs-pr' function defined."
  :type 'string
  :group 'sp-sandbox)
#+end_src

* Running the function

=sp-sandbox--run= quotes its arguments, runs =fish -c "emacs-pr ..."= and shows the output buffer. The function itself starts the sandbox in the background and returns, so the process ends quickly.

#+begin_src emacs-lisp -i
(defun sp-sandbox--run (&rest args)
  "Run `emacs-pr' with ARGS in a fish process and show its output."
  (let ((buffer (get-buffer-create "*emacs-pr*")))
    (with-current-buffer buffer
      (let ((inhibit-read-only t)) (erase-buffer)))
    (make-process
     :name "emacs-pr"
     :buffer buffer
     :command (list sp-sandbox-shell "-c"
                    (mapconcat #'shell-quote-argument (cons "emacs-pr" args) " "))
     :noquery t)
    (display-buffer buffer)))

(defun sp-sandbox--number-at-point ()
  "Pull request number near point (as in #22 or a bare 22), or nil."
  (or (thing-at-point 'number)
      (save-excursion
        (skip-chars-backward "0-9")
        (and (eq (char-before) ?#) (thing-at-point 'number)))))
#+end_src

* Commands

** Start a sandbox

The number defaults to the one at point, written either as =22= or =#22=, so the command can be run on a PR mentioned in a note or in the changelog.

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-sandbox-pr (number)
  "Fetch pull request NUMBER and start a sandboxed Emacs on it.
Running it again for the same number updates the sandbox to the latest commit."
  (interactive (list (read-number "Pull request number: "
                                  (sp-sandbox--number-at-point))))
  (sp-sandbox--run (number-to-string number)))
#+end_src

** Remove, reset and reseed

#+begin_src emacs-lisp -i
;;;###autoload
(defun sp-sandbox-remove (number)
  "Remove the sandbox of pull request NUMBER: worktree, packages and notes copy."
  (interactive (list (read-number "Remove the sandbox of pull request: "
                                  (sp-sandbox--number-at-point))))
  (when (y-or-n-p (format "Remove the sandbox of PR #%d? " number))
    (sp-sandbox--run "rm" (number-to-string number))))

;;;###autoload
(defun sp-sandbox-reset-notes (number)
  "Give the sandbox of pull request NUMBER a fresh copy of ~/notes next time."
  (interactive (list (read-number "Reset the notes of pull request: "
                                  (sp-sandbox--number-at-point))))
  (sp-sandbox--run "reset" (number-to-string number)))

;;;###autoload
(defun sp-sandbox-reseed ()
  "Drop the package seed, so the next sandbox clones the live packages again."
  (interactive)
  (sp-sandbox--run "reseed"))
#+end_src
