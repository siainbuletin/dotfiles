* Parent/child views of vulpea notes

** Context

My notes follow a Zettelkasten pattern. One file is one idea. A sub-note records its parents with a =- parents :: [[id:…][Title]]= line in its zeroth section, and vulpea stores that as metadata. A note can have several parents: either one link after another on the same line, separated by commas, or one =- parents ::= line per parent. =vulpea-graph= doesn't draw this hierarchy (it analyses links for retrieval and shows lists), so this module reads the =parents= metadata and builds the tree itself.

Besides =parents=, a note can relate to other notes in other ways: =supports=, =opposes=, =informs=, =answers=, or any relation you declare in =vulpea-hierarchy-relations=. Each relation lists the places it is read from: a metadata key on the note, the inverse of a key on the other note (=children= for =parents=), or a file property such as =DG_SUPPORTS=, which is how =discourse-graphs= stores its relations. Parents and children build the tree. The other relations are drawn as labelled, coloured, dashed links between two notes that are both in view.

Boxes are tinted by file tag. =vulpea-hierarchy-tag-colors= maps a tag to a colour, and a note takes the colour of the first of its tags that is listed. In the browser, the position of every box comes from the fCoSE layout (see =vendor/vulpea-hierarchy/README.org=): parents go above their children, and each relation can say in which direction its object goes, with =:direction= in =vulpea-hierarchy-relations=. A click on a box recentres the graph on it and cuts the tree again from there, so the page holds the tree down to =vulpea-hierarchy-embed-depth= levels (4) and the depth buttons and Backspace move through it. Emacs cuts the tree there, so a large vault doesn't make the page large; to go further, run the command again from another note. A small marker on a box folds its branch.

A vault of this size is too large to draw whole. So every command first asks for a *starting note* and a *depth*, and shows only that part: the starting note, its children, their children, down to the depth.

** The commands

| Command                              | What it shows                                                                  |
|--------------------------------------+--------------------------------------------------------------------------------|
| =vulpea-hierarchy-graph=             | An interactive graph in the browser: pan, zoom, click a box to fold it.         |
| =vulpea-hierarchy-outline-native=    | An outline of Emacs buttons. =TAB= or =[+]=/=[-]= expands, =RET= visits a note. |
| =vulpea-hierarchy-outline-vui=       | The same outline built with =vui=. A trial, to compare with the native one.     |
| =vulpea-hierarchy-svg=               | A Graphviz SVG file named =<date and time>-<note>-<depth>.svg=.                 |

Notes on the last level show how many children they hide (=+N= in the browser, a count in the outline). The browser graph can't load more, so run it again with a bigger depth; the outlines expand any note on demand.

(defgroup vulpea-hierarchy nil
  "Parent/child views of vulpea notes."
  :group 'vulpea)

(defcustom vulpea-hierarchy-relations
  '((parent :label "parent" :color "#888888"
            :sources ((meta "parents") (meta-inverse "children")))
    (supports :label "supports" :color "#2e8b57" :direction right
              :sources ((meta "supports") (property "DG_SUPPORTS")))
    (opposes :label "opposes" :color "#c0392b" :direction left
             :sources ((meta "opposes") (property "DG_OPPOSES")))
    (informs :label "informs" :color "#2874a6" :direction 45
             :sources ((meta "informs") (property "DG_INFORMS")))
    (answers :label "answers" :color "#8e44ad" :direction up
             :sources ((meta "answers") (property "DG_ANSWERS"))))
  "Relations between notes, as (NAME :label LABEL :color COLOR :direction DIRECTION :sources SOURCES).
The relation `parent' is the one that builds the tree: its edges run
from a parent down to its children.  Every other relation is drawn as a
labelled link between two notes that are both in view.

An edge reads \"SUBJECT NAME OBJECT\", for example \"claim supports
question\".  Each of SOURCES says where to look for edges, and a
relation may have several:

  (meta KEY)           the note is the subject; the links in its
                       metadata KEY (\"- KEY :: [[id:..][..]]\") are objects.
  (meta-inverse KEY)   the note is the object; the links in its metadata
                       KEY are subjects.  \"- children :: ..\" on a note
                       gives the parent edge of each child.
  (property KEY)       the note is the subject; the links, or bare ids,
                       in its file property KEY are objects.
  (property-inverse KEY)
                       like `meta-inverse', but read from a file property.

COLOR is used for the links in the browser page and the SVG export.

DIRECTION says where the object of the relation is drawn, as seen from
its subject, in the browser page: `up', `down', `left' or `right', or an
angle in degrees, where 0 is right and 90 is up, so 45 is up and to the
right.  An angle leans on both axes at once.  The relation `parent' has
no direction, because it always puts parents above their children.  A
relation with no DIRECTION is drawn to the right.  The page treats a
direction as a request: when two requests contradict each other, the
later one is dropped."
  :type '(alist :key-type symbol :value-type plist))

(defun vulpea-hierarchy--note (id notes)
  "Return the note with ID from NOTES, loading it from the database if needed."

(defun vulpea-hierarchy--value-ids (values)
  "Return the ids named in VALUES, a list of strings.
A value may hold several links, separated by commas or not.  Every link
counts, not only the first one in a value.  A value with no link is
read as bare ids separated by commas or spaces."
  (let (ids)
    (dolist (value values)
      (let ((pos 0) (found nil))
        (while (string-match org-link-bracket-re value pos)
          (setq found t)
          (let ((link (match-string 1 value)))
            (when (string-prefix-p "id:" link)
              (push (string-remove-prefix "id:" link) ids)))
          (setq pos (match-end 0)))
        (unless found
          (dolist (word (split-string value "[ ,]+" t))
            (push word ids)))))
    (delete-dups (seq-remove #'string-empty-p (nreverse ids)))))

(defun vulpea-hierarchy--source-values (note source)
  "Return the strings that SOURCE finds in NOTE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (cdr (assoc key (vulpea-note-meta note))))
    ((or `(property ,key) `(property-inverse ,key))
     (when-let ((value (cdr (assoc key (vulpea-note-properties note)))))
       (list value)))))

(defun vulpea-hierarchy--source-notes (source)
  "Return the notes that may hold SOURCE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (vulpea-db-query-by-meta-key key))
    ((or `(property ,key) `(property-inverse ,key))
     (vulpea-db-query
      (lambda (note) (assoc key (vulpea-note-properties note)))))))

(defun vulpea-hierarchy--edges ()
  "Return every edge as (SUBJECT RELATION OBJECT), and the notes read.
The second value is a hash table from id to note."
  (let ((notes (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        edges)
    (pcase-dolist (`(,relation . ,plist) vulpea-hierarchy-relations)
      (dolist (source (plist-get plist :sources))
        (dolist (note (vulpea-hierarchy--source-notes source))
          (puthash (vulpea-note-id note) note notes)
          (dolist (id (vulpea-hierarchy--value-ids
                       (vulpea-hierarchy--source-values note source)))
            (let* ((inverse (memq (car source) '(meta-inverse property-inverse)))
                   (edge (if inverse
                             (list id relation (vulpea-note-id note))
                           (list (vulpea-note-id note) relation id))))
              (unless (gethash edge seen)
                (puthash edge t seen)
                (push edge edges)))))))
    (cons (nreverse edges) notes)))

#+begin_src emacs-lisp
(defun vulpea-hierarchy--build ()
  "Return a plist describing the whole hierarchy.
:notes maps id to note, :children maps parent id to child ids,
:roots lists ids that are parents but have no parent themselves, and
:links lists the edges (SUBJECT RELATION OBJECT) of every other relation."
  (pcase-let* ((`(,edges . ,notes) (vulpea-hierarchy--edges))
               (children (make-hash-table :test #'equal))
               (has-parent (make-hash-table :test #'equal))
               (parent-ids nil)
               (links nil)
               (ids nil))
    (pcase-dolist (`(,subject ,relation ,object) edges)
      (push subject ids)
      (push object ids)
      (if (eq relation 'parent)
          (progn (puthash subject t has-parent)
                 (push subject (gethash object children))
                 (push object parent-ids))
        (push (list subject relation object) links)))
    ;; Notes that only appear as the object of an edge are not loaded yet.
    (dolist (note (vulpea-db-query-by-ids
                   (seq-remove (lambda (id) (gethash id notes))
                               (delete-dups ids))))
      (puthash (vulpea-note-id note) note notes))
    (list :notes notes
          :children children
          :links (nreverse links)
          :roots (sort (seq-remove (lambda (id) (gethash id has-parent))
                                   (delete-dups (copy-sequence parent-ids)))
                       (lambda (a b)
                         (string< (vulpea-hierarchy--title a notes)
                                  (vulpea-hierarchy--title b notes)))))))

#+begin_src emacs-lisp
(defun vulpea-hierarchy--scope (tree start depth)
  "Return the part of TREE reached from START within DEPTH levels.
The result has the same keys as the tree, plus :more, which maps an
id at the last level to how many children it hides, and :nodes, the
ids in scope.  :roots is just (START).  :links keeps the other
relations between two notes that are both in scope."
  (let ((notes (plist-get tree :notes))
        (children (make-hash-table :test #'equal))
        (more (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        (nodes (list start))
        (queue (list (cons start 0))))
    (puthash start t seen)
    (while queue
      (pcase-let ((`(,id . ,level) (pop queue)))
        (let ((kids (vulpea-hierarchy--sorted-children id tree)))
          (if (< level depth)
              (dolist (kid kids)
                (puthash id (append (gethash id children) (list kid)) children)
                (unless (gethash kid seen)
                  (puthash kid t seen)
                  (push kid nodes)
                  (setq queue (append queue (list (cons kid (1+ level)))))))
            (when kids
              (puthash id (length kids) more))))))
    (setq nodes (nreverse nodes))
    (list :notes notes
          :children children
          :more more
          :roots (list start)
          :nodes nodes
          :links (seq-filter (pcase-lambda (`(,subject ,_ ,object))
                               (and (gethash subject seen) (gethash object seen)))
                             (plist-get tree :links)))))

(defun vulpea-hierarchy--html (tree start depth)
  "Return a self-contained HTML page showing TREE from START to DEPTH.

`vulpea-hierarchy--scope'.  The page can recentre on any note in it and
cut the part to show by itself."

         (ids (let ((acc (make-hash-table :test #'equal)))
                (puthash start t acc)
                (maphash (lambda (k v)
                           (puthash k t acc)
                           (dolist (kid v) (puthash kid t acc)))
                         (plist-get tree :children))

                  (puthash subject t acc)
                  (puthash object t acc))

           (mapcar
            (lambda (id)
              (let* ((note (vulpea-hierarchy--note id notes))
                     (color (vulpea-hierarchy--tag-color note)))

                  (title . ,(vulpea-hierarchy--title id notes))
                  (path . ,(and note (vulpea-note-path note)))

                  (colorTag . ,(car color))
                  (color . ,(cdr color)))))

         (edges

           (cl-loop for (parent . kids) in
                    (let (acc)
                      (maphash (lambda (k v) (push (cons k v) acc))
                               (plist-get tree :children))
                      acc)
                    append (mapcar (lambda (kid) (vector parent kid)) kids))))
         (links

           (mapcar (pcase-lambda (`(,subject ,relation ,object))

                       (rel . ,(symbol-name relation))))
                   (plist-get tree :links))))

                 (depth . ,depth)
                 (nodes . ,nodes)
                 (edges . ,edges)

                                       (plist-get tree :more))

(defun vulpea-hierarchy--wrap (text width)
  "Return TEXT as a list of lines no longer than WIDTH, breaking long words."
  (let (lines (line ""))
    (dolist (word (split-string text))
      (while (> (length word) width)
        (when (> (length line) 0) (push line lines) (setq line ""))
        (push (substring word 0 width) lines)
        (setq word (substring word width)))
      (cond ((string-empty-p line) (setq line word))
            ((<= (+ (length line) 1 (length word)) width)
             (setq line (concat line " " word)))
            (t (push line lines) (setq line word))))
    (unless (string-empty-p line) (push line lines))
    (nreverse (or lines (list "")))))

function cut() {
  kids = new Map(); more = new Map(); collapsed.clear(); infoCache.clear();
  const seen = new Set([root]), queue = [[root, 0]];
  while (queue.length) {
    const [id, level] = queue.shift(), ks = allKids.get(id) || [];
    if (level < depth) {
      for (const k of ks) {
        if (!kids.has(id)) kids.set(id, []);
        kids.get(id).push(k);
        if (!seen.has(k)) { seen.add(k); queue.push([k, level + 1]); }

function wrap(tokens) {
  const lines = [], space = measure(' ');
  let line = [], width = 0;
  for (const tok0 of tokens) {
    for (const tok of breakToken(tok0)) {
      const w = measure(tok.text);
      if (line.length && width + space + w > TEXT_W) { lines.push(line); line = []; width = 0; }

      line.push(tok);
    }
  }

#+begin_src html :tangle ../../../libraries/modules/custom/sp-vulpea-hierarchy.html :comments no :padline yes :mkdirp yes
function constraints(ids, level) {
  const before = { x: new Map(), y: new Map() }, out = [];
  const reaches = (axis, from, to) => {
    const seen = new Set(), stack = [from];
    while (stack.length) {
      const n = stack.pop();
      if (n === to) return true;
      if (seen.has(n)) continue;
      seen.add(n);
      stack.push(...(before[axis].get(n) || []));
    }
    return false;
  };
  const add = (axis, first, second, gap) => {
    if (first === second || reaches(axis, second, first)) return;
    if (!before[axis].has(first)) before[axis].set(first, []);
    before[axis].get(first).push(second);
    out.push(axis === 'y' ? { top: first, bottom: second, gap } : { left: first, right: second, gap });
  };
  const gapY = (a, b) => (info(a).h + info(b).h) / 2 + GAPY;
  for (const id of ids) {
    for (const c of childrenOf(id)) if (ids.has(c) && level.get(c) > level.get(id)) add('y', id, c, gapY(id, c));
  }
  for (const l of D.links) {
    if (!ids.has(l.from) || !ids.has(l.to)) continue;
    const [dx, dy] = (relStyle.get(l.rel) || { direction: [1, 0] }).direction;
    if (Math.abs(dx) >= 0.38) {
      if (dx > 0) add('x', l.from, l.to, W + GAPX); else add('x', l.to, l.from, W + GAPX);
    }
    if (Math.abs(dy) >= 0.38) {
      if (dy > 0) add('y', l.from, l.to, gapY(l.from, l.to)); else add('y', l.to, l.from, gapY(l.from, l.to));
    }
  }
  const rows = new Map();
  for (const id of ids) {
    const l = level.get(id);
    if (!rows.has(l)) rows.set(l, []);
    const row = rows.get(l);
    if (!row.some(o => reaches('y', id, o) || reaches('y', o, id))) row.push(id);
  }
  return { relative: out, align: { horizontal: [...rows.values()].filter(r => r.length > 1) } };
}

  const cy = cytoscape({ headless: true, styleEnabled: true,
    style: [{ selector: 'node', style: { width: 'data(w)', height: 'data(h)', shape: 'rectangle' } }] });

function separate() {
  const boxes = [...pos.values()];
  for (let pass = 0; pass < 80; pass++) {
    let moved = false;
    for (let i = 0; i < boxes.length; i++) {
      for (let j = i + 1; j < boxes.length; j++) {
        const a = boxes[i], b = boxes[j];
        const ox = Math.min(a.x, b.x) + W - Math.max(a.x, b.x) + GAPX / 2;
        const oy = Math.min(a.y + a.h, b.y + b.h) - Math.max(a.y, b.y) + GAPY / 4;
        if (ox <= 0 || oy <= 0) continue;
        moved = true;
        if (ox <= oy * 2.5) {
          const d = ox / 2 * (a.x <= b.x ? 1 : -1);
          a.x -= d; b.x += d;
        } else {
          const d = oy / 2 * (a.y <= b.y ? 1 : -1);
          a.y -= d; b.y += d;
        }
      }
    }
    if (!moved) break;
  }
}

** Layout backend of the browser page: what changed and why

Before, the page placed boxes with its own tidy-tree code: depth gave the column, and a parent was centred on its children. That can't say "this relation goes to the right of its subject", because a link joins boxes that the tree has already placed. The page now asks the fCoSE layout for the positions and keeps its own SVG drawing (text wrapping, tags, tints, fold markers, links).

| Gained                                                           | Lost or costs                                                                  |
|------------------------------------------------------------------+--------------------------------------------------------------------------------|
| Directions per relation, with diagonals, solved together with the tree | About 560 KB of vendored scripts (=vendor/vulpea-hierarchy/=), pasted into every page |
| A note with several parents is drawn once, joined to all of them | Layout is heuristic: a crowded graph breaks some direction rules, and the result is not tidy like a tree |
| Rows of siblings are aligned, and the layout is deterministic    | A layout takes about 0.5 s for 120 boxes and grows quickly above that           |
| No dependency on the network; the scripts are MIT licensed        | The scripts must be updated by hand (=vendor/vulpea-hierarchy/README.org=)       |
| Drawing is unchanged, so wrapping, tags and tints still work      | The SVG export (Graphviz) ignores directions                                    |

Other backends considered: Cytoscape.js with its own renderer (less control over wrapped text and muted tags), ELK (layered, but one direction for the whole graph), d3-force (smaller, but no hard rules and no rectangles), and Graphviz in the browser (a static layout that can't take rules). fCoSE is the only one with built-in relative placement rules.
