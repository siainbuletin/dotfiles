* Parent/child views of vulpea notes

** Context

My notes follow a Zettelkasten pattern. One file is one idea. A sub-note records its parents with a =- parents :: [[id:…][Title]]= line in its zeroth section, and vulpea stores that as metadata. A note can have several parents: either one link after another on the same line, separated by commas, or one =- parents ::= line per parent. =vulpea-graph= doesn't draw this hierarchy (it analyses links for retrieval and shows lists), so this module reads the =parents= metadata and builds the tree itself.

A vault of this size is too large to draw whole. So every command first asks for a *starting note* and a *depth*, and shows only that part: the starting note, its children, their children, down to the depth.

** The commands

| Command                              | What it shows                                                                  |
|--------------------------------------+--------------------------------------------------------------------------------|
| =vulpea-hierarchy-graph=             | An interactive graph in the browser: pan, zoom, click a box to fold it.         |
| =vulpea-hierarchy-outline-native=    | An outline of Emacs buttons. =TAB= or =[+]=/=[-]= expands, =RET= visits a note. |
| =vulpea-hierarchy-outline-vui=       | The same outline built with =vui=. A trial, to compare with the native one.     |
| =vulpea-hierarchy-svg=               | A Graphviz SVG file named =<date and time>-<note>-<depth>.svg=.                 |

Notes on the last level show how many children they hide (=+N= in the browser, a count in the outline). The browser graph can't load more, so run it again with a bigger depth; the outlines expand any note on demand.

*** Reading every parent of a note (lines 72–88)

This is where a note with several parents is handled. vulpea's own rule for several values is one =- parents ::= line per value, and the metadata then holds one entry per line. A single line that lists several links separated by commas stays one entry, and =vulpea-note-meta-get-list= with the =link= type only returns the first link of an entry. So this function reads every link itself.

- Lines 72-75 define the function: it takes a note and returns the ids of all its parents.
- Line 76 starts an empty list, =ids=.
- Lines 77-78 go through every value stored under the parent key. A repeated key gives several values, so repeated lines are covered here.
- Line 79 sets =pos=, where to search next, and =found=, which records whether this value had any link.
- Line 80 finds the next Org link in the value, starting at =pos=.
- Line 81 records that a link was found.
- Lines 82-84 take the link target and, when it starts with =id:=, add the id without the prefix.
- Line 85 moves =pos= past this link, so the loop goes on to the next link in the same value. That is what makes a comma-separated line give every parent.
- Lines 86-87 handle a value with no link at all: if it isn't blank, the trimmed text is taken as a bare id.
- Line 88 puts the ids back in document order, drops empty ones (such as =[[id:][Title]]=), and removes duplicates.

#+begin_src emacs-lisp
(defun vulpea-hierarchy--parent-ids (note)
  "Ids of every parent NOTE names under `vulpea-hierarchy-parent-key'.
A value may hold several links, separated by commas or not, and the key
may repeat.  Every link counts, not only the first one in a line."
  (let (ids)
    (dolist (value (cdr (assoc vulpea-hierarchy-parent-key
                               (vulpea-note-meta note))))
      (let ((pos 0) (found nil))
        (while (string-match org-link-bracket-re value pos)
          (setq found t)
          (let ((link (match-string 1 value)))
            (when (string-prefix-p "id:" link)
              (push (string-remove-prefix "id:" link) ids)))
          (setq pos (match-end 0)))
        (when (and (not found) (not (string-empty-p (string-trim value))))
          (push (string-trim value) ids))))
    (delete-dups (seq-remove #'string-empty-p (nreverse ids)))))
#+end_src

#+begin_src emacs-lisp
(defun vulpea-hierarchy--build ()
  "Return a plist describing the whole hierarchy.
:notes maps id to note, :children maps parent id to child ids,
:roots lists ids that are parents but have no parent themselves."
  (let ((notes (make-hash-table :test #'equal))
        (children (make-hash-table :test #'equal))
        (has-parent (make-hash-table :test #'equal))
        parent-ids)
    (dolist (note (vulpea-db-query-by-meta-key vulpea-hierarchy-parent-key))
      (puthash (vulpea-note-id note) note notes)
      (dolist (pid (vulpea-hierarchy--parent-ids note))
        (puthash (vulpea-note-id note) t has-parent)
        (push (vulpea-note-id note) (gethash pid children))
        (push pid parent-ids)))
    ;; Parents that carry no parent key themselves are not loaded yet.
    (dolist (note (vulpea-db-query-by-ids
                   (seq-remove (lambda (id) (gethash id notes))
                               (delete-dups parent-ids))))
      (puthash (vulpea-note-id note) note notes))
    (list :notes notes
          :children children
          :roots (sort (seq-remove (lambda (id) (gethash id has-parent))
                                   (delete-dups (copy-sequence parent-ids)))
                       (lambda (a b)
                         (string< (vulpea-hierarchy--title a notes)
                                  (vulpea-hierarchy--title b notes)))))))
#+end_src

#+begin_src emacs-lisp
(defun vulpea-hierarchy--scope (tree start depth)
  "Return the part of TREE reached from START within DEPTH levels.
The result has the same keys as the tree, plus :more, which maps an
id at the last level to how many children it hides, and :nodes, the
ids in scope.  :roots is just (START)."
  (let ((notes (plist-get tree :notes))
        (children (make-hash-table :test #'equal))
        (more (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        (nodes (list start))
        (queue (list (cons start 0))))
    (puthash start t seen)
    (while queue
      (pcase-let ((`(,id . ,level) (pop queue)))
        (let ((kids (vulpea-hierarchy--sorted-children id tree)))
          (if (< level depth)
              (dolist (kid kids)
                (puthash id (append (gethash id children) (list kid)) children)
                (unless (gethash kid seen)
                  (puthash kid t seen)
                  (push kid nodes)
                  (setq queue (append queue (list (cons kid (1+ level)))))))
            (when kids
              (puthash id (length kids) more))))))
    (list :notes notes
          :children children
          :more more
          :roots (list start)
          :nodes (nreverse nodes))))

(defun vulpea-hierarchy--html (scope start depth)
  "Return a self-contained HTML page showing SCOPE from START to DEPTH."
  (let* ((notes (plist-get scope :notes))
         (nodes
          (vconcat
           (mapcar
            (lambda (id)
              (let ((note (vulpea-hierarchy--note id notes)))
                `((id . ,id)
                  (title . ,(vulpea-hierarchy--title id notes))
                  (path . ,(and note (vulpea-note-path note)))
                  (more . ,(gethash id (plist-get scope :more) 0)))))
            (plist-get scope :nodes))))
         (edges
          (vconcat
           (cl-loop for (parent . kids) in
                    (let (acc)
                      (maphash (lambda (k v) (push (cons k v) acc))
                               (plist-get scope :children))
                      acc)
                    append (mapcar (lambda (kid) (vector parent kid)) kids))))
         (data `((root . ,start)
                 (depth . ,depth)
                 (nodes . ,nodes)
                 (edges . ,edges))))
    (string-replace "__DATA__" (vulpea-hierarchy--json-for-html data)
                    (vulpea-hierarchy--html-template))))

  "Expand every node in the view above the starting depth."

      (pcase-let ((`(,id . ,level) (pop queue)))

(defun vulpea-hierarchy-view--insert (id level path)
  "Insert the line for ID at indent LEVEL, then its children if expanded.
PATH holds the ancestors, so a cycle stops the recursion."
  (let* ((tree vulpea-hierarchy--tree)
         (notes (plist-get tree :notes))
         (kids (vulpea-hierarchy--sorted-children id tree))
         (open (and kids (gethash id vulpea-hierarchy--expanded)))
         (note (vulpea-hierarchy--note id notes)))
    (let ((start (point)))
      (insert (make-string (* 2 level) ?\s))
      (vulpea-hierarchy-view--insert-line-body id kids open note)
      (put-text-property start (point) 'vulpea-hierarchy-id id))
    (insert "\n")
    (when (and open (not (member id path)))
      (dolist (kid kids)
        (vulpea-hierarchy-view--insert kid (1+ level) (cons id path))))))

;;;; Static SVG export (Graphviz)

(defun vulpea-hierarchy--dot (tree)
  "Return Graphviz source for TREE, one cluster per root."
  (let ((notes (plist-get tree :notes))
        (children (plist-get tree :children))
        (drawn (make-hash-table :test #'equal)))
    (with-temp-buffer
      (insert "digraph vulpea {\n"
              (format "  rankdir=%s;\n" vulpea-hierarchy-rankdir)
              "  node [shape=box, style=\"rounded,filled\", fillcolor=\"#f4f4f4\","
              " fontname=\"Helvetica\"];\n"
              "  edge [color=\"#888888\"];\n")
      (let ((n 0))
        (dolist (root (plist-get tree :roots))
          (insert (format "  subgraph cluster_%d {\n    style=invis;\n" (cl-incf n)))
          (let ((queue (list root)))
            (while queue
              (let ((id (pop queue)))
                (unless (gethash id drawn)
                  (puthash id t drawn)
                  (insert (format "    %S [label=%S%s];\n"
                                  id (vulpea-hierarchy--title id notes)
                                  (if (equal id root)
                                      ", fillcolor=\"#d8e6f5\", penwidth=2"
                                    "")))
                  (setq queue (append queue (gethash id children)))))))
          (insert "  }\n")))
      (maphash (lambda (pid kids)
                 (dolist (kid kids)
                   (insert (format "  %S -> %S;\n" pid kid))))
               children)
      (insert "}\n")
      (buffer-string))))

function layout(id, depth, path, row) {
  const node = { id, depth, kids: [], y: 0 };
  if (!path.includes(id)) {
    for (const c of childrenOf(id)) node.kids.push(layout(c, depth + 1, [...path, id], row));
