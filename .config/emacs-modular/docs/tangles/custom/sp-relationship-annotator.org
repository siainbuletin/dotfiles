* Typed relationships between vulpea notes

** Context

My notes follow a Zettelkasten pattern. One file is one idea. A sub-note records its parents with a =- parents :: [[id:…][Title]]= line in its zeroth section, and vulpea stores that as metadata. A note can have several parents: either one link after another on the same line, separated by commas, or one =- parents ::= line per parent. =vulpea-graph= doesn't draw this hierarchy (it analyses links for retrieval and shows lists), so this module reads the =parents= metadata and builds the tree itself.

Besides =parents=, a note can relate to other notes in other ways: =supports=, =opposes=, =informs=, =answers=, or any relation you declare in =relationship-annotator-relations=. Each relation lists the places it is read from: a metadata key on the note, the inverse of a key on the other note (=children= for =parents=), or a file property such as =DG_SUPPORTS=, which is how =discourse-graphs= stores its relations. Parents and children build the tree. The other relations are drawn as labelled, coloured, dashed links between two notes that are both in view.

Boxes are tinted by file tag. =relationship-annotator-tag-colors= maps a tag to a colour, and a note takes the colour of the first of its tags that is listed. In the browser, the position of every box comes from the fCoSE layout (see =vendor/relationship-annotator/README.org=): parents go above their children, and each relation can say in which direction its object goes, with =:direction= in =relationship-annotator-relations=. A click on a box, or Tab to it and Enter, recentres the graph on it and cuts the tree again from there, so the page holds the tree down to =relationship-annotator-embed-depth= levels (4) and the depth buttons and Backspace move through it. Emacs cuts the tree there, so a large vault doesn't make the page large; to go further, run the command again from another note. A small marker on a box folds its branch.

The module was called =sp-vulpea-hierarchy= until it took over the logic of the =discourse-graphs= package. Notes can have a /type/ (=question=, =claim=, =evidence= or =source=), read from a =DG_TYPE= property, a =type= metadata field or a file tag. A relation can say which types it should connect, so a =supports= edge from a question is flagged as an anomaly (a warning sign in the browser, a line in the review buffer). Notes can have /attributes/, numbers computed from formulas such as ={count:Supported By:evidence} - {count:Opposed By:evidence}=, and one of them is shown in brackets after the title. =rel-anno-review= lists the anomalies, the claims with gaps in their argument, and how well each answer to a question stands. For how this compares with the package, see [[file:../../architecture/relationship-annotator-vs-discourse-graphs.org][relationship-annotator-vs-discourse-graphs]].

A vault of this size is too large to draw whole. So every command first asks for a *starting note* and a *depth*, and shows only that part: the starting note, its children, their children, down to the depth.

#+begin_src emacs-lisp
(defun relationship-annotator--value-ids (values)
  "Return the ids named in VALUES, a list of strings.
A value may hold several links, separated by commas or not.  Every link
counts, not only the first one in a value.  A value with no link is
read as bare ids separated by commas or spaces."
  (let (ids)
    (dolist (value values)
      (let ((pos 0) (found nil))
        (while (string-match org-link-bracket-re value pos)
          (setq found t)
          (let ((link (match-string 1 value)))
            (when (string-prefix-p "id:" link)
              (push (string-remove-prefix "id:" link) ids)))
          (setq pos (match-end 0)))
        (unless found
          (dolist (word (split-string value "[ ,]+" t))
            (push word ids)))))
    (delete-dups (seq-remove #'string-empty-p (nreverse ids)))))

(defun relationship-annotator--source-values (note source)
  "Return the strings that SOURCE finds in NOTE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (cdr (assoc key (vulpea-note-meta note))))
    ((or `(property ,key) `(property-inverse ,key))
     (when-let ((value (cdr (assoc key (vulpea-note-properties note)))))
       (list value)))))

(defun relationship-annotator--source-notes (source)
  "Return the notes that may hold SOURCE."
  (pcase source
    ((or `(meta ,key) `(meta-inverse ,key))
     (vulpea-db-query-by-meta-key key))
    ((or `(property ,key) `(property-inverse ,key))
     (vulpea-db-query
      (lambda (note) (assoc key (vulpea-note-properties note)))))))

(defun relationship-annotator--edges ()
  "Return every edge as (SUBJECT RELATION OBJECT), and the notes read.
The second value is a hash table from id to note."
  (let ((notes (make-hash-table :test #'equal))
        (seen (make-hash-table :test #'equal))
        edges)
    (pcase-dolist (`(,relation . ,plist) relationship-annotator-relations)
      (dolist (source (plist-get plist :sources))
        (dolist (note (relationship-annotator--source-notes source))
          (puthash (vulpea-note-id note) note notes)
          (dolist (id (relationship-annotator--value-ids
                       (relationship-annotator--source-values note source)))
            (let* ((inverse (memq (car source) '(meta-inverse property-inverse)))
                   (edge (if inverse
                             (list id relation (vulpea-note-id note))
                           (list (vulpea-note-id note) relation id))))
              (unless (gethash edge seen)
                (puthash edge t seen)
                (push edge edges)))))))
    (cons (nreverse edges) notes)))

#+begin_src emacs-lisp
(defun relationship-annotator--build ()
  "Return a plist describing the whole hierarchy.
:notes maps id to note, :children maps parent id to child ids,
:roots lists ids that are parents but have no parent themselves, and
:links lists the edges (SUBJECT RELATION OBJECT) of every other relation."
  (pcase-let* ((`(,edges . ,notes) (relationship-annotator--edges))
               (children (make-hash-table :test #'equal))
               (has-parent (make-hash-table :test #'equal))
               (parent-ids nil)
               (links nil)
               (ids nil))
    (pcase-dolist (`(,subject ,relation ,object) edges)
      (push subject ids)
      (push object ids)
      (if (eq relation 'parent)
          (progn (puthash subject t has-parent)
                 (push subject (gethash object children))
                 (push object parent-ids))
        (push (list subject relation object) links)))
    ;; Notes that only appear as the object of an edge are not loaded yet.
    (dolist (note (vulpea-db-query-by-ids
                   (seq-remove (lambda (id) (gethash id notes))
                               (delete-dups ids))))
      (puthash (vulpea-note-id note) note notes))
    (list :notes notes
          :children children
          :links (nreverse links)
          :roots (sort (seq-remove (lambda (id) (gethash id has-parent))
                                   (delete-dups (copy-sequence parent-ids)))
                       (lambda (a b)
                         (string< (relationship-annotator--title a notes)
                                  (relationship-annotator--title b notes)))))))

  "Return the term (func OP RELATION TYPE ATTRIBUTE) written SPEC in FORMULA.

(defun relationship-annotator--tokenize (formula)
  "Split FORMULA into numbers, operator symbols and terms."
  (let ((pos 0) tokens)
    (while (< pos (length formula))
      (let ((char (aref formula pos)))
        (cond
         ((memq char '(?\s ?\t)) (cl-incf pos))
         ((memq char '(?+ ?- ?* ?/))
          (push (intern (string char)) tokens) (cl-incf pos))
         ((eq char ?\() (push 'open tokens) (cl-incf pos))
         ((eq char ?\)) (push 'close tokens) (cl-incf pos))
         ((eq char ?{)
          (let ((end (string-search "}" formula pos)))
            (unless end (user-error "Unclosed { in formula %S" formula))
            (push (relationship-annotator--parse-term
                   (substring formula (1+ pos) end) formula)
                  tokens)
            (setq pos (1+ end))))
         ((eq pos (string-match "[0-9]+\\(?:\\.[0-9]+\\)?" formula pos))
          (push (float (string-to-number (match-string 0 formula))) tokens)
          (setq pos (match-end 0)))
         (t (user-error "Unexpected %c in formula %S" char formula)))))
    (nreverse tokens)))

(defun relationship-annotator--parse-formula (formula)
  "Return the parse tree of FORMULA.
A tree is a number, a term (func ...), or (OPERATOR LEFT RIGHT) with
OPERATOR one of + - * /."
  (let ((tokens (relationship-annotator--tokenize formula)))
    (cl-labels
        ((peek () (car tokens))
         (next () (pop tokens))
         (expr ()
           (let ((left (term)))
             (while (memq (peek) '(+ -))
               (let ((op (next)))
                 (setq left (list op left (term)))))
             left))
         (term ()
           (let ((left (factor)))
             (while (memq (peek) '(* /))
               (let ((op (next)))
                 (setq left (list op left (factor)))))
             left))
         (factor ()
           (let ((token (next)))
             (cond
              ((numberp token) token)
              ((eq token 'open)
               (prog1 (expr)
                 (unless (eq (next) 'close)
                   (user-error "Missing ) in formula %S" formula))))
              ((eq token '-) (list '- 0.0 (factor)))
              ((eq (car-safe token) 'func) token)
              (t (user-error "Unexpected %s in formula %S"

      (prog1 (expr)

#+begin_src emacs-lisp
;;;; Static SVG export (Graphviz)

(defun relationship-annotator--wrap (text width)
  "Return TEXT as a list of lines no longer than WIDTH, breaking long words."
  (let (lines (line ""))
    (dolist (word (split-string text))
      (while (> (length word) width)
        (when (> (length line) 0) (push line lines) (setq line ""))
        (push (substring word 0 width) lines)
        (setq word (substring word width)))
      (cond ((string-empty-p line) (setq line word))
            ((<= (+ (length line) 1 (length word)) width)
             (setq line (concat line " " word)))
            (t (push line lines) (setq line word))))
    (unless (string-empty-p line) (push line lines))
    (nreverse (or lines (list "")))))

(defun relationship-annotator--label (id notes)
  "Return the title of ID from NOTES followed by its file tags, like :a:b:."
  (let* ((note (relationship-annotator--note id notes))
         (tags (and note (vulpea-note-tags note))))
    (concat (relationship-annotator--title id notes)
            (and tags (format " :%s:" (string-join tags ":"))))))

(defun relationship-annotator--dot (tree)
  "Return Graphviz source for TREE, one cluster per root."
  (let ((notes (plist-get tree :notes))
        (children (plist-get tree :children))
        (drawn (make-hash-table :test #'equal)))
    (with-temp-buffer
      (insert "digraph vulpea {\n"
              (format "  rankdir=%s;\n" relationship-annotator-rankdir)
              "  node [shape=box, style=\"rounded,filled\", fillcolor=\"#f4f4f4\","
              " fontname=\"Helvetica\"];\n"
              "  edge [color=\"#888888\"];\n")
      (let ((n 0))
        (dolist (root (plist-get tree :roots))
          (insert (format "  subgraph cluster_%d {\n    style=invis;\n" (cl-incf n)))
          (let ((queue (list root)))
            (while queue
              (let ((id (pop queue)))
                (unless (gethash id drawn)
                  (puthash id t drawn)
                  (insert (format "    %S [label=\"%s\"%s];\n"
                                  id (relationship-annotator--dot-label id notes)
                                  (relationship-annotator--dot-fill
                                   (relationship-annotator--note id notes)
                                   (equal id root))))
                  (setq queue (append queue (gethash id children)))))))
          (insert "  }\n")))
      (maphash (lambda (pid kids)
                 (dolist (kid kids)
                   (insert (format "  %S -> %S;\n" pid kid))))
               children)
      (pcase-dolist (`(,subject ,relation ,object) (plist-get tree :links))
        (insert (format "  %S -> %S [constraint=false, style=dashed, label=%S, fontsize=10, color=%S, fontcolor=%S];\n"
                        subject object
                        (relationship-annotator--relation-style
                         relation :label (symbol-name relation))
                        (relationship-annotator--relation-style relation :color "#888888")
                        (relationship-annotator--relation-style relation :color "#888888"))))
      (insert "}\n")
      (buffer-string))))

function constraints(ids, level) {
  const before = { x: new Map(), y: new Map() }, out = [];
  const reaches = (axis, from, to) => {
    const seen = new Set(), stack = [from];
    while (stack.length) {
      const n = stack.pop();
      if (n === to) return true;
      if (seen.has(n)) continue;
      seen.add(n);
      stack.push(...(before[axis].get(n) || []));
    }
    return false;
  };
  const add = (axis, first, second, gap) => {
    if (first === second || reaches(axis, second, first)) return;
    if (!before[axis].has(first)) before[axis].set(first, []);
    before[axis].get(first).push(second);
    out.push(axis === 'y' ? { top: first, bottom: second, gap } : { left: first, right: second, gap });
  };
  const gapY = (a, b) => (info(a).h + info(b).h) / 2 + GAPY;
  for (const id of ids) {
    for (const c of childrenOf(id)) if (ids.has(c) && level.get(c) > level.get(id)) add('y', id, c, gapY(id, c));
  }
  for (const l of D.links) {
    if (!ids.has(l.from) || !ids.has(l.to)) continue;
    const [dx, dy] = (relStyle.get(l.rel) || { direction: [1, 0] }).direction;
    if (Math.abs(dx) >= 0.38) {
      if (dx > 0) add('x', l.from, l.to, W + GAPX); else add('x', l.to, l.from, W + GAPX);
    }
    if (Math.abs(dy) >= 0.38) {
      if (dy > 0) add('y', l.from, l.to, gapY(l.from, l.to)); else add('y', l.to, l.from, gapY(l.from, l.to));
    }
  }
  const rows = new Map();
  for (const id of ids) {
    const l = level.get(id);
    if (!rows.has(l)) rows.set(l, []);
    const row = rows.get(l);
    if (!row.some(o => reaches('y', id, o) || reaches('y', o, id))) row.push(id);
  }
  return { relative: out, align: { horizontal: [...rows.values()].filter(r => r.length > 1) } };
}

** Layout backend of the browser page: what changed and why

Before, the page placed boxes with its own tidy-tree code: depth gave the column, and a parent was centred on its children. That can't say "this relation goes to the right of its subject", because a link joins boxes that the tree has already placed. The page now asks the fCoSE layout for the positions and keeps its own SVG drawing (text wrapping, tags, tints, fold markers, links).

| Gained                                                                 | Lost or costs                                                                                            |
|------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------|
| Directions per relation, with diagonals, solved together with the tree | About 560 KB of vendored scripts (=vendor/relationship-annotator/=), pasted into every page              |
| A note with several parents is drawn once, joined to all of them       | Layout is heuristic: a crowded graph breaks some direction rules, and the result is not tidy like a tree |
| Rows of siblings are aligned, and the layout is deterministic          | A layout takes about 0.5 s for 120 boxes and grows quickly above that                                    |
| No dependency on the network; the scripts are MIT licensed             | The scripts must be updated by hand (=vendor/relationship-annotator/README.org=)                         |
| Drawing is unchanged, so wrapping, tags and tints still work           | The SVG export (Graphviz) ignores directions                                                             |

Other backends considered: Cytoscape.js with its own renderer (less control over wrapped text and muted tags), ELK (layered, but one direction for the whole graph), d3-force (smaller, but no hard rules and no rectangles), and Graphviz in the browser (a static layout that can't take rules). fCoSE is the only one with built-in relative placement rules.

** Verification

Tested on Emacs 29.3 with mock notes, not yet on the real vulpea database:

- A note with two parents on one line, and a note with a repeated =parents ::= key, each show under all their parents.
- The scope keeps the requested depth and counts the children it hides.
- The SVG name came out as =20261020T163734-ethics-2.svg=, and =dot= wrote the file.
- The native outline expands and collapses with =TAB=.
- The vui outline renders, and its =+= and =-= buttons expand and collapse a branch.
- A link from a =DG_SUPPORTS= file property, a =children ::= line on a parent, and a repeated =opposes ::= key each give an edge, and an edge declared by two sources shows once.
- The links appear in the browser page (dashed, coloured, with a legend) and in the Graphviz source (=constraint=false=), and the outline is unchanged.
- In the page, a click on a box recentres on it with the same depth, =−= and =+= change the depth, and Backspace returns to the previous centre. The boxes of =root= and =idea= notes are tinted, the legend lists the tags in view, and the Graphviz source gets =fillcolor=\"#4e79a766\"= for a =root= note.
- The layout puts each parent above its children and rows of siblings on one height, an =answers= object above its subject, a =supports= object to the right and an =informs= object up and to the right. A graph of 121 boxes lays out in about half a second, and crowded graphs break some direction rules rather than overlap boxes.
- The generated page passes a JavaScript syntax check, and in headless Chromium a long title wraps onto several lines, with the file tags muted at the end of the last one.
- The Graphviz source wraps and escapes labels (a title with quotes came out as =Logic \"formal\"=), and =dot= accepts it.
- Types came out right from all three sources on mock notes (a =DG_TYPE= property, a =type= metadata field, and a =claim= file tag); a note with none has no type.
- On a mock question with two answers, three evidence notes and one source, the check reported only the claim that supports a question (="claim supports question, expected evidence supports claim"=), and skipped an untyped note. The attributes were =evidence-score -1= and =robustness -1.0= for a claim with one supporter and two opposers, and =answer-count 2= for the question.
- The gaps and strengths were as expected: =unanswered-opposition= and =challenged= for the opposed claim, =no-source= and =supported= for a claim whose supporter has no source, and =no-support= for a claim with none. The review buffer listed all three sections.
- Bad formulas stop with a message that quotes them: a missing operand, an unknown operation, =sum= with no attribute, a stray character, a missing parenthesis and an unknown relation. A division by zero gives 0, and two attributes that need each other stop with a message instead of recursing forever.
- In headless Chromium the boxes took the colour of their type, the badges =[2]=, =[-1]= and =[0]= were bold after the titles, the warning sign appeared on the anomalous link with its message as a tooltip, and the legend listed =question=, =claim= and =evidence=.
- Not tested: a real vault. In particular, whether vulpea puts a =DG_TYPE= or =DG_SUPPORTS= file property into =vulpea-note-properties=, which the property sources rely on.
