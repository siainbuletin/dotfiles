#+TITLE: beets on the Synology: literate configuration
#+PROPERTY: header-args:yaml :mkdirp yes :padline no
#+STARTUP: content

Literate source for the [[https://beets.io/][beets]] music library manager running in a container on the Synology NAS.

- This file writes two files into =synology/=, next to it: =config.yaml= (the beets configuration) and =compose.yaml= (the Container Manager project).
- Each =yaml= block below says which of the two it goes to with its own =:tangle= header.
- To tangle in Emacs, run =C-c C-v t= (=org-babel-tangle=) in this buffer.
- To tangle and copy the result to the NAS in one go, run [[file:deploy-to-synology.sh][deploy-to-synology.sh]] (see [[*Copying the configuration to the Synology][Copying the configuration to the Synology]]).

* Why the tangled files go into =synology/=

This file lives in =~/.config/beets/=, which is also where a beets installed on the laptop looks for its own =config.yaml=.

- The configuration below uses the paths /inside the container/ (=/music=, =/config=), which do not exist on the laptop.
- Writing it to =~/.config/beets/config.yaml= would make a local =beet= command use them and fail.
- So the files for the NAS are written to =~/.config/beets/synology/= instead, and the top of the folder stays free for a local configuration later.

* Secrets

Nothing secret goes into this repository.

- API keys and tokens (Discogs, Last.fm, AcoustID, …) go into =synology/secrets.yaml=, which is listed in [[file:.gitignore][.gitignore]].
- The configuration pulls it in with beets' =include:= option, which reads extra YAML files from the folder of =config.yaml= and merges them in.
- When an included file is missing, beets (2.14, tested) prints =configuration `import` failed= on every command and carries on; to keep that quiet, the deploy script copies your local =secrets.yaml= when there is one, and otherwise creates an empty one on the NAS if none is there yet.

An example of =secrets.yaml= (not tangled):

#+begin_src yaml :tangle no
discogs:
  user_token: YOUR-DISCOGS-TOKEN
acoustid:
  apikey: YOUR-ACOUSTID-KEY
#+end_src

* beets configuration (=config.yaml=)

** Library, paths and secrets

The container mounts the music library at =/music= and the configuration folder at =/config= (see [[*Container Manager project (=compose.yaml=)][the compose file]]).

- =library= is the SQLite database of the library. The file name =musiclibrary.blb= is the one the linuxserver image uses in its default configuration, so a library made by the image's default keeps working.
- =include= reads =secrets.yaml= (see [[*Secrets][Secrets]]).

#+begin_src yaml :tangle synology/config.yaml
# Tangled from ~/.config/beets/beets.org. Edit that file, not this one.

directory: /music
library: /config/musiclibrary.blb

include:
  - secrets.yaml
#+end_src

** Plugins

The plugins below are a starting point, close to the image's own default.

- =web= must stay: the container starts =beet web= as its main process and checks that port 8337 answers, so without the plugin the container never becomes healthy.
- =chroma= (acoustic fingerprints) works because the image ships =chromaprint=.
- =fetchart=, =embedart= and =lastgenre= fill in cover art and genres at import; =scrub= removes stray tags before beets writes its own.
- =info=, =missing= and =duplicates= are read-only reports, handy from the command line.

#+begin_src yaml :tangle synology/config.yaml

plugins:
  - web
  - chroma
  - fetchart
  - embedart
  - lastgenre
  - scrub
  - info
  - missing
  - duplicates
#+end_src

** Importing

- =copy: yes= copies files from the import folder into the library and leaves the originals where they are; switch to =move: yes= once you trust the setup.
- =write: yes= writes the corrected tags into the files themselves.
- =incremental: yes= skips folders already imported, so re-running an import on =/downloads= is cheap.
- =log= keeps a record of every decision taken during imports in the config folder.

#+begin_src yaml :tangle synology/config.yaml

import:
  write: yes
  copy: yes
  move: no
  resume: ask
  incremental: yes
  quiet_fallback: skip
  log: /config/import.log
#+end_src

paths:
  default: $albumartist/$album%aunique{}/$track - $title
  singleton: Non-Album/$artist - $title
  comp: Compilations/$album%aunique{}/$track - $title

art_filename: cover
#+end_src

** Plugin settings

=web= listens on every interface inside the container; the compose file decides which port of the NAS it is reachable on.

#+begin_src yaml :tangle synology/config.yaml

web:
  host: 0.0.0.0
  port: 8337

fetchart:
  auto: yes

embedart:
  auto: yes

lastgenre:
  auto: yes
  source: album

scrub:
  auto: yes
#+end_src

* Container Manager project (=compose.yaml=)

The project for Synology's Container Manager, using the [[https://docs.linuxserver.io/images/docker-beets/][linuxserver.io beets image]].

- In Container Manager, choose /Project → Create/, set the path to =/volume1/docker/beets= and pick /Use existing docker-compose.yml/ once the deploy script has copied =compose.yaml= there.
- =PUID= and =PGID= should be your own DSM user and group, so that files written by beets belong to you. Find them with =ssh <user>@<nas> id=; the values below (=1026= and =100=, the first DSM user and the =users= group) are a guess.
- At start the image changes the owner of everything in =/config= to that user, so it must also be the user the deploy script copies as.
- =/downloads= is where new music waits to be imported; =/volume1/music/_import= is a guess, change it to your folder.
- =TZ= is UTC; set it to your zone (for example =Europe/Berlin=) so log times match your clock.
- The web interface is at =http://<nas>:8337=.

#+begin_src yaml :tangle synology/compose.yaml
# Tangled from ~/.config/beets/beets.org. Edit that file, not this one.
services:
  beets:
    image: lscr.io/linuxserver/beets:latest
    container_name: beets
    environment:
      - PUID=1026
      - PGID=100
      - TZ=Etc/UTC
    volumes:
      - /volume1/docker/beets:/config
      - /volume1/music:/music
      - /volume1/music/_import:/downloads
    ports:
      - 8337:8337
    restart: unless-stopped
#+end_src

* Copying the configuration to the Synology

[[file:deploy-to-synology.sh][deploy-to-synology.sh]] tangles this file when the files in =synology/= are missing or older than it, then copies them to the NAS with =scp=.

#+begin_src sh :tangle no
~/.config/beets/deploy-to-synology.sh                 # defaults below
~/.config/beets/deploy-to-synology.sh -n             # dry run: print what would happen
SYNOLOGY_HOST=nas.local ~/.config/beets/deploy-to-synology.sh
~/.config/beets/deploy-to-synology.sh -H 192.168.88.10 -u sia -d /volume1/docker/beets
#+end_src

| Option | Variable           | Default                 |
|--------+--------------------+-------------------------|
| =-H=   | =SYNOLOGY_HOST=    | =192.168.88.10=         |
| =-u=   | =SYNOLOGY_USER=    | your local user name    |
| =-p=   | =SYNOLOGY_PORT=    | =22=                    |
| =-d=   | =SYNOLOGY_DEST=    | =/volume1/docker/beets= |
| =-f=   |                    | tangle even if up to date |
| =-n=   |                    | dry run                 |

Before the first run, on the NAS:

- Turn on SSH in /Control Panel → Terminal & SNMP/.
- Create the shared folder =docker= (Container Manager does this when installed) and the folder =beets= inside it.
- Put your public key in =~/.ssh/authorized_keys= of your DSM user (=ssh-copy-id= works once /User Home/ is enabled), so the script does not stop for a password.

The script calls =scp -O=, which uses the old SCP protocol instead of SFTP; DSM only answers SFTP when SFTP is turned on in /File Services/, and the old protocol works either way. Set =SYNOLOGY_SCP_LEGACY=0= to drop =-O=.

From Emacs, run it with =M-x compile= (=M-x compile RET ~/.config/beets/deploy-to-synology.sh=; use =C-u M-x compile= for a comint buffer that accepts input). With a key in your SSH agent it needs no input; for a password prompt use =C-u M-x compile=, or run it in a terminal outside Emacs.

After copying, restart the container (/Container Manager → Project → beets → Action → Restart/) so beets reads the new configuration.
