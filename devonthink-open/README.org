#+title: devonthink-open: PDFs indexed in DEVONthink open in DEVONthink (literate source)
#+property: header-args :mkdirp yes :comments no :padline no
#+startup: content

Makes PDFs that are indexed in DEVONthink open in DEVONthink when they are opened from the Finder or from Alfred's file picker. PDFs that are not in a DEVONthink database keep opening in an ordinary viewer (Preview by default); DEVONthink never gets them, so it does not offer to import them. macOS only.

This file is the source of the package. The applet source, the installer and the settings file are written from it, and they are committed as well so that Stow can link them without Emacs. Change them here, not in the generated files.

* Only on macOS

The package is for the Mac and nothing else uses it.

- =stow-migration/packages.tsv= lists =devonthink-open= as =darwin=, next to =aerospace= and =hammerspoon=, and =migrate.sh= only stows the packages of the operating system it runs on, so Linux machines never get it.
- Stow itself has no idea of operating systems: =stow devonthink-open= on Linux would link the files. Do not run it there.
- If it is run anyway, nothing happens: the files are only an AppleScript source, an installer and a settings file, and =dt-open-install= stops at once on anything but macOS (its =uname= test).

- In Emacs: open this file and run =C-c C-v t= (=org-babel-tangle=).
- From a shell, in this folder:

#+begin_example
emacs --batch --eval "(require 'org)" --eval '(org-babel-tangle-file "README.org")'

* Setting up

On the Mac, with DEVONthink installed:

#+begin_example
cd ~/dotfiles
stow devonthink-open
brew install duti        # optional: lets dt-open-install set the default itself
dt-open-install
#+end_example

=~/.local/bin= must be on =PATH= only for you to type =dt-open-install=. Without =duti=, the installer says how to set the default in the Finder: select a PDF, Cmd-I, "Open with", "DT Open PDF", "Change All...". The first time a PDF is opened, macOS asks whether "DT Open PDF" may control DEVONthink (System Settings, Privacy & Security, Automation); allow it, or every PDF falls through to the fallback viewer.

The app can also be used from a shell: =open -a "DT Open PDF" file.pdf=.

=dt-open-install --uninstall= puts the previous default back (if =duti= recorded it) and removes the app. After changing the applet source here, tangle and run =dt-open-install= again.

* Settings

They live in =~/.config/dt-open/config= (the file is in the code section below), one =NAME=value= per line. Lines that start with =#= are comments; a comment after a value is not allowed. Quotes around a value are optional. The applet reads the file at every start, so a change applies to the next PDF.

- =DT_OPEN_FALLBACK=: the app for PDFs that are not in DEVONthink (=Preview=). Set it to the viewer you used before, e.g. =Skim=. It is opened by name, so it cannot loop back into the applet.
- =DT_OPEN_LAUNCH=: =1= starts DEVONthink when it is not running and waits for a database (up to 60 s), because the lookup only works with DEVONthink running and the databases open. =0= opens the PDF in the fallback viewer instead and never starts DEVONthink.
- =DT_OPEN_MODE=: =window= opens the PDF in its own DEVONthink window; =reveal= (=?reveal=1= on the link) shows it in the main window, in its database.

* Why it is built this way

** What has to happen

Choosing DEVONthink in "Open with" does not work: it imports the file instead of showing the indexed record (the forum thread [[https://discourse.devontechnologies.com/t/open-an-indexed-item-in-devonthink-from-the-finder/50406][Open an indexed item in Devonthink from the Finder]]). What does work, as that thread and the ones it links to say, is asking DEVONthink for the record whose path is the file's path (the AppleScript command =lookup records with path=, run once per open database) and opening the record's =x-devonthink-item://= link. Only DEVONthink knows which files are indexed, so something has to ask it at the moment a PDF is opened, and that something has to sit where the Finder and Alfred send a file to be opened.

** Is an app needed?

Yes, as far as I can find. macOS sends a file to "the default app for its type", and only an app bundle that declares the type in its =Info.plist= can fill that slot; a script, a shell command or a Hammerspoon function cannot. So the applet =DT Open PDF.app= is that app, and it does the whole job itself: it reads the settings, looks the file up in DEVONthink and either opens the record or hands the file to the fallback viewer. It is built from the AppleScript source in this repository by =dt-open-install=, so there is no binary to keep.

** Hammerspoon

- Hammerspoon cannot be the default for PDFs. Its =hs.urlevent= module registers it for URL schemes (=http=, =https=, =mailto=, its own =hammerspoon://=), not for file types, and I found nothing in its API that registers it for a file type.
- What Hammerspoon can do is watch the keyboard and mouse. A =hs.eventtap= or =hs.hotkey= bound only while the Finder is frontmost could catch Cmd-O or a double-click on a selected PDF, run the same lookup and open the result. That is a different mechanism with real costs:
  + It only works in the Finder. Alfred, Mail, a browser's download list and anything else that opens a file with the default app would not be covered.
  + It reacts to input, not to the file being opened, so the PDF has to be recognised from the selection (an AppleScript call to the Finder for each key press) and the original key press has to be swallowed without breaking Return (rename in the Finder), drag selection and so on.
  + The default app would still be Preview, so a missed key press opens Preview.
- Hammerspoon is still the right tool if the aim is a hotkey ("open the selected file in DEVONthink"), and it could run =open -a "DT Open PDF"= on the selection for that. It is not a replacement for the default handler.

** Other ways, and why not

- /DEVONthink as the default, or "Open with" DEVONthink/: imports the file; it does not show the indexed record.
- /Writing each item link into the file (extended attribute or Finder comment)/: needs a smart rule that stamps every indexed PDF, still needs something to read the link when the file is opened, and the DEVONthink staff warn that file paths and links in files can go stale. A lookup at open time has nothing to keep up to date.
- /An Alfred workflow or a Finder Quick Action/: runs the lookup only when it is chosen explicitly, not when Return or a double-click opens the file.
- /A file-routing app (FileRouter and the like)/: also an app that claims the type, but one that has to be installed and configured by hand; the applet here is the same idea, with the rule in version control.

Not checked: that Alfred's Enter on a file uses the default app the way the Finder does. If it does not, Alfred's file action ("Open with" or its Open setting) has to be pointed at =DT Open PDF= by hand.

** Decision: the applet does the whole job, there is no =dt-open= script

/Decided 2026-11-11./ The first version of this package had two parts: the applet, which only passed the files on, and a bash script, =dt-open=, which read the settings, resolved symlinks with =perl=, ran the lookup in =osascript= and then called =open=. The script was removed and its work moved into the applet's AppleScript.

*** Why

- The opening is diverted to DEVONthink from the one place that is already in the way. The applet is started for every PDF anyway, so it is the natural place to decide.
- Fewer process starts on every PDF. The script version ran the applet, then bash, then =perl=, then =osascript= (which compiles the lookup script each time), then =open=. Now it is the applet, one Apple event per database, and for a PDF that is not in DEVONthink a single =open -a=. Symlinks are resolved in the same process with Foundation (=NSString=), and the settings file is read and parsed in AppleScript.
- One piece to keep in step instead of two, and nothing that has to be on =PATH= or at a fixed place in =~/.local/bin= for the applet to work. The Automation permission is also asked once, for the applet, instead of for whichever process ran =osascript=.

*** Alternatives that were kept out

- /Keep the script and the applet, with the applet calling the script/ (the first version): works, and the script can be tested in a Linux container with stand-ins for =osascript= and =open=, which is how it was checked. It costs the process starts above on every PDF, and it was the version with the unknown speed that prompted this change.
- /Keep both, the lookup in the applet and =dt-open= for the command line/: two copies of the same logic that can drift apart. The command line is covered by =open -a "DT Open PDF" file.pdf=, which goes through the same code.
- /Move the lookup to JavaScript for Automation (JXA)/: no gain; the DEVONthink examples that this is based on are AppleScript.

*** Consequences

- The logic can no longer be run or tested without a Mac. The bash tests of the first version are gone with the script, and nothing here can run AppleScript. The first run on the Mac is the test; the settings parser and the =NSString= call are the likeliest places for an error (see "Limits").
- The applet can only be compiled on a Mac that has DEVONthink, because =osacompile= needs its scripting dictionary to understand =lookup records with path= and =reference URL=. =dt-open-install= checks for it.
- The settings are read by AppleScript, so the format is stricter than the shell syntax the script accepted: one =NAME=value= per line, no comment after a value, and no =XDG_CONFIG_HOME= (only =~/.config/dt-open/config=).
- To go back to the script version, take =.local/bin/dt-open= from the git history (the first commit of this package) and make the applet's =on open= call it; the settings file is compatible with both.

** Speed

Not measured: this was written in a Linux container with no DEVONthink. What happens when a PDF is opened:

1. LaunchServices starts the applet (the AppleScript runtime, then the =open= event). This is the part that cannot be removed.
2. The applet reads the settings file and resolves the path.
3. It asks whether DEVONthink is running, then sends it one Apple event per database (up to two paths per database, the second only if the first finds nothing).
4. It opens the item link (DEVONthink comes to the front), or runs =open -a= with the fallback app and the file.

A PDF that is not in DEVONthink pays for all of this before Preview appears. I do not know the number; the time per database depends on how DEVONthink finds a record by path. To measure the part after LaunchServices has the applet, and the whole hand-off:

#+begin_example
time open -W -a "DT Open PDF" ~/some-indexed.pdf    # -W waits until the applet quits
time open -W -a "DT Open PDF" ~/some-other.pdf      # a PDF that is not indexed
#+end_example

If it is too slow:

- Close DEVONthink's unused databases (fewer Apple events).
- Set =DT_OPEN_LAUNCH=0= so that a closed DEVONthink is never started for a PDF.

* The code

** Settings file

Read by the applet. The values are the defaults, so deleting the file changes nothing.

#+begin_src sh :tangle .config/dt-open/config
# Read by DT Open PDF.app: one NAME=value per line, # starts a comment line
# (not after a value); quotes around a value are optional.
# App that opens PDFs which are not in a DEVONthink database.
DT_OPEN_FALLBACK="Preview"
# 1: start DEVONthink when it is not running, so the lookup can happen. 0: open
# the PDF in the fallback app instead (never starts DEVONthink).
DT_OPEN_LAUNCH=1
# window: the PDF opens in its own DEVONthink window. reveal: it is shown in
# the main window, in its database.
DT_OPEN_MODE=window
#+end_src

** The applet source

=DT Open PDF.app= is built from this source by =dt-open-install=. =use scripting additions= has to be written out because the file has other =use= lines; =use framework "Foundation"= gives access to =NSString=.

*** Opening files

The Finder and Alfred call =on open= with the files to open. The settings are read once, then every file is handled on its own.

#+begin_src applescript :tangle .local/share/dt-open/open-handler.applescript
-- Source of "DT Open PDF.app", built by dt-open-install with osacompile.
-- It is the default viewer for PDFs, so the Finder and Alfred hand it every PDF
-- they open. A PDF that is a record in an open DEVONthink database is opened in
-- DEVONthink; any other PDF goes to the fallback viewer (Preview by default).
use AppleScript version "2.4"
use framework "Foundation"
use scripting additions

on open theFiles
	set cfg to readConfig()
	repeat with theFile in theFiles
		openOne(POSIX path of theFile, cfg)
	end repeat
end open

#+end_src

*** Reading the settings

The file is optional: every setting has a default, and any error while reading (no file, unreadable) leaves the defaults. A line is =NAME=value=; the name is the text before the first === and the value is the rest, without a pair of surrounding quotes. A fallback named after this app is replaced by Preview, since the app is the default for PDFs and would open itself again.

#+begin_src applescript :tangle .local/share/dt-open/open-handler.applescript
-- Settings: ~/.config/dt-open/config, one NAME=value per line.
on readConfig()
	set cfg to {cfgFallback:"Preview", cfgLaunch:true, cfgReveal:false}
	try
		set cfgFile to (POSIX path of (path to home folder)) & ".config/dt-open/config"
		set cfgText to read (POSIX file cfgFile) as «class utf8»
		repeat with aLine in paragraphs of cfgText
			set aLine to contents of aLine
			set eq to offset of "=" in aLine
			if aLine does not start with "#" and eq > 1 then
				set theKey to text 1 thru (eq - 1) of aLine
				set theValue to ""
				if eq < (count aLine) then set theValue to text (eq + 1) thru -1 of aLine
				if theValue starts with "\"" and theValue ends with "\"" and (count theValue) > 1 then set theValue to text 2 thru -2 of theValue
				if theKey is "DT_OPEN_FALLBACK" and theValue is not "" then set cfgFallback of cfg to theValue
				if theKey is "DT_OPEN_LAUNCH" then set cfgLaunch of cfg to (theValue is not "0")
				if theKey is "DT_OPEN_MODE" then set cfgReveal of cfg to (theValue is "reveal")
			end if
		end repeat
	end try
	-- This app is the default for PDFs: never fall back to ourselves.
	if cfgFallback of cfg starts with "DT Open PDF" then set cfgFallback of cfg to "Preview"
	return cfg
end readConfig

#+end_src

*** Deciding for one file

A file that does not end in =.pdf= (AppleScript compares text without regard to case) is opened with plain =open=, as the Finder would have done. For a PDF, a link means DEVONthink has it: =open location= opens the link, with =?reveal=1= in =reveal= mode. Otherwise =open -a= names the fallback app, so the default app (this applet) is not consulted again.

#+begin_src applescript :tangle .local/share/dt-open/open-handler.applescript
on openOne(thePath, cfg)
	if thePath does not end with ".pdf" then
		do shell script "/usr/bin/open " & quoted form of thePath
		return
	end if
	set itemLink to lookupLink(thePath, cfgLaunch of cfg)
	if itemLink is not "" then
		if cfgReveal of cfg then set itemLink to itemLink & "?reveal=1"
		open location itemLink
	else
		do shell script "/usr/bin/open -a " & quoted form of (cfgFallback of cfg) & " " & quoted form of thePath
	end if
end openOne

#+end_src

*** Looking the file up

DEVONthink stores the path it was given when the file was indexed, and the Finder may give another name for the same file, so the path with symlinks resolved is tried first and the path as given second. Any error, such as the Automation permission being refused, gives "no link", and the PDF opens in the fallback viewer.

#+begin_src applescript :tangle .local/share/dt-open/open-handler.applescript
-- The item link of the record for the file, or "" if there is none. Any error
-- (for instance the Automation permission being refused) also gives "", so the
-- PDF still opens in the fallback viewer.
on lookupLink(thePath, mayLaunch)
	try
		-- DEVONthink stores the path it was given; try the path with symlinks
		-- resolved first, then the path as the Finder gave it.
		set resolved to ((current application's NSString's stringWithString:thePath)'s stringByResolvingSymlinksInPath()) as text
		return findLink({resolved, thePath}, mayLaunch)
	on error
		return ""
	end try
end lookupLink

#+end_src

The lookup itself:

- =application id "DNtp"= is the creator code, which DEVONthink 3 and 4 both answer to. It avoids naming the app ("DEVONthink 3" or "DEVONthink").
- If DEVONthink is not running it is started only when =DT_OPEN_LAUNCH= is =1=; otherwise the handler returns at once, with no link.
- Right after a start there are no databases yet, so it waits for the first one (120 times 0.5 s). Errors while DEVONthink is still starting are ignored (=try=).
- =lookup records with path= is asked of each database in turn, because without =in <database>= it only searches the current one. This is the loop used in the forum threads.
- The record's =reference URL= is its =x-devonthink-item://= link. A file indexed in two databases opens the record of the first one that has it.

#+begin_src applescript :tangle .local/share/dt-open/open-handler.applescript
on findLink(candidates, mayLaunch)
	if not (application id "DNtp" is running) then
		if not mayLaunch then return ""
		tell application id "DNtp" to launch
	end if
	tell application id "DNtp"
		-- Right after a start there are no databases yet: wait up to 60 s for one.
		repeat 120 times
			try
				if (count of databases) > 0 then exit repeat
			end try
			delay 0.5
		end repeat
		repeat with candidate in candidates
			repeat with theDatabase in databases
				set hits to lookup records with path (contents of candidate) in theDatabase
				if (count of hits) > 0 then return reference URL of (item 1 of hits)
			end repeat
		end repeat
	end tell
	return ""
end findLink
#+end_src

** =dt-open-install=

Builds the app from the source above and makes it the default for PDFs. It is plain bash and runs under =set -e=.

*** Usage

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
#!/bin/bash
# dt-open-install: build "DT Open PDF.app" and make it the default PDF viewer,
# so that Finder and Alfred open PDFs through it. The app does the DEVONthink
# lookup itself. macOS only: packages.tsv lists devonthink-open as darwin.
#
#   dt-open-install              build, register, set as default for PDFs
#   dt-open-install --uninstall  put the previous default back, remove the app
#
# Setting the default needs duti (brew install duti). Without it the script
# builds the app and tells you to do it in Finder (Get Info > Open with >
# DT Open PDF > Change All...).

#+end_src

*** macOS only, names and paths

The first test stops the script on any system but macOS. The app is built in =~/Applications=, so no =sudo= is needed. The bundle id is fixed so that =duti= and LaunchServices can refer to it.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
set -eu

[ "$(uname)" = Darwin ] || { echo "macOS only." >&2; exit 1; }

app="$HOME/Applications/DT Open PDF.app"
id=dev.siainbuletin.dt-open-pdf
src="${XDG_DATA_HOME:-$HOME/.local/share}/dt-open/open-handler.applescript"
state="${XDG_STATE_HOME:-$HOME/.local/state}/dt-open"
lsregister=/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister
pb=/usr/libexec/PlistBuddy

#+end_src

*** Uninstalling

Puts back the default that was recorded when the app was installed, then unregisters and removes the app. Without =duti= it says how to do it by hand.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
if [ "${1:-}" = --uninstall ]; then
  if command -v duti >/dev/null && [ -r "$state/previous-handler" ]; then
    duti -s "$(cat "$state/previous-handler")" com.adobe.pdf all
    echo "Default PDF viewer restored to $(cat "$state/previous-handler")."
  else
    echo "Pick the PDF viewer again in Finder (Get Info > Open with > Change All...)."
  fi
  [ -d "$app" ] && { "$lsregister" -u "$app"; rm -rf "$app"; }
  exit 0
fi

#+end_src

*** Checks, and remembering the current default

The AppleScript is compiled against DEVONthink's scripting dictionary (that is how =lookup records with path= and =reference URL= are understood), so DEVONthink must be installed when the app is built.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
[ -r "$src" ] || { echo "Missing $src: run stow devonthink-open first." >&2; exit 1; }
# osacompile needs DEVONthink's scripting dictionary to compile the lookup.
/usr/bin/osascript -e 'path to application id "DNtp"' >/dev/null 2>&1 ||
  { echo "DEVONthink is not installed (the applet is compiled against its dictionary)." >&2; exit 1; }

# Remember the current default (third line of "duti -x pdf" is the bundle id),
# unless it is already ours.
if command -v duti >/dev/null; then
  mkdir -p "$state"
  current=$(duti -x pdf | sed -n 3p)
  [ -n "$current" ] && [ "$current" != "$id" ] && printf '%s\n' "$current" > "$state/previous-handler"
fi

#+end_src

*** Building the applet

=osacompile= turns the AppleScript source into an applet. An applet quits by itself when its =on open= handler has finished.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
mkdir -p "$HOME/Applications"
rm -rf "$app"
/usr/bin/osacompile -o "$app" "$src"

#+end_src

*** Declaring PDFs in =Info.plist=

LaunchServices lists an app as a possible viewer for PDFs only if the app declares the type, so the generic document types that =osacompile= writes are replaced by one for =com.adobe.pdf=. =LSUIElement= keeps the applet out of the Dock while it runs; =NSAppleEventsUsageDescription= is the text of the Automation permission prompt, which is now asked for the applet itself.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
plist="$app/Contents/Info.plist"
set_key() { "$pb" -c "Set :$1 $3" "$plist" 2>/dev/null || "$pb" -c "Add :$1 $2 $3" "$plist"; }
set_key CFBundleIdentifier string "$id"
set_key LSUIElement bool true   # no Dock icon while it runs
set_key NSAppleEventsUsageDescription string "DT Open PDF asks DEVONthink whether a PDF is one of its indexed files."
"$pb" -c "Delete :CFBundleDocumentTypes" "$plist" 2>/dev/null || true
"$pb" -c "Add :CFBundleDocumentTypes array" \
      -c "Add :CFBundleDocumentTypes:0 dict" \
      -c "Add :CFBundleDocumentTypes:0:CFBundleTypeName string PDF Document" \
      -c "Add :CFBundleDocumentTypes:0:CFBundleTypeRole string Viewer" \
      -c "Add :CFBundleDocumentTypes:0:LSHandlerRank string Alternate" \
      -c "Add :CFBundleDocumentTypes:0:LSItemContentTypes array" \
      -c "Add :CFBundleDocumentTypes:0:LSItemContentTypes:0 string com.adobe.pdf" "$plist"

#+end_src

*** Signing and registering

Changing =Info.plist= invalidates the applet's signature, and an unsigned app is not run on Apple silicon, so it is signed again, ad hoc. =lsregister= makes LaunchServices read the new declaration.

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
# Editing Info.plist breaks the applet's signature; sign it again (ad hoc).
/usr/bin/codesign --force --deep --sign - "$app"
"$lsregister" -f "$app"

#+end_src

*** Making it the default

#+begin_src bash :tangle .local/bin/dt-open-install :tangle-mode (identity #o755)
if command -v duti >/dev/null; then
  duti -s "$id" com.adobe.pdf all
  echo "Built $app and made it the default for PDFs."
else
  echo "Built $app."
  echo "Make it the default: select a PDF in Finder, Cmd-I, Open with: DT Open PDF, Change All..."
fi
echo "The first PDF you open asks for permission to control DEVONthink: allow it."

* Limits

- The lookup compares paths. A file is found if it is indexed under the path the Finder gives, or under that path with symlinks resolved. A file indexed through a different mount point, or on a volume that is not mounted, is not found and opens in the fallback viewer.
- Every PDF goes through the applet, so opening a PDF that is not in DEVONthink costs the lookup and, with =DT_OPEN_LAUNCH=1=, starting DEVONthink if it is closed. See "Speed".
- The applet is the default for PDFs system-wide, so other apps that open PDFs with the default app (a browser's download list, say) also go through it.
- The settings file is read from =~/.config/dt-open/config= only; =XDG_CONFIG_HOME= is not consulted.
- A file can carry its own "open with" choice (the extended attribute =com.apple.LaunchServices.OpenWith=), which beats the default for that file; =xattr -d com.apple.LaunchServices.OpenWith FILE= removes it.
- Not run on a Mac, and the AppleScript cannot be run in the Linux container where this was written: what was checked is the bash syntax of the installer and that the tangle gives back the committed files (with a script, not with Emacs). Untested: all of the AppleScript (lookup, settings parser, the =NSString= call), =osacompile=, =PlistBuddy=, =codesign= and the LaunchServices registration. The settings parser and the symlink step are the likeliest places for a first-run error; see the git history for fixes.
