#+title: 0021 Typeset the PDF of the docs with Typst, exported from Org by ox-typst
#+date: 2026-10-24
#+status: accepted

* Context
The literate docs (=docs/main.org=, the architecture notes and one Org file per module in =docs/tangles/=) are meant to be read in Emacs. I want them as one PDF too, and later a typesetting environment for my own writing (the thesis) that is built on Typst and works from Org without leaving it. Typst compiles in milliseconds, has a real scripting language for templates, reads SVG, and does not need a TeX installation.

The docs set two requirements beyond ordinary Org: they are many files (about 180) with their own titles, tangle headers and footnote numbers, and they are mostly source code, so code blocks must break across pages and be highlighted.

* Decision
- Export with =ox-typst= (jmpunkt), an Org export back end that writes a =.typ= file and calls =typst compile=. It is installed by the =sp-typst= module with an Elpaca recipe.
- Do not export the files one by one. =sp-typst= assembles one Org text from all the docs (one heading per doc, file keywords dropped, links between docs turned into internal links, footnote labels made unique) and exports that. The same assembly exports a single file.
- The look is one Typst file, =docs/typst/template.typ=, loaded by =#show: book=. A manuscript template for my own writing is a second file beside it, later.
- The build is =make -C docs/typst pdf= (headless Emacs) or =M-x sp-typst-export-book=. It has its own Makefile and does not edit the =docs/Makefile= that builds the SVGs.
- =typst-ts-mode= and =tinymist= are the editing side (tree-sitter highlighting, language server) for the =.typ= files.

* Alternatives considered
- *Pandoc, Org to Typst*: no Emacs needed and it handles the whole document. I ran pandoc 3.1.3 on a module doc: the output needs the functions of pandoc's own template, and with that template Typst 0.15 stops with "font fallback list must not be empty" (the template and the Typst version do not match). Without the template the body does not compile either (=blockquote= is not defined). It also knows nothing of =#+INCLUDE=, macros or Org links between files. It stays a fallback for converting other formats to Org, not the exporter of these docs.
- *Org to LaTeX to PDF* (what the Org manual describes, and what =sp-latex= configures): works, but needs a TeX installation, is slow for 2 MB of text, and TeX templates are the part of this I want to leave.
- *Hand-written Typst with the Org docs as appendices*: two sources of truth.
- *A package of my own for the Org-to-Typst translation*: not before =ox-typst= has shown what it cannot do. It is small (about 1200 lines) and has the hooks I need (=#+TYPST_HEADER=, export blocks, a language mapping), so patches or an override function are cheaper than a new back end.
- *Org's own back ends asked for Typst*: =ox-typst= is not in Org; there is a request on the Org mailing list ("[FR] ox-typst"). If it lands, only the =use-package= form changes.

* Consequences
- =ox-typst= declares Emacs 30.1 and Org 9.7 in its header. It exported correctly on Emacs 29.3 with Org 9.7.11 here, but Elpaca may refuse it on an older Emacs, and Org 9.6 (the one in Emacs 29) lacks a function it calls.
- =ox-typst= passes image paths to Typst as =--input= arguments, so it has to start Typst itself (=org-typst-export-to-pdf=); a separate =typst compile= of its =.typ= loses the images. The template is copied beside the =.typ= before each export because Typst refuses to import a file outside its project root.
- The SVGs of the =dot= blocks come from =make -C docs docs= (the SVG Makefile). Without them the PDF has a one-line note where each figure belongs.
- No doc uses =:noweb yes= today. If one does, the assembly has to expand it, because export without Babel does not.
- The assembly leaves the docs on disk unchanged. A =[[*Heading]]= link resolves to the first heading of that name in the whole book.
- /untested/: running it from my Emacs with Elpaca, =typst-ts-mode= and =tinymist= (nothing of these was installed in the container), and macOS. See the doc =docs/tangles/text/sp-typst.org= for what was run.
