#+title: 0017 Fontaine presets own the fonts; emoji and tag emoji sit beside them
#+date: 2026-10-24
#+status: accepted

* Context
=init.el= ended with Customize-generated =custom-set-variables= and =custom-set-faces= blocks, and =sp-fonts= set the default face three times in competing ways (the options =sp-ui-default-font= and =sp-ui-variable-width-font=, the =ha-= font lists from Howard Abrams' configuration, and direct =set-face-attribute= calls). The last setting to run won, which was not the one I had read.

* Decision
- =sp-fonts= is rebuilt around =fontaine= (#25). A preset is the one place that decides the default, fixed-pitch and variable-pitch families, their heights, line spacing and the mode line height. =regular= is Aporetic Sans Mono at 150 with Aporetic Serif Mono as the variable-pitch face; =presentation= uses Charter and larger text. Atkinson Hyperlegible is used for the Org =#+title:= only, Literata for Org quotes, and Org headings stay at the size of the text whatever the theme says. The last preset is restored at startup and saved in =sp-cache-dir=.
- The two options and the =ha-= lists are removed. =M-+=, =M-== and =M--= change the default face height by one point.
- The Customize blocks are removed from =init.el=; each setting moved to the module that owns it, and =custom-file= points to =var/etc/custom.el=, which is never loaded, so Customize cannot write to =init.el= again.
- Colour emoji are a separate module, =sp-emoji-font=, which prepends the first installed colour emoji family to the =emoji= fontset for every graphical frame; on Linux =M-x sp-emoji-font-install= installs an Apple Color Emoji =.ttf= (#60). Showing Org tags as emoji is another, =sp-tag-emoji=, which uses it.

* Pull requests, in dependency order
1. #25 the Customize blocks out, =sp-fonts= rebuilt around =fontaine=
2. #60 =sp-emoji-font= and =sp-tag-emoji=, which depend on the emoji fontset that #25 left in =sp-fonts=
Next to them: #63 puts every =defcustom= in the Customize group =spcustom=, and #80 compares theme packages, which decide faces, not families.

* Alternatives considered
- *Keep the options and set the face once.* Two places would still decide the fonts.
- *Bundle the emoji font.* Not allowed by Apple's licence; the file is supplied by =sp-emoji-font-file= or by URL.
- *Keep Customize writing to =init.el=.* It put about 150 agenda files into =init.el= and let a snapshot override the modules.

* Consequences
- The default face is now Aporetic Sans Mono 150 instead of the PT Mono 120 that used to win at the end of startup.
- Until the first =org-mem= scan finishes, the agenda uses =~/notes/area/= and =~/notes/inbox/= instead of the old saved list of about 150 files.
- A theme that defines the Org faces can override the =set-face-attribute= values of =sp-org-emphasis=; the old =custom-set-faces= always took precedence.
- The variable-pitch face is a placeholder (Aporetic Serif Mono 120) "until the variable fonts are organised", and the symbol / emoji fallback block of =sp-fonts= (from Lambda Emacs, "Use Apple emoji") still exists beside =sp-emoji-font=.
- /Untested/ on my Mac: the =fontaine= preset keys and =fontaine-restore-latest-preset= follow its documentation but were never run; emoji rendering in a graphical frame; whether =lambda-line= prints =global-mode-string= for the tag emoji (use =sp-tag-emoji-placement= = =header-line= if not); the Linux font install with a real TTF (the Apple =.ttc= does not work on Linux).
