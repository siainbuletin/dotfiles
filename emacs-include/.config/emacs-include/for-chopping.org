**** Capture to org-journal

This will work with a special diary directory in =~/Documents/journal=. Each filename is today's date. When you want to trigger emacs to create a new journal file, use this function:

#+begin_src emacs-lisp :tangle no
(defun get-journal-file-today ()
  "Return filename for today's journal entry."
  (let ((daily-name (format-time-string "%Y%m%d")))
    (expand-file-name (concat org-journal-dir daily-name))))
#+end_src

Then a simple function to load that file:

#+begin_src emacs-lisp :tangle no
(defun journal-file-today ()
  "Create and load a journal file based on today's date."
  (interactive)
  (find-file (get-journal-file-today)))

(global-set-key (kbd "C-c f j") 'journal-file-today)
#+end_src

Since the time stamp for the file’s name was YYYYMMDD, I move back and forth between entries with a couple simple functions2, and the org-journal project lets me create the entry by selecting the day in Emacs’ calendar.

These files do not have a .org extension, but we’re talking about Emacs, so I use this code to have org-mode be the default mode for filenames consisting of nothing but numbers:

(add-to-list 'auto-mode-alist '(".*/[0-9]*$" . org-mode))

** TODO Recognising other cross-references within a PDF

One thing that I end up doing a lot during my research is that I take the referenced works from the article that I'm reading and I attempt to create a reference network, to really trace out the *relevance* of ideas across different academic work.

The manual workflow that I have outside of Emacs is that I copy-paste the name of the referenced article into my search bar (it's a little faster if I also have a search bang setup in that browser or if I'm using the extension for Alfred to open the query directly in Google Scholar), and then try to fetch the article from there. If I can't download it directly from Google Scholar, then I try to go to Sci-Hub where I can ask for the DOI. At any point, for either Google Scholar or Sci-Hub I may end up having a rate limit, or being hit with a CAPTCHA because I'm trying to download the files directly from Emacs. This isn't really ideal especially when I'm researching and I just want to have a big schema down that I can later traverse.

As I don't actually end up reading the articles that quickly, I want to have a very quick way to chart out the references so at least when I _choose_ to go out and manually download that source, I at least know for sure what it is that I'm getting into.

For this reason, I should at least be able to make a DOI into a usable BibTeX record that can be used in plotting out a reference network (or at least organise everything based on some kind of tag). This would speed up the workflow and minimise the interruptions.

It would be great that while you're reading, to be able to take the in-text references to another text and annotate it on the side to be able to look at the reference later.

This would either mean that it's an overlay, or it's in the special org file that's related to the article that I'm currently reading.
